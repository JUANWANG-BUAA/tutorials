## 原始器件手册补充

- 文档：Philips Semiconductors, **SJA1000 Stand-alone CAN controller, Product specification, 2000 Jan 04**。
- 官方托管下载：<https://www.nxp.com/docs/en/data-sheet/SJA1000.pdf>。
- 实际文件：68 物理页；SHA-256 `65b642a7257e9e91c343426a6c63c96ec0c2f6c5a3c99fa4c3cef6422ab3c1ae`。
- 本轮核读物理页：26–31、35–44、50–51、55–56。
- 不是整本已读，不把目录条目冒充正文阅读。

关键落实：

1. §6.4.3，26–27：MOD 的配置位限制、LOM 不应答、STM 不要求外部 ACK；复位握手为同步状态。实验采用正常模式，不靠自测态制造无 ACK 的成功。
2. §6.4.4，28–29：CMR 读回全零，连续命令至少间隔一个内部时钟；AT 不能截断已在线发送的帧，单次发送涉及特定命令组合。模型只执行常用命令副作用，不验证该时钟间隔和 single-shot。
3. §6.4.5，29–30：TBS 释放不等于成功，TCS 才另行表示成功完成；Bus-Off 同时设置 RM。发送驱动先检查 BS，再返回独立配置态错误。
4. §6.4.6，31：IR 读取清除除 RI 以外的位。该节续页未核读，账本保留部分状态；当前测试只检查这条已核实语义。
5. §6.4.9，36–37：ECC 读取后重新开放捕获；仅清 IR 不足以继续产生下一次相关错误中断。该锁存路径尚未建模执行。
6. §6.4.11–6.4.12，38：Bus-Off 后八位 TXERR 复用为从 127 开始的恢复计数，不能期望读出抽象 TEC=256。正文把协议计数与可见硬件读值分开。
7. §6.4.13，39–42：标准与扩展记录的 ID 字节不是 CPU 内存端序；TX ID 末字节的 RTR 副本按手册推荐填入。DLC>8 时芯片仍最多发八字节，规范化软件 API 刻意拒绝该范围。
8. §6.4.14，42–44：RX 窗口映射 FIFO，完整读取后释放；FIFO 总字节容量与帧数量有关，不能把“最多 32 条”理解为可装 32 条八字节帧。
9. §6.4.15 起始，44：AMR 的 1 表示不关心；整节后续单/双过滤配置未读完，账本不关闭该节。
10. §6.5.1–6.5.2，50–51：BTR 字段与公式核对；运行态在 PeliCAN 中只读，模型故意拒绝写入。
11. §6.5.4，55–56：CDR.7 复位态选择 PeliCAN，其他时钟相关位不应被无依据覆盖。

## 仍缺的依据与执行

- 完整 ISO CAN FD 字段级规范及目标 FD 控制器版本未核读，DLC 映射不等于 FD 编解码实现。
- 尝试补充的 `https://www.bosch-semiconductors.com/media/ip_modules/pdf_2/can_fd_spec.pdf` 返回 HTTP 404。失败下载不计为已获得或已读来源。
- SJA1000 模型未实现真实位时钟、FIFO 多帧占用、全部捕获锁存与全部错误计数例外。
- 无实体收发、错误帧、Bus-Off 恢复、线缆时序或功耗测量。
- x86 执行的是协议算法与自检，不是 SJA1000 MMIO 或 CAN IRQ。
- 两轮独立逐节技术审计仍未执行。
