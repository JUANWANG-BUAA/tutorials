# 第四章母本核读摘记（原创归纳）

PDF 文件与 SHA-256 见 `source-ledger.json`。页码为物理页，非自动推断的印刷页。
本地 pdftotext 抽页文件在忽略目录 `.qa/edge/sources/`，不随书发布原文或原图。

## ARM64

- PDF 170（纸书 149）§11.4：异常现场讨论包括 PSTATE、PC、SP 与 X0–X30。这比普通函数切换需要保护的范围更大。落点 ch04 §4.1，用来纠正“只存 callee-saved 就能处理任意中断”。
- PDF 376–377（纸书 355–356）§21.4.4：协作切换的保存组包含 X19–X29、SP 与 LR。落点 §4.4 的独立原创 a64_switch；未复制母本函数、符号或图。特别纠正 LR 虽要保存，但不能因此说 X30 是普通 callee-saved。
- PDF 378（纸书 357）§21.4.5：新任务第一次执行依赖预置的返回路径和初始上下文，而不只是一个函数地址。落点 §4.2 的 SVC 首启与 §4.4 的 trampoline 对齐合同。母本演示中的未实现分支不被移植成本书 stub。
- PDF 379（纸书 358）§21.5.1、§21.5.2：调度状态与就绪队列分开表示，示例采用链表。落点 §4.5；TCB 首字段放 SP 被明确改为本实现约定，而非所有内核定律。

## 嵌入式 C

- PDF 148–149 §3.6.1：历史 ATPCS 寄存器和栈约定说明了混合编程的前提。落点 §4.1 的 ABI 合同表。旧规则中 R12/FP 等描述不能直接当现代 AAPCS32 唯一规则。
- PDF 149–152 §3.6.2：不同编译器的 asm 扩展语法不可混用。落点 §4.2 将核心切换放入独立 .S，避免混用普通 C 函数序言与手改 SP。
- PDF 152–153 §3.6.3：汇编调用 C 之前要准备合法栈与参数。落点 §4.3；异步入口不能只保存四个寄存器再调用任意 C 分发器。
- PDF 274–278 §5.3、§5.3.1、§5.3.2：下降栈、起始栈指针、帧和调用返回信息。落点 §4.5 的任务栈/MSP 分开预算。水印是观测不是最坏空间证明。
- PDF 305–307 §5.4.2：这里讨论固定大小分区的堆管理，并非 TCB/优先级位图算法。旧草稿引用该节作位图出处不成立；已在正文明确纠正，不计为本章 RTOS 调度覆盖。
