在现代嵌入式系统开发中，大多数软件工程师的工作起始于 `int main(void)` 函数。在集成开发环境（IDE）的遮蔽下，编译、链接、内存段重定位与芯片上电复位被封装为一键式的黑盒操作。然而，当系统出现全局变量初值随机错乱、启动时突发硬件故障（HardFault）、或者需要实现双区固件升级（OTA）向量表重定向时，不了解启动全流程的工程师往往陷入束手无策的困境。

微控制器没有通用操作系统的装载器（Loader），无法解析复杂的 ELF 文件并按需动态分配虚拟内存。物理芯片上电的瞬间，CPU 面对的是一片处于原始电气状态的硅片：时钟树尚未配置，外部高速晶振尚未起振，易失性存储器（SRAM）内部充斥着随机未初始化的物理噪声，Flash 中的代码尚处于休眠状态。从物理引脚拉高释放复位电平，到 CPU 能够安全执行标准的 C 语言代码，中间必须经历一条毫秒不差、步步惊心的**汇编启动流水线**。

在这条启动流水线中，**GNU 链接脚本**（Linker Script, `.ld`）是整个固件世界的“建筑施工图纸”。它不仅规划了只读代码段（`.text`）、常量段（`.rodata`）、已初始化数据段（`.data`）与未初始化段（`.bss`）在非易失 Flash 与高速 SRAM 中的物理排布，更通过装载内存地址（LMA）与运行内存地址（VMA）的解耦，为底层 C 运行时环境（CRT0）的重定位提供了精确的物理坐标。

本章将彻底打破 IDE 的黑盒封装，以 x86_64、ARM（Cortex-M 与 AArch64）以及 RISC-V 的复位向量为起点，逐行剖析启动汇编、链接脚本语法规则、内存段搬移算法以及物理内存保护单元（MPU/PMP）的初始化配置，赋予读者掌控芯片物理初态的终极控制力。

## 2.1 三大架构复位向量与硬件上电序列 {#sec-edge.1.2.1}

处理器从上电复位到执行软件代码的过程，是由硬件微架构状态机硬编码决定的。不同的计算架构由于历史包袱与应用领域的不同，其复位后的首条指令寻址机制存在显著差异。

<pre class="layout" id="fig-edge-1-2-reset-pipeline">
+----------------------------------------------------------------------------------------------------+
|                               三大计算体系硬件上电复位序列与首地址对比                             |
+----------------------------------------------------------------------------------------------------+
| [x86 架构体系]                                                                                      |
|  芯片上电复位 ---&gt; 强制处于实模式 (16位) ---&gt; CS=0xF000, IP=0xFFF0 (物理地址: 0xFFFFFFF0)           |
|                  ---&gt; 执行长跳转 (Far Jump) 至 BIOS/UEFI 固件入口                                   |
+----------------------------------------------------------------------------------------------------+
| [ARM Cortex-M 体系]                                                                                |
|  芯片上电复位 ---&gt; 硬件自动读取 0x0000_0000 (或 VTOR 映射地址) ---&gt; 装载 [0x00] 到主栈指针 MSP     |
|                  ---&gt; 硬件自动读取 0x0000_0004 ---&gt; 装载 [0x04] 到程序计数器 PC (Reset_Handler)     |
|                  ---&gt; 硬件自动检查 PC[0] 是否为 1 (Thumb 模式标志) ---&gt; 开始执行启动汇编             |
+----------------------------------------------------------------------------------------------------+
| [RISC-V 体系]                                                                                      |
|  芯片上电复位 ---&gt; 强制处于机器模式 (M-Mode) ---&gt; PC 硬件硬编码为 Reset Vector (如 0x1000 或 0x8000_0000)
|                  ---&gt; 硬件关全局中断 (mstatus.MIE=0) ---&gt; 执行首条启动汇编指令                     |
+----------------------------------------------------------------------------------------------------+
</pre>
读图：三大架构的复位策略体现了不同的设计哲学。x86 沿用实模式历史包袱，从 4GB 顶端地址（`0xFFFFFFF0`）向下跳转；ARM Cortex-M 专为低开销嵌入式打造，硬件自动在第 0 周期与第 1 周期并发装载初始栈指针 MSP 与复位函数 PC，彻底消除了软件手工设置栈指针的开销；而 RISC-V 采用极简的直接跳转机制，将 PC 固定在芯片设计时约定的复位物理地址，软件自行负责第一行汇编的环境初始化。

### 1. x86 架构：从 0xFFFFFFF0 到实模式跳转
在现代 x86_64 处理器中，芯片在硬件上电释放复位信号（RESET# 引脚拉高）的瞬间，微架构被强制初始化为一个非常特殊的**伪实模式**状态：
- 代码段寄存器 `%cs` 的选择子被设置为 `0xF000`，但其内部不可见的基地址描述符缓存被硬件强制设定为 `0xFFFF0000`；
- 指令指针寄存器 `%eip` 被硬编码初始化为 `0xFFF0`；
- 两者相加合成的物理线性地址为：
  $$\text{Physical Address} = 0xFFFF0000 + 0xFFF0 = 0xFFFFFFF0$$
  该物理地址正好位于 32 位 4GB 地址空间的最顶端（距离 4GB 边界仅差 16 字节）。该区域被芯片组硬件映射至主板 SPI Flash 中的固件芯片（BIOS / UEFI）。由于仅有 16 字节空间，该地址处通常存放一条无条件长跳转指令（`jmp far`），跳转到更低地址的完整固件执行体。

在早期 x86 体系中，为了兼容 IBM PC 原有的 1MB 内存限制，硬件还设计了臭名昭著的 A20 地址线门控（A20 Gate）。如果 A20 门未打开，第 21 位地址线被强制拉低，地址将在 1MB 边界处发生物理回绕（Wrap-around）。现代固件在进入保护模式与长模式前，必须通过键盘控制器或系统控制端口 0x92 显式置位 A20 信号线，才能访问完整的 64 位物理线性地址。

#### x86_64 从实模式到 64 位长模式的启动跃迁流水线
在工控机与实时边缘工控领域，若从裸机固件直接引导实时控制核心，必须完整经历“16位实模式 $\to$ 32位保护模式 $\to$ 64位长模式”的经典跃迁：

```nasm
/* x86_64 裸机启动跳入 64 位长模式关键汇编序列 */
[BITS 16]
.global _start16
_start16:
    cli                         /* 1. 关中断 */

    /* 开启快速 A20 地址线门控 */
    in      al, 0x92
    or      al, 0x02
    out     0x92, al

    /* 2. 装载临时 32 位全局描述符表 (GDT) */
    lgdt    [gdt32_descriptor]

    /* 3. 置位 CR0.PE (Bit 0): 激活 32 位保护模式 */
    mov     eax, cr0
    or      eax, 0x00000001
    mov     cr0, eax

    /* 4. 长跳转冲刷 16 位流水线，进入 32 位保护模式代码段 */
    jmp     0x08:entry32

[BITS 32]
entry32:
    /* 初始化 32 位数据段选择子 */
    mov     ax, 0x10
    mov     ds, ax
    mov     es, ax
    mov     ss, ax
    mov     esp, 0x7C00         /* 设置临时栈指针 */

    /* 5. 开启 PAE 物理地址扩展 (CR4.PAE = 1, Bit 5) */
    mov     eax, cr4
    or      eax, (1 << 5)
    mov     cr4, eax

    /* 6. 将四级页表基地址 PML4 装入 CR3 控制寄存器 */
    mov     eax, pml4_table_base
    mov     cr3, eax

    /* 7. 使能 IA32_EFER 寄存器的 LME (Long Mode Enable, Bit 8) */
    mov     ecx, 0xC0000080     /* MSR 地址: IA32_EFER */
    rdmsr
    or      eax, (1 << 8)
    wrmsr

    /* 8. 开启分页机制 (CR0.PG = 1, Bit 31)，硬件瞬间正式进入 64 位兼容/长模式 */
    mov     eax, cr0
    or      eax, (1 << 31)
    mov     cr0, eax

    /* 9. 加载 64 位 GDT 并通过 64 位长跳转切换至真正的 64 位代码段 */
    lgdt    [gdt64_descriptor]
    jmp     0x08:entry64

[BITS 64]
entry64:
    /* 此时 CPU 已完全处于 64 位长模式，具备 16 个 64 位通用寄存器访问能力 */
    mov     ax, 0x10
    mov     ds, ax
    mov     es, ax
    mov     ss, ax
    mov     rsp, 0x200000       /* 设定高地址 2MB 物理栈 */
    call    main64              /* 进入 64 位 C/C++ 实时内核主入口 */
```

### 2. ARM Cortex-M 架构：双字自动装载机制
ARM Cortex-M（包括 M0/M3/M4/M7/M33）的设计理念是追求极限的精炼与快速启动。在复位向量的处理上，它完全摒弃了“复位后从固定地址开始取指执行”的传统思路，代之以**硬件双字直接装载**：

1. 芯片内核检测到复位信号释放。
2. 内部逻辑从物理地址 `0x0000_0000`（或由引导引脚 BOOT0/1 映射的 Flash/SRAM 别名区）发起首次 32 位内存读操作：
   - 读取出来的 32 位数值被硬件直接写入**主堆栈指针**（`MSP`）。这保证了在执行任何一条软件汇编指令之前，系统已经拥有合法的物理栈空间，能够立即安全响应任何突发的硬件异常。
3. 紧接着，内部逻辑发起第二次 32 位内存读操作，读取物理地址 `0x0000_0004`：
   - 读取出来的 32 位数值被硬件直接写入**程序计数器**（`PC`）。该地址即为复位中断服务函数 `Reset_Handler` 的物理入口。
4. **Thumb-2 指令集硬约束**：ARM Cortex-M 仅支持 Thumb 和 Thumb-2 编码，不支持传统的 32 位 ARM 指令集。因此，写入 `PC` 的地址的最低有效位（Bit 0）**必须为 1**（例如，若 `Reset_Handler` 的实际物理地址是 `0x0800_0100`，向量表中填入的数值必须是 `0x0800_0101`）。硬件读取该地址后自动置位 `xPSR[24]`（T 位）。如果 Bit 0 为 0，CPU 将在启动的第一周期立即抛出未定义状态的致命故障！

下表直观展示了 ARM Cortex-M 向量表前 4 个条目的内存布局：

| 物理地址偏移 | 向量条目名称 | 位宽 | 典型数值示例 | 硬件处理行为 |
|:--|:--|:--|:--|:--|
| `+0x00` | Initial MSP Value | 32 位 | `0x2002_0000` | 硬件自动写入 `MSP`，指向 SRAM 物理顶端 |
| `+0x04` | Reset Vector | 32 位 | `0x0800_01CD` | 硬件自动装载入 `PC`，Bit 0 必须为 1，启动执行 |
| `+0x08` | NMI Exception | 32 位 | `0x0800_0201` | 不可屏蔽中断入口地址 |
| `+0x0C` | HardFault Exception | 32 位 | `0x0800_0215` | 硬件致命硬故障入口地址 |

此外，以下只讨论实现 VTOR 的 Cortex-M 内核；部分早期 M0 实现需要芯片自己的重映射机制。
VTOR 通常位于 `0xE000_ED08`，有效地址范围和保留位依具体内核版本确定。
向量表基址必须满足该实现及完整向量表大小要求，不能仅凭最低七位为零就认定合法：

```text
+----------------------------------------------------------------------------------------------------+
|                         ARM Cortex-M SCB->VTOR 寄存器微架构位域布局                                |
+----------------------------------------------------------------------------------------------------+
| 31 ... 7 (TBLOFF)                                      | 6 ... 0 (保留)                            |
+--------------------------------------------------------+-------------------------------------------+
| 表基址：最低约束及向量总大小共同决定，可能需 256/512/1024 字节对齐 | 保留位按内核版本核对           |
+----------------------------------------------------------------------------------------------------+
```
对于常见 ARMv7-M 实现，应以覆盖最高向量槽的总字节数向上取二次幂，并满足至少 128 字节的要求，最终仍以目标内核手册为准。
例如 16 个内核槽加 82 个外部槽共 392 字节，应按 512 字节而非 128 字节安排。
Bootloader 与应用必须约定由谁安装新向量表，并在开放新应用中断前完成所需的 VTOR 写入和同步。
基址、初始 MSP、入口 Thumb 标志、挂起源与 CPU 状态需作为整体移交；不能把“应用第一行写 VTOR”当成通用安全跳转流程。

### 3. RISC-V 架构：Reset PC 与机器模式强制入口
RISC-V 架构的哲学是极度正交与极简。规范并未规定所有 RISC-V 芯片必须统一复位地址，而是交由芯片实现厂商（SoC Designer）在 Verilog 硬件逻辑中参数化配置：
- 在许多微控制器（如 SiFive FE310、沁恒 CH32V 系列）中，复位向量物理地址通常被固化在 `0x0000_1000`（内部 Boot ROM）或 `0x8000_0000`（Flash 起始地址）。
- 硬件复位时，CPU 强制进入最高特权级 **M-Mode（机器模式）**；
- 机器状态寄存器 `mstatus` 的 `MIE` 位（全局中断使能）被硬件强制清零，杜绝启动初期被未配置的外设中断打断；
- 程序计数器 `PC` 被强行装载为预设的 Reset PC，CPU 随即从该地址取出第一条机器指令开始顺序执行。

下表系统对比三大计算体系在复位初态上的硬件行为：

| 架构体系 | 复位后的硬件特权级 | 首条指令地址 (Reset Vector) | 栈指针 (SP) 初始状态 | 中断开关初态 |
|:--|:--|:--|:--|:--|
| **x86_64** | 16 位实模式 (Ring 0) | `0xFFFFFFF0` | 未初始化 (随机垃圾值) | `IF=0` (关中断) |
| **ARM Cortex-M** | 特权 Thread 模式 | `[0x0000_0004]` (自动间接寻址) | **自动从 `[0x0000_0000]` 加载 MSP** | 由 `PRIMASK=0` 允许 (向量表未生效前受限) |
| **RISC-V** | 机器模式 (M-Mode) | 硬编码固定地址 (如 `0x1000`) | 未初始化 (需第一条汇编 `la sp`) | `mstatus.MIE=0` (原子关中断) |

## 2.2 内存拓扑与存储器编址：SRAM, Flash, TCM 与外设 MMIO {#sec-edge.1.2.2}

在微控制器内部，没有 Linux 复杂的动态虚拟地址空间概念，整颗芯片采用**统一编址**（Memory-Mapped I/O, MMIO）机制。所有的内部 Flash、系统 SRAM、紧耦合内存以及数以百计的外设控制器寄存器，均被映射在一张连续的 32 位（$4\,\text{GB}$）扁平物理地址空间中。

以 ARM Cortex-M 统一内存架构规范为例，ARM 官方对 4GB 物理地址空间给出了标准化划分建议，芯片厂商（如 ST、NXP、TI）在此基准框架下进一步细化其物理存储器与总线挂载拓扑：

```text
+----------------------------------------------------------------------------------------------------+
|                         ARM Cortex-M 4GB 统一物理地址空间标准分区模型                              |
+----------------------------------------------------------------------------------------------------+
| 0x0000_0000 - 0x1FFF_FFFF (512MB): 代码区 (Code Space: 片上 Flash / ROM / ITCM / 引导别名区)       |
+----------------------------------------------------------------------------------------------------+
| 0x2000_0000 - 0x3FFF_FFFF (512MB): 数据区 (SRAM Space: 片上通用 SRAM / DTCM)                       |
|   * 0x2000_0000 - 0x200F_FFFF: SRAM 物理存储基地址 (1MB)                                           |
|   * 0x2200_0000 - 0x23FF_FFFF: SRAM 位带别名区 (Bit-Band Alias, 映射 0x2000_0000 的每一个比特)    |
+----------------------------------------------------------------------------------------------------+
| 0x4000_0000 - 0x5FFF_FFFF (512MB): 外设区 (Peripheral Space: APB / AHB 挂载的外设寄存器 MMIO)     |
|   * 0x4000_0000 - 0x4000_7FFF: APB1 低速总线外设 (TIM2-7, USART2-5, I2C1-3, CAN1-2)               |
|   * 0x4001_0000 - 0x4001_5FFF: APB2 高速总线外设 (USART1, SPI1, TIM1, ADC1-3)                     |
|   * 0x4002_0000 - 0x4007_FFFF: AHB1 高速总线外设 (GPIOA-K, DMA1-2, RCC 时钟控制)                  |
|   * 0x4200_0000 - 0x43FF_FFFF: 外设位带别名区 (Bit-Band Alias)                                     |
+----------------------------------------------------------------------------------------------------+
| 0x6000_0000 - 0x9FFF_FFFF (1GB):   外部存储区 (External RAM / FMC / Quad-SPI / OctoSPI Flash)      |
+----------------------------------------------------------------------------------------------------+
| 0xE000_0000 - 0xE00F_FFFF (1MB):   内核私有外设区 (PPB: NVIC, SysTick, MPU, SCB 寄存器)            |
+----------------------------------------------------------------------------------------------------+
```

### 1. 位带操作（Bit-Banding）机制微架构原理
在低功耗实时控制中，对硬件 GPIO 引脚输出、外设使能位进行单比特翻转是极其频繁的操作。传统的 C 语言读-改-写（Read-Modify-Write）方式在微架构上需要经过三条机器指令：
```armasm
ldr     r0, [r1]            /* 1. 读出整个 32 位寄存器 */
orr     r0, r0, #(1 << 5)   /* 2. 在寄存器中修改指定位 */
str     r0, [r1]            /* 3. 写回整个 32 位寄存器 */
```
这一过程**不是原子操作**！如果在读取之后、写回之前发生高优先级中断修改了同一寄存器的其他位段，将引发致命的竞争冒险覆盖。

为了解决这一问题，Cortex-M3/M4 引入了硬件**位带别名区**（Bit-Band Alias）机制：
- 将物理内存（SRAM 区或外设区）中 $1\,\text{MB}$ 的“位带区”内的**每一个独立比特**，线性映射到另一个 $32\,\text{MB}$ 的“别名区”中的一个独立 32 位双字地址。
- 当向别名区的某个 32 位地址写入数值 `1` 或 `0` 时，总线硬件控制器自动在内部发起单周期的原子读-改-写事务，精准修改原始物理位。

其物理地址换算数学公式为：
$$\text{AliasAddr} = \text{AliasBase} + (\text{ByteOffset} \times 32) + (\text{BitNumber} \times 4)$$
其中：
- SRAM 位带区基址 $\text{BitBandBase} = \text{0x2000\_0000}$，别名区基址 $\text{AliasBase} = \text{0x2200\_0000}$；
- 外设位带区基址 $\text{BitBandBase} = \text{0x4000\_0000}$，别名区基址 $\text{AliasBase} = \text{0x4200\_0000}$。

::: ex 示例 2.1.1 · 利用外设位带别名区原子翻转引脚电平 {#ex-edge.1.2.1.1}
设我们要原子置位端口 A 输出数据寄存器 `GPIOA->ODR` 的第 5 位（控制 LED 开启）：
- `GPIOA->ODR` 的物理基地址为 `0x4002_0014`；
- 字节偏移量 $\text{ByteOffset} = \text{0x4002\_0014} - \text{0x4000\_0000} = \text{0x0002\_0014}$；
- 目标比特 $\text{BitNumber} = 5$；
- 别名物理地址计算：
  $$\text{AliasAddr} = \text{0x4200\_0000} + (\text{0x0002\_0014} \times 32) + (5 \times 4) = \text{0x4200\_0000} + \text{0x0040\_0280} + \text{0x14} = \text{0x4240\_0294}$$

在 C 语言中，只需对该别名地址执行单次解引用写入，即可完成绝对无锁的原子硬件置位：
```c
#define BITBAND_PERIPH(addr, bit) \
    ((volatile uint32_t*)(0x42000000UL + (((uint32_t)(addr) - 0x40000000UL) << 5) + ((bit) << 2)))

/* 原子置位 PA5 引脚：编译为单条 STR 指令，硬件级无锁原子操作 */
*BITBAND_PERIPH(&GPIOA->ODR, 5) = 1;
```
:::

## 2.3 GNU 链接脚本 (LDS) 深度解析：MEMORY, SECTIONS 与 LMA/VMA {#sec-edge.1.2.3}

GNU 链接脚本（Linker Script）是控制固件物理内存拓扑的核心配置文件。编译器（GCC）将各个 C 源文件编译为独立的目标文件（`.o`）后，链接器（`ld`）必须严格依照链接脚本的指令，将分散的代码段和数据段拼装成一个连续的单一镜像。

::: def 装载地址 LMA 与运行地址 VMA {#def-edge.1.2.3.1}
在可重定位二进制目标程序中，任何一个输出段（Output Section）均具备两个基本内存属性：
- **运行内存地址 (VMA, Virtual / Virtualized Memory Address)**：程序在实际执行过程中，CPU 访问该段变量或取指该段代码时所发出的物理总线地址。
- **装载内存地址 (LMA, Load Memory Address)**：固件在被持久化烧录到芯片非易失存储介质（如 Flash）时，该段二进制原始映像所占据的物理起始地址。
若某段在 Flash 中直接运行（如 `.text`），则 $\text{LMA} == \text{VMA}$；若某段需要在 RAM 中读写执行（如已初始化的全局变量 `.data`），则其 $\text{VMA} \in \text{RAM}$ 且 $\text{LMA} \in \text{FLASH}$。
:::

### 1. LMA 与 VMA 的本质解耦
对于只读代码段（`.text`）和常量段（`.rodata`），代码既在 Flash 中存储，也在 Flash 中直接取指运行（即 XIP, eXecute In Place），因此它们的 **$\text{LMA} == \text{VMA}$**。

然而，对于已初始化的全局变量和静态变量（`.data` 段），情况发生了质的变化：变量在运行时必须具备可写性，因此它的执行地址 **VMA 必须分配在高速 SRAM 中**；但在芯片断电期间，SRAM 的电荷会瞬间流失，变量的初始值必须持久化保存在 Flash 中，因此它的加载地址 **LMA 必须分配在 Flash 中**！

在系统上电启动时，启动汇编必须执行一段经典的重定位循环：依据链接器导出的边界符号，将 `.data` 段从 Flash（LMA）原封不动拷贝到 SRAM（VMA）中。

```text
+----------------------------------------------------------------------------------------------------+
|                         链接段 LMA (加载地址) 到 VMA (运行地址) 映射模型                           |
+----------------------------------------------------------------------------------------------------+
| [片上 Flash 物理空间]                                       [片上 SRAM 物理空间]                   |
| 0x0800_0000 +--------------------------+                    0x2000_0000 +--------------------------+
|             | .isr_vector (中断向量表) |                                |                          |
|             +--------------------------+                                |                          |
|             | .text (程序机器指令)     |                                |                          |
|             +--------------------------+                                |                          |
|             | .rodata (常量字符串等)   |                                |                          |
|             +--------------------------+                                |                          |
| _etext ===> | .data 的 LMA 镜像数据    | ========= CRT0 搬移数据 ======> | .data (已初始化全局变量) |
|             | (断电保存初始值)         |                                +--------------------------+
|             +--------------------------+                     _edata ==> | .bss (未初始化全局变量)  |
|                                                                         | (CRT0 启动时清零)        |
|                                                              _ebss ===> +--------------------------+
|                                                                         | 堆空间 (Heap: 向高地址增长)|
|                                                                         v                          |
|                                                                         ^                          |
|                                                             _estack ==> | 栈空间 (Stack: 向下递减)  |
|                                                             0x2002_0000 +--------------------------+
+----------------------------------------------------------------------------------------------------+
```

### 2. 工业级标准 GNU 链接脚本全结构逐行精解

以下是一份严格符合 Cortex-M4/M7 标准的完整链接脚本（`stm32f407.ld`），包含详细的行内语法解析：

```ld
/* 声明程序的唯一物理入口符号为 Reset_Handler */
ENTRY(Reset_Handler)

/* 1. MEMORY 命令：定义物理芯片的存储边界 */
MEMORY
{
    /* FLASH 区域：起始地址 0x08000000，长度 1024KB (1MB)，属性只读可执行 (rx) */
    FLASH (rx)      : ORIGIN = 0x08000000, LENGTH = 1024K
    /* SRAM 区域：起始地址 0x20000000，长度 128KB，属性读写可执行 (rwx) */
    RAM (rwx)       : ORIGIN = 0x20000000, LENGTH = 128K
    /* 紧耦合内存 CCMRAM：起始地址 0x10000000，长度 64KB (仅 CPU 核心可访问) */
    CCMRAM (rw)     : ORIGIN = 0x10000000, LENGTH = 64K
}

/* 导出主栈顶指针符号 (RAM 物理最高地址: 0x20000000 + 128K = 0x20020000) */
_estack = ORIGIN(RAM) + LENGTH(RAM);

/* 堆和栈的最小保留尺寸安全约束 */
_Min_Heap_Size = 0x200;      /* 保留 512 字节堆 */
_Min_Stack_Size = 0x400;     /* 保留 1024 字节栈 */

/* 2. SECTIONS 命令：定义各个段的组装与排列顺序 */
SECTIONS
{
    /* 中断向量表：必须放置在 FLASH 的最首部 (0x08000000) */
    .isr_vector :
    {
        . = ALIGN(4);        /* 4 字节地址对齐 */
        KEEP(*(.isr_vector)) /* KEEP 关键字：防止链接器开启 --gc-sections 优化时将其当作未引用代码误删 */
        . = ALIGN(4);
    } >FLASH

    /* 代码段 (.text)：包含所有编译后的函数机器指令 */
    .text :
    {
        . = ALIGN(4);
        *(.text)             /* 收集所有输入目标文件的 .text 段 */
        *(.text*)            /* 收集所有类似 .text.startup, .text.foo 的细分子段 */
        *(.glue_7)           /* ARM/Thumb 交互胶水代码 */
        *(.glue_7t)
        *(.eh_frame)
        KEEP (*(.init))
        KEEP (*(.fini))
        . = ALIGN(4);
        _etext = .;          /* 导出代码段结束地址：标记此时 Flash 计数器的当前位置 */
    } >FLASH

    /* 只读常量数据段 (.rodata) */
    .rodata :
    {
        . = ALIGN(4);
        *(.rodata)           /* 常量字符串、const 全局变量 */
        *(.rodata*)
        . = ALIGN(4);
    } >FLASH

    /* 已初始化全局数据段 (.data)：核心解耦语法！
     * >RAM: 指定运行期地址 (VMA) 分配在 RAM
     * AT> FLASH: 指定加载期地址 (LMA) 分配在 FLASH 紧跟在 .rodata 之后
     */
    .data : 
    {
        . = ALIGN(4);
        _sdata = .;          /* 导出符号：.data 段在 RAM 中的起始 VMA */
        *(.data)
        *(.data*)
        . = ALIGN(4);
        _edata = .;          /* 导出符号：.data 段在 RAM 中的结束 VMA */
    } >RAM AT> FLASH

    /* 链接器内建函数 LOADADDR：显式获取 .data 段在 FLASH 中的真实 LMA 起始物理地址 */
    _sidata = LOADADDR(.data);

    /* 未初始化数据段 (.bss)：程序启动时无需从 Flash 搬移数据，只需全部清零 */
    .bss :
    {
        . = ALIGN(4);
        _sbss = .;           /* 导出符号：.bss 段在 RAM 中的起始地址 */
        __bss_start__ = _sbss;
        *(.bss)
        *(.bss*)
        *(COMMON)            /* 收集未初始化的全局弱符号 */
        . = ALIGN(4);
        _ebss = .;           /* 导出符号：.bss 段在 RAM 中的结束地址 */
        __bss_end__ = _ebss;
    } >RAM

    /* 用户堆栈保护与边界断言检查 */
    ._user_heap_stack :
    {
        . = ALIGN(8);
        PROVIDE ( end = . );
        PROVIDE ( _end = . );
        . = . + _Min_Heap_Size;
        . = . + _Min_Stack_Size;
        . = ALIGN(8);
    } >RAM

    /* 丢弃未使用的调试段与异常展开段，减少最终镜像体积 */
    /DISCARD/ :
    {
        libc.a ( * )
        libm.a ( * )
        libgcc.a ( * )
        *(.ARM.exidx*)
        *(.ARM.extab*)
    }
}

/* 链接期静态空间边界断言：杜绝内存溢出悄然发生 */
ASSERT(_edata <= ORIGIN(RAM) + LENGTH(RAM), "Error: .data section exceeded RAM capacity!")
ASSERT(_ebss <= ORIGIN(RAM) + LENGTH(RAM) - _Min_Stack_Size, "Error: Insufficient RAM for system stack!")
```

### 3. 高性能关键函数在 RAM 中的重定位部署 (.fast_code)
在硬实时系统中，许多核心算法（如高频滤波、SPI Flash 擦写算法、FOC 电流环）若在 Flash 中运行，会受到 Flash 等待周期与预取抖动的干扰。通过链接脚本与 C 语言属性声明，可以将特定函数在编译期定位在 Flash 中存储（LMA），并在系统启动时搬移至高速 SRAM 或 ITCM（VMA）中运行：

```ld
/* 链接脚本中自定义快速代码段 */
.fast_code :
{
    . = ALIGN(4);
    _sfast_code = .;        /* SRAM 中的起始执行地址 VMA */
    *(.fast_code)           /* 收集带有 __attribute__((section(".fast_code"))) 的函数 */
    *(.fast_code*)
    . = ALIGN(4);
    _efast_code = .;        /* SRAM 中的结束地址 */
} > RAM AT> FLASH

_sifast_code = LOADADDR(.fast_code); /* Flash 中的物理镜像基址 LMA */
```

在 C 语言中，只需对目标函数追加属性修饰：
```c
/* 强制该函数在 SRAM / ITCM 中以 0 等待周期执行 */
__attribute__((section(".fast_code"), noinline))
void foc_critical_pi_controller(float target, float actual) {
    /* 单周期取指执行，杜绝 Flash 等待周期 */
}
```
启动汇编 CRT0 只需追加一段针对 `_sifast_code` 到 `_sfast_code` 的内存拷贝循环，即可实现任意函数的运行期物理加速。

### 4. 双区 OTA 固件镜像分区链接脚本设计
在支持空中升级（OTA）的工业系统中，片上 Flash 通常被硬划分为 Bootloader 分区、活动槽位（Slot A）与候选升级槽位（Slot B）。针对 Slot A 与 Slot B 编译的固件镜像，其链接脚本必须精确指定运行基地址：

```ld
/* ota_slot_a.ld: Slot A 固件专用链接脚本 */
MEMORY
{
    /* 预留前 128KB 给 Bootloader，Slot A 起始于 0x08020000，长度 448KB */
    FLASH (rx)  : ORIGIN = 0x08020000, LENGTH = 448K
    /* 预留前 16KB 给 Bootloader 与共享 IPC，应用使用剩余 112KB RAM */
    RAM (rwx)   : ORIGIN = 0x20004000, LENGTH = 112K
}
```
通过在链接脚本中显式声明不同的 `ORIGIN`，编译器在生成重定位指令时会自动将绝对函数地址与向量表物理偏移计算到 `0x08020000` 空间，无需任何运行期动态重定位开销。

## 2.4 C 运行时初始化（CRT0）汇编级剖析 {#sec-edge.1.2.4}

在复位向量生效后、跳转执行 `main()` 之前运行的那一小段代码，在计算机体系结构中被称为 **CRT0**（C Runtime Zero）。CRT0 的使命是扫清一切裸机杂质，为标准 C 语言运行环境铺平道路。

### 1. CRT0 必须履行的三项物理铁律
1. **搬移 `.data` 段**：以 `_sidata`（Flash 中的 LMA）为源地址，以 `_sdata`（RAM 中的 VMA）为目的地址，循环拷贝内存，直至到达 `_edata`。若缺失此步骤，所有赋初值的全局变量（如 `int g_timeout = 100;`）在 `main()` 中读取到的都将是 SRAM 上电初期的未定义随机垃圾值。
2. **清零 `.bss` 段**：以 `_sbss` 为起点，以 `_ebss` 为终点，将该连续内存区域全写 `0`。C 语言标准规定所有未显式初始化的全局变量和静态变量其初值恒为 0，这一语言契约完全是由 CRT0 的这段清零循环赋予的。
3. **设置全局指针与调用静态构造函数**：在 RISC-V 体系中，还必须初始化全局指针寄存器 `gp`，以便利用 GP 相对寻址加速全局变量访问；对于 C++ 嵌入式工程，还需遍历执行 `.init_array` 段中的全局对象静态构造函数。

### 2. ARM Thumb-2 架构下的高效 CRT0 汇编实现

```armasm
.syntax unified
.thumb
.global Reset_Handler
.type Reset_Handler, %function

Reset_Handler:
    /* 1. 初始化数据段 (.data): 从 Flash (LMA) 拷贝至 SRAM (VMA) */
    ldr     r0, =_sdata         /* r0 = RAM 中 .data 的起始地址 (VMA) */
    ldr     r1, =_edata         /* r1 = RAM 中 .data 的结束地址 */
    ldr     r2, =_sidata        /* r2 = Flash 中 .data 的原始存储地址 (LMA) */
    movs    r3, #0
    b       .L_check_data_loop

.L_copy_data_loop:
    ldr     r4, [r2, r3]        /* 从 Flash 读取一个 32 位双字 */
    str     r4, [r0, r3]        /* 写入 SRAM 目标位置 */
    adds    r3, r3, #4          /* 偏移指针累加 4 字节 */

.L_check_data_loop:
    adds    r4, r0, r3
    cmp     r4, r1              /* 判断是否到达 _edata 边界 */
    bcc     .L_copy_data_loop   /* 若 r4 < r1 则继续循环拷贝 */

    /* 2. 清零未初始化段 (.bss) */
    ldr     r0, =_sbss          /* r0 = .bss 起始地址 */
    ldr     r1, =_ebss          /* r1 = .bss 结束地址 */
    movs    r2, #0              /* r2 = 清零数值 0 */
    b       .L_check_bss_loop

.L_zero_bss_loop:
    str     r2, [r0]            /* 将当前地址写 0 */
    adds    r0, r0, #4          /* 指针后移 4 字节 */

.L_check_bss_loop:
    cmp     r0, r1              /* 检查是否到达 _ebss */
    bcc     .L_zero_bss_loop

    /* 3. 硬件底层时钟与外设基础初始化 (SystemInit 函数) */
    bl      SystemInit

    /* 4. 遍历调用全局 C++ 对象构造函数 (.init_array 段) */
    ldr     r0, =__init_array_start
    ldr     r1, =__init_array_end
.L_init_array_loop:
    cmp     r0, r1
    bcs     .L_init_array_done
    ldr     r2, [r0], #4
    push    {r0, r1}
    blx     r2                  /* 调用构造函数 */
    pop     {r0, r1}
    b       .L_init_array_loop
.L_init_array_done:

    /* 5. 正式进入 C 语言主世界 */
    bl      main

    /* 6. 防御性陷阱：若 main 函数发生意外返回，在此死循环挂起 */
.L_infinite_loop:
    b       .L_infinite_loop
.size Reset_Handler, .-Reset_Handler
```

### 3. 多寄存器循环展开加速重定位
在配备大容量 RAM 的工业网关中，`.data` 段数据可能达到数十 KB。采用上述单字（4 字节）搬运循环效率较低。在 Thumb-2 指令集中，可以利用多寄存器加载存储指令 `ldmia` / `stmia` 进行 16 字节（4 双字）循环展开加速：

```armasm
/* 4 寄存器展开的高速搬运核心循环 */
.L_fast_copy_loop:
    ldmia   r2!, {r4, r5, r6, r7}   /* 单指令从 Flash 读取 16 字节并自动更新指针 r2 */
    stmia   r0!, {r4, r5, r6, r7}   /* 单指令写入 SRAM 并自动更新指针 r0 */
    cmp     r0, r1
    bcc     .L_fast_copy_loop
```
该指令充分利用了微控制器总线矩阵的突发传输（Burst Transfer）特性，将启动阶段的数据搬运耗时缩短了近 60%。

## 2.5 ARM Cortex-M 启动汇编 (startup.s) 逐行解析 {#sec-edge.1.2.5}

完整的启动汇编不仅包含 `Reset_Handler`，更包含了整个中断系统的**向量表定义**。通过合理使用汇编伪指令与弱符号（Weak Symbol），可以构建出优雅且极易被 C 语言重载的驱动框架。

下表完整列出 ARM Cortex-M 标准向量表必须实现的系统异常：

| 异常编号 | 偏移基址 | 异常类型名称 | 优先级级别 | 异常触发物理原因说明 |
|:--|:--|:--|:--|:--|
| 1 | `+0x04` | `Reset` | -3 (最高) | 上电复位、引脚复位、看门狗复位或软复位 |
| 2 | `+0x08` | `NMI` | -2 | 不可屏蔽中断，通常连接外部电源掉电检测引脚 |
| 3 | `+0x0C` | `HardFault` | -1 | 所有未被分派或未使能处理函数的严重系统故障 |
| 4 | `+0x10` | `MemManage` | 可编程 | MPU 内存保护区域越权访问或在 XN 区域取指执行 |
| 5 | `+0x14` | `BusFault` | 可编程 | 总线访问超时、预取指中止或数据总线校验奇偶错 |
| 6 | `+0x18` | `UsageFault`| 可编程 | 未定义指令、非对齐访问（若使能）或除以零异常 |
| 11 | `+0x2C` | `SVCall` | 可编程 | 由 `SVC` 指令触发的系统调用服务请求 |
| 14 | `+0x38` | `PendSV` | 可编程 | 用于 RTOS 任务上下文切换的可悬起软中断 |
| 15 | `+0x3C` | `SysTick` | 可编程 | 内核系统滴答定时器递减计数到 0 触发 |

在启动汇编中，我们必须特别注意**硬件浮点单元（FPU）的提前使能**。如果编译选项开启了硬件单精度/双精度浮点（`-mfloat-abi=hard -mfpu=fpv4-sp-d16`），而 CPU 尚未开启 FPU 协处理器访问权限，程序在进入 C 语言执行第一条浮点指令时将瞬间抛出 `UsageFault`（未定义指令异常）：

```armasm
/* 在跳转 main 之前，必须在 Reset_Handler 中使能 CP10 与 CP11 浮点协处理器 */
    ldr     r0, =0xE000ED88     /* CPACR (协处理器访问控制寄存器) 物理基址 */
    ldr     r1, [r0]
    orr     r1, r1, #(0xF << 20)/* 设置 CP10 与 CP11 权限为 0b11 (全特权访问) */
    str     r1, [r0]
    dsb                         /* 数据同步屏障 */
    isb                         /* 指令同步屏障，确保浮点流水线就绪 */
```

在汇编中，我们使用 `.weak` 声明将所有外设中断服务函数默认绑定到一个死循环处理例程 `Default_Handler`：

配合上述汇编的 C 语言转储函数能够直接通过串口或 SWD 打印出触发致命崩溃的指令物理地址（PC）与内存故障地址寄存器（BFAR/MMFAR）：

```c
/* 故障现场诊断分析函数 */
void prvGetRegistersFromStack(uint32_t *pulFaultStackAddress, uint32_t *pulSoftwareStackAddress) {
    volatile uint32_t r0  = pulFaultStackAddress[0];
    volatile uint32_t r1  = pulFaultStackAddress[1];
    volatile uint32_t r2  = pulFaultStackAddress[2];
    volatile uint32_t r3  = pulFaultStackAddress[3];
    volatile uint32_t r12 = pulFaultStackAddress[4];
    volatile uint32_t lr  = pulFaultStackAddress[5]; /* 崩溃前调用者函数返回地址 */
    volatile uint32_t pc  = pulFaultStackAddress[6]; /* 发生崩溃的指令物理地址! */
    volatile uint32_t psr = pulFaultStackAddress[7];

    /* 读取可配置故障状态寄存器 (CFSR, 包含 MemManage, BusFault, UsageFault 标志) */
    volatile uint32_t cfsr  = SCB->CFSR;
    volatile uint32_t hfsr  = SCB->HFSR;
    volatile uint32_t mmfar = SCB->MMFAR; /* 内存管理故障访问地址 */
    volatile uint32_t bfar  = SCB->BFAR;  /* 总线故障访问地址 */

    /* 触发系统黑匣子记录并重启 */
    crash_dump_save_and_reboot(pc, lr, cfsr, hfsr, mmfar, bfar);
}
```
这种设计在软件工程上极具弹性：开发者在 C 语言中只需定义普通的 C 函数 `void SysTick_Handler(void) { ... }`，链接器在符号决议（Symbol Resolution）阶段便会自动丢弃汇编中的弱符号版本，无缝建立起硬件向量到 C 业务代码的直接跳转。

## 2.6 RISC-V 启动汇编 (start.S) 逐行解析 {#sec-edge.1.2.6}

与 ARM Cortex-M 硬件自动完成主栈指针装载不同，RISC-V 处理器上电时，所有的 32 个通用寄存器处于未初始化状态。RISC-V 的启动汇编必须手工完成寄存器组清零、全局指针初始化与异常基址配置。

```riscv
/* RISC-V 工业级启动汇编 start.S (针对 RV32I / RV64I) */
.section .init
.global _start
.type _start, @function

_start:
    /* 1. 显式禁用机器模式全局中断 */
    csrci   mstatus, 8          /* 清零 mstatus.MIE */

    /* 2. 手工初始化通用寄存器组 (杜绝带电残留随机位触发模拟器未定义警告) */
    li      x1, 0
    li      x2, 0
    li      x3, 0
    li      x4, 0
    /* ... 依次清零 x5 至 x31 ... */

    /* 3. 配置全局指针寄存器 gp (Global Pointer Relaxation)
     * 利用 GNU 链接脚本导出的 __global_pointer$ 符号
     * RISC-V 编译器能够将 gp 附近 +/- 2KB 内的全局变量编译为极简单指令访问
     */
.option push
.option norelax
    la      gp, __global_pointer$
.option pop

    /* 4. 手工装载主栈顶指针 sp (Stack Pointer) */
    la      sp, _estack

    /* 5. 设置机器模式异常向量基址寄存器 mtvec */
    la      t0, trap_entry
    csrw    mtvec, t0           /* 设置为直接模式：所有异常均跳转至 trap_entry */

    /* 6. 执行 CRT0 内存段拷贝 (.data 搬移与 .bss 清零) */
    la      a0, _sdata          /* 目的起始 */
    la      a1, _edata          /* 目的结束 */
    la      a2, _sidata         /* 源数据地址 (Flash LMA) */
    b       .L_check_data

.L_copy_data:
    lw      t0, 0(a2)
    sw      t0, 0(a0)
    addi    a0, a0, 4
    addi    a2, a2, 4
.L_check_data:
    bltu    a0, a1, .L_copy_data

    /* 清零 .bss */
    la      a0, _sbss
    la      a1, _ebss
    b       .L_check_bss
.L_zero_bss:
    sw      zero, 0(a0)
    addi    a0, a0, 4
.L_check_bss:
    bltu    a0, a1, .L_zero_bss

    /* 7. 调用板级硬件初始化与 main 函数 */
    call    system_init
    call    main

    /* 兜底死循环 */
.L_park:
    wfi                         /* 等待中断休眠 */
    j       .L_park
.size _start, .-_start
```

### 2. RISC-V 向量模式异常向量表实现
下例限定 RV32 的 mtvec 向量模式。同步异常进入 BASE；中断原因码 N 进入 BASE+4×N。
这里 N 是 mcause 的中断原因号，不是 PLIC 的设备源编号；机器外部中断仍需 claim 得到设备号。
MODE 与 BASE 都可能有实现约束，写入后需要核对 WARL 读回，不能假定任意基址都被接受。

```riscv
/* RISC-V 32 位向量模式中断跳转表 */
.section .vectors, "ax"
.option push
.option norvc                   /* 每个向量槽必须恰好 4 字节，不能压缩为 c.j */
.option norelax                 /* 禁止链接松弛改变跳转槽布局 */
.global riscv_vector_table
.balign 64                      /* 本例布局；真实实现可能要求更强基址对齐 */
riscv_vector_table:
    j       handle_sync_exception   /* 0: 同步异常 (Environment Call / 缺页 / 断点) */
    j       handle_reserved         /* 1: 保留 */
    j       handle_reserved         /* 2: 保留 */
    j       handle_msip_irq         /* 3: 机器模式软件中断 (MSIP) */
    j       handle_reserved         /* 4: 保留 */
    j       handle_reserved         /* 5: 保留 */
    j       handle_reserved         /* 6: 保留 */
    j       handle_mtip_irq         /* 7: 机器模式时钟定时器中断 (MTIP) */
    j       handle_reserved         /* 8: 保留 */
    j       handle_reserved         /* 9: 保留 */
    j       handle_reserved         /* 10: 保留 */
    j       handle_meip_irq         /* 11: 机器模式外部硬件中断 (MEIP / PLIC) */
.option pop
```
每个槽只执行跳转，目标还必须提供正确的上下文保存与返回。
这些 JAL 形式跳转也有可达范围，超出时需要保持槽宽的近端入口。
向量模式可以减少入口分发，却不证明单周期响应，也不替代 PLIC 源分发。
本例尚无该向量表的目标运行证据，不能用第四章协作切换或第七章乘法测试补足。

## 2.7 内存保护单元（MPU / PMP）安全配置实战 {#sec-edge.1.2.7}

在系统完成 CRT0 数据段准备后、正式切入用户多任务执行前，必须启动物理内存保护单元。这是划分系统特权域与非特权应用域的关键一道硬件防火墙。

### 1. ARMv8-M MPU 四层静态安全分区方案
在一个具备高可靠性要求的嵌入式节点中，物理内存至少应划分为以下四个严密隔离的区域：
1. **Region 0 (Flash Code)**：基址 `0x0800_0000`，只读执行（`AP=10`，特权只读；`AP=11`，非特权只读），允许指令取指（`XN=0`）。
2. **Region 1 (SRAM System Kernel)**：基址 `0x2000_0000`，特权级全读写，非特权级严禁访问（`AP=00`），`XN=1`。
3. **Region 2 (SRAM User Task)**：基址 `0x2001_0000`，特权与非特权均可读写（`AP=01`），严禁取指执行（`XN=1`，彻底防御栈溢出 shellcode 注入）。
4. **Region 3 (Peripherals MMIO)**：基址 `0x4000_0000`，外设寄存器区，配置为 Device 内存属性（严禁任何 Cache 缓存与缓冲写合并），特权读写（`AP=00`）。

### 2. RISC-V PMP (Physical Memory Protection) 寄存器编程
RISC-V 采用紧凑的 CSR 寄存器组来表达物理保护规则：

```riscv
/* 汇编配置 RISC-V PMP: 保护机器模式代码段不可被用户态篡改 */
.global setup_pmp_security
setup_pmp_security:
    /* 1. 设置 pmpaddr0 为 Flash 代码段边界 (0x8000_0000 ~ 0x8004_0000)
     * 采用 NAPOT 模式 (自然对齐的 2 的幂次方, 256KB 空间)
     */
    li      t0, 0x80000000 >> 2
    li      t1, (256 * 1024 / 8) - 1
    or      t0, t0, t1
    csrw    pmpaddr0, t0

    /* 2. 配置 pmpcfg0 的条目 0:
     * R=1 (可读), W=0 (禁止用户态写入!), X=1 (可执行), A=3 (NAPOT 模式)
     * 数值: A=11, X=1, W=0, R=1，即 0b00011101 = 0x1D
     */
    li      t2, 0x1D
    csrw    pmpcfg0, t2

    ret
```

### 3. PMSAv7 与 PMSAv8 不可混配

Cortex-M7 的常见 MPU 属于 PMSAv7，使用 RASR 等规则，不是本节 ARMv8-M 的 RBAR/RLAR 模型。
若使用 M33 等实现 PMSAv8 的目标，应先核实区域数量，再配置不重叠的授权区间。
AP=00 是特权可读写、非特权禁止；AP=10 是特权只读、非特权禁止。
所有模式只读应使用 AP=11。
RLAR 地址位要先清除低 5 位，再写 AttrIndx 和 EN；直接 OR 未掩码的 0x...FFFF 会污染属性索引。
MAIR 定义必须与各区域 AttrIndx 一一匹配。
配置 guard 时，还要检查特权默认背景映射和栈指针跳跃越界。

| 审查对象 | PMSAv7 | PMSAv8 |
|:--|:--|:--|
| 区域尺寸 | 基址与幂次方 SIZE 编码 | 基址与 LIMIT 区间 |
| 权限字段 | RASR.AP，编码不同 | RBAR.AP |
| 内存属性 | TEX/C/B/S 等 | MAIR 属性索引 |
| 重叠规则 | 常见高编号区域优先 | 不得照搬高编号覆盖策略 |

这里不再提供把 M7 和 M33 混用的初始化函数。
选择具体开发板后，应使用对应 CMSIS 结构、偏移断言及越权访问故障注入，而不是依赖看起来相似的字段名。

## 2.8 agent 错误案例：链接脚本未对齐导致 DMA 缓冲区跨越 Cache 行或触发 HardFault {#sec-edge.1.2.8}

### 现象
某团队利用 AI 助手设计了一套高性能以太网与高速 SPI 数据采集系统。为了优化内存占用，Agent 在链接脚本中编写了自定义的段排布规则。固件编译通过且能正常启动，但在运行过程中突发极其诡异的随机故障：
1. 系统偶尔触发不可解释的 `HardFault`，硬件故障状态寄存器指示为精确数据访问总线错误（`PRECISERR`）；
2. 外设通过 DMA 接收到的大容量数据包，其开头的前几个字节经常出现随机字节被覆写翻转。

### 根因
排查发现，Agent 生成的链接脚本片段如下：

```ld
/* Agent 编写的有缺陷链接脚本片段 */
.custom_dma_buffer :
{
    _s_dma_buf = .;
    *(.dma_section)
    _e_dma_buf = .;
} > RAM AT> FLASH

.text :
{
    *(.text)
} > FLASH
```

这段脚本埋下了两个灾难性隐患：
1. **缺失 ALIGN(4) 导致 LMA 奇数地址引发硬件总线异常**：
   在 `.custom_dma_buffer` 段的前后，Agent **没有显式声明 `. = ALIGN(4);`**。链接器在将前一个段的末尾与本段拼接时，前一个段的字节长度恰好为奇数（例如 103 字节）。结果，`.data` 或 `.custom_dma_buffer` 的加载地址（LMA）被分配在了一个奇数物理地址（如 `0x0800_0167`）。
   当启动汇编 CRT0 执行 32 位双字读取指令 `ldr r4, [r2]` 尝试从 Flash 拷贝数据时，由于硬件不支持或禁用了非对齐字读取，总线接口瞬间抛出总线错误（BusFault），直接升级为致命的 `HardFault`。
2. **未对齐 Cache Line (32 字节) 导致 DMA 缓存污染翻转**：
   在开启一级数据缓存（D-Cache）的高性能 MCU（Cortex-M7 / RV64）上，DMA 缓冲区与常规局部变量在物理内存上紧挨在一起。如果 DMA 缓冲区的起始地址不是 32 字节（Cache Line 尺寸）整数倍，那么该缓冲区的前几个字节将与外部常规变量**共享同一个 Cache Line**！
   当 CPU 更新相邻的普通变量并执行 Cache 回写（Clean）时，CPU 会将整整一行（32 字节）强制刷入物理 SRAM，直接将在那几个字节中已经被 DMA 控制器写入的最新传感器数据粗暴覆盖掉！

### 如何发现
1. **查看链接映射文件（`.map` 文件）**：使用 `arm-none-eabi-readelf -S firmware.elf` 或直接查看 GCC 输出的 `firmware.map`。检索自定义段的起始物理地址，若发现地址低两位不为 0（如 `0x20000021`），即可确认为对齐缺陷。
2. **利用断言检查**：在 C 代码初始化阶段加入指针宏断言：
   `assert(((uintptr_t)g_dma_rx_buf & 0x1F) == 0);`。

### 修复
必须在链接脚本中，在**每一个段的入口与出口处强制声明对齐**。对于涉及 DMA 与 Cache 的特殊缓冲区，必须强制按 32 字节对齐：

```ld
/* 修复后的高鲁棒性链接脚本片段 */
.custom_dma_buffer (NOLOAD) :
{
    . = ALIGN(32);          /* 强制起始地址按 Cache Line (32字节) 严格对齐 */
    _s_dma_buf = .;
    *(.dma_section)
    *(.dma_section*)
    . = ALIGN(32);          /* 强制结束地址填充至 Cache Line 边界，杜绝变量共享 Cache Line */
    _e_dma_buf = .;
} > RAM
```

配套实验请直接在终端执行 `bash experiments/ch02/run.sh`。
该入口同时执行主机内存重定位模型、QEMU Cortex-M3 与 RV32 目标机启动固件，并通过破坏性变异脚本（`experiments/ch02/run_mutations.sh`）验证跳过数据搬移与 BSS 污染均能被目标机自检明确捕获。

## 2.10 本章陷阱 {#sec-edge.1.2.10}

::: errata 本章陷阱

1. **链接脚本导出符号被当成普通 C 变量取值**：在 C 代码中编写 `extern uint32_t _sdata;`，并直接使用 `_sdata` 的值作为地址。现象：指针指向了不可预知的乱码内存导致崩溃。原因：链接脚本中导出的符号**本身没有分配存储空间**，符号名代表的就是该物理地址本身！修复：在 C 代码中必须对其取地址：`uint32_t* p = &_sdata;`。
2. **向量表中 Reset_Handler 地址 Bit 0 遗漏置 1**：在手工编写二进制向量表或自制 Bootloader 跳转时，直接填入偶数地址 `0x0800_0100`。现象：CPU 上电复位的第一周期立即触发 `HardFault` 或锁定（Lockup）。原因：Cortex-M 架构强制要求向量地址最低位为 1 以指示 Thumb 状态。修复：跳转或填充向量时强制与 `1` 执行按位或：`vector_addr | 1`。
3. **CRT0 清零 BSS 段时发生地址越界回绕**：链接脚本中 `_sbss` 恰好等于 `_ebss`（程序没有未初始化全局变量）。编写的汇编清零循环使用 `do-while` 结构先写一次。现象：SRAM 全区被无辜清零 4GB，破坏已拷贝的 `.data` 段。原因：缺失入口合法性前置检查。修复：清零前先比较 `_sbss` 与 `_ebss`，若相等直接跳过清零。
4. **遗漏在 Flash 与 RAM 段之间执行 ALIGN(4)**：在链接脚本定义段时未显式对齐。现象：启动汇编中执行 `ldr/str` 四字节搬运时突发对齐异常总线错误。原因：前一段的字节长度非 4 整数倍导致后一段首地址落在奇数边界上。修复：每一个段的内部及尾部必须紧随 `. = ALIGN(4);`。
5. **在 MPU 未禁用时动态配置 MPU 区域**：直接通过寄存器改写运行中 MPU 的 `RBAR` 或 `RLAR`。现象：改写的一瞬间当前正在执行的代码被误判定为越权，瞬时触发不可恢复的 `MemManage` 异常。原因：配置过程破坏了当前代码段的保护规则。修复：配置 MPU 必须遵循“DMB屏障 $\to$ 禁用 MPU $\to$ 修改区域 $\to$ 重新使能 $\to$ DSB/ISB 流水线刷新”标准序列。
6. **将 CCMRAM/DTCM 分配给外设 DMA 控制器**：在链接脚本中将以太网或 ADC 的 DMA 接收缓冲段定义在 Cortex-M4 的 CCMRAM（基址 `0x1000_0000`）中。现象：DMA 传输完成后缓冲区内容全为 0，外设报总线错误。原因：CCMRAM 在微架构物理总线上直接直连 CPU 核心，**根本没有挂载到系统 AXI/AHB 总线矩阵上**，DMA 控制器物理上无法寻址该区域。修复：DMA 缓冲区必须严格分配在通用 SRAM1/2 或 AXI-SRAM 中。
7. **重定位后未执行指令同步屏障 (ISB)**：若程序在 RAM 中动态解压或从 Flash 拷贝了一段新代码并试图跳转执行。现象：CPU 执行到旧内存残留指令或触发未定义指令。原因：指令缓存（I-Cache）与流水线中预取的依然是未更新前的陈旧代码。修复：在代码重定位完成后、跳转执行前，必须显式调用 `__ISB()` 指令同步屏障与 I-Cache 无效化指令。
8. **链接脚本中栈顶符号设置错误导致溢出**：在链接脚本中定义 `_estack = ORIGIN(RAM) + LENGTH(RAM);`，但未保留 8 字节对齐。现象：首次函数调用即因为栈指针未满足 `SP % 8 == 0` 触发 UsageFault。修复：强制对栈顶符号取整：`_estack = ALIGN(ORIGIN(RAM) + LENGTH(RAM) - 8, 8);`。
9. **RISC-V 启动时遗漏配置全局指针 gp**：在启用链接器松弛优化（Linker Relaxation）的工程中未初始化 `gp`。现象：访问全局变量时 CPU 读取到了基地址 0 附近的未映射内存。原因：编译器将 `la` 指令优化为了基于 `gp` 的单周期相对寻址指令。修复：启动汇编首部必须执行 `.option norelax; la gp, __global_pointer$; .option pop`。
10. **忘记将中断向量表重定位寄存器 VTOR 指向新地址**：在编写 Bootloader 并跳转到应用程序后，忘记修改 `SCB->VTOR`。现象：应用程序运行中只要发生中断，CPU 依然跳转回 Bootloader 所在的 Flash 首部去执行中断函数，引发系统逻辑错乱。修复：在中断开放前按既定移交合同安装应用向量表，并核对完整表大小所需对齐、挂起源、MSP 与入口状态；不能只要求应用启动首行写一个固定地址。
11. **链接脚本遗漏 KEEP 关键字导致关键中断向量被删除**：开启 GCC 的 `-Wl,--gc-sections` 死代码裁剪选项时，未在链接脚本的 `.isr_vector` 上加 `KEEP`。现象：生成的二进制镜像没有任何中断向量表，芯片上电直接变砖。原因：中断向量表没有被任何 C 代码显式调用，被链接器判定为无用代码直接剔除。修复：在链接脚本中强制声明 `KEEP(*(.isr_vector))`。
12. **C++ 工程中 CRT0 遗漏调用静态构造函数列表**：在裸机运行 C++ 代码时，CRT0 拷贝完 `.data` 后直接跳入 `main()`。现象：全局对象中的成员变量未初始化，虚函数表指针为 NULL，调用对象方法直接死机。原因：C++ 全局对象的构造函数指针被编译器归类放置在 `.init_array` 链接段中，必须由启动代码主动循环遍历调用。修复：在进入 `main()` 前遍历并执行 `__init_array_start` 至 `__init_array_end` 中的函数指针。

:::

::: method 即时自测 {#method-edge.1.2.11.1}
**自测题**：
某团队开发了一款基于 ARM Cortex-M4 的电机驱动器。在链接脚本中，工程师将 `.data` 段的配置写为：
```ld
.data : {
    _sdata = .;
    *(.data*)
    _edata = .;
} > RAM
```
固件编译成功且大小正常。烧录至芯片后，程序能够启动并运行，但所有定义在全局作用域的配置参数（例如 `float g_kp = 12.5f; int g_max_speed = 3000;`）在 `main()` 函数中打印出来全是一堆无意义的乱码数值。请指出链接脚本中的致命缺陷，并说明为什么代码可以编译运行却没有正确数值。

::: sol
**解题思路与标准答案**：
1. **致命缺陷**：
   - 链接脚本中 `.data` 段缺失了 `AT> FLASH` 声明！
2. **根因剖析**：
   - 在缺乏 `AT> FLASH` 指定时，链接器默认将该段的加载地址（LMA）等同于其运行地址（VMA），即认为该段在下载时直接烧录到物理 RAM（`0x20000000`）中。
   - 然而在物理微控制器中，RAM 属于易失性存储介质，芯片断电后数据彻底丢失；固件烧录工具（如 J-Link 或 ST-Link）只能将二进制镜像写入片上 Flash（`0x08000000`）。
   - 结果，全局变量的初始值数据根本没有被打包写入 Flash 中；而启动汇编中的 CRT0 依然试图从未定义的 Flash 区域拷贝数据，或者根本无法找到合法的 LMA 来源，导致写入 RAM 的全是从未初始化的存储体读出的硬件随机物理噪声。
3. **正确写法**：
   - 将链接脚本修改为：`.data : { ... } > RAM AT> FLASH`，并在 Flash 中导出 `_sidata = LOADADDR(.data);` 供 CRT0 搬移使用。
:::
