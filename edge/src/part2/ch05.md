第四章的任务切换只能保证某条线程获得处理器。
设备是否已经看到命令，数据是否已经进入 CPU 可见的内存，是另一套合同。
一条 C 赋值语句可能只修改寄存器，也可能触发一次具有副作用的总线事务。
DMA 又会绕过当前线程，以独立总线主设备身份读写内存。

本章从访问语义进入外设，不从晶体管或门电路展开。
UART 使用一个可执行的 LM3S/QEMU 接口实例。
SPI/I2C 寄存器表以 STM32F407 的传统控制器为参照，不宣称适用于所有 STM32。
DMA、Cache 和两线仲裁的模型明确标为 MODEL。
这些模型不冒充 QEMU 已实现某块芯片的 DMA 总线。

读者得到两类可运行证据。
第一类是实际 ARM 指令、MMIO、NVIC IRQ5 与串口字符注入。
第二类是协议和所有权状态机的确定性反例。
本轮没有实体板卡电流、示波器或逻辑分析仪采样结果。

## 5.1 地址、访存宽度与寄存器副作用 {#sec-edge.2.5.1}

### 三套 ISA，不是三套 C 指针强转

ARM 与标准 RISC-V 设备通常映射到物理内存地址空间。
访问形式看起来与普通 RAM 相似，但物理目标与内存属性不同。
x86 既有独立 I/O 端口空间，也广泛使用 MMIO。
不能从“x86 支持 IN/OUT”推出“x86 设备不用 MMIO”。

| 架构 | 访问路径 | 指令形态 | 需要额外确认 |
|:--|:--|:--|:--|
| x86-64 port I/O | 16 位端口号空间 | in、out | IOPL/TSS 权限、访问宽度 |
| x86-64 MMIO | 普通地址空间中的设备映射 | mov 等 | PAT/MTRR 属性、posted write |
| AArch64 MMIO | Device 类型页映射 | ldr/str 等 | 页属性、共享域、平台排序规则 |
| Cortex-M MMIO | 固定物理区域 | ldr/str 等 | 默认映射、MPU 配置、总线宽度 |
| RISC-V MMIO | 平台定义的设备地址 | load/store | PMA/PMP、I/O 排序及 FENCE 域 |

以下表示“对一个允许 32 位访问的寄存器执行一次写入”。
它不是可以随意套在 8 位 FIFO 或 16 位寄存器上的宏。

```c
#include <stdint.h>

static inline void mmio_write32(uintptr_t address, uint32_t value) {
    *(volatile uint32_t *)address = value;
}

static inline uint32_t mmio_read32(uintptr_t address) {
    return *(volatile uint32_t *)address;
}
```

编译器会保留这些 volatile 访问的可观察副作用。
但这不定义整个硬件系统中的完成时刻。
也不自动生成适用于任意设备的缓存维护指令。
设备区内存属性不能靠 C 类型修饰符设置。

### 三类常见寄存器语义

::: def 寄存器访问合同 {#def-edge.2.5.1.1}
读写寄存器之前，应同时给出地址、宽度、许可访问类型和副作用。
“rw”只说明一部分。
FIFO 的读会弹出数据，W1C 的写会清除标志，读状态寄存器可能参与一个多步确认序列。
这些行为决定了能否使用读改写，不能仅凭寄存器名字猜测。
:::

| 类型 | 读的作用 | 写的作用 | 危险写法 |
|:--|:--|:--|:--|
| 普通配置 rw | 返回当前配置 | 改变配置 | 多写者同时读改写 |
| W1C 状态 | 返回当前标志 | 写 1 清指定位 | `status |= bit` 可能误清其他位 |
| FIFO data | 弹出一个元素 | 推入一个元素 | 调试器自动读取或 memcpy |
| read-to-clear | 读取即确认/清除 | 依设备定义 | 为打印日志额外读取一次 |
| set/clear 别名 | 可返回状态 | 原子置位/清位 | 将别名当普通内存缓存 |

W1C 典型正确形式是直接写清除掩码。
不是先把全寄存器读回再 OR。
如果读回时其他事件位也为 1，读改写可能把它们一起清掉。

### 对齐不是 packed 就解决

母本介绍 packed 可减少结构体填充。
但设备寄存器的空洞往往是手册要求的地址保留区。
用 packed 把空洞压没，反而破坏物理偏移。
packed 成员还可能诱导编译器生成非对齐或字节访问。

正确的寄存器结构通常保留明确的 RESERVED 字段。
然后用 offsetof 检查关键偏移。
不要把普通网络报文的紧凑布局策略照搬到 MMIO。

```c
#include <stddef.h>
#include <stdint.h>

typedef struct {
    volatile uint32_t DR;
    volatile uint32_t RSR_ECR;
    uint32_t reserved0[4];
    volatile uint32_t FR;
} UartPrefix;

_Static_assert(offsetof(UartPrefix, FR) == 0x18, "UART flag offset");
```

此例只表达 UART 前缀结构和偏移，不是完整设备头文件。
本章运行固件使用显式地址宏，便于直接对照手册和反汇编。
它没有把所有 Cortex-M 外设误认为同一套厂商寄存器。

### 中断使能有三层

设备内部 mask、NVIC/PLIC 使能、处理器全局中断使能都要满足。
任何一层关闭，设备状态都可能积压。
仅看到 ISR 不运行，不能马上归因为向量地址错误。
诊断顺序应从设备 raw status 开始，再看 mask 后状态，再看控制器 pending。
最后确认当前处理器屏蔽和优先级。

### 总线错误要保留操作上下文

记录地址、访问宽度、读写方向、设备时钟门控状态。
还需记录故障 PC 与精确/非精确属性。
写缓冲延迟错误时，PC 可能已越过实际出错指令。
在调试器里反复读 FIFO 不会帮助复现原始状态。
应使用受控的原始寄存器快照策略。

## 5.2 DMA：所有权、完成事件与可复用缓冲区 {#sec-edge.2.5.2}

### DMA 是另一个总线主设备

CPU 把数据写到缓冲区，再写 DMA 描述符，再敲门铃。
设备并不理解 C 语言对象的生命周期。
它只看到地址、长度、控制位与下一描述符地址。
栈上局部数组返回后失效，DMA 仍可能继续访问旧地址。

本章采用两块 256 B 的示意缓冲区。
每块只有一个所有者。
所有者状态如下：

<pre class="layout" id="fig-edge-ch05-dma-owner">
FREE ──arm──► DMA ──transfer complete──► READY
  ▲                                      │
  │                                      │ CPU acquire
  │                                      ▼
  └──────── release(generation) ───────── CPU

DMA 只写 DMA-owned 槽
CPU 只读 CPU-owned 槽
READY 不代表 FREE
旧 generation 不能释放已复用的新数据
</pre>
读图：一个完成中断只是把槽交给消费者，不意味着可以立即重新交给 DMA。
若 CPU 还在读取上一块数据，DMA 不能覆盖它。
零拷贝省去了复制，但没有取消所有权交接。

### STM32F407 DMA stream 寄存器参照

DMA2 的访问范围和外设请求映射与 DMA1 不完全相同。
不能只复制某个 stream 编号而不核对通道映射表。
下表只描述 stream 的寄存器合同。
本章不声称已经在实体 F407 上运行这条 DMA 路径。

| stream 相对偏移 | 寄存器 | 关键字段 | 编程约束 |
|:--|:--|:--|:--|
| +0x00 | SxCR | EN、DIR、MINC、PINC、MSIZE、PSIZE、PL、CHSEL | 许多字段仅在 EN=0 时可修改 |
| +0x04 | SxNDTR | NDT[15:0] | 数量单位按传输宽度定义，不一定是字节 |
| +0x08 | SxPAR | 外设地址 | 核对地址是否能被该 DMA 主端口访问 |
| +0x0C | SxM0AR | memory 0 地址 | 对齐和所在总线域必须合法 |
| +0x10 | SxM1AR | memory 1 地址 | 双缓冲模式中有实际作用 |
| +0x14 | SxFCR | DMDIS、FTH、FS、FEIE | FIFO 配置影响突发与错误处理 |

stream 0 基址相对 DMA 控制器通常为 +0x10。
stream 间隔为 0x18。
清除中断标志使用相应的 LIFCR/HIFCR 掩码。
不同 stream 的标志偏移并非简单按相同连续位组排列。

### 安全启动次序

1. 保证缓冲区仍然有效且已被本次事务独占。
2. 检查设备 DMA 请求暂时关闭。
3. 关闭 stream，并等 EN 确认清零。
4. 给等待设置真实超时，不能死循环。
5. 清除该 stream 的历史完成与错误标志。
6. 写 PAR、M0AR、必要的 M1AR。
7. 写 NDTR 和传输宽度。
8. 配置方向、递增、通道、优先级与 FIFO。
9. 完成平台要求的 Cache 维护和屏障。
10. 使能 stream，再按手册使能外设请求。

步骤顺序可能因控制器不同而变化。
使用链式描述符的 AXI DMA 或其他 IP 时应查其 OWN 位协议。
本章不会将 stream 寄存器强行套在所有 DMA 上。

### 中断的四种状态

| 事件 | 含义 | 应更新的状态 | 不能直接推断 |
|:--|:--|:--|:--|
| HT | 一半传输单位完成 | 可交付半块 | 全部缓冲区稳定 |
| TC | 计数器完成 | 可交付指定块 | SPI 最后一位已出线 |
| TE | 传输错误 | 停止并记录剩余计数 | 重启即可无损续传 |
| FIFO/direct error | 模式或总线问题 | 按错误协议中止 | 用户数据仍完整 |

TC 后外设移位寄存器可能仍忙。
UART DMA 完成与 UART TC 标志不是同一事件。
SPI DMA 完成后也须处理外设 BUSY、RX 残留及片选时序。
否则最后一个字节仍在传输时就可能释放 CS。

### 代际号的用途

消费者保存 acquire 时拿到的 generation。
归还时检查该 generation 是否仍属于当前事务。
若持有的旧 token 指向已经复用的槽，release 必须拒绝。
这是防御悬挂描述符的一种办法，不是内存安全万能机制。
多核场景还须用正确的原子与硬件一致性协议保护状态字段。

本章主机模型假设状态转换串行执行。
它验证非法覆盖与过期 token 的拒绝。
没有宣称模型本身就是并发 DMA 驱动。

## 5.3 屏障与 Cache：顺序不等于数据已经写回 {#sec-edge.2.5.3}

### 四个不同问题

| 问题 | 工具 | 不负责的内容 |
|:--|:--|:--|
| 编译器是否保留设备访问 | volatile 或目标访问器 | CPU 总线完成 |
| 普通线程是否正确发布对象 | C11 acquire/release | 非一致性 DMA Cache |
| 设备与普通内存访问顺序 | 目标屏障/访问器 | 自动清理所有 Cache |
| DMA 与 CPU 是否看到新数据 | clean/invalidate、共享属性或一致性硬件 | 应用所有权 |

把四个问题缩成一个 `__DSB()` 会掩盖缺失的合同。
DSB 可以等待规定范围内的操作完成。
它不会凭空遍历所有 dirty Cache line 并写回。
缓存维护指令必须针对正确的地址和作用域发出。

### ARM 的 DMB、DSB、ISB

DMB 用于规定内存访问的观察顺序。
DSB 进一步约束规定范围内的完成与后续执行。
ISB 用于让后续指令按新的执行上下文重新取得。
具体作用域和访问类型参数必须与平台匹配。

AArch64 的 `dmb ish` 与 `dmb oshst` 不是可以任意互换的装饰。
CPU 核之间的共享域与 DMA 主设备所在的一致性域不一定相同。
某平台可能需要外部共享域或全系统域。
应由平台访问器提供经验证的协议，而不是从用户态自旋锁例子照抄。

### RISC-V 的 FENCE 位域

RISC-V 把设备输入、设备输出、普通内存读写分别表达为 I、O、R、W。
`fence rw,rw` 不自动代表全部设备 I/O 都已按要求排序。
门铃前需要考虑前驱普通写与后继设备输出。
具体器件的 PMA 与 posted write 语义仍需平台说明。

CSR 原子修改也不是 DMA 内存屏障。
`csrw mie` 只修改相应 CSR。
不能因为中断配置写入是原子的，就推断之前的数据已经到达 DMA 可见 RAM。

### x86 TSO 的适用边界

缓存一致的普通 WB 内存中，许多 release/acquire 不需额外硬件 fence。
但这仍应通过语言原子或经验证的内核访问器表达。
WC 映射、非临时写、设备 posted write 都有自己的顺序规则。
不能把“x86 强序”当成所有 MMIO 与 DMA 的免审查通行证。

### 一个明确的非一致性反例

本章模型用两个独立数组表示 CPU Cache 视图和 DMA RAM 视图。
这是有意简化的机制模型，不模拟真实 Cache 组相联结构。

```text
初态：cache[0] = 0，ram[0] = 0
CPU 写 cache[0] = 0x55
仅加屏障：ram[0] 仍为 0
执行模型 clean：ram[0] = 0x55
DMA 写 ram[0] = 0xA3
CPU 未失效：cache[0] 仍为 0x55
执行模型 invalidate/refill：cache[0] = 0xA3
```

运行实验会逐项断言以上结果。
“屏障没有改变数组”不是架构性能测量。
它用明确分离的视图表示 cache clean 是另一项操作。
代码不会假称宿主机器真的发生了非一致性 DMA。

### Cache 行共享破坏

DMA 改了 ram[1]。
CPU 改了同一行内的 cache[2]，使整行变脏。
CPU 随后把整行写回 RAM。
cache[1] 中的旧值可能覆盖刚到达的 DMA 数据。
因此仅把缓冲区首地址对齐仍不充分。
末端、相邻变量、描述符和维护范围也必须隔离。

如果 Cache line 为 32 B，维护区间通常要向外取整。
这个向外取整不能触及另一个仍被 CPU 修改的共享对象。
正确设计是隔离分配和所有权，而不是在任意地址上扩大 invalidate 范围。

::: ex 示例 5.3.1 · 256 B 双缓冲的时间预算 {#ex-edge.2.5.3.1}
两通道、每通道 100 ksample/s、每样本 16 bit，数据率为 400000 B/s。
256 B 缓冲块的填充时间为 640 us。
CPU 若每块必须独占读取 700 us，长期平均消费率低于生产率。
两个缓冲区只能短暂吸收差值，不能从数学上保证无限期零丢帧。
降低计算量、降低采样率、增加可容忍延迟或实施背压，至少要改变其中一项。
:::

这组数字是设计预算，不是某 ADC 的实测速率。
另外还没计入包头、CRC、对齐和总线争用。
项目验收必须给实际工作负载与持续时间。

## 5.4 UART：帧预算、寄存器和一次真正的 IRQ 接收 {#sec-edge.2.5.4}

### 线上帧与接收时间

8N1 每个字节占一个起始位、8 个数据位、一个停止位。
总计 10 bit。
在 3 Mbaud 下，一个字节需 10/3 us。
16 字节 FIFO 的纯理想容量对应约 53.33 us。
这个值不是允许 IRQ 屏蔽 53.33 us 的可靠安全线。
还需给已有占用、触发阈值和时钟误差留余量。

<pre class="layout" id="fig-edge-ch05-uart-frame">
空闲   start   D0 D1 D2 D3 D4 D5 D6 D7   stop
  1  ──┐ 0   ┌───────────────────────┐   1
       └─────┘   LSB first          └──────

8N1：一帧 10 位
0x55：数据位从 D0 起交替为 1,0,1,0,1,0,1,0
协议不提供仲裁：两个推挽发送端不能直接并线竞争
</pre>
读图：UART 没有 SPI 那样的同步 SCK，接收器依靠起始位和采样时钟重建位边界。
这里是逻辑示意，不是本轮采集的电压波形。

### LM3S UART0 寄存器表

QEMU `lm3s6965evb` 的 UART0 地址从 `0x4000C000` 开始。
寄存器族与 PL011 风格相近，但芯片集成细节仍要看 LM3S 手册。
不要拿该地址去配置 STM32 USART。

| 相对地址 | 寄存器 | 字段 | 本例用途 |
|:--|:--|:--|:--|
| +0x00 | DR | DATA[7:0]、错误[11:8] | 读取一个字节并检查错误位 |
| +0x18 | FR | RXFE bit4、TXFF bit5 | RX 非空时读，TX 非满时写 |
| +0x24 | IBRD | 整数分频 | 写 6 |
| +0x28 | FBRD | 小数分频[5:0] | 写 33 |
| +0x2C | LCRH | WLEN、FEN 等 | 8 位、无奇偶、1 停止位，关闭 FIFO |
| +0x30 | CR | UARTEN、TXE、RXE | 使能收发 |
| +0x38 | IMSC | RXIM bit4、RTIM bit6 | 接收与接收超时中断 mask |
| +0x40 | MIS | mask 后中断状态 | 调试时可读，不是 DR |
| +0x44 | ICR | RXIC、RTIC | 写 1 确认相应中断 |
| +0x48 | DMACTL | RXDMAE、TXDMAE 等 | 本轮不使能 |

本例使用 QEMU 初始化的时钟环境。
若参考时钟为 12 MHz，则分频组合为 6+33/64。
理想公式为 baud=f_uart/(16×divisor)。
计算得到的速率是配置推导，不是线上采样结果。
实体板上必须确认参考时钟实际来源与误差。

### 为什么关闭 FIFO

这次测试只注入两个独立字节，验证 IRQ5 路径。
关闭 FIFO 可避免一字节低于接收阈值而只等待超时中断的歧义。
宿主逐字节发送并等待一段时间，降低宿主突发写入导致的模型溢出。
这不是高吞吐 FIFO 压力测试。
也不是对 DMA 接收功能的验证。

### ISR 中发生了什么

`firmware/ch05/main.c` 的 UART0_Handler 循环读 DR，直到 RXFE 为 1。
每个读出的字包含数据和错误标志。
收到的两个字必须依次为 0x55、0xA3。
ISR 更新计数，然后确认接收与超时标志。
返回前执行 DSB。

主循环只观察 ISR 更新的计数，不读取 DR。
因此 PASS 依赖中断路径确实执行。
若把 NVIC IRQ5 使能删除，测试会超时失败，而不是轮询 DR 偷偷完成。
本章没有使用一个名为 IRQ 的普通主机函数来冒充硬件中断。

### 接收错误的分层

| 错误 | 线上或缓冲区原因 | 应保留的证据 | 恢复方向 |
|:--|:--|:--|:--|
| framing | 停止位不符合预期 | DR 错误位、波特率配置 | 校验时钟与格式 |
| parity | 奇偶校验失败 | 帧内容及模式 | 记录错误，丢弃或上报 |
| break | 线路保持低电平 | 持续时间、接收状态 | 按协议解释或重同步 |
| overrun | 软件未及时清 FIFO | 累计溢出计数与屏蔽时间 | 修正服务预算与缓冲策略 |
| 软件队列满 | ISR 到任务通道不足 | FIFO 与队列分别计数 | 背压、扩容或有界丢弃 |

QEMU 字符通道不提供真实噪声、电压或采样偏移。
本例检查错误位路径，但没有声称物理 parity/framing 故障注入已完成。
上线前仍需真实串口仪器测试。

### 靶机初始化检查表

在实体 LM3S 板上复用该固件之前，需要增加以下核验。
QEMU 的默认外设初始化不能被当作芯片上电复位值。

1. 核实系统主时钟和 UART 参考时钟的真实来源。
2. 配置 UART0 所在 GPIO 的数字功能与复用，而不是只开启 UART 时钟。
3. 读取芯片规定的外设就绪状态，避免门控开启后立即访问尚未就绪端口。
4. 确认 RX/TX 引脚电平标准与外部转换器兼容。
5. 测试断线、错误波特率、break 与连续接收时的错误计数。
6. 禁用 semihosting 后提供真正的故障日志与复位出口。

本轮脚本验证的是 QEMU 设备模型，以上实体接线与时钟步骤仍须按板卡完成。
把模型固件称为“无需更改即可量产”的驱动是不准确的。

### DMA 的接收边界

固定长度 DMA 适合已知帧长度。
可变长协议常用循环 DMA 与空闲事件，但空闲并不天然等于应用包结束。
若协议允许包内长间隔，必须按长度、分隔符或 CRC 重组。
读取 NDTR 快照时还要考虑正在发生的回绕。
应用消费索引不能越过已经确认写入的数据。

UART TX DMA 完成只表示内存交付给外设。
控制 RS-485 DE 时，必须等最后一个停止位发送完成，再满足总线转向时间。
不能在 DMA TC 里立刻拉低 DE。

## 5.5 SPI：CPOL/CPHA、全双工与事务完成 {#sec-edge.2.5.5}

### 先命名边沿

leading edge 表示 SCK 离开空闲电平的第一边沿。
trailing edge 表示回到空闲电平的第二边沿。
CPOL 决定空闲电平。
CPHA 决定在哪个边沿采样。
不要只写“上升沿采样”，却没有交代模式。

| mode | CPOL | CPHA | 空闲 | 采样边沿 | 改变数据的边沿 |
|:--|--:|--:|:--|:--|:--|
| 0 | 0 | 0 | 低 | leading，上升 | trailing，下降 |
| 1 | 0 | 1 | 低 | trailing，下降 | leading，上升 |
| 2 | 1 | 0 | 高 | leading，下降 | trailing，上升 |
| 3 | 1 | 1 | 高 | trailing，上升 | leading，下降 |

CPHA=0 时，第一位必须在第一个采样边沿前已经稳定。
CPHA=1 时，第一 leading edge 用于发出第一位。
数据有效时间、setup/hold 必须从具体从设备手册获得。
模型里的零传播延迟不能替代器件时序。

### STM32F407 SPI1 寄存器参照

SPI1 基址为 `0x40013000`。
这里是传统 STM32 SPI 控制器，不是后续器件的新版 TSIZE/EOT 机制。
寄存器访问宽度应与配置的数据帧宽度匹配。

| 相对地址 | 寄存器 | 关键字段 | 典型风险 |
|:--|:--|:--|:--|
| +0x00 | CR1 | CPHA、CPOL、MSTR、BR、SPE、LSBFIRST、DFF | 运行中改模式造成边沿错位 |
| +0x04 | CR2 | RXDMAEN、TXDMAEN、ERRIE、RXNEIE、TXEIE | 只使能发送却不处理接收 |
| +0x08 | SR | RXNE、TXE、MODF、OVR、BSY | TXE 不代表线已空 |
| +0x0C | DR | 数据寄存器 | 8 位与 16 位访问混用 |
| +0x10 | CRCPR | CRC polynomial | 两端约定不同 |
| +0x14 | RXCRCR | 接收 CRC | 不等于应用层完整性验证 |
| +0x18 | TXCRCR | 发送 CRC | 与数据帧、方向配置有关 |

不要把 DR 映射成 packed 字节序列后用 memcpy 写。
编译器可能选择与设备许可不符的访存宽度。
要检查反汇编中的 STRB、STRH 或 STR 是否符合手册。

### 读操作也需要时钟

主机发送 dummy 字节来产生 SCK。
从机同时送回 MISO。
所以“只读传感器”也有 TX 数据路径。
发送命令后收到的首几个字节可能是占位数据。
需要明确命令阶段、地址阶段、dummy 阶段和有效载荷阶段。

SPI 没有 CAN 那样的非破坏仲裁。
多主支持若存在，依赖片选、模式故障或外部协议。
不能把多个普通主机同时驱动 SCK/MOSI 当作可靠竞争机制。

### 两个 DMA 通道的协同

全双工传输通常要同时管理 RX 和 TX。
RX 未及时处理时可能 OVR。
建议先准备接收，再启动可产生时钟的发送路径，具体顺序看设备要求。
完成判据要同时考虑 DMA 计数和 SPI 外设状态。

典型退出流程应检查：

1. TX DMA 是否完成。
2. RX DMA 是否获得预期字节数。
3. 外设是否仍 BUSY。
4. 是否出现 OVR 或 MODF。
5. CS 最后保持时间是否满足。
6. 清状态序列是否符合控制器版本。
7. 缓冲区所有权是否回到 CPU。
8. 上层 CRC/长度是否正确。

旧 STM32 SPI 的 OVR 清除有特定读 DR/读 SR 序列。
不能一概使用 `SR = 0`。
具体错误处理还要考虑当前是主机还是从机。

### 片选、字长与吞吐预算

设一项 SPI 事务含 1 B 命令、2 B 地址、1 B dummy、32 B 载荷。
合计 36 B，即 288 个时钟。
SCK 若为 8 MHz，纯移位耗时为 36 us。
若 CS 建立和保持各需 1 us，则最低事务时间已经变为 38 us。
还没有包含 DMA 配置、总线争用、任务排队和从设备忙时等待。

```text
每秒 10000 次事务：
有效载荷率 = 32 × 10000 = 320000 B/s
线上移位占用 = 36 us × 10000 = 36%
连同 CS 余量 = 38 us × 10000 = 38%
```

这两种占用率不同，且都不是 CPU 利用率。
DMA 可降低 CPU 搬运成本，但不能缩短线上位数。
若同总线另挂一个需要长时间保持 CS 的器件，最坏排队时间还要计入。
总线平均占用率小于 100% 并不保证每个传感器都满足截止时间。

若改为 16 位帧，协议字节序并不自动与 CPU 内存端序相同。
主机端 uint16_t 的低字节先存，SPI 外设可能按 MSB first 移出高位。
应画出实际线上比特顺序，并使用非对称测试字，例如 0x1296。
只测试 0x0000、0xFFFF 或重复字节容易隐藏端序错误。

传感器连续读可能要求 CS 在所有字节间保持低。
把每个字节拆成一次库调用并自动翻转 CS，会改变事务语义。
反过来，不同命令可能必须在两次 CS 之间留间隔。
因此 SPI API 的单位应是事务，而非只有一个裸字节发送函数。

### VCD 模型如何使用

本章模型生成 `.build/ch05/spi.vcd`。
每个模式发送相同的 0x96。
SCK 半周期设为模型中的 10 ns。
这意味着图中模型时钟为 50 MHz，不表示某块开发板运行到了 50 MHz。

用 GTKWave 打开后按 mode 段检查空闲电平与采样边沿。
模型本身断言四种配置在匹配模式下都重建出 0x96。
它没有模拟亚稳态或导线反射。
也不声称 mode 不匹配时每种器件都会得到固定的错误字节。

## 5.6 I2C：开漏仲裁、时钟拉伸与有界恢复 {#sec-edge.2.5.6}

### 高电平表示释放

I2C 的 SDA/SCL 通常使用开漏输出与外部上拉。
写 1 的逻辑含义是释放线路，不是强行推高。
两个主机同时发送时，线上电平由低电平主导。
本章只用这一接口事实分析仲裁，不展开模拟电路设计。

<pre class="layout" id="fig-edge-ch05-i2c-arbitration">
SCL 高期间比较 SDA

地址写字节：A=0xA0（地址 0x50），B=0xC0（地址 0x60）
bit7：A 释放 1，B 释放 1，线为 1，继续
bit6：A 拉低 0，B 释放 1，线为 0
       └── B 发送 1 却读到 0：B 仲裁失败，必须停止驱动
剩余位由 A 继续发送
</pre>
读图：仲裁失败不是“收到一个 NACK”。
它发生在主机发出高、却观察到低的位期间。
失败者必须让出总线，不能立刻生成破坏胜者事务的 STOP。

### 帧结构与 ACK

START 是 SCL 高时 SDA 从高变低。
STOP 是 SCL 高时 SDA 从低变高。
每个数据字节后附第九个 ACK/NACK 时钟。
发送者在第九位释放 SDA，由接收者应答。
读事务的最后一字节通常由主机发 NACK，再按事务需要 STOP 或后续控制。

7 位设备地址左移一位后附 R/W bit。
器件资料有时提供的是已经左移的 8 位地址字节。
必须先统一约定，避免在软件中重复左移。
本章仲裁模型用的是已经包含写方向的字节 0xA0、0xC0。

### STM32F407 I2C1 寄存器参照

I2C1 基址为 `0x40005400`。
它是旧版 I2C 控制器，SR1/SR2 确认序列与新版 ISR/ICR 不同。
不将 F4 清 ADDR 的操作推广到 F0/F3 等其他 IP 版本。

| 相对地址 | 寄存器 | 关键字段 | 生命周期要求 |
|:--|:--|:--|:--|
| +0x00 | CR1 | PE、START、STOP、ACK、POS、SWRST | ACK/STOP 设置时机与接收尾部相关 |
| +0x04 | CR2 | FREQ、ITERREN、ITEVTEN、ITBUFEN、DMAEN、LAST | 外设时钟 MHz 编码需正确 |
| +0x08 | OAR1 | 本机地址 | 作为从机时使用 |
| +0x0C | OAR2 | 第二地址 | 不等于目标从机地址 |
| +0x10 | DR | DATA[7:0] | 写地址字节或传输载荷 |
| +0x14 | SR1 | SB、ADDR、BTF、RXNE、TXE、BERR、ARLO、AF、OVR | 事件与错误分开处理 |
| +0x18 | SR2 | MSL、BUSY、TRA | 某些读取序列会确认事件 |
| +0x1C | CCR | FS、DUTY、CCR | 决定时钟高低时间 |
| +0x20 | TRISE | 最大上升时间编码 | 与速率及输入时钟关联 |

读 SR1 再读 SR2 可参与清 ADDR 序列。
因此调试器连续自动读取也可能改变状态。
记录寄存器快照前要了解这种副作用。
为方便打印增加一次 SR2 读取，可能改变复现条件。

### 事件与错误中断

事件 IRQ 跟踪 START、地址、字节边界和传输完成条件。
错误 IRQ 处理 BERR、ARLO、AF、OVR 等。
它们不只是“发送回调”和“失败回调”两个抽象函数。
状态机要保存事务阶段，否则同一个标志在不同阶段可能需要不同恢复。

| 状态 | 含义 | 恢复方向 |
|:--|:--|:--|
| AF / NACK | 地址或数据未被接收方确认 | 按阶段停止或重试，限制次数 |
| ARLO | 仲裁失败 | 释放驱动，等待胜者事务完成 |
| BERR | 非法总线条件 | 记录现场，再按控制器要求复位状态 |
| OVR | 数据未及时服务 | 终止损坏事务，修复服务预算 |
| BUSY 长期不清 | 总线仍占用或设备锁住 SDA | 有界等待，必要时执行恢复策略 |

NACK 不总等于硬件损坏。
器件写周期未结束、地址错误或主机读尾部主动 NACK 都要区分。
不能对所有 NACK 一概复位整颗 MCU。

### DMA 不消除接收尾部时序

DMA 可以搬运 DR 数据，但 START、重复 START、地址应答和 STOP 仍属协议控制。
旧控制器的一字节、两字节和多字节接收尾部可能有不同序列。
LAST、ACK、POS 等控制位与 DMA 最后传输有关。
不能凭“NDTR 到零”生成一个所有长度通用的接收算法。

本轮没有提供完整 STM32F407 I2C DMA 固件。
寄存器表与状态机用于设计审查，执行证据是仲裁与恢复模型。
若要交付板级驱动，必须另补各接收长度、重复 START、NACK 和拉伸故障测试。
该缺口在审计台账中保持开启，不伪报外设完整验收。

### 一笔寄存器读事务的时钟预算

读取常见 I2C 寄存器，可能采用以下序列：

```text
START
地址+W  8 bit + ACK
寄存器号 8 bit + ACK
重复 START
地址+R  8 bit + ACK
数据 0   8 bit + ACK
数据 1   8 bit + NACK
STOP
```

五个字节阶段分别带一个应答时钟，总计 45 个 SCL 周期。
400 kHz 理想时钟下，仅这些周期就需 112.5 us。
START/STOP 建立、总线空闲和时钟拉伸还需另外计算。
若周期采样为 1 ms，这一事务仅理想传输就占约 11.25% 总线时间。
并行增加十个相同传感器会超过可用预算，而不是“CPU 够快就能跑”。

重复 START 保持总线所有权，防止其他主机插入修改从设备寄存器指针。
如果应用可接受 STOP 后重新 START，也必须由器件协议许可。
驱动接口要能表达两种语义，不能暗中替用户更改事务。

### 地址阶段与数据阶段的 NACK 不能混为一谈

地址 NACK 可能意味着目标不存在、尚未上电或正在内部忙。
数据 NACK 可能表示参数、写保护或接收容量问题。
重试策略应限制次数，并区分是否可能重复执行了不可幂等命令。

例如“步进一次”或“清累计计数器”不是天然可幂等操作。
如果最后 ACK 丢失，盲重试可能造成命令执行两次。
应由应用协议提供事务编号、读回验证或幂等设计。
底层驱动只能返回已观察到的总线阶段，不应假造应用执行结果。

### 时钟拉伸与恢复超时

发送者释放 SCL 后要读取真实 SCL 电平。
若从机继续拉低，不能只在软件计数完一个半周期后假定 SCL 已高。
拉伸必须有系统可接受的上界或超时策略。
无限等待会把一个器件故障扩散成整个控制回路停止。

恢复时可在确认总线独占条件下切换 GPIO，尝试给最多 9 个 SCL 脉冲。
如果 SDA 释放，再尝试合法的 STOP 并重新初始化控制器。
9 个脉冲不是保证恢复的魔法常量。
若器件硬短路或持续拉低 SDA，仍需报告故障或切换电源域。
在多主总线上也不能随意中断他人的合法事务。

本章模型固定 SDA 一直低。
恢复循环在第 9 次后退出，并明确保留故障状态。
测试目的就是防止示例把“尝试恢复”误写成“保证恢复成功”。

## 5.7 完成协议：错误码、描述符与设备可见性 {#sec-edge.2.5.7}

### 描述符的两个生命周期

CPU 初始化描述符时，设备不得提前读取半成品。
设备设置完成标志时，CPU 不得读取尚未稳定的数据。
因此描述符有 OWN 或相似状态字段。
不论硬件是否有显式 OWN 位，软件都要表达相应的所有权边界。

一个可靠的提交协议应给出：

```text
准备缓冲区
  ↓
写描述符长度、地址、标志、下一项
  ↓
必要的 clean 与平台屏障
  ↓
交所有权给设备
  ↓
敲门铃 / 使能 DMA 请求
```

完成路径应给出：

```text
观察硬件完成或错误
  ↓
按设备顺序读取剩余计数和状态
  ↓
必要的 invalidate 与排序
  ↓
验证有效载荷长度和代际号
  ↓
交给 CPU 消费者
  ↓
消费完成后归还为 FREE
```

上层获得 READY 后不能仍让另一个路径随意重启 DMA 到同一地址。
否则即使屏障完全正确，数据仍会被合法的下一次传输覆盖。

### 错误码要区分层次

本章没有将标准 errno 数值绑定到所有裸机环境。
推荐先定义语义，再由工程决定编码。
例如：

| 语义名 | 层次 | 调用方可做什么 | 不应做什么 |
|:--|:--|:--|:--|
| BUSY | 所有权 | 稍后有界重试 | 直接覆盖占用槽 |
| TIMEOUT | 时间预算 | 停止事务并进入恢复 | 无限延长等待 |
| OVERRUN | 外设或队列 | 记录缺口并重同步 | 假装所有样本连续 |
| ARBITRATION_LOST | 总线协议 | 释放线路、退避 | 立即发破坏性 STOP |
| STALE_TOKEN | 生命周期 | 丢弃过期释放请求 | 释放当前代际槽 |
| IO_ERROR | 传输 | 保存寄存器与剩余计数 | 无条件把全长标为有效 |

返回码不能替代失帧计数。
实时系统至少应保留累计发生次数与首次/最近发生时刻。
如果诊断本身会阻塞 ISR，诊断记录也必须改成有界非阻塞通道。

### 对齐的三种单位

C 类型对齐、DMA 传输宽度和 Cache line 是三种不同单位。
4 B 对齐的地址可能仍不满足 32 B 行隔离。
32 B 对齐的地址也不保证位于 DMA 可寻址 SRAM。
某些控制器还限制突发不能越过特定边界。

使用 aligned 属性后，要检查 ELF 中的最终地址。
母本中的某次编译器对齐上限观察不能推广为“所有工具链最大只支持 16 B”。
链接器、段设置与目标文件格式共同决定最终排布。
使用 `_Alignas(32)` 或 GNU aligned 只是表达约束的第一步。

### 停止路径也是协议

超时后不能马上 free 缓冲区。
应先禁止新请求，再停止通道，等待硬件确认，最后处理完成竞态。
若设备仍可能访问旧描述符，释放就会形成 use-after-free。
这在静态数组中表现为下一事务的数据被旧 DMA 覆盖。
不需要动态 malloc 也会发生生命周期错误。

停止与完成同时到达时，应只有一个路径负责归还所有权。
否则容易二次释放、重复回调或多次入队。
generation 和明确的终态能帮助测试这类竞态。
但真正多核并发仍需 CAS 或受控锁协议。

### 循环 DMA 的位置快照不能单独证明没有丢圈

设缓冲区含 N 个传输单位。
常见写位置估计为 `position = N - NDTR`。
若 position 从小变大，可消费两位置之间的数据。
若 position 比上次小，可能发生一次回绕。
但如果 CPU 很久没运行，可能已经发生不止一整圈。
仅凭当前 NDTR 无法恢复丢掉的圈数。

```text
N = 1024，旧位置 = 100，当前位置 = 200
可能情况 A：DMA 前进了 100 单位
可能情况 B：DMA 前进了 1124 单位
可能情况 C：DMA 前进了 2148 单位
这三种情况拥有相同的位置快照
```

因此必须有服务频率上界、不可丢失的块序号或额外完成计数。
如果 TC 中断也只保留一个 pending 位，连续多次完成可能被合并。
“每次中断次数代表精确 DMA 圈数”也要核查屏蔽期间的硬件行为。

设计审查时记录：

| 参数 | 例子 | 必需约束 |
|:--|:--|:--|
| N | 1024 个半字 | 长度单位与 NDTR 一致 |
| 生产速率 | 200000 半字/s | 包含所有通道 |
| 一圈时间 | 5.12 ms | 1024 / 200000 |
| 最大服务间隔 | 设计要求 1 ms | 不是平均调度间隔 |
| 允许 backlog | 由软件消费速率决定 | 不能超过可保留数据量 |

1 ms 要由中断屏蔽、任务调度和执行时间分析共同保障。
若无法保障，改用能计数的块完成协议或足够的硬件缓冲。
不要只在循环里增加一次 DMB。

### DMA 错误后的有效长度

NDTR 可能表示剩余传输单位，但错误发生时的 FIFO 中还可能有数据。
软件不能自动假定已完成数量为 `initial - remaining` 且最后一个字节完整。
还要根据控制器对错误、FIFO 和总线响应的定义判断。

串行协议层可能已收到半个命令或部分采样帧。
如果应用没有独立长度与 CRC，重启 DMA 后会把新旧片段拼成一个看似合法的帧。
因此恢复路径需要同时复位硬件传输状态和上层重组状态。
复位一个 DMA EN 位并不能完成协议恢复。

### 中断优先级不等于 DMA 仲裁优先级

NVIC/PLIC 控制 CPU 何时服务中断。
DMA 的 PL、通道优先顺序和总线矩阵仲裁控制传输何时获得总线。
把 DMA TC 中断设为最高优先级，不能使已经堵在总线上的 DMA 更快完成。
CPU 也不能靠更高中断优先级解决不可访问 TCM 的问题。
应从主设备端口、目标 SRAM、请求源与仲裁规则逐层检查。

本章保留这些边界，而不展开 Linux 驱动模型。
IOMMU、Linux dma_map API 等只在跨书边界处引用，不在这里重写。

## 5.8 实验、时序失败案例与复现自审 {#sec-edge.2.5.8}

### 统一入口

```bash
cd edge
bash experiments/ch05/run.sh
```

第一步编译主机状态机，启用 ASan 与 UBSan。
第二步运行协议与缓冲区断言，生成 SPI VCD。
第三步交叉编译 Cortex-M3 UART 固件，再用 Unix socket 注入两个字节。
缺少 Clang、LLD 或 QEMU 时直接失败。
不会退回打印固定“硬件 PASS”的替代分支。

### 实验一：DMA 与接口离散模型

源码在 `experiments/ch05/bus_models.c`。
模型中所有状态转换串行执行。
目的在于验证所有权、预算和协议逻辑，不模拟真实 AXI 仲裁时间。

实际输出：

```text
MODEL PASS DMA ownership: overwrite blocked, stale token rejected
MODEL PASS cache: barrier != clean; shared-line writeback destroys DMA byte
MODEL PASS UART: 3Mbaud 8N1, 400us masked, 120 arrived/16 stored/104 lost
MODEL PASS SPI: four CPOL/CPHA modes, 0x96 loopback, VCD generated
MODEL PASS I2C: 0x60 loses at bit6; stuck-SDA recovery exits after 9 clocks
```

五行输出分别对应独立断言，不是无条件 puts。
例如更改 DMA arm 允许覆盖 CPU-owned 槽，会使所有权断言失败。
更改仲裁为逻辑 OR，会使 I2C 失败位断言失败。
这类模型具有局部反例价值，但不证明物理驱动已正确。

### 实验二：真实 UART IRQ 字符注入

源码位于 `firmware/ch05/main.c` 与 `start.S`。
链接布局复用第四章 Cortex-M3 的 `link.ld`。
启动代码显式执行 LMA→VMA 的 data 搬移与 BSS 清零。
本例的主要可写状态仍在 BSS，新增初始化数据也遵循相同启动协议。

宿主脚本启动 QEMU 并连接 UART0 Unix socket。
只有看到 READY 行后才发送字节。
先发 0x55，再发 0xA3。
这段宿主延迟仅用于对模型节流，不是波特率测量。

实际输出：

```text
UART READY
UART PASS: IRQ5 received 0x55 and 0xa3
```

若 QEMU 未创建 socket、READY 缺失、字节不符或退出非零，测试失败。
每个等待都有宿主超时。
主循环不读取 DR，因此不能绕过 IRQ5 的验证。
当前测试不验证 DMA、Cache、SPI 物理引脚或 I2C 外设 IP。

### IRQ 与主循环睡眠的检查竞态

本实验主循环使用短忙等观察 received，因为它要隔离验证 IRQ 路径。
生产系统通常希望等待时 WFI 休眠，但不能简单写：

```text
if (queue_empty()) {
    WFI();
}
```

检查为空后、执行 WFI 前，中断可能已经将数据入队并返回。
如果没有新的唤醒事件，线程可能继续睡眠，即使队列已有数据。
解决方案必须与架构的待处理中断和事件语义匹配。
常见做法是使用内核原子阻塞/唤醒接口，或审查过的 IRQ-mask 检查协议。
不要认为把 WFI 放进任意 while 循环都等价于正确的 RTOS 等待。

WFI 也不是零功耗承诺。
串口、定时器和 DMA 时钟域可能继续运行。
待机电流必须在明确的时钟门控、GPIO 和供电条件下测量。
这部分将在功耗章单独给证据，不从本章字符注入推导毫安数字。

### 失败案例：400 us 关中断导致丢帧

一段生成代码在临界区内复制和格式化日志，令 UART ISR 被屏蔽 400 us。
设串口持续 3 Mbaud、8N1，FIFO 初始为空、容量 16。
模型以 1/3 us 为一个离散 tick。
字节每 10 tick 到达，屏蔽区持续 1200 tick。
因此恰好到达 120 字节。
最多保留 16 字节，丢失 104 字节。

这不是由示波器采样得到的量产事故。
它是可重复的定量反例，足以否定“FIFO 很快，所以关中断几百微秒没关系”。
真实器件的 overrun 覆盖策略和中断阈值还会改变保留内容。
修复不是简单扩大任务间软件队列，因为 ISR 还没来得及从硬件 FIFO 取数。
应缩短屏蔽区、允许更高优先级 UART 服务，或使用正确的 DMA 接收与缓冲预算。

### agent 错误案例：把 DMA TC 当作 SPI 片选释放点

生成器在 DMA 完成回调中立刻拉高 CS。
它只确认内存数据已写入 SPI DR/FIFO。
最后一个字节可能仍在移位输出。
从机看到 CS 提前释放，丢掉最后若干位或将命令判为不完整。

定位应检查 DMA TC、SPI BSY、TXE 与 CS 波形的相对关系。
不能用“DMA 的传输长度正确”否认线上事务失败。
修复要依控制器版本等待真正完成条件，并满足从设备 tCSH/tCSS。
本轮没有该实体 SPI 波形，因此报告状态是“协议反例，待板级复现”，不是实测通过。

## 5.10 本章陷阱 {#sec-edge.2.5.10}

::: errata 本章陷阱

1. **对 W1C 寄存器做 OR 读改写**：读回的其他 1 也被写回，额外事件被清掉。修复为直接写欲清除掩码，并核查手册副作用。
2. **对 MMIO 结构盲加 packed**：保留洞消失或访存宽度改变。修复为显式 RESERVED 字段、offsetof 断言与目标反汇编。
3. **认为 DSB 自动 clean 所有数据**：DMA 仍读到旧 RAM。修复是明确 Cache 维护、作用域、屏障和所有权四项合同。
4. **DMA TC 后立刻释放 CS/DE**：最后数据仍在外设移位器。修复为检查协议完成状态及从设备保持时间。
5. **NDTR 的单位误当字节**：16/32 位传输时长度倍数错误。修复是同时记录数量、PSIZE、MSIZE 与目标地址递增策略。
6. **CPU-owned 缓冲块被重新 arm**：零拷贝消费者读到下一块数据。修复为独占状态机与代际 token，并对覆盖请求返回 BUSY。
7. **UART FIFO 溢出后只扩软件队列**：ISR 长期被屏蔽时，软件队列根本没机会接收。修复是从 FIFO 到达率与最大服务间隔算预算。
8. **SPI 只处理 TX 不排 RX**：全双工收到的字节填满接收路径，引发 OVR。修复为成对管理接收，或按正确的单向模式配置。
9. **把 I2C ARLO 当 NACK 后立即 STOP**：破坏胜者仍在进行的事务。修复为让出驱动并等待总线释放，再执行有界退避。
10. **认为 9 个时钟必定恢复 SDA**：硬短路或损坏器件依然拉低线路。修复为有界尝试、检查真实电平、保留故障并执行上级恢复策略。
11. **最高 CPU 中断优先级等同 DMA 最高总线优先级**：DMA 仍受主端口和目标域限制。修复是分别检查 NVIC/PLIC、DMA PL 和总线矩阵仲裁。
12. **把 VCD 和 QEMU 字符注入叫做实体波形实测**：模型没有引脚电压和模拟噪声。修复为分别标记模型、指令执行与仪器测量三类证据。

:::

::: method 即时自测 {#method-edge.2.5.11.1}
一个 256 B DMA 接收块与一个 CPU 状态变量共享末尾 Cache line。
工程师在 DMA 完成后对缓冲区执行 invalidate，然后更新状态变量。
为什么仅有 invalidate 不足以证明系统正确？

::: sol
首先，DMA 开始前若该行已有 dirty CPU 数据，后续写回可能覆盖 DMA 结果。
其次，向外取整的 invalidate 可能丢掉同一行中 CPU 尚未写回的状态变量。
再次，CPU 更新状态变量会再次使整行变脏，下一次 DMA 事务期间仍可能发生覆盖。
需要隔离整行所有权、正确的前后维护与缓冲区生命周期，而不只是增加一条屏障。
本例模型的 shared-line writeback 断言正是一个可复现反例。
:::
