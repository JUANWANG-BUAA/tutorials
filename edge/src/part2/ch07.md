本章讨论的是处理器如何接收、解释并计算样本。
不会展开运算放大器设计、晶体管级 ADC 或 IC 工艺。
模拟接口只保留固件必须知道的量程、参考、采样和混叠边界。
ADC 的原始码不是已经校准的电压，更不是天然具有单位的浮点数。

实验选择 LM3S6965 的十位 ADC 接口。
QEMU 实际执行 Cortex-M3 的 MMIO、中断和计算指令。
但是其 ADC 输入是模拟器生成的合成数，不来自实体引脚。

第二条目标路径使用 RV32IM 的有符号高、低半乘法。
它执行与 ARM 相同的数值自检，不连接 ADC 设备。
x86-64 与 AArch64 的乘法汇编本轮只交叉汇编和反汇编。
第六章 x86 长模式的成功不自动成为本章乘法函数的动态证据。

正文中的时限数字来自明确的采样模型。
测试不把 QEMU 宿主运行时间报告成滤波耗时或 WCET。
FFT 参照误差以输出整数码的 LSB 为单位。
误差通过不代表 ADC 电气精度或整机测量精度通过。

## 7.1 采样接口：代码、单位与时间戳 {#sec-edge.2.7.1}

### 先约定一个样本是什么

一个样本至少需要数值编码与时间含义。
数值编码包含有效位数、对齐方式、符号约定和通道。
时间含义包含触发时刻、通道顺序和采样间隔。
如果只保存一个 uint16_t，很多解释所需的信息并不在其中。
后续滤波器不能从整数数组中自动恢复这些条件。

例如十位无符号码范围为 0–1023。
十二位无符号码范围为 0–4095。
某些设备把有效位放在寄存器低位，另一些接口允许左对齐。
差分输入也可能使用补码，而不是偏移二进制。
移植者必须先固定一种编码，不能只看存储类型的位宽。

| 样本属性 | 本章具体约定 | 不满足时的后果 | 应保存在哪里 |
|:--|:--|:--|:--|
| 原始位数 | LM3S6965 为 10 位 | 缩放与掩码错误 | 设备配置和数据格式 |
| 原始位置 | FIFO 读值低 10 位 | 把保留位当信号 | 寄存器适配层 |
| 数值范围 | 0–1023 的无符号码 | 符号扩展或零点错位 | 转换函数合同 |
| 归一化零点 | 示范性取中点 512 | 不代表传感器真实零偏 | 算法配置 |
| 采样时钟 | 由采样触发源决定 | 频谱横轴不可信 | 块元数据 |
| 通道顺序 | 实验只使用一条序列 | 多通道被误当单通道连续流 | 扫描配置 |

以中点为零只是一种数字处理约定。
单极性电压测量可能应该保留直流量，而不是先减中点。
温度、电流等物理单位还需要量程和校准参数。
本章不会把合成 ADC 码换算成伪造的摄氏度或伏特测量。
演示重点是避免编码与计算边界错误。

读图：中断通知不是采样时钟本身。
对 ISR 进入时刻打戳，得到的是带服务延迟的观察时刻。
若用这些戳直接估计等间隔频谱，必须解释抖动和时钟域。
本章 ADC 实验不提供实体采样时间戳测量。
另外的 16 kS/s 时限算例是独立的数学模型。

### 模拟边界只保留对程序有影响的约束

输入不能超出 ADC 和板级允许的范围。
参考电压、源阻抗和建立时间可能影响转换结果。
这些条件需要器件和板级资料，不能由 C 代码保证。
开启更多采样平均也不意味着外部输入一定稳定。
电气过载、数字裁剪与算法溢出要分别记录。

采样后的数字低通不能消除已经折回目标频带的混叠。
这不是滤波器阶数不够，而是采样前信息已不再可区分。
提高采样频率、限制输入带宽或使用合适的带通采样方案，是不同设计选择。
本书不在这里推导模拟滤波电路。
但固件接口必须知道自己的有效带宽假设。

### 通道吞吐不能混成每通道采样率

假设一个序列轮流采集四个输入。
每秒完成的总转换次数不是每个通道的采样率。
需要按扫描模式和每次触发包含的转换数推导。
通道间样本也未必同时取得。
对相位敏感的算法，扫描时差不能被简单忽略。

本实验只使用 SS3 的单个样本。
没有多通道交织，没有同步多 ADC，也没有真实源建立时间证据。
这些限制可以减少实验变量，但不能悄悄延伸成多通道能力声明。
下一章讨论数据管道时还会重新核对样本率和字节率。
两者之间必须有明确的通道数、字宽和帧头开销。

## 7.2 LM3S6965 ADC：序列器、FIFO 与 IRQ17 {#sec-edge.2.7.2}

### 固定芯片与手册版本

本节使用 TI《Stellaris LM3S6965 Microcontroller》2014-07-15 版本。
ADC 基址为 `0x40038000`。
本芯片的转换结果是十位，不是所有 Cortex-M 都有相同 ADC。
处理器内核不定义 ADC 寄存器。
从一个 Cortex-M 平台迁移到另一个平台，外设合同需要重新阅读。

| LM3S6965 ADC 偏移 | 寄存器 | 关键作用 | 本实验动作 |
|--:|:--|:--|:--|
| 0x000 | ADCACTSS | 使能各采样序列 | 配置时关闭，随后使能 SS3 |
| 0x004 | ADCRIS | 原始中断状态 | ISR 检查 INR3 |
| 0x008 | ADCIM | 是否向控制器提交中断 | 配置完成后开放 SS3 |
| 0x00C | ADCISC | 中断状态及 W1C 确认 | 直接写 bit3 |
| 0x010 | ADCOSTAT | FIFO 溢出状态 | 真实移植必须记录和处理 |
| 0x014 | ADCEMUX | 各序列触发源选择 | SS3 选择 timer 事件 |
| 0x018 | ADCUSTAT | FIFO 下溢状态 | 禁止空 FIFO 盲读 |
| 0x028 | ADCPSSI | 软件发起采样序列 | 不用于本轮 QEMU 路径 |
| 0x0A0 | ADCSSMUX3 | SS3 输入选择 | 选择示范输入 0 |
| 0x0A4 | ADCSSCTL3 | 单次序列控制 | END0 与 IE0 置位 |
| 0x0A8 | ADCSSFIFO3 | 弹出转换结果 | ISR 只读一次 |
| 0x0AC | ADCSSFSTAT3 | FIFO 指针及满空 | 读数据前检查 EMPTY |

这些是三十二位寄存器访问，不沿用上章 SJA1000 的字节访问。
同为“采样设备”，访问宽度也可能完全不同。
本章 MMIO 宏只用于这个已经核实宽度的接口。
它不代表任意外设寄存器都能用 uint32_t 指针访问。
读取 FIFO 还会改变设备状态，不能把它当普通 RAM。

### 序列与 FIFO 深度

| LM3S6965 序列器 | 最多转换样本数 | 实体 FIFO 深度 | 本章使用 |
|:--|--:|--:|:--|
| SS0 | 8 | 8 | 不使用 |
| SS1 | 4 | 4 | 不使用 |
| SS2 | 4 | 4 | 不使用 |
| SS3 | 1 | 1 | 一次触发，一个样本 |

手册物理第 397 页明确列出这些差异。
本轮核看了原页表格，而不是只从名称猜测深度。
QEMU 的所读实现却给每个序列器使用十六项内部 FIFO。
因此在 QEMU 中成功承受某段服务延迟，不能证明真芯片的单项 SS3 FIFO 不会溢出。
本实验不据模拟器 FIFO 容量声称实体抗丢样能力。

### SS3 控制字段

| 寄存器字段 | 位 | 本实验取值 | 解释 |
|:--|:--|:--|:--|
| ADCACTSS.ASEN3 | 3 | 配置后为 1 | 开放 SS3 |
| ADCEMUX.EM3 | 15:12 | 5 | timer 触发 |
| ADCSSCTL3.D0 | 0 | 0 | 单端示范路径 |
| ADCSSCTL3.END0 | 1 | 1 | 本序列只有一项，必须结束 |
| ADCSSCTL3.IE0 | 2 | 1 | 该项完成可产生序列事件 |
| ADCSSCTL3.TS0 | 3 | 0 | 不使用内部温度通道 |
| ADCSSFSTAT3.EMPTY | 8 | 读值判断 | 为 1 时不读 FIFO |
| ADCSSFSTAT3.FULL | 12 | 读值判断 | 真实服务预算必须考虑满状态 |

`ADCSSCTL3 = 6` 来自 END0 和 IE0。
它不是不加解释的初始化魔数。
选择输入 0 也不表示本轮接上了外部传感器。
模拟器没有使用真实模拟电压输入。
这些寄存器主要用于验证控制通路和驱动副作用。

### 初始化顺序

先准备滤波器状态和可执行的中断入口。
再开放 ADC 与 Timer0 的外设时钟。
关闭 timer 和采样序列，避免配置过程中触发。
设置触发源、输入与序列控制。
清理旧事件，开放 ADCIM 与 NVIC IRQ17。

随后配置 Timer0 为三十二位周期模式。
装入本轮使用的计数值 49999。
置位 TAOTE 与 TAEN，使超时事件触发 ADC。
最后打开 CPU 可屏蔽中断。
主循环等待中断，不执行软件忙等轮询采样。

这里没有把计数值直接换算为实体微秒。
那需要同时锁定系统时钟、分频和 timer 的计数合同。
实际板卡还必须按手册配置 PLL、受支持晶振和模拟输入管脚。
本轮 QEMU 程序没有完成这些板级配置。
因此它不是可以不经修改就烧进任意 LM3S6965 板的完整采样固件。

### 模拟器支持范围决定实验入口

本轮另外核读 QEMU Stellaris ADC 和 GPTM 源码。
ADC 模型对处理器发起的 PSSI 写入没有实现采样动作。
它支持用于示范的 timer 触发通路。
所以本实验不写 PSSI 后无限等待 RIS。
这是根据实际模型能力选择路径，而不是为了让测试通过而伪造转换结果。

输入数据由模型内部状态生成，位于一个较窄的变化范围。
本轮目标程序收到 64 项，检查原始值不是完全相同。
这个检查只用于防止测试在没有实际接收样本时误报成功。
它不能证明噪声分布、ADC 线性度或有效位数。
模拟器源码版本线索与实际运行版本也分别记录在证据中。

### 中断入口和确认

IRQ17 对应外部中断号十七。
向量表索引还要加 Cortex-M 的十六个内核异常槽。
汇编向量表先填内核异常，再填 IRQ0–16，最后放 ADC3_Handler。
不能直接把函数指针放在向量表索引十七处。
这类差一组槽位的错误会表现成从未进入目标 ISR。

ISR 先检查 RIS 与 FIFO 非空。
读取一次 FIFO，保留低十位。
直接写 ADCISC 的 bit3 确认事件。
随后转换为 Q15 并执行四抽头滤波。
第 64 项到达后停 timer、屏蔽 ADC 通知并结束受控测试。

测试中还读回 RIS，检查这次确认动作。
这是低触发频率受控环境中的故障检测点。
生产系统不能把“确认后 RIS 又为 1”一概认作硬件错误。
新事件可能恰好已经到达。
真实并发驱动需要按 FIFO、事件和服务预算继续处理，而不是无条件报错。

本测试在最后一次 ISR 中输出并退出仿真。
这不是建议生产 ISR 打印大量日志或执行长时间系统终止。
其唯一目的是让宿主可靠判断该目标程序完成了全部条件。
长循环、业务工作和流式存储应移交任务或管道。
控制器服务时限必须重新计算。

## 7.3 Q15：扩宽、舍入和饱和是三个操作 {#sec-edge.2.7.3}

### 用整数解释缩放

::: def 本章 Q15 数值合同 {#def-edge.2.7.3.1}
本章 Q15 使用一个 int16_t 存储。
实际数值等于存储整数除以 32768。
可表示区间从 -1 到 `1 - 1/32768`。
-1 可以精确表示，+1 不能。
:::
不同资料的 Qm.n 记法可能是否计入符号位，阅读时必须明确约定。

| 存储整数 | 本章 Q15 数值 | 说明 | 用途 |
|--:|:--|:--|:--|
| -32768 | -1 | 精确负满量程 | 极值测试 |
| -16384 | -0.5 | 精确二分之一 | 乘法符号测试 |
| 0 | 0 | 零 | ADC 中点示范 |
| 8192 | 0.25 | 精确四分之一 | 四点平均系数 |
| 16384 | 0.5 | 精确二分之一 | IIR 参数示例 |
| 32767 | 约 0.99996948 | 最大正值 | 饱和上界 |

把十位码的中点 512 移到零后，还剩九位幅值尺度。
乘以 64 即可放到 Q15 范围。
原始码 0 变成 -32768。
原始码 1023 变成 32704。
不能强行让正端点也等于 +32768，再塞进 int16_t。

十二位示范码则减 2048、乘 16。
4095 得到 32752。
这个例子只测试通用格式转换，不表示 LM3S6965 变成十二位 ADC。
转换函数接收位数参数，并检查原码没有超出范围。
格式错误应在进入滤波器前被发现。

### 先扩宽再乘

两个 int16_t 在常见目标上会提升为 int。
乘法可以在三十二位有符号范围内完成，但后续累加未必能。
对一般 int32_t 乘法，先乘再转 int64_t 更可能已经溢出。
正确形式是在乘法之前完成扩宽，或调用明确返回完整积的目标函数。
转型不能回到过去修复已经发生的未定义行为。

```c
/* 不要以为外层转换能保护内部运算。 */
int64_t wrong = (int64_t)(a * b);

/* a、b 为 int32_t；乘法在 int64_t 域执行。 */
int64_t correct = (int64_t)a * b;
```

第一行只作为错误示意，不进入本章正常测试代码。
如果 a 与 b 的积超过 int32_t，正常 C 程序不能依赖固定回绕结果。
优化器也不承诺保留溢出后的符号检查。
先判断允许范围、使用更宽类型或使用适当的受检接口，才是修复。
本章选择宽类型和显式饱和。

### 不对负数左移来做缩放

`negative << n` 在本章采用的 C11 合同中不是可移植的缩放方法。
对负数右移的结果又由实现定义。
本章用范围已证明安全的乘法表示 ADC 缩放。
用有定义的除法和余数实现对称舍入。
这样不需要把某一种 ISA 的算术右移直接等同为可移植 C 规则。

整数除法从 C99 起向零截断。
余数与被除数的符号保持相应关系。
这些规则允许把 Q30 到 Q15 的还原写清楚。
正负半 LSB 的处理也由函数合同明确指定。
本章采用最近舍入，正好一半时远离零。

### 舍入函数不靠危险偏置

简单写 `value + 16384` 对极大正数可能溢出。
简单写 `abs(value)` 会在最小负数处出问题。
对所有 int64_t 输入都声称安全时，必须覆盖这两个边界。
本章先计算商与余数，再按余数调整商。
除数 32768 为编译期常量，目标编译器可以展开成指令序列。

```c
int64_t quotient = value / 32768;
int64_t remainder = value % 32768;
if (remainder >= 16384) ++quotient;
if (remainder <= -16384) --quotient;
```

完整函数位于 `experiments/ch07/dsp.c`。
测试包括 ±16383、±16384 和 INT64_MIN/MAX。
负半 LSB 返回 -1，正半 LSB 返回 +1。
这不是向负无穷舍入，也不是银行家舍入。
换一种规则可以，但必须同步更新参考结果和偏差分析。

### 饱和不能交给隐式窄化

舍入后的整数可能仍超过 int16_t。
特别是 `(-1) × (-1)` 的数学结果为 +1。
对应整数为 32768，必须按本章合同夹到 32767。
直接转换成 int16_t 不能被称为饱和。
本章先比较范围，再做已经安全的窄化。

| 情况 | 舍入后整数 | 正确本章结果 | 统计 |
|:--|--:|--:|:--|
| 正常可表示 | 12345 | 12345 | 不增加 |
| 正满量程乘积 | 32768 | 32767 | 增加裁剪数 |
| 低于负端点 | -40000 | -32768 | 增加裁剪数 |
| 负半 LSB | -1 | -1 | 不增加 |

裁剪数不是 ADC 过量程次数。
它描述数字计算结果被本章饱和策略限制的次数。
累计计数器本身也有宽度，长时间运行应定义清零和回绕策略。
本章测试只在有界批次中检查计数。
生产系统不应把一个无限运行的无符号计数器当作永不回绕。

## 7.4 宽乘法：四种汇编与两个实际执行目标 {#sec-edge.2.7.4}

### C 接口固定返回完整积

跨架构函数声明为 `int64_t dsp_mul_wide(int32_t, int32_t)`。
两个参数都具有有符号语义。
返回值必须包含完整的六十四位乘积。
不能只返回低三十二位，再让 C 猜测高位。
函数没有修改任何全局缩放状态。

| 目标 ABI | 输入 | 完整返回 | 本轮级别 |
|:--|:--|:--|:--|
| AAPCS32 / Cortex-M3 | r0、r1 | r0 低半、r1 高半 | QEMU 实际执行 |
| RISC-V ILP32 | a0、a1 | a0 低半、a1 高半 | QEMU RV32 实际执行 |
| SysV AMD64 | edi、esi | rax | 交叉汇编和反汇编 |
| AAPCS64 | w0、w1 | x0 | 交叉汇编和反汇编 |

本章不在异步异常边界保存整个上下文。
这里是普通函数调用边界，保存集合按各自 ABI。
不要用这个短函数反推中断处理只需保存这些寄存器。
前三章尚有异常入口修订项，也不会被本函数的测试关闭。
函数级验证与异步上下文验证必须独立。

### Cortex-M3 的 SMULL

ARM 目标用 SMULL 生成有符号三十二乘三十二的完整积。
临时使用 r2、r3 接收结果，再移动到返回寄存器对。
它没有用只保留低半的 MUL 冒充宽乘法。
也没有使用 Cortex-M3 不支持的较新 DSP 扩展。
文件中的处理器声明和编译目标都固定为 cortex-m3。

```asm
smull r2, r3, r0, r1
mov r0, r2
mov r1, r3
bx lr
```

r2、r3 属于普通调用可破坏寄存器。
没有必要为了这段函数额外保存全部非易失寄存器。
返回顺序是低半在 r0、高半在 r1。
若把二者交换，某些只有小正数的测试可能仍看不清错误。
边界集因此包含最小负数、负小数和极大正数。

### RV32 的 MULH 和 MUL

RV32 的 MUL 只提供乘积低半。
MULH 提供有符号乘积高半。
高半必须在覆盖输入之前计算。
因此先写 t0，再计算低半，最后把 t0 放进 a1。
这也满足六十四位返回值的寄存器对约定。

```asm
mulh t0, a0, a1
mul a0, a0, a1
mv a1, t0
ret
```

把 MULH 改为 MULHU 会改变负输入的高半。
低半可能完全相同，单测低三十二位抓不到问题。
本章故障变异实际执行了这个错误版本，并要求目标明确失败。
它不是通过检索源码中是否出现正确助记符来冒充数值测试。
反汇编检查与运行测试各自提供不同证据。

### x86-64 与 AArch64 的符号扩展

x86-64 的参数虽然放在三十二位参数寄存器中，计算前仍需建立所需六十四位有符号值。
本章先用 MOVSLQ 扩展两个参数，再用 IMULQ。
返回放在 RAX。
不把普通写 EDI 后的零扩展值当作已经完成符号扩展。
这在负输入时会造成明显不同的结果。

AArch64 示例使用 SMULL，把两个 W 寄存器的有符号积写到 X0。
这里的 SMULL 是 AArch64 指令形式，不是把 Thumb 语法复制过去。
两种架构同名助记符并不意味着参数个数和编码完全相同。
本轮两个目标都产生对象文件与实际反汇编。
尚未动态运行，所以不标为这些函数全部目标通过。

### 优化必须先保持语义

DSP 扩展、SIMD 和向量指令可能同时处理多个样本。
但打包乘加的累加宽度、饱和模式和舍入规则需要逐项核对。
不能仅凭“这条指令更快”替换标量参考函数。
某些打包 Q15 乘加在极端输入下可能使三十二位累加溢出。
需要重新证明边界，而不是默认原来的六十四位证明继续成立。

同样，使用浮点不自动免除范围和误差分析。
浮点可以在某些任务中更合适，也可能增加状态、工具链和上下文成本。
应比较完整管线的数值要求、存储和目标执行条件。
本章不宣称定点在所有 CPU 上都更快或更省电。
没有实体测量时，不给出虚构的倍速或功耗百分比。

## 7.5 FIR 与 IIR：状态、累加上界与启动响应 {#sec-edge.2.7.5}

### 有限冲激响应需要保存历史

FIR 的当前输出来自多个历史样本乘系数后相加。
本章系数和历史都用 Q15 表示。
每个乘积有三十位小数尺度。
所有乘积先在六十四位累加器中求和。
最后统一舍入到 Q15 并饱和。

每项乘完立刻窄化再相加，会引入不同的量化误差。
每加一次就饱和，也可能改变最终结果。
这两种实现不与“宽累加后一次饱和”自动等价。
优化前必须明确允许改变什么。
本章把后者作为可复现参考合同。

### 环历史不是跨线程队列

`DspFir` 保存固定上限的系数、历史和下一个写入位置。
初始化检查抽头数为 1–16。
每步把新样本写到当前位置。
第 0 个系数乘最新样本，随后沿历史向旧样本方向读取。
完成后移动写入位置，必要时回到零。

这不是 C11 SPSC 队列。
它只有一个计算所有者，不支持主任务和 ISR 同时推进状态。
若要在任务中处理 ADC 样本，先用已定义的缓冲协议交付数据。
再由单个算法上下文更新滤波历史。
给 next 加 volatile 不能把两个并发更新变正确。

### 为什么需要不对称测试

四点平均的系数都为 8192。
如果历史方向写反，平均值可能仍然一样。
只测这种对称滤波器，很容易隐藏索引错误。
所以本章另外使用不对称系数。
单个脉冲应按指定次序产生可预测输出。

| 测试 | 输入与系数 | 预期 | 发现的问题 |
|:--|:--|:--|:--|
| 四点平均冲激 | 首项 32767，其余零 | 连续四项约 8192，之后零 | 历史长度、尾部清理 |
| 四点平均常量 | 连续 16384 | 4096、8192、12288、16384 后保持 | 启动态与 DC 增益 |
| 不对称冲激 | 系数 16384、8192、4096、2048 | 8192、4096、2048、1024、0 | 历史方向与系数顺序 |
| 十六抽头大幅度 | 系数和输入均为 32767 | 正端饱和并记录 | 累加宽度与裁剪 |
| 重新初始化 | 已经处理过非零数据 | 历史回到零 | 状态残留 |

这些测试不能代替所有频率响应指标。
它们先证明实现至少符合结构、顺序和范围合同。
实际设计低通、高通或带通时，还要验证系数量化后的频响。
本章没有把四点平均说成任意场景的高性能抗混叠方案。
它只是容易算清且足够暴露状态问题的实验对象。

### 累加上界要从系数与输入出发

一个十六位有符号样本的绝对值最大为 32768。
一个十六位有符号系数也可能取 -32768。
单项乘积的绝对上界为 2 的 30 次方。
十六项的绝对上界为 2 的 34 次方。
有符号累加器因此至少需要包含符号的三十六位范围来容纳正上界。

六十四位可以覆盖这个固定上限。
三十二位不可以。
如果系数具有更紧的绝对值和上界，可以得到更小的需求。
例如四点平均的系数绝对值和恰好为一个单位。
但不能把这个特例的安全性推广到任意用户上传系数。

本章抽头上限是接口的一部分。
若允许无限抽头，原证明立即失效。
如果未来把系数扩成 Q31，也必须重新计算乘积和累加范围。
宽类型不是永久安全的魔法标签。
范围证明总是绑定数据格式和迭代次数。

### 对称线性相位与等待

对于对称 FIR，在适用的线性相位范围可以讨论群延迟。
N 个抽头的典型群延迟为 `(N - 1) / 2` 个采样间隔。
这不是 CPU 执行耗时。
也不是所有输入变化都只等待这么久才可见。
启动历史、块收集、输出协议还可能增加其他等待。

例如四点平均的群延迟为 1.5 个采样间隔。
若每次等六十四个样本才处理一块，额外块等待可能远大于它。
把算法移入“更快的 DSP 指令”不能消除已经发生的收集等待。
设计截止期应从事件时间走到输出可用时间。
不能只看乘加循环的平均耗时。

### 一阶 IIR 的反馈量化

本章提供 `previous + alpha × (sample - previous)` 的一阶平滑形式。
alpha 用能够包含 32768 的 uint16_t 表示。
因此 alpha=0 表示保持，alpha=32768 表示精确跟随。
若只用有符号 Q15，+1 的端点需要另外约定。
减法先提升到三十二位，避免十六位差值越界。

这里的状态每步仍量化回 Q15。
接近目标值时，小于半 LSB 的修正可能舍入为零。
输出可以停在目标旁边而不是达到无限精度的解析极限。
这是一种量化死区，不应该当作未定义行为。
需要更小稳态误差时，可以给内部状态保留更多小数位。

本实现对超出 32768 的 alpha 做限制。
这是一种明确的接口策略，不是任意 IIR 系数的稳定性证明。
它不实现二阶节，也不声称支持任意反馈滤波器。
测试检查零、一和中间参数，以及负半 LSB 修正。
更一般滤波器还需要极点、系数量化和极限环分析。

## 7.6 FFT64：逐级缩放、位逆序与独立参照 {#sec-edge.2.7.6}

### 明确输出究竟缩放了多少

本章实现六十四点复数 radix-2 DIT FFT。
输入输出都使用实部、虚部各一个 Q15 整数。
每一级蝶形结果除以二并舍入。
六级累计缩放为六十四分之一。
因此输出近似于标准 DFT 的结果再除以 64。

这个归一化不能藏在函数名里不说明。
若拿未缩放 DFT 的幅值直接比较，会差一个六十四倍。
如果再转 dB，误差又会被误读为约三十六分贝的增益问题。
首先确认幅值定义，再讨论窗、噪底和物理量。
算法工作正常并不意味着测量定义已经正确。

| FFT 元数据 | 本章合同 | 如果遗漏 | 测试 |
|:--|:--|:--|:--|
| 点数 | 64 | 频点和块等待错误 | 编译期固定 |
| 变换方向 | 负指数正向 DFT | 正负频率镜像 | 复数单频检查 |
| 总缩放 | 除以 64 | 幅值误判 | 常量与独立 DFT |
| 输出顺序 | 自然频率顺序 | 峰值位置错位 | k=16 单频 |
| 窗函数 | 无，矩形观察 | 泄漏和幅值解释错误 | 不伪称已加窗 |
| 输入时间间隔 | 由调用者给定 | 不能把 bin 变成 Hz | 不由 FFT 猜测 |

### 位逆序发生在哪里

迭代式 DIT 的本实现先做输入位逆序。
随后按长度二、四、八直到六十四进行蝶形。
输出自然排列。
不能在输出侧再无条件做一次位逆序。
否则可能把已经正确的频点重新打乱。

位逆序交换只在当前索引小于反序索引时执行。
这样每对元素只交换一次。
交换实部和虚部必须作为一个复数样本同步完成。
若只交换实部，纯实测试可能无法充分暴露问题。
本章独立参照使用复数输入，而不只看余弦图。

### 旋转因子离线生成

运行时核心不调用 sin、cos 或浮点库。
三十二个 Q15 旋转因子由脚本离线生成。
使用负指数方向，+1 夹到 32767。
脚本的 `--check` 比较当前表与重生成文本。
表不一致时直接失败，不默默继续使用旧文件。

浮点生成只存在于构建辅助和宿主参考。
它不是 ARM 或 RV32 目标的运行时依赖。
生成表是确定性工程制品，也应纳入版本管理。
改变符号、幅度比例或舍入规则，需要同时更新参考说明。
不要把一个来源不明的长常数表当作不可审查的黑箱。

### 复乘为什么仍用宽积

蝶形中的旋转复乘包括两项乘积的和或差。
每项先调用有符号宽乘法函数。
在六十四位中求和，再还原 Q15。
如果先把两项截成 int16_t，误差与动态范围都会改变。
如果用三十二位容纳极端差值，也可能越界。

每级除二有助于限制幅值增长。
但并不保证任意满量程复数输入都不发生分量裁剪。
输入的实部、虚部同时接近满量程时，复数幅值已经超过一个单位。
测试采用具有余量的复数输入，并检查裁剪数为零。
对任意满量程数据，本函数提供饱和保护，不提供无失真承诺。

### 三组目标自检

第一组为所有样本的实部固定为 8192、虚部为零。
归一化后直流点仍应接近 8192。
其他频点应接近零。
这能发现总体缩放和部分索引错误。
但不能充分区分正负变换方向。

第二组为四点周期的复数旋转序列。
依次输入半满量程的实正、虚正、实负、虚负。
六十四点中恰好转十六圈。
按负指数正向变换，峰值应落在 k=16。
如果符号写反，会移到相反方向的频点。

第三组仅在宿主运行独立双精度 DFT。
固定种子生成三十二个复数数据块。
参照逐个频点执行六十四项求和，再除以六十四。
它不调用定点 FFT，也不复用蝶形或位逆序代码。
比较每个输出实部和虚部，最大允许偏差为十二个输出整数 LSB。

### 本轮误差结果怎样理解

本轮最大分量误差约为 2.066014 LSB。
它是所选数据集、缩放和舍入规则下的观察结果。
不是对全部可能输入证明了 2.066014 的误差上界。
十二 LSB 是测试验收阈值，也不是 ADC 有效位数结论。
更严要求需要更完整的误差分析或更宽中间格式。

宿主的 double DFT 不运行在 Cortex-M3 上。
它只是独立参照。
目标上的自检覆盖常量、复数单频和其他数值边界。
不能把宿主三十二块参照比较的每一条路径都算成目标动态覆盖。
报告必须区分两类测试在哪里执行。

### 频点间隔不等于任意信号可分辨能力

给定等间隔采样率 fs，频点间隔为 fs/64。
例如 16 kS/s 时是 250 Hz。
两个相距小于这个数的成分是否能可靠分开，还与观察长度、窗和信噪条件有关。
零填充可以使绘图频点更密，不凭空增加原记录的信息量。
不要把显示更平滑说成测量分辨能力自动提高。

实值输入的频谱具有相应共轭关系。
但本章接口处理完整复数数组，不是优化的实 FFT 打包接口。
不能无条件丢掉后半数组再沿用同一幅值定义。
直流、奈奎斯特点与其他单边谱频点的缩放也应区别处理。
本章没有实现一套自动报告 SNR/ENOB 的测量软件。

### 窗与幅值不能遗漏

输入不恰好覆盖整数周期时，矩形观察会出现谱泄漏。
加窗可改变泄漏分布，也会改变有效增益与噪声带宽。
必须把窗系数、相干增益和带宽定义连同结果报告。
只从最高柱子读取一个 dB 数字不足以代表仪器精度。
母本中关于 FFT 噪底的描述应连同观察带宽理解。

本章不把“FFT 平均”与“时间样本平均”混为一谈。
对多个谱做平均可减少某些随机起伏。
时间域平均又有自己的频率响应和抽取问题。
不同操作要分别说明采样率、单位和有效带宽。
后续项目采用哪一种，应在数据格式和算法配置中固定。

## 7.7 两类实验：宿主参考与真实目标指令 {#sec-edge.2.7.7}

### 统一入口

所有命令从本书根目录执行。
正常入口先检查旋转因子表。
编译宿主 C 测试并启用 ASan/UBSan。
随后生成两个裸机 ELF 并实际运行。
任何工具缺失或目标超时都以失败处理。

```bash
cd edge
bash experiments/ch07/run.sh
bash experiments/ch07/run_mutations.sh
```

负向脚本复用正常入口已经生成的对象文件。
因此需要先运行正向入口。
两次运行同一套脚本不是两轮独立审计。
独立算法参照也仍然是作者提供的测试，不是独立审计员判断。
本章把这些名称分开使用。

### 文件地图

| 文件 | 作用 | 运行位置 | 不覆盖 |
|:--|:--|:--|:--|
| dsp.c | 舍入、饱和、转换、FIR/IIR、FFT | 宿主、ARM、RV32 | 任意长度 FFT、任意反馈系统 |
| wide_c.c | 乘法 C 参考适配 | 宿主 | 目标汇编 ABI |
| selftest.c | 共用数值和状态边界 | 宿主、ARM、RV32 | 独立 DFT 的全部样本 |

### 启动和运行库不能省略

ARM 入口设置可用的向量表并关闭可屏蔽中断。
按链接符号复制 data、清零 BSS。
本例按字节处理边界，不假设所有段长度都是四的倍数。
调用 main 前，栈由向量表初值建立。
初始化完成后才开放采样中断。

RV32 入口关闭机器中断，建立 gp 与 sp。
清零 BSS，再调用 C main。
链接镜像由 QEMU 放在 RAM，本例 data 不需要另从 Flash 搬移。
这不是所有 RISC-V 板的通用启动方案。
真实 XIP 平台仍要按 LMA/VMA 合同复制可写数据。

大结构初始化可能让编译器生成 memcpy 或 memset 调用。
freestanding 不意味着编译器绝不会需要这些帮助函数。
本章提供最小实现和所需 ARM EABI 内存帮助入口。
不把宿主 libc 偷偷链接进裸机 ELF。
链接缺符号直接失败，不能用空函数蒙混过去。

### 成功输出应同时包含哪些条件

ARM 先输出 DSP 自检成功。
然后必须完成 ADC IRQ17 的六十四项接收，才能输出第二条成功。
只看到第一条不能算采样路径通过。
RV32 必须输出自己的 DSP 成功标志并通过测试退出设备终止。
宿主脚本还检查进程退出码与没有 FAIL 文本。

```text
ARM DSP PASS: SMULL, Q15, FIR/IIR, FFT64
ARM ADC PASS: IRQ17, 64 synthetic samples, FIFO read and ISC clear
RV32 DSP PASS: MULH/MUL, Q15, FIR/IIR, FFT64
```

QEMU 的二十秒宿主超时用于防止测试挂死。
它不是目标算法实时预算。
模拟器调试输出也不是生产协议。
真实目标需要替换退出接口并保留自己的错误报告机制。
不能用宿主测试专用端口控制真实设备。

### 负向变异必须确实执行错误代码

第一项把 ARM 的 SMULL 改成 UMULL。
第二项把 RV32 的 MULH 改成 MULHU。
两项都只在构建目录的副本中修改。
重新汇编、链接、运行后，必须在数值自检处明确失败。
超时、无输出或进程被外部杀死不计为成功发现缺陷。

第三项让 ADC ISR 向 ISC 写零而不是写确认位。
DSP 自检应仍然通过。
ADC 通路则必须在确认检查处失败。
这可以区分“算法失败导致没启动采样”和“采样确认路径真的被破坏”。
脚本同时检查这两个阶段的输出。

::: errata agent 生成代码出错案例：助记符相近不代表语义相同
本章有意把有符号乘法换成无符号版本，复现容易由自动生成片段造成的移植错误。
两种版本对乘积低半可以一致，但高半不一致。
只检查小正数或只比较低半，会产生虚假的跨架构通过。
实际变异在两个目标均明确走 FAIL，正常源码没有被覆盖。
这个案例是受控注入，不伪称发生过实体传感器事故。
:::

### 反汇编是运行证据的补充

脚本保存两个 ELF 的反汇编。
可以查到目标实际调用 dsp_mul_wide 的位置和对应乘法指令。
也可以确认运行核心没有意外引入浮点库调用。
但反汇编中存在某个函数，不证明它已经被执行。
因此本章保留目标自检和可失败变体。

若更换优化级别或链接布局，必须重新生成证据。
不要把手工写出的“预期汇编”放到日志目录冒充工具输出。
不应为了避免差异而禁止优化，然后声称已经验证生产优化配置。
本轮使用脚本中明确列出的 O2 配置。
工具版本与原始输出路径记录在验证笔记。

## 7.8 数字失败案例：溢出、混叠和块等待 {#sec-edge.2.7.8}

### 十六抽头把正信号变成负输出

设十六个系数都为 32767。
十六个历史样本也都为 32767。
精确乘积和为 17178820624。
它超过三十二位有符号范围，但在本章六十四位范围内。
正确的舍入和饱和结果应为正端 32767。

为了展示某些硬件式回绕的危险，宿主模型刻意计算模 2 的 32 次方结果。
再用数学减法解释其有符号数值，不在 C 中实际触发 signed overflow。
回绕后的数值为 -1048560。
还原 Q15 近似得到 -32。
于是一个强正输入可能被错误路径解释成小负输出。

| 路径 | 累加值解释 | Q15 输出 | 证据级别 |
|:--|:--|--:|:--|
| 宽累加后饱和 | 17178820624 | 32767 | 宿主与目标的正确实现 |
| 明确建模的三十二位模回绕 | -1048560 | -32 | 宿主数学反例 |
| 普通 C 有符号溢出 | 无可靠约定 | 不承诺固定数值 | 不作为正常程序运行 |

这三个路径不能写成同一件事。
第二行不是替第三行赋予标准保证。
开启优化后，第三行可能产生其他结果或改变控制流。
因此修复不是在溢出后检查 sign。
而是在乘加之前就选择足够范围和受检边界。

### 64 点块处理可能先天无法满足一毫秒

设输入严格等间隔，每秒一万六千个样本。
本节只讨论收齐六十四项后才输出整块结果的算法。
第一项到最后一项之间隔六十三个采样间隔。
每个间隔为 62.5 µs。
最老样本已经等待 3937.5 µs，尚未开始 FFT 计算。

如果合同要求每个样本相关结果在一毫秒内交付，就已经违反。
即使 CPU 计算时间为零也无法修复。
加快乘法、使用 DMA 或提高任务优先级都不能消除已规定的收集等待。
必须修改块大小、输出定义、流式算法或业务截止期。
不能只优化计算阶段后宣布达到一毫秒实时性。

```text
采样率          16000 sample/s
相邻样本间隔    62.5 us
块大小          64
最老等待        (64 - 1) × 62.5 = 3937.5 us
要求            最老样本到相关结果 <= 1000 us
结论            收集阶段已超期，尚未加计算/调度/发送时间
```

这个结论不要求假设某条指令需要多少周期。
它是数据依赖和输出合同直接造成的失败。
宿主测试执行整数纳秒换算并断言该结果。
实验没有把这个 16 kS/s 时钟套到 QEMU ADC 的 timer 配置上。
两套参数属于不同的验证对象。

若业务合同改成“每隔四毫秒输出最近一块”，结论可能不同。
需要重新定义结果时间戳与新鲜度。
把旧截止期悄悄换成新合同，不是修复原系统。
更诚实的做法是把需求变化和新的分析一起记录。
实时系统关心的是被承诺的可用时刻，不是术语是否叫实时。

### 混叠反例只需要数字序列

设采样率为 1000 sample/s。
理想正弦的 900 Hz 输入在该采样时刻会映射成一个 100 Hz 的离散序列，方向或相位相应变化。
在采样后只看到该序列，不能仅靠低通判定原来是 900 Hz 还是目标带内成分。
这说明抗混叠边界必须在采样条件中定义。
它不要求本书提供一套模拟电路设计。

对实余弦，同一组采样点的 900 Hz 与 100 Hz 结果可相同。
后续增加 FFT 点数不会恢复原频率来源。
适当的带通采样在额外带宽和频带约束下可以工作。
但不能把这种专门方案当作任意低采样率都没问题的理由。
本章的基带接口不作这样的隐藏假设。

### ENOB 不能从数组位宽推出

十六位容器不等于十六位 ADC。
十位 ADC 输出左移六位也没有产生六位新信息。
FFT 柱状图看起来平滑同样不等于有效位数提高。
测量指标需要输入幅度、频率、带宽、窗和噪声失真定义。
模拟器合成噪声不提供这些实体证据。

母本关于 SINAD、SNR 与 ENOB 的讨论提示了定义差异。
本章不从一条模型 FFT 自动生成“芯片 ENOB”结论。
输出误差的 LSB 指本章 Q15 整数码。
ADC 原始 LSB、物理单位误差和算法输出 LSB 是三个不同尺度。
数值报告必须标明自己在哪一层。

## 7.10 本章陷阱 {#sec-edge.2.7.10}

1. 把寄存器容器宽度当成转换分辨率。
   现象是十位数据按十二或十六位还原，量程和零点全部错误。
   原因是只看 uint32_t 读值，没有核对 DATA 字段。
   修复是固定芯片版本、掩码与原始格式。

2. 写 PSSI 后在 QEMU 中永远等待转换。
   现象是依赖齐全、寄存器地址正确，却从不完成。
   原因是模型没有实现这个触发入口。
   修复是使用已核实的 timer 触发路径，并单列硬件与模型差异。

3. 依据模拟器十六项 FIFO 估计真芯片 SS3 缓冲时间。
   现象是仿真可用，实体却很快溢出。
   原因是真芯片 SS3 只有一项。
   修复是按器件深度预算服务间隔，不能拿模型内部数组背书。

4. 读取 FIFO 两次，一次处理、一次打印。
   现象是每条日志都跳过样本或触发下溢。
   原因是读取具有弹出副作用。
   修复是一次读取保存快照，后续只打印软件副本。

5. 将乘法结果先算在窄类型，再转宽类型。
   现象是边界输入输出异常，优化后还可能改变控制流。
   原因是溢出早于强制转换。
   修复是先扩宽，或使用经过 ABI 验证的完整积函数。

6. 用无符号高半乘法替换有符号高半。
   现象是正数通过，负数高半错误。
   原因是助记符相似但符号语义不同。
   修复是比较完整六十四位并运行负数变异测试。

7. 认为 -32768 乘 -32768 可以直接窄化。
   现象是正满量程变成负端点或其他实现相关结果。
   原因是 +1 超出有符号 Q15 正端。
   修复是舍入后显式饱和，并记录裁剪。

8. 只用四点平均检查 FIR 历史方向。
   现象是测试通过，换成不对称系数后响应顺序反转。
   原因是对称系数掩盖了索引错误。
   修复是保留不对称冲激和重新初始化测试。

9. 把 IIR 的量化死区当作算法一定到达解析极限。
   现象是输出在目标附近停住一个码。
   原因是每步反馈被窄化，微小修正舍入为零。
   修复是明确容差，必要时扩宽内部状态。

10. 忘记 FFT 每级除二。
    现象是与参照幅值差六十四倍，或全程裁剪。
    原因是没有记录累计缩放。
    修复是把归一化写入接口元数据，并检查常量 DC。

11. 把先收齐六十四项的算法称为一毫秒逐样本结果。
    现象是 CPU 几乎空闲，最老样本仍然超期。
    原因是截止期预算漏掉收集等待。
    修复是从采样时刻算完整路径，必要时改变算法合同。

12. 把合成 ADC 噪声或 FFT 输出误差说成芯片 ENOB。
    现象是数字结果漂亮，却没有实体输入、时钟和测量带宽。
    原因是混淆数值自检与仪器测量。
    修复是分别报告验证层次、单位和未覆盖条件。

## 7.11 本章出口检查与复现自审 {#sec-edge.2.7.11}

::: method 从数值合同到目标执行
先运行旋转因子重生成检查与宿主 sanitizer 测试。
再查看独立 DFT 的误差报告，确认缩放和单位。
随后检查 ARM、RV32 的实际日志及 ELF 反汇编。
最后执行三个故障变体，要求明确 FAIL，不能以超时代替。
:::

本章至少有两个独立可执行方向。
一是宿主范围、滤波状态和独立 DFT 参照。
二是裸机 ARM/RV32 的乘法、算法与目标接口执行。
ARM 方向还包含真实执行的 MMIO、NVIC 和合成 ADC 中断路径。
这里的“真实执行”指指令与设备模型，不指实体模拟输入。

::: ex 读者复核 {#ex-edge.2.7.11.1}
在临时副本中把 FFT 的总归一化解释错误地改成未缩放输出，比较常量测试。
再将 FIR 系数反向排列，观察不对称冲激测试，而不是只看四点平均。
最后把六十四点块改成更小块，重新推导最老样本等待和频点间隔。
每次修改都应说明同时改变了哪个数值合同或输出合同。
:::

复现者还应确认以下边界没有被遗漏。
未对 QEMU ADC 声称电压精度、ENOB 或实体采样率。
未把 x86/AArch64 对象存在等同为动态运行。
未将宿主 double DFT 的结果说成目标浮点计算。
未将单次运行最大值称为 WCET 证明。

滤波器状态仍需接入真实应用的所有权与错误协议。
ADC 溢出、丢样、时间戳和恢复策略尚需扩展验证。
本轮没有实体开发板、示波器、功耗或热漂移证据。
母本全覆盖与两轮独立逐节审计未完成。
这些限制保留在审计台账，不能因章节长度达标就移除。
