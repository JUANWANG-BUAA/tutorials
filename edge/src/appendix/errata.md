## B.1 八大经典嵌入式架构陷阱速查

| 序号 | 经典架构陷阱 | 故障表象 | 物理 / 微架构根因 | 正确防御机制与代码准则 |
|--:|:--|:--|:--|:--|
| 1 | **DMA 缓冲区 Cache 未刷新** | CPU 读到陈旧数据或外设发送垃圾数据 | DMA 控制器直接旁路 CPU Cache 访问物理内存，D-Cache 未做 Invalidate 或 Clean | 在启动 DMA 传输前执行 `SCB_CleanDCache_by_Addr`，接收完成后执行 `SCB_InvalidateDCache_by_Addr`，缓冲区按 Cache Line (32/64B) 严格对齐 |
| 2 | **中断服务程序漏清中断标志** | 退出中断后 CPU 立即重复陷入中断，主循环永久饥饿 | 外设中断标志位未写 1 清零，或总线写缓冲滞后导致清零操作尚未写入外设寄存器 | 必须在 ISR 首部或尾部显式清零中断标志，并在退出前执行内存屏障 (`DSB`) 确保外设总线写入完成 |
| 3 | **Thumb-2 / RISC-V 栈指针非双字对齐** | 浮点或 64 位指令触发 UsageFault / 对齐异常 | AAPCS 规定函数调用边界上 SP 必须保持 8 字节对齐（`SP % 8 == 0`） | 启动汇编中确保栈基址按 8 字节对齐，中断入口栈帧保存后检查对齐位（如 ARM `xPSR[9]` 对齐指示） |
| 4 | **弱内存序架构下无锁队列写撕裂** | 单生产者单消费者环形队列读出乱序数据 | ARM/RISC-V 具备弱内存序流水线，写数据与更新写指针被 CPU 或编译器重排 | 在写入数据与更新索引之间插入写内存屏障（ARM `DMB`，RISC-V `fence w,w`，x86 `sfence`） |
| 5 | **CAN 总线采样点偏离 75%–80%** | 节点在高温、长线缆或高负载下突发 Stuff Error 并最终 Bus-Off | 同步段、传播段与相位缓冲段计算错误，导致在电平建立不稳定阶段读取总线 | 严格按照传播延迟公式 $2 \times (T_{prop} + T_{rx} + T_{tx})$ 计算传播段，确保采样点位于位时间的 75% 至 80% 之间 |
| 6 | **关中断临界区未保存原始优先级** | 嵌套临界区退出后过早开启全局中断，破坏外层保护 | 简单使用 `cpsie i` / `cpsid i` 而非保存和恢复之前的 `PRIMASK` 状态 | 采用保存机制：`uint32_t pri = __get_PRIMASK(); __disable_irq(); ... __set_PRIMASK(pri);` |
| 7 | **通用定时器中断喂看门狗假活** | 主任务由于死锁或资源耗尽永久挂起，但系统永不复位 | 看门狗喂狗操作独立于业务逻辑，定时器中断仍在周期性触发 | 采用任务心跳标志图机制：所有核心任务均必须在周期内打卡置位，主循环验证全置位后方可喂狗 |
| 8 | **低功耗模式进入前 GPIO 引脚浮空** | 待机状态下芯片实测电流比手册理论值大 100 至 1000 倍 | 浮空输入引脚内部施密特触发器处于线性放大区，产生严重穿通漏电流 | 进入 Sleep/Stop 模式前，将所有未连接或悬空的 GPIO 配置为模拟输入（Analog Mode）或上拉/下拉 |

## B.2 硬件勘误报告规范

当在开发板或仿真靶机上捕获到异常时，应遵循以下工业级证据格式记录：
1. **测试靶机环境**：芯片型号、硅片版本（Stepping）、主频、编译工具链版本及优化级别（如 `-O2`）。
2. **复现命令与配置**：完整的 GDB 调试脚本、启动参数或逻辑分析仪采样率配置。
3. **故障现象与现场转储**：捕获故障时的 PC、LR、SP、PSR 寄存器值及外设寄存器 Raw Hex Dump。
4. **根因归因**：指明是编译器优化乱序、硬件总线冲突、时钟漂移还是逻辑竞争。
5. **最小复现用例与验证补丁**：提供一段脱离复杂依赖的最小独立验证源码。
