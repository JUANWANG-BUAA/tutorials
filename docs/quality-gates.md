# 质量检查与内容审校

## 本地与 CI 的同一入口

在仓库根运行：

```bash
bash check.sh                 # 单元测试、章节检查、项目测试、完整构建、产物和浏览器检查
bash check.sh --no-browser    # 不运行浏览器；其余检查照常执行
bash check.sh --no-build      # 检查已有 _site；只适合未修改正文、主题或构建脚本时
```

构建依赖为 mdBook 0.5.4、mdbook-katex 0.10.0、Python 3.11+、Node.js 24，以及 Python 包 `markdown-it-py`、`pillow`，以及 `tools/formal/requirements.txt` 中固定版本的 Z3、SymPy、mpmath。编译器项目测试需要 clang；安装 LLVM 可增加反汇编检查，Rust 用例需要 rustc。缺少目标平台执行能力时，项目测试会明确报告跳过项。

浏览器检查通过固定版本的 Playwright CLI 执行，首次使用需下载 Chrome：

```bash
npx --yes --package @playwright/cli@0.1.22 playwright-cli install-browser chrome --with-deps
node tools/check_browser.mjs  # 复用已有 _site，仅运行浏览器检查
```

CLI 的安装和调用方式见 [Playwright CLI 官方说明](https://github.com/microsoft/playwright-cli)。脚本使用独立浏览器会话、系统分配的本地端口和临时 `/tutorials/` 路径，结束后关闭自身进程并删除临时目录。浏览器截图保存在忽略目录 `output/playwright/`。

`.github/workflows/deploy.yml` 在 main 推送、面向 main 的 PR 和手动触发时调用 `bash check.sh`。仅 main 的非 PR 运行在全部检查成功后发布 Pages；PR 只验证。修改检查范围时改 `check.sh`，构建步骤统一在 `build.sh` 中维护。

## 已接入的检查与边界

| 层 | 检查内容 | 边界 |
|:--|:--|:--|
| 数学核验 | 33 项 SMT-LIB 义务与 196 个迭代表数值复算；见[核验记录](formal-verification.md) | 只证明已编码的有限维或标量命题，不表示全书已形式化证明 |
| 共享前端 | 偏好 schema、共享文件与符号链接、搜索恢复、计时器、高亮、索引编码、缓存 | 单元测试不能代替实际页面交互 |
| 章节结构 | Linux、Agent、分布式、编译器四卷现有 `check_book.py` | 检查结构、锚点和链接等机械规则，不证明知识结论正确 |
| 覆盖映射 | Linux、Agent、编译器重建覆盖矩阵；分布式校验覆盖表 | 有落点不等于讲解充分；生成器会刷新对应 Markdown 文件 |
| 配套项目 | Agent 两个项目、迷你编译器、代码验证器、幂等后端、复制 KV | 执行项目测试，不宣称已运行所有正文片段或全部章节实验 |
| 站点构建 | 八卷完整构建、中文搜索探针、术语和资源后处理 | 保留 mdBook 的大索引警告；不将其误报为公式渲染错误 |
| 部署产物 | 运行资源、CSS 字体、重复 ID、每页唯一且同步执行的 head 偏好脚本 | 同时检查全站本地正文链接与片段；Agent、编译器另执行现有 HTML 链接检查 |
| 浏览器 | 阅读交互、课程筛选与跨课程恢复、主题和移动视口、存储拒绝、无 JavaScript 降级、真实 Service Worker 缓存 | 当前使用桌面 Chrome 的移动视口模拟，未覆盖 Safari 或手机实机 |

首屏偏好恢复同时检查源模板和生成 HTML。模板缺失、脚本只在 body 中出现、重复加载或被改为 async/defer/module 都会让检查失败。空 `_site` 同样不通过。

## 内容审校方法

机器检查通过后，每次内容改动仍需逐项检查：

1. 对照本节学习目标，确认例题和自测确实要求读者运用该能力。
2. 重新推导公式、重算数值；定理写清假设与适用边界，结论至少检查一个反例或边界情形。
3. 对版本相关结论链接到对应官方规范，记录版本与核验日期，避免将某一版行为写成永久事实。
4. 对可运行示例记录环境、命令、实际输出及跳过项，区分结构检查、语法检查与运行结果。
5. 在审校记录中注明检查范围；未抽查的章节保持未审状态。

篇幅和覆盖数用于发现遗漏。最终验收以学习目标、技术正确性、实验结果和引用证据为依据。
