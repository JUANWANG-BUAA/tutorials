# 5.1 从 ARMv7-A 到 ARMv8-A：版本演进

第二章 2.1 讲过 ARM 把体系结构版本与处理器核分开：Cortex-A9 用的是 ARMv7-A。现在要补上后半段故事——**ARMv8 起，版本号不再只意味着"加了新指令"**。（依据素材书第 1 章）

## 5.1.1 AArch32 与 AArch64：两个执行状态族

ARMv8 起，"体系结构"被拆成两条并行演进的线：

| | AArch32 | AArch64 |
|:--|:--|:--|
| 指令宽度 | 32 位 ARM + 16 位 Thumb | **恒定 32 位**（不再有 Thumb 压缩态） |
| 寄存器宽度 | 32 位 | **64 位**（x0–x30），另有 32 位视图 w0–w30 |
| 通用寄存器 | R0–R15（16 个） | x0–x30（31 个）+ SP + PC |
| 异常体系 | 7 种异常 + 固定低向量表 | **4 个异常级 EL** + 可编程向量表（VBAR_ELx） |
| 状态寄存器 | CPSR / SPSR | PSTATE + 各 EL 的 SPSR_ELx（系统寄存器） |
| 典型形态 | Cortex-A/R/M | Cortex-A/R，服务器与高端 MCU |

关键点：**AArch64 不是 AArch32 的兼容超集**。ARMv8 处理器可以只实现 AArch32（兼容老软件），也可以只实现 AArch64，也可以两者都实现（此时 AArch32 被称为 "AArch32 compatibility"）。在 ARMv9 之后，**AArch32 被逐步放弃**：ARMv9 规定实现 AArch64 是强制的，AArch32 变成可选特性；苹果 M 系列等平台已彻底不提供 AArch32。

::: note 一个命名细节
"AArch64" 这个名字是为了与 "ARMv8-A AArch32" 区分而起的——若直接叫 "ARMv8"，就会和同版本的 32 位体系结构混淆。这个命名沿用到今天，"AArch64 处理器"就等于"跑 AArch64 指令集的核"。
:::

## 5.1.2 为什么 ARM 要做 64 位

素材书给的三条理由概括了当时的产业动因：

1. **地址空间**：32 位地址最多 4 GB。手机操作系统、应用、虚拟机、GPU 缓冲加在一起，4 GB 远远不够——64 位地址空间让"每进程独立地址空间 + 大内存"成为可能。
2. **通用计算的入场券**：服务器与桌面此前由 x86-64 占据。ARMv8-A 的推出让 ARM 拿到进入该市场的技术许可；苹果 2020 年底发布的 M1 是标志性事件（ARMv8.5-A）。
3. **生态与授权**：在手机与嵌入式芯片领域，ARM64 架构处理器占比超过 90%；海思、展讯、瑞芯微、全志等国内芯片厂商都基于 ARM64 打造方案。

::: think 64 位带来的不只是"地址变多"
地址空间只是最直观的一条。64 位还带来：更大的寄存器（编译器能少做几次搬运）、更大的 SIMD/FP 寄存器、统一的地址与指针语义。代价是**兼容性负担**——同一家公司既要维护 32 位产品线，又要维护 64 位产品线，指令集与寄存器模型还不能直接复用，这正是 [5.3](sec5-3.md) 要讲的"为什么 A64 的立即数要换一套构造法"。
:::

## 5.1.3 ARMv8 与 ARMv9 的关键增量

素材书 1.5 节简介了 ARMv9。要点：

- **ARMv8-A** 起引入**异常级（Exception Level）**概念（详见 [5.4](sec5-4.md)），这是权限模型的基础；
- **ARMv8.1** 引入 AArch64 的内存标记扩展（MTE）、更强的 PASID 支持，以及页表项的**硬件管理访问位/脏位**（TTHM，详见 [5.6](sec5-6.md)）；
- **ARMv8.2** 引入 SVE（可伸缩向量扩展，素材书第 23 章）与复合加载/存储等；
- **ARMv8.3 / 8.4 / 8.5 / 8.6** 持续补充安全性（指针认证、内存标记、机密计算）与多核一致性特性；
- **ARMv9** 强制实现 AArch64，并引入**可扩展架构（Realm）**与更多安全增强。

::: note 素材书基于 ARMv8.6
《ARM64 体系结构编程与实践》明确以 **ARMv8.6** 为基准。本章讲到具体特性时会指出它属于哪个小版本——因为"这颗核支不支持"直接决定代码能不能用。
:::
