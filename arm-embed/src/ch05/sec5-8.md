# 5.8 高速缓存：映射方式与共享性

第二章 2.3.3 说过 Cortex-A9 有多级 Cache、CP15 协处理器控制它，但没说清 Cache 到底怎么组织、哪些内存可以共享。本节补上这两块——它们是理解多核一致性的前提。（依据素材书第 15 章）

## 5.8.1 Cache 的基本构件

处理器访问 Cache 时的地址被切成三段（以 32 位地址为例）：

| 字段 | 作用 |
|:--|:--|
| **标记（tag）** | 地址高位，用于判断"这一行是不是我要的" |
| **索引（index）** | 用于定位到哪一组（set） |
| **偏移量（offset）** | 在行内定位到具体的字节/字 |

配套概念：

- **高速缓存行（cache line）**：Cache 中最小的访问单元，通常 **32 或 64 字节**；
- **组（set）**：由索引相同的行组成；
- **路（way）**：组内并列的多条行。

一次 Cache 查找（素材书 15.3）：**用索引找组 → 在组内用标记比对 → 命中则用偏移取数据**。

## 5.8.2 三种映射方式

| 方式 | 结构 | 特点 |
|:--|:--|:--|
| **直接映射** | 每组只有 1 行 | 硬件最简单，但冲突严重 |
| **全相连映射** | 只有 1 组，组内 n 行 | 冲突最小，比较器多、成本高 |
| **组相连映射** | 多组，每组若干行 | **现代处理器的标准做法** |

**直接映射的冲突代价**（素材书给了具体例子）：一个 4 行、每行 4 字的 Cache，用 Bit[5:4] 作索引。主存中 Bit[5:4] 相同的地址（0x00、0x40、0x80……）**全部映射到同一行**。于是：

```c
void add_array(int *data1, int *data2, int *result, int size) {
    for (i = 0; i < size; i++) result[i] = data1[i] + data2[i];
}
```

若 data1=0x40、data2=0x80、result=0x00，三者同映射一行——每轮循环都要把行换出去又换进来，这就是**高速缓存颠簸（cache thrashing）**。

**组相连**的改进：2 路组相连时，0x00/0x40/0x80 可以映射到同一组的任意一行，替换时有 50% 概率不冲突。

**算一个真实的 Cache 结构**（素材书 15.4.4 例）：32 KB、4 路、64 字节行：

```
每路大小   = 32 KB / 4      = 8 KB
每路行数   = 8 KB / 64 B    = 256 行
→ 组数     = 256
→ 索引域   = Bit[12:5]   （8 位）
→ 标记域   = Bit[31:13]
→ 偏移域   = Bit[4:0]    （行内寻址：Bit[4:2] 选 8 个字，Bit[1:0] 选字节）
```

## 5.8.3 共享属性：谁能看到这份数据

多核系统里，内存区域按"谁能访问/共享"分四类（素材书 15.8.1）：

| 属性 | 含义 |
|:--|:--|
| **Non-shareable（不可共享）** | 只能被**一个处理器**访问，其他处理器不能访问 |
| **Inner Shareable（内部共享）** | 区域内的**处理器**可以共享其 Cache；**系统中的其它硬件单元（DMA、GPU）不能** |
| **Outer Shareable（外部共享）** | 处理器**以及**有访问内存能力的硬件单元（GPU 等）**都可以**相互访问并共享 Cache |
| **System Shareable（系统共享）** | 系统中所有访问内存的单元都可访问并共享 |

这套属性写在页表项的 **SH** 字段里（5.6.4），与内存屏障的行为也相关（5.10）。

::: think 为什么"共享"要分内外
因为**一致性的代价不同**。内部共享只需核间保持一致（SCU 或片内互连负责，2.3.2）；外部共享还要让 GPU、DMA 这类非核主设备看到一致的数据（需要 ACE 协议，5.9.2）。把二者分开标注，硬件才能只对真正需要跨域一致的区域付出代价。
:::

## 5.8.4 PoU 与 PoC：两个观察点

这是 AArch64 高速缓存最关键的概念（素材书 15.8.2），也是理解维护指令的前提。

| | **PoU**（Point of Unification，统一点） | **PoC**（Point of Coherency，一致点） |
|:--|:--|:--|
| 观察角度 | **处理器**（或一组内部共享的处理器） | **整个系统**（所有能发起访存的单元） |
| 保证什么 | 该处理器看到的指令 Cache、数据 Cache、TLB、MMU 是**同一份数据的副本** | 系统里所有主设备（CPU、GPU、DMA）看到的**同一地址的数据一致** |
| 典型观察点 | L2 Cache（核内各核看到的副本相同） | **系统内存** |

**举例**（素材书 15.8.2）：

- 系统只有 CPU、带 L1 与 L2 Cache：PoU 就等于 PoC；
- 系统有 CPU + GPU：CPU 侧的 L1/L2 构成 **PoU**（GPU 改了内存，CPU 的 L1/L2 可能与内存不一致）；CPU、GPU 与系统内存整体构成 **PoC**。

**为什么要分这两个**：**高速缓存维护指令必须知道作用范围**——"失效 PoU 处的指令 Cache"与"失效 PoC 处的整行"是两种不同的操作。前者便宜（只影响本核共享域），后者昂贵（要跨到系统总线）。

## 5.8.5 高速缓存维护操作

AArch64 的维护操作分四类（素材书 15.9）：

| 操作 | 做什么 |
|:--|:--|
| **失效（invalidate）** | 让缓存行作废，**丢弃**其中的数据 |
| **清理（clean）** | 把**脏**行写回下一级或内存，然后清除脏位 |
| **清零（zero）** | 把零数据主动写进缓存行（用于大块临时内存的预热，节省带宽） |
| **清理并失效** | 先 clean 再 invalidate |

作用范围可以是：整块 Cache、某个虚拟地址、特定的行/组/路。

指令通过 **DC（数据 Cache）** 与 **IC（指令 Cache）** 两条前缀实现，操作码由四部分组成：

- **功能**：如清理、失效；
- **类型**：`VA`（单个虚拟地址）、`SW`（按组/路）、`ALL`（整块 Cache）；
- **观察点**：`U`（站在 PoU 角度）、`C`（站在 PoC 角度）；
- **共享**：`IS`（内部共享属性）。

例如 `IC IALLUIS`：使**内部共享域中所有处理器**的指令 Cache 全部失效（站在 PoU 角度）——这正是多核系统里"内核改了代码，其它核也得看到"的必要操作。

**枚举 Cache 信息**用系统寄存器 **CLIDR_EL1**：其中 Ctype\<n> 字段描述每一级 Cache 的类型，软件遍历这些字段直到读到 000，就知道系统实现的最高 Cache 级数与各级参数。

## 本节小结

Cache 的三段地址编码（标记/索引/偏移）决定查找方式；三种映射方式中**组相连**是现代标准，它化解了直接映射的颠簸。共享属性分不可共享/内部共享/外部共享/系统共享四档；**PoU 与 PoC** 两个观察点则回答了"维护操作的作用范围有多大"。下一节讲跨核的一致性协议与第二章 2.3.2 的 SCU 如何接上。
