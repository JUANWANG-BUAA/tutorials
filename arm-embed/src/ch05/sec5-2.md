# 5.2 AArch64 执行状态与寄存器组

AArch32 有 16 个通用寄存器（R0–R15），R15 当 PC、R13 当 SP。64 位时代这套约定没法直接照搬——于是 ARM 重新设计了一遍：**寄存器数量从 16 变成 31，PC 与 SP 从通用寄存器里独立出来**。（依据素材书第 1 章）

## 5.2.1 x0–x30：31 个通用寄存器

AArch64 提供 **31 个 64 位通用寄存器 x0–x30**，外加两个独立寄存器：

- **SP（栈指针）**：不再是某个通用寄存器，而是独立寄存器；**PC（程序计数器）**：同样独立，不再能当通用寄存器读写。

这条变化的来由很实际：AArch32 里 R15 当 PC 时有一堆限制（读到的值要 +8、写入要 4 字节对齐、不能参与大多数运算），R13 当 SP 也有一堆限制（不能做偏移量之外的用途）。AArch64 把它们**彻底摘出去**，代价是汇编代码要改，但换来了干净的架构。

```asm
; AArch32（第 3.5.2 节）：R13 当 SP，R15 当 PC
        MOV   PC, LR           ; 返回
        STMFD SP!, {R0-R3, LR} ; 压栈

; AArch64：SP 与 PC 是独立寄存器，x30（LR）回归普通通用寄存器
        RET                    ; 等价于 PC ← x30，返回
        STP   x29, x30, [sp, #-16]!   ; 压栈（成对存储，见 5.3）
```

::: note x30 的别名：LR
AArch64 仍把 **x30 叫作 LR（Link Register）**——它承担 BL 指令保存返回地址的职责，于是"保存 LR"这条约定保留下来。但它**不再有特殊地位**：可以参与任何运算，x0–x30 一视同仁。真正的 SP/PC 是独立寄存器。
:::

## 5.2.2 32 位视图 w0–w30

每个 x 寄存器都有一个 **32 位视图 w0–w30**：写 w 寄存器时，只更新对应 x 寄存器的低 32 位，**高 32 位清零**。

```asm
        MOV   x0, #0x123456789abcdef0
        MOV   w0, #0x11223344    ; x0 变成 0x0000000011223344（高 32 位被清零）
```

这与 AArch32 的语义差别很大，值得记住：AArch32 里 R0 天然就是 32 位，不存在"高半部分"的概念；AArch64 里寄存器是 64 位的，w 视图是一次**显式截断**，而且截断方式是"清零"而不是"保留高位"。

## 5.2.3 零寄存器：XZR 与 WZR

AArch64 提供了两个**恒为零的寄存器**：

- **XZR**：读作 0 的 64 位寄存器；
- **WZR**：读作 0 的 32 位寄存器（是 XZR 的低 32 位视图）。

它们不是"某个被硬件强制为 0 的通用寄存器"——而是编码上省位的技巧：**写 xzr 等价于丢弃结果**，所以像"比较但不保留结果"这类操作用 xzr 表达最自然。

```asm
        SUBS  xzr, x1, x0       ; 计算 x1 - x0 并更新标志，但不保留结果
        B.hs  out_of_index      ; 进位为 1 说明 x1 >= x0（无符号）
```

这正是素材书自测题第 5 题的写法：**用 xzr 做"只比较不保存"**，是 AArch64 相对 AArch32 的一个顺手的改进（AArch32 得靠 CMP 指令）。

## 5.2.4 向量与浮点寄存器

除了通用寄存器，AArch64 还有 SIMD/浮点寄存器组：

- **v0–v31**：128 位，每个既可当 128 位向量用，也可拆成若干 64/32 位标量元素；
- 标量视图 **d0–d31**（64 位双精度）、**s0–s31**（32 位单精度）、**h0–h31**（16 位半精度）。

这个"一套寄存器、多种视图"的做法与 w/x 的思路一致：**用同一份物理存储，通过不同的访问宽度满足不同精度需求**，编译器因此不必为浮点单独分配寄存器组。

::: note SVE 是另一回事
素材书第 22、23 章讲的 NEON 与 SVE 是"可向量化的数据处理"，与本章讲的"寄存器组视图"是两个层面。NEON 固定 128 位，SVE 则把向量长度做成**运行时可配置**（128–2048 位），为此需要额外的可伸缩向量寄存器组 Z0–Z31。
:::

## 5.2.5 与第二章寄存器表的对照

| | AArch32（2.7 节） | AArch64 |
|:--|:--|:--|
| 通用寄存器 | R0–R12（13 个） | x0–x30（31 个） |
| 栈指针 | R13（约定为 SP） | **独立 SP** 寄存器 |
| 链接寄存器 | R14（LR，存返回地址） | x30（LR，可参与运算） |
| 程序计数器 | R15（PC，有读写限制） | **独立 PC** 寄存器 |
| 状态寄存器 | CPSR + 5 个 SPSR | **PSTATE** + 各 EL 的 SPSR_ELx |
| 分组寄存器 | R8–R12 两份、R13/R14 七份 | **无分组**——异常级切换不换寄存器组 |
| 零寄存器 | 无（R0 靠清零） | **XZR / WZR** |

最后一行值得强调：AArch32 的分组寄存器是"每种模式一套栈指针与返回地址"（2.7.2），AArch64 **取消了分组**——因为异常级之间切换时改用 `SP_ELx` 选择（[5.4](sec5-4.md)），寄存器 x0–x30 全局共享。这让 AArch64 的异常处理代码简洁得多。
