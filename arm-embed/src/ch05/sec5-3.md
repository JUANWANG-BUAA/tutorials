# 5.3 A64 指令集：与 A32 的关键差异

AArch32 的指令编码把 cond、寄存器编号、操作码挤在 32 位里，每加一个特性都要精打细算（3.1 节）。AArch64 换了个思路：**指令恒定 32 位，但语法大幅简化**，把省下来的空间用在别处。本节讲六个最影响写法的差异。（依据素材书第 3–7 章）

## 5.3.1 编码恒定 32 位，语法更规整

AArch64 **没有 Thumb 状态**：所有指令都是 32 位。这带来一个直接后果——

::: ex 例 5.3.1 · 一个看似矛盾的问题 {#ex-5.3.1}
**A64 指令集支持 64 位宽的数据和地址寻址，为什么指令的编码宽度只有 32 位？**

因为 AArch64 换了一套编码哲学：**指令不再是"定长编码 + 可变立即数"，而是"定长编码 + 可变长度立即数"**。64 位立即数无法塞进 32 位指令字，但可以拆成多条指令（见 5.3.2）；64 位地址也一样，靠 PC 相对寻址分两步走（见 5.3.5）。
:::

指令编码仍然 32 位，但字段划分完全重排，助记符与字段是一一对应的——这让 A64 的指令集**更容易扩展**（新增指令只需占用新的编码空间，不必像 AArch32 那样从 4 位 cond 里抠）。

## 5.3.2 立即数：MOVZ / MOVK 拼装

AArch32 的立即数用"8 位循环右移偶数位"构造（3.2.4），能表达的常数有限。AArch64 换成了**两条指令拼装任意 64 位常数**：

```asm
        MOVZ  x0, #0x1234, LSL #0      ; x0 = 0x0000000000001234
        MOVK  x0, #0x5678, LSL #16     ; 把 0x5678 插到第 16 位
        ; 此时 x0 = 0x0000000056781234
```

| 助记符 | 作用 |
|:--|:--|
| **MOVZ** | 把立即数零扩展到 64 位并写入目标寄存器（Z = Zero） |
| **MOVK** | 把立即数**保留**目标寄存器其它位、只替换指定位段（K = Keep） |

`MOVZ` 后可跟 `LSL #0/16/32/48`，指定该 16 位片段落在 64 位里的哪一段。于是**任意 64 位常数最多 4 条指令拼出**，而且每条只处理 16 位——这正是"定长编码 + 可变长度立即数"的含义。

对照 AArch32 的能力边界（素材书自测题第 2 题）：

| 常数 | AArch32（8 位循环右移） | AArch64（MOVZ/MOVK） |
|:--|:--|:--|
| `0x1234` | ✓ | ✓（1 条 MOVZ） |
| `0x1abcd` | ✗（需 5 个位） | ✓（MOVZ + MOVK） |
| `0x12bc0000` | ✗ | ✓（MOVZ + MOVK） |
| `0xffff0000ffff` | ✗ | ✓（4 条） |

## 5.3.3 条件执行：cond 域消失，改为 CSEL

AArch32 每条指令都带 4 位 cond 域（3.1.2），不满足条件时整条指令变成空操作。AArch64 **取消了 cond 域**——因为 32 位太宝贵，且"条件执行"这个特性用**选择指令**实现更灵活：

```asm
        CMP   x0, #10
        CSEL  x1, x2, x3, EQ      ; 若 EQ 成立取 x2，否则取 x3
```

`CSEL`（Conditional Select）四个操作数：目标、目的为真时的源、目的为假时的源、条件。同族还有：

| 指令 | 行为 |
|:--|:--|
| **CSEL** | 二选一 |
| **CSINC** | 二选一，"假"分支可加 1（用于指针步进） |
| **CSINV** | 二选一，"假"分支取反 |
| **CSNEG** | 二选一，"假"分支取负 |

::: think 为什么放弃 cond 域是进步
AArch32 的 cond 域有个尴尬：条件不满足时指令不执行，但**仍然占用取指带宽与译码资源**——AArch32 的流水线遇到"不执行"的指令要照常走完。CSEL 则是**实际执行**一条数据处理指令（只是从两个源里选一个），在乱序执行的多发射核上反而更高效。代价是表达式写起来啰嗦——`CMP + ADDcc` 两行，变成 `CMP + CSEL` 两行，收益不直观，这正是 AArch64 代码"可读性下降"抱怨的来源之一。
:::

**例外**：AArch64 保留了几条"条件执行"性质的指令——**分支指令 B.cond 仍然带条件**，以及**立即数被零扩展/符号扩展的分支类指令**。但数据处理指令不再有条件版本。

## 5.3.4 Load/Store 与寻址

AArch32 的寻址方式有九种（3.2），前/后索引、寄存器偏移、移位偏移一应俱全。AArch64 把它们**大幅收敛**：

- **不再有"后索引"**（`[Rn], #off`）——内存偏移寻址只保留**前索引**形式（偏移在方括号内，基址可选择回写）；
- **不再有单独的"寄存器偏移 + 移位"**——寻址模式简化为"基址 + 立即数偏移"或"基址 + 寄存器偏移"；
- **新增 LDP/STP**（Load/Store Pair）：一次存取**两个相邻的 64 位寄存器**。

```asm
; AArch32（第 3.4.3 节）：满递减栈
        STMFD SP!, {R4-R7, LR}
        LDMFD SP!, {R4-R7, PC}^

; AArch64：成对存取，偏移在方括号内
        STP   x29, x30, [sp, #-16]!   ; 存 x29/x30，SP 先减 16
        LDP   x29, x30, [sp], #16      ; 取回并把 SP 加 16
```

STP/LDP 的偏移写法与 AArch32 的后索引等价（先访问、后更新基址），但因为偏移在括号**内**，读起来是"前索引"的样子——这是 A64 里最容易看错的地方。

## 5.3.5 PC 相对寻址：ADRP + ADD

AArch32 里取一个较大范围的地址要靠伪指令 `LDR Rd, =addr`（走文字池，3.9.4），链接距离受 4KB 限制。AArch64 用两条真指令实现位置无关的大范围寻址：

```asm
        ADRP  x0, symbol        ; x0 = 页基址（PC 相对，页粒度 4KB）
        ADD   x0, x0, :lo12:symbol  ; 加上页内偏移，得到完整地址
```

| 助记符 | 作用 |
|:--|:--|
| **ADRP** | PC 相对，取**页基址**（地址向下对齐到 4KB 边界） |
| **ADD（带 `:lo12:`）** | 把页内 12 位偏移加到基址上 |

这是把 64 位地址拆成"页基址 + 页内偏移"两半来编码——与 5.3.1 的思路一致（定长编码靠拆解实现大常量）。

## 5.3.6 A32 → A64 指令对照速查

| 用途 | AArch32 | AArch64 |
|:--|:--|:--|
| 装立即数 | `MOV Rd, #imm`（8 位旋转限制） | `MOVZ Rd, #imm` / `MOVK Rd, #imm, LSL #n` |
| 寄存器传送 | `MOV Rd, Rm` | `MOV Xd, Xm`（或 `ORR Xd, XZR, Xm`） |
| 取反 | `MVN Rd, Rm` | `MOVN Xd, #imm`（位取反立即数） |
| 加/减 | `ADD/SUB Rd, Rn, Rm` | `ADD/SUB Xd, Xn, Xm` |
| 比较 | `CMP Rn, Rm` | `SUBS XZR, Xn, Xm`（或 `CMP` 别名） |
| 条件传送 | `MOVcc Rd, Rm` | `CSEL Xd, Xn, Xm, cond` |
| 调用/返回 | `BL label` / `MOV PC, LR` | `BL label` / `RET` |
| 压栈 | `STMFD SP!, {…}` | `STP x29, x30, [sp, #-16]!` |
| 条件执行 | 指令后缀 `EQ/NE/…` | 数据处理无后缀，用 `CSEL` |

## 本节小结

AArch64 用"定长编码 + 拆解"换取规整：立即数靠 MOVZ/MOVK 拼、条件执行靠 CSEL 选择、大地址靠 ADRP+ADD 两步走、栈存取靠 STP/LDP 成对。对照第三章会觉得"A64 更啰嗦"，但换来的是编码空间充裕、扩展容易、便于 JIT 与静态分析——这正是 AArch32 在服务器与移动生态里被替代的原因之一。
