# 5.5 中断控制器 GIC

第二章 2.9 讲 ARMv7 的中断时，视角是**处理器核自己**：nIRQ 与 nFIQ 两根引脚（低电平有效），CPSR 的 I/F 位做总屏蔽。真实 SoC 里，几十上百个外设都会拉中断——谁先服务、怎么分优先级、怎么路由到某个核，都不是核自己能决定的。这活儿交给**中断控制器**。（依据素材书第 12、13 章）

## 5.5.1 从两根引脚到一棵中断树

| | AArch32（2.9） | AArch64 + GIC |
|:--|:--|:--|
| 核的视角 | nIRQ / nFIQ 两根引脚 | 同样两根引脚，但由 GIC 驱动 |
| 中断源 | 芯片内部逻辑自行编排 | **GIC 统一管理**：SPI / PPI / SGI |
| 优先级 | 核内固定（FIQ > IRQ） | **可编程**：每中断源一个优先级 |
| 分发 | 直达核 | **Distributor** 分发到目标核（可指定 CPU） |
| 屏蔽 | CPSR 的 I/F 位 | GIC 的使能/屏蔽寄存器 + PSTATE 的 D/A/I/F |

AArch64 的 PSTATE 里仍有 **D（调试）、A（SError）、I（IRQ）、F（FIQ）** 四个屏蔽位，与 2.8.3 的 CPSR I/F 位同源——但**每个中断源的独立屏蔽**改由 GIC 负责。

## 5.5.2 三类中断源

| 类型 | 全称 | 特点 |
|:--|:--|:--|
| **SGI** | Software Generated Interrupt | **核间中断**：一个核给另一个核发信号，用于核间通信与停核 |
| **PPI** | Private Peripheral Interrupt | **核私有**：每个核一份，如该核自己的定时器、调试中断 |
| **SPI** | Shared Peripheral Interrupt | **系统共享**：外设中断（UART、SPI、以太网……），数量最多 |

SPI 通常是**级联**的：芯片上有若干个中断控制器（如树莓派 4B 上的传统中断控制器 + GIC-400），它们再把中断汇到 GIC。

## 5.5.3 GIC 的两个部件

**GIC（Generic Interrupt Controller）**分两部分：

- **Distributor（分发器）**：全局部分。负责中断源的使能/屏蔽、优先级设置、目标核选择、以及**中断 ID 的分配**；
- **CPU Interface（CPU 接口）**：每个核一份。负责把中断送给本核、读取活跃优先级、发送 EOI（End of Interrupt）确认。

这与 2.3.2 的 SCU 是不同层次的东西：SCU 管的是**缓存一致性**（2.3.2、5.9），GIC 管的是**中断分发**。在多核 SoC 里两者通常并存。

## 5.5.4 中断的处理流程

一个 SPI 到达后的典型路径：

```
外设事件 → GIC Distributor 记录中断 ID、优先级
         → 按目标核配置分发
         → 目标核的 GIC CPU Interface 拉低 nIRQ 引脚
         → 核进入异常（跳到 VBAR_EL1 + 0x480 之类，5.4.2）
         → 处理程序读 GIC 的中断 ID 寄存器，知道是谁在请求
         → 处理（清外设中断源）
         → 向 GIC 写 EOI，表示"这个中断我处理完了"
```

**注意第 3 步和第 6 步**：与第二章 2.9.3 讲的 AArch32 硬件四步相比，AArch64 的**硬件步骤其实一样**（进异常、跳向量）；变的是**中断号的获取方式**——AArch32 时代软件往往靠设备地址猜是谁在请求，AArch64 时代由 GIC 提供**中断 ID 寄存器**，软件直接读出中断号。

## 5.5.5 与第四章 4.11 的关系

第四章 4.11 讲的中断响应时间（= 关中断的最长时间 + 保护寄存器 + 进入 ISR + 执行 ISR 第一条指令），在 AArch64 + GIC 上多了一项：**从 nIRQ 拉低到异常向量被取指**，中间要经过 GIC 的分发延迟。

同时，4.11.2 提到的"Linux 的 Bottom Half"——把中断处理拆成上半部（马上响应）与下半部（延后处理）——正是为了压短上半部的长度，把不适合在中断上下文做的事推迟到任务上下文。

::: note 与 seL4 的对照
4.4.9 讲过 seL4 把中断抽象成"向端点发消息"——那是**软件层面**的做法。硬件层面 GIC 该做的事一件不少：分发、优先级、EOI。seL4 的做法是让中断处理程序（用户态线程）收到消息后，仍需向 GIC 写 EOI。
:::

## 本节小结

GIC 解决了"一个核 + 两根引脚"管不了的问题：中断源编号（SGI/PPI/SPI）、每源可编程优先级、目标核选择、EOI 确认。它的 CPU 接口部分驱动 nIRQ/nFIQ，与 5.4 的异常体系对接：**GIC 决定"谁来处理"，异常体系决定"处理程序怎么跑"**。下一节开始进入内存系统——这是 AArch64 与 AArch32 差距最大的另一块。
