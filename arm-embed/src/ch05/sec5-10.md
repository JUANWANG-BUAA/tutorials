# 5.10 内存屏障与原子操作

第四章 4.10 讲共享内存互斥时给的"三选一"是：关中断 / 禁止任务切换 / 信号量。在**单核**系统里这三条都成立；在**多核**系统里它们全都挡不住另一个核的乱序访存。本节讲多核并发编程真正需要的东西——内存屏障与原子操作。（依据素材书第 18、19、20 章）

## 5.10.1 乱序访问从哪来

**若程序实际执行的访存顺序与代码写的顺序不一致，就是内存乱序访问。**它有两个来源：

| 来源 | 机制 | 对策 |
|:--|:--|:--|
| **编译时** | 编译器重排访存以提高指令级并行 | C 的 `barrier()` 宏：`__asm__ __volatile__ ("" ::: "memory")` |
| **执行时** | 流水线、乱序发射、乱序执行、写缓存、Cache、超标量 | **硬件内存屏障指令** |

在**单处理器**上，CPU 怎么乱序执行都不影响结果——只有一个观察者。但在**多核**上，一个核的访存乱序会被别的核观察到。

## 5.10.2 两个不同的"一致性"

素材书 18.1 节把这件事分得很清楚：

| | **缓存一致性（Cache Coherency）** | **存储一致性（Memory Consistency / 存储序）** |
|:--|:--|:--|
| 解决什么 | 多个处理器访问**同一个地址** | 多个处理器访问**多个不同地址**的**次序** |
| 手段 | **MESI 协议**（5.9.3） | **内存屏障指令**（本节） |
| 问题 | 数据不一致 | 顺序不一致 |

**这正是第四章 4.10 缺的那一半**：4.10.2 说共享内存"必须自己保证互斥"，本章说明**互斥（靠信号量）只解决了"不要同时改"，还得靠内存屏障解决"不要看到中间状态"**。

## 5.10.3 三种内存模型

按"允许多大程度的乱序"分三档（素材书 18.1.1–18.1.3）：

| 模型 | 放宽了什么 | 典型实现 |
|:--|:--|:--|
| **顺序一致性（SC）** | 不放宽：读→读、读→写、写→写、写→读 **四种次序全部保证** | 最严格，ARM 的强基线 |
| **处理器一致性（PC）** | 放宽**写→读** | x86-64 的 **TSO**（全序写）模型 |
| **弱一致性（Weak）** | 四种次序都可放宽，但**需要用同步操作显式保证** | ARM64、RISC-V 默认 |

顺序一致性的两个约束（Lamport 1979）：

1. **单处理器视角**：访存执行次序以程序为准；
2. **多处理器视角**：所有访存是原子的，执行顺序不必严格遵循时间顺序。

**顺序一致性的经典论证**（素材书 18.1.1）：

```c
    /* CPU0 */              /* CPU1 */
    a = 1;                 x = b;
    b = 1;                 y = a;
```

若 CPU1 读出 `b == 1`，在顺序一致性模型下**不可能**读出 `a == 0`（CPU0 写 b 在写 a 之后，CPU1 读 b 在读 a 之前，传递性保证了 a 也已可见）。在弱一致性模型下就可能——因为两次读被重排了。

## 5.10.4 三条屏障指令

| 指令 | 全称 | 保证什么 |
|:--|:--|:--|
| **DMB** | Data Memory Barrier | **数据**访存不能越过它（前后都要有序） |
| **DSB** | Data Synchronization Barrier | 数据访存不能越过它，且**后续访存必须等它之前的所有访存真正完成** |
| **ISB** | Instruction Synchronization Barrier | **指令**流水线的重新同步（上下文切换后必须用） |

**DMB 与 DSB 的区别**（素材书自测题第 6 题）：

- **DMB** 只保证**次序**：后面的访存不会跑到前面访存之前；
- **DSB** 还保证**完成**：后面的访存要等前面的访存**真正落到内存**（对设备内存尤其重要——写 FIFO 的完成意味着数据已进设备）。

**ISB 的用途**：改了执行上下文（如改了系统寄存器、做了异常返回）后，用 ISB 确保流水线丢弃旧指令、从新地址重新取指。

```asm
    STR   x5, [x1]        ; 写数据
    DMB   ISH              ; 保证上面的写先于下面的写完成（对内部共享域）
    STR   x0, [x2]        ; 置标志
```

::: note 屏障的代价
屏障会**阻止流水线继续推进**，直接吃掉性能。ARM64 的做法是把屏障"内建"进特定指令——见 5.10.5，这比插裸 DMB 快得多。
:::

## 5.10.5 加载-获取与存储-释放原语

ARMv8 提供了两个**单指令屏障原语**，比 DMB 更高效：

| 原语 | 含义 | 典型指令 |
|:--|:--|:--|
| **加载-获取（Load-Acquire）** | 之后的访存不能**向前**越过这次加载 | `LDAR` |
| **存储-释放（Store-Release）** | 之前的访存不能**向后**越过这次存储 | `STLR` |

```asm
    /* CPU1：发布数据 */
        STR   x5, [x1]        ; 写数据（普通）
        STLR  x0, [x2]        ; 置标志（内置存储-释放屏障）

    /* CPU2：消费数据 */
        LDAR  x5, [x1]        ; 读数据（内置加载-获取屏障）
```

因为 `STLR` 内置了存储-释放原语，前面的 `STR` **不会越过它**；`LDAR` 内置加载-获取原语，后面的访存不会越过它向前——**读者看到标志置位时，数据必然已经写好了**。

素材书指出：**用加载-获取 + 存储-释放的组合，性能上优于直接用 DMB**。

**还能更省**（素材书 18.3.2 例）：用**地址依赖**构造顺序，省掉获取屏障：

```asm
    /* CPU1 */
        STR   x5, [x1]
        STLR  x0, [x2]

    /* CPU2 */
        WAIT([x2] == 1);            /* 宏内部用了 w12 */
        AND   w12, w12, wzr;         /* w12 在 WAIT 宏里 */
        LDR   x5, [x1, w12];         /* 地址依赖：w12 作为偏移 */
```

`LDR x5, [x1, w12]` 的地址依赖 w12 → **CPU 不能把这次加载提前**（因为地址依赖的值还没算出来），于是省掉了获取屏障。

## 5.10.6 独占访问：LDXR / STXR

**独占内存访问（Exclusive Access）**是 ARM64 实现原子读改写的基础。

```asm
        LDXR  w5, [x1]        ; 独占读取（带监控器）
        STR   w6, [x1]        ; 失败则重试
        STXR  w5, w0, [x1]    ; 独占存储：成功时 w5=0，失败时 w5≠0
```

- **LDXR**（Load Exclusive Register）：读取并"标记"这块内存为独占监控状态；
- **STXR**（Store Exclusive Register）：只有当独占监控仍有效时才写入成功，**返回值 0 表示成功、非 0 表示失败**，失败时必须重试整段。

**AArch32 与 AArch64 的写法差异**（素材书 18.3.2）：**ARM64 写作 LDXR / STXR，ARM32 写作 LDREX / STREX**。

::: note 这与第二章 2.9 / 3.4.6 的 SWP 什么关系
第二章 2.11 与第三章 3.4.6 讲过 **SWP**（交换）——"读旧值 + 写新值"一条指令完成，是 AArch32 实现信号量的硬件基础。但 SWP 只能做"交换"，做不了"比较并交换"（CAS）。**LDXR/STXR 是通用解**：用"读 + 条件写 + 重试"实现任意原子读改写。
:::

**与缓存一致性的关系**：独占监控器是**与 Cache 关联**的——若在 LDXR 与 STXR 之间，另一个核修改了同一地址（导致 Cache 行状态变化），STXR 就会失败。**这就是为什么独占访问必须紧邻使用，中间不能有别的访存把它"挤掉"**。

## 5.10.7 用独占访问实现自旋锁

素材书给的自旋锁实现（例 18-13）：

```asm
    prfm  pstl1keep, [x1]     ; 预取，提前把锁行拉进 Cache
loop
    ldaxr w5, [x1]            ; 独占读取（内置加载-获取屏障）
    cbnz  w5, loop             ; 非 0 → 锁被持有，自旋
    stxr  w5, w0, [x1]         ; 尝试写入 1（获取锁）
    cbnz  w5, loop             ; 非 0 → 写入失败，重试
    ; 成功获取锁
```

**释放锁**（例 18-14）：

```asm
    ; 临界区的读写
    stlr  wzr, [x1]            ; 写 0 释放锁（内置存储-释放屏障）
```

释放锁**不需要独占存储指令**——因为通常只有持有者会改这个锁；但需要**存储-释放屏障**，让其它核能看到锁的变化。

**用 LDAXR 而非 LDXR 的理由**：LDAXR 内置加载-获取屏障，防止临界区内的访存被重排到临界区外。

**WFE/SEV 优化**（例 18-15）：自旋时用 **WFE（Wait For Event）** 让 CPU 进入低功耗状态而不是空转烧电，靠 **SEVL/SEV** 事件唤醒。配合"清除全局独占监视器"来触发事件，就**不需要 DSB 和 SEV 指令**。

## 5.10.8 自旋锁 vs 信号量

回到第四章 4.10.4 的信号量。AArch64 上有更轻的选择：

| | 信号量 | 自旋锁 |
|:--|:--|:--|
| 等待方式 | **睡眠**（挂起任务，让 CPU 去干别的） | **自旋**（占着 CPU 空转） |
| 适合 | 临界区较长、竞争不激烈 | 临界区**极短**、多核 |
| 实现 | 内核调度 + 等待队列 | 一条独占读 + 一条独占写 |

**选择依据**：临界区在几百个周期以内 → 自旋锁更划算（省掉一次调度往返）；临界区可能长时间阻塞 → 必须用信号量（否则 CPU 全浪费在自旋上）。

## 本节小结

多核并发的三个正交问题：**互斥**（不要同时改，用信号量/自旋锁）、**一致性**（要看到最新值，用 MESI 与 clean/invalidate）、**存储序**（要看到正确顺序，用内存屏障）。内存屏障有 DMB（次序）、DSB（次序 + 完成）、ISB（指令流）三条，更好的做法是用内建屏障原语的 LDAR/STLR；原子读改写用 LDXR/STXR（失败重试），配 LDAXR/STLXR 可省掉显式屏障。**第四章 4.10 的"关中断"只在单核成立**——多核下必须靠这些指令。
