# 习题集

第五章习题（延伸阅读）。前两组是理解题，后两组是推演与设计题。**不需要设备**，纸笔可完成；涉及页表与屏障的题目要求写清过程。

## A 组 · 体系结构对照（5.1–5.3）

**A1** AArch64 的指令编码宽度是 32 位，但支持 64 位数据与 64 位地址。解释这个看似矛盾的组合。

**A2** 下面四条 AArch64 指令，哪些能执行成功？成功时 x0 的值是多少？
```asm
    mov x0, #0x1234
    mov x0, #0x1abcd
    mov x0, #0x12bc0000
    mov x0, #0xffff0000ffff
```

**A3** AArch32 的 `MOV R0, #0xFF00` 与 AArch64 的 `MOVZ X0, #0xFF00` 都能装下这个常数。但 AArch32 无法装载 `0xFFFFFF00`，AArch64 却可以。分别说明各自怎么做。

**A4** AArch32 的 `ADDHI R0, R1, R2` 在 AArch64 没有直接对应。用 A64 改写同样的语义。

**A5** 为什么 AArch64 取消了 Thumb 的 16 位指令？给出至少两条理由。

::: sol A 组解答要点
A1：编码宽度固定，但**立即数与地址用拆解实现**——64 位常数用 MOVZ/MOVK 拼（每条只处理 16 位），64 位地址用 ADRP（取页基址）+ ADD（加页内偏移）两步走。定长编码换来了规整的字段划分与充裕的扩展空间。
A2：`mov x0, #0x1234` 成功（x0=0x1234）；`#0x1abcd` 超 16 位立即数范围，**失败**；`#0x12bc0000` 超 16 位，**失败**；`#0xffff0000ffff` 远超 16 位，**失败**——AArch64 的 MOV 立即数形式只支持 16 位（可 LSL #0/16/32/48 放置）。要装大常数须用 MOVZ+MOVK 组合。
A3：AArch32 的立即数是"8 位循环右移偶数位"，`0xFFFFFF00` 需要 24 个 1 位，装不进 8 位窗口——**装不下**。AArch64 用 `MOVZ X0, #0xFF00, LSL #32` 放高位、`MOVK X0, #0xFF00, LSL #16` 放中位、`MOVK X0, #0xFF` 放低位，三条拼出 0xFFFFFF00。
A4：`CMP X1, X2`（比较更新标志）+ `CSEL X0, X1, X2, HI`（若 HI 成立取 X1，否则取 X2）。
A5：① 编码空间统一后不必为 Thumb 保留另一套译码路径，简化核的设计与验证；② 32 位定长指令消除了取指对齐的分支逻辑，对流水线更友好；③ 64 位地址/数据无法在 16 位编码里有效表达（立即数与偏移都受限）；④ 便于 JIT、静态分析与反汇编工具的一致实现。
:::

## B 组 · 异常体系（5.4–5.5）

**B1** AArch32 的异常向量表有 8 项、每项 4 字节；AArch64 有 16 项、每项 128 字节。说明各自的设计动机。

**B2** AArch64 为什么需要 SP_EL0 与 SP_ELx 两套栈指针？SPSel 寄存器控制的是什么？

**B3** 用户态（AArch64）的一个进程触发了 IRQ，陷入 EL1。处理器需要保存哪些内容？保存在哪里？由谁保存？

**B4** 一条指令访问了地址 0x8000000000（未对齐），触发了什么异常？ESR_ELx 里哪个字段告诉你这件事？哪个字段告诉你出错的是读还是写？

**B5** SGI、PPI、SPI 三类中断各举一个实际来源。

::: sol B 组解答要点
B1：AArch32 每项只放一条跳转指令（4 字节），处理程序要再跳一次；AArch64 给足 128 字节（32 条指令），处理程序可直接写在向量项里，省掉一次跳转与它带来的流水线冲刷。AArch64 还要按"来源 EL × 使用的栈指针 × 执行状态"细分（16 项），因为它支持多个异常级与 AArch32 兼容态。
B2：t（tied）语义下该 EL 用当前 EL 的栈指针（SP_ELx），h（hyp）语义下用 SP_EL0。SPSel 的第 0 位选择：**0 = 所有 EL 都用 SP_EL0**，**1 = 用 SP_ELx**。内核借此决定"异常发生时是切到内核独立栈，还是沿用用户栈"。
B3：硬件自动保存 **PSTATE（→SPSR_ELx）、PC（→ELR_ELx）**，并自动选择目标 EL 的栈指针；**x0–x30 由软件压栈保存**（在目标 EL 的内核栈上）。保存位置：发生异常那个进程的**内核态栈空间**。
B4：**数据访问**未对齐属于 Data Abort（EC=0x24/0x25；取指未对齐才是 PC_ALIGN，EC=0x22）。此时看 ISS 的 **WnR 位（Bit[6]）**：0 = 读，1 = 写。
B5：SGI —— 一个核给另一个核发信号（核间中断，用于核间通信/停核）；PPI —— 核私有的外设，如该核自己的定时器、调试中断；SPI —— 系统共享的外设，如 UART、SPI 控制器、以太网。
:::

## C 组 · 内存系统（5.6–5.9）

**C1** 48 位虚拟地址、4 KB 页面，若用**一级页表**覆盖整个地址空间，页表本身要多大？为什么必须多级？

**C2** 某进程把一页的权限从"可读写"改成"可执行"。内核改页表后，为什么还要做 TLB 失效与 Cache 失效？

**C3** 为什么设备内存（Device memory）不能被 Cache 缓存，也不能被重排？各举一个后果。

**C4** VIPT Cache 为什么不会出现 5.7.4 说的"同名问题"？它的成立条件是什么？

**C5** 一段代码先用 CPU 往 DMA 缓冲区写数据，再启动 DMA 把它搬到设备。写出必须插入的两步维护操作及其位置（启动前/启动后）。如果顺序写反，会出什么现象？

::: sol C 组解答要点
C1：需 $2^{48}/2^{12} = 2^{36}$ 个页表项，每项 8 字节 → $2^{39}$ = **512 GB**，不可行。多级的意义是**逐级收窄**：不同虚拟地址区域共享低层页表，实际页表内存只需几十 MB。
C2：TLB 里缓存的是**旧的翻译结果**（VA→PA 及权限），不改则 CPU 仍按旧权限访问；Cache 里可能缓存着该页的旧内容与旧属性。改完页表要失效 TLB，并按需失效/清理对应的 Cache 行。
C3：不能缓存——外设寄存器的读写有副作用（写 FIFO 触发发送、读状态寄存器清标志），缓存后读到的是旧值；不能重排——两次写的顺序若被调换，设备收到的顺序与程序写的不同。
C4：VIPT 用**物理地址做标记**，跨进程切换后旧行因标记不匹配而被判为未命中，不会误用。成立条件：**物理地址与虚拟地址的索引位必须对应**（页大小 ≥ Cache 组跨度），否则无法在翻译完成前确定组号。
C5：**启动 DMA 之前 clean**（把脏行写回内存，否则 DMA 搬走的是旧数据）；**DMA 完成之后 invalidate**（丢掉 CPU Cache 里可能陈旧的行，否则 CPU 读到旧数据）。顺序写反的后果：DMA 搬走旧数据（写回没做），或 CPU 读到陈旧数据（失效没做）——都是"偶发、无崩溃"的难查 bug。
:::

## D 组 · 内存屏障与原子操作（5.10）

**D1** 第四章 4.10.2 给出的共享内存互斥三选一（关中断 / 禁止任务切换 / 信号量），在**多核系统**里为什么全部失效？正确的做法是什么？

**D2** 什么是"存储一致性"？它与"缓存一致性"有什么区别？各自的手段是什么？

**D3** 下面三段代码分别需要哪种屏障？DMB、DSB、ISB。
```asm
    ; (a) 写数据后置标志，确保别的核看到标志时数据已就绪
    ; (b) 上下文切换后，确保流水线从新地址重新取指
    ; (c) 设备写 FIFO 后，确保后续读能看到设备的状态
```

**D4** 用 LDXR/STXR 实现"比较并交换"（CAS）：若内存中的值等于期望值，就写入新值。写出完整序列并说明失败时怎么办。

**D5** 自旋锁的获取与释放分别用什么指令？为什么释放锁不需要独占存储指令？

**D6** 为什么 LDXR 与 STXR 之间不能插入别的访存指令？

::: sol D 组解答要点
D1：这三条都只能约束**本核**的行为——关中断只关本核的 IRQ，禁止任务切换只挡本核的调度，信号量虽然会触发核间通信但**不保证访存的可见次序**。多核上另一个核的访存可能重排、可能读到旧 Cache 行。正确做法：互斥用**信号量/互斥量/独占访问自旋锁**（跨核），可见性靠**缓存一致性 + clean/invalidate**，次序靠**内存屏障**。
D2：缓存一致性保证**同一地址**在多个 Cache 中的副本一致（MESI 等协议）；存储一致性保证**多个不同地址**的访存次序在各核观察者看来一致（屏障、内存模型）。前者靠硬件协议，后者靠屏障指令与同步原语。
D3：(a) 用 **STLR**（存储-释放，内置屏障）或 DMB——保证写数据先于置标志可见；(b) 用 **ISB**（指令同步屏障）；(c) 用 **DSB**（要求完成，不只是次序）或 DMB——写 FIFO 的"完成"需要 DSB 级别的保证。
D4：典型序列：LDXR 取当前值 → 比较 → 不等则返回失败 → 相等则 STXR 写新值 → **检查 STXR 返回值**，非 0 表示写入失败（被别的核抢先），**必须重新执行整段**。
D5：获取用 `LDAXR`（读）+ `STXR`（写），失败重试；释放用 **`STLR` 写 0**——因为通常只有持有者会改这个锁，不需要独占语义；但需要存储-释放屏障，让别的核能看到锁已释放。
D6：独占监控器与 Cache 行关联。若在 LDXR 与 STXR 之间发生别的访存（或别的核修改了同一地址导致行状态变化），独占监控会失效，STXR 必然失败。所以两步之间必须紧邻。
:::

## E 组 · 综合设计

**E1** 某 64 位 Linux 系统上，进程 A 与进程 B 共享一段内存。A 往共享区写数据、置标志位；B 等标志位后读数据。请写出 A、B 两侧的关键指令序列（用 A64），并说明为什么需要屏障。

**E2** 内核把一段可执行代码从只读区复制到可执行区，然后要在其它核上生效。列出必须做的全部步骤，并说明为什么其中一步必须通过 IPI。

**E3** 一个多核系统上，两个核同时对同一个内存地址做"读-改-写"（如计数器 ++）。分别用（a）信号量、（b）独占访问实现，说明各自需要哪些硬件/软件支持，以及在核数增加时哪种方案的可扩展性更好。

::: sol E1 解答要点
A 侧：`STR X_data, [x_shared]`（写数据）→ `STLR X_flag, [x_flag]`（置标志，内置存储-释放屏障）。
B 侧：循环 `LDAXR X_flag, [x_flag]` 直到读到非 0（内置加载-获取屏障）→ `LDR X_data, [x_shared]`（读数据）。
为什么需要屏障：**没有屏障时，A 的写数据可能重排到置标志之后**（B 看到标志却读不到数据），**B 的读数据也可能重排到读标志之前**（B 还没看到标志就读了旧数据）。STLR/LDAR 分别封住这两条路径。
:::

::: sol E2 解答要点
步骤：① 把新代码写入可执行区（必要时先 clean 数据 Cache）；② **失效指令 Cache**（`ic ivau <addr>`，PoC 角度，因为其它核的指令 Cache 里还是旧代码）；③ **发 IPI** 让其它核立即执行一遍失效；④ 屏障（ISB/DSB）确保失效完成后再跳转执行新代码。
**为什么必须 IPI**：一个核不能直接修改另一个核的指令 Cache——那是另一个核的硬件状态。只能通过核间中断把那个核叫醒，让它自己执行失效。
:::

::: sol E3 解答要点
(a) 信号量：需要**内核提供的互斥量**（含原子操作实现，通常基于 LDXR/STXR 或 SWP）+ **跨核的内存屏障**（释放锁时用存储-释放语义）。核间通信（如自旋锁里的 cache line 独占）由一致性协议保证。
(b) 独占访问：需要**硬件的独占监控器**（与 Cache 行关联）+ 屏障原语。实现上更轻（无内核参与），但忙等会烧 CPU。
可扩展性：核数多、临界区短 → 自旋锁（独占访问）更划算（避免调度往返）；核数多、临界区长或竞争激烈 → 信号量（阻塞让出 CPU）更划算，否则大量核在自旋上耗电。信号量的实现本身在多核下最终也要靠独占访问。
:::
