# 第五章 · AArch64 与内存系统（延伸阅读）

## 你手上的核，可能已经不听 ARM 指令了

第二、三章讲的是 **AArch32**：ARMv7-A 的 32 位指令集，Thumb 是它的 16 位压缩版。今天绝大多数手机、车载芯片与云服务器跑的是 **AArch64**——ARMv8-A 引入的 64 位执行状态。它不是"AArch32 加宽"，几乎每一处设计都重新来过：寄存器从 32 位变 64 位、立即数换了一套装法、条件执行改用选择指令、异常体系从"7 种异常 + 固定向量表"变成"4 个异常级 + 可编程向量表"。

本章是**延伸阅读**：不属于课程考纲，但它能解释三件前面按下的葫芦：

1. 现在的手机芯片为什么用 64 位（[5.1](sec5-1.md)–[5.3](sec5-3.md)）；
2. 操作系统启动时"内存管理"到底管什么（[5.6](sec5-6.md)–[5.9](sec5-9.md)）；
3. 第四章那个"关中断保护临界区"的土办法，在多核上为什么不够（[5.10](sec5-10.md)）。

## 怎么读这一章

**先看 5.4**，它是全章的骨架：ARMv8 的异常体系与第二章的 ARMv7 异常机制一一对应，读完你就知道"向量表从 8 个 4 字节项变成 16 个 128 字节项"背后的道理。然后按需取用：

- 想搞懂**为什么现在要写 64 位** → 5.1–5.3；
- 想搞懂**操作系统怎么管内存** → 5.6–5.9；
- 正在写**多核/并发代码** → 5.10 必读，这节会直接推翻第四章"关中断就万事大吉"的印象；
- 正在做**汇编与 C 混合** → 5.11。

## 素材与口径

本章内容依据《ARM64 体系结构编程与实践》（奔跑吧 Linux 社区编著，人民邮电出版社，2022）一书整理，并对照 ARM 官方体系结构手册（ARMv8-A 与 ARMv8.6）核实。该书以树莓派 4B 与 QEMU 为实验平台，讲解 ARMv8.6 体系结构。

**口径声明**：本章是延伸阅读，与课程课件（ARMv7-A / AArch32）不是同一套体系。凡两者概念同名而含义不同处（异常向量表、栈指针、状态寄存器、内存屏障），正文都会明确标出"这是 AArch64 的做法"，不与前四章混用。写作中凡教材未展开而按 ARM 官方手册补全的部分，在[勘误页](errata.md)登记出处。
