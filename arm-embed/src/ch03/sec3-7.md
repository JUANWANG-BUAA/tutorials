# 3.7 分支指令与状态切换

程序要拐弯，有两种办法：**分支指令直接跳**，或**向 PC 赋值**。ARM 的分支三兄弟各管一件事——B 跳、BL 记返回地址、BX 还能顺手切 ARM/Thumb 状态。本节把"返回地址到底是哪条"算清楚，这是读递归和中断代码的前提。（课件 Slide 100–106）

## 3.7.1 三兄弟总表

| 助记符 | 说明 | 操作 | 跳转范围 |
|:--|:--|:--|:--|
| **B** | 分支 | PC ← label | 当前指令 ±32 MB |
| **BL** | 带链接的分支 | **LR ← 下一条指令地址**，PC ← label | ±32 MB |
| **BX** | 带状态切换的分支 | PC ← Rm（位[0] 决定状态） | ±32 MB（由 Rm 值决定） |

范围都是 ±32 MB，因为 B/BL 的编码里放的是 **24 位有符号立即数 ×4**（指令按字对齐，最低 2 位恒为 0，可省）：$2^{23} \times 4 = 32\text{MB}$ 的跨度，正负各半。

## 3.7.2 B：单纯跳转

```asm
B{cond}  label
```

```asm
        B     WAITA          ; 无条件跳到 WAITA
        ...
WAITA   ...
```

B 不保存任何返回信息——它适合循环、分支汇合、远跳。

## 3.7.3 BL：子程序调用的半个协议

```asm
BL{cond}  label
```

执行时硬件做两件事：**把下一条指令的地址装入 LR（R14）**，把 label 装入 PC。

课件讲得很细，值得原样理解：

> 1. 当程序执行到 BL 跳转指令时，硬件将下一条指令的地址 Addr2 装入 LR 寄存器，并把跳转地址装入 PC；
> 2. 程序跳转到 Label 继续执行，子程序结束时，将 LR 内容存入 PC，返回调用处。

所以子程序末尾的标准写法是 `MOV PC, LR`（3.5.2 提过）。返回地址的精确值有版本细节：

::: note BL 存的是"下一条"还是"当前+8"？
**体系结构语义**：BL 把**返回地址**（BL 之后那条指令的地址，即当前 +4）放进 LR。课件表格里"LR←PC−4"是这个语义的另一种写法——因为执行 BL 时读 PC 得到的是当前+8（三级流水线，2.7.5），LR←PC−4 恰好等于当前+4。
**要警惕的版本差异**：ARMv5 及以后 BL 存的是"下一条"（当前+4）；某些旧文档按 ARMv4 口径写作"当前+8 且返回时需减 4"。做题按课件"下一条指令地址"答，遇到"返回地址偏移"的题先确认版本口径。
:::

::: ex 例 3.7.1 · 算一次 BL 的 LR {#ex-3.7.1}
```asm
0x1000  BL    func       ; 执行时 PC 读值 = 0x1008
0x1004  MOV   R0, #1     ; ← 这是"下一条"
...
0x2000  func  ...
```
LR 应为 **0x1004**（下一条指令地址）。若有人算成 0x1008（PC 读值），那是把"PC 值"和"返回地址"混了——这也是 2.7.5 "读 PC 得 +8" 与本节最容易混淆的一处。
:::

## 3.7.4 BX：一位之差，换一套指令集

```asm
BX{cond}  Rm
```

规则（与 2.5.2 完全一致，此处从指令编码角度再看一次）：

| Rm[0] | 跳转后 CPSR T 位 | 处理器状态 |
|:--|:--|:--|
| 0 | 0 | ARM |
| 1 | 1 | Thumb |

细节（课件原话）：**Rm 的位[0] 不用作地址的一部分**——跳转时被丢弃；若 Rm[0]=1 则 T 置位、目标代码按 Thumb 解释；**若 Rm[0]=0，则 Rm[1] 不能为 1**（Thumb 地址半字对齐，ARM 地址字对齐，故 Rm[1]=1 而 Rm[0]=0 非法）。

```asm
        ADRL  R0, ThumbFun+1   ; 目标地址最低位置 1
        BX    R0               ; 跳到 ThumbFun 并切到 Thumb
```

这就是"汇编器怎么表达一个 Thumb 函数指针"：**函数指针值 = 真实地址 | 1**。C 语言里把它强制转成函数指针调用，编译器生成的正是 BX。

::: think 为什么 ARM 不设一条专门的"切换状态"指令？
切换状态必须与"跳到哪里继续执行"同时决定——单独改 T 位再顺序执行，流水线里已取的指令会按新宽度误解码（2.5.2 的告诫）。BX 把"改状态"绑在"跳转"上，两者原子发生，硬件才能安全地清空并重取。这是"机制绑定在正确的原子操作上"的经典设计。
:::

## 3.7.5 向 PC 直接赋值也算跳转

```asm
MOV   PC, LR            ; 返回
LDR   PC, [R0, R1, LSL #2]  ; 查表散转（3.3.5）
LDMFD SP!, {R4-R7, PC}  ; 多寄存器出栈并返回（3.4.3）
```

所有"写 R15"的指令都等价于一次跳转（2.7.5）。返回、散转、异常返回都靠这一招。**不能在用户模式这么写**——写 PC 本身没问题，但若涉及异常返回（`^`）需要特权。

## 本节小结

B 纯跳、BL 存返回地址到 LR（子程序末尾 `MOV PC,LR`）、BX 用 Rm[0] 切换状态；范围 ±32MB 来自 24 位有符号偏移×4；写 PC 的任何指令都是跳转。下一节处理剩下的"杂项"——它们数量最少，但其中 SWI 是用户程序进入内核的唯一合法门。
