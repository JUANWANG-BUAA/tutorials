# 3.9 伪指令

有些"指令"汇编器根本不认识——它们在汇编时被替换成一条或多条真实指令。ARM 只有四条伪指令，但几乎每段汇编代码都用到它们，因为它们替你解决了"立即数装不下""地址超出范围"这类麻烦。（课件 Slide 118–130）

## 3.9.1 什么是伪指令

**伪指令不属于 ARM 指令集**，是为了编程方便而定义的。它们像普通指令一样写在源程序里，但**汇编时被等效的一条或多条真实指令取代**。

ARM 有四条伪指令：

| 伪指令 | 作用 | 展开为 |
|:--|:--|:--|
| **ADR** | 小范围地址读取 | 1 条 ADD 或 SUB |
| **ADRL** | 中等范围地址读取 | 2 条指令 |
| **LDR** | 大范围地址/常数读取 | 1 条 LDR（或 MOV/MVN），常数入文字池 |
| **NOP** | 空操作 | 空操作（如 `MOV R0,R0`） |

## 3.9.2 ADR：小范围地址读取

```asm
ADR{cond}  register, expr
```

把**基于 PC 相对偏移**或**基于寄存器相对偏移**的地址值读入寄存器。汇编器通常用**一条 ADD 或 SUB** 实现；若一条不够，**编译失败**。

取指范围（课件口径）：

| 表达式类型 | 范围 |
|:--|:--|
| 字节对齐 | −255 ～ 255 |
| 字对齐 | −1020 ～ 1020 |

```asm
        ADR   R1, Delay        ; 源程序：把标号 Delay 的地址存入 R1
...
Delay   MOV   R0, R14
```

编译后的反汇编（课件示例）：

```asm
0x20   ADD   r1, pc, #0x3c    ; ADD r1, pc, #60 —— pc 相对加出目标地址
0x64   MOV   r0, r14
```

**为什么用 PC 相对**：地址与代码位置无关，代码搬个地方不用重编译——这是位置无关代码（PIC）的基础，也是 3.2.6 相对寻址的实际用途。

查表场景的典型用法（课件示例）：

```asm
        ADR   R0, DISP_TAB      ; 加载转换表地址
        LDRB  R1, [R0, R2]     ; 用 R2 作下标查表
        ...
DISP_TAB
        DCB   0xC0,0xF9,0xA4,0xB0,0x99,0x92,0x82,0xF8
```

注意 `DCB`（定义字节）与 `DCD`（定义字）不是指令，是**汇编器伪操作**——它们在汇编时直接把数据写进代码段。

## 3.9.3 ADRL：中等范围

```asm
ADRL{cond}  register, expr
```

比 ADR 范围大，**被替换成两条指令**；两条不够则编译失败。

| 表达式类型 | 范围 |
|:--|:--|
| 字节对齐 | −64K ～ 64K |
| 字对齐 | −256K ～ 256K |

```asm
        ADRL  R1, Delay
```

编译后（课件示例）：

```asm
0x20   ADD   r1, pc, #0x40
0x24   ADD   r1, r1, #0xFF00
```

两条 ADD 拼出一个大偏移——比 ADR 强，也比 LDR= 简单（不占文字池）。

## 3.9.4 LDR =：大范围与任意常数

```asm
LDR{cond}  register, =expr | label_expr
```

加载 **32 位立即数**或**地址值**到寄存器。汇编时的处理策略：

- 若常数在 MOV 或 MVN 的范围内 → **用 MOV 或 MVN 代替**；
- 否则 → 汇编器把常量放进**文字池**，用一条**程序相对偏移的 LDR** 从文字池读出。

三条注意事项（课件原话）：

1. 与 ARM 指令的 LDR 相比，伪指令 LDR 的参数**有"="号**；
2. expr 可以是**任意的 32 位立即数**（不受 8 位循环右移限制）；
3. **文字池到该指令的地址距离小于 4KB**。

常量的展开示例：

```asm
LDR   R2, =0xFF0          ; → MOV R2, #0xFF0        （MOV 能装下）
LDR   R0, =0xFF000000     ; → MOV R0, #0xFF000000   （MOV 能装下）
LDR   R1, =0xFFFFFFFE     ; → MVN R1, #0x1          （MOV 装不下，MVN 能）
```

地址的展开示例：

```asm
        LDR   R1, =InitStack
...
InitStack
        MOV   R0, LR
```

编译后：

```asm
0x60   LDR   R1, [pc, #4c]   ; 程序相对偏移读文字池
0xb4   DCD   0xfff64          ; 文字池里的常量 = InitStack 的地址
```

::: note "LDR Rd,=常量" 与 "LDR Rd, label" 是一回事吗？
都是"读文字池"，但写法不同：伪指令 `LDR Rd, =expr` 里的 expr 可以是**任意表达式**（汇编器求值后放文字池）；而真实指令 `LDR Rd, label` 里的 label 若是标号，汇编器也会生成文字池条目——所以 2.5.2 里那句 `LDR R0,=Label+1` 实际上等价于"把 Label+1 放进文字池再读出来"。**在 ARM 汇编里，看到 `LDR Rd, =xxx` 就应想到"文字池"。**
:::

## 3.9.5 NOP：空操作

NOP 在汇编时被替换成 ARM 的空操作（可能是 `MOV R0,R0`）。它可用于**延时操作**，而且**逻辑意义更清晰**。

```asm
        mov    R1, #0x1234
Delay
        NOP                     ; 空操作
        NOP
        NOP
        SUBS   R1, R1, #1       ; 循环次数减一
        BNE    Delay            ; 没结束就跳回去
        MOV    PC, LR           ; 子程序返回
```

::: note 用 NOP 做延时是"能跑但不该用"的写法
NOP 延时依赖具体核的流水线与执行时间，不同核、不同优化下行为不同，且编译器可能把它优化掉。**正规延时做法**：读一个 volatile 变量、或用硬件定时器、或用 DSB（数据同步屏障）指定等待周期。本课以理解伪指令为目的，真实工程里请用定时器。
:::

## 3.9.6 四条伪指令的选择顺序

写代码时的自然选择：

| 需求 | 用什么 |
|:--|:--|
| 取标号地址，范围小 | `ADR` |
| 取标号地址，范围中等 | `ADRL` |
| 取标号地址，范围任意 / 装任意 32 位常数 | `LDR Rd, =expr` |
| 单纯占位/延时 | `NOP` |

## 本节小结

伪指令 = 汇编器替你算账：ADR 一条 ADD（±255/±1020）、ADRL 两条（±64K/±256K）、LDR= 走文字池（任意 32 位常数，池距 <4KB）、NOP 是空操作。文字池这条机制解释了 2.5.2 的 `LDR R0,=Label+1` 是怎么变成"带最低位的地址"的——文字池里存的就是 Label+1 这个 32 位值。
