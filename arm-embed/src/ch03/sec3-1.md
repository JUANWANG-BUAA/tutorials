# 3.1 指令集概览与条件域

一条 ARM 指令是 32 位，但这 32 位不是"随便排"的——同一套字段模板贯穿全部指令族：最高 4 位永远是条件，最低若干位永远是寄存器编号与第二操作数。本节把这套模板拆开，并讲清"条件执行"这个 ARM 最著名的设计：为什么一条普通指令自己就能带 if。（课件 Slide 27–41）

## 3.1.1 三地址格式

ARM 是**三地址指令格式**，助记符模板：

```
<opcode>{<cond>}{S}  <Rd>, <Rn>{, <operand2>}
```

`<>` 内必选，`{}` 内可选。逐项：

| 字段 | 含义 |
|:--|:--|
| **opcode** | 指令助记符（ADD、LDR…） |
| **cond** | 执行条件，如 EQ、NE、GT；**缺省为 AL（无条件）** |
| **S** | 是否更新 CPSR 的条件标志位（N Z C V） |
| **Rd** | 目标寄存器 |
| **Rn** | 第一操作数寄存器 |
| **operand2** | 第二操作数（三种形态，见 3.1.3） |

例：`ADD r3, r1, r2` —— Rd=r3，Rn=r1，Rm(r2)=r2，即 r3 ← r1 + r2。"三地址"指一条指令同时说出**两个源、一个目的**，而 x86 常见的两地址格式要 `ADD r1, r2`（r1 ← r1+r2）才能表达同样的事。

## 3.1.2 条件域 cond：一条指令自带 if

**所有 ARM 指令都可以条件执行**；Thumb 指令只有 B（跳转）具备条件执行。不写条件即默认 AL（无条件）。

16 个条件码（4 位编码恰好用满）：

| 编码 | 助记符 | 标志条件 | 含义 |
|:--|:--|:--|:--|
| 0000 | **EQ** | Z=1 | 相等 |
| 0001 | **NE** | Z=0 | 不相等 |
| 0010 | **CS/HS** | C=1 | 无符号 ≥ |
| 0011 | **CC/LO** | C=0 | 无符号 ＜ |
| 0100 | **MI** | N=1 | 负 |
| 0101 | **PL** | N=0 | 正或零 |
| 0110 | **VS** | V=1 | 溢出 |
| 0111 | **VC** | V=0 | 未溢出 |
| 1000 | **HI** | C=1 且 Z=0 | 无符号 ＞ |
| 1001 | **LS** | C=0 或 Z=1 | 无符号 ≤ |
| 1010 | **GE** | N=V | 有符号 ≥ |
| 1011 | **LT** | N≠V | 有符号 ＜ |
| 1100 | **GT** | Z=0 且 N=V | 有符号 ＞ |
| 1101 | **LE** | Z=1 或 N≠V | 有符号 ≤ |
| 1110 | **AL** | 任何 | 无条件（默认） |
| 1111 | **NV** | —— | 从不执行（不要使用） |

两条关键洞察：

1. **无符号与有符号各有一套**：无符号看 C（借位/进位），有符号看 N 与 V 的关系。GE 是 N=V 而不是 N=0——因为溢出会让"负"的直觉失效。
2. **HI/LS/GT/LE 是把"严格"与"非严格"拆成两条**：C=1 同时 Z=0 才是"大于"，因为 C=1 只说明"没借位"（≥）。

::: ex 例 3.1.1 · C 代码 → 条件指令，零跳转 {#ex-3.1.1}
```c
if (a > b) a++;
else       b++;
```
```asm
        CMP   R0, R1         ; R0(a) 与 R1(b) 比较（做 R0−R1，更新标志）
        ADDHI R0, R0, #1     ; 若 a>b（无符号），a++
        ADDLS R1, R1, #1     ; 若 a≤b（无符号），b++
```
对照常见写法"CMP + BLE else 标签"：条件执行把跳转省了——省下的是流水线冲刷的代价（2.3.1 的分支预测失败惩罚）。短小的 if 用条件指令往往比跳转快，这是 ARM 代码的典型风格。
:::

::: think 条件域为什么能实现"高效逻辑操作"？
课件原话是"节省跳转和条件语句，提高代码效率"。跳转的代价不只是指令周期，还包括深流水线上取指错误（A9 八级、A78 十五级）。条件执行让"不满足条件"的指令原地变成一个空操作，流水线照常前进——代价为零。代价是占用编码空间：条件占 4 位，这就是 ARM 指令只有 4 位 opcode 的原因之一。
:::

## 3.1.3 operand2 的三种形态

第二操作数 `operand2` 是 ARM 编码最灵巧的地方，三种形态：

1. **`#immed_8r`（常数表达式）**：一个 **8 位常数循环右移偶数位**得到的数。合法例：`0xff`、`0x104`、`0xff00`、`0xff000000`；非法例：`0x101`、`0x102`、`0xff1`、`0xffffffff`。构造规则与判别法见 3.2.4。
2. **`Rm`（寄存器方式）**：操作数即寄存器值，如 `SUB R1, R1, R2`。
3. **`Rm, shift`（寄存器移位方式）**：先把 Rm 移位，再参与运算，**移位不消耗额外时间**（桶形移位器在 ALU 前一级，见 3.2.5）。移位操作码五种：LSL（逻辑左移）、LSR（逻辑右移）、ASR（算术右移）、ROR（循环右移）、RRX（带扩展的循环右移 1 位）。

```asm
AND   R1, R2, #0x0F        ; R1 = R2 & 0x0f
MOV   R0, R2, LSL #3       ; R0 = R2 << 3（即 R2×8）
ANDS  R1, R1, R2, LSL R3   ; R2 左移 R3 位后与 R1 相与
ADD   R1, R1, R1, LSL #3   ; R1 = R1 + R1<<3 = R1×9
RSBS  R1, R2, R2, LSL #2   ; R1 = (R2<<2) - R2 = R2×3
```

最后两例是"用移位做乘法"的经典手法：乘 9 拆成 x + x×8，乘 3 拆成 x×4 − x。在乘法指令较慢或想省一条 MUL 时常用。

## 本节小结

三地址模板 = opcode + cond + S + Rd + Rn + operand2；cond 让每条指令自带 if，无符号看 C、有符号看 N 与 V；operand2 三形态中最特殊的是"8 位循环右移偶数位"的立即数。下一节把这套语法铺到九种寻址方式上——那才是"操作数到底在哪"的完整答案。
