# 3.5 数据处理指令与桶形移位器

算术、逻辑、比较、传送——ALU 干的活全在这里。这类指令有个共同骨架：`opcode{S} Rd, Rn, operand2`，且**只能对寄存器操作，不碰存储器**。真正让它们好用的是三件事：S 后缀管标志、operand2 带移位、条件域管执行。本节按四族展开，并专门讲清"比较指令为什么不存结果"。（课件 Slide 64–88）

## 3.5.1 四族总览与共同约束

数据传送（MOV/MVN）、算术（ADD/SUB/RSB/ADC/SBC/RSC）、逻辑（AND/ORR/EOR/BIC）、比较（CMP/CMN/TST/TEQ）。

- **只能对寄存器操作**，不能直接对内存数据运算（Load/Store 结构，2.1.2）；
- **所有数据处理指令都可选 S 后缀**影响状态标志；
- 运算结果写 Rd，比较指令**不写 Rd**（只更新标志，见 3.5.5）。

判别哪个逻辑运算配哪条指令，看目标语义：**要"置位"某几位用 ORR，"清零"某几位用 BIC，"取反"某几位用 EOR**。这三个动作覆盖了嵌入式开发里绝大多数位操作。

## 3.5.2 数据传送：MOV 与 MVN

```asm
MOV{cond}{S}  Rd, operand2      ; Rd ← operand2
MVN{cond}{S}  Rd, operand2      ; Rd ← ~operand2（按位取反后传送）
```

```asm
MOV   R11, #0xF000000B     ; 立即数传送
MOV   R0, R1               ; 寄存器传送
MOVS  R3, R1, LSL #2       ; R3 = R1<<2，并影响标志位
MOV   PC, LR               ; PC ← LR，子程序返回（3.7 再谈）
MVN   R1, #0xFF            ; R1 = 0xFFFFFF00
MVN   R1, R2               ; R1 = ~R2
```

**MVN 的实战价值**：它让"取反后才是合法立即数"的大常数得以装载（3.2.4）。`MVN R1,#0xFF` 得到 0xFFFFFF00——若直接 `MOV R1,#0xFFFFFF00`，汇编器会因为该常数不是 8 位循环右移形式而报错。

`MOV` 还兼任"移位器搬运工"：`MOV R0, R2, LSL #3` 就是"乘 8 后赋值"，不需要乘法指令。

## 3.5.3 算术运算：六条，两个方向 × 是否带进位

| 指令 | 操作 | 用途 |
|:--|:--|:--|
| **ADD** | Rd ← Rn + operand2 | 加法 |
| **SUB** | Rd ← Rn − operand2 | 减法 |
| **RSB** | Rd ← operand2 − Rn | **逆向**减法（减数在前） |
| **ADC** | Rd ← Rn + operand2 + C | 带进位加（多字长加法） |
| **SBC** | Rd ← Rn − operand2 − NOT(C) | 带进位减（多字长减法） |
| **RSC** | Rd ← operand2 − Rn − NOT(C) | 带进位逆向减 |

这六条**都影响 N Z C V**（带 S 时）。RSB 的存在是为了"常数在前"的减法：`RSB R3,R1,#0xFF00` 算 0xFF00 − R1，用 SUB 写不出来（立即数是减数而不是被减数）。

**ADC / SBC 是 64 位运算的积木**——课件给了两个必背范例：

```asm
; (R1,R0) + (R3,R2) → (R1,R0)
        ADDS  R0, R0, R2      ; 低 32 位相加，产生进位 C
        ADC   R1, R1, R3      ; 高 32 位相加，再加低位进位

; (R1,R0) − (R3,R2) → (R1,R0)
        SUBS  R0, R0, R2      ; 低 32 位相减，产生借位（C=0）
        SBC   R1, R1, R3      ; 高 32 位相减，再减低位借位
```

注意第一条**必须带 S**（ADDS）：没有 S 就不产生 C，ADC 加进来的就是垃圾。这是多字长运算最经典的错误点。

```asm
; RSC 求 64 位数的相反数：0 − (R1,R0)
        RSBS  R2, R0, #0      ; R2 = −R0
        RSC   R3, R1, #0      ; R3 = −R1 − NOT(C)
```

## 3.5.4 逻辑运算：AND / ORR / EOR / BIC

| 指令 | 操作 | 位操作语义 |
|:--|:--|:--|
| **AND** | Rd ← Rn & operand2 | 取位（掩码提取） |
| **ORR** | Rd ← Rn \| operand2 | 置位 |
| **EOR** | Rd ← Rn ^ operand2 | 按位取反（翻转） |
| **BIC** | Rd ← Rn & ~operand2 | **清零**（bit clear） |

带 S 时：**按结果更新 N 和 Z，按 operand2 更新 C，不影响 V**——与算术指令"四标志全动"不同，这个差别要记住。

```asm
ANDS  R0, R0, #0x0F        ; 取最低 4 位，结果影响 Z（可用于判是否为 0）
AND   R0, R0, #0xFFFFFFF0  ; 最低 4 位清零（也可写作 BIC R0,R0,#0x0F）
ORR   R0, R0, #0x0F        ; 低 4 位置 1
BIC   R1, R1, #0x0F        ; 低 4 位清零，其余不变
EOR   R0, R0, #0x0F        ; 低 4 位取反，高 28 位不变
```

::: ex 例 3.5.1 · 位域打包（面试级小题） {#ex-3.5.1}
把 R2 的高 8 位搬到 R3 的低 8 位，其余位保留：

```asm
        MOV   R1, R2, LSR #24   ; R1 = R2 的高 8 位（移到最低 8 位）
        ORR   R3, R1, R3, LSL #8 ; 组合（课件示例的写法）
```

更直接的写法是 `BIC R3,R3,#0xFF` 再 `ORR R3,R3,R1`——两步"先清后置"，是配置外设寄存器位域的标准套路。两种都行，关键是**清与置要配对**，只置不清会把旧位留着。
:::

## 3.5.5 比较指令：只更新标志，不存结果

四条比较指令的**共同点：不写 Rd，只改 CPSR 的 N Z C V**。

| 指令 | 实际运算 | 与谁等价（差别） |
|:--|:--|:--|
| **CMP** | Rn − operand2 | SUBS（但不保存结果） |
| **CMN** | Rn + operand2 | ADDS（但不保存结果） |
| **TST** | Rn & operand2 | ANDS（但不保存结果） |
| **TEQ** | Rn ^ operand2 | EORS（但不保存结果） |

- **CMP** 后接 EQ/NE/GT/LT 等条件，是"if 比较"的标准前奏；
- **CMN** 用于负数比较：`CMN R0,#1` 等价于"R0 与 −1 比较"，R0 为 −1 时 Z 置位；
- **TST** 是位测试：`TST R0,#0x01` 判最低位；**TST R1,#0x0F** 判低 4 位是否全 0。全 0 时 Z=1（EQ 有效），有一位非 0 则 NE 有效；
- **TEQ** 是相等测试且**不影响 V 和 C**（异或结果不产生进位/溢出）——比 CMP 更"干净"，用于只需判等、不想破坏 C/V 的场合。

::: think 为什么比较指令要"不算结果"？
`SUBS R2, R0, R1` 会写 R2——但比较场景根本不想要结果，写 R2 反而破坏了现场。CMP 把结果扔掉只留标志，一条指令既省了一个寄存器又省了一次写回。这也解释了为什么 CMP 没有 S 后缀：它天生更新标志。
:::

条件码的配合范例（回到 3.1.2）：

```asm
        CMP   R1, #10          ; R1 与 10 比较
        CMPGT R1, R2           ; 若上一句 R1>10，才做这次比较（条件执行）
```

四族共用 `{S} Rd,Rn,operand2` 骨架；算术六条要记 RSB 的"逆"与 ADC/SBC 的多字长用法（低位必须带 S）；逻辑四条的位语义 = 取/置/翻/清；比较四条只更新标志不存结果。下一节是唯一不走桶形移位器的一条旁支——乘法。
