# 3.10 Thumb 指令集与 ARM/Thumb 互操作

ARM 状态下的指令 4 字节长，Thumb 状态下 2 字节长。同一颗芯片、同一套寄存器，为什么要在两套指令集之间切换？答案是代码密度。本节把 Thumb 的收益账算清，并交代 ARM/Thumb 混编时的规矩。（课件 Slide 2–6、131–133）

## 3.10.1 两套指令集的基本事实

| | ARM 状态 | Thumb 状态 |
|:--|:--|:--|
| 指令长度 | 32 位（4 字节） | 16 位（2 字节） |
| 代码密度 | 低 | **高，约为 ARM 的 65%** |
| 性能 | 高 | 保持 ARM 的大部分性能优势 |
| 条件执行 | **所有指令**都可以 | **只有 B 指令**可以 |
| 关系 | —— | **ARM 指令集的子集** |

课件的定位很直接：**ARM 指令集支持 ARM 核所有的特性，高效快速；Thumb 指令集灵活、小巧。**

体系结构版本上有两条并行路线：Thumb 最初是 ARM 的 16 位精简集（Thumb-1），Thumb-2 在此基础上加入 32 位 Thumb 指令，形成混合宽度集（课件里标为 **T32**）——所以现代 ARMv7 核的"Thumb 状态"实际能执行 16 位与 32 位两种 Thumb 指令。

## 3.10.2 Thumb 的编译期约束

课件列出的"由编译器产生的大部分 Thumb 指令"的特点（Slide 131）：

- **没有条件执行**（只有 B 有）；
- **源、目的寄存器必须相同**；
- **仅能使用低寄存器**（R0–R7；高寄存器需特殊编码才能访问）；
- **常数大小有限制**；
- **不能使用在线移位器**（没有桶形移位器，第二操作数不能带移位）。

这几条正好解释了 Thumb 指令"变小"的代价：16 位里塞不下 cond 域、塞不下桶形移位器的编码、塞不下高寄存器编号。

## 3.10.3 Thumb 的收益：密度换带宽

课件用一张基准测试图说明：**Thumb 代码总量约为 ARM 的 65%**，但性能曲线与 ARM 接近（在 20 MHz、Dhrystone 2.1 下两者相当）；在**窄总线存储器**上，Thumb 的优势更明显——取指带宽减半，16 位指令每周期取到的代码更多。

内存是嵌入式系统最稀缺的资源（2.11 的地址空间、4.4 的 RTOS 内存管理都受它约束），所以 Thumb 的价值主要在"同样的 Flash 装下更多功能"。

## 3.10.4 ARM 与 Thumb 互操作

课件明确：**ARM 程序和 Thumb 程序可相互调用，相互之间的状态切换开销几乎为零。**

实现方式就是 [3.7.4](sec3-7.md) 的 BX：

```asm
; ARM 代码调用 Thumb 函数：地址最低位置 1
        ADRL  R0, ThumbFun+1
        BX    R0

; Thumb 代码调用 ARM 函数：地址最低位为 0
        ADRL  R0, ArmFun
        BX    R0
```

规则回顾（2.5.2、3.7.4）：

- **BX 的目标地址最低位是状态标志**：1 → Thumb，0 → ARM；该位不参与地址计算；
- ARM 指令 4 字节对齐、Thumb 指令 2 字节对齐，所以空闲的第 0 位可以安全地当标记；
- **切换状态不影响处理器模式与寄存器内容**（2.5.1）。

从 C 语言一侧看：**函数指针的值 = 真实地址 | 1** 表示"这是个 Thumb 函数"，编译器生成的调用指令就是 BX（3.7.4）。C 语言里把函数指针强转成整数再或上 1，就是手工指定"按 Thumb 调用"。

## 3.10.5 Thumb 的代价与实践建议

课件给了一条很实在的判断（Slide 133）：

> **Thumb 不是一个"好"指令集！最好用编译器来产生；约束并不一致；手动编码使用 ARM 指令集比较好。**

理由：Thumb 的指令约束（低寄存器、无桶形移位、条件执行受限）与手写者的直觉不一致，人工优化容易写出比编译器更差的代码。实践上的分工是：

| 场景 | 选择 |
|:--|:--|
| 空间敏感（Flash 小、成本敏感） | 编译器按 `-mthumb` 生成 Thumb |
| 极致性能热点 | 手写 ARM 汇编 |
| 手写 Thumb 汇编 | 一般不划算 |

## 本节小结

Thumb = 16 位（现代为 Thumb-2 混合宽度）、ARM 的子集、代码密度约 65%、只有 B 能条件执行、无桶形移位器、仅用低寄存器；ARM/Thumb 互操作靠 BX 的地址最低位，切换开销几乎为零；实践建议是让编译器产出 Thumb，手工优化仍用 ARM。下一节处理课件第三块——汇编程序本身怎么组织，以及它和 C 怎么互相调用。
