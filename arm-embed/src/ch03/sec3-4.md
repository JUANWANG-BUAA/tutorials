# 3.4 存储器访问指令：多寄存器与数据交换

函数入口把 R0–R3 和 LR 一口气压栈、出口一口气弹回——这是每个汇编函数的第一行和最后一行。一条指令搬 16 个寄存器的任意子集，靠的是 LDM/STM 加一个四字母后缀。这四字母（IA/IB/DA/DB 与 FD/ED/FA/EA）是全章最绕的一张表，本节把它拆成"方向 × 先后"两个维度来讲。（课件 Slide 55–62）

## 3.4.1 LDM / STM 总述

**LDM**（LoaD Multiple）一次读多个寄存器；**STM**（STore Multiple）一次存多个。允许一条指令传送 **16 个寄存器的任何子集或全部**，主要用于**现场保护、数据复制、常数传递**。

格式：

```
LDM{cond}<模式>  Rn{!}, reglist{^}
STM{cond}<模式>  Rn{!}, reglist{^}
```

- `!`：基址回写（与 3.3 同义）；
- `reglist`：花括号内的寄存器列表，可用连字符范围（`{R2-R7,R12}`）；
- `^`：特殊后缀，**只在列表含 PC 时有意义**——见 3.4.5。

## 3.4.2 八种模式：方向 × 先后

两个自由度：

- **方向（U 位）**：地址往上（增，I 系）还是往下（减，D 系）；
- **先后（P 位）**：先传后改（After）还是先改后传（Before）。

组合出四种数据块传送模式：

| 模式 | 全称 | 含义 |
|:--|:--|:--|
| **IA** | Increment After | 每次传送**后**地址 +4 |
| **IB** | Increment Before | 每次传送**前**地址 +4 |
| **DA** | Decrement After | 每次传送**后**地址 −4 |
| **DB** | Decrement Before | 每次传送**前**地址 −4 |

同一组模式换一套名字就成了栈操作：

| 数据块模式 | 栈模式 | 栈类型 |
|:--|:--|:--|
| STMDA / LDMDA | **STMED / LDMED** | 空递减 |
| STMIA / LDMIA | **STMEA / LDMEA** | 空递增 |
| STMDB / LDMDB | **STMFD / LDMFD** | 满递减 |
| STMIB / LDMIB | **STMFA / LDMFA** | 满递增 |

课件的对照表值得抄下来：**"右四种为栈操作、左四种为数据传送操作"**，并给出一条实用结论——两段代码（`STMDA/LDMIB` 与 `STMED/LDMED`）执行结果一样，但**栈指令编程简单，只要前后一致即可**；数据块指令要自己考虑空/满、加/减的配对。

::: note 为什么"满/空"会换个名字？
同一硬件动作，从两个视角命名：讲"数据块"时关心地址怎么走（IA/IB/DA/DB）；讲"栈"时关心 SP 指向什么（满 = 指向有效数据，空 = 指向下一个空位）。FD 与 DB 是同一件事，ED 与 DA 也是——**FD=DB、ED=DA、FA=IB、EA=IA**。考试若问"STMFD 等价哪个数据块指令"，答 STMDB。
:::

## 3.4.3 方向与先后的图形直觉

设 R1=0x4000、R5=0x11、R6=0x22、R7=0x33，执行 `STM?? R1!,{R5-R7}`：

| 模式 | 存储器布局（低→高地址） | R1 终值 |
|:--|:--|:--|
| IA | [0x4000]=11, [0x4004]=22, [0x4008]=33 | 0x400C |
| IB | [0x4004]=11, [0x4008]=22, [0x400C]=33 | 0x4010 |
| DA | [0x3FF8]=11, [0x3FFC]=22, [0x4000]=33 | 0x3FF4 |
| DB | [0x3FF4]=11, [0x3FF8]=22, [0x3FFC]=33 | 0x3FF0 |

读法：IA 从基址开始往后填；IB 先跳一格再填；DA 先退一格填完再退；DB 边退边填。寄存器列表**永远按编号从小到大配存储器的低到高**（与写的次序无关）。

::: ex 例 3.4.1 · 典型栈骨架（满递减） {#ex-3.4.1}
Cortex/ARM 最常用的栈是**满递减（FD）**：栈向低地址生长，SP 指向最后一个有效数据。

```asm
foo     STMFD SP!, {R4-R7, LR}   ; 压栈：LR 与 R4-R7 入栈，SP 下移
        ...                       ; 函数体
        LDMFD SP!, {R4-R7, PC}    ; 出栈：恢复 R4-R7，末项直接回 PC
```

注意出口用 **PC** 而不是 LR：出栈的最后一个值（原 LR）直接写进 PC，一步完成"恢复现场 + 返回"。这就是 2.7.4 说的"进入先压栈"的标准落地。
:::

## 3.4.4 多寄存器寻址与块拷贝的用法差别

两种用途，同一批指令：

**块拷贝（数据复制）**：先设好源、目标两个指针，再用 LDMIA/STMIA 等搬运。

```asm
        LDMIA R0!, {R1-R7}      ; 从 R0 读 7 个字到 R1-R7，R0 前移
        STMIA R1!, {R1-R7}      ; 存到 R1 指向处，R1 前移
```

**栈操作**：设好 SP，用 STMFD/LDMFD（或 ED/FA/EA 组合）配对。

::: note 寄存器列表里的"陷阱"
`STMIA R1!,{R1-R7}` 这类写法（基址寄存器也在列表里）在旧核上行为依实现而定（基址值与新值谁先写不确定）。**规范做法：基址寄存器不要出现在自己的 reglist 里**。考试遇到这类题，答"结果不可靠/依赖实现"。
:::

## 3.4.5 `^` 后缀：异常返回的钥匙

`^` 后缀的含义分两种：

- **LDM + 列表含 PC**：除了加载寄存器，还要把 **SPSR 复制回 CPSR**——即"异常返回"（2.9.4 的 `LDMFD SP!,{R0-R3,PC}^`）。这是从异常模式回到用户模式的唯一干净通道。
- **LDM/STM + 列表不含 PC**（且在用用户/系统模式寄存器时）：访问**用户模式**的寄存器组（用于特权模式读写用户态寄存器）。

考试最常见的是第一种：看到 `LDMFD SP!, {...PC}^` 就要能说出"恢复现场 + SPSR→CPSR + 模式返回"三件事一次完成。

## 3.4.6 SWP：寄存器和存储器交换

```asm
SWP{cond}{B}  Rd, Rm, [Rn]
```

一条指令内完成"读—写"原子交换：Rd ← [Rn]，同时 [Rn] ← Rm。`B` 后缀交换字节。规则：

- **Rn 不能与 Rd、Rm 相同**；
- **Rd 与 Rm 可以相同**——此时就是"寄存器与存储器内容互换"，`SWP R1,R1,[R0]` 是最常见写法。

编码字段：cond | B | Rd | Rn | Rm，B=1 字节、B=0 字。

**为什么这条指令重要**：它是实现**信号量（semaphore）**的硬件基础——"读旧值 + 写新值"不可被打断，多任务环境下的锁操作才可能正确。第四章 4.9 会回到这里：RTOS 的互斥量底层往往是一条类似 SWP 的原子指令（Cortex-A9 用 LDREX/STREX，思想相同）。

::: think SWP 与普通 LDR+STR 的差别在哪？
`LDR R1,[R0]` 与 `STR R2,[R0]` 是两次独立的存储器访问，中间可以被中断/切换打断；SWP 是**单条指令内的原子读改写**。多核系统里"检查标志再置标志"的经典竞态，只能靠原子指令或总线锁消除。
:::

## 本节小结

LDM/STM = 方向（I/D）× 先后（A/B），换到栈视角就是满/空 × 递增/递减，其中 **FD=DB** 最常用；`!` 回写、`^` 在含 PC 的 LDM 上恢复 CPSR；SWP 提供原子读改写，是信号量的硬件基石。下一节转到 ALU 那一侧——数据处理指令。
