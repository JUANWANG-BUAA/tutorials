# 习题集

第三章习题按节分组。**读程序题要求写出每步的寄存器/存储器变化**，不要只写结论——写出来才会暴露理解漏洞。

## A 组 · 格式、条件码与寻址（3.1–3.2）

**A1** 填空：`SUBS R0, R1, R2, LSL #1` 中，条件执行部分是什么？S 是什么？第三操作数实际参与运算的值是什么？

**A2** 下面这些立即数哪些合法？说明理由：0x00、0x3F、0x40、0x100、0xFF00、0x101、0x00FF0000、0xFFFFFFFF、0x80000000。

**A3** 写一段不超过 3 条指令的代码，把 R1 的低 4 位清零（其余位保留），再用另一段把 R1 的低 4 位置 1。

**A4** `LDR R0, [R1, #4]`、`LDR R0, [R1, #4]!`、`LDR R0, [R1], #4` 三条，R1=0x1000 时分别访问哪个地址？后两条执行后 R1 是多少？

**A5** 为什么 `MOV R0, #0xFFFFFFF0` 可能无法汇编？给出两种替代写法。

::: sol A 组解答要点
A1：无条件（AL）；S=更新 NZCV；实际参与运算的是 R2<<1（桶形移位器先行移位）。A2：合法 0x00、0x3F、0x40（8 位窗口）、0xFF00、0x00FF0000、0x80000000（0x80 左移 24）；非法 0x100（1 在 bit8，需 9 位窗口）、0x101、0xFFFFFFFF、其余不符者。判据：所有 1 位能否装进一个 8 位窗口。A3：`BIC R1, R1, #0x0F`；置 1 用 `ORR R1, R1, #0x0F`。A4：分别访问 0x1004 / 0x1004 / 0x1000；后两条执行后 R1 = 0x1004（第二条先加后访存，第三条访存后加）。A5：0xFFFFFFF0 不是 8 位循环右移形式；替代：`MVN R0, #0x0F`（取反得 0xFFFFFFF0），或 `LDR R0, =0xFFFFFFF0`（走文字池）。
:::

## B 组 · 存储器访问（3.3–3.4）

**B1** 区分下列后缀的作用：`LDR` / `LDRB` / `LDRSB` / `LDRT` / `LDRH` / `LDRSH`。为什么 `LDRT` 在用户模式下无效？

**B2** 存储器地址 0x2000 处字节为 0x8A。分别用 `LDRB R0,[R1]`（R1=0x2000）与 `LDRSB R0,[R1]` 读取，R0 各是多少？两者在后续被当作无符号数使用时有区别吗？

**B3** 已知 `STMIA R0!, {R5-R7}` 中 R0=0x4000、R5=0x11、R6=0x22、R7=0x33。写出执行后 0x4000–0x400C 各单元内容与 R0 的新值。再写 `STMFD R0!, {R5-R7}` 的对应结果。

**B4** `LDMFD SP!, {R4-R7, PC}^` 中每个符号的含义是什么？为什么少了 `^` 就不能返回？

**B5** 用 SWP 实现"原子地把内存单元的值加 1"（提示：需要先读、再加、再写，注意原子性）。

::: sol B 组解答要点
B1：B=字节、H=半字（无后缀=字）；S=符号扩展（有符号字节/半字）；T=以用户模式访存。用户模式下本就按用户权限，T 无意义，故无效。B2：LDRB → 0x0000008A（零扩展）；LDRSB → 0xFFFFFF8A（符号扩展，因 bit7=1）。有区别：按无符号用，前者得 138、后者得 −118。B3：IA → [0x4000]=11, [0x4004]=22, [0x4008]=33，R0=0x400C；FD（=DB）→ 先退 4 再填：[0x3FF4]=11, [0x3FF8]=22, [0x3FFC]=33，R0=0x3FF0。B4：LDM=多寄存器加载，FD=满递减栈，!=基址回写，^=同时把 SPSR 恢复回 CPSR（异常返回）；没有 ^ 时 CPSR 里的模式位不恢复，处理器留在异常模式。B5：`SWP R1,R1,[R0]` 读出旧值 → 加 1 → 再写回；但两次 SWP 之间并非原子，**真正原子需 LDREX/STREX 或关中断**——SWP 只能保证"读"和"写"各自不撕裂。这是本题的考点：SWP 原子的是单次访存，不是整个读改写序列。
:::

## C 组 · 数据处理与乘法（3.5–3.6）

**C1** 填表：R0=5、R1=7，执行 `SUBS R2, R0, R1` 后 N Z C V 各为多少？若换成 `CMP R0, R1`，R2 会变吗？

**C2** 写出三条指令，把 (R1,R0) 视为 64 位数加到 (R3,R2) 上，结果存回 (R1,R0)。若第一条漏写 S 后缀，第二条会怎样？

**C3** `BIC R0, R1, #0x0F` 的结果是什么（语义描述）？要"取 R1 的低 8 位并清零其余位"，写一条指令。

**C4** `MUL R1, R2, R3` 中若把 R1 写成 R2 会怎样？为什么？`UMULL R0, R1, R5, R8` 的 64 位结果如何装入寄存器？

**C5** 某程序需要判断 R0 是否为负数（补码），写出两条指令。再写一条判断 R0 是否为**无符号意义**下大于 100 的指令组合。

::: sol C 组解答要点
C1：N=1（−2）、Z=0、C=0（借位）、V=0；CMP 不写 R2（R2 保持原值）。C2：`ADDS R0,R0,R2` / `ADC R1,R1,R3`；漏 S 则第一条不更新 C，第二条 ADC 加进来的是"上一条遗留的 C"，结果错。C3：R0 = R1 & ~0x0F（R1 低 4 位清零，其余保留）；取低 8 位并清其余：`AND R0, R1, #0xFF`。C4：Rd=Rm 与编码字段冲突，结果不可预测/报错；64 位结果低 32 位在 RdLo(R0)、高 32 位在 RdHi(R1)。C5：`TST R0,#0x80000000` 配合 `BMI`（测 bit31）；或 `CMP R0,#0` + `BMI`；无符号大于 100：`CMP R0,#100` + `BHI`（C=1 且 Z=0）。
:::

## D 组 · 分支、杂项、伪指令（3.7–3.9）

**D1** `BL func` 之后 LR 的值是什么？子程序返回该写什么？若子程序还要调用别的子程序，LR 怎么办？

**D2** 写出"ARM 状态调用 Thumb 函数"的完整三行代码，并解释每一行。

**D3** 用 MRS/MSR 写一个"关中断并保存原 CPSR"的子程序：进入时保存 CPSR 到 R0，关中断；返回时恢复。

**D4** SWI 处理程序如何取出 SWI 的 24 位立即数？说明为什么 Thumb 与 ARM 取法不同。

**D5** `ADR R1, label` 与 `LDR R1, =label` 有什么本质区别？各在什么情况下会编译失败？

**D6** 解释这段代码：`LDR R0, =0xFFFFFFFE`。

::: sol D 组解答要点
D1：LR = BL 之后那条指令的地址（当前+4）；返回写 `MOV PC, LR`；若嵌套调用，内层 BL 会覆盖 LR，所以外层要在自己的栈帧里保存 LR（`STMFD SP!,{...,LR}`），返回前 `LDMFD` 恢复。D2：`LDR/ADRL R0,=ThumbFunc+1`（地址最低位置 1）/ `BX R0`（最低位=1 → Thumb）；可用 `ADRL R0,ThumbFunc+1; BX R0`（ADRL 立即数在范围内时更简洁）。D3：`MRS R0,CPSR` → `ORR R0,R0,#0x80` → `MSR CPSR_c,R0`（清 I 位前先备份）；恢复时 `MSR CPSR_c,R0`（R0 需在栈中保存）。D4：先读 SPSR 测 T 位判断来自哪种状态（Thumb→读 LR−2 处的 16 位指令、ARM→读 LR−4 处的 32 位），再用 BIC 取低 8 位（Thumb）或低 24 位（ARM）。D5：ADR 用 PC 相对偏移、展开为一条 ADD/SUB，范围受限（字对齐 ±1020），超范围编译失败；LDR= 走文字池，可装任意 32 位常数与任意远地址，但要求**文字池距指令 <4KB**，否则失败。D6：0xFFFFFFFE 不是合法立即数；汇编器发现 MVN 能表达（~0x1 = 0xFFFFFFFE），故展开为 `MVN R0,#0x1`。
:::

## E 组 · Thumb 与汇编程序（3.10–3.11）

**E1** Thumb 指令集有哪些限制？为什么"手动编码用 ARM 更好"？

**E2** 一个汇编文件里 `ENTRY` 出现两次会怎样？`AREA` 是什么？

**E3** 下列标识符各是什么指示符：`DCB`、`DCD`、`EQU`、`IF/ENDIF`、`MACRO/MEND`、`EXPORT`、`END`？

**E4** C 调用汇编函数时，参数按什么约定传递？为什么被调用者必须保存 R4–R11？

::: sol E 组解答要点
E1：16 位、只有 B 能条件执行、仅用低寄存器、常数受限、无桶形移位器（不能在线移位）；约束与人的直觉不一致，人工编码容易低于编译器水平，故建议编译器生成 Thumb、手工优化用 ARM。E2：ENTRY 一个源文件只能有一个，重复会报错；AREA 声明一段新的代码段或数据段（name, type, 属性）。E3：DCB 定义字节、DCD 定义字、EQU 定义常量符号、IF/ENDIF 条件汇编、MACRO/MEND 宏定义、EXPORT 导出符号给链接器、END 表示源程序结束。E4：APCS 约定参数从 R0–R3 起传、返回 R0；R4–R11 是"被调用者保存"寄存器（别名 v1–v8），跨调用必须由被调方保存恢复，否则调用者的值被破坏。
:::

## F 组 · 综合读程序

**F1** 跟踪以下 8 行代码（初始 R0=0x1000，R1=0x00000000，内存 [0x1000]=0xAABBCCDD）：

```asm
        LDR   R2, [R0]        ; 1
        LDRB  R3, [R0], #1    ; 2
        MOV   R1, R2, LSR #16 ; 3
        ORR   R1, R1, #0x00FF ; 4
        STRH  R1, [R0], #2    ; 5
        SUBS  R2, R2, #1      ; 6
        BNE   somewhere       ; 7
        SWI   0x123456        ; 8
```

逐行写出 R0、R1、R2、R3 的值变化（内存按小端，2.11.3）。

**F2** 承接 F1：第 8 行 SWI 触发后，硬件做了什么？（按 2.9.3 回答）处理程序如何知道服务号？返回时 PC 与 CPSR 各如何变化？

::: sol F1 解答（逐行）
初始：R0=0x1000，R1=0，内存小端 [0x1000]=DD [0x1001]=CC [0x1002]=BB [0x1003]=AA。

1. `LDR R2,[R0]`：R2 = 0xAABBCCDD，R0 不变。
2. `LDRB R3,[R0],#1`：R3 = 0xDD（零扩展），R0 = 0x1001。
3. `MOV R1,R2,LSR #16`：R1 = 0x0000AABB。
4. `ORR R1,R1,#0x00FF`：R1 = 0x0000AABB | 0xFF = 0x0000AABB（低 8 位本就为 BB）。
5. `STRH R1,[R0],#2`：把 R1 低 16 位（0xAABB）存到 0x1001（小端 → [0x1001]=BB, [0x1002]=AA），R0 = 0x1003。
6. `SUBS R2,R2,#1`：R2 = 0xAABBCCDC，标志：N=1、Z=0、C=1（无借位）、V=0。
7. `BNE somewhere`：条件 NE 成立（Z=0）→ 跳转。
8. `SWI 0x123456`：产生 SWI 异常，进入 svc 模式。

**F2 解答**：硬件四步（2.9.3）：LR_svc ← SWI 下一条地址（ARM 状态 +4）、CPSR → SPSR_svc、模式位 → 10011（svc）且 I 置 1、T 清 0、PC ← 向量 0x00000008。处理程序按 3.8.3：读 SPSR 测 T 位判断状态 → ARM 状态读 [LR−4] 取 32 位指令 → `BIC R0,R0,#0xFF000000` 取低 24 位 = 0x123456。返回时 `SUBS PC,R14_svc,#4`（或 LDMFD ^）：PC 回到 SWI 之后，CPSR ← SPSR_svc（模式回原模式、I 清回原值）。
:::
