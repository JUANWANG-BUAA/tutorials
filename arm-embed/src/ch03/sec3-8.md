# 3.8 杂项指令：SWI 与程序状态寄存器访问

三条指令，管着"用户程序怎么请操作系统办事"和"操作系统怎么读改处理器状态"。SWI 是用户态进入内核的唯一合法门；MRS/MSR 是唯一能读改 CPSR/SPSR 的正规途径。（课件 Slide 108–116）

## 3.8.1 三条杂项指令

| 助记符 | 说明 | 操作 |
|:--|:--|:--|
| **SWI** | 软中断指令 | 产生 SWI 异常，处理器**进入管理模式** |
| **MRS** | 读状态寄存器 | Rd ← psr（psr 为 CPSR 或 SPSR） |
| **MSR** | 写状态寄存器 | psr_fields ← Rd 或 #immed_8r |

## 3.8.2 SWI：系统调用的硬件形态

**SWI{cond} immed_24**——指令里带一个 24 位立即数（值域 0～2²⁴−1）。执行时 CPU **忽略该参数作为操作数**，但把它作为**异常信息**带给处理程序：产生 SWI 异常 → CPU 切到**管理模式 svc** → CPSR 存入 SPSR_svc → 跳到向量 0x00000008（2.9.2）。

**SWI 不影响条件码标志。**

它的用途：**用户程序调用操作系统的系统服务**，操作系统在 SWI 异常处理程序中完成相应功能。

参数传递有两种约定：

| 方式 | 立即数的作用 | 参数 |
|:--|:--|:--|
| ① 立即数指定服务类型 | 24 位立即数 = 服务号 | 通过通用寄存器传（如 R0） |
| ② 立即数被忽略 | 忽略 | 服务类型由寄存器决定（如 R0 = 服务号，R1 = 子功能号） |

```asm
; 方式一
        MOV   R0, #34        ; 子功能号 34
        SWI   12             ; 调用 12 号软中断
; 方式二
        MOV   R0, #12        ; 服务号 12
        MOV   R1, #34        ; 子功能号 34
        SWI   0              ; 立即数被忽略
```

## 3.8.3 处理程序怎么取出服务号

这是本节最值得学的一段代码——课件给的标准做法，完整走一遍：

```asm
SWI_Handler
        STMFD  SP!, {R0-R3, R12, LR}    ; 现场保护
        MRS    R0, SPSR                 ; 读 SPSR：里面有异常前的 CPSR
        STMFD  SP!, {R0}                ; 保存 SPSR，返回时出栈
        TST    R0, #0x20                ; 测试 T 标志位（第 5 位 = T）
        LDRNEH R0, [LR, #-2]            ; 若是 Thumb，读 16 位指令码
        BICNE  R0, R0, #0xFF00          ; 取 Thumb 指令的 8 位立即数
        LDREQ  R0, [LR, #-4]            ; 若是 ARM，读 32 位指令码
        BICEQ  R0, R0, #0xFF000000      ; 取 ARM 指令的 24 位立即数
        ...                             ; 根据 R0 中的服务号分派
        LDMFD  SP!, {R0-R3, R12, PC}^   ; SWI 异常返回
```

三步逻辑：

1. **判断来自哪种状态**：读 SPSR，测 T 位（`TST R0,#0x20`，因为 CPSR 的位 5 是 T）——Thumb 时 SPSR 的 T=1；
2. **找到触发的那条指令**：SWI 的返回地址在 LR 里（2.9.3：LR ← 下一条指令地址）。所以 **Thumb 指令在 LR−2 处、ARM 指令在 LR−4 处**；
3. **从指令编码里抠出立即数**：Thumb 取低 8 位（`BIC R0,R0,#0xFF00` 保留低 8 位），ARM 取低 24 位（`BIC R0,R0,#0xFF000000` 保留低 24 位）。

::: ex 例 3.8.1 · 手算一次服务号 {#ex-3.8.1}
用户态（Thumb 状态）执行 `SWI 0x12`：

- Thumb 编码：`0xDF02`（SWI 立即数为 0x12 时，Thumb 的 SWI 编码是 0xDF02）。
- LR = 触发指令地址 + 2 = 0x1002（假设 SWI 在 0x1000）。
- 处理程序：`LDRNEH R0,[LR,#-2]` → 读 0x1000 处的半字 = 0xDF02；
- `BICNE R0,R0,#0xFF00` → 保留低 8 位 → R0 = **0x02**。

服务号拿到了。
:::

## 3.8.4 MRS：读 CPSR / SPSR

```asm
MRS{cond}  Rd, psr        ; psr = CPSR（编码 0）或 SPSR（编码 1）
```

- Rd **不能为 R15**；
- 读 CPSR 可了解当前处理器工作状态；读 SPSR 可了解**进入异常前**的处理器状态；
- **不影响条件码**。

```asm
MRS   R1, CPSR      ; 当前 CPSR → R1
MRS   R2, SPSR      ; 异常前的 CPSR → R2
```

## 3.8.5 MSR：写 CPSR / SPSR（域掩码是关键）

```asm
MSR{cond}  psr_fields, #immed_8r
MSR{cond}  psr_fields, Rm
```

`psr_fields` 是**"CPSR 或 SPSR" + 域掩码**的组合。域掩码用**小写**字母，可以是以下之一或组合：

| 字母 | 域 | 位范围 |
|:--|:--|:--|
| **c** | 控制域 | psr[7:0] |
| **x** | 扩展域 | psr[15:8] |
| **s** | 状态域 | psr[23:16] |
| **f** | 标志域 | psr[31:24] |

**掩码的作用是"只写我关心的那几段，其余保持原值"**——这就是 2.8.3 说的"读—改—写"策略在指令层的落地。

**经典例：使能/禁止 IRQ**（中断总开关，第四章的必备操作）：

```asm
; 使能 IRQ
ENABLE_IRQ
        MRS   R0, CPSR         ; 1. 读出 CPSR
        BIC   R0, R0, #0x80    ; 2. 清掉 I 位（bit7）
        MSR   CPSR_c, R0       ; 3. 只写回控制域
        MOV   PC, LR           ; 4. 返回

; 禁能 IRQ
DISABLE_IRQ
        MRS   R0, CPSR
        ORR   R0, R0, #0x80    ; 置 I 位
        MSR   CPSR_c, R0
        MOV   PC, LR
```

两条流程完全对称，只有第 2 步是 BIC（清）与 ORR（置）的区别。**注意 MSR 的目标写的是 `CPSR_c`（带域掩码）而不是 `CPSR`**——不带掩码会连保留位一起覆盖，破坏可移植性（2.8.3）。

MSR 与 MRS 配合能实现：切换处理器模式、允许/禁止 IRQ/FIQ、修改标志位。

::: note 两条禁令
1. **不要用 MSR 改 T 位**（控制域 c 含 T 位）——不配合跳转改状态会让处理器进入不可预测状态（2.5.2、2.8.3）。要切状态用 BX。
2. **用户模式下不能写控制域**——控制域只有特权模式可写（2.8.3），否则用户程序就能给自己提权或关中断。
:::

## 3.8.6 三条指令的分工回顾

- **SWI**：用户 → 内核的**唯一合法入口**（配合 2.6 的模式分层）；
- **MRS**：读回状态（诊断代码里最常见）；
- **MSR**：受控地改状态（开关中断、切模式），必须带域掩码。

三条合起来，正好对应 2.8 的 CPSR 三块：SWI 动模式位（硬件自动）、MSR 动控制域、MRS 读一切。

## 本节小结

SWI 带 24 位立即数、进 svc 模式、不影响标志；处理程序靠"SPSR 的 T 位 → LR−2/−4 → BIC 取立即数"三步取服务号；MRS 只读 CPSR/SPSR，MSR 必须带域掩码（c/x/s/f）做读—改—写，禁止改 T 位。下一节讲伪指令——它们让汇编程序员不必手算立即数和文字池。
