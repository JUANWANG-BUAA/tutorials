# 2.5 处理器状态：ARM 与 Thumb

同一段程序，编译成 32 位 ARM 指令占 4 KB，编译成 16 位 Thumb 指令只占约 2.6 KB——代价是慢一点。ARM 允许一个程序里两种代码混着放、随时切换。本节回答两个问题：切换**怎么触发**，切换**会不会把现场弄乱**。（课件 Slide 38–39）

## 2.5.1 两种操作状态

ARM 处理器内核（v4T 起）有两种操作状态，对应两套指令宽度：

| 状态 | 指令宽度 | 取指特征 |
|:--|:--|:--|
| **ARM 状态** | 32 位，字方式执行 | 地址 [1:0] = 0b00 |
| **Thumb 状态** | 16 位，半字方式执行 | 地址 [0] = 0 |

两条性质先立住，后面全靠它们：

1. **异常一律在 ARM 状态处理**。Thumb 状态下发生异常，进入异常时硬件自动切到 ARM 状态；异常返回时若原先是 Thumb，又自动切回。所以异常处理程序永远按 ARM 指令写。
2. **两种状态的切换不改变处理器模式，也不改变寄存器内容**。状态（ARM/Thumb）说的是"怎么解释指令流"，模式（usr/svc/irq…，见 2.6）与寄存器组（2.7）是另一套独立的东西——切状态不换寄存器，切模式才可能换。

::: note 状态 vs 模式，先分家
- **状态（state）**：ARM / Thumb——指令流宽度与译码方式；
- **模式（mode）**：usr / sys / svc / irq / fiq / abt / und——特权级与可见寄存器组。
两维独立：每种模式下都可以跑 ARM 或 Thumb 代码。考试里"状态切换影响模式吗"是经典陷阱题，答案是不影响。
:::

## 2.5.2 用 BX 切换：秘密在地址最低位

状态切换不走专用模式寄存器，而是**搭跳转指令 BX 的便车**（详见第三章 3.7）。规则只有一条：

::: def 定义 2.5.1 · BX 的状态切换规则 {#def-2.5.1}
执行 `BX Rn` 时，目标地址取 Rn 的值并将**最低位清零**；Rn 的**位 [0] 为 1 则切换到 Thumb 状态**，位 [0] 为 0 则切换到（或保持）ARM 状态。
:::

课件的原例值得逐行读懂：

```asm
; 从 ARM 状态切换到 Thumb 状态
        LDR   R0, =Label+1      ; 目标地址最低位置 1
        BX    R0                 ; 跳转并进入 Thumb 状态
; 从 Thumb 状态切换到 ARM 状态
        LDR   R0, =Label         ; 目标地址最低位为 0
        BX    R0                 ; 跳转并回到 ARM 状态
...
Label   MOV   R1, #6             ; Thumb 代码从这里开始执行
```

为什么"最低位当开关"能成立？回想 2.4：ARM 指令 4 字节对齐、Thumb 指令 2 字节对齐——合法目标地址的低位本来就恒为 0，把空闲的第 0 位挪用做状态标记，一位都不浪费。硬件跳转时自动把它清掉再当地址用。

::: think 手工用 MSR 改 CPSR 的 T 位，不就切状态了吗？
能改，但**不要这么做**：直接写 T 位而不配合正确的跳转，流水线里已取指的指令会被按另一种宽度重新解释，结果不可预测（2.8 节的告诫）。状态的合法切换通道只有 BX/BLX 这类分支指令和异常进出。
:::

## 本节小结

ARM/Thumb 是指令宽度的两种状态；异常强制 ARM 状态处理；切换靠 BX 携带的地址最低位，且不动模式与寄存器。Thumb 的完整收益账（65% 体积、15% 性能损失、切换 3 周期）见 2.3.4，指令级对比见 [3.10](../ch03/sec3-10.md)。
