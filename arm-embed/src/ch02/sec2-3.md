# 2.3 Cortex-A9 微架构

同一套 ARM 指令，ARM7 每周期最多译一条，Cortex-A9 却能同时发射多条、乱序执行还带分支预测。本节看课件选定的这颗"教学旗舰"：流水线怎么变深、多核怎么协同、存储系统怎么分层。微架构细节考得不深，但"乱序/超标量/一致性"这几个词必须能说清。（课件 Slide 27–33）

## 2.3.1 八级乱序超标量流水线

Cortex-A9 采用 **ARMv7-A 体系结构**、推测型**八级流水线**，具有**动态长度、多发射、超标量、乱序执行**特性——最多可同时发射 4 条指令。对照 2.1 节的族谱：ARM7 三级、ARM9 五级，到 A9 这里，"取指→译码→执行"的线性秩序被打破了：

- **超标量 / 多发射**：一个周期同时送多条指令进执行单元；
- **乱序执行**：指令不按程序顺序、谁的操作数就绪谁先执行（结果仍按序提交，程序员看到的顺序不变）；
- **推测执行**：遇到分支先猜方向往下跑，猜错了再回滚——配合动/静态**分支预测**降低流水线冲刷损失。

代价与收益都在"深"字上：流水线越深，单周期工作量越小、主频越高；可一旦分支预测失手，冲掉的未完成指令也越多。

## 2.3.2 MPCore：SCU 与 ACP

Cortex-A9 有单核与 **MPCore 多核**两种形态。多核不是把几个核摆在一起就完事——两个核各带 Cache，同一份数据在两块 Cache 里改了怎么办？A9 的答案是 **SCU（Snoop Control Unit，侦测控制单元）**：多核互联、总线仲裁、核间通信、Cache 间及与系统内存的传输、**缓存一致性**等管理都由它负责。课件给它的比喻是"ARM 多核技术的中央情报局"。

**ACP（Accelerator Coherency Port，加速器一致性端口）**则让外设（如 DMA、FPGA 逻辑）直接参与处理器的缓存一致性协议，省掉"外设写内存→再通知 CPU 失效 Cache"的来回，大幅降低系统开销。

::: note 单词表：coherency ≠ consistency 课程的口径
本课程按课件口径：**缓存一致性（coherency）**指多核各自的 Cache 副本对同一地址的值保持一致，硬件（SCU）自动维护；不要与操作系统的数据一致性（consistency，软件同步层面）混用。
:::

## 2.3.3 存储系统：VMSA 与多级 Cache

Cortex-A9 采用 **VMSA（Virtual Memory System Architecture，虚拟存储系统架构）**：经 MMU 支持虚拟地址→物理地址转换与存储保护。课件给出的存储层次是典型的多级 Cache 架构（L1 指令/数据 Cache 分离，经 SCU 共享 L2，再往外到主存）；对 MMU/TLB 的控制经由 **CP15 协处理器**的 C0–C15 寄存器（控制 Cache、MMU、TLB 等）。第 2.11 节会从程序员视角再看一次存储器；MMU 的页表机制本课程不深入。

## 2.3.4 四种指令集状态与 Thumb-2

A9 这一代处理器提供了 4 种**指令集状态**：ARM 状态、Thumb 状态、Jazelle 状态和 ThumbEE 状态。

| 状态 | 是什么 | 一句话命运 |
|:--|:--|:--|
| ARM | 32 位指令，性能取向 | 本课程主战场 |
| Thumb | 16 位指令，密度取向 | 以约 ARM 65% 的存储空间，换接近 ARM 的性能（约 15% 性能损失）；实时解压缩、全 32 位运算，ARM/Thumb 切换开销约 3 个时钟周期 |
| Jazelle | 硬件加速 Java 字节码 | 智能机时代的过渡方案 |
| ThumbEE | Thumb-2 的运行时扩展 | 面向 Limbo、Java、C#、Perl、Python 等动态语言的即时编译 |

注意区分"指令集状态"与 2.5 节的"操作状态"：日常真正用到的两种执行状态是 ARM 与 Thumb，Jazelle/ThumbEE 是附带的技术分支。Thumb 的完整对比留到 [3.10](../ch03/sec3-10.md)。

## 本节小结

Cortex-A9 = ARMv7 + 八级乱序超标量流水线；多核靠 SCU 管一致性，ACP 让外设直连一致性域；存储走 VMSA 多级 Cache；执行状态名义四种、实际主用 ARM 与 Thumb。这些词在第 4 章都会回来：上下文切换的开销、缓存一致性对多核 RTOS 的意义，都建立在本节的图景上。
