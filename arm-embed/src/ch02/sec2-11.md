# 2.11 存储器与存储器映射 I/O

在 ARM 眼里，存储器没有"类型"之分：从 0 号字节开始线性排到头，程序、数据、外设寄存器全都住在这条地址线上。这个朴素的设计决定了一大堆嵌入式编程习惯——访问一个 UART 数据寄存器用的指令和访问一个内存变量一模一样。本节三件事：线性空间、统一编址（MMIO）、大小端。（课件 Slide 112–127）

## 2.11.1 线性字节空间与冯·诺依曼结构

ARM（ARM7 这类经典核）采用**冯·诺依曼结构**：指令与数据共用一条 32 位总线、统一编址。存储器被视为**从 0 开始线性递增的字节集合**：

- 字节 0–3 存第 1 个字，字节 4–7 存第 2 个字……字地址恒为 4 的倍数；
- 地址 A 的**半字**占 A、A+1；地址 A 的**字**占 A–A+3（对齐规则，2.4）。

对存储器中数据的访问只有**加载、保存、交换**指令（Load/Store 结构，2.1.2）。

## 2.11.2 存储器映射 I/O（Memory-Mapped I/O）

**统一编址**：外设的控制/数据寄存器直接占据存储器地址空间的某段地址——这就是**存储器映射 I/O**。于是"读串口收到没"变成"读地址 0x???????? 的某 bit"，与读内存同一个指令、同一套寻址：

```asm
LDR   R1, =0x50000000     ; 某外设状态寄存器地址
LDR   R0, [R1]            ; 和读内存变量没有任何区别
TST   R0, #0x01           ; 测第 0 位（就绪位）
BEQ   wait                ; 未就绪就等
```

对比另一种流派（独立编址 + 专用 I/O 指令，x86 的 IN/OUT）：统一编址让访问外设复用全部寻址方式与数据宽度，代价是吃掉一段地址空间。ARM 选择了前者——这也是第三章所有 LDR/STR 例子里经常直接出现外设地址的原因。

## 2.11.3 大端与小端

一个 32 位字住进 4 个字节单元，先放谁？两种**字节序（endianness）**：

| | 规则 | 0x12345678 从低地址到高地址 |
|:--|:--|:--|
| **小端 Little-endian** | **最低位字节放最低地址**（字节 0 接数据线 7–0，低位对齐） | `78 56 34 12` |
| **大端 Big-endian** | **最高位字节放最低地址**（字节 0 接数据线 31–24，高位对齐） | `12 34 56 78` |

两个等价记忆法：小端 = "低对低"（低位字节在低地址）；小端读地址 `int8_t* p = (int8_t*)&x` 拿到的是 x 的**最低字节**。

::: ex 例 2.11.1 · 亲手排一遍（自测样板） {#ex-2.11.1}
把 0xDEADBEEF 存到地址 0x400：

| 地址 | 小端 | 大端 |
|:--|:--|:--|
| 0x400 | EF | DE |
| 0x401 | BE | AD |
| 0x402 | AD | BE |
| 0x403 | DE | EF |

写反了会怎样？按小端存的数组按大端读，0x400 那个字节读出来是 0xEF 而非 0xDE——通信协议解析、文件格式读取、芯片间数据交换，凡是两端字节序不一致的地方都会出这种错。混字节序数据的工程对策是**显式逐字节拼装**（`x = p[0] | p[1]<<8 | ...`），不依赖本机字节序。
:::

课件用 BIGEND 输入信号说明核如何选择：硬件配置决定系统按大端还是小端连接存储器（核 2.3 数据通路的 BIGEND 引脚）；软件侧则要求通信双方约定统一字节序。网络字节序通常定为大端（"big-endian on the wire"）。

::: note 课件内部的一处矛盾（勘误 #2-3）
课件 Slide 117 的示意图把小端模式画成了 0x12 在低位地址，与同章 Slide 118 的表格（小端：78 56 34 12）**自相矛盾**。本节按 Slide 118 及通用口径（小端 = 低字节在低地址）书写。详见[勘误页](errata.md)。
:::

## 本节小结

存储器是线性字节空间；冯·诺依曼统一编址使外设寄存器成为"普通地址"，LDR/STR 就是驱动外设的指令；一个字 4 字节先放谁分大小端，跨机传数据必须先对齐字节序。第二章到此收束——模式、寄存器、异常、存储器四张图拼成完整的程序员模型，第三章开始教你怎么用指令驱动它。
