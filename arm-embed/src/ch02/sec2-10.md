# 2.10 复位

复位是最优先的"异常"，也是每次上电的第一个动作。它没有返回——系统从零开始。本节两页课件，重点是分清"复位后什么是确定的"。（课件 Slide 109–110）

## 2.10.1 复位时与复位后

**nRESET 信号被拉低时**（外部复位引脚变化、芯片其它复位源都会驱动这个内核信号）：处理器放弃正在执行的指令。

**nRESET 再次变高时**，硬件执行（与 2.9 复位向量的伪操作一致）：

1. CPSR 的 M[4:0] ← `10011`（进入**管理模式 svc**）；
2. **置位 I 和 F**（IRQ、FIQ 全关）；
3. **清零 T**（ARM 状态）；
4. PC ← **0x00000000**（未配置高向量时；配置了则 0xFFFF0000），从那里取第一条指令。

对应伪操作（课件原文口径）：

```asm
R14_svc   = UNPREDICTABLE      ; 复位不返回，LR 无意义
SPSR_svc  = UNPREDICTABLE
CPSR[4:0] = 0b10011            ; svc 模式
CPSR[5]   = 0                  ; ARM 状态（清 T）
CPSR[6]   = 1                  ; 禁 FIQ
CPSR[7]   = 1                  ; 禁 IRQ
PC        = 0x00000000         ; 或高向量 0xFFFF0000
```

## 2.10.2 复位后：确定与不确定

**确定的**只有 PC 和 CPSR（如上五项）。**除这两个寄存器外，所有寄存器的值都不确定**——R0–R12 里是上一世的随机数据，各模式的栈指针也没有魔法初值。

由此得出启动代码（bootloader / 启动段）的必做清单：

- 为**每个将要用到的模式**分别初始化 R13（每种模式自己的栈，2.7.3）；
- 需要开中断时再按受控顺序清 I/F（先装好向量表、初始化外设）；
- 然后才轮得到跳进 C 的 `main`。

::: think 为什么复位进的是 svc 而不是 usr？
启动阶段全是特权活：设栈、映射存储器、写中断控制器。svc 给操作系统保护模式（2.6 表），启动代码正是"操作系统的人格开端"。等初始化完毕要放用户程序出场时，才主动降到 usr。
:::

## 本节小结

复位 = 强制 svc + 关中断 + ARM 状态 + PC 清零；除此之外一切不确定，初始化是软件的责任。这条"确定/不确定"分界线直接决定了每个裸机工程的头几十行代码在干什么。下一节把视角从寄存器挪开，看存储器这个大仓库。
