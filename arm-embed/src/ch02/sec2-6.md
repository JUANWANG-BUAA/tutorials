# 2.6 处理器模式：特权与异常的分层

同样是"改 CPSR"，用户态的程序做不到，系统态的操作系统随手就能做。谁被允许做什么，由当前**处理器模式**决定。七种模式、两层分类（特权/非特权、异常/非异常）——本节这张分类表是 2.7 寄存器分组和 2.9 异常流程的总纲，必须闭卷默写。（课件 Slide 41–44）

## 2.6.1 七种模式一览

| 模式 | 缩写 | 用途 | 进入方式 |
|:--|:--|:--|:--|
| 用户 | usr | 正常程序执行 | 程序正常运行所在 |
| 系统 | sys | 运行操作系统的特权任务 | 特权代码主动切换 |
| 快中断 | fiq | 高速数据传输及通道处理 | FIQ 异常响应 |
| 中断 | irq | 通用中断处理 | IRQ 异常响应 |
| 管理 | svc | 操作系统保护模式 | **系统复位**与 SWI（软件中断） |
| 中止 | abt | 支持虚拟内存 / 存储器保护 | 取指中止、数据中止 |
| 未定义 | und | 支持硬件协处理器的软件仿真 | 未定义指令异常 |

课件的一条背景注：abt"在 ARM 没大用处"是老版课件口径（无 MMU 的裸机系统里确实少见），带 MMU 的系统（如 Linux）里缺页处理全靠它。考试以表口径为准。

## 2.6.2 第一层分类：特权 vs 非特权

**除 usr 外的六种模式都是特权模式。**特权模式可以自由切换处理器模式、访问受限制的寄存器与片内资源；用户模式不能直接切换到其它模式。

usr 与 sys 构成一对有趣的对照：**两者使用完全相同的寄存器组**，都不能由异常进入——区别只在特权。sys 的存在让操作系统既能用 usr 的寄存器视角（方便访问用户数据），又保留特权（随时可以切换出去）。

## 2.6.3 第二层分类：异常模式 vs 非异常模式

五种模式——**fiq、irq、svc、abt、und**——称为**异常模式**：除了可由程序切换进入，还会在**特定异常发生时**被硬件强制进入；每种异常模式带一组自己的分组寄存器（R13/R14 专属副本等），保证异常退出时用户模式的状态仍然可靠（2.7 展开）。

分层图把七种模式放进一张图：

```
            ┌─ 非特权 ── usr ──────────── 不能切模式、不响应异常进入
处理器模式 ─┤
            └─ 特权 ──┬─ 非异常模式 ─ sys ─ 与 usr 同寄存器组
                      └─ 异常模式 ─┬─ fiq（快中断）
                                   ├─ irq（中断）
                                   ├─ svc（复位、SWI）
                                   ├─ abt（中止）
                                   └─ und（未定义指令）
```

::: think 用户模式"不能直接切换"，那用户程序怎么调用操作系统？
靠"制造异常"：执行 SWI 指令主动触发软件中断，硬件强制进入 svc 模式（§2.9、§3.8）。这正是系统调用的底层形态——用户态永远不能自提特权，只能请求已授权的特权入口替它做事。
:::

::: note 为什么 FIQ 要单列一种模式，而 x86 只有一套中断处理？
FIQ 的"快"是全链路的：向量放在向量表末尾（0x1C，可直接放处理代码省一次跳转）、自带 R8–R14 分组副本（不用保存现场，§2.7）、CPSR 的 F 位可单独屏蔽。这套设计让 FIQ 从响应到开始干活几乎零保存开销——嵌入式实时性的典型思路：能用硬件分组解决的，不用软件压栈解决。
:::

## 本节小结

七种模式按两层分类：非特权仅 usr；特权中的五种异常模式由异常进入并带专属寄存器，sys 与 usr 同组但不由异常进入。模式决定了下一节"你能看到哪 37 个寄存器中的哪些"。
