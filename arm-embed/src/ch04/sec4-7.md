# 4.7 进程、线程与任务模型

嵌入式系统里"进程""线程""任务"三个词经常混着讲，但它们在课程里有明确分工。本节先把三个概念分层，再讲任务的状态机、前后台系统、内核的职责、临界区与共享资源——这一节的概念是 4.8 调度与 4.10 同步的对象。（课件 Slide 127–130、143–148）

## 4.7.1 三个概念：进程、线程、任务

课件 Slide 127 的定义：

| 概念 | 定义（课件口径） |
|:--|:--|
| **进程（Process）** | **内存保护的单元**。一个进程不能访问其他进程的内存空间。一个进程有一个或多个线程 |
| **线程（Thread）** | **执行的单元**。同一个进程的线程**共享地址空间**。**调度程序（scheduler）负责对线程（而不是进程）进行调度** |
| **任务（Task）** | 在嵌入式系统中，**线程又称为任务**。实时应用程序的设计过程包括如何把问题分割成多个任务，每个任务都是整个应用的某一部分；**每个任务被赋予一定的优先级，有它自己的一套 CPU 寄存器和自己的栈空间** |

三个要点串起来看：

1. **调度的是线程，不是进程**——多线程进程里的线程轮流用 CPU，但共享一份地址空间；
2. **嵌入式里"任务"= 线程**（VxWorks 里没有独立虚拟内存空间，可以把"任务"理解为"线程"，见 4.8.4）；
3. **任务有自己的寄存器与栈**——这条直接来自第二章：ARM 的分组寄存器（R13_sp、R14）与任务栈是任务上下文的硬件载体（4.8.2）。

## 4.7.2 任务的状态机

课件 Slide 129 给出线程的三种基本状态：

| 状态 | 含义 | 迁出条件 |
|:--|:--|:--|
| **执行状态（Running）** | 正在占用 CPU | 时间片用完 / 被抢占 |
| **就绪状态（Ready）** | 具备运行条件，等待 CPU | **被选中** → 执行状态 |
| **阻塞状态（Blocked）** | 又称等待状态、睡眠状态 | 等待需要的资源 → 获得所需资源 → 就绪 |

迁移关系：

```
        ┌──────────┐   被选中    ┌──────────┐
        │  就绪     │ ─────────► │  执行     │
        │ (Ready)  │ ◄───────── │ (Running) │
        └──────────┘  时间片用完  └──────────┘
             ▲  ▲                   │
             │  │                   │ 等待资源
        获得资源│  └───────────────────▼
             │                      ┌──────────┐
             └──────────────────────│  阻塞     │
                获得所需资源          │ (Blocked) │
                                    └──────────┘
```

课件图中的标注：**"选中"**（就绪→执行）、**"时间片用完"**（执行→就绪）、**"等待需要的资源"**（执行→阻塞）、**"获得所需资源"**（阻塞→就绪）。

记住两条路径的不对称：**就绪→执行是内核调度决定的；执行→阻塞是任务自己决定的**（申请资源失败、等待消息、延时到期）。这也是 4.10 里"阻塞式"与"非阻塞式"API 的分水岭。

## 4.7.3 前后台系统：没有 RTOS 的嵌入式

对基于芯片的开发来说，应用程序一般是一个**无限的循环**，可称为**前后台系统**或**超循环系统**。很多基于微处理器的嵌入式系统采用前后台系统设计，例如**微波炉、电话机、玩具**等。

结构（课件 Slide 143–144）：

```
┌────────────────────────────────────────────┐
│  中断服务程序 ISR   ← 前台（中断级/事件处理级） │
│  时间相关很强的关键操作一定靠 ISR 保证        │
├────────────────────────────────────────────┤
│  后台主循环        ← 后台（任务级/系统管理调度） │
│  循环中调用相应函数完成操作；                  │
│  掌管整个系统的软硬件资源分配、管理与任务调度   │
└────────────────────────────────────────────┘
```

| | 前台（中断服务程序） | 后台（主循环） |
|:--|:--|:--|
| 别称 | 中断级、事件处理级程序 | 任务级、系统管理调度程序 |
| 职责 | 处理**异步事件**；时间相关性很强的关键操作 | 循环调用函数完成操作；分配管理软硬件资源与调度 |
| 调度 | **抢占**后台（中断一来后台停下） | **各任务优先级相同**，只能靠顺序轮转 |

课件对后台的批评一针见血：**"由于各任务优先级相同，这种系统在处理的及时性上比实际可以做到的要差"**——关键任务必须等当前主循环轮回来。

另外一种极端（课件 Slide 143 末）：**在另外一些嵌入式系统中，为降低能耗，平时系统处在停机状态，所有工作都靠中断服务来完成**。

::: think 前后台系统与 RTOS 的取舍
前后台系统的优点是**极简**：没有任务栈、没有调度器、没有优先级——适合十几行代码的简单产品。缺点在 4.1.5 说过：安全关键系统要求"时间确定性"，而前后台系统的响应时间取决于主循环有多长，**不随负载变化**。当"关键任务必须立刻响应"这条要求出现，RTOS 才成为必需品。
:::

## 4.7.4 内核：多任务系统的大脑

课件 Slide 147 的定义：

- 多任务系统中，**内核负责管理各个任务**，或者说**为每个任务分配 CPU 时间**，并负责任务之间的通信；
- 内核提供的**基本服务是任务切换**；
- 使用实时内核可以大大简化应用系统的设计——**允许将应用分成若干个任务，由实时内核对它们进行管理**；
- 内核需要消耗一定的系统资源，比如 **2%～5% 的 CPU 运行时间**、RAM 和 ROM 等；
- 内核提供必不可少的系统服务，如**信号量、消息队列、定时**等。

::: note 内核的代价（4.5.6 也提过）
课件在 4.5.6 的"使用嵌入式操作系统的优缺点"里给出：**优点**是设计扩展容易、开发效率高，充分发挥 32 位 CPU 的多任务潜力、实时性与健壮性更有保证；**缺点**是增加 ROM/RAM 开销、带来 **5%～10% 的 CPU 额外负荷**。两处数字（2%～5% vs 5%～10%）口径略有差异，**记"个位数百分比"这个量级即可**。
:::

## 4.7.5 中断：异步事件的入口

课件 Slide 148 的机制描述：

> **中断**是一种重要机制，用于通知 CPU 有异步事件发生。中断一旦被识别和响应，**CPU 保存部分（或全部）上下文**（部分或全部寄存器的值），跳转到**中断服务程序（ISR）** 执行。中断服务程序做事件处理，处理完成后，程序返回：
> - 在**前后台系统**中，程序回到**后台程序**；
> - 对**非占先式内核**而言，程序回到**被中断的任务**；
> - 对**占先式内核**而言，让**进入就绪态的优先级最高的任务**开始执行。

这段话把第二章（硬件保存上下文）与 4.8（软件层的调度决策）连起来了：**硬件只负责"跳过去"，"跳回去后跑谁"是内核的软件策略**。

## 4.7.6 临界区与共享资源

**共享资源**（课件 Slide 146）：程序运行时可使用的软硬件环境统称为资源；**可以被一个以上任务使用的资源叫共享资源**。为了防止数据被破坏，每个任务在与共享资源打交道时必须**独占**该资源——这就是**互斥**。

**临界区**（课件 Slide 145）：代码的临界区指**处理时不可分割的代码，运行这些代码不允许被打断**；一旦这部分代码开始执行，则不允许任何中断打扰。课件给了一个精确的例外：**如果中断不调用任何包含临界区的代码，也不访问任何临界区使用的共享资源，这个中断可能可以执行**。

**保证临界区执行的流程**：进入临界区之前**关中断**，临界区代码执行完成后**立即开中断**。

::: ex 例 4.7.1 · 用指令实现临界区 {#ex-4.7.1}
回到第三章的 MRS/MSR（3.8.5）：

```asm
        MRS   R0, CPSR         ; 1. 备份当前 CPSR（含 I 位）
        BIC   R0, R0, #0x80    ; 2. 清 I 位：禁止 IRQ
        MSR   CPSR_c, R0       ; 3. 写回控制域

        ; ---- 临界区开始：读写共享结构 ----
        LDR   R1, [R2]
        STR   R1, [R3]
        ; ---- 临界区结束 ----

        MSR   CPSR_c, R0       ; 4. 恢复原 CPSR（重新开 IRQ）
```

注意第 4 步用**备份的 R0**恢复，而不是重新置位——这样即使进入临界区前 IRQ 本来就是关的，退出后状态也正确。
:::

**实现互斥的三种常见手段**（课件 Slide 139，后文 4.10 详述）：

1. **开/关中断**；
2. **禁止任务切换**；
3. **信号量（semaphore）机制**。

## 本节小结

进程 = 内存保护单元，线程 = 执行单元（调度对象），嵌入式里线程即任务（有自己的寄存器与栈）；任务三态机（运行/就绪/阻塞）中"就绪→执行"由内核决定、"执行→阻塞"由任务自己决定；前后台系统无优先级、响应时间不随负载确定；内核的本质是任务切换器，代价是 2%～5% 的 CPU 与额外内存；临界区靠关中断保证，共享资源靠互斥保护。下一节讲内核最核心的能力：调度。
