# 4.8 任务调度：非抢占、抢占与上下文切换

"调度"是把 CPU 时间分给各个任务的规则。两条分界线：**谁来决定切换**（非抢占 vs 抢占）、**同优先级怎么分**（时间片轮转）。本节讲清这两种内核的行为差异与上下文切换的代价。（课件 Slide 131、134–137、174–179）

## 4.8.1 两种进程调度方式

课件 Slide 176 的定义：

**① 非抢占方式（Non-Preemptive）**：一旦把处理机分配给某进程后，便让该进程**一直执行**，直到该进程完成或发生某事件而被阻塞，才再把处理机分配给其他进程，**决不允许某进程抢占已经分配出去的处理机**。

课件评价：**显然它难于满足紧急任务的要求，实时系统中不宜采用这种调度方式。**

**② 抢占方式（Preemptive）**：允许调度程序根据某种原则，**停止某个正在执行的进程**，将已分配给该进程的处理机重新分配给另一进程。抢占的原则包括：

- **时间片原则**：各进程按时间片运行，时间片用完后停止该进程的执行而重新进行调度；
- **优先级原则**（4.8.3）。

## 4.8.2 非抢占式（协作式）内核：中断只能"唤醒"，不能"夺权"

课件 Slide 134 的要点：

- **非占先式内核要求每个任务自我放弃 CPU 的所有权**；非抢占式调度也称作**合作型多任务**，各个任务彼此合作共享一个 CPU；
- **异步事件还是由中断服务来处理**：中断服务可以使一个高优先级任务由**挂起状态变为就绪状态**，但**中断服务以后控制权还是回到原来被中断的那个任务**，直到该任务**主动放弃** CPU 的使用权时，高优先级任务才能获得 CPU 的使用权。

课件 Slide 135 的时间轴图（低优先级任务 + ISR + 高优先级任务，7 个时刻）说明了这个过程：

{{#include ../assets/figures/arm-scheduling.md}}

```
低优先级任务 ────► ISR ────┐
                            │ 中断服务程序使高优先级任务就绪
高优先级任务（就绪，等）      │ 低优先级任务释放 CPU 使用权
                            └──► 高优先级任务开始运行
```

关键在于**第 6→7 步**：高优先级任务在第 1 步就已经就绪了，但要等到低优先级任务主动让出 CPU 才跑得上——**这次延迟不可预测**，正是 4.12 实时性指标要管的东西。

## 4.8.3 抢占式内核：高优先级一旦就绪就接管 CPU

课件 Slide 136：

- **最高优先级的任务一旦就绪，即能得到 CPU 的控制权**；
- 一旦有优先级更高的任务进入就绪状态，**当前任务的 CPU 使用权即被剥夺（被挂起）**，高优先级的任务立刻得到 CPU 的控制权；
- 如果是中断服务子程序使一个高优先级任务进入就绪态，**中断完成时，被中断了的任务被挂起**，优先级高的那个任务开始运行；
- **当系统响应时间有严格要求时，要使用抢占式内核**；
- **绝大多数商用嵌入式实时内核都是抢占式内核**。

课件 Slide 137 的时间轴图与 4.8.2 对比：只有 **6 个时刻**——中断服务程序使高优先级任务就绪后，**高优先级任务即刻得到 CPU 使用权**，不必等低优先级任务"主动配合"。

::: ex 例 4.8.1 · 同一场景，两种内核的差别 {#ex-4.8.1}
场景：低优先级任务 L 正在跑一个长循环；此时 UART 收到数据，ISR 触发一个高优先级任务 H 的就绪。

| | 非抢占式 | 抢占式 |
|:--|:--|:--|
| ISR 结束后的执行者 | 回到 **L** | 切到 **H** |
| H 何时运行 | L 主动调用阻塞/让出 API 时 | **立即**（在 ISR 退出时的那次调度点） |
| L 的长循环 | 不可被打断 | 可被 H 抢占 |
| 响应时间 | 由 L 的让出时机决定，**不确定** | 由优先级与调度开销决定，**有界** |
:::

## 4.8.4 上下文切换：把 CPU 寄存器搬到栈上

课件 Slide 130 的定义（关键机制）：

> **上下文切换（context switching）**：当多任务内核决定运行另外的任务时，它**保存正在运行任务的当前状态，即 CPU 寄存器中的全部内容**；这些内容保存在任务的**当前状态保存区，也就是任务自己的栈区**之中。入栈工作完成以后，就**把下一个将要运行的任务的当前状态从任务的栈中重新装入 CPU 的寄存器**，并开始下一个任务的运行。

**代价**（课件原话）：该过程增加了应用程序的额外开销；**CPU 的内部寄存器越多，额外开销就越大**；做任务切换所需要的时间取决于 **CPU 有多少寄存器要入栈**。

::: think 这一节和第二章的对接
"context switch = 保存 CPU 全部寄存器内容到任务自己的栈"——在 ARM 上就是**第二章的分组寄存器压栈/出栈**：

```asm
; 保存当前任务上下文（R0-R3 是调用者保存，其余 callee-saved 由被调方保存）
        STMFD SP!, {R4-R11, LR}     ; 3.4.3 满递减栈
; ... 切到新任务，取出它的上下文 ...
        LDMFD SP!, {R4-R11, PC}^    ; 3.4.5 ^ 同时恢复 CPSR
```

**CPU 寄存器越多、切换越贵**这条规律在 ARM 上尤其明显：37 个寄存器（2.7.1），其中任务上下文相关的那部分每次切换都要进出栈。**这就是嵌入式 RTOS 刻意减少任务数、精简上下文的动机**——切换开销直接吃掉实时预算。
:::

## 4.8.5 调度与时间片

**时间片（time slice）**：任务由系统内核调度运行**一段固定长度的时间**。

**调度（scheduling）**：为任务分配资源和时间，使系统满足特定的性能要求。

**调度算法的目的**（课件 Slide 175）：在正常情况下尽可能满足所有任务的时限；**在峰值负载条件下，保证强实时任务满足时限**。因为**时限是区分实时系统和非实时系统的关键因素**，所以调度算法是实时系统的基本问题。

课件还点明：实时操作系统所具有的运行性能——**吞吐量的大小、周转时间的长短、响应的及时性和可预测性**——在很大程度上都取决于实时调度。

## 4.8.6 VxWorks 的调度策略（工业级样板）

课件 Slide 174–179 给出 VxWorks 的做法，是理解调度策略的标准样本：

**任务状态有四种**（比 4.7.2 的三态更细）：

| 状态 | 含义 |
|:--|:--|
| **就绪态（Ready）** | 任务只等待系统分配 CPU 资源 |
| **挂起态（Pend）** | 任务需等待某些不可利用的资源而被阻塞 |
| **休眠态（Sleep）** | 如果系统不需要某一个任务工作，则该任务处于休眠状态 |
| **延迟态（Delay）** | 任务被延迟时所处的状态 |

课件注明：**在 VxWorks 中，因为每个任务没有自己独立的虚拟内存空间，可以把"任务"理解为"线程"**（呼应 4.7.1）。

**Wind 内核缺省调度机制：基于优先级的抢占式调度**（Slide 177）：

- 系统把处理机分配给**优先级最高的进程**；
- 一旦出现另一个优先级更高的进程，调度程序**剥夺当前任务的执行**，把处理机分配给高优先级任务；
- **相同优先级的多个任务之间，采用时间片轮转调度机制**（到轮转队列后面等自己的时间片，时间片内没结束就再等下一个）。

**具体机制**（Slide 178）：

- **优先级抢占式**：每个任务优先级介于最高 0 到最低 255 之间；**任一时刻，内核一旦发现一个优先级更高的任务转变为就绪态，内核就保存当前任务的上下文并把当前任务状态转换为阻塞态，同时切换到这个高优先级任务的上下文执行**；
- **轮转调度**：处于就绪态的**优先级相同**的一组任务依次轮流执行预先确定长度的时间片；若不使用轮转，同优先级中第一个获得处理机的任务将独占处理机（除非阻塞或主动放弃）。

**混合方式与动态优先级**（Slide 179）：

- 优先级抢占式可与轮转相结合：同优先级组轮流平均分配处理机时，若有高优先级任务转为就绪态则可**抢占该组任务**，直到再次符合执行条件，该组才重新共享处理机；
- VxWorks 提供**动态优先级机制**（任务优先级在运行期间可动态变化）；
- 为防止**优先级反转**，还具有**优先级继承机制**——通过使用互斥信号量，防止高优先级任务被迫等待一段不确定时间，直到低优先级任务完成（4.10 会展开这个机制）。

## 本节小结

非抢占（协作式）内核里，中断只能让高优先级任务**就绪**，CPU 仍归原任务，直到它主动让出——响应时间不确定，实时系统不宜采用；抢占式内核里高优先级任务一旦就绪立刻接管 CPU，是绝大多数商用嵌入式实时内核的选择。上下文切换 = 把 CPU 全部寄存器压入当前任务栈、再从新任务栈装载，**寄存器越多越贵**。VxWorks 的样板是"优先级抢占 + 同优先级轮转 + 动态优先级 + 优先级继承"。下一节把"谁先跑"从工程惯例变成可证明的算法。
