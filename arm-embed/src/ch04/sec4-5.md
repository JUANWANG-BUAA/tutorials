## 4.5.2 嵌入式 Linux 与 μC Linux

**嵌入式 Linux**（课件口径）：对 Linux 经过小型化裁剪后，能固化在容量只有几百 KB 或几 MB 的存储器芯片或单片机中，应用于特定嵌入式场合的专用 Linux 操作系统。

其优势（课件原话）：内核小、功能强大、API 丰富，系统健壮、效率高，易于定制剪裁，**在价格上极具竞争力**；不仅支持 x86，还支持其它数十种 CPU 芯片。

产业数据（课件）：13% 的用户已开始用嵌入式 Linux 开发；52% 的用户决定在未来 24 个月内用 Linux 作为嵌入式 OS 开发原型。

**μC Linux** 的定位（课件 Slide 33）：

- 完全符合 **GNU/GPL**，完全开放代码；
- 从 **Linux 2.0/2.4 内核**派生而来，沿袭主流 Linux 绝大部分特性；
- **专门针对没有 MMU 的 CPU**，为嵌入式系统做了许多小型化工作；适用于没有虚拟内存或 MMU 的处理器，**例如 ARM7TDMI**；
- 通常用于**很少内存或 Flash** 的嵌入式系统；
- 保留 Linux 的大部分优点：稳定、良好移植性、优秀网络功能、完备的文件系统支持、丰富的标准 API。

::: note μC Linux 与 2.9 节的联系
第二章讲过 A9 采用 **VMSA 虚拟存储体系结构**（有 MMU）。**有 MMU 的 Cortex-A 可以跑标准嵌入式 Linux**；**无 MMU 的 Cortex-M / ARM7 只能跑 μC Linux 这类"去内存管理"的版本**。这是"裁剪"二字最实际的一次落地。
:::

## 4.5.3 VxWorks、QNX、μC/OS

**VxWorks**（Wind River，1983 年）：嵌入式 RTOS，具有良好的持续发展能力、高性能内核与友好的开发环境。显著特点是**可靠性、实时性和可裁剪性**；支持多种处理器（x86、i960、Sun Sparc、Motorola MC68xxx、MIPS、PowerPC 等）。以良好的可靠性和卓越的实时性广泛应用于**通信、军事、航空航天**等高精尖技术领域——课件举例：**火星探测器（1997 年 7 月 4 日登陆火星表面）**。

**QNX**（加拿大）：在 **x86 体系**上开发出来（这和别的 RTOS 不一样——好多 RTOS 是从 68K 上开发成熟再移植到 x86）。实时、可扩充，部分遵循 POSIX 相关标准；有强大的图形界面功能，适合机顶盒、手持设备、GPS 设备（黑莓智能手机即用 QNX）。

**μC/OS、μC/OS-II、μC/OS-III**（Jean Labrosse，1992 年完成）：

- 应用覆盖照相机、医疗器械、音响设备、发动机控制、高速公路电话系统、自动提款机等，**已应用于数百种产品**；
- 1998 年 μC/OS-II（课件版本 V2.72）；**2000 年得到美国航空管理局（FAA）认证，可用于飞行器**；最新 v3.08.02（2022 年 12 月）；
- **源码公开、可移植、可裁剪、占用资源少、抢先式的实时多任务操作系统**；绝大部分源码用 ANSI C 写，移植性好；高校教学可免费使用。

μC/OS 的四个特性（课件逐条展开）：

| 特性 | 说明 |
|:--|:--|
| **公开源代码** | —— |
| **可移植性（Portable）** | 绝大部分源码用可移植性强的 ANSI C 写；与硬件相关的部分用汇编写，且**已压到最低限度**；可在 8/16/32 甚至 64 位 MCU、DSP 上运行 |
| **可固化（ROMable）** | 为嵌入式应用设计，只要有固化手段（编译、连接、下载、固化）即可嵌入产品 |
| **可裁剪（Scalable）** | 只使用应用程序需要的那些系统服务，靠**条件编译**实现，节省 RAM 与 ROM |

性能特点：**抢占式（Preemptive）**；可管理 **64 个任务**（当前版本保留 8 个给系统，应用程序最多 56 个）；**可确定性**——全部函数调用与服务执行时间具有确定性。

## 4.5.4 RTEMS：开源里的性能标杆

**RTEMS（Real-Time Executive for Multiprocessor Systems）**：最早用于美国国防系统，早期名称是"实时导弹系统（Real Time Executive for Missile Systems）"，后改名"实时军用系统（Real Time Executive for Military Systems）"。1993 年开始开发，1999 年开放源代码，由 OAR 公司维护升级。开源优势 + 可与最优秀的商业 RTOS 相当的性能。

**体系结构上，RTEMS 是微内核抢占式的实时系统**（课件列出的优点）：

- 优秀的实时性能：支持硬实时与软实时（可抢占内核）、**支持优先级继承防止优先级反转**、支持单调周期调度、支持优先级调度；
- 非常稳定、运行速度快。

**高度可裁剪内核**：目标系统小到只有 **30KB**，大可上百兆。最小内核只包含 BSP、任务调度、内存模块；其大小与 CPU 指令集、外设多少、二进制代码格式相关。CPU 为 ARM7 时，ELF 格式的标准 ARM 目标可减到 **46KB**；只保留最主要功能时，未压缩目标可控制在 **60KB**（内核 + BSP + 简单应用）——课件对比说"这比起 Linux 2.4 压缩后还有 700K 的庞大体积来说，更适合成本体积敏感的应用"。Tiny RTEMS 项目中未压缩最小镜像（内核 + BSP）只有 **20KB**（该项目把 RTEMS id 变成 16 位，并把 BSD TCP/IP 换成 lwIP）。

其他能力：支持 ARM、MIPS、PowerPC、SPARC、i386、DSP、AVR、Zilog 等多种 CPU 的 BSP；提供 **POSIX API**（Linux/UNIX 程序便于移植）、完整 BSD TCP/IP 协议栈；支持 ISO/ANSI C 库与 C++ 库/STL、可重入 glibc；支持图形界面（Microwindows/Nano-X）、文件系统（FAT、IMFS）、多种调试（GDB、DDD、串口、以太网）；**支持多处理器结构（同构与异构，如 ARM+DSP）**；支持优先级天花板协议 **PCP（Priority Ceiling Protocols）**与优先级继承。

**性能对比**（课件 Slide 73–75，测试平台 PowerPC 604 300MHz，产生 200 万次中断、中断平均频率 4kHz）：

| 系统 | 中断时延 最大/平均（μs） | Context 转换 最大/平均（μs） | | 中断时延 最大/平均 | Context 转换 最大/平均 |
|:--|:--|:--|:--|:--|:--|
| | **中等负载** | | | **重负载** | |
| RtLinux | 13.5 / 1.7 | 33.1 / 8.7 | | **196.8** / 2.1 | 193.9 / 11.2 |
| RTEMS | 15.1 / 1.3 | 16.4 / 2.2 | | 20.5 / 2.9 | 51.3 / 3.7 |
| RTEMS1 | 14.9 / 1.3 | 16.9 / 2.3 | | 19.2 / 2.4 | 213 / 10.4 |
| VxWorks | 13.1 / 2.0 | 19.0 / 3.1 | | 25.2 / 2.9 | 38.8 / 9.5 |

（RTEMS1 = 使用 Pthread 库版本）

课件的解读：**RtLinux 无论实时性还是线程任务迁移都远不能满足要求**——重负载下中断处理时延波动极厉害，平均 2.1 μs 但实际可能 200 μs，这在时间要求严格的系统中不可允许；**RTEMS 表现非常理想，基本达到或超过老牌商业系统 VxWorks**。值得一提：RTEMS 用了 Pthread 库后性能有所下降，但最差情况也不会比 RtLinux 差。

## 4.5.5 TinyOS：传感器网络的另一种答案

课件 Slide 60–63 给出 TinyOS 的设计（美国伯克利，**面向无线传感器网络**）：

- **Tasks And Events 并发模型**：tasks 用于时间要求不高的应用，tasks 之间**平等的**，执行时按先后顺序、**不能互相占先**，为减少运行时间要求每个 task 都很短小；**events** 用于时间要求严格的应用，**可以占先**于 tasks 和其它 events 执行，由操作完成或外部环境事件触发，一般由硬件中断处理驱动；
- **Split-Phase Operations**：因为 tasks 之间不能互相占先，TinyOS **没有提供任何阻塞操作**；为让耗时操作尽快完成，把"对这个操作的需求"和"这个操作的完成"分开实现；
- **其它特点**：支持传感器网络的自配置；**消息是定长的**；只有两种中断——**时钟与射频**；**单共享栈**；**没有内核、进程管理、虚拟内存**；与硬件完全集成。

TinyOS 的"没有阻塞、没有内核"是反直觉但自洽的：无线传感器节点能量以毫瓦计，多一个内核就多一份常驻开销，于是把并发交给编译期（nesC）与事件驱动。

## 4.5.7 车载与物联网：两个新战场

课件把"车载操作系统"与"物联网操作系统"单列，理由是它们的约束与传统 RTOS 不同：

**车载操作系统**（Slide 25）：分两类——**座舱系统**（智能座舱）与**自动驾驶/车控系统**。主流方案四条：

1. **QNX 嵌入式微内核系统**（理想、蔚来）；
2. **Linux**（特斯拉 FSD v12、比亚迪）或 **ROS**；
3. **华为的车载鸿蒙操作系统（AOS）**；
4. **PikeOS** 等。

课件还给出一条产业判断：**汽车电子系统的价值已超过汽车价值的 60%**；一辆普通新车大约有 **1 亿行代码**；汽车行业开发周期长达数年，而消费电子以月计算——思科、谷歌、苹果因此进入汽车领域。

**物联网操作系统**（Slide 26–30）的四个特点：**内核尺寸伸缩性与整体架构可扩展性**、**内核的实时性**、**高可靠性**、**低功耗**；"连接、区别、识别、沟通、操作"五大问题贯穿始终。Linux 仍是物联网主要操作系统：资源受限设备中占 44.1%，物联网网关上占 66.9%；发行版中 Raspbian（45.5%）与 Ubuntu（44%）居前两位。

## 本节小结

分类靠两个维度：**收费**（商用/免费）与**实时性**（硬/软/无）；代表产品按生态认：商业硬实时 VxWorks、开源硬实时 RTEMS/seL4/μC-OS、无实时 Linux 与 ROS、传感器专用 TinyOS、车载 QNX/Linux/鸿蒙/PikeOS、物联网 Linux 占主流。RTEMS 的对比数据说明"开源 ≠ 不实时"。下一节看国产与国产化——这是本章的国内产业重点。
