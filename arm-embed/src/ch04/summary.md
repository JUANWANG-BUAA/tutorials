# 第四章总结

本章讲"多个程序共用一个核"。前半是坐标系（4.1–4.6：为什么嵌入式世界另有一套 OS），后半是机制（4.7–4.13：任务、调度、通信、中断、实时性）。考前把下面五张表过一遍。

## 表一：任务三态与迁移

| 状态 | 迁出条件 | 谁决定 |
|:--|:--|:--|
| 就绪 Ready | **被选中** → 执行 | **内核** |
| 执行 Running | 时间片用完 → 就绪；等待资源 → 阻塞 | 内核 / 任务自身 |
| 阻塞 Blocked | 获得资源 → 就绪 | 任务自身 |

（4.7.2）

## 表二：两种内核

| | 非抢占（协作式） | 抢占式 |
|:--|:--|:--|
| 中断让高优先级任务就绪后 | CPU **仍归原任务**，等它主动让出 | **立刻**切给高优先级任务 |
| 响应时间 | **不确定** | 有界 |
| 实时系统适用性 | 课件：**不宜采用** | 绝大多数商用嵌入式 RTOS |
| 上下文切换 | 同样要保存 CPU 全部寄存器到任务栈（寄存器越多越贵） | 同左 |

（4.8）

## 表三：三种实时调度算法

| | RMS | EDF | LLF |
|:--|:--|:--|:--|
| 类型 | 静态 | 动态 | 动态 |
| 优先级依据 | **周期**（短者高） | **截止期**（早者高） | **空闲时间**（小者高） |
| 空闲时间定义 | —— | —— | 截止期 − 剩余执行时间 |
| 最优性 | 静态最优 | 单处理器最优（利用率可达 100%） | 可调度条件同 EDF |
| 开销 | 小 | 大 | 大 |

（4.9）

## 表四：通信与同步

| 要解决 | 手段 |
|:--|:--|
| 数据传递 | **共享内存**（快、须自己保证互斥）／**消息传递**（邮箱存 1 条、队列存多条） |
| 互斥 | 二进制信号量／互斥量（**有所有权**）／关中断／禁止任务切换 |
| 事件通知 | 计数器型信号量、事件标志、邮箱 |
| 行为同步 | 信号量 |
| 死锁防范 | **统一资源申请顺序**（先全拿齐、用同样顺序申请、逆序释放） |
| 优先级反转防范 | **优先级继承**（前提：互斥量有所有权） |
| 中断安全 | 被调用函数必须**可重入**（只用局部变量） |

（4.10）

## 表五：三个时延指标与实时性判据

| 指标 | 从哪到哪 | 主要影响因素 |
|:--|:--|:--|
| **中断时延** | nIRQ 拉低 → 开始执行 ISR | 中断屏蔽时长、嵌套支持、流水线、临界区长度 |
| **调度时延** | ISR 执行完 → 目标任务开始跑 | 调度算法、抢占能力 |
| **上下文切换时延** | 保存旧任务 + 装载新任务 | **CPU 寄存器数量**、是否用 MMU（用 MMU 更慢） |

实时性三条判据：**时间确定性**（任何状态下执行时间有上界）、**故障处理确定性**（故障范围可预见）、**可验证性**（可审查、可证明）。硬实时 = 错过即灾难、微秒级精度；软实时 = 只是品质下降、毫秒级。

（4.11–4.12）

## 三个一秒判断

1. 抢占式内核里，ISR 让高优先级任务就绪后，**中断结束时直接切给它**——不用等原任务配合。
2. 上下文切换贵在**寄存器数量**，不是算法——37 个寄存器的 ARM 每次切换都要搬一堆。
3. 实时 ≠ 快：99 次 50 ms、1 次 250 ms，指标按**最坏那次**算。

## 衔接

第四章的每个机制都在前两章有硬件落点：**上下文切换** = 分组寄存器压栈/出栈（2.7、3.4）；**临界区** = MRS/MSR 开关中断（3.8）；**系统调用与事件通知** = SWI（3.8）；**驱动访问外设** = LDR/STR 访 MMIO（2.11、3.3）。反过来，第二、三章的每个"硬件动作"在第四章都有"为什么需要它"的答案。
