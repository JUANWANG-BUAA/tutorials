# 习题集

第四章习题按节分组。**调度题必须画时间轴，计算题必须写出参数表**——这两类题的失分点几乎都在"没写过程"。

## A 组 · 概念与产业（4.1–4.6）

**A1** 复述"嵌入式系统"的定义，指出其中四个硬指标。为什么"嵌入式系统 ≠ 实时系统"？

**A2** 什么是安全关键系统？说出它的三条典型特征与三条技术特征。

**A3** DO-178B/C 的 DAL 分几级？按什么分的？Level A 与 Level E 的差别在于什么？DAL 与 Common Criteria 的 EAL 有何不同？

**A4** ARINC 653 解决什么问题？列出课件给出的两种符合该标准的产品及其认证等级。

**A5** 单内核、微内核、混合内核的核心差别是什么？为什么说"混合内核是妥协"？微内核的代价是什么、seL4 怎么把代价压下来？

**A6** 按"收费模式"和"实时性"两个维度给 VxWorks、RTEMS、Linux、ROS、seL4、RTLinux 归类。RTEMS 属于哪一格，它的性能数据说明了什么？

**A7** RT-Thread 的定位是什么？它与道系统、翼辉、天脉的面向领域有何不同？

::: sol A 组解答要点
A1：定义见 4.1.2；四个硬指标 = 功能（含 AI）、可靠性、成本、体积、功耗。嵌入式系统 ≠ 实时系统，因为有些嵌入式系统没有实时性要求（4.12.1）。A2：失效导致不可接受的安全事故（人命/财产/环境/社会）；典型特征：异构节点分布式且多任务并发、硬实时、周期与非周期任务混合；技术特征：层次性、涌现性（失效概率 <10⁻⁹、失效模式、任务运行时间）、确定性（时间确定 + 故障处理确定）。A3：DAL A–E，按"失效后果严重性 × 发生频率"分；Level A 需最严格的验证与文档，Level E（无危害）最松；EAL 是信息安全评测等级（1–7），度量对象不同。A4：解决"大应用切成多个分区、互不影响"；VxWorks 653 与 INTEGRITY-178B，均通过 DO-178B A 级认证。A5：单内核集成高效但一个 bug 拖垮全系统；微内核把服务搬进用户态，故障隔离好、可形式化验证，代价是 IPC 开销；混合内核把部分用户态代码搬回内核换速度，是妥协；seL4 用三代演进（Mach 100 μs → L4 1 μs → seL4 0.2–1 μs）压低 IPC 代价并做形式化验证。A6：VxWorks=商用+硬实时；RTEMS=免费+硬实时；Linux=免费+无实时（实时版另说）；ROS=免费+无实时；seL4=免费+硬实时；RTLinux=免费+软实时。RTEMS 数据（重负载下中断时延 20.5 μs vs RtLinux 196.8 μs）说明"开源≠不实时"。A7：RT-Thread 面向物联网（IoT OS 平台：RTOS 内核 + 中间件 + 社区）；其余面向控制系统（军工/轨交电网/航空/工控）。
:::

## B 组 · 任务模型与调度（4.7–4.9）

**B1** 任务的三种状态是什么？"就绪→执行"和"执行→阻塞"分别由谁决定？为什么这个分工很重要？

**B2** 前后台系统（超循环）的结构是什么？它的主要缺陷是什么？为什么说它的响应时间"比实际可以做到的差"？

**B3** 非抢占式内核里，ISR 使一个高优先级任务就绪后，CPU 归谁？直到什么时候高优先级任务才能运行？为什么这在实时系统里不可接受？

**B4** 上下文切换具体做了什么？它的开销与什么因素成正比？结合第二章说说 ARM 上一次切换大约要搬多少东西。

**B5** 三种调度算法（RMS / EDF / LLF）各自的优先级依据是什么？为什么 RMS 开销小？为什么 EDF/LLF "应用受到一定限制"？

**B6** 三个周期任务：T₁=10 ms、C₁=2 ms；T₂=20 ms、C₂=3 ms；T₃=50 ms、C₃=5 ms，截止期均等于周期。
① 算总利用率 $U$；② 用 RMS 充分条件判定；③ 写出 RMS 下的优先级顺序；④ 用 EDF 模拟 50 ms 内的执行情况，确认无冲突。

**B7** 承接 B6：若 C₃ 改成 12 ms，$U$ 是多少？RMS 充分条件还成立吗？这是否等于"系统不可调度"？该怎么进一步确认？

::: sol B 组解答要点
B1：运行/就绪/阻塞；"就绪→执行"由内核调度器决定，"执行→阻塞"由任务自身（申请资源失败、等待消息、延时）决定。分工重要：前者是内核的策略（可抢占/不可抢占），后者是任务的行为（同步原语的基础）。B2：前台=ISR 层级（处理异步事件、时间相关强的关键操作），后台=主循环（掌管软硬件资源分配管理与调度）；缺陷是各任务优先级相同、只能顺序轮转，关键任务要等主循环轮回来，响应时间不确定、随负载变化。B3：CPU 仍归被中断的任务，直到它主动放弃 CPU（调用阻塞/让出 API）；高优先级任务可能等很久，延迟不可预测——课件明确"实时系统中不宜采用非抢占式调度"。B4：把当前运行任务的 CPU 寄存器全部内容保存到**任务自己的栈区**，再把下一任务的上下文从其栈装入 CPU 寄存器；开销与 **CPU 寄存器数量**成正比。ARM 上 37 个寄存器（2.7.1），其中任务上下文相关的部分每次进出栈。B5：RMS 按**周期**（短者高）、静态；EDF 按**截止期**（早者高）、动态；LLF 按**空闲时间 = 截止期 − 剩余执行时间**、动态。RMS 优先级不变、无需重算，开销小；EDF/LLF 每次调度点都要计算并改优先级，开销大、不易实现，应用受限。B6：① $U = 0.2 + 0.15 + 0.1 = 0.45$；② $n(2^{1/n}-1) = 3(2^{1/3}-1) \approx 0.78$，$0.45 \le 0.78$ 成立，**可调度**；③ 优先级 A(10 ms) > B(20 ms) > C(50 ms)；④ 50 ms 内：A 占 10 ms、B 占 7.5 ms、C 占 5 ms，合计 22.5 ms < 50 ms，无冲突。B7：$U = 0.2 + 0.15 + 0.24 = 0.59$；仍 $\le 0.78$，**充分条件仍成立**（本例只是示意改法不对）。**注意**：若改成使 $U > 0.78$，也只是"不能由该判据证明"，**不等于不可调度**——须用时间轴模拟逐点验证（见 4.9.6 方法二）。
:::

## C 组 · 通信与同步（4.10）

**C1** 共享内存与消息传递各有什么优点、各自必须解决什么问题？实现共享内存互斥的三种手段是什么？

**C2** 消息邮箱与消息队列的区别是什么？两者各自提供的四项内核服务是什么？

**C3** 信号量的三种主要用途是什么？二进制型与计数器型分别适合什么场景？

**C4** 用课件的例子描述优先级反转的完整过程。为什么用"普通信号量"替代互斥量会让优先级继承失效？

**C5** 判断下面的函数是否可重入，并说明理由：
```c
int counter = 0;
void add(int n) {
    counter = counter + n;      /* 读-改-写 */
}
```

**C6** 两个任务 T1、T2 共享资源 R1 与 R2。写出一种会导致死锁的申请顺序，并给出避免死锁的改法。

::: sol C 组解答要点
C1：共享内存快（无拷贝）但必须自己保证互斥；消息传递由内核搬运、代价高但天然隔离。共享内存互斥三手段：开/关中断、禁止任务切换、信号量机制。C2：邮箱存 1 条消息（通常是指针），队列是邮箱阵列、可存多条；服务四项：初始化、post（放入）、pend（等待）、取出消息。C3：控制共享资源使用权（互斥）、标志某事件发生、使两任务行为同步；二进制型（0/1）用于互斥，计数器型用于资源计数/事件计数。C4：A 高优先级但睡眠，B 低优先级在跑并向文件服务进程发请求后睡眠；A 就绪后与文件服务进程同为就绪，而文件服务进程优先级高于 A，于是 A 被"代表 B 的进程"压住——等待链长度随负载增长，延迟不可预测。**优先级继承失效的原因**：优先级继承要求"锁有所有权"（谁加锁谁解锁、能识别谁正持有锁），普通信号量无所有权，内核无法确定该提升谁的优先级。C5：**不可重入**：`counter` 是全局变量，读-改-写之间被抢占会被另一任务改写，返回值错误。改法：用局部变量累加后再写回，或加互斥量保护。C6：死锁顺序：T1 先取 R1 再取 R2；T2 先取 R2 再取 R1（互相等待）。改法：统一申请顺序（都先 R1 再 R2），或"先拿齐再干活"，释放时逆序。
:::

## D 组 · 中断、实时性（4.11–4.12）

**D1** 时钟节拍是什么？它有两个什么作用？节拍率提高的代价是什么？

**D2** 三个时延指标分别是什么？上下文切换时延与什么因素成正比？为什么"采用 MMU"反而使切换更慢？

**D3** 课件举的"100 次中 99 次 50 ms 内响应，1 次 250 ms"说明什么？为什么不能取平均值？

**D4** 用 Gillies 的定义说明"实时系统"是什么。为什么 Windows 不是实时操作系统（即便它很快）？

**D5** 硬实时与软实时的区别是什么？各举一个课件中的例子。

**D6** IEEE 给出的实时操作系统典型特征有哪七条？

::: sol D 组解答要点
D1：时钟节拍是特定的周期性中断（系统心跳），间隔一般 10–200 ms；作用：让内核把任务延时若干个整数节拍、给等待事件的任务提供超时依据；代价：节拍率越快，系统的额外开销越大（每次节拍都要进内核跑调度）。D2：中断时延（nIRQ → 开始执行 ISR）、调度时延（ISR 结束 → 目标任务开始跑）、上下文切换时延（保存+装载）。上下文切换时延与 **CPU 寄存器数量**成正比（寄存器越多入栈越慢）；用 MMU 更慢是因为切换地址空间要刷 TLB、更新页表基址。D3：说明指标要按**最坏情况**取——那次 250 ms 就是系统的中断响应时间上界；取平均值（50.5 ms）会严重高估系统能力，在安全关键场合导致误判。D4：实时系统的正确性不仅取决于逻辑正确性，还取决于结果产生的时间；未满足时间约束即认为系统失效。Windows 空闲时响应很快，但后台任务运行时响应可能变得非常漫长（甚至读文件任务长时间无响应）——**它不提供确定性**，这是结构问题不是性能问题。D5：硬实时错过截止期后果是灾难性的、时间精度微秒级（如汽车气囊，VxWorks）；软实时错过只是品质下降、毫秒级（如 IPTV 丢几帧视频）。D6：异步事件响应、切换时间与中断时延确定、优先级中断与调度、抢占式调度、内存锁定、连续文件、同步。
:::

## E 组 · 实时 Linux（4.13）

**E1** Linux 的 SCHED_OTHER、SCHED_FIFO、SCHED_RR 分别是什么策略？SCHED_FIFO 下正在运行的进程什么时候才会被换下？

**E2** 课件列出 Linux 用于实时应用的五个问题，逐条说出。

**E3** 瘦内核方法的基本结构是什么？为什么它能提供硬实时？它的缺点是什么？

**E4** 超微内核与 hypervisor 有什么相似之处？ADEOS 怎么处理硬件事件？

**E5** 资源内核的"预留参数"包括哪些？若无法提供确定性访问，内核返回什么？

**E6** CONFIG_PREEMPT 解决了 Linux 的什么问题？代价是什么？PREEMPT_RT 为了实现硬实时做了哪三项修改？

::: sol E 组解答要点
E1：SCHED_OTHER = 普通进程的**比例共享**调度（按 priority+counter 选最大者，epoch 内 counter 递减）；SCHED_FIFO = 实时进程按 rt_priority 排队，同级先到先跑，**运行中的进程不因时间片被换下**，只有被更高优先级抢占、自己阻塞或主动 `sched_yield` 才让出；SCHED_RR = 与 FIFO 类似但**加时间片**，时间片到则让出（长度用 `sched_rr_get_interval` 取）。E2：① 调度单位 10 ms，精确定时不足；② 内核态不可被抢占；③ 大量封中断操作造成中断丢失；④ 虚拟内存缺页要读硬盘，随机读写时间影响截止期；⑤ 缺乏有效的实时任务调度机制，网络协议处理与设备中断未与对应进程调度关联。E3：第二个内核作为硬件与 Linux 内核间的抽象接口；非实时 Linux 内核作为**低优先级任务**在后台托管全部非实时任务，实时任务直接在瘦内核上运行；瘦内核**截获中断**，保证非实时内核无法抢占瘦内核，从而提供硬实时。缺点：实时与非实时任务独立导致**调试困难**；非实时任务未得到 Linux 平台完整支持。E4：都对硬件做抽象、供更高级别的系统使用；ADEOS 支持多个并发操作系统同步运行，**硬件事件发生后对链中每个操作系统依次查询**，决定由谁处理。E5：预留参数 = **循环周期、需要的处理时间、截止时间**；若无法提供确定性访问，**返回错误**（而非默默延迟）。E6：解决"内核态不可被抢占"——CONFIG_PREEMPT 允许在内核调用期间被高优先级任务抢占，得到**软实时**；代价是**吞吐量与内核性能略微下降**（该选项本身有开销），且对服务器等场景不一定合适。PREEMPT_RT 的三项修改：**重新实现内核锁定原语**实现完全可抢占、**内核互斥的优先级继承**、**把中断处理程序转换为内核线程**以实现线程可抢占。
:::

## F 组 · 综合设计题

**F1** 某飞控系统有两个任务：A 为姿态控制，周期 5 ms、执行 1.5 ms；B 为数据记录，周期 20 ms、执行 3 ms。系统用抢占式内核，优先级可动态调整。
① 算 $U$ 并用 RMS 充分条件判定；
② 若改用 EDF，说明 B 的截止期应如何设置才合理；
③ 若记录任务偶尔会与控制任务争抢同一条 SPI 总线，画出优先级反转的发生过程，并给出两种防法。

**F2** 设计一个"UART 接收中断 → 环形缓冲区 → 解析任务"的方案，要求写出：ISR 里做什么、为什么不能在 ISR 里解析、任务之间用什么机制传数据、共享缓冲区的互斥怎么保证。

::: sol F1 解答要点
① $U = 1.5/5 + 3/20 = 0.30 + 0.15 = 0.45$；$n=2$，$2(2^{1/2}-1) = 2(1.4142-1) = 0.828$；$0.45 \le 0.828$ ⇒ 充分条件成立，RMS 下可调度（优先级 A > B）。
② 周期性任务的截止期通常取 $D_i = T_i$（B 的 $D = 20$ ms）；若允许抖动可放宽，但放宽会降低 EDF 的紧迫度评估价值。
③ 过程：低优先级的 B 持有 SPI 总线锁并正在使用；高优先级 A 就绪后也要用总线，被阻塞；B 因某原因迟迟不释放（或被中低优先级任务抢占）→ A 被拖住，即优先级反转。**防法一：优先级继承**（A 阻塞 B 持有的锁时临时提升 B 的优先级，B 释放后降回）；**防法二：优先级天花板协议 PCP**（拿锁就直接提到该锁的最高可能优先级）。二者都要求**互斥量有所有权**（4.10.4）。

**F2 解答要点
- **ISR 里做**：读 UART 数据寄存器（单次 LDR，2.11 MMIO）、写进环形缓冲区（更新头指针）、**清除中断源**、通知任务（置事件标志 / post 消息）。**不做**：解析协议、格式化、打印、任何可能阻塞或耗时的操作——ISR 抢占所有任务，ISR 里的每一行都计入最坏情况中断时延（4.11.6），且 ISR 不可重入（4.10.7）。
- **为什么不能解析**：解析可能耗时（变长帧、查表、浮点），会把中断响应拉长；且解析可能调用不可重入的函数或申请资源（阻塞在 ISR 里是禁止的）。
- **任务之间传数据**：数据走**共享内存**（环形缓冲区），通知走**信号量/事件标志**（ISR post，解析任务 pend 等待）——这正是 4.10.2 说的"共享内存 + 信号量"组合；数据量大时也可让 ISR 直接 post 消息指针。
- **互斥保证**：ISR 与任务共享缓冲区时，用**关中断/禁止任务切换**保护入队操作（4.10.2 三种手段之一），或用计数型信号量。关键：**入队是原子的**（读头指针→写数据→更新头指针之间不能被打断），否则会出现半写入的数据。
:::
