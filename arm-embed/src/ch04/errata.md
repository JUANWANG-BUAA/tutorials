# 勘误与补注（对照课件）

记录《第 4 章 嵌入式操作系统》课件与通用口径的差异。编号 #4-n。处理原则：正文按考纲口径书写，课件原文如实转述于此。

## 已核实的课件问题

::: errata #4-1 SWI 章节中的返回寄存器（跨章一致性问题）
第二章勘误 #2-4/#2-5 已指出课件 Slide 103、106 把 SWI 与未定义指令的返回写成 `SUBS PC, R14_irq, #4`。本章 4.11.1 给出的 ISR 骨架用的是 `LR_irq`（IRQ 场景正确），两处口径不同但都指向各自的正确值，**不重复记为新勘误**，复习时以 2.9.5 的表为准。
:::

::: errata #4-2 "内核占用 2%～5%" 与 "5%～10% CPU 额外负荷" 两处数字不一致（Slide 147 与 Slide 156）
- Slide 147（内核）："内核需要消耗一定的系统资源，比如 **2%～5% 的 CPU 运行时间**、RAM 和 ROM 等"；
- Slide 156（使用嵌入式 OS 的缺点）："嵌入式操作系统增加 ROM/RAM 等额外开销，**5%～10％的 CPU 额外负荷**"。

两处讲的是同一件事（内核开销）却给出不同区间。正文按"个位数百分比量级"表述并标出两处出处。**考试若问具体数字，按课件原页作答并说明出处。**
:::

::: errata #4-3 时钟节拍率与"毫秒级软实时/微秒级硬实时"的刻度冲突（Slide 149 与 Slide 159）
- Slide 149：时钟节拍间隔"一般在 **10ms 到 200ms** 之间"；
- Slide 159：软实时调度精度"毫秒级（以上）"，硬实时"微秒级（以下）"。

按字面理解，**10–200 ms 的节拍无法支撑微秒级硬实时的定时精度**——这不是矛盾，而是两个不同层面：**节拍率决定的是"内核按节拍调度"的粒度**，而硬实时任务可以用独立的硬件定时器触发自己（4.9 的周期任务、4.11.6 的 ABS 例子），不必依赖节拍。课件未展开这一层，正文在 4.11.3 作了补充说明。
:::

::: errata #4-4 μC/OS 任务数量口径（Slide 51）
课件："μC/OS-II 可以管理 **64 个任务**，然而，目前这一版本保留 **8 个给系统**。应用程序最多可以有 **56 个任务**"。课件同页标题写的是 μC/OS-II，而 Slide 49 提到"目前版本 μC/OS-III V2.72"（该版本号实为 μC/OS-II 的版本）。**版本与任务数的对应以课件原页为准**，正文按"μC/OS-II 可管理 64 个任务、系统保留 8 个、应用最多 56 个"书写。
:::

::: errata #4-5 seL4 内核代码规模（Slide 37）
课件："内核规模约 **9 千行代码**"。Slide 39 的第三代微内核表同样写"约 9 千行"。seL4 官方公开的规模数字（含 C 代码与汇编）约一万行量级，课件取"约 9 千行"，**口径一致，不构成冲突**。此处登记仅为说明该数字是"内核本体"，不含用户态库与验证模型。
:::

::: errata #4-6 RTEMS 最小内核体积的三处数字（Slide 69）
同一页给出三个数字：最小内核 **30KB**；CPU 为 ARM7 时 ELF 格式的标准 ARM 目标可减到 **46KB**；只保留主要功能时未压缩目标（内核 + BSP + 简单应用）可控制在 **60KB**。三者口径不同（内核 / 内核+BSP / 内核+BSP+应用），课件未逐一标注，**正文按各自口径分别引用并注明**。
:::

## 口径澄清（非笔误）

::: note #4-7 "μC Linux" 的写法
课件全篇写作 **µcLinux / uClinux**（Slide 33、108）。通行写法为 **uClinux**（也有 μClinux）。正文统一写作 **μC Linux**，首次出现处标注课件原写法。
:::

::: note #4-8 "抢占式"与"抢先式"两种译名
课件在 μC/OS 部分用"抢先式"（Slide 50），在调度部分用"抢占式/占先式"（Slide 134–136、177）。二者指同一机制（preemptive），正文统一使用**抢占式**，引用 μC/OS 特性时保留"抢先式"原词并加注。
:::

::: note #4-9 RTEMS 名称缩写
课件写 "Real-Time Executive for Multiprocessor Systems"，并给出早期名 "Real Time Executive for Missile Systems / Military Systems"（Slide 67）。**Multiprocessor** 反映其多处理器支持能力（4.5.4 列有"支持多处理器结构（同构与异构）"）。
:::

::: note #4-10 seL4 与 L4 的继承关系图
Slide 40 的图出自 Elphinstone & Heiser, SOSP 2013，**蓝线是接口（ABI/API）继承、黑线是代码继承**。课件给出图但未展开细节，正文按课件原话转述其含义（"共享接口而非代码"）。
:::

::: note #4-11 RT-Linux 拼写
课件在 Slide 74/75 写 **RtLinux**，在 Slide 107/183 写 **rtlinux**，标准写法为 **RTLinux**。正文统一用 RTLinux。
:::
