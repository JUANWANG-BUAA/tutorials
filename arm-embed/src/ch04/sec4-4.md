# 4.4 微内核与 seL4

seL4 是第一个通过**形式化机器检查证明**的通用操作系统内核。它的价值不在于"跑得快"，而在于"**可证明地对**"。本节按课件的顺序讲：三代微内核的量化演进、seL4 的设计理念（capability）、内核对象、内存管理、线程模型、调度、中断与驱动。（课件 Slide 36–48）

## 4.4.1 L4 与 seL4 的来历

**L4** 是一组基于微内核构架的操作系统内核。澳大利亚研究组织 **NICTA** 开发了 L4 的一个新版本 **seL4（Secure Embedded L4）**，宣布在世界上率先开发出**第一个形式化机器检测证明（formal machine-checked proof）的通用操作系统**。

seL4 微内核设计针对实时应用，可潜在应用于强调安全与关键性的任务领域，如**军用和医疗**。课件强调两点突破：

- 在较小内核中的形式证明此前已实现，但这是**首次在执行复杂任务的操作系统内核中实现**；
- 研究发现常用的攻击方法对 seL4 **无效**，如恶意程序常用的**缓存溢出漏洞**。

seL4 的基本信息：内核规模约 **9 千行代码**；由 NICTA 维护，归 **General Dynamics C4 Systems** 所有；官网 sel4.systems，源码在 GitHub。

## 4.4.2 微内核的三代演进（量化）

课件 Slide 39 用一张表把三代微内核的差距摊开：

| 代 | 代表 | 系统调用数 | 代码规模 | IPC 延迟 | 特点 |
|:--|:--|:--|:--|:--|:--|
| **第一代** | Mach、Chorus | 180 个 | 约 10 万行 | 约 100 μs | 仍然比较复杂、不够简洁 |
| **第二代** | L4 家族 | 不到 10 个 | 约 1 万行 | 约 1 μs | 注重精简、手工优化、比第一代性能高；遗留资源管理、内核对象保护等问题 |
| **第三代** | seL4 | 不到 5 种 | 约 9 千行 | 约 0.2–1 μs | 进一步提升性能；着重安全、可靠；对象保护机制；资源管理策略放用户空间；**形式化验证** |

这张表就是微内核历史的浓缩：**用"功能少"换"可证明"，再用实现质量把性能追回来**。注意 IPC 延迟从 100 μs 到 1 μs 再到亚微秒级——这正是"消息传递是微内核的基本操作"的代价与优化过程。

课件另给出 L4 家族的继承关系图（Slide 40，来源 Elphinstone & Heiser, SOSP 2013）：**蓝线表示接口（ABI/API）继承关系，黑线代表代码继承关系**——seL4 与 L4 系列共享接口而非代码，这是"接口稳定、实现重写"的演化模式。

## 4.4.3 seL4 的设计理念

**① 单一保护机制：capability**

- 一种**间接访问控制**；
- 可用来描述、管理内核对象的权限。

**② 精简系统调用**

只提供必要的、无法替代的；其他可以通过 IPC 等方式实现。主要系统调用：**Send、Wait 及其变种、Yield**。

**③ 内核对象**（内核管理的实体）：

- 线程 **TCB**（Thread Control Block）；
- **地址空间**（如页表项、页表、页目录）；
- **IPC 端点**（Endpoints，同步/异步 IPC）；
- **Capability 空间**；
- **页框**；
- **中断对象**；
- **未定义内存**。

## 4.4.4 Capability：权限即对象

**Capabilities** 的机制（课件 Slide 42）：

| 要素 | 内容 |
|:--|:--|
| **Token** | 记录所描述的对象 |
| 对象有关的**权限** | **读、写、授权**（转移 Cap，如授权另一个线程） |
| 检查时机 | 在**调用该对象时**检查权限是否匹配 |
| 优势 | **不需要使用全系统的访问控制列表**；调用对象时与该对象相关的 Cap 会检查权限等信息 |
| 存储位置 | 存在 **Capability 空间**中 |

::: think capability 与传统权限的区别
传统做法：进程有个"用户 ID / 组 ID"，系统对每个对象维护一张"谁能访问我"的 ACL 表——表会随进程数膨胀，而且**不能表达"把某个权限转交出去"**。Capability 做法是：权限本身是一个**对象**（token），装在调用者的 Cspace 里；"你能访问 X"= "你的 Cspace 里有 X 的 token 且带相应权限位"。授权就是把 token 复制给对方——**权限可以像数据一样流动**。
:::

## 4.4.5 IPC：微内核的基本操作

课件 Slide 43 的四点刻画：

- 一种基本的微内核操作；
- **由受保护的用户级进程提供**；
- 基于 **C/S（Client/Server）模式**；
- 通过 **IPC 端点**进行"握手"然后通信，提供**同步/异步**通信。

第四章后面讲的消息队列、邮箱（4.10）本质上是同一件事的内核实现版本：消息传递是微内核世界的通用货币。

## 4.4.6 内存管理：未定义内存与 Retype

seL4 的内存模型（课件 Slide 44）：

**内存分类**：

| 类别 | 说明 |
|:--|:--|
| **未定义（untyped）** | 未使用内存，可以通过 **Retype** 操作分配 |
| **页框（frames）** | 可被映射进地址空间 |
| 其他（如页表等） | 用于存储特定的内核数据结构 |

**关键设计**：**内核启动后不分配内存**——剩余内存被标记为"未定义"并送入初始地址空间；**内核对象的内存需求必须明确定义**，以确保**强资源隔离**。

"Retype"是这个模型的独特之处：未定义内存是一块"可以变成任何内核对象"的原材料，把一块未定义内存**改造（retype）**成某个内核对象（比如一个线程控制块），是这个对象内存的唯一来源。内存的所有权因此是显式的、可审计的。

## 4.4.7 线程模型

线程由 **TCB** 描述和表示（课件 Slide 45），主要成员：

- **Vspace**：虚拟地址空间；
- **Cspace**：capability 索引（指针）；
- **故障入口**：发生错误时，内核向该入口抛出异常；
- **IPC 缓冲区**；
- **栈指针 SP、指令指针 IP** 等；
- **调度优先级**；
- **时间片长度**。

看回第二章：**每个任务有自己的一套 CPU 寄存器和自己的栈空间**（4.7），在 seL4 里这个"栈"和"寄存器组"就是 TCB 的一部分——硬件层的分组寄存器与栈，操作系统层对应 TCB。

## 4.4.8 调度：重实时而非公平

seL4 目前采用**基于优先级的时间片轮转调度**：

- 共 **256 个优先级（0–255）**，优先级被明确定义；
- **总是选择优先级最高的线程**；
- 采用时间片轮转方式；
- **着重于实时性能，而不是公平性**；
- 正在开发基于**多临界状态（Mixed Criticalities）**的调度机制。

"不追求公平"是硬实时内核的共同取舍：低优先级的线程可以一直得不到 CPU——只要系统设计时保证了高优先级线程的时限可满足就行。

## 4.4.9 中断与异常：被抽象成"通信"

课件 Slide 47 是 seL4 设计里最漂亮的一笔：

- **中断请求过程被抽象为"通信"**——向一个**异步通信端点**发送消息；中断句柄通过该端点接收消息；中断句柄**确认并处理**中断请求；
- **异常处理类似**——发生异常时，内核向**故障端点**发送消息（包含异常处理协议预先定义的错误信息）；**回复异常消息将重启引发异常的线程**。

把中断做成消息，意味着"处理中断"就是"处理消息"，内核不需要为中断单独维护一套机制——只需一条消息队列加一个端点。这正是 4.10 的"中断服务程序"与"消息处理"可以统一起来的原因。

::: think 对照第二章的异常向量
第二章说：异常发生时硬件把 PC 指向向量、CPU 进异常模式。seL4 把这一步之后的事**全部改造成消息传递**：硬件仍按 ARM 规则跳向量，但向量处的代码不再是"传统 ISR"，而是"把异常信息打包成消息，发给故障端点"。**硬件机制不变，软件范式变了**——这正是"机制与策略分离"（4.3.3）的极致。
:::

## 4.4.10 设备驱动：用户态线程

课件 Slide 48：设备驱动的职责是**处理中断、与操作系统其它组件通信、访问设备寄存器**。它的实现方式是：

- 作为**用户级线程**实现，**从内核剥离**；
- 提高内核可靠性，**防止第三方代码导致内核故障**。

这正是 4.1.5 说的"故障限制单元范围确定"的具体手段：驱动的 bug 最坏结果是该设备失灵，而不是整个系统崩溃。

## 本节小结

三代微内核用"少而精"换可证明性（IPC 100 μs → 1 μs → 0.2–1 μs）；seL4 = 9000 行 + 形式化验证 + capability 单一权限模型 + 未定义内存/Retype 显式内存所有权 + 中断异常抽象成消息 + 驱动用户态化。这一节与第四章机制部分（4.7–4.12）互为镜像：**线程/调度/IPC/中断/内存**，一个内核五件事，seL4 给出了每件事的"最小可信实现"。下一节跳出微内核，看整个产品 landscape。
