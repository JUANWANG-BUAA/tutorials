# 4.6 RT-Thread 与国产 RTOS 生态

嵌入式 OS 的另一半战场在中国。国产 RTOS 覆盖军品、航空、轨交、电网、工控、物联网与消费级——谱系比想象中完整。本节按课件口径梳理：典型国产嵌入式实时操作系统、国产国防 OS 谱系、华为的三条产品线。（课件 Slide 97–104）

## 4.6.1 典型国产嵌入式实时操作系统（民用五强）

课件 Slide 97 列出的五家：

| 厂商 | 产品 | 课件要点 |
|:--|:--|:--|
| **道系统** | **Delta OS** | 主要应用于**军工装备领域**，已在多兵种装备上应用；**微秒级响应时间**；提供基于**优先级抢占**的实时任务调度策略；提供动态加载功能 |
| **翼辉** | **Sylix OS** | 功能全面、稳定可靠、易于开发的大型实时操作系统平台；面向**轨道交通、智能电网、航空航天、工业自动化、汽车、通信**等领域 |
| **天脉系统** | **ACore OS** | 面向**航空电子**领域，起源于航空工业计算所（631 所）；突破**可伸缩架构、多核支持、实时进程、64 位支持**等多核操作系统关键技术；主要用于机载系统 |
| **科东软件** | **Intewell OS** | 是"道"操作系统的**民用品牌**；基于**微内核架构**；具备软件定义控制、**高实时（μs 级响应）**、高可靠、**自主可控**、多业务承载、软硬件解耦等特性；实现控制、计算、网络、云服务技术的融合统一 |
| **赛睿德** | **RT-Thread** | 见 4.6.2 |

课件对这五家的分类口径：道系统（Delta OS）在"商用型 + 硬实时"两侧都出现；Sylix OS（翼辉OS）在"免费型"与"硬实时"两侧都出现。

## 4.6.2 RT-Thread：IoT 操作系统平台

课件 Slide 102 的定义（原文口径）：

> **RT-Thread** 是一个集**实时操作系统（RTOS）内核、中间件组件和开发者社区**于一体的技术平台；也是一个组件完整丰富、高度可伸缩、简易开发、**超低功耗、高安全性**的**物联网操作系统**。它具备一个 IoTOS 平台所需的所有关键组件，例如 **GUI、网络协议栈、安全传输、低功耗组件**。

官网 rt-thread.org。

::: think RT-Thread 的定位为什么特殊
前四家（道系统、翼辉、天脉、科东）都是"做控制系统"的——面向航空、军工、电网、轨交。RT-Thread 面向的是**物联网**：设备多、功耗低、要联网、要 GUI、要安全传输。同一套内核要同时满足"能联网"和"够实时"，这就是它强调**高度可伸缩**与**中间件组件**的原因——用配置裁剪出从手环到网关的不同形态。
:::

## 4.6.3 国产国防嵌入式实时操作系统谱系

课件 Slide 103 给出的机构—产品对应表：

| 机构 | 产品 |
|:--|:--|
| 航天科技北京神舟软件 | **神舟嵌入式实时操作系统（神舟OS）** |
| 航天科技五院 502 所 | **星载计算机操作系统——SpaceOS-天卓**（第三代天卓，2022 年 1 月发布） |
| 中航工业西安航空计算技术研究所（631 所） | **天脉操作系统**（支持 **ARINC 653** 规范） |
| 中国航天科工集团公司二院（706 所） | **"天熠"移动操作系统** |
| 中国航天科工集团公司三院 | ①"天熠"嵌入式实时操作系统 ②"海鹰-翼辉"嵌入式实时操作系统 ③"科斗"安全移动操作系统 |

两个细节值得注意：

- **"移动操作系统"在这里指移动终端/手持设备**，不是"移动代码"——706 所的"天熠移动操作系统"与三院的"天熠嵌入式 RTOS"是两个产品；
- **天脉支持 ARINC 653 规范**（4.2）——国产 OS 也走国际认证路线。

## 4.6.4 华为的三条操作系统产品线

课件 Slide 104 的梳理：

| 产品 | 面向 | 认证/定位 |
|:--|:--|:--|
| **鸿蒙（HarmonyOS）** | **C 端**：手机、电脑、物联网、自动驾驶等，面向**万物互联网** | 内核于 **2023 年 7 月获 CC EAL6+ 证书** |
| **欧拉（openEuler）** | **B 端**：企业级服务器操作系统、云端操作系统 | 通过 **CC EAL4+ 认证** |
| **矿鸿** | 工矿业专用的**鸿蒙特殊版本** | 与欧拉、鸿蒙不同：可与欧拉连接（云端依赖欧拉），后端又可与鸿蒙连接 |
| **AOS** | 华为**自动驾驶操作系统内核**（含虚拟化机制），用于 MDC 智能驾驶计算平台 | **2019 年通过 CC EAL 5+ 认证、2020 年获车规 ISO 26262 ASIL-D 认证** |

## 4.6.5 国产化为什么重要：从"能自主"到"可验证"

把 4.2 的标准体系与本节对照，能看出国产 OS 生态的两条路径：

| 路径 | 代表 | 特征 |
|:--|:--|:--|
| **国际标准认证路线** | 天脉（ARINC 653）、AOS（CC EAL5+、ISO 26262 ASIL-D）、RT-Thread（CC EAL6+ 内核） | 用国际标准证明"可被安全关键领域接受" |
| **自主可控 + 场景专用路线** | 道系统（军工）、科东（软件定义控制）、矿鸿（工矿） | 在特定行业里形成完整闭环（控制 + 计算 + 网络 + 云） |

课件对"自主可控"的表述出现在科东 Intewell 的特性里。**这不是口号问题而是工程问题**：安全关键系统一旦被供应链卡住，飞机的安全论证链条就断了——所以"自主可控"与"可验证"是一体两面。

## 本节小结

国产 RTOS 有两条线：面向控制系统的道系统/翼辉/天脉/科东（微秒级响应、优先级抢占、微内核、自主可控），以及面向物联网的 RT-Thread（RTOS 内核 + 中间件 + 社区）。国防领域另有机构—产品谱系（神舟OS、SpaceOS 天卓、天脉、天熠、海鹰-翼辉、科斗）。华为以鸿蒙（C 端）、欧拉（B 端）、矿鸿（工矿）、AOS（自动驾驶）四条线覆盖全场景，认证等级是其进入安全关键领域的通行证。

产业部分到此结束——[4.7](sec4-7.md)起进入机制部分：一个核上，多任务如何共存。
