## 第一部分 · 概念辨析（每题 5 分，共 30 分）

判断对错并写一句理由。只写「对/错」不得分。

1. 一段代码里只有一条 `compare_exchange_weak` 加自旋，没有任何 `lock()` 调用，所以它是 Lock-Free。
2. Michael-Scott 队列的入队线性化点，在成功执行 `CAS tail -> X` 的那条指令上。
3. 计数器 0→1→0 与指针 0x1000 被释放后重新分配，两者都属于必须歼灭的破坏性 ABA。
4. EBR 的读路径没有屏障，所以读密集场景一律应该选 EBR。
5. 本书实测机的缓存行是 128 字节，所以把 128 写进常量就得到了可移植的正确对齐。
6. 只要有一个线程攥住 `Guard` 不撕，其余线程退休再多对象也释放不了。

## 解答与给分说明

**1. 错。** 分类依据是进展行为，不是指令种类。持锁线程被挂起时其余线程无法前进，连 Obstruction-Free 都不满足（[定义 11.1.2](ch11.md#def-11.1.2)、[例 11.1.1](ch11.md#ex-11.1.1)）。给分：判断 2 分；理由点到「挂起测试」或「排他持有」得 3 分。

**2. 错。** 入队线性化点在 CAS 把旧尾节点的 `next` 从 `null` 改成 `X` 那条指令上；更新 `tail` 只是帮助性推进。出队点在 CAS 前移 `head` 那条（11.2.3）。给分：指出正确指令 3 分。

**3. 错。** 计数器比对单元是纯数值，状态机语义里「值为 0」就是「值为 0」，`contracts.rs` 的探针证明它不引发 UB；指针的比对单元是地址，同一数值背后对象已换命，才必须歼灭。判据是两问：是不是指针、是否可能 free 再 malloc（[定义 11.3.2](ch11.md#def-11.3.2)）。

**4. 错。** EBR 的滞留上界无界：一个停在 `Guard` 里的线程就能冻住全局回收。内存受限、线程可能长休眠的场景要选 HP，代价是读路径每跳一发屏障（11.4.7 表、[例 11.4.1](ch11.md#ex-11.4.1)）。

**5. 错。** 缓存行大小是宿主属性，不是语言常数；写死 128 与写死 64 犯的是同一个错。正确姿势是运行时探测 `hw.cachelinesize`，或按最大合理值对齐并留注释（[思考 11.5.1](ch11.md#think-11.5.1)）。

**6. 对。** 代际推进的判据是所有活跃线程的局部纪元都追平全局，一张旧门票就足以否决。代价是内存与延迟，不是正确性：协议按设计工作（[定义 11.7.1](ch11.md#def-11.7.1)）。给分：判断 2 分；理由写到「追平全局」或「正确行为、代价在内存」得 3 分。

**7.（参考，a 3 分、b 2 分、c 3 分）**
- （a）同列对同列：72.861686 / 40.647478 ≈ 1.79，即加速比 1.79x，原文写作吞吐提升 79.3%。
- （b）不能。均值是批均值，回答吞吐；这里没有逐请求观测。能说的是批次间抖动：无锁 sd 8.023660，是互斥锁 2.683101 的近三倍，方向与「尾更稳」相反。
- （c）拒绝该口径。40.647478 是批均值，无逐请求数据；同批证据里无锁 p99 达 53.237915。要写 SLO 得另做请求级采集，当前只能承诺「4 线程拓扑下的吞吐改善」。给分：b 只说「均值更小所以更快」得 0 分。

**8.（参考，a 2 分、b 3 分、c 3 分、d 2 分）**
- （a）$4096 \times 256 = 1{,}048{,}576$，每条对象带 256 字节载荷，四条逐字节吻合。
- （b）证明「一个都没释放」，全部滞留在堆上；不证明额外占了多少——垃圾袋簿记与分配器元数据不在探针计量内，所以这份日志不能读成 RSS。
- （c）不能。实验只采了两个场景的单批耗时，pin、defer、推进尝试各占多少没有采集，36.9% 是总账。
- （d）积压会在撕票瞬间集中销毁（`after_unpin,dropped=4096`），延迟尖刺与突发内存压力要单独写进预算。

**9.（参考，a 3 分、b 3 分、c 6 分）**
- （a）`ArrayQueue<u64>` 那一行的 384 字节大小与 128 字节对齐：对齐值等于实测缓存行，说明高频字段按整行分开。
- （b）不够。`head` 与 `tail` 各 8 字节相邻，必然同落一条缓存行；64 字节填充跨不过 128 字节的物理行，隔了 64 仍可能同线。合规做法是按探测值 128 对齐。
- （c）`stamp == lap*2` 授权给生产者写入，写毕跃迁到 `lap*2+1`；`stamp == lap*2+1` 授权给消费者读出，读毕跃迁到 `(lap+1)*2`（[定义 11.5.2](ch11.md#def-11.5.2)）。

**10.（参考，每段 6 分、范围限定 2 分）**
- A 段：驻留期从 `pin()` 到函数末尾 `drop`，覆盖 200 个节点遍历，期间无挂起点，功能上合法。风险在持有期过长；改法是把 pin 收窄到纯指针遍历段，遍历后立即 drop 或 flush。
- B 段：驻留期把取数、等对端、回包与 `process` 全包进去，挂起点就是那个 `.await`，判「不可跨」。改法：Guard 里只查找并克隆 `Arc` 或值快照，`drop(guard)` 之后再 await（[定义 11.8.3](ch11.md#def-11.8.3)）。
- C 段：错。保护随 `Guard` 结束，指针立刻可能被释放复用；clone 裸指针不延长保护。改法是克隆快照值，或重新 `pin()`。
- 范围限定示例：「本方案只保证驻留期内的可访问性，不覆盖驻留期外的悬垂使用，也不覆盖跨执行器迁移的线程局部状态。」给分：每段缺「驻留期区间」扣 3 分，缺「是否可跨」扣 3 分。

**11.（参考，三个坑各 3 分、结论 1 分）**
- 坑一：位宽只有 16 位、65536 个取值，高吞吐下 tag 绕一圈后整体重合，ABA 原样复发（[例 11.3.1](ch11.md#ex-11.3.1)）。
- 坑二：偷借指针高位在启用 PAC 或 Top-Byte Ignore 的宿主（如 macOS Darwin）上会触发硬件解引用异常，破坏跨平台移植。
- 坑三：它仍然不解决「节点已 free、地址未复用」的悬垂提交；Tag 只证明这个字没被改过，不证明内存还活着（[思考 11.3.1](ch11.md#think-11.3.1)）。
- 结论示例：「短位宽 Tag 只能把检测窗口变窄，不能替代 SMR；要么用 128 位双字原子并保证 16 字节对齐，要么让释放推迟到所有观测者退场。」

**12.（参考，四处各 2.5 分）**
- 「快 79.3%」只给增速、不给抖动：补上 sd 从 2.683101 到 8.023660 的这一半。
- 「p99 53.2 比 p50 72.6 低」是跨分位数比较：同列对同列，无锁 p50 40.676117 对互斥 72.586060。
- 「4096 个对象、`dropped` 恒为 0 验证零泄漏」读反了：这正是 `stalled_pin` 的回收冻结形态，不是健康指标。
- 「承诺生产 P99 40ns」把批均值当请求级延迟：要写 SLO 得另做请求级采集；当前能承诺的只有 4 线程拓扑下的吞吐改善。
