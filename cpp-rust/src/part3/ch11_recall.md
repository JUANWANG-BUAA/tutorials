# 第11章 · 闭卷回忆卡

「看懂」只说明答案在眼前时能识别；评审和线上排障要的是从空白纸上提取。这一页把第十一章拆成 23 张卡，先读卡面自己答，再展开核对。

术语先对齐：缓存行（核之间搬运数据的最小单位）、伪共享（两个独立变量挤在同一行）、线性化点（调用真正生效的那一瞬间）、位模式（内存里那串二进制值）、分配器（发放与回收堆地址的组件）、RCU（内核的读-复制-更新）、epoch（用户的年代编号）、探针（测量尺寸与析构次数的小程序）、寄存器（CPU 里直接存取的那几个槽位）。

**用法与节奏**

| 时点 | 做什么 | 判定 |
|:--|:--|:--|
| 学完当天 | 第一组「定义卡」8 张 | 关键词写全才算 ✓ |
| 第 1 天 | 第二组「结论卡」9 张 | 能说清前提才算 ✓ |

每张卡给自己一个记号：✓ 一次说对；△ 说对一半或要提示；× 想不起来。只重做 △ 与 ×，不要把整叠反复过一遍——那是在读，不是在提取。

## 第一组 · 定义卡（说全称与前提）

::: ex 卡 1 · 三级进度保证 {#rc-11-1}

卡面：非阻塞的三级各承诺什么？判级用哪一个场景？

::: sol 核对

Obstruction-Free：挂起其他所有线程后，孤立的单线程能在有限步完成，最弱，可能活锁。Lock-Free：无论怎样交错、哪些线程被永久挂起，全局至少有一个线程在有限步取得进展，个体可能饥饿。Wait-Free：每个活跃线程都各自有限步返回，无人饿死。判级场景是「持锁或重试的线程被无限期挂起，其余线程还能不能完成」。对照[定义 11.1.2](ch11.md#def-11.1.2)。
:::

:::

::: ex 卡 2 · 乐观重试 {#rc-11-2}

卡面：写出乐观重试的四步循环，并说明重试失败意味着什么。

::: sol 核对

读快照 → 私有推测（在寄存器或栈上算出新拓扑）→ 单次原子 CAS 提交 → 失败就丢弃推测、重读再来。CAS 失败只说明有人抢先提交，是无锁结构的常态，不是算法写错的信号。硬件载体在 AArch64 上是 `casal`，在 x86_64 上是带 `lock` 前缀的 `cmpxchg`。对照[定义 11.1.3](ch11.md#def-11.1.3)。
:::

:::

::: ex 卡 3 · 线性化点 {#rc-11-3}

卡面：线性化的三条要求分别是什么？它比顺序一致性强在哪一步？

::: sol 核对

一是瞬时生效点：每次调用可在调用与返回之间指定一个不可分割的瞬间。二是逻辑等价：按瞬间点排序后的串行序列符合单线程规约。三是因果保持：物理上先返回的操作，在串行历史中必须在前。它比顺序一致性多的是实时锚——SC 允许把更晚发起的操作排到前面。对照[定义 11.2.1](ch11.md#def-11.2.1)。
:::

:::

::: ex 卡 4 · ABA 与两问检验 {#rc-11-4}

卡面：CAS 检查什么、不检查什么？判断一次 CAS 会不会中招，问哪两个问题？

::: sol 核对

CAS 只检查目标内存单元当前的位模式是否等于预期值，位模式就是那串二进制值；它不检查这块内存期间是否被释放、重分配或语义重构。两问：① 比对单元是不是指针（而非纯数值）？② 该指针指向的内存是否可能在快照与提交之间被 free 再 malloc（分配器把地址收回又发出去）？两问皆是，就必须上 SMR 或双字标记。对照[定义 11.3.1](ch11.md#def-11.3.1)、[定义 11.3.2](ch11.md#def-11.3.2)。
:::

:::

::: ex 卡 5 · 安全内存回收 {#rc-11-5}

卡面：SMR 承诺什么？它补的是所有权系统哪一段缺口？

::: sol 核对

承诺：只要仍有任何活跃线程可能持有指向某节点的悬垂观测，该节点的物理内存就禁止归还分配器。缺口是静态借用检查看不见的那段生命周期——穿过 `AtomicPtr` 的裸指针观测，借用检查器看得见的引用才谈生命周期。对照[定义 11.4.1](ch11.md#def-11.4.1)。
:::

:::

::: ex 卡 6 · HP 与 EBR 的保护粒度 {#rc-11-6}

卡面：两者各保护什么单位？各自把成本记在谁的账上？

::: sol 核对

HP 保护单个指针：读者解引用前把地址登记进全局可见的 Hazard Slot，写完发一次 `SeqCst` 屏障再校验；写者退休节点后批量扫描槽位，不在任何名单上才 free。EBR 保护一段时间：`pin()` 拿票时盖上当前纪元，代际内任意解引用零屏障；写者把节点投进当前纪元的垃圾袋，等所有活跃线程的局部纪元追平全局才推进。对照[定义 11.4.2](ch11.md#def-11.4.2)、[定义 11.4.3](ch11.md#def-11.4.3)。
:::

:::

::: ex 卡 7 · 伪共享与槽位世代号 {#rc-11-7}

卡面：伪共享的物理原因是什么？槽位世代号凭什么让 ABA 无从成立？

::: sol 核对

伪共享：两个逻辑独立的变量落在同一条缓存行里，缓存行是核之间搬运数据的最小单位；一方原子写把另一方副本置为 Invalid，硬件把两个线程当成同一个争用对象。世代号把「这个槽位现在轮到谁、处于第几圈」编进原子 stamp：写者只在 `stamp == lap*2` 时获准写，读者只在 `stamp == lap*2+1` 时获准读，过期指令的状态条对不上号。槽位可以复用，stamp 从不回头。对照[定义 11.5.1](ch11.md#def-11.5.1)、[定义 11.5.2](ch11.md#def-11.5.2)。
:::

:::

::: ex 卡 8 · 静止状态、宽限期、驻留期 {#rc-11-8}

卡面：三个词各指哪一段时间？宽限期的判据是时钟还是计数？

::: sol 核对

静止状态：某线程一次 `pin()`/`unpin()` 周期已闭合、旧代际观测确定失效的时刻。宽限期：从写者发布新版本到旧版本允许释放之间的等待，判据是「每个可能的观测者都至少越过一次静止状态」——内核数上下文切换，用户态数 `pin()` 周期闭合，是计数事件不是计时器。守卫驻留期：从 `pin()` 拿到 `Guard` 到它被 `drop` 之间的整段时间。对照[定义 11.7.1](ch11.md#def-11.7.1)、[定义 11.8.1](ch11.md#def-11.8.1)、[定义 11.8.3](ch11.md#def-11.8.3)。
:::

:::

## 第二组 · 结论卡（说清前提与范围）

::: ex 卡 9 · 有界自旋也不产生进展承诺 {#rc-11-9}

卡面：`AdaptiveMutex` 同样自旋，为什么它不算违例？两段循环的差别在哪？

::: sol 核对

差别不在转了多少圈，而在转圈的人离开后别人能不能继续。自适应锁的自旋只缩短进内核前的等待，临界区仍排他持有；持锁者一挂起，系统照样停摆，进度等级不变。有界性只限制浪费上限，不产生进展承诺。这段对照的耗时，本章没有采集。对照[思考 11.1.1](ch11.md#think-11.1.1)。
:::

:::

::: ex 卡 10 · 互斥锁的三层代价 {#rc-11-10}

卡面：三层各是什么？哪一层解释了「临界区 10 纳秒、等待却达几微秒」？

::: sol 核对

一是原子争用与缓存行弹跳；二是内核态上下文切换，单次物理耗时通常 1,000 至 5,000 纳秒，比 10 纳秒的临界区高两到三个数量级；三是优先级反转与锁护送。几微秒的等待正好落在挂起与唤醒区间，所以第一优先假设是慢速路径，其次才是弹跳。对照[定义 11.1.1](ch11.md#def-11.1.1)、11.1.1。
:::

:::

::: ex 卡 11 · 线性化点在哪条指令上 {#rc-11-11}

卡面：Michael-Scott 队列的入队、出队、空队列检测三个线性化点各落在哪里？

::: sol 核对

入队：CAS 成功把旧尾节点的 `next` 从 `null` 改成新节点 `X` 的那条指令；之后更新 `tail` 只是帮助性推进，不是线性化点。出队：CAS 成功把 `head` 从哨兵前移到下一个有效节点的那条指令。空队列检测：出队线程原子读取 `head.next` 并判定为 `null` 的那一瞬间。对照 11.2.3、[例 11.2.1](ch11.md#ex-11.2.1)。
:::

:::

::: ex 卡 12 · Tag 防检测，SMR 防事故 {#rc-11-12}

卡面：128 位双字原子为什么不能替代 SMR？16 位偷借 Tag 又漏了什么？

::: sol 核对

Tag 只证明「这个字没被别的 CAS 改过」，不证明「指针指向的内存还活着」。节点已 free、地址尚未复用且 Tag 恰好没被消费时，CAS 仍可能把 `head` 写成悬垂地址，除非 Tag 递增与禁止物理释放绑定。16 位 Tag 只有 65536 个取值，高吞吐下绕满一圈后 (地址, tag) 可能整体重合，ABA 原样复发；绕回所需的吞吐门槛，本章没有采集。对照[例 11.3.1](ch11.md#ex-11.3.1)、[思考 11.3.1](ch11.md#think-11.3.1)。
:::

:::

::: ex 卡 13 · 为什么三个纪元代际就够 {#rc-11-13}

卡面：0、1、2 三状态轮转的充分性靠哪条推理？

::: sol 核对

纪元 `e` 内退休的对象，只可能被处于纪元 `e` 或更早已进入且未退出的线程观察到；`e` 之后新进临界区的线程读到的纪元必然不小于 `e`。当所有活跃线程的局部纪元都达到或超过 `e+1`，就没有线程还活着进入早于 `e` 的引用。此时存活视野最多横跨 `e` 与 `e-1`，属于 `e-2` 的对象必定可安全释放。对照 11.4.6 证明框。
:::

:::

::: ex 卡 14 · 128 字节缓存行与 384/128 {#rc-11-14}

卡面：实测机的缓存行是多少？`ArrayQueue` 的类型尺寸与对齐是多少，说明什么？

::: sol 核对

`hw.cachelinesize` 在 Apple M5 Pro 上是 128 字节。探针测得 `crossbeam_queue::ArrayQueue<u64>` 大小为 384 字节、对齐 128 字节，设计考量是让头尾索引与缓冲区彻底隔离。对照表里 `Guard` 与 `Collector` 都是 8/8，`Arc<[u8]>` 与 `&[u8]` 是 16/8 胖指针，`Vec<u8>` 是 24/8 三字结构。对照[定义 11.5.1](ch11.md#def-11.5.1)、11.5.1 表。
:::

:::

::: ex 卡 15 · 快 1.79x，抖近三倍 {#rc-11-15}

卡面：queue 实验的四个关键数是什么？快与抖为什么同源？

::: sol 核对

`Mutex<VecDeque>` 均值 72.861686 ns/item、sd 2.683101；`ArrayQueue` 均值 40.647478、sd 8.023660，吞吐提升 79.3%，加速比 1.79x。同源于乐观重试：无碰撞时单次 CAS 直接提交，所以快；碰撞时整轮重读重试，批次耗时被重试次数带着走，所以抖。互斥锁相反，排他串行化压平波动也压住吞吐。对照[定义 11.6.1](ch11.md#def-11.6.1)、[例 11.6.1](ch11.md#ex-11.6.1)。
:::

:::

::: ex 卡 16 · 一张旧门票的账单 {#rc-11-16}

卡面：停顿参与者的实验留下了哪几个必须照抄的数？36.9% 能拆到哪一步？

::: sol 核对

4096 个 256 字节对象滞留在堆上，`payload_bytes` 停在 1,048,576，`dropped` 恒为 0；`drop(guard)` 之后 `after_unpin,dropped=4096` 一次爆发。两场景均值 22.967872 对 16.773780 ns/item，延迟激增 36.9%。36.9% 是总账：pin 成本、defer 成本、推进尝试成本各占多少，本章没有采集，不能说「慢在哪一步」。对照[定义 11.7.1](ch11.md#def-11.7.1)、[例 11.7.1](ch11.md#ex-11.7.1)。
:::

:::

::: ex 卡 17 · RCU 与 EBR 的分水岭 {#rc-11-17}

卡面：五格对照里，哪一行让「用户态就是内核 RCU（读-复制-更新）的库版本」这句话失效？

::: sol 核对

第四行「抢占容忍度」：经典 RCU 严禁读侧睡眠，PREEMPT_RCU 才支持抢占；用户态线程随时可能被操作系统剥夺，EBR 只能依赖主动刷新。第三行的静止状态定义也随之不同：内核数上下文切换、进 idle 或系统调用返回，用户态数 `flush()` 或离开 `Guard`。回收触发点从内核软中断挪到工作线程的协作分摊。对照 11.8.2 表、[定义 11.8.2](ch11.md#def-11.8.2)。
:::

## 第三组 · 第一行卡（只写第一步）

这一组练的是「一离开答案不知道第一行写什么」那个毛病。每题只写第一行动作，不做判断。

::: ex 卡 18 · 同事说「我们实现了无锁队列」 {#rc-11-18}

卡面：第一行写什么？

::: sol 核对

第一行：写下挂起测试——把持锁或正在重试的线程无限期挂起，其余线程还能不能在有限步内完成操作。这一步定级，先不读代码。对照[定义 11.1.2](ch11.md#def-11.1.2)。
:::

:::

::: ex 卡 19 · 看到 AtomicPtr 上的 CAS 加 Box::from_raw {#rc-11-19}

卡面：第一行写什么？

::: sol 核对

第一行：走两问检验——比对单元是不是指针，该地址是否可能在快照与提交之间被 free 再 malloc。两问皆是就按破坏性 ABA 处理，别先去加内存序。对照[定义 11.3.2](ch11.md#def-11.3.2)。
:::

:::

::: ex 卡 20 · 要在这段遍历里用 EBR {#rc-11-20}

卡面：第一行写什么？

::: sol 核对

第一行：画出驻留期——从 `pin()` 到 `Guard` 析构，把路径上每个 `.await`、阻塞读写、锁等待标出来。有挂起点落在里面就先做快照交接，再谈遍历拓扑。对照[定义 11.8.3](ch11.md#def-11.8.3)。
:::

:::

::: ex 卡 21 · 有人只报「无锁快 1.79x」 {#rc-11-21}

卡面：第一行写什么？

::: sol 核对

第一行：要同一份协议的 21 批，并把标准差一起上桌——2.68 走到 8.02 的那一半不能切掉。再确认被测对象是同容量、同起跑条件。对照[定义 11.6.1](ch11.md#def-11.6.1)。
:::

:::

::: ex 卡 22 · 线上 RSS 只涨不跌、泄漏工具查不出 {#rc-11-22}

卡面：第一行写什么？

::: sol 核对

第一行：导出 retired 与 `dropped` 随时间的曲线，找「退休持续、释放为零」的形态，再盘点跨越长耗时操作的 `pin()`。对照 11.7 的 retention 五行日志。
:::

:::

::: ex 卡 23 · 有人问 Wait-Free 是不是更快 {#rc-11-23}

卡面：第一行写什么？

::: sol 核对

第一行：把它买的东西和付的东西分开写——买的是每个线程的步数上限，付的是协助队列与状态登记的常数开销，常规吞吐往往远低于 Lock-Free。对照 11.2.5 的表与[定义 11.1.2](ch11.md#def-11.1.2) 第 3 级。
:::

:::
