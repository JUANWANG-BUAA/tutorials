# 第十章 · 综合自测卷

**闭卷，60 分钟，100 分。**不许查正文、不许跑代码、不许看[回忆卡](ch10_recall.md)。允许一张空白草稿纸。做完先按[评分标准](#ch10-exam-score)自己打分，再逐题对照解答；低于 70 分不要往下读第十一章。

时间分配建议：第一部分 15 分钟，第二部分 20 分钟，第三部分 20 分钟，留 5 分钟检查单位与措辞。

<a id="ch10-exam-p1"></a>

## 第一部分 · 概念辨析（每题 5 分，共 30 分）

判断对错并写一句理由。只写「对/错」不得分。

1. 把不可信插件放进独立子进程，就等于给它做了安全沙箱。
2. 子进程已经退出，读端就一定会读到 EOF。
3. 24 字节协议的 flags 字段当前必须全为 0；要启用某一位，必须升版本。
4. 一次 `read` 返回的字节数少于请求数，说明对端违反了协议。
5. cap 既是进程 RSS 的上限，也是「达到上限就自动杀进程」的开关。
6. persistent case 的计时从 8 字节 ready 握手核对完成之后开始。

## 第三部分 · 设计与表达（共 40 分）

10.（20 分）为一个 4-worker 池写一页设计备忘，至少覆盖：状态与责任（不少于四个状态）、准入与队列容量、执行标识、失败后的不确定性处理、与 10.4 单 worker 数据的可比性。每项写一句「谁负责什么」。

11.（10 分）下面是一段收尾伪代码：

```text
spawn
timeout(deadline, child.wait())
read_to_eof(stdout)
read_to_eof(stderr)
```

helper 会先写 2MiB 到 stdout、再写 2MiB 到 stderr，还可能留下继承写端的后代。指出至少两处缺陷，按 10.7.2 重写顺序，并为每段标一个可观察的成功标志。

12.（10 分）文档写「参数 30ms，所以这个函数最多运行 30ms」。指出三处会让实际时长超过 30ms 的原因，给出端到端预算的拆分方式与一句准确的措辞。

## 解答与给分说明

**1. 错。** 地址空间分离不限制文件、网络、权限与后代；隔离边界的前三行与治理边界之间没有自动蕴含关系，本实验只管理受信任 helper（[定义 10.1.2](ch10.md#def-10.1.2)）。给分：判断 2 分；理由提到「不限制权限/后代/文件网络」任一即得 3 分。

**2. 错。** EOF 的条件是所有写端关闭且缓冲读完；后代可能继续持有写端，直接子进程退出不是 EOF 的充分条件（[定义 10.2.1](ch10.md#def-10.2.1)）。给分：理由必须出现「写端」二字。

**3. 对。** flags 预留位全 0 是当前版本的硬性约束；启用 flag 需要版本升级，旧解码器遇到未知版本必须拒绝而不是猜（[思考 10.3.1](ch10.md#think-10.3.1)）。给分：判断 2 分；提到「升版本 + 旧解码器拒绝」得 3 分，只说「要升版本」得 2 分。

**4. 错。** 管道提供字节流，允许短读；继续读即可，不构成协议违规。只有帧首之后中途 EOF 才是截断（[定义 10.3.2](ch10.md#def-10.3.2)）。给分：理由区分「短读正常」与「帧中途 EOF 才是错」得 3 分。

**5. 错。** cap 只约束 prefix 长度；它不是 RSS 上限（Vec 容量、读块、任务头和内核缓冲都有额外开销），也不是自动杀进程开关（[定义 10.5.2](ch10.md#def-10.5.2)）。给分：两个「不是」各 1.5 分。

**6. 对。** 「已就绪」＝worker 输出 8 字节 `RPCv0001` 并 flush、父进程 read_exact 核对完成；persistent case 从就绪之后计时，创建与握手在计时外（[定义 10.4.2](ch10.md#def-10.4.2)）。给分：理由提到握手核对完成即得 3 分。

**7.（参考，8 分）**
- 计时外三件事：创建 worker、8 字节 ready 握手、批末的 stdin 关闭与 wait（10.4.4 表）。各 1 分，共 3 分。
- 不能写。理由任两条：1219110.006 ns 含握手、往返、校验、关闭与 wait，没有拆出创建成本；本节没有采集动态链接、页错误与用户初始化的分解；它还是 16 次请求墙钟均值的批均值。每条 1 分，共 2 分。
- 结论句 3 分，必须含「本机 macOS ARM64」「固定 release」「极小整数业务」「单 worker 一请求一响应」中的至少三项，并出现「批均值」而非「延迟」。示例：「在本机 macOS ARM64、固定 release 构建、极小整数业务与单 worker 严格一次请求一次响应的条件下，每请求启动的完整生命周期批均值约为单 worker 稳态往返批均值的 222 倍；该比值不引入统计保证。」缺一项限定扣 1 分。

**8.（参考，10 分）**
- 三处问题各 2 分：① 0.001 的均值差小于两组 sd（0.031 与 0.027），方向不稳健；② 本轮没有构造配对差值区间、没有显著性检验、没有 p 值；③ 两个 case 的批 p50 与批 p99 相同，说明这组数据根本没有分辨出固定前缀的速度优势。
- 可发布版本 2 分：「固定前缀正确完成了同样的排空工作，且保留内容大幅减少」；不支持「在所有环境下保证某个百分比加速」（[例 10.6.1](ch10.md#ex-10.6.1)）。
- 单位解释 2 分：ns/聚合输出字节是批墙钟除以 4194304 个聚合输出字节，是聚合吞吐的倒数，两个流在同一轮中可交叠推进，不能当作单字节从写入到用户可见的延迟（[定义 10.6.1](ch10.md#def-10.6.1)）。

**9.（参考，12 分）**
- 四处越界各 2 分：① 360 项与 800 份报告是工程验证，不是独立审计，也不是所有内核交错的证明；② 修复只保护 `run_child` 创建的捕获管道，不能让所有标准库 Command 自动变安全；③ 旧版 macOS 没有 pipe2 时明确返回 Unsupported，不静默退回，所以不存在「所有平台」的等价替换；④ 历史首次事故的唯一归因仍不可证明，普通测试也没有穷尽取消、崩溃与操作系统调度交错。
- 真正支持的结论 4 分：在本机 macOS ARM64、给定交错下，原子 CLOEXEC 版 debug/release 各 4 组通过，gate 见 `pipe2` 和 flags=1、无额外 PIPE；可复验的范围只到 `run_child` 的捕获管道与这组交错（10.7.8、10.7.10）。写成「所有平台的标准库 Command 都已安全」扣满 4 分。

**10.（参考骨架，按五项各 4 分）**
- 状态与责任：starting（握手前不接业务）、ready（接受有限请求）、busy（请求 id 与 worker 代际绑定）、draining（不接新工作并决定在途策略）、failed（标记受影响请求的不确定性）、restarting（递增代际并重新握手）。写满四个即得 4 分。
- 准入与队列容量：每个 worker 输入队列、父进程分发队列、请求正文各算一段容量，说明谁持有内存、满了是阻塞还是拒绝；只写「总并发 4」不得分（10.8.2）。
- 执行标识：`(session, generation, request id)` 三元组；不用 pid，不只比请求 id。
- 失败后的不确定性：写明「可能已提交副作用」的窗口，处理方式是幂等键或提交/确认两段，不是静默重试（[思考 10.8.1](ch10.md#think-10.8.1)）。
- 可比性：本轮 persistent case 无并发在途、无分发排队建模，不能把 5.484 µs 乘或除 worker 数；扩展性要另做实验（[思考 10.4.1](ch10.md#think-10.4.1)）。

**11.（参考，10 分）**
- 缺陷：① `wait` 在读之前，helper 写满 stdout 或 stderr 缓冲后阻塞，wait 永不返回，形成背压停滞；② stdout 与 stderr 串行读，读第一路期间第二路可能写满并卡住写方；③ 没有 grace，后代持有写端时排空会无限等（每项 2 分，共 6 分）。
- 重写顺序 2 分：spawn 前配置 stdin=null、stdout/stderr=piped、kill_on_drop；spawn；取出两个输出端点；启动两个排空任务；`timeout(deadline, child.wait())`，超时则 `start_kill` 再 wait；并发等两个排空任务的 drain_grace，到期 abort 并观察取消；移交 Capture 返回 Report。
- 成功标志 2 分：wait 返回＝直接子进程已回收；grace 内读到 EOF＝该流完整；grace 到期＝部分结果且 `eof=false`。

**12.（参考，10 分）**
- 三处原因各 2 分：spawn 发生在 timeout 构造之前；kill 后的 wait 与输出 grace 还要增加收尾时间；async 计时器本身需要 runtime 获得执行机会。
- 预算拆分 2 分：启动、运行、终止、收尾分别预算，端到端期限按四段相加，而不是只写一个 30ms。
- 措辞 2 分：示例「deadline 只约束 wait 阶段的期限判断；函数从开始到返回的最坏时长还要加上启动、kill 后的 wait 与 grace，并受调度影响」。只写「大约 30ms」不得分。

## 每题落在主线哪一步

分数只告诉你错了几个，这张表告诉你**缺的是哪一步的证据**。[四步主线](../mainline.md#mainline-spine)：① 工作真的发生、② 这个数是什么、③ 差异不是噪声、④ 守得住、可复核。

|:--|:--|:--|:--|
| 1 | ④ | 隔离边界与治理边界是两张表：换地址空间不限制文件、网络、权限与后代 | [定义 10.1.2](ch10.md#def-10.1.2) |
| 2 | ① | EOF 的条件是「所有写端关闭且缓冲读完」，直接子进程退出不是充分条件 | [定义 10.2.1](ch10.md#def-10.2.1) |
