## 八节一览

| 节 | 留下的结论 | 破坏它的最快方式 |
|:--|:--|:--|
| [9.1](ch09.md#sec-cpp-rust.3.9.1) | 一次读-改-写同时决定「谁在跑」和「欠不欠一次 poll」；运行权与通知责任是两条独立的账 | 把队列弹出当成 poll 授权，或先读状态再单独写状态 |
| [9.2](ch09.md#sec-cpp-rust.3.9.2) | 合并通知省的是再次入队，不省可见性；取消是状态登记，`abort` 返回不等于析构 | poll 返回后直接设 idle，或在合并分支删掉 Release |
| [9.3](ch09.md#sec-cpp-rust.3.9.3) | 队列形状是调度策略；LIFO（后入先出）换局部性、风险是饥饿；窃取搬的是任务引用 | 把 256、31、61 当语言常量，或给没打点的窃取定价 |
| [9.4](ch09.md#sec-cpp-rust.3.9.4) | 句柄尺寸不是任务成本；擦除在调度边界，具体 Future 仍被单独生成 | 用 8 字节 `JoinHandle` 估容量，或从 `casal` 的存在算同步占比 |
| [9.5](ch09.md#sec-cpp-rust.3.9.5) | 口径是「一批墙钟 ÷ 1048576 个逻辑 step」；2.602 与 0.750 只能在同一负载内比较 | 把 ns/step 读成一次 poll 或一次 step 的延迟 |
| [9.6](ch09.md#sec-cpp-rust.3.9.6) | 污染是执行权被占住，不是数据竞争；23.658 ms 与 13.633 µs 差在执行域 | 把时间戳放在 `recv` 之后，或用 21 点 p99 承诺生产尾部 |
| [9.7](ch09.md#sec-cpp-rust.3.9.7) | 背压（让上游等一等）约束在途数量；准入在昂贵分配之前；许可与真实工作同寿 | 先 `spawn` 再等 send，或让 permit 随调用方释放 |
| [9.8](ch09.md#sec-cpp-rust.3.9.8) | 公平性是两个有限性前提下的等待上界；慢法按阶段切分，退出逐步观察 | 把 `yield_now` 当指定切换，或把「主函数返回」当全部停止 |

9.9–9.11 不承担新机制，只收口证据与出口：[9.9](ch09.md#sec-cpp-rust.3.9.9) 登记母本与源码核读范围，[9.10](ch09.md#sec-cpp-rust.3.9.10) 把各节 errata 合并成 12 条陷阱，[9.11](ch09.md#sec-cpp-rust.3.9.11) 给出三条复验命令与 8 个应能解释的差异。

## 一条主线

**先立两条账 → 再放进交错 → 再换队列形状 → 再落到字节 → 最后量两种成本、补背压与退出。**

- 9.1 把「通知位」升级成状态字：运行权管谁在跑，通知责任管谁欠一次 poll。
- 9.2 把两条账放进真实交错：丢失唤醒丢进展，双 poll 丢内存安全。
- 9.3 从单个任务转向几百个任务的分布：局部队列、LIFO 槽、窃取与公平性上界。
- 9.4 落到字节与符号：尺寸、擦除、ABI 边界，以及「工作没被折叠」的证据。
- 9.5 量聚合吞吐：128 任务 × 8192 步、500 ms 预热、每 case 21 批。
- 9.6 把观察点收窄到恢复延迟：同一个 20 ms 睡眠，换执行域就从毫秒级落到微秒级。
- 9.7 补另一半：谁被允许进来，许可能活多久。
- 9.8 把前提、观测与收尾写成协议：公平性、阶段时间、退出七步。

任何一环没走完，后面的纳秒数都只是修辞。

## 能否讲出这几句话

不看书，用自己的话回答。答不上来的，回到对应小节只看那一段。

1. 从队列里弹出一个任务，为什么还不算拿到 poll 它的授权？独占权只能从哪里来？
2. 一次 wake 承担哪两项义务？合并通知省掉的是其中哪一项的哪一部分？
3. 2.602 与 0.750 各是什么口径？为什么不能写成「每次调用快了三倍」？
4. offload 的 13.633 µs 为什么不能说明睡眠变短了？它量的到底是哪一段？
5. 容量 64 的有界通道为什么挡不住无限 `spawn`？准入该放在哪一步之前？
6. 公平性承诺的是什么、依赖哪两个前提？它为什么不承诺轮流执行？
