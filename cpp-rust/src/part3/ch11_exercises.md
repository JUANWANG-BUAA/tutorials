# 第11章 · 习题集

共 19 题，分三组。**A 组概念**检验你能否把名词说准；**B 组推理**检验你能否从表格、日志与代码推出结论；**C 组实操**是证明与诊断任务——指出窗口、写出三步、把账算平，不跑基准。全部附解答，较难的题另给提示层。

用法：先写下自己的答案，再展开核对。看解答时先只看第一行，问自己「下一步是不是我会走的」，再往下读。C 组题要求写成可复核的短文，不是写感想。

术语按正文定义：线性化点（调用真正生效的那一瞬间）、位模式（内存里那串二进制值）、分配器（发放与回收堆地址的组件）、缓存行（核之间搬运数据的最小单位）、伪共享（两个独立变量挤在同一行）、探针（测量尺寸与析构次数的小程序）。

## A 组 · 概念（1–7）

::: ex A1 · 三级进度保证（主线 ①） {#ex-11.A.1}

Obstruction-Free、Lock-Free、Wait-Free 各承诺什么？三者按什么方向收紧？

::: sol 解答

Obstruction-Free：挂起其他所有线程后，孤立的单线程能在有限步完成，不保证并发时系统有进展，可能活锁。Lock-Free：无论交错与挂起如何，全局至少有一个线程在有限步取得进展，单个线程可能饥饿。Wait-Free：每个活跃线程都各自有限步返回，无人被无限推迟。方向是从「单线程能走」收紧到「全局总有人走」，再到「每个人都走」。对照[定义 11.1.2](ch11.md#def-11.1.2)。
:::

:::

::: ex A2 · 没有 lock() 就是无锁吗（主线 ①） {#ex-11.A.2}

一段代码只用了 `compare_exchange_weak` 与 `spin_loop`，没有 `lock()` 调用。它能不能被叫作无锁？判定动作是什么？

::: sol 解答

不能凭代码形态判定。判定动作是挂起测试：持锁者被操作系统挂起后，其余线程还能不能在有限步前进。自旋锁在这里直接失败，它连 Obstruction-Free 都不满足，因为临界区仍是排他持有。原子指令只是提交手段，分类依据是进展行为。对照[定义 11.1.2](ch11.md#def-11.1.2)、[例 11.1.1](ch11.md#ex-11.1.1)。
:::

:::

::: ex A3 · 互斥锁的代价拆成几层（主线 ②） {#ex-11.A.3}

写出互斥锁开销的三个层次，并说明自适应锁把哪一层挪到了哪里。

::: sol 解答

一是原子状态争用与总线锁，表现为缓存行在核心之间弹跳。二是内核态上下文切换：自旋若干周期后陷入慢速路径，也就是发起系统调用（把线程交回内核挂起）再等调度器换人；Linux 上是 `futex(FUTEX_WAIT)`，macOS Darwin 上是 `__psynch_mutexwait`，单次通常 1,000 至 5,000 纳秒。三是优先级反转与锁护送。自适应锁先按预算自旋，超预算才发起系统调用，把第二层的触发往后推，但没有取消它。对照[定义 11.1.1](ch11.md#def-11.1.1)、11.1.1、11.1.2。
:::

:::

::: ex A4 · 线性化与顺序一致差在哪一步（主线 ①） {#ex-11.A.4}

写出线性化的三条要求，并说清它与顺序一致性、可串行化各是哪一级放宽。

::: sol 解答

三条：瞬时生效点、逻辑等价性、因果顺序保持。顺序一致性只要求存在某种全局一致的交错，且每个线程内部顺序符合程序序，不要求这个序与墙上时钟吻合。可串行化面向数据库事务调度，只要求结果等价于某种串行执行，连实时因果都不要。三者一级一级放宽：可线性化必是顺序一致的实现，反之不成立。对照[定义 11.2.1](ch11.md#def-11.2.1)、11.2.2。
:::

:::

::: ex A5 · 两类 ABA（主线 ①） {#ex-11.A.5}

逻辑 ABA 与破坏性内存 ABA 各是什么？用什么判据区分，各自怎么处理？

::: sol 解答

逻辑 ABA：纯数值状态字从 A 变 B 又变回 A，比对单元是数值，算法若只关心当前值或靠单调时钟约束，就不破坏内存安全。破坏性内存 ABA：比对单元是裸地址，该地址在快照与提交之间被释放又发放给新对象，过期的拓扑推断被赋权，直接 UAF。判据是两问：是不是指针、该地址是否可能 free 再 malloc。前者用探针验证安全性，后者必须上 SMR 或双字标记。对照[定义 11.3.1](ch11.md#def-11.3.1)、[定义 11.3.2](ch11.md#def-11.3.2)。
:::

:::

::: ex A6 · HP 与 EBR 各保护什么（主线 ①） {#ex-11.A.6}

两者各自把保护粒度落在什么单位上？谁的内存滞留有确定上界？

::: sol 解答

HP 落在单个指针：读者把地址登记进全局 Hazard Slot，写者扫描所有槽位后才 free。EBR 落在时间代际：读者 `pin()` 时盖上门票，代际内任意解引用统一受保。滞留上界：HP 严格为 $O(Threads \times Slots)$，也就是与线程数和插槽数成正比；EBR 无界，一个停在 `Guard` 里的线程就能让垃圾无限积压。代价方向相反：HP 读路径每跳一发写屏障，EBR 只在进出时付费。对照[定义 11.4.2](ch11.md#def-11.4.2)、[定义 11.4.3](ch11.md#def-11.4.3)、11.4.7 表。
:::

:::

::: ex A7 · 伪共享与世代号（主线 ②） {#ex-11.A.7}

伪共享指的是两个逻辑独立变量挤在同一条缓存行里，判定它需要哪两个物理量？`ArrayQueue` 的槽位 stamp 与 11.3 的 Tagged Pointer 都在防过期，机制差在哪？

::: sol 解答

判定需要各字段的 `size_of`/`align_of` 与宿主的 `hw.cachelinesize`，本书实测机是 128 字节。Tagged Pointer 防的是指针 CAS 误提交：地址相同、Tag 不同即拒绝，保护单字比对。stamp 防的是槽位轮次误读写：轮次被编进每格的状态条，读写授权按值匹配，保护访问权限而非指针。前者防 ABA 事故，后者让 ABA 无从成立。对照[定义 11.5.1](ch11.md#def-11.5.1)、[定义 11.5.2](ch11.md#def-11.5.2)。
:::

:::

## B 组 · 推理（8–14）

::: ex B8 · 一张表里读出两件事（主线 ③） {#ex-11.B.8}

queue 实验汇总表给出两行：`Mutex<VecDeque>` 均值 72.861686、sd 2.683101、p50 72.586060、p99 78.983948；`ArrayQueue` 均值 40.647478、sd 8.023660、p50 40.676117、p99 53.237915。有人只摘「快 79.3%」。这一半证据丢了什么？补上之后结论该怎么写？

::: sol 解答

丢掉的是确定性那一半：标准差从 2.68 放大到 8.02。补上之后能写的是「在 2 生产 2 消费、1024 容量、21 批交替的协议下，批均值改善，同时批次间波动变大」。不能写「延迟全面更好」，因为均值回答吞吐，sd 回答批次抖动，两者是两个维度。硬实时场景里「方差小」本身就是性能指标。对照[定义 1.5.2](../part1/ch01.md#def-1.5.2)、[例 11.6.1](ch11.md#ex-11.6.1)。
:::

:::

::: ex B9 · 最快的批次与最慢的批次（主线 ③） {#ex-11.B.9}

21 批里 Round 5 是 25.574、Round 7 是 53.238，均值却是 40.647478。这三个数能不能拼成「稳定跑到 25ns」？如果同事要求删掉 Round 7，按本章的纪律该问什么？

::: sol 解答

不能。25.574 是 21 批里最快的一批，原文归因为「线程交错极度协调，无碰撞重试」；53.238 是最慢一批，归因为「CAS 发生连续碰撞，自旋重试放大耗时」。单点最优值不能当稳态，均值仍是 40.65。删点要先问「支持这是外部干扰的独立证据是什么」，写不出来就不删；有证据也要整对处理并同时报告两种情况。对照 11.6.3 表、[定义 11.6.1](ch11.md#def-11.6.1)。
:::

:::

::: ex B10 · 五行日志的算术（主线 ①） {#ex-11.B.10}

日志为 `retention,batch=4,retired=4096,dropped=0,payload_bytes=1048576`，末行 `retention,after_unpin,dropped=4096`。`payload_bytes` 与 `retired` 是什么算术关系？这行日志证明了什么、没证明什么？

::: sol 解答

$4096 \times 256 = 1{,}048{,}576$，逐字节吻合：每个探针对象带 256 字节载荷，4096 个全部滞留在堆上，一个都没释放。它证明「没释放」，不证明「额外占了多少」——垃圾袋自身的簿记内存与分配器元数据不在探针计量内。所以这份日志不能读成 RSS。末行说明撕票之后积压对象在一次代际推进里集中销毁。对照[例 11.7.1](ch11.md#ex-11.7.1)、11.7.3。
:::

:::

::: ex B11 · 36.9% 能拆到哪一层（主线 ②） {#ex-11.B.11}

`stalled_pin` 均值 22.967872、`short_pin` 16.773780，差 36.9%。能不能说「慢在扫描垃圾袋」？

::: hint 提示

钱是两笔总账相减得来的。要拆到机制层，缺的是哪一类观测？

:::

::: sol 解答

不能。实验只采集了两个场景的单批耗时，没有逐阶段分解：「pin 的成本」「defer 的成本」「推进尝试的成本」各占多少，本章没有采集。36.9% 是总账，只能说更慢，不能说慢在哪一步。要拆开得新做实验，把三个阶段各自计时。对照[例 11.7.1](ch11.md#ex-11.7.1)、11.7.4 小结。
:::

:::

::: ex B12 · 尺寸表能支撑什么（主线 ②） {#ex-11.B.12}

探针表给出 `ArrayQueue<u64>` 384/128、`Guard` 8/8、`Arc<[u8]>` 16/8、`Vec<u8>` 24/8、`AtomicPtr<u64>` 8/8。哪些行能支撑「头尾索引与缓冲区彻底隔离」这句话？`Guard` 是 8/8，是不是说明它不重要？

::: sol 解答

支撑这句话的是 `ArrayQueue` 那一行的 384 字节大小与 128 字节对齐：对齐值等于实测缓存行，说明它按整行填充把高频字段分开。`Guard` 8/8 说明它内部只包含线程本地代际句柄的轻量引用，适合在栈上高频传递；对齐 8 是因为它不与别的线程争同一条缓存行的原子字，不是因为它不重要。`Arc<[u8]>` 16 与 `Vec<u8>` 24 分别是胖指针与三字结构的自然尺寸。对照 11.5.1 表、[例 11.5.1](ch11.md#ex-11.5.1)。
:::

:::

::: ex B13 · async 读侧的驻留期（主线 ①） {#ex-11.B.13}

`bad_async_rcu_reader` 在 `pin()` 之后 `.await` 取远端数据，取回后才 `process`。驻留期覆盖了什么？后果有哪两类？这 30 秒里能报出 `dropped` 的数字吗？

::: sol 解答

驻留期覆盖取数、等对端、回包与 `process` 全过程，长度由对端决定，函数体管不住。后果两类：持有期不可控，全局代际回收被封冻直到回包；多线程运行时可能把任务窃取到另一个工作线程，`Guard` 绑定的线程局部状态对不上，代际计数竞态甚至断言崩溃。数字不能报：实测的 4096 个对象、1,048,576 字节是同步 `stalled_pin` 场景，async 版本的滞留量本章没有采集，只能给形态。对照[定义 11.8.3](ch11.md#def-11.8.3)、[例 11.8.1](ch11.md#ex-11.8.1)。
:::

:::

::: ex B14 · 两个「够用了」（主线 ①） {#ex-11.B.14}

「16 位偷借 Tag 够用了」与「有了双字原子就不用 SMR」这两句，各错在哪一格？

::: hint 提示

一句错在取值空间会绕回来，一句错在 Tag 证明的是哪个命题。

:::

::: sol 解答

第一句错在位宽：16 位只有 65536 个取值，高吞吐栈每轮分配与释放都推 Tag，绕满一圈后 (地址, tag) 可能整体重合，ABA 原样复发；具体门槛本章没有采集。第二句错在命题范围：Tag 只证明「这个字没被别的 CAS 改过」，不证明「指针指向的内存还活着」，节点已 free 而地址未复用时仍可能写出悬垂地址。Tag 防检测、SMR 防事故，两者互补。对照[例 11.3.1](ch11.md#ex-11.3.1)、[思考 11.3.1](ch11.md#think-11.3.1)。
:::

## C 组 · 实操（15–19）

这一组是证明与诊断题：找出一个窗口、写出三步协议、把一笔账驳倒或算平。答案要能贴进 code review 或事故报告。

::: ex C15 · 指出一个 ABA 窗口（主线 ①） {#ex-11.C.15}

取本章的 `pop_broken`：先 `load` 得 `curr`，读 `(*curr).next` 得 `next_ptr`，再 `compare_exchange_weak(curr, next_ptr)`。要求：① 指出窗口落在哪两行之间；② 构造五步事故链，写清每步是谁做的；③ 给出两条修复路线与各自代价；④ 说明为什么把 `Ordering` 全改成 `SeqCst` 不算修复。

::: hint 提示

窗口里发生的事不是「值变了」，而是「地址被回收又发放」。五步链的第三步是分配器，不是线程。

:::

::: sol 参考路径

① 窗口在读到 `(*curr).next` 之后、`compare_exchange_weak` 之前。② 链条：线程 1 读快照 `curr=0x1000`、`next_ptr=0x2000`；被时钟中断挂起；线程 2 连续两次 `pop()`，`Box::from_raw` 把 0x1000 与 0x2000 归还分配器；分配器出于缓存局部性把 0x1000 重新分配给新节点 A′，拓扑变成 A′→D→C；线程 1 恢复，CAS 的 `expected=0x1000` 比对成功，`head` 被写成早已释放的 0x2000，D 与 C 整段丢失。③ 路线一：带 Tag 的双字原子，必须保证 16 字节对齐；代价是 128 位原子在部分架构开销可观，且短位宽会绕回。路线二：接入 SMR，让释放推迟到所有观测者退场；代价是读路径或驻留期管理成本。④ 顺序强度管可见性，不管生命周期：地址被复用是因果问题，内存序再强也拦不住。对照[定义 11.3.2](ch11.md#def-11.3.2)、11.3.2 图 11-1、11.3.5。
:::

:::

::: ex C16 · 写出一次 hazard-pointer 读取的三步（主线 ①） {#ex-11.C.16}

读者要解引用写者刚摘除的节点 P。要求按「发布—校验—再读取」写出三步，标出屏障位置与失败分支，并解释屏障为什么不能挪到最后补。

::: hint 提示

屏障保护的不是读者的访问，而是写者扫描的时机。谁看见了空槽位，谁就会合法地 free。

:::

::: sol 参考路径

第一步发布：`slots[idx].store(P, Release)`，把 P 写进线程私有的 Hazard Slot。第二步屏障加校验：下发 `SeqCst` 全屏障（AArch64 是 `dmb ish`，x86 是 `mfence`），再确认 P 是否仍在共享结构中；若已被摘除，清空槽位、回到读取指针重来。第三步再读取：确认 P 仍有效后解引用；用完 `unprotect` 把槽位写回空指针。失败分支只有一个——槽位清空后重试整个循环。屏障不能后补：写者扫描时若登记还压在 Store Buffer 里，它看到的是空槽位，于是合法地释放读者正要用的节点；事后补屏障保护的是一场已经发生的事故。对照[定义 11.4.2](ch11.md#def-11.4.2)、[思考 11.4.1](ch11.md#think-11.4.1)、11.4.3。
:::

:::

::: ex C17 · 为什么回收比 CAS 更难（主线 ①） {#ex-11.C.17}

写一段不超过五句的论证，说明「无锁的难点在回收，不在 CAS」。要求：用本章的实测形态做证据，并指出 CAS 与回收各自缺的那一个信息。

::: hint 提示

CAS 缺的是「谁还看着」；回收缺的是「谁已经看完」。前者是单点比对，后者要靠全场投票。

:::

::: sol 参考路径

CAS 只需要一个信息：目标单元的位模式还是不是预期值，这是单点、瞬时的判断。回收需要另一个信息：还有多少线程可能正看着这块内存，这是全场、跨时间的判断，而且没有哪个线程的局部状态能单独给出答案。证据形态：一张不撕的旧门票就足以让回收冻结——4096 个 256 字节对象、1,048,576 字节滞留，`dropped` 恒为 0，撕票瞬间一次性释放 4096 个。同一份工作里 CAS 全部成功、断言全部通过，所以「正确」与「能回收」是两个问题。代价也分头记：CAS 的失败是重试，回收的失败是内存只涨不跌。对照[定义 11.1.3](ch11.md#def-11.1.3)、[定义 11.4.1](ch11.md#def-11.4.1)、11.7.3。
:::

:::

::: ex C18 · 线性化点审计（主线 ①） {#ex-11.C.18}

对 Michael-Scott 队列做一次审计：① 列出 `push` 与 `pop` 各自的成功与失败出口；② 指出每条出口的线性化点；③ 判断「`push(A)` 尚未返回时 `pop()` 返回空」是否合法，并说明依据是定义的第几条。

::: sol 参考路径

① `push` 出口：CAS `tail.next` 成功（继续推进 `tail`）、CAS 失败重读；`pop` 出口：CAS `head` 成功、`head.next` 为 `null`（判空）、CAS 失败重读。② 入队线性化点是 CAS 把 `tail.next` 从 `null` 改为 `X` 那条指令，不是更新 `tail` 的那条；出队线性化点是 CAS 把 `head` 前移那条；判空点是原子读取 `head.next` 并判定为 `null` 的瞬间。③ 合法：两个操作的时间区间重叠，`pop` 的线性化点可以落在 `push` 的线性化点之前。依据是定义 11.2.1 第 1、2 条；若 `push` 已物理返回，则受第 3 条因果保持约束，返回空不合法。对照 11.2.3、[例 11.2.1](ch11.md#ex-11.2.1)、[定义 11.2.1](ch11.md#def-11.2.1)。
:::

:::

::: ex C19 · 把驻留期写成容量预算（主线 ④） {#ex-11.C.19}

一个服务在 `pin()` 的保护下查到索引项，随后发 HTTP 请求，RSS 持续上涨。要求：① 画出驻留期，标出挂起点；② 写最小修复；③ 写验证动作；④ 说明为什么不能给出「修复后滞留多少字节」这个数。

::: hint 提示

修复的动作只有一个方向：缩短驻留期，不是加检查。验证看的是 retired 与 dropped 两条曲线是否重新分开。

:::

::: sol 参考路径

① 驻留期从 `pin()` 起，覆盖查找、发请求、等回包、处理响应，挂起点就是那个 `.await`。② 在 `Guard` 里只做查找并克隆 `Arc` 或值快照，`drop(guard)` 之后才 await；恢复后若还要读共享结构，重新 `pin()` 拿当前代际的新票。③ 测试构建里导出 retired 与 dropped 曲线，对照 11.7 的 retention 模板看释放是否恢复；线上先盘点所有跨越挂起点的 `pin()` 路径。④ 同步 `stalled_pin` 的 1,048,576 字节是 4096 个 256 字节探针的实测，async 版本的滞留量本章没有采集，只能给形态不能给字节数。对照[定义 11.8.3](ch11.md#def-11.8.3)、[例 11.8.1](ch11.md#ex-11.8.1)、11.8.3。
:::

## 批改时最常给的三条意见

1. **把「无锁」当形容词用**：先跑挂起测试再给结论，说清哪一级，别用「比较无锁」代替定级。见[定义 11.1.2](ch11.md#def-11.1.2)。
2. **只报一半证据**：增速与抖动、退休与释放、命中与滞留，永远成对出现。只给一个数就是切掉证据的一半。见[例 11.6.1](ch11.md#ex-11.6.1)。
3. **结论超出采集范围**：36.9% 拆不到阶段、async 版本没有字节数、HP 读路径没有实测——没采到的量不要写成结论。见[例 11.7.1](ch11.md#ex-11.7.1)。
