# 第12章 · 习题集

共 21 题，分三组。**A 组概念**检验你能否说出名词指的是什么；**B 组推理**检验你能否从数据或汇编推出结论；**C 组实操**要求你真的跑归档、开诊断、写契约。全部题目附解答，难题另附提示层。

用法约定：先写下自己的答案，再展开核对。看解答时只看第一行就停住，问自己「接下来那一步是不是我要走的」，再往下读。直接通读解答，得到的只是「看懂了」，不是「会做了」。

术语先对齐：向量化（把一条指令同时用于多个数据）、零拷贝（只传指针与长度，不复制字节）、分配器（发放与回收堆内存的组件）、寄存器（CPU 里直接存取的那几个槽位）。

## A 组 · 概念（1–8）

::: ex A1 · 三堵墙与一条出路（主线 ②） {#ex-12.A.1}

标量循环撞的三堵墙分别是什么？撞上「指令吞吐墙」之后，为什么继续堆算力没有收益？

::: sol 解答

三堵墙是发射槽、寄存器写端口、内存访问延迟。吞吐墙指算术单元还有空闲，但每周期能译码、发射、引退的指令数已经到硬件上限；此时加算力只是让更多指令排队。唯一出路是让一条指令携带更多数据，这就是 SIMD 的全部动机。循环展开只消掉分支，微操作仍要抢同一批重命名槽与 ROB。对照[定义 12.1.1](ch12.md#def-12.1.1)。

:::

:::

::: ex A2 · 数车道（主线 ②） {#ex-12.A.2}

128 位 NEON 寄存器按 `u8`、`u16`、`u32`、`u64` 各是几条车道？512 位寄存器按 `u64` 呢？为什么 12.6 的实验按 4 车道规划主循环？

::: sol 解答

128 位按 `u8` 是 16 条，按 `u16` 是 8 条，按 `u32` 是 4 条，按 `u64` 是 2 条；512 位按 `u64` 是 8 条（512 ÷ 64）。车道数永远是位宽除以元素位宽，与寄存器叫 ZMM 还是 YMM 无关。实验机是 Apple M5 Pro 的 NEON，128 位，`u32` 车道数 4，所以手写内核每次步进 4 个元素。对照[定义 12.1.2](ch12.md#def-12.1.2)、[例 12.1.1](ch12.md#ex-12.1.1)。

:::

:::

::: ex A3 · 四类障碍（主线 ①） {#ex-12.A.3}

阻碍自动向量化的四类障碍是什么？Rust 在别名这一类上占的便宜具体来自哪里？

::: sol 解答

① 指针别名模糊：输入输出可能重叠时，向量化会破坏写后读；② 循环携带依赖；③ 迭代边界或步长不可预测，含不可预测的 `break`、提前返回、可能 panic 的边界检查；④ 非连续或跨步访问，编译器要么放弃，要么付出 Gather/Scatter 的代价。Rust 的优势是借用规则让 `&T` 与 `&mut T` 永不共存，编译器可直接向 LLVM 标注 `noalias`，不需要 C 的 `restrict` 注解。对照[定义 12.2.1](ch12.md#def-12.2.1)、[定义 12.2.2](ch12.md#def-12.2.2)。

:::

:::

::: ex A4 · 浮点为什么默认不向量化（主线 ①） {#ex-12.A.4}

`sum += a[i]` 这样的浮点累加为什么默认不被向量化？两个授权入口是什么，授权之后谁负责数值确定性？

::: sol 解答

浮点加法在数学上不满足结合律，向量化把串行累加改成多车道再求和，括号顺序变了，结果会出现 ULP 级偏离。默认 IEEE 754 模式下编译器宁可退回标量。授权入口是 `-C fp-contract=fast` 与未稳定的 `core::intrinsics::fadd_fast`。授权之后数值确定性由使用者负责，数值验收要改成允许 ULP 差的测试。对照[定义 12.2.3](ch12.md#def-12.2.3)。

:::

:::

::: ex A5 · 三步封装（主线 ①） {#ex-12.A.5}

安全地使用手写内核要有哪三步？跳过「探测」这一步，危险会跑到哪里去？

::: sol 解答

① 入口用 `is_aarch64_feature_detected!("neon")` 或 `is_x86_feature_detected!("avx2")` 建立运行时凭证；② 把指令集使用圈在 `#[target_feature(enable = "...")]` 的 `unsafe fn` 里；③ 探测失败走标量或自动向量化回退。少了探测，二进制把只属于某代 CPU 的指令编进所有机器都会执行的路径，旧机器上直接 `SIGILL`。全局 `-C target-feature` 开关同样抹掉了凭证与回退。对照[定义 12.3.2](ch12.md#def-12.3.2)。

:::

:::

::: ex A6 · 胖指针与零拷贝（主线 ②） {#ex-12.A.6}

切片视图在 ABI 上是几个字节、由哪两部分组成？「零拷贝」省掉的到底是哪几步？

::: sol 解答

16 字节：一个指针字加一个长度字。切分与传递只动这两个字，不动底层字节。把同样的 100 字节帧改成拥有型 `Vec`，要多出一次 `malloc`、一次逐字节 `memcpy`、以及离开作用域时一次 `free`；12.7 的 `owned_copy` 每帧就走这一遍。对照[定义 12.4.1](ch12.md#def-12.4.1)。

:::

:::

::: ex A7 · 尺寸与对齐（主线 ②） {#ex-12.A.7}

`[u32; 4]` 的尺寸与对齐各是多少？为什么对齐不是 16？知道它是 16 字节，能推出「循环里一定被展开成一条向量指令」吗？

::: sol 解答

尺寸 16 字节，对齐 4 字节。对齐由元素 `u32` 决定，数组不提高对齐要求，总尺寸是 4 × 4 而对齐仍是 4。16 字节可以一次装进 128 位向量寄存器，但「可以装进去」不等于「一定装进去」：装不装要看上下文与寄存器压力，只有编译产物能回答。对照[定义 12.5.1](ch12.md#def-12.5.1)。

:::

:::

::: ex A8 · 两种通知模型（主线 ①） {#ex-12.A.8}

就绪通知与完成通知的差别用一句话怎么说？为什么这个差别会改掉缓冲区的生命周期要求？

::: sol 解答

就绪通知只说「这个描述符现在可以读写」，搬运仍由用户发 `read()` 完成；完成通知要求用户先提交一个带缓冲区的请求，内核搬完再报告。前者内核只在 `read()` 期间碰缓冲区，后者在提交那一刻就拿到了指针，归属期从「一次调用」拉长到「一次提交」，所以借用型签名在完成型接口下不成立。对照[定义 12.8.1](ch12.md#def-12.8.1)。

:::

:::

## B 组 · 推理（9–16）

::: ex B9 · 7.73 倍归到谁头上（主线 ②） {#ex-12.B.9}

`scalar_call` 批均值 0.535004，`auto` 0.069184，`neon` 0.069965，单位 ns/元素。算出两个倍数，并说明第一个倍数支持哪个工程决策、不支持哪个。

::: sol 解答

`0.535004 ÷ 0.069184 = 7.733`，即 7.73 倍；`0.535004 ÷ 0.069965 = 7.647`，即 7.65 倍。第一个倍数支持「把逐元素热路径上的函数调用去掉」——`scalar_call` 每个元素都要走一次 `bl` 与一次栈帧，`auto` 与 `neon` 都把这一步消掉了。它不支持「向量化带来 7.73 倍」，也不支持「手写优于自动」：调用开销与向量化收益没有拆开，本节没有采集周期数。对照[定义 12.6.4](ch12.md#def-12.6.4)。

:::

:::

::: ex B10 · 1.1% 能不能排座次（主线 ③） {#ex-12.B.10}

`auto` 比 `neon` 低 0.000781 ns/元素。两者标准差是 0.003189 与 0.003086。请判断这个差能不能分出来，并写出唯一能下的结论。

::: sol 解答

差 0.000781 ÷ 0.069965 ≈ 1.1%，而标准差相对均值约 4.6% 与 4.4%，比均值差还大；归档也没有做配对差值、没有区间。按三态判定属于「证据不足」，不能写「自动更强」。能写的是：在这台机器、这个构建、这组输入上，两者没有分出方向；要分方向得用配对设计重采，本节没有采集。对照[定义 12.6.2](ch12.md#def-12.6.2)。

:::

:::

::: ex B11 · 65539 的尾部账（主线 ②） {#ex-12.B.11}

`N = 65539`。NEON 内核按 4 步进、AVX2 内核按 8 步进，主循环各跑多少轮、尾部各剩几个元素？如果把 `q` 寄存器换成 `d`、`4s` 换成 `2s`，尾部变成几个？

::: hint 提示

先做除法：`65539 = 4 × 16384 + 3`。换寄存器只改车道数，元素总数不变。

:::

::: sol 解答

`65539 = 4 × 16384 + 3 = 8 × 8192 + 3`，所以 NEON 主循环 16384 轮、AVX2 8192 轮，两个内核都剩 3 个尾部元素；实验取这个长度，正是要让每条实现都必须走进清理分支并被校验和抓住。换成 2 车道后主循环 32769 轮、尾部 1 个元素。对照[例 12.3.1](ch12.md#ex-12.3.1)、[例 12.5.1](ch12.md#ex-12.5.1)。

:::

:::

::: ex B12 · p50 与 p99 来自哪一轮（主线 ②） {#ex-12.B.12}

三种实现的 p50 分别来自第 7、19、6 轮，三个 p99 来自第 15、15、13 轮。为什么不能把这些数当成「中间那一轮」或「某一轮的读数」？

::: sol 解答

因为它们是排序后的样本，不是时间序列上的某一轮。nearest-rank 把 21 个数排序后取第 `ceil(21 × p)` 个：p50 是第 11 个，p99 是第 21 个，也就是最大值。21 个样本上的 p99 没有尾部含义，只描述某一轮；把它当生产尾延迟需要另一套采集设计，本节没有采集。对照[定义 12.6.3](ch12.md#def-12.6.3)。

:::

:::

::: ex B13 · 22 纳秒花在哪（主线 ②） {#ex-12.B.13}

`owned_copy` 30.635765、`borrowed_view` 8.510533 ns/帧，差 22.125232。这 22.1 ns 能不能全记在 `memcpy` 头上？帧长缩到 16 字节，差值会变成多少？

::: hint 提示

`to_vec()` 在分配器里走四步，`memcpy` 只是第三步。

:::

::: sol 解答

不能。它含分配、簿记、拷贝、释放四段，本节没有把四段拆开采集，只能读作「一次拥有化路径减一次借用路径」的整包差价。16 字节帧本节没有采集，能推断的只有方向：`memcpy` 那段跟着字节数缩小，分配那段基本不变；比例没有测，不写数字。同理，这个差值也不能用来推内存带宽。对照[定义 12.7.1](ch12.md#def-12.7.1)、[例 12.7.1](ch12.md#ex-12.7.1)。

:::

:::

::: ex B14 · 21 批底账读出了什么（主线 ③） {#ex-12.B.14}

逐批比值落在 3.31 到 3.72 之间。最慢批、最快批分别是第几批？借用侧最慢的批与拥有侧最慢的批是同一批吗？「每帧省 22.125232 ns」能不能直接乘一百万帧当总收益？

::: sol 解答

最慢批是第 9 批（31.352），最快批是第 20 批（30.202）；借用侧最慢是第 8 批（9.155），与拥有侧最慢批不是同一批。21 批没有一批出现方向反转，说明在这个配置下方向稳定。乘百万帧可以算，但要写明前提：倍数只在 1024 字节帧与稀疏消费下成立，本节没有采集网关侧的端到端指标，乘出来的总收益属于外推。对照[例 12.7.2](ch12.md#ex-12.7.2)。

:::

:::

::: ex B15 · 8 行汇编能证明什么（主线 ①） {#ex-12.B.15}

`neon_inner` 的循环主体是 8 行，其中 3 条搬数据。为什么不能说「循环体只消耗 3 条指令」？又为什么不能用这份 `.s` 解释 12.6 的计时？

::: sol 解答

3 条是数据指令（`ldr`、`mla`、`str`），把常量 `movi.4s v2` 与控制用的 `sub`/`add`/`cmp`/`b.hi` 算进去是 8 条；说成 3 条会让人误以为循环开销为零。这份 `.ll`/`.s` 由 `cargo rustc --lib --emit=mir,llvm-ir,asm` 产生，而最终二进制还经过 thin LTO，归档没有保留最终二进制的反汇编，所以「auto 也被展开成 4 车道」这句话本节没有代码生成证据。产物只对生成它的那次构建负责。对照[定义 12.5.2](ch12.md#def-12.5.2)。

:::

:::

::: ex B16 · 取消之后谁还在写（主线 ①） {#ex-12.B.16}

一个读请求已提交进 SQ，`tokio::select!` 的超时分支先完成，持有 `buf` 的 Future 被 `drop`。内核知道这件事吗？把 `buf` 改成按值传进请求，问题就全消失了吗？

::: hint 提示

SQE 里只有地址、长度与 `user_data`，没有「撤回」字段。

:::

::: sol 解答

内核不知道。SQE 里没有任何字段能撤回已下发的硬件操作，网卡按提交时拿到的地址继续写，落到已被复用的对象上，这是 DMA 版的释放后使用，编译器看不见、运行时也不报错。按值传只挡住「提前释放」这一种：所有权移入后缓冲区不能就地释放，得在 `Drop` 里送进泄漏池，等对应 CQE 返回再真正释放；泄漏池无人收割就变成内存泄漏。对照[例 12.8.1](ch12.md#ex-12.8.1)、[定义 12.8.4](ch12.md#def-12.8.4)。

:::

::: ex C18 · 让 remark 自己交代（主线 ①） {#ex-12.C.18}

在 `bench/systems-lab` 下用 `RUSTFLAGS` 打开循环向量化诊断，构建一次，记录三条不同类型的 remark，并说明每条对应四类障碍里的哪一类。

::: hint 提示

命令是 `RUSTFLAGS="-C remark=loop-vectorize -C pass-remarks-analysis=loop-vectorize -C pass-remarks-missed=loop-vectorize" cargo build --release`。

:::

::: sol 参考路径

正文给的三类输出是：`loop vectorized (width: 4, unroll: 2)` 表示成功并展开 2 轮；`could not prove that the loop-carried dependencies allow vectorization` 对应携带依赖；`cannot identify array bounds` 对应边界不可预测。别名与跨步访问可能没有单独一行，要结合代码判断。remark 只是该 pass 当时的判断，后续流水线仍可能改写，最终要看优化后 IR 与汇编。对照[定义 12.2.1](ch12.md#def-12.2.1)、[定义 12.2.2](ch12.md#def-12.2.2)。

::: ex C19 · 把长度改成 65536（主线 ②） {#ex-12.C.19}

如果把 `N` 从 65539 改成 65536，主循环轮数与尾部元素数各变成多少？校验和还能沿用 140746630219670 吗？这个改动能不能直接拿来证明「尾部开销有多大」？

::: sol 参考路径

65536 = 4 × 16384，NEON 主循环仍是 16384 轮，尾部变成 0 个元素；AVX2 是 8 × 8192，同样没有尾部。校验和必须重算——输入长度变了，逐元素校验和必然不同，不能沿用 140746630219670。要证明尾部开销，得在同一夹具下分别跑两种长度并做配对，本节没有这组数据；只能说这个改动让清理分支不再被执行。对照[例 12.3.1](ch12.md#ex-12.3.1)。

::: ex C20 · 给 64 字节帧写契约（主线 ④） {#ex-12.C.20}

你的解析器每帧 64 字节（4 字节头加 60 字节载荷），也在用 `to_vec()`。写一份对照实验契约：输入、计时边界、观察方式、外部条件与 CSV 字段、判定规则。并说明能不能直接引用 3.60 倍。

::: sol 参考路径

## 批改时最常给的三条意见

1. **倍数越界**：把 7.73 倍说成向量化收益、把 3.60 倍说成 `to_vec()` 的通用价格。给倍数补上它量的是哪两件事，以及帧长、消费密度、线程数。
2. **拿极值当分布**：把 21 个样本的 p99 当生产尾延迟，把某一轮的读数当稳态。先写样本量，再写它只是最大值。
3. **层与层互相顶替**：拿 `size_of` 推速度、拿 rlib 的 `.s` 解释最终二进制、拿 remark 当落地凭证。按 12.5 的顺序，先问尺寸、再问产物、最后问计时。
