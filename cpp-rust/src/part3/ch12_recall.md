# 第12章 · 闭卷回忆卡

「看懂」只说明答案在眼前时能识别；评审与排障要的是从空白纸上提取。这一页把第十二章拆成 24 张卡，先读卡面自己答，再展开核对。

术语先对齐：向量化（把一条指令同时用于多个数据）、零拷贝（只传指针与长度，不复制字节）、系统调用（用户程序请内核代做一步操作）、分配器（发放与回收堆内存的组件）、缓存行（核之间搬数据的最小单位）、内联（把函数体搬进调用点）、寄存器（CPU 里直接存取的那几个槽位）。

**用法与节奏**

| 时点 | 做什么 | 判定 |
|:--|:--|:--|
| 学完当天 | 第一组「定义卡」8 张 | 关键词写全才算 ✓ |
| 第 1 天 | 第二组「结论卡」10 张 | 能说清前提才算 ✓ |
| 第 3 天 | 第三组「第一行卡」6 张 | 写出第一步才算 ✓ |
| 第 7 天 | 只重做标成 △ 和 × 的卡 | 全对即可进入下一章 |

每张卡给自己一个记号：✓ 一次说对；△ 说对一半或要提示；× 想不起来。只重做 △ 和 ×，不要把整叠卡反复过一遍——那是在读，不是在提取。

## 第一组 · 定义卡（说全称与前提）

::: ex 卡 1 · 指令吞吐墙 {#rc-12-1}

卡面：什么叫指令吞吐墙？撞墙之后为什么继续堆算力没有收益？

::: sol 核对

算术单元还有空闲，但每周期能译码、发射、引退的指令数已经到硬件上限。撞墙后堆算力没有收益，唯一出路是让一条指令携带更多数据。标量循环展开只消掉分支，译码、重命名、ROB 与写端口仍是同一批物理资源。对照[定义 12.1.1](ch12.md#def-12.1.1)。
:::

:::

::: ex 卡 2 · 车道与位宽 {#rc-12-2}

卡面：车道数怎么算？128 位 NEON 寄存器有哪四种视图？

::: sol 核对

车道数 = 向量位宽 ÷ 元素位宽。同一个 128 位寄存器按 `v0.16b` 是 16 个 8 位车道，按 `v0.8h` 是 8 个 16 位，按 `v0.4s` 是 4 个 32 位，按 `v0.2d` 是 2 个 64 位。视图错配就读错了数据。对照[定义 12.1.2](ch12.md#def-12.1.2)。
:::

:::

::: ex 卡 3 · 自动向量化的两条通道与本质 {#rc-12-3}

卡面：两条向量化通道各作用于什么？「自动向量化」的本质是什么？

::: sol 核对

循环向量化器作用于连续迭代的循环或迭代器链，带首尾清理块；SLP 向量化器在基础块内部找独立同构的标量运算，打包成一条向量指令。本质是一次等价性证明：改写前后每个元素的结果必须一致，证不出就退回标量。对照[定义 12.2.1](ch12.md#def-12.2.1)。
:::

:::

::: ex 卡 4 · 循环携带依赖 {#rc-12-4}

卡面：什么是循环携带依赖？本章的 benchmark 为什么刻意避开它？

::: sol 核对

后一次迭代要等前一次的结果才能开始，例如 `x_i = x_{i-1} × 3 + 7`。这是迭代之间的串行链，车道之间没有可独立分配的同构工作，向量化器无从并行。本章选的是不含携带依赖的逐元素映射 `output[i] = input[i] × 3 + 7`。对照[定义 12.2.2](ch12.md#def-12.2.2)。
:::

:::

::: ex 卡 5 · 浮点非结合律与 fast-math {#rc-12-5}

卡面：为什么浮点累加循环默认不被向量化？两个授权入口是什么？

::: sol 核对

有限精度舍入让浮点加法不满足结合律，向量化会改变括号顺序，结果出现 ULP 级偏离。默认 IEEE 754 模式下编译器保守拒绝。授权入口有两个：`-C fp-contract=fast`（允许硬件融合乘加）与未稳定的 `core::intrinsics::fadd_fast`（显式允许代数重排）。授权之后数值确定性由你负责。对照[定义 12.2.3](ch12.md#def-12.2.3)。
:::

:::

::: ex 卡 6 · 内联函数的边界 {#rc-12-6}

卡面：内联函数是什么？调用它时哪些前提要自己证明？

::: sol 核对

它是编译器提供的一层薄封装，函数体基本对应一条硬件指令，例如 `vld1q_u32` 对应一次向量加载，放在 `core::arch` 的平台模块里。调用它通常意味着 `unsafe`：边界、对齐、非重叠都要由调用方证明。对照[定义 12.3.1](ch12.md#def-12.3.1)。
:::

:::

::: ex 卡 7 · target_feature 的三步 {#rc-12-7}

卡面：安全封装带 `target_feature` 的内核，要有哪三步？为什么它强制 `unsafe fn`？

::: sol 核对

① 调用前用 `is_x86_feature_detected!` 或 `is_aarch64_feature_detected!` 建立运行时凭证；② 用 `#[target_feature(enable = "...")]` 的 `unsafe fn` 圈定危险范围；③ 探测失败时走标量或自动向量化回退。强制 `unsafe` 的原因是硬件：宿主没有该流水线时调用会触发非法指令，内核随即杀死进程。对照[定义 12.3.2](ch12.md#def-12.3.2)。
:::

:::

::: ex 卡 8 · 胖指针与生命周期级联 {#rc-12-8}

卡面：切片视图在 ABI 上是什么形状？`'a` 级联之后，约束怎么传播？

::: sol 核对

一个指针字加一个长度字，共 16 字节；创建、切分、传递视图只动这两个字，不动底层数据。级联指 `PacketHeader<'a>` 嵌进 `PacketView<'a>` 这类结构后，二者共享同一份「宿主缓冲区存活期」上限：`'a` 一结束，链条上每个视图同时失效。对照[定义 12.4.1](ch12.md#def-12.4.1)、[定义 12.4.2](ch12.md#def-12.4.2)。
:::

:::

## 第二组 · 结论卡（说清前提与范围）

::: ex 卡 9 · 16 字节说明什么 {#rc-12-9}

卡面：`&[u8]` 是 16 字节，能推出「传参便宜」还是「跑得快」？

::: sol 核对

只能推出传参形状：16 字节正好两个机器字，按 AArch64 调用约定可用两个通用寄存器装下。`Vec<u8>` 是 24 字节，多一个 `cap` 字，通常改走内存。跑多快属于计时问题，尺寸回答不了；本节也没有测传参开销。对照[定义 12.5.1](ch12.md#def-12.5.1)。
:::

:::

::: ex 卡 10 · 这份产物的 8 行 {#rc-12-10}

卡面：`neon_inner` 的循环主体有几行、几条数据指令、每轮几个元素？

::: sol 核对

8 行，其中真正搬数据的是 3 条：`ldr q1, [x10], #16`、`mla.4s v2, v1, v0`、`str q2, [x11], #16`；`movi.4s v2` 每轮重建加数，`sub`/`add`/`cmp`/`b.hi` 管计数与跳转。每轮 4 个元素。说成「循环体 3 条指令」会让人误以为循环开销为零。对照[定义 12.5.2](ch12.md#def-12.5.2)。
:::

:::

::: ex 卡 11 · 7.73 倍买到了什么 {#rc-12-11}

卡面：`auto` 相对 `scalar_call` 是 7.73 倍，这个数支持哪个决策？不支持哪个？

::: sol 核对

支持「把逐元素热路径上的函数调用去掉」：改成内联、迭代器或显式向量，都是这个量级。不支持「手写 SIMD 优于自动向量化」——那是 1.1% 且没有区间的那一行。加速比是基准批均值除以候选批均值，分母换了就不能横向比。对照[定义 12.6.4](ch12.md#def-12.6.4)。
:::

:::

::: ex 卡 12 · 1.1% 分不出方向 {#rc-12-12}

卡面：`auto` 0.069184、`neon` 0.069965，差 0.000781 ns/元素。为什么不能写「自动更强」？

::: sol 核对

因为差比波动小：两者标准差是 0.003189 与 0.003086，约 4.4%–4.6%，而均值差只有 1.1%。归档没有做配对差值，也没有区间。按第 1 章的三态判定，这属于「证据不足」。能写的是：在这台机器、这个构建、这组输入上，两者没分出方向。对照[定义 12.6.2](ch12.md#def-12.6.2)。
:::

:::

::: ex 卡 13 · 30.64 与 8.51 的账单 {#rc-12-13}

卡面：两条解析路径在源码上差哪一行？差出的账单有哪几项？

::: sol 核对

差的是 `payload.to_vec()`。它换来一次 1024 字节的分配、一次簿记、一次 `memcpy` 与一次 `free`，每帧一遍，一批 4096 帧就是 4096 次分配与 4096 次释放；借用版在同一批里严格为 0 次。拥有型买到的只有独立存活期。对照[定义 12.7.1](ch12.md#def-12.7.1)。
:::

:::

::: ex 卡 14 · 3.60 倍的适用范围 {#rc-12-14}

卡面：3.60 倍在什么条件下成立？哪三件事会让它失效？

::: sol 核对

条件：4096 个 1024 字节帧、单线程、每帧只按 64 字节步进采样（1024 字节的帧只碰 16 个字节）。帧更小、帧更大、消费更密都会改倍数，而归档只覆盖一组配置；多线程下分配器争用还会放大拥有型的代价。对照[定义 12.7.2](ch12.md#def-12.7.2)。
:::

:::

::: ex 卡 15 · 就绪与完成 {#rc-12-15}

卡面：就绪通知与完成通知的差别在哪一句？缓冲区归属期怎么变？

::: sol 核对

就绪通知只报告「这个描述符现在可以读写」，搬运仍由用户发 `read()` 完成；完成通知要求用户先提交一个带缓冲区的请求，内核搬完再报告。归属期随之从「一次调用」拉长到「一次提交」。对照[定义 12.8.1](ch12.md#def-12.8.1)。
:::

:::

::: ex 卡 16 · 两个环与 user_data {#rc-12-16}

卡面：SQ 与 CQ 各放什么？`user_data` 为什么不能省？

::: sol 核对

SQ 放用户写的请求描述符 SQE，CQ 放内核写的结果 CQE；两者都通过 `mmap` 映射进用户地址空间，两侧只读写 tail 与环掩码，所以提交本身不再搬数据。`user_data` 提交时写什么、完成时原样拿回，是把 CQE 认回请求的唯一凭据，多数运行时把它编码成 Future 或 Waker 的地址。对照[定义 12.8.2](ch12.md#def-12.8.2)。
:::

:::

::: ex 卡 17 · 固定缓冲区的代价 {#rc-12-17}

卡面：固定缓冲区省掉了什么？代价是什么？

::: sol 核对

应用通过 `io_uring_register` 提前把内存交给内核，内核钉住这些页并记住物理地址，网卡可以按 DMA 直接写入，内核态与用户态之间的搬运就省掉了。代价明确：注销之前，这块内存不能移动，也不能提前释放。对照[定义 12.8.3](ch12.md#def-12.8.3)。
:::

:::

::: ex 卡 18 · 拥有型 I/O 缓冲区的三件事 {#rc-12-18}

卡面：拥有型 I/O 缓冲区要求哪三件事同时成立？

::: sol 核对

所有权在提交时移入、完成时随结果移出；等待期间发起方手上没有它，无法提前释放；`Drop` 里把块送进泄漏池，等 CQE 返回再真正释放。类型系统负责「不许提前释放」，运行时负责「最终一定释放」，缺一不可。对照[定义 12.8.4](ch12.md#def-12.8.4)。
:::

:::

## 第三组 · 第一行卡（只写第一步）

这一组练的是「一离开答案就不知道第一行写什么」那个毛病。每题只写第一行动作，不计算。

::: ex 卡 19 · 循环没变快 {#rc-12-19}

卡面：同事改写了循环结构，说「理论上该快」，第一行写什么？

::: sol 核对

第一行：把 remark 打开（`-C remark=loop-vectorize` 一类），看它是在别名、携带依赖、边界还是跨步访问上失败；再按 12.5 用优化后 IR 与汇编核对。不要先猜编译器不行。
:::

:::

::: ex 卡 20 · 老机器上崩了 {#rc-12-20}

卡面：同一份二进制在旧服务器上 `SIGILL`，第一行写什么？

::: sol 核对

第一行：找调用点的 `is_x86_feature_detected!` 或 `is_aarch64_feature_detected!` 凭证；没有凭证就不能调用带 `target_feature` 的函数，探测失败分支必须有标量回退。对照[定义 12.3.2](ch12.md#def-12.3.2)。
:::

:::

::: ex 卡 21 · 有人报「快 3.6 倍」 {#rc-12-21}

卡面：一份解析器报告写着 3.60 倍，第一行写什么？

::: sol 核对

第一行：写下对方的帧长与每帧读多少字节。本节的 3.60 只对 1024 字节帧、每 64 字节读 1 字节成立；帧长与消费密度不同就要重测，别引用这个数。对照[定义 12.7.2](ch12.md#def-12.7.2)。
:::

:::

::: ex 卡 22 · 两个均值只差 1% {#rc-12-22}

卡面：两个实现的批均值只差 1.1%，第一行写什么？

::: sol 核对

第一行：算标准差除以均值，再看有没有配对区间。本节三种实现的相对波动是 2.4%–4.6%，比 1.1% 的差还大；没有区间就写「本次未分出方向」，不排座次。对照[定义 12.6.3](ch12.md#def-12.6.3)。
:::

:::

::: ex 卡 23 · 决定手写 SIMD {#rc-12-23}

卡面：准备给一个热循环手写 NEON，第一行写什么？

::: sol 核对

第一行：写出车道数（128 ÷ 元素位宽）、主循环轮数、`len mod 车道数` 的尾部元素数；并说明这件事为什么不在「简单逐元素映射」里——本节实测手写相对自动没有额外收益，却多出移植与 `unsafe` 面。对照[例 12.3.1](ch12.md#ex-12.3.1)。
:::

:::

::: ex 卡 24 · 取消后内存被写 {#rc-12-24}

卡面：`io_uring` 请求被取消后，别处对象被写脏，第一行写什么？

::: sol 核对

第一行：查提交之后谁持有缓冲区指针。内核只在 SQE 里拿到地址、长度与 `user_data`，撤不回已下发的操作；若 `Drop` 直接释放，就是 DMA 版的释放后使用。修法是所有权移入请求，并在 `Drop` 里把块送进泄漏池。对照[定义 12.8.4](ch12.md#def-12.8.4)、[例 12.8.1](ch12.md#ex-12.8.1)。
:::

:::
