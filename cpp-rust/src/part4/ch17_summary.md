# 第17章 · 全章总结

这一页只回答一件事：**八块机制各留下了什么可复用的结论。**算术、代码与展开解释都在正文，这里把每条结论压成一句可以带走的句子。合上正文再读这页，读不下去的那一行就是断点。正文里标了「本节没有采集」的位置，这一页同样不替它补数字。

## 8 节一览

| 节 | 留下的结论 | 破坏它的最快方式 |
|:--|:--|:--|
| [17.1](ch17.md#sec-cpp-rust.4.17.1) | 项目契约是四元组（操作集合、输入家族、不变量、不覆盖范围），写在采集之前；不变量必须能被测试一次性证伪 | 交一句「做个更快的 KV 引擎」就开工；不覆盖范围留空等着被质疑再补 |
| [17.2](ch17.md#sec-cpp-rust.4.17.2) | 段文件三区（数据、索引、页脚）的分工是「少搬字节」不是「少占字节」；97 字节记录、12 字节索引项是静态算术，能算不用测 | 拿内存里的「字段顺序」道理去改磁盘格式；索引变长还宣称支持二分 |
| [17.3](ch17.md#sec-cpp-rust.4.17.3) | 零拷贝（省掉「先复制一份再交出去」的那次搬运）省下复制，代价是把缓冲寿命钉在借用上；三条安全不变量缺一即未定义行为 | 为躲一次边界比较上 `unsafe`，注释里只写「格式保证偏移正确」 |
| [17.4](ch17.md#sec-cpp-rust.4.17.4) | 泛型与 dyn 的差别落在四个层上；「快多少」必须先指定口径，没口径就没有真值。实测（17.4.2）：每条记录的额外成本**方向不可判定**（95% 区间 [−0.054, +0.208] ns/记录），区间最坏端低于 1 ns/记录 的预算 → 接受 | 拿 benchmark 夹具的数除单元测试的数，写成「慢 34%」 |
| [17.5](ch17.md#sec-cpp-rust.4.17.5) | 快照不可变，发布用 `SeqCst` 换指针（降到 `Release/Acquire` 没有实测依据，见 17.5.2 的 E-c）；回收要靠引用计数或 epoch（记读者代际的计数器）保护；延迟释放必须有可观测计数 | 换完快照立刻 `drop` 旧值；退休表长度没人监控 |
| [17.6](ch17.md#sec-cpp-rust.4.17.6) | 准入满即拒：不阻塞、不入队、不重试；引擎没有按请求取消的 API，「已受理但提交方已放弃」那一格要调用方自己记（**定义** 17.6.2/17.6.3，在 17.6.1 小节内）；饱和时吞吐、延迟、拒绝率必须同窗报告。实测（17.6.2）：`CAP` 从 64 降到 4 改变的是谁被拒（拒绝率 0.6858 → 0.9664），同一把墙钟的两个分母给出两句不同的话——ns/尝试 配对差值 −691,518.3（95% 区间 [−741,468.5, −652,422.3]），区间上端低于 5,000 ns/操作 的预算 → 接受；ns/受理 差值 +14,007.4（区间 [−105,221.5, +132,036.5]）跨零 → 证据不足。**每请求端到端延迟与按请求取消未采集** | 用无界队列测吞吐，或把被拒请求从分母里抹掉 |
| [17.7](ch17.md#sec-cpp-rust.4.17.7) | 子进程两路输出各由独立线程排空到 EOF，父线程收齐并 `join` 后才 `wait`；幂等要求任务标识来自输入段生成号集合——**本项目还没做到**（段名取最大号加一、发布前不检查）；输出走「临时名→同步→原子重命名」。实测（17.7.2）：子进程每次合并多付 1.48 ms（95% 区间 [1.37, 1.59] ms），在 10 ms/次 的预算内 → 接受 | `wait` 之后才读管道；失败后拿提交时刻当标识直接重放 |
| [17.8](ch17.md#sec-cpp-rust.4.17.8) | 基线与候选要先满足等价工作；计时边界含批内全部副作用；三态判定每一态自带下一步；证据包是结论的一部分 | 计时器里 `if` 掉 flush；换种子跑到绿灯为止；只交一张汇总表 |

## 一条主线

**① 工作真的发生 → ② 这个数是什么 → ③ 差异不是噪声 → ④ 守得住、可复核。**

17.1 的 $O$ 与 $I$、17.3 的三条不变量、17.5 的红色窗口、17.6 的「取消不等于没发生」、17.8 的「flush 进界内」，都在回答 ①。17.2 把「总字节」与「一次读搬多少」分成两笔账，17.4 要求先指定口径，17.6 盯住分母——这些是 ②。17.4 的等价工作四缺口与 17.8 的同轮交替、配对差值，回答 ③。17.1 的 $X$、17.5 的确定性测试、17.7 的幂等、17.8 的证据包，回答 ④。

前面十六章每章只走一环；这一章要求在同一个仓库里四环同时成立。任何一环缺位，最后的数字就只是修辞。

## 能否讲出这几句话

不看书，用自己的话回答。答不上来的，回到对应小节只看那一段。

1. 契约的四个槽位里，哪一个专门防「读者自己外推结论」？为什么它必须写在采集之前？
2. 「分区摆放总字节更大」和「分区摆放读得更快」，哪句是静态算术、哪句需要实测？各自的前提是什么？
3. 零拷贝（不复制值、直接交出指向段缓冲的切片）读路径的三条安全不变量是什么？各由哪个具体机制担保？
4. 纯计数为什么可以用 Relaxed？举一个「看着像计数、实际是发布边」的反例形状。
5. 饱和状态下必须同窗报告的三个指标是什么？它们的分母各是什么？
6. 三态判定的三种结果各接什么下一步？为什么「证据不足」不许用「换个种子再跑」来代替？
