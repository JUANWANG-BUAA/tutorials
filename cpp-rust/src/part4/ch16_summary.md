## 一条主线

**先定责任 → 再锁形状 → 守住指针与身份 → 换掉失败出口 → 证明边界真的在 → 才谈两组数。**

16.1–16.2 定的是责任与形状：返回之后数据归谁，哪些表示必须两侧各锁一次。
16.3–16.4 守的是每次调用的裸指针与跨调用的身份：先数值后引用，句柄三关缺一不可。
16.5 把内部 panic 换成整数码，并写清 C 侧的清理规则。
16.6 用构建与代码生成证明这层边界没有被优化器或断言开关悄悄改掉。
16.7–16.8 才开始报数字：一组比调用粒度，一组比结果消费位置。
16.9–16.11 收尾：数字的来源、十八条陷阱、以及交付与未验证的边界。

任何一环跳过去，后面那个 ns/word 都只是修辞。
