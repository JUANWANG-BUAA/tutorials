## 一条主线

**定分母 → 分证据层 → 查可加性 → 读事件契约 → 读聚合图 → 比两份画像 → 量观测成本 → 划采样边界 → 装证据包 → 写一句可反驳的结论。**

13.1 先定分母。一个数字统计的是墙钟、运行时间、事件数还是栈观察数，决定它能和谁比较。五层证据从业务现象走到受控修改，上层提问，下层不自动认领责任。

13.2 到 13.3 检查可加性与契约。父帧与子帧是同一批观察的两层表示；硬件事件要先读事件名、范围、槽位、精确度与采集状态。两部分都在回答同一句话：这个数能不能进结论。

13.4 到 13.5 把样本聚合成图，再用两份画像对照。宽度只承诺权重份额，CPU 图补不出等待区间；1698 与 1648 来自两次独立启动，份额不能相减，更不能替换计时表。

13.6 到 13.7 量观测本身。逐项打点把 2.472857 推到 32.832639 ns/聚合 step，差值不是可减掉的常数；采样频率、锁步与模拟器各有自己的边界。

13.8 收进证据包，再用六关审一句话。13.9 到 13.11 交代来源、合并陷阱、留下复现命令与未验证清单。

这条线从「这个数是什么」走到「这句话能说什么」。任何一环没走完，后面的数字都只是修辞。

## 能否讲出这几句话

不看书，用自己的话回答。答不上来的，回到对应小节只看那一段。

1. 为什么第一步不是跑最长的那条采样命令，而是写下要解释的现象与分母？
2. 一条样本记录了什么？为什么 1698 与 1082 加 616 不能再相加一次？
3. 事件契约的五项是什么？零、不支持、未运行各是什么状态，压成一个 0 会破坏什么？
4. flamegraph 的宽度承诺什么、不承诺什么？为什么 1698 与 1648 的份额不能相减？
5. each 的 32.832639 是什么单位？为什么不能减出 30.359782 的「净打点成本」？
6. 采样器开销为什么只能靠附着／未附着对照？本轮采集了哪两份证据，哪几项没有采集？
