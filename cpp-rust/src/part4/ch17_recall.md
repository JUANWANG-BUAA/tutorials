# 第17章 · 闭卷回忆卡

「看懂」只说明答案在眼前时能识别；评审与答辩需要的是从空白纸上提取。这一页把第 17 章拆成 24 张卡，每张卡先写卡面问题，合上正文自己答，再展开核对。正文标了「没有采集」的位置，卡面只问概念与协议，不问你数字。

**用法与节奏**

| 时点 | 做什么 | 判定 |
|:--|:--|:--|
| 学完当天 | 第一组「定义卡」全部 8 张 | 槽位与要件写全才算 ✓ |
| 第 1 天 | 第二组「结论卡」全部 11 张 | 能说清前提与出处才算 ✓ |
| 第 3 天 | 第三组「第一行卡」全部 5 张 | 写出第一步动作才算 ✓ |
| 第 7 天 | 只重做标成 △ 和 × 的卡 | 全对即可进入篇末复盘 |

每张卡给自己一个记号：✓ 一次说对；△ 说对一半或要提示；× 想不起来。只重做 △ 和 ×，不要把整叠卡反复过一遍——那是在读，不是在提取。

<a id="ch17-recall-def"></a>

**这 24 张卡在主线上落在哪一步。**合上卡片先想「这一步要保证什么」，再想具体那张卡问的是什么：

| 步 | 用到的卡 | 这一步在本章的形态 |
|:--|:--|:--|
| ① 工作真的发生 | 2、6、11、19、22 | 不变量有测试、缓冲没有写路径、`unsafe` 的担保写得出来 |
| ② 这个数是什么 | 4、5、7、8、9、10、12、20、21、23 | 字节账是算的还是测的、吞吐的分母用哪一格计数 |
| ③ 差异不是噪声 | 16、17 | 配对差值、区间、方向——两题都来自第 1 章的协议 |
| ④ 守得住、可复核 | 1、3、13、14、15、18、24 | 边界与出口条件、回收窗口、双路排空、幂等发布 |

③那一格只有两题不是疏漏：本章的比较协议直接沿用[第 1 章](../part1/ch01.md)，那里才是配对与区间的母版。

## 第一组 · 定义卡（说全称与前提）

::: ex 卡 1 · 项目契约四元组 {#rc-17-1}

卡面：写出契约的四个槽位，并说明采集之后哪两个不许改。

::: sol 核对

$O$ 操作集合、$F$ 输入家族、$I$ 不变量、$X$ 不覆盖范围。契约写在采集之前，采集之后不许修改 $F$ 与 $X$——事后改它们等于为这次结果临时换判定口径。对照[定义 17.1.1](ch17.md#def-17.1.1)。
:::

:::

::: ex 卡 2 · 不变量 {#rc-17-2}

卡面：不变量的定义是什么？说出本项目六条里的至少四条。

::: sol 核对

定义：任何合法操作序列之后都成立、且能用测试一次性证伪的命题。六条：已同步的写重启后仍在；`get` 与朴素参考实现逐键相等；删除对后续读不可见；段文件字节写下不改；同批键压缩前后集合相同；读者持有快照期间旧段不释放。一条不变量要配一个能触发它的测试。对照[定义 17.1.2](ch17.md#def-17.1.2)。
:::

:::

::: ex 卡 3 · 里程碑出口条件 {#rc-17-3}

卡面：为什么「测试通过」不算出口条件？M2 的出口条件是什么？

::: sol 核对

出口条件是「一组可执行的判据 + 判据输出的落盘位置」，只说跑通无法复核。M2：无漏报测试通过，假阳率有实测计数，原始输出落盘。对照[定义 17.1.3](ch17.md#def-17.1.3) 与 [17.1 里程碑表](ch17.md#sec-cpp-rust.4.17.1)。
:::

:::

::: ex 卡 4 · 段文件三区 {#rc-17-4}

卡面：三区各放什么？索引项几个字节、有效几字节？

::: sol 核对

数据区按字典序放每条记录：17 字节条目头（键长 4、值长 4、标记 1、序号 8）+ 键 + 值；索引区是等宽数组，每项 12 字节（键长 4 + 条目偏移 8）——键长复制一份，是为了二分不必先读条目头；页脚 34 字节放魔数、版本、条目数、两区偏移与长度、CRC32。对照[定义 17.2.1](ch17.md#def-17.2.1)。
:::

:::

::: ex 卡 5 · 墓碑与 niche {#rc-17-5}

卡面：墓碑是什么？为什么它必须活到压缩？niche（编译器给判别式留的空闲比特位）省的是什么？

::: sol 核对

删除在内存表里写成值为空的条目，它就是墓碑；若提前抹掉，旧段里的同键值会复活。niche（编译器为判别式预留的空闲比特位）用比特形状而不是数值表达「有没有值」，不多占字节。对照[定义 17.2.2](ch17.md#def-17.2.2)。
:::

:::

::: ex 卡 6 · 读路径三条安全不变量 {#rc-17-6}

卡面：返回切片而非复制，要同时成立哪三条？各由谁保证？

::: sol 核对

①目标字节落在段缓冲范围内，范围由索引区给出——构造时核对加边界检查；②缓冲在切片存活期间不改不释放——引用计数与 epoch（记读者代际的计数器）回收；③段字节写定后不可变——要改就新建段。任何一条只靠「大家都知道不会这么做」，就是没有保证。对照[定义 17.3.2](ch17.md#def-17.3.2)。
:::

:::

::: ex 卡 7 · 分发口径 {#rc-17-7}

卡面：比较泛型与 dyn 的代价，允许报哪三种口径？

::: sol 核对

每次调用的墙钟差（减掉共同开销）、生成代码的字节数、热循环里的指令数。三种口径的结论可以互相矛盾，所以没有口径时「dyn 慢多少」这句话没有真值。本项目的实测结论：每条记录的额外成本方向不可判定（95% 区间 [−0.054, +0.208] ns/记录，跨零），区间最坏端低于 1 ns/记录 的预算，判接受；汇编证据是泛型实例 0 次间接调用、`encode_all_dyn` 1 次 `blr`。对照[定义 17.4.2](ch17.md#def-17.4.2)、[例 17.4.1](ch17.md#ex-17.4.1)。
:::

:::

::: ex 卡 8 · 有界准入 {#rc-17-8}

卡面：队列满时的三个「不」是什么？许可什么时候归还？`CAP` 算不算契约的一部分？

::: sol 核对

不阻塞、不入队、不重试，立即返回 `AdmissionRejected`。「许可」就是队列里的一个槽位：`submit` 只看队列长度。归还点**不是**落盘之后——写线程一次 `take_batch` 取走至多 256 条，槽位在这一刻就空了，日志还没写。所以在途上界是 `CAP + 256`，报内存上限要按这个数说。`CAP` 是实验契约的一部分，改它就等于换实验。对照[定义 17.6.1](ch17.md#def-17.6.1)。
:::

:::

## 第二组 · 结论卡（说清前提与范围）

::: ex 卡 9 · 一笔静态算术 {#rc-17-9}

卡面：键长 16、值长 64、装满 $2^{16}$ 条记录，数据区、索引区、各占多少字节？

::: sol 核对

数据区每条 $17+16+64=97$ 字节，共 $6{,}356{,}992$；索引区每条 12 字节，共 $786{,}432$；两区合计 $7{,}143{,}424$，加 34 字节页脚是 $7{,}143{,}458$（不计布隆区）。这些是静态可算的字节，不是需要采集的性能量。对照[例 17.2.1](ch17.md#ex-17.2.1)。
:::

:::

::: ex 卡 10 · 合并还是分区 {#rc-17-10}

卡面：把索引里重复的键长去掉，每条索引省多少字节、整个段文件省多少？为什么不能说索引越小越好？

::: sol 核对

每条索引从 12 减到 8，省 $4 \times 65536 = 262{,}144$ 字节。但点读命中率不是 100% 时，二分每一步都要先读 17 字节条目头才知道键长，一次点读约 16 步；分区省「一次读搬多少」，合并省「磁盘占多少」。对照[例 17.2.1](ch17.md#ex-17.2.1)。
:::

:::

::: ex 卡 11 · 零拷贝的钱付给谁 {#rc-17-11}

卡面：`get` 返回切片省了复制，这笔账在哪里偿还？

::: sol 核对

返回的借用把段缓冲的寿命钉住：切片不放手，旧段就不能释放，退休表随最慢的读者增长。省下的复制换成「回收延迟」；判断划不划算看值长与读者停留时间的分布，而且退休表长度本身要可观测。对照 [17.3 思考盒](ch17.md#sec-cpp-rust.4.17.3)、[17.5 思考盒](ch17.md#sec-cpp-rust.4.17.5)。
:::

:::

::: ex 卡 12 · 「dyn 慢 34%」为何作废 {#rc-17-12}

卡面：泛型版跑基准夹具、dyn 版在单元测试跑一次，得出百分比——列出四个缺口。

::: sol 核对

计时边界不同；分母没写清（每条还是总时长）；没有同轮交替，机器热状态进了差值；没验两版输出逐字节相同。补齐顺序：先定契约再采数。正文按这个顺序跑完一轮（17.4.2），结论是方向不可判定、但最坏端在预算内。对照[例 17.4.1](ch17.md#ex-17.4.1)。
:::

:::

::: ex 卡 13 · 红色窗口 {#rc-17-13}

卡面：换快照后立刻释放旧段，哪个时间窗里是未定义行为？修法分几层？

::: sol 核对

从写者换下快照、到最后一个固定在旧代际的读者退出之前——图 17-3 里红色那一格。两层修法：旧快照装进引用计数（读端每次有原子增减）；或 epoch 保护加退休表，靠可驱动的推进接口做确定性测试。两层的成本对照属于 17.8，17.5 没有单独采集。对照[例 17.5.1](ch17.md#ex-17.5.1)。
:::

:::

::: ex 卡 14 · 双路排空 {#rc-17-14}

卡面：为什么子进程的 stdout 和 stderr 必须「同时」被读走？

::: sol 核对

每路管道容量有限。只等 `wait` 之后再读，子进程可能写满其中一路而阻塞，父进程在等它退出、它在等父进程读——互等成死锁，而且只排空一路时死在报错路上。本项目的做法：stdin/stdout/stderr **三路各起一个独立线程**，两个输出线程读到 EOF 后经 channel 送回，父线程收齐两个结果、`join` 完线程才 `wait`（`src/ipc.rs` 的 `spawn_compactor`）。对照[定义 17.7.1](ch17.md#def-17.7.1)。
:::

:::

::: ex 卡 15 · 幂等从哪来 {#rc-17-15}

卡面：压缩任务的标识来自什么？原子重命名解决了什么、没解决什么？

::: sol 核对

幂等要求标识来自输入段的生成号集合、发布前检查同名段——**本项目两条都没做**：段名取当前最大号加一，`rename` 前不检查，而 POSIX `rename` 遇同名是静默覆盖。所以这里是「可重放但不幂等」。临时名加同步加原子重命名解决了「半个文件被当成合法段」，没解决重复段；`.tmp` 残留因为临时名由最终名派生，只会覆盖同一份，不堆积，但也没有任何代码回收它。对照[定义 17.7.2](ch17.md#def-17.7.2)、[例 17.7.1](ch17.md#ex-17.7.1)。
:::

:::

::: ex 卡 16 · 三态判定 {#rc-17-16}

卡面：区间 $[L, U]$ 与预算 $B$ 的三条规则，和三句话各自接着做什么？

::: sol 核对

$U \le B$ 接受：合入，并把 $B$ 与判据留在门禁配置；$L > B$ 拒绝：回到具体机制，别只写「没达标」；其余证据不足：独立时段重跑或扩大输入家族，不许换种子跑到绿灯为止。$B$ 在采集前写下。对照[例 17.8.1](ch17.md#ex-17.8.1)。
:::

:::

::: ex 卡 17 · 结论句六槽位 {#rc-17-17}

卡面：背出结论句骨架的六个槽位；没有采集的槽位怎么填？

::: sol 核对

机器与构建、输入家族、两个量各是多少（含单位与分母）、差值与区间、方向判定、不覆盖范围。实测位置只能填实测值；没采集就留空并注明，不许用印象数字顶替。对照[例 17.8.1](ch17.md#ex-17.8.1)。
:::

:::

<a id="ch17-recall-first"></a>

::: ex 卡 23 · 三个计数必须分开 {#rc-17-23}

卡面：一次写请求会落进哪三个互斥计数？报吞吐时为什么必须点名用哪一个？

::: sol 核对

受理（拿到许可）、完成（写进日志并推进序列）、被拒（`AdmissionRejected`）。引擎只报两个数：`Stats.put` 是提交尝试、`Stats.admission_reject` 是被拒，受理数 = 两者之差；**「完成」这一格没有计数器**——`Stats` 里没有 applied 或 written，一条写落定没有只能问 `await_seq` 用的内部水位。第四格「已受理但提交方已放弃」引擎同样不报——`put` 是 fire-and-forget，没有按请求取消的 API，要记这格得调用方自己来（[定义 17.6.2](../part4/ch17.md#def-17.6.2)）。饱和时「完成数 ÷ 总时长」与「受理数 ÷ 总时长」是两个不同的数，不点名分母，吞吐就没有真值（[17.6](../part4/ch17.md#sec-cpp-rust.4.17.6)）。
:::

:::

::: ex 卡 24 · 新段什么时候能进快照 {#rc-17-24}

卡面：压缩产出一个新段，要走完哪三步才允许出现在任何快照里？重命名遇到同名已存在，算失败吗？

::: sol 核对

写临时名 → `fsync` 临时名 → 原子重命名到最终名，只有第三步完成才算发布；同名已存在不是错误，是幂等收敛的信号，要单独计数（[17.7](../part4/ch17.md#sec-cpp-rust.4.17.7)）。
:::

:::

## 第三组 · 第一行卡（只写第一步）

这一组练「离开答案不知道第一行写什么」的毛病。每题只写第一行动作，不展开。

::: ex 卡 18 · 立项只有一句话 {#rc-17-18}

卡面：看到「做个 Rust KV 引擎，比某某快」，第一行写什么？

::: sol 核对

第一行：把 $O$、$F$、$I$、$X$ 四个槽位列在纸上，空的先标空，再跑立项评审五问。不先补边界，代码写得越快返工越多。
:::

:::

::: ex 卡 19 · 审一段 `unsafe` {#rc-17-19}

卡面：评审里看到 `from_raw_parts`，第一行问什么？

::: sol 核对

第一行：问「有没有安全写法能达到同样效果」。有就用安全的；没有，再问省下的到底是什么操作、前提能不能用检查或类型固定下来。
:::

:::

::: ex 卡 20 · 想比泛型和 dyn {#rc-17-20}

卡面：同事开始跑两种写法的对比，第一行拦什么？

::: sol 核对

第一行：让他先写口径——报每次调用墙钟差、代码体积还是指令数，三选一并说明另两个为什么不算；同时固定同一输入与逐字节相同的输出。
:::

:::

::: ex 卡 21 · 延迟变好了 {#rc-17-21}

卡面：报告说调小 `CAP` 之后 p99 降了，第一行查什么？

::: sol 核对

第一行：查拒绝率和分母——被受理请求的延迟当然降，前提是有一部分请求没被受理。这三个数（吞吐、延迟、拒绝率）必须来自同一时间窗。`CAP=64` 与 `CAP=4` 的实测对照正文已经有了（17.6.2 与 `results/run-03/`），先读那份；要补的是它没测的每请求端到端延迟。
:::

:::

::: ex 卡 22 · 功能刚跑通 {#rc-17-22}

卡面：全测试绿了，很想写发布说明，第一行写什么？

::: sol 核对

第一行：搭六槽位结论句的骨架，没采集的槽位留空标注；再对照证据包八项清单逐项打勾。句子搭不起来的地方，就是还欠的证据。
:::

:::
