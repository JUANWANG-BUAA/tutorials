# 第14章 · 全章总结

这一页只回答一件事：**十一节各留下了什么可复用的结论。**表格、实测与命令都在正文，这里把每条结论压成一句能带走的句子。合上正文再读，读不下去的那一行就是断点。

## 十一节一览

| 节 | 留下的结论 | 破坏它的最快方式 |
|:--|:--|:--|
| [14.1](ch14.md#sec-cpp-rust.4.14.1) | 构建身份是六层输入全集，不是一行版本号；产物指纹只判「是不是同一个对象」 | 把「同一提交」当「同一程序」；哈希不同就宣布变慢 |
| [14.2](ch14.md#sec-cpp-rust.4.14.2) | feature 是编译输入，生效的是闭包；`default-features = false` 只约束自己那条边 | 只看顶层 `Cargo.toml` 一行，或用 `all-features` 代替组合矩阵 |
| [14.3](ch14.md#sec-cpp-rust.4.14.3) | 可复现分三级，前两级的成立对第三级没有蕴含；本轮 21 份产物 21 个不同 SHA256 | 用 remap 或固定时间戳把哈希「修」成一致 |
| [14.4](ch14.md#sec-cpp-rust.4.14.4) | 先命名缓存边界再报数：fresh 338–1996 ms，noop 约 18 ms；`lto = false` 不等于 `"off"` | 把新目标目录叫冷构建，或拿 noop 评价 CI 速度 |
| [14.5](ch14.md#sec-cpp-rust.4.14.5) | 门禁要靠一个真实会失败的候选自证；三种退出码 0 / 1 / 2 互不冒充 | 只让基线通过就宣布有效；把 20% 读成显著性 |
| [14.6](ch14.md#sec-cpp-rust.4.14.6) | PGO 把训练分布变成构建输入；插桩版与最终版是两份产物，墙钟不能混用 | 拿插桩版耗时当收益；只留一个 `latest.profdata` |
| [14.7](ch14.md#sec-cpp-rust.4.14.7) | 先验证证据，再比较数字；证据不可比比「证据不足」更早一步 | 前一层失败时用默认值补上；红了就重跑到绿 |
| [14.8](ch14.md#sec-cpp-rust.4.14.8) | 测试是有限契约，清单要能被机器核对，基线是被认可的产物加协议 | 用测试条数证明覆盖；把最好值设成基线 |
| [14.9](ch14.md#sec-cpp-rust.4.14.9) | 本章落点可追到 S11、S14、S09 与四份在线规范，版本差异以实际执行为准 | 把旧版本文档的选项当成已验证 |
| [14.10](ch14.md#sec-cpp-rust.4.14.10) | 15 条陷阱是各节 errata 的合并清单，每条都能回到一个锚点 | 把「release 构建」当成完整身份 |
| [14.11](ch14.md#sec-cpp-rust.4.14.11) | 出口检查钉住复现入口、一次真实拒绝、273 条观察与 10 个应能回答的问题 | 把退出码 1 当成工具故障，再补一条兜底命令把它吞掉 |

## 一条主线

**认身份 → 讲闭包 → 划承诺 → 定边界 → 让门禁拒绝一次 → 把证据交给发布。**

1. 14.1 先把「同一个程序」拆成六层，任何比较都从这六层开始。
2. 14.2 处理最容易漏的第二层：feature 闭包与构建单元。
3. 14.3 把「可复现」拆成三级，并承认本轮只到第二级。
4. 14.4 给构建计时命名边界，给 CGU 与 LTO 的配置差异配上数字。
5. 14.5 用 `checked` 造出一个输出正确、成本更高的候选，让门禁真的拒绝。
6. 14.6–14.7 把训练数据与 CI 顺序接上，14.8 把这一切交给发布责任链。

任何一环被写成「已覆盖全部情况」，后面的数字就只剩修辞。

## 能否讲出这几句话

不看书，用自己的话回答。答不上来的，回到对应小节只看那一段。

1. 同一提交、同一锁文件，为什么还可能编出执行了不同工作的程序？差别落在第几层？
2. 为什么「默认配置与 `checked` 的 checksum 都是 133693440」不能推出两者可比？
3. 21 份产物大小同为 518448 字节而 SHA256 全不同，这证伪了哪一级承诺、又对另外两级说了什么？
4. 一个 18 ms 的构建数字回答了哪个问题？它不能回答哪个问题？
5. 门禁凭什么证明自己会拒绝？退出码 2 为什么不能和退出码 1 合并成一个红灯？
6. 要被别人复核的发布，除了「通过了」还需要交出哪几样东西？
