# 第十六章 · 闭卷回忆卡

「看懂」只说明答案在眼前时能认出来；做评审、写接口时要的是从空白纸上提取。
这一页把第十六章拆成 24 张卡：先读卡面，合上正文自己答，再展开核对。

**用法与节奏**

| 时点 | 做什么 | 判定 |
|:--|:--|:--|
| 学完当天 | 第一组「定义卡」11 张 | 关键词写全才算 ✓ |
| 第 1 天 | 第二组「结论卡」7 张 | 数字、返回码与口径都对才算 ✓ |
| 第 3 天 | 第三组「第一行卡」6 张 | 写出第一步动作才算 ✓ |
| 第 7 天 | 只重做标成 △ 和 × 的卡 | 全对即可进入下一章 |

每张卡给自己一个记号：✓ 一次说对；△ 说对一半或要提示；× 想不起来。
只重做 △ 和 ×，不要把整叠卡反复过一遍——那是在读，不是在提取。

## 第一组 · 定义卡（说全称与前提）

::: ex 卡 1 · 安全核与协议适配层 {#rc-16-1}

卡面：安全核与协议适配层各指哪部分代码？分层只有哪一条验收标准？

::: sol 核对

安全核是不碰裸指针、只用切片和 `Result` 表达工作的实现，本章就是 `mix`、`transform`、`checksum`。
协议适配层是 `extern "C"` 入口：数值检查、形成引用、把 `Result` 换成整数码，不重写算法。
验收标准只有一条——出问题时能不能只推理一层。对照[定义 16.1.1](ch16.md#def-16.1.1)。

:::

:::

::: ex 卡 2 · 所有权路径的三问与四路 {#rc-16-2}

卡面：所有权路径的三个问句是什么？四条数据路径各是谁所有？

::: sol 核对

三问：调用期间谁是数据所有者；返回后谁是；Rust 是否保留了指向 C 分配的指针。
四路：同步批量变换是 C 到 C；create_copy 是 C 原件加 Rust 新副本；generate 是 Rust 存储、C 承担句柄释放责任；copy 导出是两份分配各自管理。
四条路径都不保留 C 指针。对照[定义 16.1.2](ch16.md#def-16.1.2)。

:::

:::

::: ex 卡 3 · ABI 面、自描述与输入协商 {#rc-16-3}

卡面：一个类型该不该进 ABI 面，用什么问题判定？自描述输出与输入协商各是什么？

::: sol 核对

判据是「对方改了它，我要不要重新编译」：要，就锁死；不要，就别让它出现在头文件里。
自描述输出是结构里的 `abi_version` 与 `struct_size`，它们描述本次写出的东西，是结果的一部分。
输入协商是调用者在写入之前用参数声明版本与尺寸，`rb_info` 要求版本为 1 且尺寸恰好为 24。对照[定义 16.2.1](ch16.md#def-16.2.1)、[定义 16.2.2](ch16.md#def-16.2.2)。

:::

:::

::: ex 卡 4 · 稳定错误词表 {#rc-16-4}

卡面：0 到 7 八个数值各是什么？「稳定」只承诺哪两件事？

::: sol 核对

0 OK；1 EINVAL（null、对齐、重叠、版本或尺寸错误）；2 ERANGE（长度上限、转换或地址算术溢出）；3 ESTALE（无效槽、旧代、重复释放）；4 ECAPACITY（C 输出容量小于对象长度）；5 EPANIC（捕获到 unwind panic）；6 EPOISON（注册表锁被毒化）；7 ERESOURCE（可报告的预留失败或槽上限）。
稳定只承诺两件事：同一数值不因改版换意思，也不会凭空多出一个新值。
它不承诺检查顺序，也不承诺多条规则同时被违反时返回哪一个。对照[定义 16.2.3](ch16.md#def-16.2.3)。

:::

:::

::: ex 卡 5 · 数值守卫与调用者义务 {#rc-16-5}

卡面：数值守卫只做哪几件事？头文件里那五条调用者义务是什么？

::: sol 核对

守卫只看整数：零长、非空、对齐、`len × size_of` 是否溢出、总字节是否超过 `isize::MAX`、两个半开区间是否相交。
产物只是一对地址整数和一个返回码。
五条义务：整段区间属于一个有效分配；对象表示与目标类型匹配；容量足够且返回前不失效；本次各参数区间两两不相交；没有别的线程并发访问同一输出。对照[定义 16.3.1](ch16.md#def-16.3.1)、[定义 16.3.2](ch16.md#def-16.3.2)。

:::

:::

::: ex 卡 6 · 代号句柄 {#rc-16-6}

卡面：句柄的位怎么分？有效身份要同时过哪三关？

::: sol 核对

高 32 位是该槽当前的代号（generation），低 32 位是槽下标加一，低位为 0 表示无效身份。
三关：低位非零且槽存在；代号与槽当前值相等；槽仍持有所有者。
同一槽的代号在一份库实例生命周期内单调不减，达到 `u32::MAX` 的槽退休而不回绕；当前上限 4096 槽。对照[定义 16.4.1](ch16.md#def-16.4.1)。

:::

:::

::: ex 卡 7 · 快照与线性化点（操作真正发生的那一瞬） {#rc-16-7}

卡面：快照是什么？`rb_release` 的线性化点在哪一步？

::: sol 核对

快照是在注册表锁内克隆出来的一个 `Arc<[u64]>`，它拥有自己那份数据的引用计数，有效期与槽无关。
线性化点是锁内的 `take()`：从这一刻起新查找必然 `ESTALE`。
锁外的 `drop` 只是清理成本，所以 release 不是等读者结束的 join。对照[定义 16.4.2](ch16.md#def-16.4.2)、[定义 16.4.3](ch16.md#def-16.4.3)。

:::

:::

::: ex 卡 8 · panic 边界三件 {#rc-16-8}

卡面：`boundary` 的三条出口各返回什么？载荷遗忘换来了什么、代价是什么？

::: sol 核对

闭包 `Ok(())` 给 `OK`；闭包 `Err(code)` 给该整数码；捕获到展开则遗忘载荷并给 `EPANIC`。
遗忘换来确定性：异常路径上只剩「返回 `EPANIC`」一件事，不会有第二次展开。
代价是每次捕获都可能泄漏该载荷占用的资源。锁被毒化则统一 `EPOISON`，不用 `into_inner` 解锁继续。对照[定义 16.5.1](ch16.md#def-16.5.1)、[定义 16.5.2](ch16.md#def-16.5.2)、[定义 16.5.3](ch16.md#def-16.5.3)。

:::

:::

::: ex 卡 9 · 原生构建与代码生成层次 {#rc-16-9}

卡面：原生构建的判据是什么？哪几层可以作为证据，各只说哪一类话？

::: sol 核对

判据只有一条：把 Rust 目标从这个构建里拿掉，C 的可执行文件应当链接失败。
层次是 MIR、LLVM IR、本机汇编，加运行时的采样栈：MIR 说明前端保存了什么语义，IR 说明优化后剩什么结构，汇编说明本机发出哪些指令，采样说明运行时走到了哪个函数。
跨层推断不算证据。异常表缺失只说明该函数正常路径不会展开。对照[定义 16.6.1](ch16.md#def-16.6.1)、[定义 16.6.2](ch16.md#def-16.6.2)、[定义 16.6.3](ch16.md#def-16.6.3)。

:::

:::

::: ex 卡 10 · 计时边界与每词成本 {#rc-16-10}

卡面：哪些阶段计入每个正式批次、哪些不计？ns/word 是什么量？

::: sol 核对

计入：每轮 FFI 调用、输入读取与输出写入、C 侧 checksum 遍历。
不计：初始化输入、独立参考 checksum、校验 expected、CSV 格式化与打印、程序启动与退出。
每词成本是一批的墙钟时间除以该批词数（这里固定 524288），是聚合量，包含循环、守卫、边界调用摊销与 C 侧遍历。对照[定义 16.7.1](ch16.md#def-16.7.1)、[定义 16.7.2](ch16.md#def-16.7.2)。

:::

:::

::: ex 卡 11 · 双向契约与两种消费位置 {#rc-16-11}

卡面：双向契约测试指什么？复制导出与拥有句柄内归约各交付什么？

::: sol 核对

双向契约是同一份契约由两侧各执行一次：Rust 侧证明内部不变量，C11 侧证明跨语言可观察行为。
任何一侧缺席，都只能说明「在我这边成立」。
复制导出用 `rb_copy` 把完整数组复制进 C 的缓冲，之后两份分配互相独立；拥有句柄内归约只交摘要，完整数组从未离开组件。对照[定义 16.5.4](ch16.md#def-16.5.4)、[定义 16.8.1](ch16.md#def-16.8.1)、[定义 16.8.2](ch16.md#def-16.8.2)。

:::

## 第二组 · 结论卡（说清数字与口径）

::: ex 卡 12 · 布局的六个断言 {#rc-16-12}

卡面：`InfoV1` 的尺寸、对齐、四个字段偏移是多少？两侧各用什么锁定？

::: sol 核对

24 字节、对齐 8；偏移 0、4、8、16。
Rust 用 `size_of`、`align_of`、`offset_of!` 断言，写在 `tests/contracts.rs::layout_matches_c_v1`。
C 侧用六行 `_Static_assert` 与 `offsetof`；头文件还断言指针大小为 8，32 位目标在构建阶段被拒。对照[16.2.2](ch16.md#sec-cpp-rust.4.16.2)。

:::

:::

::: ex 卡 13 · 错误码的资源后果 {#rc-16-13}

卡面：`EINVAL`、`ECAPACITY`、`ESTALE` 各自对资源和输出做了什么？

::: sol 核对

`EINVAL`（1）不消费原句柄：在 `rb_info` 上它连输出结构的一个字节都不写，版本或尺寸错误都走它。
`ECAPACITY`（4）时数据与 `written` 都不写，输出缓冲保持调用者的原值。
`ESTALE`（3）不再释放资源——槽里已经没有所有者，重复释放只会再得一次 `ESTALE`。对照[16.2.4](ch16.md#sec-cpp-rust.4.16.2)、[例 16.2.1](ch16.md#ex-16.2.1)。

:::

:::

::: ex 卡 14 · 一个句柄的两次生命 {#rc-16-14}

卡面：空表插入、释放、再插入，两个句柄的数值各是多少？旧句柄再用会怎样？

::: sol 核对

槽 0 首次启用代号 1，`h1 = (1 << 32) | 1 = 4294967297`，十六进制 `0x1_0000_0001`。
释放后槽 0 代号仍是 1、数据为空；复用时代号加一变成 2，`h2 = 8589934593`。
用 `h1` 查快照：低位 1 定位到槽 0，但代号 1 不等于 2，返回 `ESTALE`。对照[例 16.4.1](ch16.md#ex-16.4.1)。

:::

:::

::: ex 卡 15 · 十二个线程释放同一个句柄 {#rc-16-15}

卡面：12 个线程同时 `release(h2)`，各自拿到什么？为什么不会有两个析构？

::: sol 核对

恰好一个拿到 `OK`，其余 11 个看到 data 已空，各自得到 `ESTALE`。
原因是释放只在锁内 `take()` 一次：取走所有者是唯一的线性化点，后来者即使代号相同也过不了「槽仍持有所有者」那一关。对照[例 16.4.1](ch16.md#ex-16.4.1)。

:::

:::

::: ex 卡 16 · 第一组的两行数字 {#rc-16-16}

卡面：per_element 与 batch 的均值、N−1 sd、批 p50、批 p99 各是多少？两者 checksum 是什么？

::: sol 核对

per_element：0.978652、0.021629、0.986099、1.005173，n = 21。
batch：0.211897、0.004042、0.211716、0.217438，n = 21。
两者 checksum 都是 `999f7c01d1040000`；样本方差约 0.000467809 与 0.000016336，单位是 `(ns/word)^2`。
均值之差 0.766755 是每词聚合成本差，不是一次调用成本。对照[16.7.5](ch16.md#sec-cpp-rust.4.16.7)、[例 16.7.1](ch16.md#ex-16.7.1)。

:::

:::

::: ex 卡 17 · 第二组的两行数字 {#rc-16-17}

卡面：copy_out 与 owned_handle 的四个统计量各是多少？差值能说明什么？

::: sol 核对

copy_out：0.641505、0.028644、0.642776、0.684738，n = 21。
owned_handle：0.358854、0.013968、0.356674、0.400543，n = 21。
两者 checksum 都是 `f9e695131a980000`；差值 0.282651 是每词聚合差，量的是「导出并遍历」这一段。
两条路径都付了生成、分配、注册表、`Arc::from(Vec)` 内部复制与释放。对照[16.8.4](ch16.md#sec-cpp-rust.4.16.8)、[例 16.8.1](ch16.md#ex-16.8.1)。

:::

:::

::: ex 卡 18 · 代号退休的代价与测试账 {#rc-16-18}

卡面：代号到顶的槽会怎样？本轮四层测试各有多少项？

::: sol 核对

`find` 的条件是 `slot.generation < u32::MAX`，到顶的空槽被跳过，插入改用新槽；槽用满则返回 `ERESOURCE`。
代价是极端长期运行下可用槽逐渐减少，换来的是旧身份不会重新出现。
测试账：Rust 内部 4 项、Rust 导出契约 6 项、C11 契约可执行文件 1 项、CTest CLI 3 项，CTest 总计 4 项，其中一项是完整 C11 契约程序。对照[16.4.3](ch16.md#sec-cpp-rust.4.16.4)、[16.5.7](ch16.md#sec-cpp-rust.4.16.5)。

:::

## 第三组 · 第一行卡（只写第一步）

这一组练的是「一离开答案不知道第一行写什么」那个毛病。每题只写第一行动作，不做推理。

::: ex 卡 19 · 拿到 ESTALE {#rc-16-19}

卡面：第一行写什么？

::: sol 核对

第一行：先看低 32 位是否为 0——为 0 说明拿的是初值或默认值，根本没有创建成功。
之后才查二次释放、句柄来源、并发释放；不要在 `ESTALE` 之后继续读旧对象。对照[16.4](ch16.md#sec-cpp-rust.4.16.4) 的判定流程。

:::

:::

::: ex 卡 20 · 拿到 EPANIC {#rc-16-20}

卡面：第一行写什么？

::: sol 核对

第一行：先确认这是 `EPANIC` 还是 `EPOISON`，再看 panic 发生在取锁之前还是持锁期间。
取锁之前注册表仍可用；持锁期间才按毒化处理，之后的调用统一 `EPOISON`。对照[16.5](ch16.md#sec-cpp-rust.4.16.5) 的判定流程。

:::

:::

::: ex 卡 21 · 一个裸指针参数要进 unsafe {#rc-16-21}

卡面：第一行写什么？

::: sol 核对

第一行：先写零长放行——`len == 0` 直接返回空区间，null 在这个位置合法（仅数据区域）。
之后才是非空与对齐、乘法与 `isize::MAX`、`separate` 查相交；`from_raw_parts` 只能出现在这些之后。对照[定义 16.3.1](ch16.md#def-16.3.1)。

:::

:::

::: ex 卡 22 · 要给 ABI 结构加字段 {#rc-16-22}

卡面：第一行写什么？

::: sol 核对

第一行：先问「对方改了它，我要不要重新编译」——要，就不能插进已发布的 v1。
正确做法是定义 v2 结构与新入口，v1 定义保持不变；本版的 `struct_size` 仍必须恰好 24，传 23 只会得到 `EINVAL`。对照[定义 16.2.2](ch16.md#def-16.2.2)。

:::

:::

::: ex 卡 23 · 创建成功但 info 失败 {#rc-16-23}

卡面：第一行写什么？

::: sol 核对

第一行：仍然调用 `rb_release`，并检查它的返回码。
查询失败不消费句柄，清理责任还在调用者手上；只有创建成功之后才拥有要释放的句柄。对照[16.5.5](ch16.md#sec-cpp-rust.4.16.5)。

:::

:::

::: ex 卡 24 · 有人指着 vector.body 说 SIMD {#rc-16-24}

卡面：第一行写什么？

::: sol 核对

第一行：去本机汇编里找有没有对应的向量指令，而不是读 IR 的块名。
当前转换核在 `vector.body` 里是展开后的标量 i64 运算，本机汇编也是多条标量 `madd`，所以只能写「四元素展开」。对照[例 16.6.1](ch16.md#ex-16.6.1)。

:::
