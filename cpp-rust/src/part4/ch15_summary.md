## 一条主线

**先划范围 → 再把上界建在 spawn 之前 → 沿所有权链看取消 → 用三个观察点认回收 → 让代码生成与计时各自说话 → 用关闭协议与测试收口。**

- 15.1–15.2 回答「谁有资格进来、进来后谁持有资源」：注册入口、参数预算、`Q`/`C`/`R` 与总许可。
- 15.3–15.4 沿同一条所有权链回答「调用方走了工作还在谁手里、凭什么说收干净」：取消意图、许可寿命、wait、双路 EOF、join。
- 15.5–15.7 把结构、代码生成与两组计时接上：一组纳秒级的拒绝尝试，一组毫秒级的工具批完成。
- 15.8–15.11 收口：shutdown 协议、测试矩阵、采样边界、来源核读与复现契约。

跳过任何一环，后面的数字都只是没有回收凭证的观察。

## 能否讲出这几句话

不看书，用自己的话回答。答不上来的，回到对应小节只看那一段。

1. 有界执行器要求哪三件事？它明确不做的两件事是什么？为什么两者不能混着说？
2. 为什么「先 spawn 再等信号量」不算有界准入？`Q+C` 是持有上界还是接收保证？
3. 调用方 drop Ticket 之后，许可为什么不能立刻归还？它绑定的到底是什么？
4. wait 成功为什么还不算清理完成？`drain_grace` 到期允许写什么、不允许写什么？
5. `R=0` 时日志处理成本为什么不是零？size 表为什么不能当 RSS 公式？
6. 3.662 ns/拒绝尝试与 1.046813 ms/工具分别是什么对象？各缺哪一件限定就不能对外引用？

配套的检测：各节[即时自测](ch15.md#sec-cpp-rust.4.15.1)分散在正文末尾，跨节提取用[回忆卡](ch15_recall.md)，成套做题用[习题集](ch15_exercises.md)，限时验收用[综合自测卷](ch15_exam.md)，达标判定用[自检表](ch15_checklist.md)。

**机制参照。**「取消只能落在安全点上」不是本项目的发明：rCore 第 7 章的信号机制里，内核把这个检查放在 trap 处理完之后、交回用户态之前的最后一个路口，并靠一次专门的返回调用把执行现场恢复出来（站点见[参照主线](../rcore-line.md#rcore-line-map)）。这条机制解释了你为什么要挑点，但**不**告诉你该挑哪个点——那是本项目 15.6 节自己的判定。
