# 第十三章 · 闭卷回忆卡

「看懂」只说明答案在眼前时能识别；评审和故障定位要的是从空白纸上提取。这一页把第十三章拆成 24 张卡，先读卡面自己答，再展开核对。

**用法与节奏**

| 时点 | 做什么 | 判定 |
|:--|:--|:--|
| 学完当天 | 第一组「定义卡」11 张 | 关键词写全才算 ✓ |
| 第 1 天 | 第二组「结论卡」7 张 | 能说清前提才算 ✓ |
| 第 3 天 | 第三组「第一行卡」6 张 | 写出第一步才算 ✓ |
| 第 7 天 | 只重做标成 △ 与 × 的卡 | 全对即可进入第十四章 |

每张卡给自己一个记号：✓ 一次说对；△ 说对一半或要提示；× 想不起来。只重做 △ 与 ×，不要把整叠卡反复过一遍——那是在读，不是在提取。

## 第一组 · 定义卡（说全称与前提）

::: ex 卡 1 · 观测对象与分母 {#rc-13-1}

卡面：什么是观测对象，什么是分母？两者为什么决定一个百分比能和谁比较？

::: sol 核对

观测对象是数字真正统计的东西：一次批次的墙钟间隔、一段进程运行时间、一类硬件事件计数，或一批栈观察的条数。分母是归一化时用的计数集合：批内元素数、每次调用的字节数，或总观察数。分母不同的两张图，即使都写满 100%，说的也不是同一件事。对照[定义 13.1.1](ch13.md#def-13.1.1)。
:::

:::

::: ex 卡 2 · 证据层次 {#rc-13-2}

卡面：五层证据各是什么？为什么下层不会自动把样本转换成业务责任？

::: sol 核对

业务现象、执行分解、观测、候选机制、受控修改与独立重跑。业务现象含批次时间、输入与正确性；执行分解分运行、就绪未运行、主动等待、外部等待；观测是栈采样与符号，或阶段时间与标识；候选机制列更多工作、失去向量化（把逐元素运算合并成一条向量指令）、竞争、排队、外部资源；最后一层要求独立重跑并保留反例。每层只支持自己能支持的那句话。对照[定义 13.1.2](ch13.md#def-13.1.2)。
:::

:::

::: ex 卡 3 · 可反驳的归因假设 {#rc-13-3}

卡面：一句可反驳的假设必须含哪两件？「这个函数很热」为什么不算？

::: sol 核对

必须同时写出机制与至少一个能在现有证据之外检查、且有可能不成立的预测。它还要承诺业务输入输出不变、删除观测后结果不变等可检查事项。「这个函数很热」只是描述，没有任何结果能否定它。对照[定义 13.1.3](ch13.md#def-13.1.3)。
:::

:::

::: ex 卡 4 · inclusive 与 self {#rc-13-4}

卡面：inclusive 与 self 各统计什么？为什么把所有层的 inclusive 相加会出错？

::: sol 核对

inclusive 是经过这个栈帧的观察条数，已经包含所有经过该帧的子栈；self 是观察恰好停在这个位置的条数，也叫 exclusive 或叶子计数。父帧的 inclusive 已吃掉子帧的观察，逐层相加会把同一条观察数两遍。加完要与根对照：总数大于根，几乎一定是层级重复。对照[定义 13.2.2](ch13.md#def-13.2.2)。
:::

:::

::: ex 卡 5 · 事件契约 {#rc-13-5}

卡面：一个 PMU（硬件性能计数器）数字由哪五件事共同决定？缺一项会怎样？

::: sol 核对

事件完整名称与修饰符、计数范围（用户态／内核态过滤与线程、进程或 CPU 范围）、可用槽位、精确度（skid，事件发生位置与记录位置的偏移）、采集状态（丢失、不支持、未运行）。脱离这五项的一段输出没有唯一解释；别名在不同主机上也可能映射到不同原始编码。对照[定义 13.3.1](ch13.md#def-13.3.1)。
:::

:::

::: ex 卡 6 · 零、不支持、未运行 {#rc-13-6}

卡面：三种状态各是什么？压成一个 0 会污染哪些下游计算？

::: sol 核对

零是数据值，事件在采集期间确实没有发生；不支持是能力信息，该平台或权限无法计数；未运行是采集状态，事件被请求但没拿到槽位，或进程没覆盖到区间。压成同一个 0，读者会把「无法测量」读成「测得为零」，以这些数为分母的 IPC（每周期执行指令数）、miss 率都会算出无意义的值。对照[定义 13.3.3](ch13.md#def-13.3.3)。
:::

:::

::: ex 卡 7 · 折叠图的宽度与横轴 {#rc-13-7}

卡面：flamegraph（火焰图）的宽度承诺哪两件事？横轴与颜色各不承诺什么？

::: sol 核对

宽度承诺某个路径的权重份额，以及路径之间的层级关系；父框覆盖经过该调用路径的权重，子框展示更深一层的分布。横轴不是时间轴，相邻框不表示先后；颜色通常也不是温度计，没有图例时不能把红色解释成更慢或更高温。同名函数出现在不同父路径下，通常仍是不同框。对照[定义 13.4.1](ch13.md#def-13.4.1)。
:::

:::

::: ex 卡 8 · off-CPU 与线程栈快照 {#rc-13-8}

卡面：off-CPU 分析与线程栈快照各统计什么？为什么后者不能说「阻塞了精确多少纳秒」？

::: sol 核对

off-CPU 分析回答线程何时停止运行、何时重新运行，通常要调度事件与栈信息配合，重建部分运行区间，统计量是区间累计时长。线程栈快照只在若干时刻记录线程位于哪条栈上，等待线程可以反复显示同一睡眠栈，统计量是观察条数。观察条数无法换算出精确的阻塞时长。对照[定义 13.4.2](ch13.md#def-13.4.2)。
:::

:::

::: ex 卡 9 · 业务关联标识 {#rc-13-9}

卡面：业务关联标识是什么？三条设计约束各是什么？

::: sol 核对

让一条观察能被归回某个请求的最小信息，例如请求 id、span、任务 id 或消息序号。三条约束：跨线程可识别，同一请求由不同线程推进时仍能拼回；生命周期可区分，同一个 id 被复用时必须能分辨是哪一次；规模有界，不能为补因果永久保留全部上下文。采集顺序不等于因果顺序。对照[定义 13.4.3](ch13.md#def-13.4.3)。
:::

:::

::: ex 卡 10 · 同 checksum 诊断夹具 {#rc-13-10}

卡面：什么叫同 checksum 诊断夹具？它把比较收窄成了什么？

::: sol 核对

参与比较的分支共享完全相同的业务工作核与输出，校验和必须相等，只在被研究的那一个因素上不同。这样观察到的差异只能来自那个因素、夹具扰动或随机波动，不能来自「多做了一件事」。它把等价工作比较收窄成单因素实验。对照[定义 13.5.1](ch13.md#def-13.5.1)。
:::

:::

::: ex 卡 11 · 聚合 step 单位 {#rc-13-11}

卡面：`ns/聚合 step` 的分子分母各是什么？它不是什么？

::: sol 核对

一批 200000 步的总墙钟除以 200000。它回答「平均每步摊到多少时间」，是批次墙钟的一种归一化。它不是单步延迟的分位数，也不是一次事件的独立测量；读到 2.472857 或 32.832639 时，先记住分子是一整批的总时间。对照[定义 13.6.2](ch13.md#def-13.6.2)。
:::

:::

## 第二组 · 结论卡（说清前提与范围）

::: ex 卡 12 · 1698 与 1082 加 616 {#rc-13-12}

卡面：本轮 CPU 采样的根、两个叶子各是多少？为什么 1698＋1082＋616 是错的？

::: sol 核对

根 1698，`mix` 叶子 1082，`compute` 自身叶子 616，且 1082＋616 正好等于 1698。再加一次根，就是把同一批观察数了两遍。`mix` 的份额写成 1082／1698，`compute` 自身写成 616／1698，两者互斥、和为 100%。1698 是主线程根观察数，不是 CPU 时间、周期数或业务工作量。对照[例 13.2.1](ch13.md#ex-13.2.1)。
:::

:::

::: ex 卡 13 · 符号缺席的四条解释 {#rc-13-13}

卡面：图里没有函数 F，至少哪四种情况能解释？demangle（把修饰名还原成可读名字）后的名字能当 ABI（二进制接口约定）吗？

::: sol 核对

函数被完全内联（函数体被直接放进调用者）；尾调用改变栈形状；采样区间从未覆盖短暂初始化；工具无法展开某段栈。先查产物与采集范围，再判断 F 是否真的不运行。demangle 后的文字不能视为可链接的稳定 ABI；只保存转换结果还可能丢掉区分 crate 实例的信息，应同时保存命令与工具版本。对照[思考 13.2.1](ch13.md#think-13.2.1)。
:::

:::

::: ex 卡 14 · 六项归档与「基线还是线索」 {#rc-13-14}

卡面：采样报告的最低归档要求是哪六项？最常被省掉的是哪一项？

::: sol 核对

可执行映像或可核验指纹、源码指纹、构建 profile 与 feature 集合、目标三元组与编译器版本、采样命令与区间与间隔、原始报告而不只是截图。最常被省掉的是第五项；没有命令、区间与间隔，读者只能猜分母能怎么读。缺任何一项，图只能作临时线索，不能作长期回归基线。对照[定义 13.2.4](ch13.md#def-13.2.4)。
:::

:::

::: ex 卡 15 · 2000 与 1698 的缺口 {#rc-13-15}

卡面：2000 是怎么算出来的？1698 与 1648 小于它，能算丢样比例吗？锁步为什么让样本数失效？

::: sol 核对

2 秒除以 1 毫秒等于 2000，这是按请求参数推算的理想值。1698 与 1648 是报告根计数，都小于 2000；请求间隔不是精确时钟，工具会限流、合并或拒绝记录，进程启停也吃掉窗口两端，本轮没有采集丢样计数，缺口不能按比例归因。锁步时采样与周期性工作保持近似固定相位，增加样本只是在重复同一段代码，偏差不随样本数下降。对照[例 13.7.1](ch13.md#ex-13.7.1) 与[定义 13.7.1](ch13.md#def-13.7.1)。
:::

:::

::: ex 卡 16 · 13.3 倍是谁的开销 {#rc-13-16}

卡面：13.3 倍来自哪两个数、什么单位？它能不能写成 sample 或 perf 的开销倍率？

::: sol 核对

来自 each 的 32.832639 与 none 的 2.472857，单位是 ns/聚合 step，每批 200000 步，checksum 同为 188478885453998054。它来自应用自己逐项读时钟、构造事件并经屏障观察，差值里还含代码形状变化；各成分各占多少，本节没有采集。不能写成 sample 或 perf 的开销倍率：一个由应用自己读时钟，一个由外部进程读栈，观察对象与扰动来源都不同。附着／未附着对照本轮没有采集。对照[例 13.6.1](ch13.md#ex-13.6.1)、[定义 13.7.2](ch13.md#def-13.7.2)。
:::

:::

::: ex 卡 17 · 30.359782 与 0.002817 {#rc-13-17}

卡面：32.832639 减 2.472857 得 30.359782，为什么不能叫「打点净成本」？none 与 batch 的 0.002817 为什么不是优化？

::: sol 核对

因为是两整批墙钟的平均之差。插桩改变寄存器压力（同时要保活的临时值太多）、内联与循环优化机会，还改变运行时长与调度机会；减法需要额外的可加性假设，对极轻量循环尤其危险。0.002817 ns/step 约合 0.11%，小于两列任一批次标准差（0.094581 与 0.079995），把它写成优化是把噪声当收益。对照[例 13.6.1](ch13.md#ex-13.6.1)。
:::

:::

::: ex 卡 18 · 21 条上的 p99 与模拟器边界 {#rc-13-18}

卡面：N=21 时 p99 是排序后的第几条？六位小数是不是六位有效精度？Cachegrind 的数字是什么口径？

::: sol 核对

`ceil(0.99 × 21) = 21`，p99 就是 21 条批均值里的最大值；本轮 each 列是 34.306250。它描述批次之间的波动，不是逐 step 延迟，也不是生产尾延迟。六位小数只为复算保留，不代表六位有效精度。Cachegrind 累计的是模拟出来的指令计数，不是硬件 PMU 的 retired instructions（硬件实际退休的指令数）；它还可能默认关闭缓存模拟。本轮没有执行 Cachegrind，也没有生成任何 `cachegrind.out`。对照[定义 13.7.3](ch13.md#def-13.7.3)、[例 13.7.2](ch13.md#ex-13.7.2)、[定义 13.7.5](ch13.md#def-13.7.5)。
:::

:::

## 第三组 · 第一行卡（只写第一步）

这一组练的是「一离开答案不知道第一行写什么」那个毛病。每题只写第一行动作，不计算。

::: ex 卡 19 · 看到一块很宽的框 {#rc-13-19}

卡面：第一行写什么？

::: sol 核对

第一行：写权重与范围——这是观察条数还是时长，哪条线程、哪个区间、什么间隔。然后造两个竞争解释（更多次／每次更慢，或运行／等待），再设计能否定其一的实验。对照[定义 13.4.1](ch13.md#def-13.4.1)。
:::

:::

::: ex 卡 20 · 收到一张 PMU 截图 {#rc-13-20}

卡面：第一行写什么？

::: sol 核对

第一行：要原始报告、事件完整名称与修饰符、计数范围、`time_enabled`／`time_running` 或运行比例、以及错误输出。只有截图时，图降级为线索，既不能恢复丢失记录，也无法核对事件含义。对照[定义 13.3.1](ch13.md#def-13.3.1)。
:::

:::

::: ex 卡 21 · 要比较两张归一化图 {#rc-13-21}

卡面：第一行写什么？

::: sol 核对

第一行：先要两张图各自的总权重与总运行量，并注明是否归一化。否则「份额增加」会被读成「绝对成本增加」；本轮的 1698 与 1648 就是这类总量信息。对照[例 13.4.2](ch13.md#ex-13.4.2)。
:::

:::

::: ex 卡 22 · 有人提议先测 each 再减常数 {#rc-13-22}

卡面：第一行写什么？

::: sol 核对

第一行：停。写下「插桩改变寄存器压力、内联与循环形状，差值不是可加项」，再做保持其他条件不变的受控消融。本章只报告两套真实程序的总体差异，不报告推算出来的净打点成本。对照[13.6 逐项打点与批量聚合](ch13.md#sec-cpp-rust.4.13.6)、[思考 13.6.1](ch13.md#think-13.6.1)。
:::

:::

::: ex 卡 23 · 要把归因结论发出去 {#rc-13-23}

卡面：第一行写什么？

::: sol 核对

第一行：按六关顺序过一遍——正确性、单位、对象、原始数据、构建、完整性。六关全过，才写一句带条件的结论；任何一关不过，就写「证据不足」。对照[13.8 从代码生成到证据包](ch13.md#sec-cpp-rust.4.13.8)。
:::

:::

::: ex 卡 24 · 要归档一次采样 {#rc-13-24}

卡面：第一行写什么？

::: sol 核对

第一行：清点六项归档——映像与指纹、源码指纹、构建 profile 与 feature、目标三元组与编译器版本、采样命令与区间与间隔、原始报告。先保住原始报告，再谈截图与折叠结果；后者只是派生产物。对照[定义 13.2.4](ch13.md#def-13.2.4)、[定义 13.8.3](ch13.md#def-13.8.3)。
:::

:::
