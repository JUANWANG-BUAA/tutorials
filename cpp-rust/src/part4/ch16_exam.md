# 第十六章 · 综合自测卷

**闭卷，60 分钟，100 分。**不许查正文、不许跑代码、不许看[回忆卡](ch16_recall.md)。允许一张空白草稿纸。做完先按[评分标准](#ch16-exam-score)自己打分，再逐题对照解答；低于 70 分不要往下读下一章，回到扣分项对应的小节重读那一段。

时间分配建议：第一部分 12 分钟，第二部分 20 分钟，第三部分 23 分钟，留 5 分钟检查返回码与单位。

## 第一部分 · 概念辨析（每题 5 分，共 30 分）

判断对错并写一句理由。只写「对/错」不得分。

1. 句柄低 32 位为 0 表示无效身份，所以低 32 位为 0 的数值不可能是有效句柄。
2. `rb_transform` 批量入口为了跑分，跳过了长度、对齐与重叠检查。
3. `rb_release` 返回 `OK` 之后，任何线程都不可能再读到那块数据。
4. 21 个批均值的 nearest-rank p99，就是这 21 个数里的最大值。
5. `rb_info` 的 `struct_size` 传 23 时，会按前缀兼容少写一格并返回 `OK`。
6. panic 探针（故意触发 panic 的测试入口）跑过之后 C 侧仍能正常调用，说明全局 poison 恢复路径已经验证。

## 第二部分 · 误用判读与数据判读（共 30 分）

**7.（10 分）** 夹具先 `rb_create_copy(input, 3, &h)` 得到长度 3 的对象，`written` 预置 777，`info` 为调用者的原值。随后四次误用：

| 序号 | 调用 |
|:--:|:--|
| ① | `rb_info(h, 2, sizeof(info), &info)` |
| ② | `rb_info(h, 1, sizeof(info) - 1, &info)` |
| ③ | `rb_copy(h, short_out, 2, &written)`（`short_out` 只有 2 格） |
| ④ | `rb_release(h)` 之后 `rb_info(h, 1, 24, &info)` |

逐行填表：返回码、输出是否被改动、句柄是否被消费、接住它的守卫在函数体哪一步。

**8.（10 分）** 第一组实测两行：per_element 均值 0.978652、sd 0.021629、批 p99 1.005173；batch 均值 0.211897、sd 0.004042、批 p99 0.217438；两者 n 都是 21，checksum 都是 `999f7c01d1040000`。判断三句话，各给一句理由：

- (a)「一次跨边界调用成本 0.766755 ns。」
- (b)「批量比逐元素快约 4.6 倍。」
- (c)「batch 的 p99 是 0.217438 ns，线上尾延迟很低。」

**9.（10 分）** CLI 里 `rb_generate` 成功拿到句柄，接着 `rb_info` 返回 `EINVAL`。写出接下来的分支与释放动作；再补一句：如果 `info` 成功而 `rb_release` 返回 `ESTALE`，说明什么？

## 解答与给分说明

**1. 对。** 低 32 位是槽下标加一，为 0 保留为无效身份，所以低位为 0 只可能是初值或默认值，从未创建成功（[定义 16.4.1](ch16.md#def-16.4.1)）。

**2. 错。** 批量入口仍然检查参数、长度、对齐和重叠，守卫一个都没少；收益来自同一次检查摊到 8192 个词，以及更少的返回码分支（[16.7.6](ch16.md#sec-cpp-rust.4.16.7)）。

**3. 错。** 新查找必然 `ESTALE`，但先克隆出快照的读者仍能把 checksum 算完；`rb_release` 不是等待全部读取结束的 join（[定义 16.4.2](ch16.md#def-16.4.2)、[定义 16.4.3](ch16.md#def-16.4.3)）。

**4. 对。** nearest-rank 取排序后第 `ceil(21 × 0.99) = 21` 个，正是最大值；它描述批间波动，不是请求尾延迟（[定义 16.7.2](ch16.md#def-16.7.2)）。

**5. 错。** `struct_size` 必须恰好等于 24，否则返回 `EINVAL` 且一个字节都不写；前缀兼容需要先定义最小尺寸与写入上界，本项目没有实现（[定义 16.2.2](ch16.md#def-16.2.2)、[例 16.2.1](ch16.md#ex-16.2.1)）。

**6. 错。** 探针在取得注册表锁之前故意 panic，从未毒化注册表；全局 poison 只有局部 Mutex 的确定性测试覆盖（[例 16.5.1](ch16.md#ex-16.5.1)）。

**7.（参考表，每行 2.5 分）**

| 序号 | 返回码 | 输出 | 句柄 | 守卫位置 |
|:--:|:--|:--|:--|:--|
| ① | `EINVAL`（1） | `info` 未写 | 未消费 | `rb_info` 的第一条判断，排在 `range(out, 1)` 与句柄查找之前 |
| ② | `EINVAL`（1） | `info` 未写 | 未消费 | 尺寸必须恰好 24 那条判断 |
| ③ | `ECAPACITY`（4） | `short_out` 两格与 777 均未变 | 未消费 | `capacity < data.len()`，排在复制与写 `written` 之前 |
| ④ | `ESTALE`（3） | `info` 未写 | 已在 `rb_release` 那次被消费 | 槽里已无所有者（代号比较之后的同一把锁内） |

①③④ 都没有消费句柄，所以 ①②③ 之后仍可正常调用（[例 16.2.1](ch16.md#ex-16.2.1)）。

**8.（参考，各约 3 分 + 理由）**
(a) 不成立：0.978652 − 0.211897 = 0.766755 是每词聚合成本之差，含调用次数、每词错误码分支与守卫摊销的变化，两条路径的优化范围也不同。
(b) 在固定工作量、固定构建下成立，但要写成「本夹具的聚合成本约为逐元素的 1/4.6」；不能推广成对任何调用者的加速比。
(c) 不成立：21 个值的 p99 就是最大批均值，单位是 524288 个词一次批量；原始 `elapsed_ns` 还有 1000 ns 步长，1 ns 级差别不可分辨（[例 16.7.1](ch16.md#ex-16.7.1)）。

**9.（参考）** 仍然调用 `rb_release`，并检查它的返回码；查询失败不消费句柄，清理责任还在调用者手上，打印时把 info 的码与 release 的码一起报出来（[16.5.5](ch16.md#sec-cpp-rust.4.16.5)）。
若 `info` 成功而 `rb_release` 返回 `ESTALE`，说明这个句柄此前已被释放过一次，或它不属于这张注册表——一次创建只有一个释放责任，重复释放必然 `ESTALE`（[例 16.4.1](ch16.md#ex-16.4.1)）。

**10.（参考，每条 2 分）** ① 干净目录复现：离线且 `--locked` 跑 fmt、clippy（`-D warnings`）、`cargo test`、CMake 配置与构建、`ctest`。② 链接是真的：删掉 Rust 目标后 C 应当链接失败。③ 两侧布局都编译过：Rust 断言与头文件 `_Static_assert` 同时存在，24/8/0/4/8/16。④ 断言没被 Release 删掉：三个 C 目标带 `-UNDEBUG`，benchmark 用显式分支校验。⑤ 探针不进发布物：新目录加 `RB_TEST_HOOKS=OFF`，`rb_test_panic` 不导出。⑥ 代码生成对得上入口：保存 MIR / LLVM IR / 汇编逐层核对。⑦ 条件写进证据：工具链、目标三元组、优化配置、宿主与 cacheline 归档。
「链接是真的」的证法就是反向实验：把 Rust 目标从这个构建里拿掉，C 侧必须链接失败；做不到这一点的集成只是两份构建并排跑过（[定义 16.6.1](ch16.md#def-16.6.1)、[16.6 发布前 FFI 交付检查](ch16.md#sec-cpp-rust.4.16.6)）。

**11.（参考，三问各 3 分，扩大 ABI 面 3 分）** 谁分配：Rust 分配则 C 不能 `free`，必须给出一个消费者入口；C 提供缓冲则要声明容量与写入上界，容量不足需要一个像 `ECAPACITY` 的码。谁释放、何时：若指针只在下一次调用前有效，读取顺序就成了新契约，正是线程局部缓冲被批评的隐式寿命。寿命还牵涉跨模块可见性与编码。
拒绝的理由是资源后果：整数词表让每个数值对应一种可判定的后果（是否消费句柄、是否写输出），且没有借出的字符串。坚持要做的话，字符串编码、所有权、线程局部可见性都要进头文件，ABI 面随之扩大（[定义 16.2.3](ch16.md#def-16.2.3)、[16.2.4](ch16.md#sec-cpp-rust.4.16.2)）。

**12.（参考）** 结论句示例：「在这次固定的构建与 `aarch64-apple-darwin` 目标下，长度 8192 的对象走『generate → info → release』时，每词聚合成本为 0.358854 ns/word（n = 21，sd 0.013968）；它只覆盖只要摘要的调用者，不覆盖需要逐元素的场景，也不代表没有复制。」
差值解释：copy_out 还要在 C 侧遍历完整 output 求和，owned_handle 在 `rb_info` 内完成同一归约，两条路径的消费位置整个不同；0.282651 是每词聚合差，本轮也没有单独测 memcpy 吞吐，两条路径还共同承担 `Arc::from(Vec)` 的内部复制（[例 16.8.1](ch16.md#ex-16.8.1)）。

## 每题落在主线哪一步

分数只告诉你错了几个，这张表告诉你**缺的是哪一步的证据**。[四步主线](../mainline.md#mainline-spine)：① 工作真的发生、② 这个数是什么、③ 差异不是噪声、④ 守得住、可复核。这一章的 ① 与 ④ 都压在「谁负责、哪道守卫接住」这一条线上。

| 题 | 主导步 | 这一步在这里缺的东西 | 答不出先回 |
|:--|:--|:--|:--|
| 1 | ② | 句柄这个数怎么读：低 32 位是槽下标加一，0 是保留的无效身份；把数值当所有权凭证就错位 | [16.4](ch16.md#sec-cpp-rust.4.16.4) |
| 2 | ① | 批量入口的守卫一个都没少，收益来自一次检查摊到 8192 个词、少掉一段返回码分支 | [16.7](ch16.md#sec-cpp-rust.4.16.7) |
