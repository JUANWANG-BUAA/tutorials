# 实验怎么下笔：六种设计骨架

**设计一个能被别人复核的测量**，是这本书反复要练的事。跑一次 benchmark 不难，难在让别人照着重做也得到同样的数。[第 1 章](part1/ch01.md)给了判断标准：一个数字要可信，得先回答输入、计时、观察、外部条件这四组问题（[@def-1.1.3]）。标准不等于入口。真正动手时的卡点是一张空白页——你知道要比较两个东西，手指放在键盘上，写不出设计稿的第一行。

实验设计不从完整方案开始，而从五行草稿开始：

| 草稿栏 | 要写什么 |
|:--|:--|
| **对象** | 要估计的量是什么？单位、分母、结论的适用范围 |
| **前提** | 被测的工作真的发生了吗？谁读走了结果（[@def-1.3.1]） |
| **对照** | 和什么比？两边算的是不是同一个函数（[@def-1.6.1]） |
| **判定** | 看到什么算通过、什么算失败、什么算「现在还不能说」（[@def-1.7.2]） |
| **交接** | 别人凭哪几个文件复核（[@def-1.8.1]） |

::: method 下笔前的 30 秒

先不要装计时器。写下两句话：**我要估计的量是 ____；我打算推翻的说法是 ____。** 第二句写不出来，手上这个就还不是实验，只是一次好奇。

然后从下面六个骨架里挑一个：证机制、比快慢、扫参数、算代价、过门禁、找故障。每个骨架给一张填空模板和一个填好的样例。样例里的数字全部来自 [1 性能测量：让一个数字变得可信](part1/ch01.md)，没有一个是编出来的。

:::

## 六个骨架怎么选

| 你现在的处境 | 选哪个 |
|:--|:--|
| 想知道「它到底做没做」 | [骨架一](#skel-1) |
| 想知道「谁更省、差多少、方向定不定」 | [骨架二](#skel-2) |
| 想知道「参数推到哪儿开始变、到哪儿失效」 | [骨架三](#skel-3) |
| 想知道「为了这点速度付了什么」 | [骨架四](#skel-4) |
| 想知道「这个变更能不能合」 | [骨架五](#skel-5) |
| 想知道「这次跑不出来该动哪一层」 | [骨架六](#skel-6) |

前三个骨架产出认识，后三个骨架产出决定。一次实验常常要用两个：先证机制，再比快慢；先扫参数，再过门禁。

## 骨架一：机制验证型 {#skel-1}

**它回答什么问题。** 某个语义事实是不是真的成立。「编译器有没有把这段求和删掉」「这个写法到底生成没生成一次复制」「这条同步边建起来了没有」。答案不是快慢，是「发生了什么」。这一类骨架不需要时钟很准，需要的是可检查的痕迹。

**填空模板。**

```text
被检查的事实：在 ____（编译器版本 / 优化级别 / 目标三元组）下，
              ____（哪段代码）____（被删除 / 被保留 / 被合并 / 被执行）。
让它可观察的痕迹：动态侧 ____（每次调用的输出槽、停表后的比对）；
                静态侧 ____（哪几个生成代码文件）。
每层证据只说一句：MIR 说 ____；优化后 IR 说 ____；本机汇编说 ____；符号别名说 ____。
每层不能说的话：____。
结论句式：在这个构建产物里，____；这一层证据不支持 ____。
```

**填好的最小样例。** 这是第 1 章的第一个实验（1.5.1、1.5.4 的夹具与四层核对）。

```text
被检查的事实：rustc 1.99.0、aarch64-apple-darwin、opt-level=3 下，
              dce_empty 里那段 fold 不被执行。
让它可观察的痕迹：动态侧——批内每次调用一个 u64 输出槽（K = 256，N = 65536），
                停表后逐项比对；discarded 的期望值有意写成 0，不冒充求和值；
                静态侧——归档里的 .mir、.ll、.s 三个文件。
每层证据只说一句：MIR 仍可见迭代语义；优化后 IR 里这个函数返回常量 0；
                本机汇编只剩 mov x0, #0 与 ret。
每层不能说的话：不能因为「输入过了 black_box」就断言数组被读过；
              不能把 sum_iter 与 sum_soa 的符号别名说成 ABI 承诺。
结论句式：在这个构建产物里，求和被删除，0.000016082 ns/名义元素 只说明空路径被大分母稀释；
          这一层证据不支持「所有编译器都在同一阶段删除」。
```

**适用章节。** [1.1](part1/ch01.md#sec-cpp-rust.1.1.1)、[1.3](part1/ch01.md#sec-cpp-rust.1.1.3)、[1.5](part1/ch01.md#sec-cpp-rust.1.1.5) 是它的完整形态。后面几乎每一章的代码生成小节都回到这里：第 4 章 [4.3](part1/ch04.md#sec-cpp-rust.1.4.3)、第 6 章 [6.3](part2/ch06.md#sec-cpp-rust.2.6.3)、第 8 章 [8.2](part2/ch08.md#sec-cpp-rust.2.8.2)、第 12 章 [12.2](part3/ch12.md#sec-cpp-rust.3.12.2)、第 16 章 [16.6](part4/ch16.md#sec-cpp-rust.4.16.6)、第 17 章 [17.4](part4/ch17.md#sec-cpp-rust.4.17.4)（三种编解码写法各留下什么代码）。

**常见误用。** 在一层看到证据就宣布整条流水线成立，或者把交叉生成的汇编当成在目标机上跑过。

## 骨架二：A/B 配对对照型 {#skel-2}

**它回答什么问题。** 两个实现摆在一起，单位成本差多少、方向能不能定。它的全部心思都花在一件事上：把「实现之间的差异」和「机器随时间的变化」分开（[@def-1.4.1]）。

**填空模板。**

```text
A = ____，B = ____。两边算的是同一个函数吗：
   输入 ____ / 算术语义 ____ / 输出形状 ____ / 校验用的独立参考值 ____。
单位：批均值 = T / (K × N)，K = ____，N = ____，轮数 = ____。
夹具：两侧相同，够小，并且声明它仍然被计入 ____。
顺序：一轮内 A、B 各测一批；第 0 轮 ____，第 1 轮 ____，之后交替；
     每条记录存 round、position、case、单位、校验值 ____。
统计：每轮先算 d = b − a，再对 ____ 个 d 求均值与标准差；
     区间算法 ____、重采样次数 ____、随机种子 ____。
判定：区间含零写 ____；不含零写 ____；「等价」这个词要等 ____ 出现才允许用。
```

**填好的最小样例。** 第 1 章的第二个实验（1.6.1、1.6.3）。

```text
A = indexed（while 索引累加），B = iterator（copied + fold）。
同一个函数吗：同一份 data(65536)；都是 u64 模加法，换遍历顺序不改变结果；
            都返回完整 u64；expected 由一次独立的 fold 算出，不与被测实现同源。
单位：ns/元素，K = 512，N = 65536，21 轮。
夹具：两侧共用同一个 run，闭包调用、输出数组写入、black_box 都在计时之内。
顺序：第 0 轮 indexed、iterator，第 1 轮反过来，之后交替；21 是奇数，
     A 先跑 11 次、B 先跑 10 次——这一轮不平衡写进结论，不藏起来。
统计：d 均值 0.000074625，d 标准差 0.000484383；
     固定种子 13013、10000 次有放回重采样，区间 [−0.000128553, 0.000269819]，跨零。
判定：写「本次运行内方向不可判定」；不写「等速」，因为还没有预算 B。
```

**适用章节。** [1.4](part1/ch01.md#sec-cpp-rust.1.1.4)、[1.6](part1/ch01.md#sec-cpp-rust.1.1.6)。后面各章凡是「几个实现争谁更省」的 benchmark 节都用这套结构：第 3 章 [3.5](part1/ch03.md#sec-cpp-rust.1.3.5)（借用与显式克隆）、第 5 章 [5.5](part2/ch05.md#sec-cpp-rust.2.5.5)（每元素分派与每批分派）、第 7 章 [7.5](part2/ch07.md#sec-cpp-rust.2.7.5)、第 11 章 [11.6](part3/ch11.md#sec-cpp-rust.3.11.6)（无锁队列对决互斥锁队列）、第 12 章 [12.6](part3/ch12.md#sec-cpp-rust.3.12.6)、第 16 章 [16.7](part4/ch16.md#sec-cpp-rust.4.16.7)（逐元素调用与批量 FFI）、第 17 章 [17.8](part4/ch17.md#sec-cpp-rust.4.17.8)（内存表基线对整台引擎的批生命周期）。

**常见误用。** 先跑完 A 再跑完 B，或者把两组各自的均值算好再相减，冒充配对差值（[@def-1.4.2]）。

## 骨架三：参数扫描型 {#skel-3}

**它回答什么问题。** 沿一个自变量往外推——输入规模、批大小、并发度、队列深度、对齐粒度——成本在哪儿改变斜率，结论在哪儿失效。扫描的价值不在曲线好看，在于它同时给出拐点和你不该再往外走的边界。

**填空模板。**

```text
自变量 = ____；档位 = ____、____、____（至少一档落在已知的失效区）。
其余全部固定：输入家族 ____、K ____、构建配置 ____、顺序规则 ____。
每一档是一次独立实验，不是同一实验的重复：这档的单位 ____、分母 ____。
拐点判据（采集之前写）：当 ____ 时，认为斜率或量级改变。
失效边界：到 ____ 结论不再适用，因为 ____。
跨档只比：____（同一个定义清楚的单位）；不同入口不能当成同一个实验的随机重复。
```

**填好的最小样例。** 只填设计，不填结果。档位借第 1 章正确性回归已经用过的输入长度（1.5.5）。

```text
自变量 = 每次调用处理的元素数 N；档位 = 0、1、7、65、65536。
其余固定：u64 模加法；同一份生成规则（索引乘 17 再异或常量）；K = 256；
        同一构建（rustc 1.99.0、target-cpu=native、opt-level=3）；同样的交替顺序。
每档独立：单位都是 ns/元素，但 65536 那档走的是热数据路径，
        N = 1 那档走的是调用与夹具——两档的估计对象已经不同。
拐点判据：单位成本低于一次整数加法的量级（零点几纳秒）时，先查工作有没有发生，
        不宣布「变快」（1.8.7 的异常快检查）。
失效边界：输入短到落在向量化尾部之外时，比较对象不是算法而是分派与夹具。
跨档只比：同单位、同夹具、同构建；每档的 K 与 N 一起公布。
```

**适用章节。** [1.2](part1/ch01.md#sec-cpp-rust.1.1.2)（K 与缓存状态）、[1.5](part1/ch01.md#sec-cpp-rust.1.1.5)（长度回归）。第 2 章 [2.5](part1/ch02.md#sec-cpp-rust.1.2.5) 就是按列做的扫描；第 7 章 [7.5](part2/ch07.md#sec-cpp-rust.2.7.5)、第 9 章 [9.5](part3/ch09.md#sec-cpp-rust.3.9.5)（让出粒度与 worker 数）、第 12 章 [12.6](part3/ch12.md#sec-cpp-rust.3.12.6)（标量、自动与手写向量三档）、第 14 章 [14.4](part4/ch14.md#sec-cpp-rust.4.14.4)（CGU 与 LTO）扫的是不同的量。

**常见误用。** 把不同 K、不同规模的档位当成同一个实验的重复样本，或者扫完之后回头挑一个好看的点当拐点。

## 骨架四：资源代价型 {#skel-4}

**它回答什么问题。** 时间之外的东西：内存、正确性覆盖、精度、panic 面、回收延迟。一个更快的实现可能分配更多内存，也可能把误差界放宽，或者让某类输入不再被检查（1.7.6）。这个骨架把这些代价写成与时间并列的可判定约束。

**填空模板。**

```text
时间：单位 ____；结论 ____；这一条对应的业务余量 ____。
内存：测的是峰值还是常驻 ____；采集方式 ____；超出多少算失败 ____。
正确性：必须通过的输入家族与测试 ____；校验强度是否配得上声明 ____。
语义 / 精度：算术语义 ____；换顺序会不会改变结果 ____；
           会的话，误差界 ____、在哪个量级上比较 ____（采集之前定）。
任何一条被突破都算失败。
结论句式：在 ____ 条件下 ____ 变好，代价是 ____；这个取舍影响的是 ____ 类工作负载。
```

**填好的最小样例。** 第 1 章 1.7 节那个思考框的完整填法。

```text
时间：批均值下降 8%。原来的预算只写了「每元素耗时」这一条——这就是预算漏项。
内存：峰值从 240 MB 涨到 336 MB。它是独立的一条约束，不是时间的附属说明。
正确性：逐次比对只覆盖「结果相等」；空输入、短输入、非整块尾部要另一个测试。
      checksum 相同不等于实现正确（1.3.4）。
语义 / 精度：u64 模加法可以换顺序；换成 f64 就必须先写误差界，否则测的是两个不同
           函数（例 1.1.3）。
判定：时间通过、内存突破 → 整体失败。要放行，就把取舍和受影响的工作负载一起写进
     结论，而不是只报「快 8%」。
```

**适用章节。** [1.7](part1/ch01.md#sec-cpp-rust.1.1.7)。第 2 章 [2.6](part1/ch02.md#sec-cpp-rust.1.2.6)（容量失败与安全字节区域）、第 3 章 [3.5](part1/ch03.md#sec-cpp-rust.1.3.5)（借用与显式克隆）、第 6 章 [6.6](part2/ch06.md#sec-cpp-rust.2.6.6)（静态表复用与逐批重建）、第 11 章 [11.7](part3/ch11.md#sec-cpp-rust.3.11.7)（停顿参与者的回收代价）、第 12 章 [12.7](part3/ch12.md#sec-cpp-rust.3.12.7)（复制流与借用分帧）、第 15 章 [15.2](part4/ch15.md#sec-cpp-rust.4.15.2)（有界准入）都是它的战场。

**常见误用。** 用速度收益把内存和正确性预算覆盖掉，或者看到结果之后再补一条对自己有利的约束。

## 骨架五：门禁判定型 {#skel-5}

**它回答什么问题。** 这个变更能不能发布。只问一件事：有没有越过预先写下的预算。统计问题和工程问题分开回答：区间由实验给，预算由业务给（[@def-1.7.1]）。

**填空模板。**

```text
回归量 = ____ − ____ 的配对差值，单位 ____（与统计量同一口径）。
预算 B = ____（绝对量），来自这条业务约束 ____；写下的时间点：采集之前。
并列约束：内存 ____ / 正确性 ____ / 精度 ____；任何一条突破都算失败。
三态：U ≤ B → ____；L > B → ____；L ≤ B < U → ____。
等号归哪边：____（预先固定，不为这次变更改口径）。
相对预算怎么进来：____（把统计量换成同一口径的相对量，不能塞进绝对区间）。
停止规则：____（固定轮数；不越看越停）。
不进三态的两种情况：正确性失败、夹具被优化删除。
```

**填好的最小样例。** 例 1.7.1 的三组候选，加上 1.7.9 那段可执行判定的边界约定。

```text
回归量：候选 − 基线的配对差值，ns/元素（第 1 章口径见 1.6.3）。
预算：B = 0.0005 ns/元素，约定是「每元素多花 0.0005 纳秒以内可接受」。
三组候选：[0.0002, 0.0004] → U ≤ B，记录协议后接受；
         [0.0006, 0.0011] → L > B，阻止发布并分析；
         [−0.0001, 0.0009] → L ≤ B < U，证据不足，既不放行也不退回。
等号：gate.py 把 high == budget 视为可接受；low == budget 而 high 更大时仍是证据不足。
停止规则：固定 21 批；不重跑直到出现 accept。
出局条件：checksum 不过 → 先修功能；工作被删 → 重建观察边界，两条都不进三态。
```

**适用章节。** [1.7](part1/ch01.md#sec-cpp-rust.1.1.7)、[1.6](part1/ch01.md#sec-cpp-rust.1.1.6)（区间怎么来）。工程侧的延伸集中在第 14 章：[14.5](part4/ch14.md#sec-cpp-rust.4.14.5)（会拒绝的门禁）、[14.7](part4/ch14.md#sec-cpp-rust.4.14.7)（CI 先验证证据再比数字）、[14.8](part4/ch14.md#sec-cpp-rust.4.14.8)（从实验包到发布责任链）。

**常见误用。** 看到数字之后再定 B，或者把「证据不足」重跑成一次绿灯。

## 骨架六：失败定位型 {#skel-6}

**它回答什么问题。** 一次复现失败、一次和书上对不上的结果，到底属于哪一层。五层的修法完全不同：构建、功能、采集、解释、统计（1.8.9）。不分层，就只能整章重跑。

**填空模板。**

```text
① 构建：编译起来了吗？工具链 ____、目标三元组 ____、依赖是否锁定 ____。
② 功能：校验值与独立参考值对不对得上 ____；不过就先修功能。
③ 采集：每个 case 的轮次齐吗？round、position、case、单位、校验字段都在吗？
       缺失的批次有没有被分析脚本默默当成有效小样本 ____。
④ 解释：新机器的代码生成或布局变了吗？结论的适用范围要不要改写 ____。
⑤ 统计：区间是不是跨预算 ____；跨了就是证据不足，不是二选一。
报告句式：第 ____ 层失败；第一行动作是 ____；性能字段 ____（留空 / 只作参考）。
```

**填好的最小样例。** 例 1.8.1 的三则报告。

```text
① 换一台机器，cargo test 就没过 → 构建失败。性能字段留空，先对齐实验契约的
  外部条件（1.1.3）。
② 跑通了，checksum 与归档不符 → 功能失败。先修功能，短耗时没有意义。
③ 跑通且校验通过，批均值 0.11 ns/元素，比第 1 章的 0.0586 大近一倍 → 解释失配。
  这不一定是错误，而是结论的适用范围变了：改写结论句，而不是追问
  「为什么没跑出书上的数」。
```

**适用章节。** [1.8](part1/ch01.md#sec-cpp-rust.1.1.8)。第 4 章 [4.8](part1/ch04.md#sec-cpp-rust.1.4.8)（证据链与回归定位）、第 13 章 [13.8](part4/ch13.md#sec-cpp-rust.4.13.8)（从代码生成到证据包）、第 14 章 [14.7](part4/ch14.md#sec-cpp-rust.4.14.7) 都会用到这张分层表。

**常见误用。** 五层统一写成「benchmark 失败」，于是每次失败都要把整章重跑一遍。

## 四个常见「断笔点」

| 卡住的位置 | 自问 | 修复动作 |
|:--|:--|:--|
| 写不出第一行 | 我要估计的量是什么？单位里的分母是谁给的？ | 先写「估计对象 = …」，再选骨架 |
| 不确定该加几道屏障 | 真实应用读走了结果的哪一部分？ | 让夹具复刻应用的输出形状（[@def-1.1.2]） |
| 跑完不敢下结论 | 有没有一条在采集之前写下的判据？ | 补预算 B 或三态规则，写在下一轮之前 |
| 数字好看得可疑 | 结果被谁用了？分母是真实工作量吗？ | 回到[@def-1.1.1]与[@def-1.5.1]，先看代码再解释表 |

::: method 一页练习

不看正文，只写设计的第一行和判定规则，不做任何计算：

1. 证明某个 `fold` 在 release 下被删掉了（骨架一）。
2. 比较两种 JSON 序列化器的单位成本（骨架二）。
3. 找 worker 数与让出粒度的拐点（骨架三）。
4. 一个改动快 8%、峰值内存从 240 MB 涨到 336 MB（骨架四）。
5. 给「p99 读延迟 ≤ 10 ms」的组件设一道门禁（骨架五）。
