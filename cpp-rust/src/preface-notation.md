# 符号表

符号表管记号，[术语表](appendix/glossary.md)管词。术语表一条一个词，给一句话定义；这一页一条一个记号、单位或缩写。

它多了两样东西：这个记号在哪一节被讲清楚，以及它最容易和谁混淆。查到一个记号，点第三列回去读正文；正文才给证明。

全书的数字都绑定环境：一台机器、一个工具链版本、一组构建参数。这一页只说明记号指什么，不复述数值。凡是「本机」量，都以正文的归档为准。

**表的读法。**第一列是书里原样出现的写法；第二列是一句大白话；第三列指向这一项被定义或被展开的那一节；第四列只在真有易混点时填。空格不是省略，是「这一条没有已知的坑」。

[导论](introduction.md)先把编译流水线的名字点了一遍——HIR、MIR、LLVM IR、单态化、LTO、`opt-level`。这一列给的是真正展开它们的那一节，不是第一次念到名字的地方。

::: note 字母 `N` 在本书有三种用法

第 1 章的 `N` 是一次调用处理的元素数（1.2）。同一个字母在第 1.5 节的 sd 与 nearest-rank 里指样本个数，在第 7.5 节里指线程个数。读到 `N` 先认节，再代公式。

第 7.5 节里每个线程的操作数记作 `I`，两者相乘是要校验的总量；`I` 别和罗马数字一混。`j` 是线程序号，只用来指「第 j 个位置」。

:::

| `ns` | 纳秒，十亿分之一秒 | [1.1](part1/ch01.md#sec-cpp-rust.1.1.1) | 单位写到这里，不代表这块时钟真能分辨到纳秒 |

## 这一页没收录什么 {#sym-scope}

第一，不收录 Rust 语法本身。语言基础在[阅读指南](guide.md)里给了去处，书里只在性能相关处解释机制。

第二，不收录没有正文依据的记号。某个缩写如果在某章只出现一次又立刻被解释掉，就留在那一章，不在这里重复。

第三，不做数值速查。缓存行字节数、缓存容量、批次数量这类数，都绑定一台机器和一个版本，一律回到该节表格里看，抄进这张表就会变成假的通用值。

要找词的解释，去[术语表](appendix/glossary.md)。要找「我现在该怎么做」的清单，去[速查卡](appendix/cheatsheet.md)。要背一句结论和它的前提，去[速查背记卡](memory-sheet.md)。
