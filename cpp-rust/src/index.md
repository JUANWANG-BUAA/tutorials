# Rust 底层性能工程

你写了一段 Rust 代码，逻辑没问题，测试也过了，但一到压测就慢得莫名其妙。你打开 profiler，看到一堆看不懂的栈；你把 `clone` 改成引用，快了一点，但不知道为什么会快；你听说 `Relaxed` 比 `SeqCst` 快，改完却没有变化。你想要的不是「性能优化 108 招」，而是一套能回答「为什么慢、改哪里、改完怎么证明」的方法。

这本书是一本教材，讲的就是这套方法。你可以在课堂上按[课程说明](syllabus.md)的 18 周计划学，也可以自己按[阅读指南](guide.md)的路径读。

**只学过 Rust 基础语法、没学过计算机底层？** 从[第 0 章 · 零基础起步](onboarding.md)开始：它只用你会的那点 Rust，把「代码怎么变成机器指令、内存和缓存是什么、纳秒意味着什么」讲到够用，并给出一条 12 周的慢速路线——最后两周落在[第 17 章](part4/ch17.md)的大项目上，让你亲手把四步主线走通一次。

**想知道这本书到底通向哪里？** 看[主干线与终极目标](mainline.md)：一条四步主线、十七章各挂在哪一步、以及学完之后你能交出的三件产物（组件、证据包、一页结论）和十二个必须答得上的追问。这三件产物不是口号——[第 17 章 · 综合大项目](part4/ch17.md)就是把它们一次交出来的那份作业。

**想知道「这个代价到底在哪一层发生」？** 看[参照主线：把 rCore 当成机制侧的坐标系](rcore-line.md)：它把清华大学那本用 Rust 写内核的教材逐页映射到本书的章节，告诉你某个用户态的慢，往下一层是哪条内核机制在被付账——以及为什么这条线上的数字一个都不能借。

它从 Rust 程序真正变成机器码的过程讲起：编译器把你的代码降成什么、对象在内存里怎么摆、原子操作在硬件上付出什么代价、async 任务怎么被调度、进程和管道怎么背压、SIMD 和零拷贝能带来多少真实收益，以及怎样用 profiling 和回归门禁把「感觉快了」变成可复核的证据。每一章都尽量给出可运行的代码、原始数据和适用边界；没有测量的地方，书里会明说。

如果你对「延迟、吞吐、尾延迟、资源占用」这些词还没有把握，先读[导论](introduction.md)。它用几个真实场景把这些指标分开，再说明一个请求从客户端到磁盘要经过哪些层。

## 这本书不是什么

**它不是 Rust 语法书。** 变量、函数、`match`、模块、生命周期这些基础语法，书里不重复讲。但「只会基础语法、没学过计算机底层」并不妨碍开始：[第 0 章 · 零基础起步](onboarding.md)会用你已有的那点 Rust，把机器码、内存、缓存、线程这些词讲到够用，再交回给正文。如果你连基础语法还没写过，先读[《Rust 程序设计语言》中文版](https://rustwiki.org/zh-CN/book/)第 4、10、11、13 章。

**它不是「最佳实践清单」。** 书里不会给你一组「永远这样写」的规则。性能结论依赖编译器版本、目标平台、输入规模和工作负载；同一段代码在另一台机器上可能得到相反的结果。这本书教你怎么在自己的机器上把结论重新测出来，而不是让你背结论。

**它不是一台机器的跑分报告。** 书中的数字来自一台具体的 Mac（Apple M5 Pro，`aarch64-apple-darwin`，rustc 1.99.0）。这些数字用于说明方法和量级，不是跨平台承诺。哪些结论可以搬走、哪些必须重测，[阅读指南](guide.md)和每一章的「边界」小节会分别说明。

## 读之前，你最好已经会

- Rust 的基本语法、所有权、借用、`trait`、`Result` 和 `cargo`；
- 操作系统的基本概念：线程、进程、虚拟内存、系统调用；
- 一点统计常识：均值、标准差、分位数、置信区间。

缺哪一项，先补哪一项，具体补法见[先修工具箱](prerequisite.md)——它按「所有权、操作系统与硬件、统计与抽样、编译器与命令行」四个抽屉给出最小可用版本，随用随查。不确定自己缺哪一格，先花 15 分钟做[入学诊断自测](entry-test.md)。硬着头皮读下去，你会在第 1 章被 DCE 和 `black_box` 卡住，在第 7 章被 happens-before 卡住，在第 9 章被 Tokio 的状态字卡住。那不是你的问题，是前置知识没到位。

## 三条阅读路径

这本书不要求你从第 1 页读到最后一页。你可以按下面的路径选一条。

**通读：先建立完整的方法链。** 按 `1 → 2 → 3 → 4 → 7 → 8 → 9 → 13 → 14 → 15/16 → 17` 读。这条路径覆盖「测量—对象—所有权—编译器—并发—异步—执行器—profiling—门禁—项目」，先把性能工程的主干走通。第 5、6、10、11、12 章可以第二遍再读。最后那一章（[第 17 章](part4/ch17.md)）是毕业作品：把十六章的机制收进同一个代码仓库，并交出一份别人能复核的证据包。

**按问题查：带着一个具体问题进来。**

| 你的问题 | 先读 |
|:--|:--|
| 结构体、容器、缓存为什么慢 | 第 2、3、5、6 章 |
| 锁、原子、无锁队列怎么选 | 第 7、11 章 |
| async 任务为什么不被调度 | 第 8、9 章 |
| 进程、管道、日志为什么堵 | 第 10、12 章 |
| 不知道程序慢在哪 | 第 1、13、14 章 |
| 要把优化做成可发布的组件 | 第 15、16、17 章 |
| 一个人做完一整件事，从设计到能交付 | 第 17 章（前面各章按需回查） |

**查阅：只想知道一个词或一个命令。** 直接看[术语表](appendix/glossary.md)和[速查卡](appendix/cheatsheet.md)。术语表按主题分组，每条都给出一句话定义和正文入口；速查卡把内存序选择、布局属性、测量检查、profiling 命令、FFI 清单压成表。

## 约定

- **路径**：正文里的 `bench/...`、`projects/...` 都相对于仓库的 `cpp-rust/` 目录；在网页上可以直接点开对应的 GitHub 目录。
- **代码块**：`rust` 是可以编译的 Rust；`text` 是伪代码或格式示意；`asm` 是编译器实际生成的汇编；`bash` 是可以在终端执行的命令。
- **单位**：`ns/元素` 是批均值除以元素数，`ns/调用` 是批均值除以调用次数；正文会明确说分母是什么。批均值不是单次请求延迟，p99 也不是「最慢的那一次」。
- **本机与可移植**：标为「本机」的数字只在作者这台 Mac 上有效；标为「机制」的结论（比如「Release 发布之前的写入对 Acquire 可见」）不依赖机器，但仍然依赖你正确使用同步原语。
- **证据**：正文里的表格和结论都对应实验包里的原始 CSV、`statistics.json` 或编译器输出。找不到对应文件的数字，不应该被引用。

## 版本与勘误

本书的快照日期是 2026 年 10 月。正文固定使用 rustc 1.99.0、LLVM 23.1.1、Tokio 1.54.0；涉及 nightly 内部接口的地方会单独标注版本。编译器、标准库和 Tokio 都会继续变化，书里的行为观察可能随版本失效；如果你发现某段代码在新版本上不再复现，先检查版本，再提 issue。

勘误、实验包更新和补充测量记录在仓库的 [GitHub Issues](https://github.com/JUANWANG-BUAA/tutorials/issues)。提交问题时，请附上你的 `rustc -Vv`、目标三元组、`Cargo.lock` 和最小复现代码；只写「我这边跑不出来」无法定位。
