# 第四章 · 闭卷回忆卡

「看懂」只说明答案在眼前时能识别；评审和生产事故需要的是从空白纸上提取。这一页把第四章拆成 24 张卡，每张卡先写卡面问题，合上正文自己答，再展开核对。

**用法与节奏**

| 时点 | 做什么 | 判定 |
|:--|:--|:--|
| 学完当天 | 第一组「定义卡」全部 8 张 | 三层、四类说全才算 ✓ |
| 第 1 天 | 第二组「结论卡」全部 8 张 | 能说清前提与适用范围才算 ✓ |
| 第 3 天 | 第三组「第一行卡」全部 8 张 | 只写出第一步动作也算 ✓ |
| 第 7 天 | 只重做标成 △ 和 × 的卡 | 全对即可进入下一章 |

每张卡给自己一个记号：✓ 一次说对；△ 说对一半或要提示；× 想不起来。只重做 △ 和 ×，不要把整叠卡反复过一遍——那是在读，不是在提取。

## 第一组 · 定义卡（说全称与前提）

::: ex 卡 1 · 分层证据 {#rc-04-1}

卡面：写出分层证据的三层，各说一句「它只支持什么判断」。

::: sol 核对

语言允许的行为：只规定义务，即谁可用、谁负责释放，不规定机器动作。固定版本编译器采用的表示：记录这一版用什么结构表达该程序，如 HIR、THIR、MIR 里的 Place、`move`、cleanup 边。固定目标机器执行的程序：记录这次构建真正留下哪些调用与内存操作，即 LLVM IR、汇编与实际运行的代码。前一层约束后一层，但不唯一决定后一层。对照[定义 4.1.1](ch04.md#def-4.1.1)。
:::

:::

::: ex 卡 2 · 概念依赖图 {#rc-04-2}

卡面：表示关系图表达的是什么？它与时间日志差在哪？

::: sol 核对

它表达「哪个表示需要哪个前置事实」，不是「谁先执行完」。允许两个函数体停在不同阶段，也允许一份产物在被需要时才第一次构造。时间日志是一串按时间排好、可逐条复现的执行记录，本章没有采集这类日志。所以不能从图里一个箭头推出整个 crate 已完成前一阶段。对照[定义 4.1.2](ch04.md#def-4.1.2)。
:::

:::

::: ex 卡 3 · 本机观察 {#rc-04-3}

卡面：什么叫本机观察？它的适用范围由什么划定？举一个本章的本机观察。

::: sol 核对

只在这台机器、这个版本、这套选项下成立的事实。适用范围由第 1 章的外部条件集合划定：换工具链提交、换目标三元组、换构建选项，都算换了一个观察对象。可以如实报告，但不能升格成承诺。本章的例子：系统报告的 cache line 为 128 字节，来自这台 Apple M5 Pro、macOS 27.0.1 上 `environment.txt` 的一条查询输出。对照[定义 4.1.3](ch04.md#def-4.1.3)。
:::

:::

::: ex 卡 4 · HIR 与项的身份 {#rc-04-4}

卡面：HIR 的关键变化是什么？「身份」与「一次使用」怎么区分？

::: sol 核对

HIR 是解析与脱糖之后、以项为单位的表示；项指有身份的定义，如模块、函数、结构体、trait。关键变化是身份与依赖粒度：读父模块不必无条件读每个函数体。身份指「这是哪一个定义」，一次使用指「哪一处源码引用了它」；一个函数可以有无数调用位置，每个有自己的源码范围，位置不是多份定义；两处文字相同的类型也可能是两个语法位置上的同一类型。对照[定义 4.2.1](ch04.md#def-4.2.1)、[定义 4.2.2](ch04.md#def-4.2.2)。
:::

:::

::: ex 卡 5 · THIR 与 body {#rc-04-5}

卡面：THIR 把哪四类隐式动作写显式？body 指什么？

::: sol 核对

自动引用、自动解引用、方法调用与重载运算符选到的具体目标、销毁作用域。它位于类型检查之后，节点已带类型，使从高级表达式降级到控制流有足够信息。body 是它承载的范围：函数体与 `const` 初始化器；结构体声明本身不是 body。不能把 THIR 想成 HIR 全树的常驻副本，它按需构造、及时释放。对照[定义 4.2.3](ch04.md#def-4.2.3)。
:::

:::

::: ex 卡 6 · local、Place 与投影 {#rc-04-6}

卡面：三个词各指什么？为什么记账单位不是变量名？

::: sol 核对

local 是 MIR 函数体里的存储槽编号，写成 `_0`、`_1`，`_0` 通常是返回位置；编号不是稳定符号。Place 是一个可访问位置；投影是附加在它后面的访问步骤：字段名、解引用、下标。整个 local、`a.0`、`*p`、`v[3]` 是四个不同的 Place。初始化和借用都按 Place 记账，因为结构体部分移动要区分字段。对照[定义 4.3.1](ch04.md#def-4.3.1)、[定义 4.3.2](ch04.md#def-4.3.2)；move path 的父子关系见[定义 4.3.3](ch04.md#def-4.3.3)。
:::

:::

::: ex 卡 7 · 两个初始化集合 {#rc-04-7}

卡面：给出「必定初始化」与「可能未初始化」的定义，各说一句合流规则。

::: sol 核对

必定初始化：该位置在到达这个点的所有路径上都已完成初始化；合流点要求所有前驱都成立，一条缺失就够推翻它。可能未初始化：至少一条到达路径没有初始化它，或某条路径把它移走了；只要一条路径成立就成立。前者决定能否无条件读取，后者决定析构责任是否需要保留。这是本章阅读产物的记法，不是 rustc 内部类型的名字。对照[定义 4.3.4](ch04.md#def-4.3.4)。
:::

:::

::: ex 卡 8 · 四类析构责任与 cleanup 块 {#rc-04-8}

卡面：说出四类情形各是什么；MIR 里标着 cleanup 的基本块管什么？

::: sol 核对

Static 是此处总是已初始化；Dead 是此处总是未初始化；Conditional 是整体有或整体无，取决于到达路径；Open 是可能只剩部分字段。标着 `(cleanup)` 的块是展开路径上的收尾块：前面的操作 panic 时控制流沿 unwind 边进入它，由它销毁此刻仍负责的位置，再用 `resume` 把异常往外传。`return`、`goto` 属于正常边。对照[定义 4.4.2](ch04.md#def-4.4.2)、[定义 4.4.3](ch04.md#def-4.4.3)。
:::

## 第二组 · 结论卡（说清前提与范围）

::: ex 卡 9 · 借用检查不产生运行时记账 {#rc-04-9}

卡面：「borrowck 会插入引用计数」错在哪？RefCell 算不算例外？

::: sol 核对

borrowck 是 MIR 上的一组编译期分析：把访问位置、时段与允许的再借用连成区域约束，再检查读写、移动与借用是否冲突。它不在程序运行时执行，不为普通引用插入计数更新，普通引用也没有随调用传播的运行时借用表。RefCell 的动态检查是另一套库机制，不是借用检查器。对照[定义 4.4.1](ch04.md#def-4.4.1)、[例 4.4.1](ch04.md#ex-4.4.1)。
:::

:::

::: ex 卡 10 · 责任、状态、搬运 {#rc-04-10}

卡面：移动一个 `Vec` 之后，给出可复用的三问顺序；反过来用行不行？

::: sol 核对

先问责任，再问状态，最后问搬运。语言层原名字失效、销毁责任转给新名字；表示层出现一次 `move`，改写初始化状态与责任归属；机器层可能只是把 24 字节的句柄拷进寄存器或栈槽，名字从不同时活跃时连这份拷贝都可能消失。顺序反了就会拿一张汇编表去否定一条语言规则，或反过来用一条语言规则虚构一次复制。对照[例 4.1.1](ch04.md#ex-4.1.1)。
:::

:::

::: ex 卡 11 · 编译期拒绝意味着什么 {#rc-04-11}

卡面：E0381、E0382、E0502 三个诊断码共同说明哪一层的事？运行时会不会补救？

::: sol 核对

三个都由编译期产生，属于第二层：E0382 是移动之后再次使用，E0381 是存在未赋值路径的读取，E0502 是共享借用仍要在打印处使用时取得冲突的可变借用。编译器在产生可执行程序之前拒绝，本轮 `extra.py` 只检查非零退出状态与诊断代码，从未运行这些输入。旧位模式仍在，但既不让读取重新合法，也不会让非法读取变成可检测的运行时错误。对照[例 4.3.3](ch04.md#ex-4.3.3)、[例 4.4.1](ch04.md#ex-4.4.1)、[4.3.5](ch04.md#sec-cpp-rust.1.4.3)。
:::

:::

::: ex 卡 12 · flag 是上界模型 {#rc-04-12}

卡面：「每个变量一个 drop flag」为什么不是生成代码的要求？StorageLive 又管什么？

::: sol 核对

已知状态无需动态 flag；始终共同变化的多条路径可能共享状态；后续优化还可能消除或改写这些状态。本轮产物用一次状态记录表达 Conditional，但「用 flag」只是实现后果之一。StorageLive 宣告某个 local 的存储生命周期开始，StorageDead 宣告结束；二者管存储在不在这个范围内存在，不管里面是不是合法完整的值，也不等于一次用户可见的 `Drop` 调用。存储范围、初始化、借用是三个维度。对照[定义 4.3.5](ch04.md#def-4.3.5)、[例 4.4.2](ch04.md#ex-4.4.2)。
:::

:::

::: ex 卡 13 · `drop(value)` 与 `drop(&value)` {#rc-04-13}

卡面：两者资源效果差在哪？NLL 会提前放开持锁守卫吗？

::: sol 核对

`std::mem::drop` 的签名接收参数本身，调用就是把值移走，销毁责任在这一点完成；`&value` 只是借出一个观察位置，原所有者仍在，值要到自己的作用域退出才销毁。借用的有效范围是另一个维度：最后一次解引用过去之后，持锁守卫仍可能持锁到作用域末尾。资源边界要用显式块或 `drop` 写出来。对照[思考 4.4.1](ch04.md#think-4.4.1)、[4.3.6](ch04.md#sec-cpp-rust.1.4.3)。
:::

:::

::: ex 卡 14 · 那个 0.143648 {#rc-04-14}

卡面：clone 分支与借用分支的批均值差能说什么？为什么说还需要第二条证据？

::: sol 核对

能说的只是：在本机、本输入长度（16384 个 `u64`，即 128KiB 热输入）、本构建配置下，克隆分支的批均值比借用分支高约 0.14 ns/元素。不能归给 borrowck——它是编译期分析，不在进程运行时循环中执行；也不能当可外推常数，本轮没有计算配对区间。第二条证据是产物核验：`cloned_sum` 的 LLVM IR 保留 allocator 调用、`llvm.memcpy` 与 deallocator，本机目标码可见 `_memcpy` 的真实调用。缺任何一条，「clone 更贵」只是猜测。对照[例 4.5.2](ch04.md#ex-4.5.2)、[定义 4.5.2](ch04.md#def-4.5.2)。
:::

:::

::: ex 卡 15 · 尺寸不变不等于代码相同 {#rc-04-15}

卡面：`Option<DropProbe>` 与 `DropProbe` 同为 8 字节，这张尺寸表能定什么、不能定什么？那条均值差又缺什么？

::: sol 核对

能否定「Option 多分配了一个堆盒子」：尺寸没变，产物里也没有额外分配。不能判定「两种写法一样快」：合流点保留「空或非空」的指针状态，后续要检查它才能决定是否销毁，这是控制流事实，尺寸表看不到。niche 填充省掉的是判别字段的空间，省不掉检查动作；最后一行的限定要一起读——`Option<&u64>` 同尺寸不推广成任意 Option 都同尺寸。本轮 implicit 与 option 的均值差约 0.216 ns/逻辑调用，是两个批均值相减，不是同轮配对差值，也没有区间支撑。对照[定义 4.6.2](ch04.md#def-4.6.2)、[例 4.6.2](ch04.md#ex-4.6.2)、[例 4.6.3](ch04.md#ex-4.6.3)。
:::

:::

::: ex 卡 16 · 三个家都在构建期 {#rc-04-16}

卡面：说出三个「缓存」，各给一句命中条件；为什么都不进运行期的表？

::: sol 核对

会话内记忆化只在同一次编译进程里有效，进程结束就消失。增量编译跨构建复用，要先判断之前记录的输入与依赖是否仍有效——磁盘上有目录并不意味着每一项都可命中，换工具链或重要编译选项可能使旧缓存失效。Cargo 判定整个构建单元最新时，连 rustc 会话都不会进入。查询是构建期的需求接口，不是应用运行时的 HashMap；no-op 构建时间也不能当成查询引擎耗时。本轮没有采集增量编译的定量加速表。对照[定义 4.7.3](ch04.md#def-4.7.3)、[定义 4.7.1](ch04.md#def-4.7.1)、[例 4.7.1](ch04.md#ex-4.7.1)。
:::

## 第三组 · 第一行卡（只写第一步）

这一组练的是「一离开答案不知道第一行写什么」那个毛病。每题只写第一行动作，不计算、不下结论。

::: ex 卡 17 · 怀疑某段工作没执行 {#rc-04-17}

卡面：同事说「这个函数每次调用都新建一个 `Vec`」。第一行写什么？

::: sol 核对

第一行：先定层——「怀疑工作没执行」属于第三层，去看 LLVM IR 与目标汇编里对应的 allocator 调用和内存操作是否还在。层选错的核验做得再细，也只是在回答另一个问题。对照[4.1.4 的判定流程](ch04.md#sec-cpp-rust.1.4.1)、[例 4.5.2](ch04.md#ex-4.5.2)。
:::

:::

::: ex 卡 18 · 条件移动后仍执行析构 {#rc-04-18}

卡面：线上偶发「同一块资源被释放两次」，代码里只有一个 `drop(first)`。第一行写什么？

::: sol 核对

第一行：打开 MIR 产物，把 `first` 对应的 local 与该 local 的全部 `drop` 目标列出来，然后沿 `unwind:` 边检查每个 cleanup 块——这是第二层的工作，先于任何计时实验。对照[例 4.4.3](ch04.md#ex-4.4.3)、[读 MIR 的流程框](ch04.md#sec-cpp-rust.1.4.4)。
:::

:::

::: ex 卡 19 · 想指认某个 pass {#rc-04-19}

卡面：`stages-o0.mir` 与 `stages-o3.mir` 有差异，你想写「pass X 删了那条 drop」。第一行写什么？

::: sol 核对

第一行：先问「本轮有没有逐 pass 的 before/after 转储」。两份都是最终表示，中间没有逐 pass dump，谁先删的无法定位；允许的写法只到「在 opt-level 3 的最终 MIR 里看不到，opt-level 0 里还能看到，本轮未确定是哪个转换删的」。对照[例 4.7.2](ch04.md#ex-4.7.2)、[4.7.6](ch04.md#sec-cpp-rust.1.4.7)。
:::

:::

::: ex 卡 20 · 想加工具拿转储 {#rc-04-20}

卡面：设一个环境变量就能让稳定版接受 `-Z` 参数，你想这么干。第一行写什么？

::: sol 核对

第一行：写下这份转储的适用条件——设过变量的 rustc 不再是用户实际使用的稳定配置，`-Z` 输出格式也没有跨版本承诺，所以它不能与本章按本机观察归档的产物并列。现有产物能否反驳当前假设，决定值不值得加工具；实在拿不到就写成证据缺口。对照[思考 4.2.1](ch04.md#think-4.2.1)、[要不要加工具的流程框](ch04.md#sec-cpp-rust.1.4.2)。
:::

:::

::: ex 卡 21 · 那处 `to_vec()` 删不删 {#rc-04-21}

卡面：同事的代码里有一处 `to_vec()` 是为了让借用检查通过。第一行写什么？

::: sol 核对

第一行：问语义——调用者只需观察、需要独占修改，还是要两个独立拥有者？前两种才谈得上删除，第三种复制就是正确业务。性能优化首先要保持所需语义，之后才是产物核验与同一夹具下的计时。对照[4.5.6](ch04.md#sec-cpp-rust.1.4.5)。
:::

:::

::: ex 卡 22 · 想写请求级 p99 {#rc-04-22}

卡面：表里 borrow 的批 p99 是 0.063338，有人要写成「单次调用的 99 分位延迟」。第一行写什么？

::: sol 核对

第一行：核对分母与样本是什么——`value` 除以的是「批重复数 × units」，每个样本是一整批调用的归一化墙钟时间，21 个批样本的 nearest-rank p99 就是最大值。要请求级分位数得换采集设计，不是在旧表上改列名。对照[例 4.8.2](ch04.md#ex-4.8.2)、[定义 4.8.1](ch04.md#def-4.8.1)。
:::

:::

::: ex 卡 23 · 「按 128 对齐一定最优」 {#rc-04-23}

卡面：评审意见里有这句话，依据是本章记录的 cache line。第一行写什么？

::: sol 核对

第一行：把它降格成本机观察——这个数字来自一台 Apple M5 Pro、macOS 27.0.1 上 `environment.txt` 的一条查询输出；「这台机器系统报告的值」和「该指令集所有实现的常数」不是同一个命题。第二，即使缓存行相同，「按它对齐就更快」还需要分布与测量支持，而本章没有采集对齐档位之间的对比。对照[思考 4.1.1](ch04.md#think-4.1.1)。
:::

:::

::: ex 卡 24 · 把结论写成一句话 {#rc-04-24}

卡面：要给一次「加回 clone 后变慢」的观察写交付句。第一行写什么？

::: sol 核对

第一行：按四步顺序搭骨架——业务是否一致、工作是否留在产物里、批次是否支持方向、机制能否解释；只有前三步成立才写第四句，缺 PMU 就不写 cache miss、IPC 或分支命中率，并把机器、版本、输入长度与构建选项写在句子旁边。对照[例 4.8.3](ch04.md#ex-4.8.3)、[回归定位的四步流程框](ch04.md#sec-cpp-rust.1.4.8)。
:::
