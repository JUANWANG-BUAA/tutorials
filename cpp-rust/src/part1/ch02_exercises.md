## A 组 · 概念（1–7）

::: ex A1 · 三元组与步长（主线 ②） {#ex-2.A.1}

本轮探针表给出 `Record` 的 size 是 64、align 是 8。说出这两个数各自管什么；65536 个 `Record` 排成数组时相邻元素隔多少字节？align 和 size 相等吗，为什么？

::: sol 解答

size 是一个值占的字节数并决定数组步长；align 是合法存放位置的地址约束（起始地址须为 8 的倍数）。步长 64 字节，总跨度 65536 × 64 = 4194304 字节。不相等：64 是 `hot` 加 7 个冷 `u64` 的字段总和，`repr(C)` 下没有内部填充；8 是成员 `u64` 提出的对齐要求。size 恰好是 align 的倍数，但两者是不同的量，不能互推。对照[定义 2.1.1](ch02.md#def-2.1.1)。

:::

:::

::: ex A2 · 四句话落层（主线 ④） {#ex-2.A.2}

把下面四句话分别落到语言约束、标准库保证或本机观测，并说哪几句换目标必须重测：① `repr(C)` 按声明顺序排列字段；② `Option<NonZeroU64>` 与载荷同 size；③ `RustOrder` 是 16 字节；④ 切片引用是 16 字节。

::: sol 解答

①语言约束（本目标的对齐规则仍适用）；②标准库保证（条件见文档的 Representation 段，转述时条件不可省略）；③④本机观测。③④必须重测；②里「与载荷同 size」这个关系在文档范围内不需要重测，但探针表那一列的 8 字节仍是本轮打印值，换目标时 size 与 align 都要重量。①方向稳定，也要在新目标上核对。对照[定义 2.1.3](ch02.md#def-2.1.3)、[例 2.2.1](ch02.md#ex-2.2.1)。

::: ex A3 · 加了 repr(C) 就够了吗（主线 ④） {#ex-2.A.3}

同事给外层结构加了 `repr(C)`，就说「现在可以把它按裸字节写进文件，其他语言直接读」。列出这句话漏掉的至少四条。

::: sol 解答

① `repr(C)` 只约束本目标上的布局算法，不自动统一大小端；②不自动统一不同目标的整型对齐；③外层 `repr(C)` 不会递归改变内层默认 `repr`；④含 `String`、`Vec` 或引用的结构仍需所有权与生命周期协议，直接写文件只会存下一批无意义的地址；⑤填充字节未承诺值，接收方按整对象字节比较会踩坑。稳定格式要走显式字段编码。对照[2.1 节](ch02.md#sec-cpp-rust.1.2.1)、[例 2.1.2](ch02.md#ex-2.1.2)。

:::

::: ex A4 · 省标签要查两件事（主线 ②） {#ex-2.A.4}

同事说「我们的枚举也只有一个非零指针变体，所以它的 `Option` 一定省标签」。按正文，你要查哪两件事？若都查不到，结论只能写成什么？

::: sol 解答

①标准库文档是否把这一类类型列入保证范围，还是只是本机碰巧；②该类型自身的有效值集合是否真的留出了可作 `None` 的位模式。两者都不满足时，只能记录为一次观测，不能写进接口承诺。对照[定义 2.2.1](ch02.md#def-2.2.1)、[定义 2.1.3](ch02.md#def-2.1.3)。

:::

::: ex A5 · 一次分支的成本（主线 ①） {#ex-2.A.5}

有人嫌 `handle(raw)` 里 `NonZeroU64::new` 多一次分支，写 `transmute` 把 0 直接塞进 `Handle`。指出这条捷径错在哪一步，以及省分支的正确做法。

::: sol 解答

错在把「位模式相同」当成「有效值相同」。0 不在 `Handle`（内层 `NonZeroU64`）的有效值集合里；`None` 是 `Option` 的合法表示，不是 `Handle` 的合法值。这样造出的对象从诞生就违反约束，后续使用是未定义行为，而且优化器有权假设它非零。正确做法是保留构造、把判断挪到批次入口摊薄成本；若 0 本身是业务合法值，就不能为凑 niche 把它抹掉。对照[思考 2.2.1](ch02.md#think-2.2.1)、[定义 2.2.2](ch02.md#def-2.2.2)。

:::

::: ex A6 · 投影与完整模型（主线 ④） {#ex-2.A.6}

写出「热列投影」的三点限定，并说明每一点各拦住正文里的哪一句过度结论。

::: sol 解答

①只保存热字段列，没有冷列与索引——拦住「数据层应整体改列式」；②两个表示计时前同时存在，构建与转换不在区间——拦住「重构净收益 8.74 倍」；③未比较完整模型的总内存峰值——拦住任何内存节省声明。访问集合（顺序扫描单字段）与生命期（一次构造多次扫描）是另外两条限定。对照[定义 2.4.1](ch02.md#def-2.4.1)、[思考 2.4.1](ch02.md#think-2.4.1)。

:::

::: ex A7 · 签名就是文档（主线 ①） {#ex-2.A.7}

`take(&mut self, len: usize) -> Option<&mut [u8]>` 这一个签名写了哪三条约束？实现里用 `get_mut` 而不用索引切片，是为了什么？

::: sol 解答

①返回 `Option`：容量不足是可恢复的正常结果，且只给字节切片、不构造任意 `T`；②`&mut self`：同一时刻只允许一个存活切片，下一次 `take` 会被前一个借用的使用挡住；③返回引用的生命周期绑定 `self`：旧借用没结束就调不了 `reset`。`get_mut` 把越界变成可检查的 `None` 而不是 panic，配合 `checked_add` 构成事务性游标——失败发生在更新游标之前。对照[定义 2.6.2](ch02.md#def-2.6.2)、[2.6 节](ch02.md#sec-cpp-rust.1.2.6)。

## B 组 · 推理（8–15）

::: ex B8 · 一笔 Vec 的两本账（主线 ②） {#ex-2.B.8}

locality 实验的数组有 65536 个 `u64`，`Vec` 描述符 24 字节。报「这只 `Vec` 占多少内存」要给出哪两个数？2.3 节算地址跨度时该用哪个？为什么另一个不行？

::: sol 解答

描述符 24 字节与元素区 65536 × 8 = 524288 字节，相加 524312 字节；描述符只占约两万分之一（524288 ÷ 24 ≈ 21845）。算跨度、谈缓存必须用 524288：被扫描、被搬进缓存的是元素区。描述符大小恒定，工作集随元素数增长；用 24 当分母，后面的缓存推理全建在错的数上。对照[定义 2.1.2](ch02.md#def-2.1.2)、[例 2.1.1](ch02.md#ex-2.1.1)。

:::

:::

::: ex B9 · 三行 Option 对照（主线 ②） {#ex-2.B.9}

探针表里 `Option<NonZeroU64>` 是 8、`Option<u64>` 是 16、`Option<Handle>` 是 8。解释这三行，并指出哪一行的「8」仍然只是本机打印的观测值。

::: sol 解答

`NonZeroU64` 排除 0，`None` 借用这个被排除的位模式，不需要额外标签；`u64` 所有位模式都是合法数值，装 `None` 只能另开 8 字节；`Handle` 是字段不公开的单字段元组结构，标了 `#[repr(transparent)]`；niche 照样传递，所以也是 8。第三行的数字虽落在保证范围内，但那一列仍是本轮 `size_of` 打印值，换目标时 size 与 align 都要重量。对照[例 2.2.1](ch02.md#ex-2.2.1)、[定义 2.1.3](ch02.md#def-2.1.3)。

:::

:::

::: ex B10 · 八倍能说到哪一步（主线 ②） {#ex-2.B.10}

AoS 跨度 4194304 字节、热列 524288 字节。有人写：「AoS 每次扫描多带 7 倍内存流量，其中 4194304 − 524288 = 3670016 字节是从 DRAM 读进来的冷字段。」指出这条推理越过证据边界的全部位置。

::: hint 提示

先把「可算的」「要采的」「采过的」分成三堆，再给这句话的每个动词找出处。

:::

::: sol 解答

两处越界。①「多带流量」把地址跨度改名为搬运字节：cacheline 本机 128 字节、`Vec` 只保证 8 字节对齐，跨行边界数量不确定，且重复扫描同一份热数组时不少访问可能命中某层缓存；搬运字节属于第二类证据，本章没采。②「从 DRAM 读进来」给未采集的事件安了具体字节数——3670016 只能作为两者跨度的差，不能解释成任何一次读取量。能保留的只有：跨度差 8 倍、双方逻辑有效负载相同（都 524288 字节）、密度 12.5%。对照[例 2.3.1](ch02.md#ex-2.3.1)、[定义 2.3.2](ch02.md#def-2.3.2)。

:::

:::

::: ex B11 · 从六行汇编数步长（主线 ②） {#ex-2.B.11}

AoS 片段四条标量装载位于 −128、−64、0、+64，随后 `add x13, x13, #256`；热列片段两条 `ldp` 后四条 `add.2d`。各数出「一轮处理几个逻辑元素、基址前进多少字节」。再由这两段推算「一次 `sum_aos` 调用消耗多少周期」，可以嘛？

::: sol 解答

AoS：四个相隔 64 字节的热字段，一轮 4 个元素、前进 256 字节，每元素 64。热列：`ldp` 成对取回 4 个 16 字节寄存器、推进 64 字节，四条 `add.2d` 累加 4 × 2 = 8 条 64 位通道——一轮 8 个元素、前进 64 字节，每元素 8。比值 8，与跨度差一致；同时执行形态也换了（标量逐元素对批量向量）。不可以推算周期：片段省略了循环控制与尾部处理，完整符号才包含入口与返回；指令选择也只是本机观测。对照[例 2.4.1](ch02.md#ex-2.4.1)。

:::

::: ex B12 · 把均值换算回毫秒（主线 ②） {#ex-2.B.12}

一批 = 128 次调用 × 65536 元素。用 aos 均值 0.519143207 算出一批多长、21 批合计多长；再把配对均值 −0.459762329 换算成每批时间。这类换算防住什么错误？

::: hint 提示

先算每批元素数 8388608，乘回 ns 再换毫秒；对不上账的那一步就是单位错。

:::

::: sol 解答

8388608 × 0.519143207 ns ≈ 4 354 889 ns ≈ 4.35 ms；21 批约 91.5 ms。热列侧 8388608 × 0.059380878 ≈ 498 123 ns ≈ 0.50 ms，21 批约 10.5 ms；差值 −0.459762329 换回每批约 −3.857 ms，与两者相减一致。用处：①量级自检——换算出「一批 0.004 ms」就说明单位或分母写错；②暴露批均值含义——0.519 是 4.35 ms 摊到 838 万个元素，不是一次访问的耗时；③防止把 sd 读成亚纳秒级稳定——0.005283686 摊到每批约 44 μs。对照[例 2.5.1](ch02.md#ex-2.5.1)。

:::

:::

::: ex B13 · 区间不跨零之后（主线 ③） {#ex-2.B.13}

`byte_region` 减 `fresh_vec` 的配对均值 −5.434458415，区间 [−5.514596121, −5.358680362]，不跨零。业务方据此写「区域路径每块稳定省一次 malloc 的 5.43 ns，全面替换系统分配」。这段话里有几处错？

::: sol 解答

至少四处。①单位：−5.43 是 ns/逻辑块操作，含取存储、`fill(7)` 与 `black_box` 观察，不是 `malloc` 调用延迟；②语义：两者不是同一算法——区域不做每块的全局分配释放、提前持有 262144 字节、`reset` 不擦除，收益属接口语义而非实现优化；③边界：区域构造与销毁在计时外，只用一次请求要把成本加回来，表里也没有内存列（多连接常驻未采集）；④判定：没有预先写下的预算 B，「全面替换」越出三态门禁。区间不跨零只支持「本次运行内方向可定」。对照[定义 2.7.1](ch02.md#def-2.7.1)、[定义 2.7.2](ch02.md#def-2.7.2)、[思考 2.7.1](ch02.md#think-2.7.1)。

:::

::: ex B14 · 手推一串 take（主线 ①） {#ex-2.B.14}

`ByteRegion::new(8)`，依次：`take(6)` 并把切片 `fill(9)`；`take(1)`；`take(2)`；`reset()`；`take(6)`。写出每步后 `used`、返回内容与切片字节。这两条「失败不动游标、复用见旧字节」各被哪个测试断言？

::: hint 提示

每一步先 `checked_add`，再问 `get_mut` 的范围越不越出长度 8；两个都成功才提交游标。

:::

::: sol 解答

`take(6)`：0→6，成功，前两写位变 `[9; 6]`。`take(1)`：end=7，成功，第 7 字节是旧内容 0，`used=7`。`take(2)`：`checked_add` 得 9（不溢出），`get_mut(7..9)` 越出长度 8，返回 `None`，`used` 仍 7。`reset()`：`used=0`，`storage` 一字节未动。`take(6)`：成功，内容 `[9; 6]`——旧字节被看见。归档的容量失败用例断言「失败不消耗剩余空间」（两种 `None` 后仍能取成功），`reset` 后再取读到此前的值，断言「不擦除」。对照[例 2.6.1](ch02.md#ex-2.6.1)、[2.7 节](ch02.md#sec-cpp-rust.1.2.7)。

:::

::: ex B15 · 采样为什么保持中立（主线 ①） {#ex-2.B.15}

`sample-locality.txt` 里 `sum_aos` 与 `sum_soa` 的采样计数接近。有人说「采样是中立证据，说明两者单次成本接近」。指出绕过的一个前提，并说出这份报告实际支持的句子。

::: sol 解答

绕过了「采样覆盖的是哪段时间」：预热按固定墙钟时间运行，两个 case 在被采样时段都反复执行各自的工作核；AoS 一轮约 4.35 ms、热列约 0.50 ms，同样时长里 AoS 完成的调用次数更少，而采样统计的是符号在跑的次数，不是每次的字节数。所以计数接近既不支持「成本接近」也不支持「热列没更快」；它能支持的只有「两个工作核确实都在运行」。差距仍看计时表，机制区分要补事件采集（本章没做）。对照[思考 2.5.1](ch02.md#think-2.5.1)。

::: ex C17 · 补一份「热 + 两列冷」实验契约（主线 ②） {#ex-2.C.17}

你要为「每次读取 `hot` 与 2 个冷字段」补实验。按实验契约四组问题写出输入、计时边界、观察与外部条件，并说明新数字能否与 2.5 的 0.519/0.059 直接比较。

::: hint 提示

先想清楚两种表示怎么做到「同一份逻辑工作」，再定校验值覆盖哪些字段。

::: sol 评分要点

合理解答须含：①输入——两种表示由同一份字段值生成，冷字段有确定内容（不能留未初始化）；②计时边界——构建与转换在不在区间要写死，若把转换计入，单位含义就离开「重复访问阶段」；③观察——校验值覆盖全部被读字段，两个实现处理同一份工作；④单位与规模——ns/逻辑元素还是每字段、元素数多少；⑤比较声明——访问集合变了，契约就不同，新数字与只读 `hot` 的 0.519/0.059 不可直接比较，只能各自成表。缺任一条，结论就失去与本轮归档对话的资格。对照[定义 1.1.3](ch01.md#def-1.1.3)、[2.4 节](ch02.md#sec-cpp-rust.1.2.4)。

::: sol 参考路径

预测：前 2048 块成功，之后 `take(64)` 的 `get_mut` 越界返回 `None`，`expect("fixed capacity")` panic——「容量恰好覆盖一次工作核」的前提被破坏；游标不会被失败消耗，但工作核做不完。回退候选（正文「容量治理」段列出）：拒绝该请求、分块多次取用、申请拥有缓冲、转慢路径——各自改变尾延迟与内存峰值，须单独记录失败频率与慢路径成本，不能只测永远命中池的路径。对照[例 2.6.1](ch02.md#ex-2.6.1)、[2.8 节](ch02.md#sec-cpp-rust.1.2.8)。

::: ex C19 · 复现那个 compile-fail（主线 ①） {#ex-2.C.19}

照正文写出「取出切片、`reset`、再写切片」的 compile-fail 片段，确认它在编译期失败。再写出两个能编译的变形，并解释为什么「能编译」不等于「旧内容符合预期」。

::: sol 参考路径

失败形状：`let slice = region.take(4)...; region.reset(); slice[0] = 3;`——`slice` 的后续使用把借用区间撑到 `reset` 之后，两个可变借用重叠，借用检查器拒绝。能编译的变形：①切片最后一次使用在 `reset` 之前；②`region.take(4).unwrap()[0] = 3;` 后立刻 `reset`——临时借用随语句结束。这两个通过只说明程序不再访问旧切片；重新 `take` 同一区域读到的仍是上一轮字节，`reset` 不清零。用 `static` 或裸指针绕过拒绝是把义务藏起来，不是满足它。对照[例 2.6.2](ch02.md#ex-2.6.2)、[定义 2.6.3](ch02.md#def-2.6.3)。

::: sol 参考路径

应核对四个事实：u8 与 u64 组合后 `value_offset = 8`、补齐后 size 16、align 8；`Layout::array::<u64>(usize::MAX)` 被拒绝；100 个单元值的 size 0、align 1。结论句示例：「在本机受检 `Layout` 规划下，u8 头加 u64 尾的组合给出偏移 8、补齐尺寸 16、对齐 8，超大数组请求被拒绝；这些是布局规划结果，不是实际内存消耗测量，偏移相对满足整体对齐的基地址成立，不授予对 `Vec<u8>` 缓冲的直接引用权。」说出「先证 base、再谈偏移」这半句，这道题才算完整。对照[2.8 节](ch02.md#sec-cpp-rust.1.2.8)、[定义 2.8.1](ch02.md#def-2.8.1)。

## 批改时最常给的三条意见

1. **单位与对象错位**：把 0.519 说成一次访问的耗时、把 2.81 说成 `malloc` 延迟。先改句子里的分母，再改表格。
2. **证据串类**：拿跨度差宣布 miss 差、拿代码形态宣布唯一因果。给每个「因为」标明它用的是布局事实、机制证据还是计时结果，第二类本章没有就不许出现。
3. **边界失踪**：结论句里没有「计时外构造」「重复扫描阶段」「本机观测」「预留 262144 字节」这些限定。用[定义 1.1.3](ch01.md#def-1.1.3) 的四组问题与落层检查逐条补齐。
