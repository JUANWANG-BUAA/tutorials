# 第三章 · 闭卷回忆卡

「看懂」只说明答案在眼前时能识别；考试和代码评审需要的是从空白纸上提取。这一页把第三章拆成 24 张卡，每张卡先写卡面问题，合上正文自己答，再展开核对。

**用法与节奏**

| 时点 | 做什么 | 判定 |
|:--|:--|:--|
| 学完当天 | 第一组「定义卡」全部 8 张 | 术语的适用范围写全才算 ✓ |
| 第 1 天 | 第二组「结论卡」全部 9 张 | 能说清前提与边界才算 ✓ |
| 第 3 天 | 第三组「第一行卡」全部 7 张 | 写出第一步动作才算 ✓ |
| 第 7 天 | 只重做标成 △ 和 × 的卡 | 全对即可进入第四章 |

每张卡给自己一个记号：✓ 一次说对；△ 说对一半或要提示；× 想不起来。只重做 △ 和 ×，不要把整叠卡反复过一遍——那是在读，不是在提取。

## 第一组 · 定义卡（说全称与适用范围）

::: ex 卡 1 · 所有者与移动 {#rc-3-1}

卡面：给出「所有者」与「移动」的定义；写出编译器消除物理搬运的三种方式。

::: sol 核对

所有者承担一个值的合法使用与最终清理责任；移动把这份责任转移给新位置，旧绑定随即失效。移动本身不要求为每一步执行某段固定机器指令：寄存器传递、栈槽复用、返回位置优化都可能消除物理搬运。对照[定义 3.1.1](ch03.md#def-3.1.1)。
:::

:::

::: ex 卡 2 · Copy 与 Clone {#rc-3-2}

卡面：两者的差别是什么？为什么 `Vec` 与 `Arc` 的 clone 不能共用一个成本模型？

::: sol 核对

`Copy` 是允许隐式复制的类型属性：值被使用一次后原绑定仍可用，它不调用用户定义的深克隆逻辑，且不能与 `Drop` 同时要求。`Clone` 是显式可调用的操作，成本与语义由具体实现决定。`Vec` 的 clone 复制载荷、成本随元素数增长；`Arc` 的 clone 只增加共享计数、与载荷大小无关，但带来计数的实际语义。对照[定义 3.1.2](ch03.md#def-3.1.2)。
:::

:::

::: ex 卡 3 · 排他访问与共同读取 {#rc-3-3}

卡面：两者分别是什么？按什么维度描述？`UnsafeCell` 不在其中提供什么？

::: sol 核对

排他访问：某段时间区间内只有这一条路径被允许写入这块存储。共同读取：多条路径可以同时读，但都不写。两者都按时间描述，不按指针变量的个数描述。`UnsafeCell` 提供内部可变性的例外基础，但不会自动提供线程同步，也不会自动允许任意别名写入。对照[定义 3.2.1](ch03.md#def-3.2.1)。
:::

:::

::: ex 卡 4 · 容量与长度 {#rc-3-4}

卡面：两个词分别指什么？`Vec::with_capacity(n)` 之后长度是多少？安全 `push` 的顺序为什么重要？

::: sol 核对

容量是分配器已经买下的存储元素数；长度是当前被承认「此处存在合法 `T`」的元素数。`with_capacity(n)` 取得容量 n，初始长度为 0，它没有提前构造 n 个 `T`。安全 `push` 先写入新值、再把该位置纳入长度，这个顺序保证析构只触及已初始化元素。对照[定义 3.3.1](ch03.md#def-3.3.1)。
:::

:::

::: ex 卡 5 · 销毁责任与 drop flag {#rc-3-5}

卡面：销毁责任由什么决定？drop flag 为什么不能进 `size_of` 表？三条退出路径分别是什么？

::: sol 核对

责任由初始化状态决定，不由变量名决定；移动后的旧位置不再拥有同一值，部分移动后剩余已初始化字段仍有责任。编译器用数据流分析确定哪些位置需要 drop：某些控制流需要运行时状态（俗称 drop flag），另一些在编译期就能消除，所以它不是每个对象里隐藏的固定布尔字段，不能算成每对象固定开销。三条路径：正常返回把责任移给调用方、展开清理已建前缀、`panic = "abort"` 不执行普通展开清理。对照[定义 3.4.1](ch03.md#def-3.4.1)。
:::

:::

::: ex 卡 6 · 额外拥有副本路径与单位口径 {#rc-3-6}

卡面：这条路径包含哪几个动作、发生在哪个边界之内？本节单位是什么、不是什么？

::: sol 核对

在被计时的工作核内部完成「分配一份独立存储 → 复制元素 → 使用 → 释放」；独立 `Vec` 不逃出 `cloned`，析构发生在函数返回之前，所以全部计入时间。单位是 `ns/输入元素`：批次墙钟时间除以「迭代次数 × 元素数」，是一次工作核调用的平均元素成本，不是一次 `borrow` 语法操作的耗时——借用语法本身没有运行时开销。对照[定义 3.5.1](ch03.md#def-3.5.1)。
:::

:::

::: ex 卡 7 · unsafe 边界与安全封装 {#rc-3-7}

卡面：`unsafe` 允许什么、不允许什么？安全封装额外要证明什么？

::: sol 核对

`unsafe` 允许执行某些编译器无法自动证明安全的操作，它不允许未定义行为。安全封装的额外义务是：任意符合公开接口的安全客户端都不会触发未定义行为——公开方法的组合、panic、提前返回与泄漏都要考虑。只证明示例调用合法不够。对照[定义 3.7.1](ch03.md#def-3.7.1)。
:::

:::

::: ex 卡 8 · 地址稳定与 `Pin` {#rc-3-8}

卡面：地址稳定指什么？`Pin` 约束什么、不约束什么？

::: sol 核对

地址稳定指「在被依赖的这段时间里，这个值的地址不会变」。所有权转移不保证它，借用约束也不自动保证它。`Pin<P>` 表达「被指向的值在 pin 之后不再按普通方式移动」；它不是普遍禁止移动一切句柄——移动 `Pin` 包装的指针句柄，与移动被指向的值要分开谈。对照[定义 3.8.1](ch03.md#def-3.8.1)。
:::

:::

## 第二组 · 结论卡（说清前提与边界）

::: ex 卡 9 · `split_at_mut` 的两半 {#rc-3-9}

卡面：两个切片来自同一个原数组，算不算非法别名？反过来说，变量名不同算不算合法？

::: sol 核对

都不算判断依据。`split_at_mut` 把一段可变存储分成两个不相交区间，读侧与写侧的地址范围已经不重叠，排他条件仍然满足；反过来，两个不同的变量名也不自动证明范围不重叠——名字不决定地址。对照[例 3.2.1](ch03.md#ex-3.2.1)。
:::

:::

::: ex 卡 10 · IR 属性支持到哪一句 {#rc-3-10}

卡面：本轮 `copy_add` 的目标指针带 `noalias` 与 `writeonly`，源指针带 `noalias` 与 `readonly`。这支持什么、不支持什么？

::: sol 核对

支持「本次构建中读写互不重叠，因此后端可以安全批量化」这一句。不支持「Rust 保证所有指针互不别名」（裸指针与 `UnsafeCell` 在例外面里），也不支持「只要参数带属性，任何机器码都会向量化」——属性给的是优化许可，不保证后端采用。它是版本化代码生成观测。对照[定义 3.2.2](ch03.md#def-3.2.2)、[例 3.2.2](ch03.md#ex-3.2.2)。
:::

:::

::: ex 卡 11 · 借用冲突不是未定义行为 {#rc-3-11}

卡面：`RefCell` 上 `try_borrow` 返回错误时发生了 UB 吗？换成 `borrow` 失败形态怎么变？

::: sol 核对

没有 UB。两条路径在同一阶段想访问同一存储，违反排他前提，运行时借用机制把它变成可观察失败（返回 `Err`）。改用 `borrow` 时冲突通常表现为 panic（运行时中止）。选哪个取决于失败是否属于正常控制流；手工解引用内部裸指针只是移除保护，不解决冲突。对照[例 3.2.3](ch03.md#ex-3.2.3)、[思考 3.2.1](ch03.md#think-3.2.1)。
:::

:::

::: ex 卡 12 · 零能不能当初始化 {#rc-3-12}

卡面：`u64`、`&u64`、`NonZeroU64` 三种类型里，「先置零再覆盖」哪些能用？前提是什么？

::: sol 核对

只有 `u64` 能：零是有效值，且没有 `Drop` 责任。`&u64` 不能，零不是合法引用；`NonZeroU64` 不能，它的合法值集合明确排除零，`vec![0; n]` 在这两个类型上根本构造不出来。前提是「零是该类型的合法值」，这个前提要逐类型检查，不能由泛型 `T` 继承。对照[例 3.3.2](ch03.md#ex-3.3.2)。
:::

:::

::: ex 卡 13 · 计数 3 与计数 4 {#rc-3-13}

卡面：`try_build(8, make)`，`Err` 注入在下标 3、panic 注入在下标 4，两个 Drop 计数分别是多少？为什么不是 8？

::: sol 核对

分别是 3 与 4。`Err` 那组：下标 0、1、2 构造成功并入队，前缀长度 3，早退时局部 `Vec` 清理这 3 个；panic 那组前 4 个（0–3）已进入前缀。只有已初始化前缀有清理责任，余量位置还没有 `T`，读取或析构它们反而制造未定义行为。对照[例 3.4.2](ch03.md#ex-3.4.2)、[定义 3.3.2](ch03.md#def-3.3.2)。
:::

:::

::: ex 卡 14 · 0.1 ns 不是借用检查的价格 {#rc-3-14}

卡面：配对均值 0.100168563 ns/元素，能写成「借用检查节省了 0.1 ns」吗？能写成「clone 慢 2.70 倍」吗？

::: sol 核对

都不能。借用检查在编译期完成，被测循环里一个元素也没有检查过；差值包含分配、复制、释放和缓存状态变化，属于额外拥有副本路径。2.70 倍（0.159020461 ÷ 0.058851898）只在「同一分母下的批均值」这一层有意义，两者不是同一个语义工作，且本轮没有对分配、复制、释放逐项计时。对照[例 3.5.1](ch03.md#ex-3.5.1)、[思考 3.5.1](ch03.md#think-3.5.1)。
:::

:::

::: ex 卡 15 · 5.73 倍与反直觉结果 {#rc-3-15}

卡面：3.6 的哪个结果否证了哪个直觉？这个结论带哪四个条件？

::: sol 核对

`zero_fill` 的均值 0.201331729 只有 `push` 的 1.153849851 的约 1/5.73，配对均值 −0.952518123 的区间 [−0.959926571, −0.945401044] 整体在零的同一侧，否证「`with_capacity` 加 `push` 没有提前清零，所以必然更快」。四个条件：`T` 为 `u64`、零合法、消费者要求完整切片、本机本轮构建。本章保留这个结果，而不是改参数直到出现预期排序。对照[例 3.6.1](ch03.md#ex-3.6.1)、[定义 3.6.1](ch03.md#def-3.6.1)。
:::

:::

::: ex 卡 16 · 机制解释与成分归因 {#rc-3-16}

卡面：两者靠什么区分？3.6 拿到了哪一个、没有拿到哪一个？

::: sol 核对

靠证据类型：机制解释用产物里可见的结构差异（保留的容量比较与 `grow_one` 路径、`alloc_zeroed`、成对展开写入与 `stp` 序列）说明差值与哪种循环形状相容；成分归因要把差值拆成「清零占多少、覆盖占多少、分配占多少」，需要逐项计时或流量采集。本轮只有前者，没有后者，也没有采集真实内存流量。对照[定义 3.6.2](ch03.md#def-3.6.2)。
:::

:::

::: ex 卡 17 · `Box` 与内部指向 {#rc-3-17}

卡面：把带内部指针的结构 `Box` 起来，能说「地址不会再变，所以内部指针永远有效」吗？

::: sol 核对

不能。`Box` 只保证「移动句柄不动载荷」这一条，没有排除三种变化：构造顺序（先在别处建好指针再搬进 `Box`，指向的是旧位置）、合法替换（`mem::take` 一类移出载荷）、析构期间的先后。内部指向必须在最终位置建立，之后不再移动该值，这才是 `Pin` 与类型约束要解决的事。对照[例 3.8.1](ch03.md#ex-3.8.1)。
:::

:::

## 第三组 · 第一行卡（只写第一步）

这一组练的是「一离开答案不知道第一行写什么」那个毛病。每题只写第一行动作，不展开证明。

::: ex 卡 18 · 有人断言「按值传参多复制一个数组」 {#rc-3-18}

卡面：第一行写什么？

::: sol 核对

第一行：问「调用方在这个函数返回之后还要不要用它」。移动转移的是描述符与责任，元素存储留在原分配中；真正要查的是接口是否迫使调用方保留两份数据，而不是数源码里有几个 move。对照[例 3.1.1](ch03.md#ex-3.1.1)、[思考 3.1.1](ch03.md#think-3.1.1)。
:::

:::

::: ex 卡 19 · 判断两个访问冲不冲突 {#rc-3-19}

卡面：第一行写什么？

::: sol 核对

第一行：列出每次访问覆盖的**地址区间**，再标出每个借用的起止位置——范围与阶段两列都写出来，才谈得上判断。不要从变量名开始。对照 3.2 的判定流程①②、[定义 3.2.3](ch03.md#def-3.2.3)。
:::

:::

::: ex 卡 20 · 报告写「每元素 0.00002 ns，比 borrowed 快很多」 {#rc-3-20}

卡面：第一行写什么？

::: sol 核对

第一行：去目标产物里看那个函数是否还在遍历——本节 `borrowed` 是 0.058851898，量级差四个数量级通常意味着工作被删掉，再核对分母是不是名义元素数。这比加批次或换计时器更快定位。对照 3.5 即时自测第 3 题、[定义 3.5.1](ch03.md#def-3.5.1)。
:::

:::

::: ex 卡 21 · 要给一行裸指针解引用签字 {#rc-3-21}

卡面：第一行写什么？

::: sol 核对

第一行：把十个维度（所有权、空间、时间、对齐、初始化、别名、同步、销毁、panic、泄漏）逐行写下依据，空白按不通过处理；先补「时间」和「别名」两条。对照[例 3.7.1](ch03.md#ex-3.7.1)、3.7.5。
:::

:::

::: ex 卡 22 · 想加一个 unsafe 版本当「理论下界」 {#rc-3-22}

卡面：第一行写什么？

::: sol 核对

第一行：先问这个候选是否满足「长度以内每个位置都有合法 `T`」。benchmark 不应执行未定义行为来换取好看的下界；要拆分差值，就设计只改变一个合法结构的对照实验。对照[思考 3.6.1](ch03.md#think-3.6.1)、3.6.8 判定流程①③。
:::

:::

::: ex 卡 23 · 评审一份只暴露 Pin 装箱自引用的库 {#rc-3-23}

卡面：第一行写什么？

::: sol 核对

第一行：查两件事——类型是否实现了 `Unpin`（若是，`Pin` 不施加同等约束），以及有没有任何公开方法能把被 pin 的字段移出或替换（等价于 `mem::take`）。任一条不过，接口就不能对外宣称地址不变量成立。对照[定义 3.8.2](ch03.md#def-3.8.2)、[思考 3.8.1](ch03.md#think-3.8.1)。
:::

:::

::: ex 卡 24 · 要把接口从拥有改成借用 {#rc-3-24}

卡面：第一行写什么？

::: sol 核对

第一行：写下两个必答问题——调用方是否可能在被调用方之后销毁输入、结果是否要活过输入；再约定改造后的验证方式：仍能编译且给出相同输出，并确认产物真的去掉了分配与复制。对照 3.1.4 判定流程①②⑤、3.5.5 判定流程④⑤。
:::

:::
