# 第一章 · 综合自测卷

**闭卷，60 分钟，100 分。**不许查正文、不许跑代码、不许看[回忆卡](ch01_recall.md)。允许一张空白草稿纸。做完先按[评分标准](#ch01-exam-score)自己打分，再逐题对照解答；低于 70 分不要往下读第二章，回到扣分项对应的小节重读那一段。

时间分配建议：第一部分 15 分钟，第二部分 20 分钟，第三部分 20 分钟，留 5 分钟检查单位与措辞。

<a id="ch01-exam-p1"></a>

## 第一部分 · 概念辨析（每题 5 分，共 30 分）

判断对错并写一句理由。只写「对/错」不得分。

1. 把返回值用 `black_box` 包一次，就能保证 `K` 次调用的工作每次都真实发生。
2. 批均值 0.058 ns/元素 意味着一次 `u64` 加法约花费 0.058 ns。
3. 21 个批均值的 p99 与其中的最大值是同一个数。
4. 两个 case 的均值各算好再相减，与逐轮配对再平均，得到的标准差相同。
5. 差值的 bootstrap 区间跨零，可以写「两种实现等价」。
6. 复现时把不同运行里各自最快的批次拼成一份新样本，是合理的去噪手段。

## 解答与给分说明

**1. 错。** 输出侧只保活一次，前 `K−1` 次调用没有痕迹，可以被合并或整体折叠；保活要为**每次调用**准备槽位，并在停表后逐个比对（[定义 1.3.1](ch01.md#def-1.3.1)）。

**2. 错。** 它是批次墙钟时间除以元素数的批均值，含向量加载、累加链、归约与夹具成本；除以 `K × N` 得到的是吞吐口径，不是任何一条指令或一次调用的延迟（[定义 1.2.2](ch01.md#def-1.2.2)）。

**3. 对。** nearest-rank 取排序后第 `ceil(21 × 0.99) = 21` 个，正是最大值；因此这里的 p99 只表示批次间波动范围，不表示生产请求尾部（[定义 1.5.2](ch01.md#def-1.5.2)）。

**4. 错。** 同轮 A、B 正相关，配对让共同时间条件在相减时抵消，差值方差是 `Var(A)+Var(B)−2Cov(A,B)`；拆成两组独立样本会丢掉相关性信息，波动被高估。实测 sd：indexed 0.000458518、iterator 0.000541829，独立合成约 0.00071，实际配对 sd 0.000484383。

**5. 错。** 跨零只说明本次运行内方向不可判定。「等价」需要预先给出容差 `B`，且区间整体落在 ±B 内（[例 1.6.1](ch01.md#ex-1.6.1)、[定义 1.7.1](ch01.md#def-1.7.1)）。

**6. 错。** 这样得到的样本不对应任何真实实验过程；重跑要生成新归档，运行间差异另行分析（1.7.8）。

**7.（参考）** 不能。方差与均值同量级缩放时才谈得上「相对稳定性」；discarded 的绝对波动小，是因为它几乎没有工作可做——被删空的路径本来就不该参与稳定性比较。要比较稳定性应在同一语义的两个实现之间做，或改用相对量并说明归一化方式。给分：指出「语义不同」得 8 分；只说「sd 小就是稳」得 0 分。

**8.（参考）** 至少两处：① 分子不是同一件事（discarded 没读数组，observed 读了），比值量的是「被删掉的工作」；② 基线接近零使比值发散，微小绝对误差被放大成巨大倍数；③ 因果说反：删除是优化器对无用基准代码的行为，真实程序拿不到这 3600 倍。正确表述示例：「observed 的批均值 0.058630038 ns/元素对应一次真实求和；discarded 的 0.000016082 对应被完全删除的空路径，两者不可解释为加速比。」给分：每列一处错误 3 分，正确表述 2 分。

**9.（参考）** 均值：基本不变或略升——`K` 只改变夹具在总时长中的占比，两次时钟读取与循环入口的成本摊到更少的调用上会被抬高；若观察到明显变化，先怀疑分辨率。sd：可能略升——固定开销的相对抖动被放大。p99：仍是 21 个数中的最大值，**分辨率不因 `K` 改变而改善**；位数变化不等于精度变化。给分：每项 4 分，其中依据必须提到「夹具占比」或「样本数决定分位数」，只给方向得 1 分。

**10.（参考骨架，按四项各 5 分）**
- 输入：同一份 65536 个 `u64`，clone 侧每轮重新分配并保活到停表之后；先预热到热态，明确不声称冷缓存。
- 计时界内：clone（含分配与拷贝）+ 求和；界外：断言、checksum 比对、打印。
- 观察：每次调用把结果写入独立槽位，停表后逐个 `black_box` 读回并核对 checksum，保证 `K` 次都留下痕迹。
- 外部条件与字段：rustc 1.99.0 / LLVM 23.1.1 / `aarch64-apple-darwin` / `-C target-cpu=native` / `opt-level=3`、`codegen-units=1`、`lto=false`；CSV 含 `kind,round,position,case,ns_per_unit,checksum`。
- 统计与判定：21 轮同轮交替配对，`d = clone − borrowed`，N−1 sd，固定种子 bootstrap；`B` 预先由「每次调用的时间与内存预算」给出（例如 `B = 0.0005 ns/元素`，并附内存上界），按 `U ≤ B` 接受、`L > B` 拒绝、其余证据不足。

**11.（参考）** `U = 0.000269819 ≤ B = 0.0005` → **接受**。动作：把协议（输入家族、构建、环境、种子）记录后发布，并在发布说明里保留区间与样本数。结论句示例：「在这台机器、`-C target-cpu=native` 的 release 构建与热数组输入下，clone 相对借用的配对差值上界为 0.00027 ns/元素，未超出 0.0005 的预算；本结论不覆盖冷缓存、其他构建配置与请求级尾延迟。」给分：判定 4 分、动作 4 分、结论句含对象/条件/指标/限制四件各 3 分。

**12.（参考，四处各 2.5 分）**
- 「预热已做」缺时长与正确性检查 → 补预热时长与检查方式（[定义 1.2.3](ch01.md#def-1.2.3)）。
- 「已删除 2 个批次」缺外部事件证据且可能单侧删点 → 给出事件记录，整对删除，并同时报告含与不含的结果。
- 「p99 = 0.00002 ns/元素」把批次分位数当请求分位数，且数值量级像被删空的路径 → 改报批均值并附样本数；先核查工作是否真的执行。
- 「快 2900 倍」跨语义比值 + 未说明 `B` → 只在等价实现间用比值，并预先写下预算与三态判定；「可发布」要由 `U ≤ B` 支撑，而不是由倍数支撑。
