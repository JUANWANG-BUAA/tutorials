## 第一部分 · 概念辨析（每题 5 分，共 30 分）

判断对错并写一句理由。只写「对/错」不得分。

1. 移动一个拥有 `Vec` 的句柄，会把堆上的元素一起搬到新位置。
2. 从同一个数组用 `split_at_mut` 得到的两半，因为共享同一次分配，构成非法别名。
3. `Vec::with_capacity(n)` 之后可以安全读取前 n 个位置，因为容量已经买下。
4. 结构体的字段与同一块作用域里的局部变量都按声明顺序析构。
5. `copy_add` 的 `dst` 参数带 `noalias`，说明本次构建中后端利用了「这块存储不被其它参数别名写入」这一事实。
6. 只要指针的地址来自一个仍然活着的 `Vec`，解引用它就不必再单独论证初始化与别名。

9. （10 分）下面是正文的安全构建器（节选）。设调用 `try_build(7, make)`，其中 `make` 对下标 0、1 返回 `Ok`，对下标 2 返回 `Err("injected")`，其余下标从未被调用。

```rust
pub fn try_build<T, E>(
    n: usize,
    mut make: impl FnMut(usize) -> Result<T, E>,
) -> Result<Vec<T>, E> {
    let mut out = Vec::with_capacity(n);
    for i in 0..n {
        out.push(make(i)?);
    }
    Ok(out)
}
```

## 解答与给分说明

**1. 错。** 移动转移的是「谁使用、谁释放」的责任，元素存储留在原分配中，旧绑定不再拥有清理责任；但也不能反过来断言「一定只复制 24 字节」——物理搬运由具体调用边界与是否内联决定，编译器可用寄存器传递、栈槽复用或返回位置优化消除它（[定义 3.1.1](ch03.md#def-3.1.1)）。

**2. 错。** `split_at_mut` 把一段可变存储分成两个不相交区间，读侧与写侧的地址范围已不重叠，排他条件仍成立；「来自同一个原数组」不等于非法别名（[例 3.2.1](ch03.md#ex-3.2.1)）。

**3. 错。** `with_capacity(n)` 取得容量 n、初始长度为 0，它没有提前构造 n 个 `T`；按容量去读会越过已初始化前缀（[定义 3.3.1](ch03.md#def-3.3.1)）。

**4. 错。** 两条规则分属不同容器：结构体（含元组）字段通常按声明顺序销毁，同一块作用域里的局部变量一般按相反声明顺序销毁，临时值另受表达式与 edition 规则影响（[定义 3.4.2](ch03.md#def-3.4.2)、[例 3.4.1](ch03.md#ex-3.4.1)）。

**5. 对。** 属性表示该指针指向的存储在本函数有效范围内不被其它参数别名写入，本轮 IR 里目标指针带 `noalias` 与 `writeonly`，随后出现向量加载、加与存储。它只支持「本次构建利用了访问性质」，不支持「所有借用核都向量化」，也不是完整的语言别名模型（[定义 3.2.2](ch03.md#def-3.2.2)、[例 3.2.2](ch03.md#ex-3.2.2)）。

**6. 错。** 「来自 `Vec`」是一次性事实，不是持续状态：`Vec` 可能被移动、扩容、`mem::take` 走内容或析构。可解引用范围只覆盖长度以内，容量余量里没有 `T`；同一存储上若另有被允许的可变路径，就破坏排他前提。三条分别落在「时间」「初始化/空间」「别名」三行，任何一行都不能由「来自 `Vec`」推出（[思考 3.7.1](ch03.md#think-3.7.1)、[定义 3.3.1](ch03.md#def-3.3.1)）。

**7.（参考）** (a) 单位是 ns/输入元素：批次墙钟时间除以「迭代次数 × 元素数」，是一次工作核调用摊到每个元素的平均成本，**不是一次 `borrow` 语法操作的耗时**——借用语法本身没有运行时开销。(b) 0.100168563 × 65536 ≈ 6564.6 ns，即一次 `cloned` 调用约多花 6.6 微秒；一批 256 次约 1.68 毫秒。(c) 差值包含分配、复制、释放和缓存状态变化；不能命名为「借用检查节省了 0.1 ns」，也不能拆成「分配占几成」——本轮没有逐项计时。给分：(a) 说出「工作核调用」得 2 分，说出「不是语法操作耗时」得 1 分；(b) 每项换算 1.5 分；(c) 列出三个资源动作 2 分、指出禁止的命名 2 分。

**8.（参考）** (a) 21 个批均值上 `ceil(21 × 0.99) = 21`，所以这一列就是该 case 的最大批均值，只描述批次之间的波动范围，不是一次调用的最坏情况，也不是请求尾部。(b) 不宜直接横比：两个 case 的均值相差约 5.73 倍，绝对波动随均值同量级缩放；要比稳定性得改用相对量并说明归一化方式（按本表各除以自己的均值约 1.7% 与 3.0%，方向反而相反）。(c) 否证「`with_capacity` 加 `push` 没有提前清零，所以必然更快」；四个条件：`T` 为 `u64`、零是合法值、消费者要求完整切片、本机本轮构建。给分：(a) 2 分说明是最大值、1 分说明不能当请求尾部；(b) 指出缩放 2 分、给归一化方向 1 分；(c) 直觉 2 分、四条件各 0.5 分。

**9.（参考）** 容量 7（`with_capacity(7)` 一次买下）；退出时长度 2（下标 0、1 各 `push` 一次，前缀里有两个合法 `T`）；已被丢弃的元素数 2（局部 `Vec` 离开作用域时清理前缀）；下标 2 到 6 从未进入长度，既没有被读取也没有被析构；调用方拿到的是 `Err`，没有 `Vec`，拿不到半成品。给分：五项各 2 分；写成「7 个位置都要清理」该项 0 分（[例 3.3.1](ch03.md#ex-3.3.1)、[例 3.4.2](ch03.md#ex-3.4.2)）。

**10.（参考骨架）**
- 时间：解引用发生在 `Vec` 被 drop、扩容或被 `mem::take` 之前还是之后？地址相等不延长生命周期，本例没有记录。
- 空间：范围 `[ptr, ptr + 65536)` 应属同一次分配；本例没记录范围长度的来源，也不能靠「两个地址看起来连续」论证。
- 初始化：长度以内都已写入合法 `u64`；若原 `Vec` 扩容，前缀位置整体改变，这条就不再由旧地址保证。
- 别名：需按排他条件论证这段时间内没有别的路径写入同一存储；保存裸指针时这条最容易被跳过。
- 泄漏：客户端 `mem::forget` 之后地址仍在但没有拥有者——这是安全封装明列的义务，不能假定调用方最后肯定会 `Drop`。
- 其余五行：可以标「不适用」，但必须逐行写明为什么不适用（单线程、无并发发布；本例无构造过程，故无半构建路径），空白不等于通过。
- 最少要补的两条：**时间**与**别名**。前者要求证明解引用时存储仍存活，后者要求证明这段时间没有别的路径写入同一存储（[例 3.7.1](ch03.md#ex-3.7.1)）。

**11.（参考骨架）**
- 预算 `B`：在采集之前写下，单位与被测统计量一致（ns/输入元素），来源写成业务口径（每次请求的时间余量或配额），并注明内存与正确性是并列约束。事后定 `B` 等于把判定权交给想要的结论。
- 口径：沿用本章协议——21 批、同轮交替记录 `position`、按原始 `round` 配对求 `d`，报均值、N−1 标准差、nearest-rank 批 p50 与 p99，区间用固定种子 bootstrap。换分母就是新实验。
- 判定：`U ≤ B` 接受；`L > B` 拒绝；其余证据不足，动作是加检测能力（独立重跑、真实输入分布、完整调用链），不是压成通过。
- 并列上报与边界：时间之外还要报内存（副本的峰值占用）与正确性；本章没有采集分配/复制/释放的成分占比、没有采集真实内存流量、没有做跨机器与跨版本重跑，所以不能说「省下的时间里有几成来自免掉分配」，也不能把区间说成跨构建成立。
- 参照[例 3.5.2](ch03.md#ex-3.5.2) 的形状：那里的 `B = 0.0005` 是**假想约定**，用于演示判定形状，不是采集量；粒度（每请求一次还是启动时一次）决定同样的数字是否值得拦。

**12.（参考，四处各 3 分）**
- ① 把版本化的代码生成观测说成语言形式语义 → 改成「本次构建中后端利用了读写不重叠这一事实」，并注明属性给的是优化许可、不保证所有借用核向量化。
- ② 把资源工作量的差读成语法价格，还把它推广成通用规则 → 先问粒度与「结果是否要活过输入」；需要独立生命周期时副本是正确设计，比值只在同一分母的批均值这一层有意义。
- ③ 把「若干条具体控制流测过」当成「所有泛型实例与所有退出路径证明完」→ 补上静态产物（MIR 的 cleanup 边）与接口契约，并说明 `panic = "abort"` 构建没有展开路径可测。
- ④ 把 `u64` 的前提当成泛型结论 → 零对引用与 `NonZero` 不合法，`String` 一类还有 `Drop` 责任；要改就按「只改一个合法结构」另做单因素实验。
- 结论句示例：「在这台机器、native-01 归档对应的构建与单线程同步输入下，本轮证据支持额外拥有副本路径更贵（每输入元素多 0.100168563 ns，区间 [0.099374896, 0.101163745]）；本结论不覆盖分配/复制/释放的成分占比、跨机器与跨版本差异，也不构成『所有 `clone` 都应删除』的接口规则。」给分：对象 1 分、条件 1 分、指标与区间 2 分、限制 1 分。

## 重做规则

错 3 题以内：只重做错题对应的最小练习包（见[习题集](ch03_exercises.md#ch03-ex-pack)）。
错 4–7 题：重做该题所在小节的正文加该节的即时自测。
错 8 题以上，或第三部分未达合格线：不要刷第二遍卷子。回到 3.1–3.4，把「谁负责 → 能访问什么 → 有没有合法的值」这条线重新走一遍，用[回忆卡](ch03_recall.md)第一、二组自测，然后隔 3 天再考一次。
全卷 ≥70 且第三部分 ≥28：进入[第四章](ch04.md)，7 天后只重做[自检表](ch03_checklist.md)里标过 △ 和 × 的条目。
