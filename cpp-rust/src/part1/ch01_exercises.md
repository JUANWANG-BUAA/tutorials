# 第一章 · 习题集

共 20 题，分三组。**A 组概念**检验你能否说出名词指的是什么；**B 组推理**检验你能否从数据或代码推出结论；**C 组实操**要求你真的改代码、跑数据、写结论。全部题目附解答，难题另附提示层。

用法约定：先写下自己的答案，再展开核对。看解答时只看第一行就停住，问自己「接下来那一步是不是我要走的」，再往下读。直接通读解答，得到的只是「看懂了」，不是「会做了」。

## A 组 · 概念（1–7）

::: ex A1 · 估计对象与单位（主线 ②） {#ex-1.A.1}

「批均值 = `T / (K × N)`」这个式子里，`T`、`K`、`N` 分别是什么？它的单位是什么？为什么这个数不能解释成「一次加法要多久」？

::: sol 解答

`T` 是一个批次的墙钟时间间隔（两次 `Instant::elapsed` 之间），`K` 是这一批里连续调用的次数，`N` 是每次调用处理的元素数。单位是 ns/元素。它不能解释成单次指令延迟，因为一次批次里发生了 `K` 次调用、每次处理 `N` 个元素，`T` 还把计时读取与循环入口的夹具成本摊了进去；除以 `K × N` 之后得到的是**平均摊到每个元素上的成本**，属于吞吐口径，不是任何一条指令的延迟。对照 [定义 1.2.2](ch01.md#def-1.2.2)。

:::

:::

::: ex A2 · DCE 到底删了什么（主线 ①） {#ex-1.A.2}

死代码消除（DCE）删掉的「死」，判定标准是什么？是「这段代码没用了」还是「这个值没人观察」？

::: sol 解答

判定标准是后者：**这个值是否进入可观察集合**。编译器不关心你「打算」用它，只关心在当前函数里它是否被写出、返回、比较或传出不透明的边界。`dce_empty` 的 `fold` 在语义上遍历了数组，但返回值被立即丢弃，整个遍历就被删掉了。对照 [定义 1.1.1](ch01.md#def-1.1.1) 与 [例 1.1.1](ch01.md#ex-1.1.1)。

:::

:::

::: ex A3 · 屏障的方向（主线 ①） {#ex-1.A.3}

`black_box` 加在输入上和加在输出上，各自阻止的是什么？为什么只加输入屏障防不住 DCE？

::: sol 解答

输入屏障阻止优化器利用「这个值我已知」的事实——它让编译器对值的**来源**保持悲观，于是读取真的发生。输出屏障让这个值必须**存在**到一个不可预测用途的观察点，于是计算的结果被保住。只加输入屏障时，工作核仍然接收了不透明的数据，但返回值没人用，纯计算照样可以整段删除。方向搞混是这一章最常见的失败模式，见 [定义 1.3.1](ch01.md#def-1.3.1) 的四道屏障位置。

:::

:::

::: ex A4 · 配对的定义（主线 ③） {#ex-1.A.4}

什么才叫「一轮配对」？为什么两组各自算好均值再相减，不算配对差值？

::: sol 解答

一轮 = 每个实现各测一个批次，并在同一轮里记录先后位置；配对差值是先对**同一轮的 a、b** 求 `d = b − a`，再对这 21 个 `d` 求均值与标准差（[定义 1.4.2](ch01.md#def-1.4.2)）。两组均值各自算好再相减，得到的数值可能一模一样，但波动估计完全不同：配对的用意是让同一轮的共同时间条件（热状态、频率、后台负载）在相减时抵消，拆成两组独立样本后这种相关性信息就丢了，标准差会被高估。

:::

:::

::: ex A5 · 三种「没问题」（主线 ③） {#ex-1.A.5}

「区间跨零」、「区间整体落在预算内」、「正确性失败」这三种情况，分别能下什么结论？

::: sol 解答

区间跨零只说明**本次运行内方向不可判定**，不能写「两者等速」；区间整体落在预算 `B` 之内（即 `U ≤ B`）才按 [定义 1.7.2](ch01.md#def-1.7.2) 判为接受，且结论只绑定那组输入、环境与构建；正确性失败**不进入性能判断**，先修功能与契约——一个错的实现再快也没有意义。

:::

:::

::: ex A6 · 探索性与确认性（主线 ④） {#ex-1.A.6}

在同一批数据上反复换指标、换切片，最后发布「最好的一次」，问题出在哪一步？

::: sol 解答

问题在把 [探索性实验](ch01.md#def-1.7.3) 当成了确认性实验。探索阶段可以自由改输入和指标，用来发现机制；一旦要用它出结论，协议、输入家族、统计量和判定规则必须在采集前固定，并独立重跑。同一批数据上多次尝试后挑最好的一次，偶然极值被系统性选中，报告出来的收益是选择偏差，不是性能。

:::

:::

::: ex A7 · 五种复现失败（主线 ④） {#ex-1.A.7}

复现失败分成哪五层？为什么把它们统一写成「benchmark 失败」会妨碍定位？

::: sol 解答

构建失败（工具链/目标/依赖不同）、功能失败（checksum 或断言不过）、采集失败（原始记录缺轮次）、解释失配（换机器后代码生成或布局不同，未必是错误，是结论范围变了）、统计不确定（区间跨预算）。五层的修法完全不同：第一层改环境，第二层改实现，第三层改采集，第四层改结论措辞，第五层加证据。合成一句话就没法知道该动哪里，见 [1.8 复现失败要分层报告](ch01.md#sec-cpp-rust.1.1.8)。

:::

:::

## B 组 · 推理（8–14）

::: ex B8 · 3600 倍错在哪（主线 ②） {#ex-1.B.8}

`dce` 的 observed 均值 0.058630038，discarded 均值 0.000016082。有人写：「实测比删掉的版本慢 3600 倍，说明优化器带来 3600 倍加速。」请指出这句话的全部错误。

::: hint 提示

两个数的分母相同吗？它们的分子量的是同一件事吗？

:::

::: sol 解答

三层错误。① 语义不同：discarded 根本没有读取数组（[定义 1.1.1](ch01.md#def-1.1.1)），它的分母仍是 65536 个**名义**元素，分子是一次空返回的耗时；observed 做的是一次真实求和。相除得到的是「被删掉的工作 vs 没被删掉的工作」之比，不是任何算法的加速。② 基线接近零时比值发散，微小的绝对误差会变成巨大的倍数。③ 「优化器带来 3600 倍加速」把因果说反了——删除是优化器的行为，但被删的是基准自己的无用工作，真实程序里没有这 3600 倍可拿。

:::

:::

::: ex B9 · p99 为什么等于最大值（主线 ②） {#ex-1.B.9}

一个 case 有 21 个批均值，nearest-rank p99 报成 0.059458137，而它正是这 21 个数的最大值。这是 bug 吗？这个数能说明什么、不能说明什么？

::: sol 解答

不是 bug。nearest-rank 把 p 分位数定义为排序后第 `ceil(N × p)` 个值，`ceil(21 × 0.99) = 21`，取的就是最后一个。它能说明「这 21 批里最慢的一批是 0.059458137」，即批次之间的波动范围；不能说明生产请求的 p99，也不能说明单次调用尾部分布——那需要逐请求观测和匹配尾部概率的样本设计（[1.8 尾分位数需要不同的采集设计](ch01.md#sec-cpp-rust.1.1.8)）。样本数必须和分位数一起报，否则读者会误判证据强度。

:::

:::

::: ex B10 · 差值 sd 为什么不能由两组 sd 合成（主线 ③） {#ex-1.B.10}

indexed 的 sd 是 0.000458518，iterator 是 0.000541829，配对差值的 sd 却是 0.000484383。有人说「按独立样本合成应该约等于 `√(0.000458518² + 0.000541829²) ≈ 0.00071`，你的数偏小，统计有问题」。怎么回应？

::: hint 提示

写 `Var(B − A) = Var(A) + Var(B)` 时用的是什么前提？同一轮的 A、B 满足吗？

:::

::: sol 解答

独立合成的公式前提是两个量互不相关。同一轮的 A、B 恰好共同经历了那段机器状态，正相关；配对的用意就是用相减抵消这部分共同波动，所以 `Var(B − A) = Var(A) + Var(B) − 2Cov(A,B)`，协方差项为正时差值方差必然小于独立合成的值。实测 0.000484383 明显小于 0.00071，说明配对确实抵消了共同漂移，这正是采用配对设计的理由（[定义 1.4.1](ch01.md#def-1.4.1)）。

:::

:::

::: ex B11 · 前后段差 0.0001（主线 ③） {#ex-1.B.11}

`paired` 里 indexed 前 7 轮均值 0.058683、后 7 轮 0.058575，iterator 分别是 0.058684、0.058643。有人据此写「本次运行无漂移」。这个结论的问题是什么？正确的措辞是什么？

::: sol 解答

问题是把「检测不到」说成「不存在」。四个数的前后差分别约 0.000108 与 0.000041 ns/元素，而批均值的样本标准差在 0.0005 量级——差值远小于批间波动，这个诊断根本没有能力分辨这么小的漂移。正确措辞是：「前后 7 轮均值之差小于批间标准差，本次运行未检出明显的线性时间漂移；该诊断不足以排除小于批间波动的漂移。」前 7 / 后 7 只给出弱结论（见 1.4.4 的漂移诊断），要判长期稳定性得在不同时段独立重跑。

:::

:::

::: ex B12 · 区间跨零之后（主线 ③） {#ex-1.B.12}

iterator 减 indexed 的配对均值为 0.000074625 ns/元素，bootstrap 区间 [−0.000128553, 0.000269819]。现在给出两种工程背景：(a) 这段代码每秒调用 10 万次，每次 65536 元素；(b) 只在启动时跑一次。两种背景下「区间跨零」的含义相同吗？

::: sol 解答

数据层面相同，决策层面不同。(a) 里每元素 0.000074625 ns 乘以 65536 × 100000 约为每次运行 0.49 秒的累计差——这个量级值得提高检测能力（独立重跑、真实输入分布、完整调用链），把方向问出来；(b) 里同样的差值累计不到 5 微秒，落在任何预算之内，可以直接接受可读性更好的写法。区间跨零只回答「本次证据分不出方向」，值不值得继续测取决于 `B` 与调用频率，不取决于统计量本身（[定义 1.7.1](ch01.md#def-1.7.1)）。

:::

:::

::: ex B13 · 谁删了样本（主线 ④） {#ex-1.B.13}

同事说：「有两批明显是后台干扰，我把它们删了，p99 好看得多。」按 [1.7.7](ch01.md#sec-cpp-rust.1.1.7) 的规则，这个操作违反了什么？在什么条件下删点是可以接受的？

::: sol 解答

违反的是：删除必须有**外部事件证据**，不能从「这个值偏大」本身推定它无效——那是循环论证，而且配对分布是整对的，只删一侧还会破坏轮次对应。可接受的条件是：① 有独立于观测值的记录（系统日志、并发任务、散热事件）指出受影响批次；② 整对删除，两侧一起去掉；③ 同时报告包含与排除两种结果的敏感性分析，不能只发布有利的一种；④ 事先说明规则。做不到就保留全部 21 批，这也是本次实验的处理方式。

:::

:::

::: ex B14 · 汇编与计时谁说了算（主线 ①） {#ex-1.B.14}

静态证据（MIR、优化后 LLVM IR、本机汇编）和实际计时，各能证明什么、各不能证明什么？举一个「静态通过但计时无效」和一个「计时正常但静态会误导」的例子。

::: sol 解答

静态证据回答「优化后保留了哪些操作」，能证明工作没被删、能定位删除路径；它不能给出端到端成本，也不能证明当前执行路径真的走到了那段代码。计时回答「这台机器、这组输入下的墙钟成本」；它不能解释机制，也无法在夹具被删空时给出有意义的数——「静态通过但计时无效」的例子就是 `dce`：汇编里只剩 `mov x0, #0; ret`，计时照样跑出一个稳定的极小值。「计时正常但静态会误导」的例子是把某个 `#[inline(never)]` 的独立函数当成生产路径——实际调用点上它会被内联，看错函数体会得出相反的结论。两类证据互相约束，不互相替代（[1.8 MIR、IR 与汇编的分工](ch01.md#sec-cpp-rust.1.1.8)）。

:::

## C 组 · 实操（15–20）

实验包在 `bench/foundations-lab/`，数据在 `bench/foundations-lab/results/native-01/`。这组题要求真的动手：改代码、跑脚本、把结论写成可复核的句子。

::: ex C15 · 让被删的求和活过来（主线 ①） {#ex-1.C.15}

::: sol 参考路径

关键是让结果进入可观察集合，例如 `println!("{}", black_box(sum))`。修改后汇编里应当出现向量加载与累加，而不是只有 `mov x0, #0; ret`。如果你的版本仍然只剩常量，按顺序检查：返回值是否被丢弃、`println!` 是否在计时边界之外、`black_box` 包的是值还是描述符（[定义 1.3.1](ch01.md#def-1.3.1)）。命令与产物路径见 [1.8 复现命令](ch01.md#sec-cpp-rust.1.1.8)。

::: ex C16 · 原始 CSV 的最小复核（主线 ④） {#ex-1.C.16}

打开 `dce.csv` 与 `paired.csv`，用 3 分钟完成一次最小复核，并写下你检查了哪四项。

::: sol 参考路径

四项：① 每个 case 恰好 21 个不同 `round`；② `position` 在相邻轮次交替（不是前 21 轮全 A 后 21 轮全 B）；③ 同一 case 内 checksum 不变化；④ 用 `T`、`K`、`N` 反向乘回原始量级，检查单位是否自洽。若只看表格没核对代码，实验复现还没完成。重跑 `analyze.py` 时把 CSV 复制到新目录，不要覆盖原归档的 `statistics.json`。

::: ex C17 · 分组求和的配对实验（主线 ③） {#ex-1.C.17}

给 `paired.rs` 增加 `sum_chunks`：每 8 个元素一组累加，组间用 `wrapping_add` 合并，保持模加法语义。跑 21 批，报告配对差值与 bootstrap 区间，并给出三态判定。

::: hint 提示

分组会改变自动向量化形态，先预测方向再测。别把 `B` 留到看见数字之后再定。

:::

::: sol 评分要点

合理解答需要含：① 等价性论证（分组与合并都是模加法，结果与逐个相加一致，含空输入与尾组）；② 契约四组问题（输入家族、计时边界、观察方式、外部条件）；③ 与 indexed 的同轮配对差值、N−1 标准差、固定种子区间；④ 预先写下的 `B` 与三态结论；⑤ 一句限定范围的结论。任何一步缺失都扣分，见 [综合自测卷](ch01_exam.md) 的评分标准。

:::

::: ex C18 · 改变 K 会动什么（主线 ②） {#ex-1.C.18}

把 `dce` 的 `K` 从 256 改成 64，重新跑 21 批。先预测均值、标准差和 p99 各自怎么变，再用数据检验，并说明哪些变化来自时钟/夹具、哪些来自热漂移。

::: sol 参考路径

预测应写成可核对的三条：均值——夹具（两次时钟读取与循环入口）在总时间中占比变大，若工作核本身耗时远大于夹具，均值会被抬高；标准差——同一量级或略大，因为固定开销的相对抖动被放大；p99——仍然是 21 个数里的最大值，**分辨率没有改善**，位数变化不代表精度变化。区分来源：看单批绝对时长与重复运行之间的波动，随 `K` 明显变化更像夹具/时钟问题，随时间位置变化更像热漂移。改完记得重新生成代码证据——`K` 不进内核语义，但表格里 `K` 是分母的一部分。

:::

::: ex C19 · clone 与借用的完整契约（主线 ④） {#ex-1.C.19}

设计一个实验回答：「在这台机器上，`Vec<u64>` 的 clone 后求和与借用求和，差异是否可区分？」写出实验契约、CSV 字段、统计方法与三态判定。

::: sol 参考路径

契约：输入为同一份 65536 个 `u64`，clone 侧必须逐次重新分配并保活到停表后（否则分配被删）；计时边界只包围 clone + 求和 vs 借用求和；观察每次的 checksum 与输出槽位；外部条件记录 rustc 1.99.0、`aarch64-apple-darwin`、`-C target-cpu=native`、`opt-level=3`、`codegen-units=1`、`lto=false`。CSV 字段至少 `kind,round,position,case,ns_per_unit,checksum`。统计：21 轮配对差值、N−1 sd、固定种子 bootstrap。判定：`U ≤ B` 接受、`L > B` 拒绝、其余证据不足，`B` 由「每次调用的内存与耗时预算」预先给出。注意这一题里内存是并列约束，不能只报时间（[定义 1.7.1](ch01.md#def-1.7.1)）。

:::

:::

::: ex C20 · 把结论写成一句话（主线 ④） {#ex-1.C.20}

用 [1.8 发布结论的最小句式](ch01.md#sec-cpp-rust.1.1.8) 给本次 `paired` 实验写一句结论，然后指出这句话故意**没有**承诺哪三件事。

::: sol 解答

示例：「在这次固定的热数组、`-C target-cpu=native` 的 release 构建与单进程交替批次条件下，两种求和核的批均值接近，配对差值的 95% bootstrap 区间跨零，本次运行内无法判定方向。」它没有承诺：① 语言级的实现等速（换编译器或优化级别可能变）；② 生产请求的尾延迟（这里只有批均值）；③ 跨时段或跨机器的稳定性（区间只覆盖本次运行的抽样波动）。三个「没有」正是这句话可信的部分。

## 批改时最常给的三条意见

1. **单位与对象错位**：把批均值说成指令延迟、把批次 p99 说成请求 p99。先改句子，再改表格。
2. **结论超出证据**：区间跨零写成「等价」，单次运行写成「稳定」。给每个结论补上「在这组输入、这个构建、这次运行内」。
3. **契约缺项**：只说「预热过」不写时长，只说「测了 21 批」不写轮次与位置。用[定义 1.1.3](ch01.md#def-1.1.3) 的四组问题逐条补齐。
