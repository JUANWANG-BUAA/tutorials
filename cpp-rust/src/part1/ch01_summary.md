# 第一章 · 全章总结

这一页只回答一件事：**九节各留下了什么可复用的结论。**证明、数据和展开解释都在正文，这里把每条结论压缩成一句可以带走的句子。合上正文再读这页，读不下去的那一行就是断点。

## 九节一览

| 节 | 留下的结论 | 破坏它的最快方式 |
|:--|:--|:--|
| [1.1](ch01.md#sec-cpp-rust.1.1.1) | 一个耗时数字必须带着实验契约：输入、计时边界、观察方式、外部条件，缺一条就不是同一个量 | 让返回值没人用，DCE 把整段工作删掉，数字照样稳定 |
| [1.2](ch01.md#sec-cpp-rust.1.1.2) | 一次观测的单位是批均值 `T / (K × N)`；它回答吞吐，不回答单次请求延迟 | 逐元素读时钟，测到的是「计时 + 工作」的混合 |
| [1.3](ch01.md#sec-cpp-rust.1.1.3) | 可观察性是逐次调用建立的：每次调用都要留下痕迹，事后统一 `black_box` 不算 | 只在最后一次调用外包屏障，前 `K−1` 次被合并 |
| [1.4](ch01.md#sec-cpp-rust.1.1.4) | 配对、交替顺序、原始 `round`/`position` 是对抗时间漂移的最低配置 | 先跑完 A 再跑完 B，加倍样本只会让错误结论更精确 |
| [1.5](ch01.md#sec-cpp-rust.1.1.5) | 均值、N−1 标准差、nearest-rank 分位数要一起报；21 个数的 p99 就是最大值 | 只报均值，把批次波动和尾部分布一起丢掉 |
| [1.6](ch01.md#sec-cpp-rust.1.1.6) | 差值区间跨零意味着方向不可判定，不意味着等速；等价需要预先给容差 | 用「误差条重叠」当检验，或直接写「两者一样快」 |
| [1.7](ch01.md#sec-cpp-rust.1.1.7) | 判定是三态：`U ≤ B` 接受、`L > B` 拒绝、其余证据不足；`B` 在采集前写下 | 看到数字再定预算，或把「证据不足」压成通过 |
| [1.8](ch01.md#sec-cpp-rust.1.1.8) | 结论要限定对象、条件、指标与限制；复现失败要分五层报告 | 把一次运行的结果写成语言级的保证 |
| [1.9](ch01.md#sec-cpp-rust.1.1.9) | 方法来自三类母本：Effective Rust 第 30 条、标准库文档、The Book 第 11/13 章 | 把语言层面的说法当成测量协议 |

## 一条主线

**先证明工作真的发生 → 再谈单位 → 再谈差异 → 最后谈能不能守住。**

1.1–1.3 都在回答第一件事：结果有没有进入可观察集合。1.2 把「有」量化成批均值，1.3 把「一直有」写成夹具里四道屏障的位置。1.4–1.5 转向第二件事：这个数是什么的口径——吞吐还是延迟、批次还是请求。1.6–1.7 回答第三、四件事：差异有多大、多小可以不算，判定规则的三态。1.8 收尾于「别人怎么复核」：文件级证据、复现命令、五层失败。

任何一环没走完，后面所有数字都只是修辞。

## 能否讲出这几句话

不看书，用自己的话回答。答不上来的，回到对应小节只看那一段。

1. 「死代码消除」删的是没用的代码，还是没人观察的值？为什么这两件事在基准里不一样？
2. 为什么批均值 `T / (K × N)` 不能当成一次加法的延迟？分母里的 `K` 起了什么作用？
3. 一次批次的 21 个数字之间，是什么让它们彼此相关？配对抵消掉了哪一部分波动？
4. bootstrap 区间的两处前提是什么？它覆盖了哪一层不确定性、没覆盖哪一层？
5. 「证据不足」和「拒绝」的下一步动作为什么必须不同？
6. 一个合格的性能结论要含哪四件？给一个把三件漏掉的反例。
