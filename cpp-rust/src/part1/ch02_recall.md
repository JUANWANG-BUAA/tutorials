# 第二章 · 闭卷回忆卡

「看懂」只说明答案在眼前时能识别；评审和复现时需要的是从空白纸上提取。这一页把第二章拆成 24 张卡，每张卡先写卡面问题，合上正文自己答，再展开核对。

**用法与节奏**

| 时点 | 做什么 | 判定 |
|:--|:--|:--|
| 学完当天 | 第一组「定义卡」全部 8 张 | 关键词写全才算 ✓ |
| 第 1 天 | 第二组「结论卡」全部 7 张 | 能说清前提才算 ✓ |
| 第 3 天 | 第三组「第一行卡」全部 7 张 | 写出第一步才算 ✓ |
| 第 7 天 | 只重做标成 △ 和 × 的卡 | 全对即可进入第三章 |

每张卡给自己一个记号：✓ 一次说对；△ 说对一半或要提示；× 想不起来。只重做 △ 和 ×，不要把整叠卡反复过一遍——那是在读，不是在提取。

## 第一组 · 定义卡（说全称与前提）

::: ex 卡 1 · 布局三元组 {#rc-2-1}

卡面：写出布局三元组，并说出哪一个决定同类型数组的步长。

::: sol 核对

size、align、字段偏移。size 决定相邻元素的步长；align 约束合法存放位置的地址；偏移是字段距起点的距离。三者合起来才叫布局，只报 size 会漏掉 align 与偏移两条边界。对照[定义 2.1.1](ch02.md#def-2.1.1)。
:::

:::

::: ex 卡 2 · 描述符与元素区 {#rc-2-2}

卡面：这两个词各指什么？为什么必须分开记账？

::: sol 核对

描述符是你拿在手里的对象（如 `Vec` 本身），元素区是它指向的承载数据的存储。移动 `Vec` 只动描述符。本章 `Vec<u64>` 描述符 24 字节、元素区 524288 字节，混成一笔就会把扫描与缓存推理建在错的分母上。对照[定义 2.1.2](ch02.md#def-2.1.2)、[例 2.1.1](ch02.md#ex-2.1.1)。
:::

:::

::: ex 卡 3 · 保证层级 {#rc-2-3}

卡面：一句布局结论可以落在哪三层？各举探针表里一行。

::: sol 核对

语言约束（`repr(C)` 按声明顺序）、标准库保证（`Option<NonZeroU64>` 与载荷同 size，条件见文档）、本机观测（`RustOrder` 是 16 字节、切片引用是 16 字节）。第三类换目标、换编译器版本必须重测。对照[定义 2.1.3](ch02.md#def-2.1.3)。
:::

:::

::: ex 卡 4 · 有效值集合与 niche {#rc-2-4}

卡面：给出两者定义，并说清 niche 为什么不是运行时压缩。

::: sol 核对

有效值集合是该类型合法的那些位模式；niche 是被排除在外、不能当正常载荷的表示。`NonZeroU64` 排除 0，`None` 借用这个位模式，所以不用额外标签。这是编译器在表示层的利用，不是扫描数据的算法。对照[定义 2.2.1](ch02.md#def-2.2.1)。
:::

:::

::: ex 卡 5 · 热列投影 {#rc-2-5}

卡面：给这个词下定义，并说出它与完整 SoA 的三点差别。

::: sol 核对

只保存热字段那一列的投影，不是完整 SoA。三点差别：① 没有冷字段列；② 两个表示在计时前同时存在，未测转换成本；③ 未比较两种完整模型的总内存峰值。对照[定义 2.4.1](ch02.md#def-2.4.1)。
:::

:::

::: ex 卡 6 · 计时外构造 {#rc-2-6}

卡面：定义是什么？它换来什么好处、付出什么代价？

::: sol 核对

被扫描的数据在正式计时区间开始前全部建好，夹具只选择扫描哪一个。好处：两次扫描面对同一份工作集。代价：构建与转换成本被移出边界，数字只属于「重复访问阶段」。对照[定义 2.5.1](ch02.md#def-2.5.1)。
:::

:::

::: ex 卡 7 · 逻辑块操作 {#rc-2-7}

卡面：allocation 实验的计量单位「一次逻辑块操作」由哪几件事组成？

::: sol 核对

取一段 64 字节、用 7 填满、把首字节加进校验、把整段切片交给 `black_box` 观察。单位是 ns/逻辑块操作，含取存储、写入、观察三项，不是纯分配调用延迟。对照[定义 2.7.1](ch02.md#def-2.7.1)。
:::

:::

::: ex 卡 8 · 两种对齐 {#rc-2-8}

卡面：相对偏移对齐与绝对地址对齐差在哪？哪一条才满足 `&mut T` 的要求？

::: sol 核对

相对做法只让游标 `used` 成为 align 的倍数；绝对做法要求 `base + used`（计入 padding 后）本身是 align 的倍数，且对象完整落在同一次分配内。只有后者满足引用要求——align 量的是「合法存放位置的地址约束」。对照[定义 2.8.1](ch02.md#def-2.8.1)。
:::

:::

## 第二组 · 结论卡（说清前提与范围）

::: ex 卡 9 · 声明顺序不是契约 {#rc-2-9}

卡面：「默认 `repr` 里字段按声明顺序排」这句话的问题在哪？

::: sol 核对

默认 `repr` 允许编译器选任何满足约束的安排，根本不承诺顺序。本轮 `RustOrder` 的偏移是 10、0、8，与声明顺序不同；由此不能把字段顺序写进文件格式或网络协议。这与有没有启用布局随机化无关。对照[2.1 节](ch02.md#sec-cpp-rust.1.2.1)、[定义 2.1.3](ch02.md#def-2.1.3)。
:::

:::

::: ex 卡 10 · 填充不是隐藏存储 {#rc-2-10}

卡面：COrder 有几个填充字节？能借用它们吗？

::: sol 核对

字段共 11 字节、size 24，填充 13 字节（偏移 1–8 的 7 字节加尾部 6 字节）。不能借用：编译器移动或赋值时可能不保留它们，它们还可能未初始化；所以也不能用整对象字节做 `memcmp` 或稳定哈希。对照[例 2.1.2](ch02.md#ex-2.1.2)。
:::

:::

::: ex 卡 11 · niche 省空间不省判断 {#rc-2-11}

卡面：省掉标签之后，`None` 的分支会消失吗？这条结论的适用范围？

::: sol 核对

不一定。机器代码仍可能测试零值；判断是否被删要看调用上下文的产物，上游没证明就跳不过。且本节没有为 `Option` 采集时间数据，不能报 niche 带来的纳秒加速。对照[2.2 节](ch02.md#sec-cpp-rust.1.2.2)、[定义 2.1.3](ch02.md#def-2.1.3)。
:::

:::

::: ex 卡 12 · 跨度不等于流量 {#rc-2-12}

卡面：「AoS 跨度是热列 8 倍」能推到哪一句？再往前缺什么？

::: sol 核对

能说到：跨度 4194304 对 524288 字节、密度 12.5%，这是可算的布局事实。再往前（搬运字节、miss 次数、带宽）需要第二类证据：本章没采 PMU 事件，`Vec` 也不保证 128 字节起点对齐，重复扫描的命中情况未知。对照[定义 2.3.2](ch02.md#def-2.3.2)、[例 2.3.1](ch02.md#ex-2.3.1)。
:::

:::

::: ex 卡 13 · 8.74 倍能叫什么 {#rc-2-13}

卡面：耗时差 8.74 倍、跨度差 8 倍，可以说「差距由跨度造成」吗？

::: sol 核对

只能说方向一致（相容）。同一时间代码形态也变了：AoS 是标量加载加 64 字节步长，热列是连续向量加载加多条累加链；归因需要事件采集，本章没有。对照[例 2.4.1](ch02.md#ex-2.4.1)、[定义 2.3.2](ch02.md#def-2.3.2)。
:::

:::

::: ex 卡 14 · 复用不等于新建零缓冲 {#rc-2-14}

卡面：「区域每块等价于每次新建 `Vec`」这条等价声明被什么破坏？

::: sol 核对

被「未写入的字节」破坏：`vec![0u8; 64]` 全零，复用区域 `take(64)` 给的是上一轮残留；只有写入覆盖每个字节才在被读位置等价。第二条是释放时机：`fresh_vec` 每块归还、区域整批保留。只能写「在本实验读取集合上不可区分」。对照[思考 2.6.1](ch02.md#think-2.6.1)。
:::

:::

::: ex 卡 15 · 测试证明不了概率 {#rc-2-15}

卡面：容量失败测试覆盖了四条断言，它没有覆盖哪两件事？

::: sol 核对

没覆盖：① 失败在生产中发生的频率（块数分布没采集）；② 失败后回退策略的成本。确定性测试只证明「失败给出 `None` 且游标不动」，不能写成「生产中不会失败」。对照[例 2.7.2](ch02.md#ex-2.7.2)、[例 2.6.1](ch02.md#ex-2.6.1)。
:::

:::

## 第三组 · 第一行卡（只写第一步）

这一组练的是「一离开答案不知道第一行写什么」那个毛病。每题只写第一行动作，不计算。

::: ex 卡 16 · 有人说这个结构很小 {#rc-2-16}

卡面：听到「它 size 才 24 字节」，第一行写什么？

::: sol 核对

第一行：问「它指向的元素区多大、谁在被扫描」，把描述符与元素区分成两笔记账；不要先接受这个数当内存成本。对照[定义 2.1.2](ch02.md#def-2.1.2)。
:::

:::

::: ex 卡 17 · 想把内存布局写成文件 {#rc-2-17}

卡面：第一行写什么？

::: sol 核对

第一行：落层检查——这句话来自 `repr` 语法、标准库文档，还是一次 `size_of` 打印？默认 `repr` 的直接改用显式字段编码（字节序、长度、版本）。对照[定义 2.1.3](ch02.md#def-2.1.3)。
:::

:::

::: ex 卡 18 · 想把差距说成缓存收益 {#rc-2-18}

卡面：手里只有计时表和布局表，第一行写什么？

::: sol 核对

第一行：问「有没有第二类证据」——cache miss、TLB 事件、指令退休数采了没有。没采就停在「跨度差与耗时差方向一致」，机制留在候选解释里。对照[定义 2.3.2](ch02.md#def-2.3.2)。
:::

:::

::: ex 卡 19 · 区间不跨零就想发布 {#rc-2-19}

卡面：第一行写什么？

::: sol 核对

第一行：找预先写下的预算 B。locality 实验没有定义业务 B，65536 元素的顺序扫描不对应任何请求预算；没有 B 就停在限定结论句。对照[例 2.5.2](ch02.md#ex-2.5.2)、[定义 1.7.1](ch01.md#def-1.7.1)。
:::

:::

::: ex 卡 20 · 要给组合存储算偏移 {#rc-2-20}

卡面：要用 `Layout` 把 u8 头和 u64 尾部拼进一次分配，第一行写什么？

::: sol 核对

第一行：分清两份证明——`extend` 给的是「相对满足整体 align 的基地址」的偏移；基地址对齐、加法溢出、范围完整都要另证。先写受检计算（`checked_add` 一类），不写位运算上取整。对照[例 2.8.1](ch02.md#ex-2.8.1)、[定义 2.8.1](ch02.md#def-2.8.1)。
:::

:::

::: ex 卡 21 · 想拿区域切片当新缓冲 {#rc-2-21}

卡面：下游假设「取到的切片必定为零」，第一行写什么？

::: sol 核对

第一行：核对 `reset` 语义——它只把游标设 0，旧字节仍在 `storage` 里。要么保证每字节被覆盖，要么显式加清理策略并计入成本。对照[例 2.6.1](ch02.md#ex-2.6.1)、[2.6 节](ch02.md#sec-cpp-rust.1.2.6)。
:::

:::

::: ex 卡 22 · 旧切片还在用就想 reset {#rc-2-22}

卡面：第一行写什么？

::: sol 核对

第一行：画「有效借用区间」——这个借用之后还有没有使用？有就编译失败，不该用裸指针或 `static` 绕过；没有（最后一次使用在 `reset` 前）才合法。对照[定义 2.6.3](ch02.md#def-2.6.3)、[例 2.6.2](ch02.md#ex-2.6.2)。
:::

:::

## 第四组 · 机制参照卡（往下一层问「谁决定的」）

这一组不考正文的数，考你能不能把一条布局结论追到它下面那一层的**设计决定**。出处与禁忌见[参照主线](../rcore-line.md#rcore-line-map)：那一页的常量一个都不要背成自己的结论。

::: ex 卡 23 · 空闲匹配三种策略 {#rc-2-23}

卡面：一个分配器只能在最先匹配、最优匹配、最差匹配里选一种。说出前两种各自的代价，以及「为什么省空间的策略反而可能更慢」。

::: sol 核对

最先匹配（first-fit）从空闲链头开始找，找到第一个装得下的块就切给你，好处是不必遍历整条链；代价是链头会越积越多小块，后面的请求要跳过它们。最优匹配（best-fit）遍历整条链挑一个最贴合的，好处是浪费的尾字节少；代价是每次分配都要多扫一遍，而且留下的碎片往往小到没人能用——总量看着够，单个请求却满足不了。**省空间与省时间是两本账**，选哪个取决于你的分配频率与块尺寸分布，不取决于哪个名字更好听。这一格与本章的布局无关，属于分配器策略，出处是 rCore 第四章「超越物理内存的地址空间」；本书只借它的取舍框架，不借它的任何数字。对照[定义 2.6.4](ch02.md#def-2.6.4)。
:::

:::

::: ex 卡 24 · 你的对象布局被谁读走 {#rc-2-24}

卡面：你说「这个结构体太大，热字段只占 12.5%」。往下一层问：这个「大」除了浪费字节，还在哪一层产生第二笔代价？

::: sol 核对

第二笔代价在地址翻译那一层：跨度变大意味着同样的元素数量摊到更多页上，页表遍历更深、TLB（地址翻译缓存）更容易装不下，于是同一份数据被访问的次数越多，翻译开销越明显。大页能减轻这一层，但它的代价不在布局上，而在分配器——要支持多种大小的连续区域，就不能再用简单的插槽式管理。所以「把结构体缩小」的收益要分两本账报：搬运的字节数（可静态算）与翻译/缓存命中（要测）。这条机制的出处是 rCore 第四章 SV39 页表那两页，**它给的是方向，不是倍数**。对照[定义 2.3.2](ch02.md#def-2.3.2)、[定义 2.6.4](ch02.md#def-2.6.4)。
:::

:::
