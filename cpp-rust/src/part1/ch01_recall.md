# 第一章 · 闭卷回忆卡

「看懂」只说明答案在眼前时能识别；考试和评审时需要的是从空白纸上提取。这一页把第一章拆成 24 张卡，每张卡先写卡面问题，合上正文自己答，再展开核对。

**用法与节奏**

| 时点 | 做什么 | 判定 |
|:--|:--|:--|
| 学完当天 | 第一组「定义卡」全部 8 张 | 关键词写全才算 ✓ |
| 第 1 天 | 第二组「结论卡」全部 8 张 | 能说清前提才算 ✓ |
| 第 3 天 | 第三组「第一行卡」全部 8 张 | 写出第一步才算 ✓ |
| 第 7 天 | 只重做标成 △ 和 × 的卡 | 全对即可进入第二章 |

每张卡给自己一个记号：✓ 一次说对；△ 说对一半或要提示；× 想不起来。只重做 △ 和 ×，不要把整叠卡反复过一遍——那是在读，不是在提取。

## 第一组 · 定义卡（说全称与前提）

::: ex 卡 1 · 死代码消除 {#rc-1}

卡面：写出 DCE 的判定标准，并说出它为什么不算「编译器出了 bug」。

::: sol 核对

判定标准是**这个值有没有进入可观察集合**，不是你打算不用它。Rust 的语义只规定抽象机的行为，优化器在不改变可观察结果的前提下可以任意简化，删掉没人读取的纯计算完全合法。对照[定义 1.1.1](ch01.md#def-1.1.1)。
:::

:::

::: ex 卡 2 · 实验契约 {#rc-2}

卡面：一份实验契约要写清哪四组问题？少一组会怎样？

::: sol 核对

输入（数据形态与冷热）、计时（边界在哪、单位是什么）、观察（结果怎样进入可观察集合）、外部条件（编译器、目标、构建参数、运行环境）。少任何一组，两个数字就不再是同一个量，别人无法复核，也无法判断结论的适用范围。对照[定义 1.1.3](ch01.md#def-1.1.3)。
:::

:::

::: ex 卡 3 · 批均值 {#rc-3}

卡面：写出批均值公式并解释每个符号；它属于哪种口径？

::: sol 核对

`T / (K × N)`：`T` 是一个批次的墙钟间隔，`K` 是批内调用次数，`N` 是每次调用的元素数。单位 ns/元素，是**吞吐口径的平均摊薄**，不是单次调用或单条指令的延迟。对照[定义 1.2.2](ch01.md#def-1.2.2)。
:::

:::

::: ex 卡 4 · 预热与装载 {#rc-4}

卡面：预热能处理什么、不能处理什么？

::: sol 核对

能处理一次性装载：首次缺页、代码与数据冷热转换、动态链接、分配器初始化。不能处理随时间变化的热漂移：频率随温度回降、后台任务抢占、内存带宽竞争、线程被迁到另一类核心。预热要写明时长与正确性检查，否则可能测了一条错误路径。对照[定义 1.2.3](ch01.md#def-1.2.3)。
:::

:::

::: ex 卡 5 · 一轮与位置 {#rc-5}

卡面：什么是一「轮」？`position` 记录的是什么？

::: sol 核对

一轮 = 每个实现各测一个批次，中间只隔一次状态复位；`position` 记录这一轮里谁先跑。顺序在相邻轮次交替，使时间位置与实现分离，才能把「先跑的是不是总更快」这件事查出来。对照[定义 1.4.1](ch01.md#def-1.4.1)。
:::

:::

::: ex 卡 6 · 配对差值 {#rc-6}

卡面：写出配对差值的定义与三条操作纪律。

::: sol 核对

同一轮 `d = b − a`，先逐轮算差值，再对 21 个 `d` 求均值与标准差。纪律：按原始 `round` 配对；缺轮整对删除（两侧一起删）；不许先排序再相减，也不许把两组均值相减冒充配对结果。对照[定义 1.4.2](ch01.md#def-1.4.2)。
:::

:::

::: ex 卡 7 · nearest-rank 分位数 {#rc-7}

卡面：nearest-rank 怎么定义 p99？N=21 时它等于什么？

::: sol 核对

排序后取第 `ceil(N × p)` 个值。`ceil(21 × 0.99) = 21`，所以 p99 就是最大值。报分位数必须同时报样本数，否则读者会把「21 个数里的最大」当成生产尾部。对照[定义 1.5.2](ch01.md#def-1.5.2)。
:::

:::

::: ex 卡 8 · 三态门禁 {#rc-8}

卡面：给出三条判定规则，并说明等号归哪一边由谁决定。

::: sol 核对

设区间 `[L, U]`、预算 `B`：`U ≤ B` 接受；`L > B` 拒绝；其余证据不足。等号归属本身是协议的一部分——本章的 `gate.py` 把 `high == budget` 判为可接受、`low == budget` 且 `high` 更大时判为证据不足。团队可以选别的保守规则，但必须在看到候选数字之前固定。对照[定义 1.7.2](ch01.md#def-1.7.2)。
:::

:::

## 第二组 · 结论卡（说清前提与范围）

::: ex 卡 9 · 断言不是证据 {#rc-9}

卡面：「断言通过了，所以计算真的发生了」——这句话对吗？

::: sol 核对

不对。断言检查的是声明，不是意图：如果期望值由被测实现自己算出，或断言发生在计时边界之外，它既不能证明工作发生，也不能证明工作正确。要证明「真的算了」，得看汇编/IR 里累加还在，或让结果进入被核对的观察槽位。对照[例 1.1.1](ch01.md#ex-1.1.1)。
:::

:::

::: ex 卡 10 · 屏障的方向 {#rc-10}

卡面：只把输入 `black_box` 包住，能防住 DCE 吗？为什么？

::: sol 核对

不能。输入屏障只让编译器无法利用输入的具体值，读取会发生；但返回值仍然没人使用，整段纯计算照样被删。防 DCE 要靠输出侧的保活：写入数组槽位、返回、比较，或传入不透明边界。对照[定义 1.3.1](ch01.md#def-1.3.1)。
:::

:::

::: ex 卡 11 · 描述符不是数据 {#rc-11}

卡面：`black_box(&slice)` 保证 slice 的元素被读了吗？

::: sol 核对

没有。它藏住了指针与长度，优化器仍可证明「这些元素没人用」，于是一次都不读。要保数据，就得让元素的值进入被观察的结果（如逐项累加后保活结果）。对照[例 1.3.1](ch01.md#ex-1.3.1)。
:::

:::

::: ex 卡 12 · 空循环扣噪 {#rc-12}

卡面：「跑一个空循环，再从结果里减掉它的耗时」为什么不可靠？

::: sol 核对

工作被删掉之后，代码形态和执行路径都变了：空循环可能被整体消掉、可能被向量化成完全不同的结构。减法扣的是一个不对应任何真实路径的常数。正确做法是说明共同夹具包含什么，而不是虚构一个完美的去噪过程。对照[例 1.2.1](ch01.md#ex-1.2.1)。
:::

:::

::: ex 卡 13 · 跨零不等于等速 {#rc-13}

卡面：差值区间跨零，能写什么、不能写什么？

::: sol 核对

能写：本次运行内方向不可判定；当前证据不足以支持「某个实现更快」。不能写：两者等速、语言级的实现无差别、生产环境也不会差。要说「在容差内等价」，必须预先给出 `B` 并让区间整体落在内。对照[例 1.6.1](ch01.md#ex-1.6.1)。
:::

:::

::: ex 卡 14 · 区间的边界 {#rc-14}

卡面：bootstrap 区间覆盖了哪一层不确定性？两处前提是什么？

::: sol 核对

只覆盖「本次运行内的抽样波动」。前提一是差值可交换（没有明显时间相关性，否则区间偏窄）；前提二是不含编译器版本、机器与跨时段差异。跨环境结论要靠独立重跑，不是把区间算得更长。对照[定义 1.6.2](ch01.md#def-1.6.2)。
:::

:::

::: ex 卡 15 · 比值的陷阱 {#rc-15}

卡面：什么时候可以用比值/加速比，什么时候不能用？

::: sol 核对

只在两个语义等价的实现之间用，并说清平均方式（平均比值通常不等于两组均值的比值）。基线接近零时比值发散，不能用它跨语义比较——observed 除以 discarded 的 3600 倍，量的是「被删掉的工作」，不是任何算法的加速。对照[例 1.4.2](ch01.md#ex-1.4.2)。
:::

:::

::: ex 卡 16 · 采样不替代计时 {#rc-16}

卡面：`sample` 的调用栈能证明什么、不能证明什么？

::: sol 核对

能有限度地证明「相应工作确实在运行」（栈上出现了目标函数）。不能给出 cache miss、IPC、能耗，也不该当成稳定态 CPU 百分比——采样覆盖了预热与正式循环的混合阶段。没采到的指标不能出现在结论里。对照[1.8 采样没有替代计时](ch01.md#sec-cpp-rust.1.1.8)。
:::

:::

## 第三组 · 第一行卡（只写第一步）

这一组练的是「一离开答案不知道第一行写什么」那个毛病。每题只写第一行动作，不计算。

::: ex 卡 17 · 数字异常小 {#rc-17}

卡面：拿到 0.00002 ns/元素，第一行写什么？

::: sol 核对

第一行：先问「结果进入了谁的观察集合」，去汇编里找 `mov x0, #0; ret` 这类只剩常量的形态；不要先解释成算法快。
:::

:::

::: ex 卡 18 · 数字异常大 {#rc-18}

卡面：结果比预期慢一个量级，第一行写什么？

::: sol 核对

第一行：核对计时边界与构建类型——是不是 debug 构建、断言或校验进了区间、`K`/`N` 是否进了分母。先查单位与边界，再谈性能。
:::

:::

::: ex 卡 19 · 要比较两个实现 {#rc-19}

卡面：第一行写什么？

::: sol 核对

第一行：写下实验契约四组问题，并声明「两者做的是同一件工作」的条件（输入、语义、输出观察点）。条件不等价就没有可比性。对照[定义 1.6.1](ch01.md#def-1.6.1)。
:::

:::

::: ex 卡 20 · 要设性能门禁 {#rc-20}

卡面：第一行写什么？

::: sol 核对

第一行：写下预算 `B` 及其来源（业务余量、配额、SLA），单位和统计量一致，并注明内存与正确性是并列约束。数字还没测，`B` 必须先在纸上。对照[定义 1.7.1](ch01.md#def-1.7.1)。
:::

:::

::: ex 卡 21 · 怀疑有漂移 {#rc-21}

卡面：第一行写什么？

::: sol 核对

第一行：按 `position` 分组看均值差，再算前 7 轮与后 7 轮均值与批间 sd 比较——先看能不能分辨，再决定说什么。检测不到 ≠ 不存在。
:::

:::

::: ex 卡 22 · 想删慢批 {#rc-22}

卡面：第一行写什么？

::: sol 核对

第一行：写下「支持这是外部干扰的独立证据是什么」。写不出来就不删；有证据则整对删除并同时报告含与不含两种结果。
:::

:::

::: ex 卡 23 · 别人复现失败 {#rc-23}

卡面：第一行写什么？

::: sol 核对

第一行：判定属于五层里的哪一层（构建 / 功能 / 采集 / 解释 / 统计），只报告那一层的现象，性能字段留空。
:::

:::

::: ex 卡 24 · 写发布结论 {#rc-24}

卡面：第一行写什么？

::: sol 核对

第一行：搭句子骨架「在〔条件〕下，〔对象〕的〔指标〕是〔数值 + 不确定度〕，本结论不覆盖〔限制〕」，再往里填数。
:::

:::
