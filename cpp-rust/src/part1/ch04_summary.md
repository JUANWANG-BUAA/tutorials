# 第四章 · 全章总结

这一页只回答一件事：**九节各留下了什么可带走的判断。**证明、MIR 摘录、计时表和产物路径都在[正文](ch04.md)，这里把每条结论压成一句能背走的句子。合上正文再读这页，读不下去的那一行就是断点。

## 九节一览

| 节 | 留下的结论 | 破坏它的最快方式 |
|:--|:--|:--|
| [4.1](ch04.md#sec-cpp-rust.1.4.1) | 一个判断属于三层里的哪一层，才谈得上取哪份产物：语言管责任，表示管状态，机器管搬运 | 拿「汇编里没看到复制」去否认移动语义 |
| [4.2](ch04.md#sec-cpp-rust.1.4.2) | 类型检查之后的隐式调整省不掉；本机 nightly 不可用，HIR 与 THIR 只有文档证据 | 设那个环境变量跑一份转储，冒充稳定版本机产物 |
| [4.3](ch04.md#sec-cpp-rust.1.4.3) | 「未初始化」是前向数据流事实：读取要「必定初始化」，析构责任看「可能未初始化」 | 把它读成「内存里的位是垃圾」，再用 raw pointer 把移走的位置读回来 |

| [4.7](ch04.md#sec-cpp-rust.1.4.7) | 查询记忆化、增量编译、Cargo 最新判断是三个家，都在构建期 | 看到 `target/` 目录就声称增量命中 |
| [4.8](ch04.md#sec-cpp-rust.1.4.8) | 六个入口共用一份夹具；定位回归按业务一致、工作留存、批次支持、机制解释四步走 | 把批 p99 写成请求 p99，把目录锁称作操作系统级隔离 |

## 一条主线

**先选层 → 再取产物 → 再核对工作与数字 → 最后按顺序归因。**

4.1 把「哪一层能说什么」定下来，并给出五步的层选择流程；4.2 补上「类型检查之后」那层为什么省不掉，同时如实写下本机拿不到转储。4.3–4.4 进入有真实产物的那一层：初始化集合管读取与责任，四类情形与 cleanup 边管「静态定不下来时机器上留什么」。4.5–4.6 用两个已执行的 benchmark 把责任、状态、搬运拆开计量——一个测复制成本，一个测析构状态成本。4.7 把查询缓存、增量缓存与代码生成单元放回构建期。4.8 收尾于「别人怎么复核」：共享夹具、校验强度、分位数含义与四步归因顺序。

任何一环跳过去，后面的数字与汇编片段都只是修辞。

## 能否讲出这几句话

不看书，用自己的话回答。答不上来的，回到对应小节只看那一段。

1. 分层证据的三层各是什么？为什么说「前一层约束后一层，但不唯一决定后一层」？
2. 移动一个 `Vec` 时，语言层要求什么、MIR 记录什么、机器层可能留下什么？三层为什么不能互相顶替？
3. 「未初始化」为什么既不是内存位模式，也不是运行时错误？读取和析构责任分别看哪个集合？
4. 四类析构情形里哪两类可能需要动态状态？为什么「每个变量一个 flag」只是上界模型？
5. clone 分支那两个批均值的差能说什么、不能说什么？为什么方向还需要第二条证据？
6. 尺寸同为 8 字节的 `Option` 写法为什么代码不同？构建期那三个家分别是什么，为什么都不进运行期的表？
