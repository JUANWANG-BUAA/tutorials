## 内存布局

| 需求 | 第一选择 | 要注意 |
|:--|:--|:--|
| 和 C 共享布局 | `#[repr(C)]` | 字段顺序固定，但仍有填充；用 `offset_of!` 核对 |
| 节省枚举标签 | niche 优化 | 只对编译器能找到非法位模式的类型生效 |
| 扫描热字段 | SoA | 热字段连续，冷字段另放；不要盲目拆散所有结构体 |
| 指定对齐 | `#[repr(align(N))]` | 对齐会增加尺寸和分配压力 |
| 批量小对象 | Arena | 生命周期必须一致；reset 时不能有存活借用 |
| 避免伪共享 | 把热点分开到不同缓存行 | 本机缓存行 128 字节，不是所有平台都如此 |
| 观察布局 | `std::mem::size_of` / `align_of` / `offset_of!` | 本机结果不是跨平台 ABI 承诺 |

正文：[1.2.1](../part1/ch02.md#sec-cpp-rust.1.2.1) 到 [1.2.8](../part1/ch02.md#sec-cpp-rust.1.2.8)。

## 内存序选择

这张表只帮你选第一版；正确性仍然要用 happens-before 证明。

| 场景 | 第一选择 | 理由 |
|:--|:--|:--|
| 只统计次数，不发布数据 | `Relaxed` | 只要原子性，不需要跨线程顺序 |
| 发布一个指针或数据 | store `Release` + load `Acquire` | 发布之前的写，在读取之后可见 |
| 读改写计数器 | `AcqRel`，或 `Acquire` 读 + `Release` 写 | RMW 同时承担读和写的同步责任 |
| 不确定 | `SeqCst` | 先保证正确，再测性能；不要用弱序赌运气 |
| 用 `Relaxed` 发布指针 | 不应该 | 读者可能看到指针，却看不到它指向的数据 |

正文：[2.7.2](../part2/ch07.md#sec-cpp-rust.2.7.2)。

## Profiling 命令

先确定问题，再选工具。不要因为手上有 `perf`，就拿它回答所有问题。

| 问题 | 工具 | 命令形状 |
|:--|:--|:--|
| 哪些函数在 CPU 上占时间 | Linux `perf` | `perf record -F 99 --call-graph dwarf -- ./workload` |
| 函数级采样报告 | Linux `perf` | `perf report --stdio` |
| 硬件事件计数 | Linux `perf stat` | `perf stat -e cycles,instructions -- ./workload` |
| macOS 调用栈采样 | `sample` | `sample <pid> 2 1 -file sample.txt` |
| 看 MIR / LLVM IR / 汇编 | `rustc` | `cargo rustc --release -- --emit=mir,llvm-ir,asm` |
| 火焰图 | 采样结果 + 聚合工具 | 宽度是样本比例，不是耗时 |

注意：`perf` 的 PMU 事件需要权限和硬件支持；`sample` 的栈计数不是 cache miss。正文：[4.13.3](../part4/ch13.md#sec-cpp-rust.4.13.3) 到 [4.13.7](../part4/ch13.md#sec-cpp-rust.4.13.7)。

## 诊断决策树

| 症状 | 先排除 | 再查 |
|:--|:--|:--|
| 数字好得不真实 | DCE、常量折叠、分母错误 | 工作核是否读取输入、输出是否被观察 |
| 数字抖动很大 | 预热不足、批太小、后台负载 | 配对、交替顺序、增加独立运行 |
| 单线程很快，多线程不涨 | 伪共享、锁争用、内存带宽 | 缓存行布局、临界区长度、NUMA |
| 异步程序吞吐低 | `poll` 阻塞、队列无界、worker 太少 | 阻塞调用、背压、公平性 |
| 子进程卡住 | 管道写满、没有双路排空 | stdout/stderr 读取、超时、kill/wait |
| 跨语言崩溃 | ABI 不匹配、panic 越过边界、所有权混乱 | `repr(C)`、句柄、`catch_unwind`、释放责任 |
| 生产慢但本地复现不了 | 输入分布、并发度、系统调用 | 请求级采样、真实负载、资源上限 |
