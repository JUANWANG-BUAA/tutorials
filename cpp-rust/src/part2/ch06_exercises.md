# 第6章 · 习题集

共 19 题，分三组。**A 组概念**检验你能否说出名词指的是什么；**B 组推理**检验你能否从产物或数字推出结论；**C 组实操**要求你真的跑命令、读归档、写结论。全部题目附解答，难题另附提示层。

用法约定：先写下自己的答案，再展开核对。看解答时只看第一行就停住，问自己「接下来那一步是不是我要走的」，再往下读。直接通读解答，得到的只是「看懂了」，不是「会做了」。

## A 组 · 概念（1–7）

::: ex A1 · 两道门各问什么（主线 ①） {#ex-6.A.1}

优化依据指什么？合法性判断与成本判断各回答哪个问题？为什么「源码写法可以向量化」永远只是必要条件？

::: sol 解答

优化依据是后端可以据以改写代码的**可证明事实**，不是对常见情形的猜测。合法性问「这样改写会不会改变合法输入的可观察行为」，靠语言语义、引用契约与循环结构回答；成本问「这样改写值不值」，靠目标向量能力、调用边界和循环规模回答。两者都可能否决一次向量化，所以「能向量化」只是必要条件。对照[定义 6.1.1](ch06.md#def-6.1.1) 与[定义 6.1.3](ch06.md#def-6.1.3)。

:::

:::

::: ex A2 · 别名与冲突访问（主线 ①） {#ex-6.A.2}

两个只读指针指向同一块内存，妨碍优化吗？优化器真正需要知道的是什么？noalias 与 readonly 各自把这个判断写成了什么形式？

::: sol 解答

不妨碍很多读取优化。真正危险的是**冲突访问**：一个写入会改变另一个读取的来源。优化器需要的是「有没有冲突访问」，不是「有没有别名」。本轮 IR 里 output 形参带 noalias（经这个指针的写入不会与同批其他带标记的指针冲突），input 带 readonly（经由这个指针不写）。两者都来自 Rust 的借用契约，不是程序员口头承诺。对照[定义 6.2.1](ch06.md#def-6.2.1) 与[定义 6.2.2](ch06.md#def-6.2.2)。

:::

:::

::: ex A3 · 长度一致的两种语义（主线 ②） {#ex-6.A.3}

「长度不等时 panic」与「按较短一侧截断」有什么区别？为什么删掉断言之后，两个版本不能进同一张性能表？

::: sol 解答

前者让多余元素使程序拒绝执行，后者会少算尾部——是两个函数，不是同一个函数的快慢版。契约要求在进入循环之前断言等长，因为比较的双方必须算同一件事；语义没定下来之前测出的数字没有对象。对照[定义 6.3.1](ch06.md#def-6.3.1)。

:::

:::

::: ex A4 · 完整数据通路与期望值（主线 ①） {#ex-6.A.4}

`vectorize` 的批计时区间里依次发生哪三件事？`expected` 由谁算出、为什么必须独立于两个 case？

::: sol 解答

`output.fill(0)` → 配对读取与加法 → 输出求和（`borrowed_sum`）。`expected` 由 `input.iter().copied().fold(0, u64::wrapping_add)` 独立算出，两个 case 共用同一个值。若让期望值来自其中一个 case，断言就只会验证错误目标。对照[定义 6.4.1](ch06.md#def-6.4.1) 与[定义 6.4.2](ch06.md#def-6.4.2)。

:::

:::

::: ex A5 · 三件容易被混称的事（主线 ①） {#ex-6.A.5}

`const fn`、常量传播、Miri 各是什么？各自失败时会看到什么现象？

::: sol 解答

`const fn` 只是「有资格参与常量求值」的函数声明，普通运行时调用仍可作为普通函数执行。常量传播是优化器把已知常量沿数据流推进的成本决策，不做也没错。Miri 是 `cargo miri test` 这类工具运行，检查真正跑到的路径上的 UB。常量上下文算不出来是构建失败（E0080）；常量传播不生效什么也不报；Miri 不跑就没有结果可报。对照[定义 6.5.1](ch06.md#def-6.5.1)、[定义 6.5.2](ch06.md#def-6.5.2)、[定义 6.5.4](ch06.md#def-6.5.4)。

:::

:::

::: ex A6 · 放置时机与穷举验证（主线 ④） {#ex-6.A.6}

`static_table` 与 `rebuild_table` 差在哪一行？「穷举验证」为什么比单一 checksum 强，本章的定义域多大？

::: sol 解答

`rebuild_table` 的闭包里多一句 `let table = runtime_table();`，构造与查表都在计时内。穷举验证把整个定义域逐一算一遍并与参考实现比较，位置错误不会在求和里互相抵消。本章定义域是 0..=255，共 256 个输入，参考值是 `count_ones`，结果范围 0 到 8。对照[定义 6.6.1](ch06.md#def-6.6.1) 与[定义 6.6.2](ch06.md#def-6.6.2)。

:::

:::

::: ex A7 · 提示、编译单位与节大小（主线 ②） {#ex-6.A.7}

inline 属性属于哪一类标注？CGU 改变的是什么、不改变什么？`__text` 字节数能支持哪句话？

::: sol 解答

inline 属优化提示，影响决策权重，不构成接口承诺，最终要看产物。CGU 是 rustc 切给后端并行处理的单位，改变优化可见范围与构建并行度，不是运行时线程数。`__text` 是 Mach-O 里存放机器指令的节，本机用 `size -m` 读取，报的是静态尺寸：能说「产物变小了」，不能单独说「某个负载变快了」。对照[定义 6.7.1](ch06.md#def-6.7.1)、[定义 6.7.3](ch06.md#def-6.7.3)、[定义 6.7.4](ch06.md#def-6.7.4)。

:::

## B 组 · 推理（8–14）

::: ex B8 · 0.376540 能撑起哪句话（主线 ③） {#ex-6.B.8}

`zip` 均值 0.347104、`calls` 均值 0.723644，差 0.376540 ns/元素。这个差是配对差值吗？能写「差 0.376540，所以显著」吗？能写「一次 `u64` 加法要 0.347104 ns」吗？

::: hint 提示

先问这个差是按列相减还是按轮相减；再问单位里的分母是谁。

:::

::: sol 解答

不是配对差值，而是两组均值之差；要得到配对差值与区间必须按轮相减，本轮归档没有把这一对差值的区间作为结论给出，所以只能用它说明量级，不能写「显著」。也不能把 0.347104 ns/元素 当单次加法成本：它是完整通路的批均值，含 `output.fill(0)`、向量主体、标量路径与 checksum 读取。对照[例 6.4.1](ch06.md#ex-6.4.1)。

:::

:::

::: ex B9 · 11.5 倍是哪个问题的答案（主线 ②） {#ex-6.B.9}

1.953818 / 0.169413 ≈ 11.5。三种说法：①「查表比 popcount 快 11.5 倍」；②「每批重建这张 256 字节表，让本用例的归一化成本约高出 11.5 倍」；③「表越大，倍数越夸张」。哪一条成立、各缺什么？

::: sol 解答

只有②成立，且要带口径：单位 ns/字节、输入是全域 256 个字节值、样本是 21 个批均值，时间含构造与查表两段。①错在问题错位——两个 case 都在查表，`count_ones` 只出现在参考值计算里，从未计时。③是外推：本节受控外推只支持「这个 256 字节全域输入下复用更便宜」。对照[例 6.6.1](ch06.md#ex-6.6.1)。

:::

:::

::: ex B10 · 「4 条指令开销」怎么处理（主线 ①） {#ex-6.B.10}

评审报告写：「`calls` 的回退主要来自 `call` 指令本身的 4 条指令开销。」按本章你要求它补什么？在补上之前能说什么？

::: sol 解答

先要求出示指令级证据：本轮没有采集指令退休数或 PMU 事件，「4 条指令」是推测。能说的只有产物里保留了逐元素调用、以及总体成本方向与代码生成一致；循环宽度、寄存器使用、读写交错也都不同，不能把差值归成裸 call 延迟。缺的那一层就写「没有采集」。对照[例 6.4.1](ch06.md#ex-6.4.1)。

:::

:::

::: ex B11 · 有 vector.body 这个名字（主线 ①） {#ex-6.B.11}

有人主张：IR 里出现 `vector.body` 这个块名，说明自动向量化已经跑起来了，不必再看汇编。这个前提哪里容易被绕过？正确的动作是什么？

::: sol 解答

绕过它不需要改代码，只需要后端换一次决策：块名是 LLVM 生成中间结构时的命名，保留它不等于保留 SIMD——第 5 章观察到的正是只有名为 `vector.body` 的标量展开。正确动作是回到目标码找成组的 `ldp`、`add.2d`、`stp`，并确认同一函数还包含标量尾部与长度断言失败路径，避免只摘主体。对照[思考 6.1.1](ch06.md#think-6.1.1)。

:::

:::

::: ex B12 · align 8 被说成 16 字节保证（主线 ①） {#ex-6.B.12}

本轮向量 load 的 align 是 8。有人说「align 8 说明这批访问按 16 字节对齐，可以直接用要求 16 字节对齐的 intrinsic」。这句话错在哪一层？要成立还缺什么？

::: sol 解答

错在把语言类型的最小对齐当成实际放置。align 8 是 `u64` 切片接口降级后的观察值，不承诺传入地址按 16 或 128 字节对齐；语言类型的最小对齐与缓存行大小也是不同概念。要用手写 intrinsic，更强对齐必须另行保证。对照[例 6.2.1](ch06.md#ex-6.2.1) 第 3 问与[定义 6.6.3](ch06.md#def-6.6.3)。

:::

:::

::: ex B13 · 测试全绿算不算向量化证据（主线 ①） {#ex-6.B.13}

0..129 的长度全部通过，逐元素与参考值一致。能否据此写「向量化路径也被验证过」？反过来，看到主体里有 `add.2d`，能否推出小输入也用它？

::: hint 提示

测试证明的是语义还是产物？两条证据链各自能说到哪一步？

:::

::: sol 解答

都不能。全部走标量路径，测试同样全绿；正确性测试证明「语义与尾部都对」，两条路径有没有真的生成、走没走，属于产物层问题，要在 IR 与目标码里看。反过来也成立：主体里有 `add.2d`，推不出小输入也用了它——同一函数还有失败路径与标量尾部。对照[思考 6.3.1](ch06.md#think-6.3.1) 与[定义 6.3.3](ch06.md#def-6.3.3)。

:::

:::

::: ex B14 · checksum 一致能否推出「可以上生产」（主线 ④） {#ex-6.B.14}

`profile-use` 输出与训练程序相同的 `95338125850705920`，16 个实例也逐个与参考函数比较通过。写「PGO 不改变程序行为，可以放心上生产」，漏了哪几步？

::: sol 解答

漏两步。第一，校验通过只覆盖这个探针的这个输入域，它是正确性证据，不是性能证据，也不是形式证明。第二，「安全上生产」还要看训练分布是否代表生产负载、profile 缺口是否影响关键函数、以及同负载的正式配对计时；本轮没有测，所以那一格是空缺而不是绿灯。另外把插桩程序的耗时拿来当收益基线也是错的，插桩本身改变了执行开销。对照[思考 6.8.1](ch06.md#think-6.8.1)。

:::

:::

## C 组 · 实操（15–19）

实验包在 `bench/compiler-lab/`，正式归档在 `results/stable-02/` 与 `results/extra-02/`。这组题要求真的动手：跑命令、读 CSV、翻 IR 与汇编、把结论写成可复核的句子。

::: ex C15 · 从零跑一遍并指出产物（主线 ④） {#ex-6.C.15}

在 `cpp-rust/` 下按 6.11 的命令跑 `fmt`、`clippy`、`test` 与 `run.sh`（用全新归档目录）。然后列出：正式 CSV 叫什么、IR 与汇编在哪、常量拒绝诊断在哪。

::: sol 参考路径

命令顺序：`cargo fmt --manifest-path bench/compiler-lab/Cargo.toml --check`；`cargo clippy --offline --locked --manifest-path bench/compiler-lab/Cargo.toml --all-targets -- -D warnings`；`cargo test --offline --locked --manifest-path bench/compiler-lab/Cargo.toml`；`bash bench/compiler-lab/run.sh bench/compiler-lab/results/my-llvm-run`；`python3 bench/compiler-lab/extra.py bench/compiler-lab/results/my-pgo-run`。正式脚本运行六个入口，不在后台并行跑一组 benchmark。产物：`vectorize.csv` 与 `ctfe_table.csv` 是正式批次，`stable-02/codegen/` 存 MIR、LLVM IR 与本机汇编，`extra-02/const_bounds.txt` 是常量拒绝诊断。参见 [6.11 复现命令](ch06.md#sec-cpp-rust.2.6.11)。

:::

:::

::: ex C16 · 两个 CSV 的最小复核（主线 ④） {#ex-6.C.16}

打开 `vectorize.csv` 与 `ctfe_table.csv`，用 3 分钟完成一次最小复核，并写下你检查了哪四项。

::: hint 提示

四项里有两项是结构（每个 case 多少观察、顺序怎么排），两项是语义（输出校验、单位反乘）。

:::

::: sol 参考路径

四项：① 每个 case 恰好 21 个原始观察；② case 顺序在批次间轮转，不是前若干批全跑一个；③ 两个 case 的批 checksum 都与同一个 `expected` 校验通过，且断言发生在时间戳之后；④ 用均值乘回输入长度，检查单位是否自洽——`vectorize` 是 ns/元素、输入 16384 个 `u64`，`ctfe_table` 是 ns/字节、输入 256 个字节值。只读表格不核对代码，复现还没完成；重跑时把新结果放进新目录，不要覆盖原归档。依据见 6.4.3 的计量表与 6.6.5。

:::

:::

::: ex C17 · 在产物里定位主体、尾部与保留调用（主线 ①） {#ex-6.C.17}

在 `stable-02/codegen/` 里找到 `add_slices` 的向量 load、`add.2d` 与 store；再确认三件事：同函数里有标量尾部与长度失败路径，`add_with_calls` 里 `scalar_add` 的调用保留，`runtime_table` 的构造循环没有消失。把每条的定位依据写下来。

::: sol 参考路径

IR 层应能读到 `%wide.load = load <2 x i64>, ptr %1, align 8`、`%8 = add <2 x i64> %wide.load10, %wide.load`、`store <2 x i64> %8, ptr %0, align 8`，以及 `%index.next = add nuw i64 %index, 8`；汇编层应能读到成组 `ldp`、四条 `add.2d`、成组 `stp` 与 `subs x11, x11, #8`。主体之外还要在同一函数里找到标量尾部与长度断言失败路径——只摘主体不能宣布小输入同样走这条路。`add_with_calls` 的产物保留逐元素直接调用；`runtime_table` 的 IR 保留逐表项循环与 bits 右移计数循环，结果经 256 字节输出位置传递。对照[例 6.3.1](ch06.md#ex-6.3.1) 与 6.6.6。

:::

:::

::: ex C18 · 换成前缀和，哪条依据先失效（主线 ①） {#ex-6.C.18}

把内核改成 `output[i] = output[i-1] + input[i]`。先预测哪几条依据失效、产物会怎么变，再说归档怎么办。不要跑出数字就写「更快」。

::: hint 提示

第 i 个元素现在读的是第 i−1 个位置刚写下的新值。成组处理会读到什么？

:::

::: sol 参考路径

失效的是「跨迭代独立」：冲突访问判断要重做，长度契约虽仍在也不够；wrapping 求和的模运算重组不再适用。本章 6.4.7 的循环形态表把前缀递推标为「未做正式实验」，浮点归约标为「未使用该类内核」。所以正确动作是重新设计夹具、重跑并新开归档，而不是在旧表上写新句子——换边界就是新实验。对照[定义 6.2.1](ch06.md#def-6.2.1) 与 6.4.7。

:::

:::

::: ex C19 · 走一遍 PGO 四阶段并交证据（主线 ④） {#ex-6.C.19}

按 `extra.py` 的 PGO 分支跑一次，然后回答：四个阶段各留下哪个文件？`llvm-profdata` 的版本输出是什么？`lang_start` 那条警告为什么不能关掉？

::: sol 参考路径

四阶段与文件：插桩构建 → `pgo-generate.txt`；执行训练 → `pgo-training-run.txt` 与 `extra-02/pgo-data/` 下的 `.profraw`；合并 → `pgo-merge.txt` 与 `merged.profdata`；使用与校验 → `pgo-use.txt`、`pgo-use-run.txt`、`pgo-size.txt`，另加 `profdata-version.txt`。版本输出应为 `23.1.1-rust-1.99.0-stable`，来自与 rustc 相同的稳定工具链目录，不能拿 Xcode 里另一个同名程序冒充。`-pgo-warn-missing-function` 报出 `lang_start` 包装函数缺少 profile，含义是「训练覆盖或匹配有缺口」，不是编译失败；关掉它只是把已知局限藏起来。对照[例 6.8.1](ch06.md#ex-6.8.1) 与[定义 6.8.3](ch06.md#def-6.8.3)。

## 批改时最常给的三条意见

1. **跨层引用**：拿 IR 里的向量类型说本机 SIMD，拿节大小说延迟，拿 checksum 说收益。先补一句「这句话属于哪一层」，再决定能不能写。
2. **口径缺项**：写 ns/元素 不说含 `fill(0)` 与 checksum，写 11.5 倍不说输入域与构造成本，写 p99 不说只有 21 个批值。数字后面必须跟着集合。
3. **把未采写成已通过**：Miri 没跑、速度没测、构建时间没比，就在结论里明写「本章没有采集」，不要用一个看起来合理的替代品填格。
