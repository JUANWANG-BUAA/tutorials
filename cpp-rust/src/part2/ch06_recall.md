# 第6章 · 闭卷回忆卡

「看懂」只说明答案在眼前时能识别；写代码评审或回答同事时，需要的是从空白纸上提取。这一页把第六章拆成 24 张卡，每张卡先看卡面自己答，再展开核对。

**用法与节奏**

| 时点 | 做什么 | 判定 |
|:--|:--|:--|
| 学完当天 | 第一组「定义卡」全部 8 张 | 说全术语与前提才算 ✓ |
| 第 1 天 | 第二组「结论卡」全部 8 张 | 说清适用范围才算 ✓ |
| 第 3 天 | 第三组「第一行卡」全部 8 张 | 写出第一步动作才算 ✓ |
| 第 7 天 | 只重做标成 △ 和 × 的卡 | 全对即可进入第 7 章 |

每张卡给自己一个记号：✓ 一次说对；△ 说对一半或要提示；× 想不起来。只重做 △ 和 ×，不要把整叠卡反复过一遍——那是在读，不是在提取。

## 第一组 · 定义卡（说全称与前提）

::: ex 卡 1 · 优化依据与两道门 {#rc-06-1}

卡面：优化依据指什么？合法性与成本各问什么、各举一个本章的否决理由。

::: sol 核对

优化依据是后端可以据以改写的**可证明事实**，不是对常见情形的猜测。合法性问「改写会不会改变合法输入的可观察行为」，否决理由如可能存在跨迭代冲突；成本问「改写值不值」，否决理由如调用边界把元素操作隔在保留调用后面。两者都过才有向量化。对照[定义 6.1.1](ch06.md#def-6.1.1) 与[定义 6.1.3](ch06.md#def-6.1.3)。
:::

:::

::: ex 卡 2 · 四层产物 {#rc-06-2}

卡面：一份源码留下哪四层可核对的产物？每层只支持哪句话？

::: sol 核对

MIR（语言层控制流与析构责任）、LLVM IR（低层类型、属性与循环）、本机汇编（指令选择与保留的调用）、运行计时（本机桌面环境中的总体效果）。跨层引用必须说明证据来自哪一层。对照[定义 6.1.4](ch06.md#def-6.1.4)。
:::

:::

::: ex 卡 3 · 冲突访问与内部可变性 {#rc-06-3}

卡面：别名与冲突访问的区别是什么？为什么元素类型能推翻「共享引用绝不变」？

::: sol 核对

别名指两个名字能指到同一块内存；冲突访问指一个写入会改变另一个读取的结果。优化器要的是「有没有冲突访问」。`UnsafeCell` 与 `Cell` 让共享引用下也能修改内容，所以「全程不变」必须先看元素类型，不能只看引用形式。对照[定义 6.2.1](ch06.md#def-6.2.1) 与[定义 6.2.3](ch06.md#def-6.2.3)。
:::

:::

::: ex 卡 4 · 三个参数属性 {#rc-06-4}

卡面：本轮 IR 里 noalias、readonly 各挂在哪个形参上？对齐观察值是多少、它不承诺什么？

::: sol 核对

output 形参带 noalias，input 形参带 readonly，两者的对齐观察都是 8。8 来自 `u64` 切片接口降级，不承诺 16 或 128 字节对齐。对照[定义 6.2.2](ch06.md#def-6.2.2) 与[例 6.2.1](ch06.md#ex-6.2.1)。
:::

:::

::: ex 卡 5 · 长度一致契约 {#rc-06-5}

卡面：契约要求函数在进入循环前做什么？删掉断言只留 zip 得到的是什么？

::: sol 核对

先 `assert_eq!(output.len(), input.len())`，不等就 panic。删掉断言只留 zip 得到的是**另一个函数**：它按较短一侧静默截断，会少算尾部，不是「更快的同一个函数」。对照[定义 6.3.1](ch06.md#def-6.3.1)。
:::

:::

::: ex 卡 6 · 保留调用边界 {#rc-06-6}

卡面：什么叫保留调用边界？由哪一层判定，不靠什么？

::: sol 核对

编译产物里确实存在一次 `call`，被调函数的体没有并进调用方。它由本机汇编一层判定，不靠源码上写没写 `#[inline(never)]`——属性只是提示。对照[定义 6.3.2](ch06.md#def-6.3.2)。
:::

:::

::: ex 卡 7 · 向量主体与标量尾部 {#rc-06-7}

卡面：主体一次推进几个元素？为什么「主体向量化」不等于「所有输入都走 SIMD」？

::: sol 核对

本轮一次主体迭代推进八个元素。标量尾部处理长度不足一个主体的剩余部分，两者是同一函数的不同分支；长度 7 的输入走不到主体。对照[定义 6.3.3](ch06.md#def-6.3.3)。
:::

:::

::: ex 卡 8 · CTFE 与常量传播 {#rc-06-8}

卡面：各用一句话定义，并说出失败方式的差别。

::: sol 核对

CTFE 指常量上下文（`const` 项、`static` 初始化器、数组长度、泛型常量参数）要求编译器在构建期把表达式算成一个值，算不出来就编译失败。常量传播是优化器把已知常量沿数据流推进、顺带算掉部分表达式，属成本决策，不做也没错。对照[定义 6.5.1](ch06.md#def-6.5.1) 与[定义 6.5.2](ch06.md#def-6.5.2)。
:::

:::

## 第二组 · 结论卡（说清前提与范围）

::: ex 卡 9 · 完整数据通路 {#rc-06-9}

卡面：计时区间里的三段是什么？它相对「只测内核」与端到端各自多了或少算什么？

::: sol 核对

`output.fill(0)` → 配对读取与加法 → 输出求和（`borrowed_sum`）。相对只测内核，它多含初始化与观察工作；相对端到端吞吐，它少了 Vec 创建。所以写 ns/元素 必须同时说清这个集合。对照[定义 6.4.1](ch06.md#def-6.4.1)。
:::

:::

::: ex 卡 10 · 0.376540 的来历 {#rc-06-10}

卡面：这个差值按表怎么算出来？它是配对差值吗？能说到哪一步？

::: sol 核对

按两列均值直接相减：0.723644 − 0.347104 = 0.376540 ns/元素，是**两组均值之差**。要得到配对差值及其区间，必须按轮相减；本轮归档没有把这一对的区间作为结论给出，所以只用它说明量级，不写「显著」。对照[例 6.4.1](ch06.md#ex-6.4.1)。
:::

:::

::: ex 卡 11 · 11.5 倍属于哪个问题 {#rc-06-11}

卡面：1.953818 / 0.169413 ≈ 11.5 说明什么？三种常见误读各错在哪？

::: sol 核对

说明「每批重建这张 256 字节表，让本用例的归一化成本约高出 11.5 倍」，单位 ns/字节，含构造与查表两段。误读一「查表比 popcount 快 11.5 倍」：两个 case 都在查表，count_ones 只算参考值、没有计时。误读二「表越大倍数越夸张」：属外推。对照[例 6.6.1](ch06.md#ex-6.6.1)。
:::

:::

::: ex 卡 12 · 穷举验证 {#rc-06-12}

卡面：本章的定义域多大？参考值是什么？它比单一 checksum 强在哪？

::: sol 核对

定义域 0..=255 共 256 个输入，全部覆盖；参考值是 `count_ones`，结果范围 0 到 8，没有近似误差。它比单一 checksum 强，因为位置错误不会在求和里互相抵消。对照[定义 6.6.2](ch06.md#def-6.6.2)。
:::

:::

::: ex 卡 13 · Miri 与 CTFE 的覆盖 {#rc-06-13}

卡面：两者共享什么技术？覆盖对象差在哪？本轮为什么不填这一格？

::: sol 核对

都建立在 MIR 解释之上。CTFE 只求值常量上下文；Miri 把（通常未优化的）程序交给解释器执行，检查越界、悬垂、数据竞争等 UB。本轮没有执行 `cargo miri test`，nightly 安装也不可用，所以测试列表里那一格写「没有执行」。对照[定义 6.5.4](ch06.md#def-6.5.4)。
:::

:::

::: ex 卡 14 · inline 是提示 {#rc-06-14}

卡面：`#[inline(never)]` 能保证什么、不能保证什么？「没被内联」推得出「函数体原样编译」吗？

::: sol 核对

它是优化提示，不是接口承诺；本轮 `scalar_add` 的调用确实被保留，要回目标码确认。推不出：边界保留与体内优化互相独立，`visible_dynamic` 的调用边界被保留，但它内部的 dyn 来源仍能被消解。对照[定义 6.7.1](ch06.md#def-6.7.1) 与[定义 6.7.2](ch06.md#def-6.7.2)。
:::

:::

::: ex 卡 15 · CGU 与三种目标 {#rc-06-15}

卡面：CGU 是什么、不是什么？尺寸、构建时间、延迟各要什么证据？

::: sol 核对

CGU 是 rustc 把程序切分给后端并行处理的单位，`codegen-units=1` 扩大局部视野但可能减少构建并行；它不是运行时线程数量设置。尺寸要静态节大小，构建时间要构建矩阵，延迟要同负载的正式配对测量，三者不能用一张表回答。对照[定义 6.7.3](ch06.md#def-6.7.3) 与[思考 6.7.1](ch06.md#think-6.7.1)。
:::

:::

::: ex 卡 16 · PGO 是构建输入 {#rc-06-16}

卡面：插桩式与采样式 PGO 各靠什么产生数据？本轮归档必须留下哪些文件？

::: sol 核对

插桩式在编译时插入计数代码，真跑一遍写出 `.profraw`（本轮走这条）；采样式依赖外部监控设施抓取栈与事件，macOS `sample` 的文本格式不能直接交给 `-Cprofile-use`。`.profraw` 与 `merged.profdata` 都要留在归档里，只保存最后的二进制等于丢掉流程输入。对照[定义 6.8.1](ch06.md#def-6.8.1) 与[定义 6.8.2](ch06.md#def-6.8.2)。
:::

:::

## 第三组 · 第一行卡（只写第一步）

这一组练的是「离开答案就不知道第一行写什么」那个毛病。每题只写第一行动作，不做判断。

::: ex 卡 17 · 只有一行向量加法 {#rc-06-17}

卡面：同事贴来 `add <2 x i64>`，问「SIMD 用上了吧」，第一行写什么？

::: sol 核对

第一行：先问这句属于哪一层——它只支持「本轮 IR 中存在向量加法」。要看目标码里的 `add.2d` 与成组 `ldp`／`stp` 才谈得上 SIMD。对照[例 6.1.1](ch06.md#ex-6.1.1)。
:::

:::

::: ex 卡 18 · 要给出裸指针的代价 {#rc-06-18}

卡面：有人要「去掉引用换裸指针会慢多少」的数字，第一行写什么？

::: sol 核对

第一行：写下「本节没有采集」——本轮没有构造 raw pointer 对照，也没有对应正式批次，任何数字都是外推。可以讲机制（运行时重叠检查），不给百分比。对照 6.2.6 的判定流程。
:::

:::

::: ex 卡 19 · p99 被当成尾延迟 {#rc-06-19}

卡面：报告写「p99 = 0.378854 就是尾延迟」，第一行写什么？

::: sol 核对

第一行：数样本——21 个批值上 `ceil(21 × 0.99) = 21`，这个 p99 就是最大批值，只表示批次间波动。请求级尾延迟要逐请求观测，本章没有采集。对照[例 6.4.1](ch06.md#ex-6.4.1) 第 3 问。
:::

:::

::: ex 卡 20 · 编译通过被写成 Miri 通过 {#rc-06-20}

卡面：PR 描述写「cargo test 通过，无 UB」，第一行写什么？

::: sol 核对

第一行：把三件事分栏——编译期事实、运行时观察、工具结论。没有运行 `cargo miri test` 就不能声称无 UB，那一格写「没有执行」并说明 nightly 不可用。对照[思考 6.5.1](ch06.md#think-6.5.1)。
:::

:::

::: ex 卡 21 · 静态表更快要全局默认 {#rc-06-21}

卡面：同事说「改 static 表后快 11 倍，建议全局默认」，第一行写什么？

::: sol 核对

第一行：问口径——这个倍数在哪个输入域、含不含构造成本。第二问才是表值在请求之间是否真的恒定、配置更新时版本与生命周期怎么处理。对照[例 6.6.1](ch06.md#ex-6.6.1) 与 6.6.7。
:::

:::

::: ex 卡 22 · 节变小被当成变快 {#rc-06-22}

卡面：报告写「ThinLTO 让 `__text` 小 5388 字节，所以更快」，第一行写什么？

::: sol 核对

第一行：问有没有正式速度样本——本轮两个构建都对 16 个实例做了输出校验，但没有采样运行时间，只能报静态尺寸。`__text` 不含 `__PAGEZERO` 保留量，也不等于 I-cache 工作集。对照[例 6.7.1](ch06.md#ex-6.7.1)。
:::

:::

::: ex 卡 23 · 要写 PGO 结论 {#rc-06-23}

卡面：只能拿到 `pgo-use` 二进制与一行 checksum，第一行写什么？

::: sol 核对

第一行：列出缺的证据链——`pgo-generate.txt`、`pgo-training-run.txt`、`.profraw` 与 `merged.profdata`、`pgo-merge.txt`、`pgo-use.txt`、`profdata-version.txt`。缺一件，「四步已完成」就得降级。对照[例 6.8.1](ch06.md#ex-6.8.1)。
:::

:::

::: ex 卡 24 · 怀疑慢侧被优化掉 {#rc-06-24}

卡面：对照里慢的一侧会不会其实没做事？第一行写什么？

::: sol 核对

第一行：查三处——`seed` 是否经 `black_box` 处理、IR 与目标码里构造循环与表写入是否仍在、`expected` 是否由独立参考算出并逐批校验。还缺的一维是冷加载，本轮没有测。对照[思考 6.6.1](ch06.md#think-6.6.1)。
:::

:::
