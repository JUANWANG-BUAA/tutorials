# 第七章 · 闭卷回忆卡

「看懂」只说明答案在眼前时能识别；评审和答辩时需要的是从空白纸上提取。这一页把第七章拆成 22 张卡，每张卡先写卡面问题，合上正文自己答，再展开核对。

**用法与节奏**

| 时点 | 做什么 | 判定 |
|:--|:--|:--|
| 学完当天 | 第一组「定义卡」8 张 | 三条件、两层条件、八条义务逐条写全才算 ✓ |
| 第 1 天 | 第二组「结论卡」7 张 | 说清前提与边界才算 ✓ |
| 第 3 天 | 第三组「第一行卡」7 张 | 写出第一步动作才算 ✓ |
| 第 7 天 | 只重做标成 △ 和 × 的卡 | 全对即可进入第八章 |

每张卡给自己一个记号：✓ 一次说对；△ 说对一半或要提示；× 想不起来。只重做 △ 和 ×，不要把整叠卡反复过一遍——那是在读，不是在提取。

## 第一组 · 定义卡（说全称与前提）

::: ex 卡 1 · 冲突访问与数据竞争 {#rc-7-1}

卡面：写出冲突访问的两个条件、数据竞争的第三个条件，并说明「读到旧值」为什么不是它的同义词。

::: sol 核对

冲突访问：内存区域重叠，且至少一个是写入。数据竞争再加两条：冲突双方至少一个不是原子操作；两者之间没有 happens-before 排序（先发生，语言保证顺序）排序。三条同时成立才是数据竞争。它是 UB（未定义行为，标准不再承诺结果），不是「偶尔读到旧值」这种可以靠重试观察的温和错误。对照[定义 7.1.1](ch07.md#def-7.1.1)。
:::

:::

::: ex 卡 2 · 同步证明的三个层次 {#rc-7-2}

卡面：三层各证明什么？原子类型主要买哪一层？

::: sol 核对

第一层：对象的合法生命周期——载荷存在、已初始化、没有被提前销毁。第二层：访问互斥与可见性——谁能写、谁能读、哪条边建立同步。第三层：业务不变量——多个字段是否必须一起改变。原子类型只提供第二层的构件，不自动完成另外两层。对照[定义 7.1.2](ch07.md#def-7.1.3)。
:::

:::

::: ex 卡 3 · 修改顺序与 Relaxed {#rc-7-3}

卡面：什么是修改顺序？Relaxed 放弃的到底是什么、没有放弃什么？

::: sol 核对

对同一个原子位置的所有写入构成修改顺序：每次原子读要么读到某个完整写入，要么读到另一个完整写入，不会读到「半条」递增。Relaxed 放弃的是跨位置的排序承诺，保留的是位置内的原子性与这条修改顺序。所以「没有跨变量同步」和「值可以乱来」是两件事。对照[定义 7.2.1](ch07.md#def-7.2.1)。
:::

:::

::: ex 卡 4 · synchronizes-with 边 {#rc-7-4}

卡面：一个 Release store 与一个 Acquire load 要在什么条件下才构成这条边？边成立后可见范围是什么？

::: sol 核对

当且仅当该 Acquire load 观察到了（reads-from，值来源关系）这个 Release store 写入的值。成立时，Release 之前的所有写入对 Acquire 之后的读取可见。两个条件缺一不可：一边一个操作不算；「后来的时间点」也不算，观察关系必须是具体的值来源关系。对照[定义 7.2.2](ch07.md#def-7.2.2)。
:::

:::

::: ex 卡 5 · RMW 的两半 {#rc-7-5}

卡面：一次读改写有哪两半？Acquire、Release、AcqRel 各管哪一半？

::: sol 核对

两半是读侧（旧值被谁看到、能否释放本侧之前的访问）与写侧（新值发布什么、对方 Acquire 后才能读什么）。Acquire 只管读侧，Release 只管写侧，AcqRel 两者都要。漏写一半的后果：用 Release 递增去发布载荷，递增自身的旧值读取没有获取语义。对照[定义 7.2.3](ch07.md#def-7.2.3)。
:::

:::

::: ex 卡 6 · Send 与 Sync {#rc-7-6}

卡面：两者各转移什么？`Cell<u64>`、`RefCell<u64>`、`Rc<u64>` 各缺哪一侧？

::: sol 核对

`T: Send` 表示值的所有权可以转到另一个线程；`T: Sync` 表示共享引用 `&T` 可以转到另一个线程，强度等于「多线程同时只读是安全的」。`Cell` 与 `RefCell` 可 Send、不可 Sync；`Rc` 两者都不满足。判断时问一句：转移的是值还是 `&`。对照[定义 7.3.1](ch07.md#def-7.3.1)。
:::

:::

::: ex 卡 7 · unsafe impl Sync 的八条义务 {#rc-7-7}

卡面：默写八条。任何一条被后续修改破坏，会发生什么？

::: sol 核对

①端点唯一，无两个并发生产者；②无两个并发消费者；③消费者只在 full 状态读已初始化的 T；④生产者只在 empty 状态写；⑤两个方向都有 Release/Acquire 交接；⑥T 按值跨线程转移，要求 Send；⑦载荷不被多线程按共享引用访问，不要求 T: Sync；⑧Slot 销毁时排除所有存活端点。任何一条被破坏，整段 `unsafe impl` 失效，编译器不会重新核对。对照[定义 7.3.4](ch07.md#def-7.3.4)。
:::

:::

::: ex 卡 8 · 槽位状态机 {#rc-7-8}

卡面：写出四个状态、各自的「可访问方」，以及第五行「再次 empty」是什么。

::: sol 核对

empty：无有效 T，生产者可写；written-unpublished：有 T 但未交接，仅生产者可见；full：已发布，消费者可移出；moved-out：T 归接收者，Slot 不得再次 drop。再次 empty 是消费者发布 `false` 之后生产者取回复用权、开始下一代。协议的正确性就是证明实现不会停在表外状态。对照[定义 7.6.1](ch07.md#def-7.6.1)。
:::

:::

## 第二组 · 结论卡（说清前提与范围）

::: ex 卡 9 · 汇编相同不等于语义相同 {#rc-7-9}

卡面：代码生成证据与语义承诺各回答什么问题？为什么不能从产物倒推语义？

::: sol 核对

代码生成证据回答「这个编译器版本、这个 target、这份源码发出了什么指令」，是绑定版本的观察。语义承诺回答「任何符合标准的实现必须给出什么顺序」，跨平台成立但不指定指令。同一段 `movq` 可能来自 Acquire，也可能来自 Relaxed，指令本身不再携带源码的排序义务。对照[定义 7.4.1](ch07.md#def-7.4.1)。
:::

:::

::: ex 卡 10 · LL/SC 与 LSE {#rc-7-10}

卡面：AArch64 有哪两条 lowering 路线？选哪条由什么决定？本章给重试成本数字了吗？

::: sol 核对

LL/SC 靠独占加载与条件存储（如 `ldaxr`/`stlxr` 对），失败要重试；LSE 直接发单条原子指令（如 `ldadd` 系）。选哪条由 CPU 特性、编译器 lowering 与 outline atomic 策略共同决定，同源码在不同 target 下可以分岔。重试成本取决于竞争、监控粒度与干扰，本章没有采集其分布，只给机制不给数字。对照[定义 7.4.2](ch07.md#def-7.4.2)。
:::

:::

::: ex 卡 11 · 单变量对照组 {#rc-7-11}

卡面：什么条件下才允许把差异归因给一个因素？本章哪两对是单变量，哪一对不是？

::: sol 核对

两行的差异能唯一落在一个实验因素上时，才允许归因。本章：Shared 与 Shared-SeqCst 只差内存序；Adjacent 与 Padded 只差布局。Shared 与 Batched 同时差全局 RMW 次数与可观测语义，不构成单变量对照，只能支持「聚合减少了共享写」的机制假设。对照[定义 7.5.1](ch07.md#def-7.5.1)。
:::

:::

::: ex 卡 12 · 聚合吞吐倒数 {#rc-7-12}

卡面：写出 ns/聚合操作的算法，并解释多线程下它为什么可以小于单核一条指令的周期。

::: sol 核对

表中数值 = 批次墙钟时间 ÷（线程数 × 每线程操作数）。它回答系统整体每完成一次逻辑操作摊到多少时间，是吞吐的倒数。分母合并了并行完成的操作，所以多线程下可以小于单核一条指令的周期，这不表示处理器用更短周期执行了一条指令。对照[定义 7.5.2](ch07.md#def-7.5.2)。
:::

:::

::: ex 卡 13 · 栈观察计数与事件计数 {#rc-7-13}

卡面：sample 报告里的 826 是什么数？它能推出「锁占多少 CPU」吗？

::: sol 核对

826 是采样器每毫秒抓栈、落在主线程等待路径上的观察次数。它受线程角色、内联与符号保留方式、采样窗口影响。硬件事件计数（如缓存缺失、指令退休数）由 CPU 计数单元给出，单位是事件次数。把观察次数读成「826 纳秒在锁上」或「锁占 CPU 的百分比」，是把一种对象冒充成另一种。对照[定义 7.7.1](ch07.md#def-7.7.1)。
:::

:::

::: ex 卡 14 · 载荷标志与合并通知 {#rc-7-14}

卡面：`full` 与执行器的 notified 各是什么语义？互相套用会坏什么？

::: sol 核对

`full` 是一对一交接状态：读到 `true` 就消费一次可用载荷。notified 是可合并信号：多次 notify 可以塌缩为一次唤醒，唤醒后必须重新 poll 验证条件，仍可能 Pending。把前者套到后者，会破坏背压与取消协议；把后者套到前者，会给槽位凭空加出一条不存在的合并路径。对照[定义 7.8.1](ch07.md#def-7.8.1)。
:::

:::

::: ex 卡 15 · 进度保证的层级 {#rc-7-15}

卡面：lock-free 与 wait-free 各要求什么？更强的 Ordering 能解决 ABA 吗？

::: sol 核对

lock-free：冲突操作中至少一个线程能在有限步内推进，不依赖持锁者被调度。wait-free：每个操作自身有有限步数上界，无论竞争如何。两层都只对「被定义出来的操作集合」成立。ABA 是寿命与回收问题：指针数值重新相等不代表同一代对象，Hazard Pointer、epoch、RCU 处理的是三层证明的第一层，不是 SeqCst 的另一种拼写。对照[定义 7.8.2](ch07.md#def-7.8.2)。
:::

:::

## 第三组 · 第一行卡（只写第一步）

这一组练的是「离开答案就不知道第一行写什么」那个毛病。每题只写第一行动作，不计算。

::: ex 卡 16 · 拿到一个跨线程交接点 {#rc-7-16}

卡面：第一行写什么？

::: sol 核对

第一行：画访问图——谁读、谁写、载荷在哪些状态间转移，并逐个标记冲突访问。图没画完，不要谈锁与内存序。对照[7.1](ch07.md#sec-cpp-rust.2.7.1)的判定流程第 1 步。
:::

:::

::: ex 卡 17 · 有人说「改成 Relaxed 就能提速」 {#rc-7-17}

卡面：第一行写什么？

::: sol 核对

第一行：先问两次写是不是同一个位置、争用来自哪里。共享写热点有计算、可见性、争用、调度四个候选，内存序只占一个，且排在最后。对照[思考 7.1.1](ch07.md#think-7.1.1)。
:::

:::

::: ex 卡 18 · 要引用一张指令对照表 {#rc-7-18}

卡面：第一行问什么？

::: sol 核对

第一行：问版本与 target——这段指令来自哪个 rustc/LLVM、是产物还是网页抄录。再问跨度（指令形态还是运行期成本）与方向（解释源码还是倒推语义）。对照[7.4.7](ch07.md#sec-cpp-rust.2.7.4)的四个问题。
:::

:::

::: ex 卡 19 · 看到 0.418 对 5.980 {#rc-7-19}

卡面：第一行写什么？

::: sol 核对

第一行：查这两行之间动了几个因素、分母是什么。Padded 与 Shared 同时差布局与共享性；真正单变量的一对是 Adjacent 与 Padded（1.408 的标准差与 0.002 的反差是线索）。单位是聚合吞吐倒数，不是一次访问的延迟。对照[例 7.5.1](ch07.md#ex-7.5.1)。
:::

:::

::: ex 卡 20 · 看到 112 对 3070 {#rc-7-20}

卡面：第一行写什么？

::: sol 核对

第一行：先列接口差异——断开检测、超时、取消、多生产者、多消费者、公平性、是否声称 wait-free。两边不等价，时间比值就不能写成算法排名。对照[例 7.6.1](ch07.md#ex-7.6.1)与 7.6.8 的缺失清单。
:::

:::

::: ex 卡 21 · 报告里有 826 次等待观察 {#rc-7-21}

卡面：第一行写什么？

::: sol 核对

第一行：按线程角色分组——主线程的职责就是等工作线程完成，它在 barrier 等待中被采样很正常。不要从宽栈直接宣布锁瓶颈，也不把观察次数换算成占比。对照[定义 7.7.1](ch07.md#def-7.7.1)、7.7.4。
:::

:::

::: ex 卡 22 · 要把结论写进评审 {#rc-7-22}

卡面：第一行写什么？

::: sol 核对

第一行：搭骨架「在〔这台机器、这个构建、这组输入、这个负载〕下，〔对象〕的〔指标〕是〔数值〕；本结论不覆盖〔限制〕」，再填数。缺对象、条件、指标、限制任何一件，句子就不合格。对照[7.7](ch07.md#sec-cpp-rust.2.7.7)的归因台阶。
:::

:::
