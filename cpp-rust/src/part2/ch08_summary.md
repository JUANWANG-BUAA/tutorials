# 第八章 · 全章总结

这一页只回答一件事：**八节各留下了什么可带走的结论，收尾三节各管什么用。**
推导、产物与连线图都在[正文](ch08.md)，这里把结论压成一句能复述的话。
合上正文再读这页，读不下去的那一行就是断点。

## 八节一览

| 节 | 留下的结论 | 破坏它的最快方式 |
|:--|:--|:--|
| [8.1](ch08.md#sec-cpp-rust.2.8.1) | 调用 `async fn` 只构造一个还没算的匿名 Future；构造、提交、完成是三个时点 | 只测 Future 构造，就宣布测到了异步完成 |
| [8.2](ch08.md#sec-cpp-rust.2.8.2) | 帧里只放跨 await 存活的字段；poll 读判别值跳进对应分支，不是重跑 | 把 `variant_fields` 的编号 0/1/2/3 当成 ABI |
| [8.3](ch08.md#sec-cpp-rust.2.8.3) | 帧尺寸等于跨挂起存活集合的大小；Pin 钉地址稳定，与栈/堆正交 | 把 4097 与 2 的差说成「常驻内存省了 4095 字节」 |
| [8.4](ch08.md#sec-cpp-rust.2.8.4) | Pending 附带「将来会通知」的义务；wake 会被合并，不是完成计数 | 无新通知时紧密轮询，或按 wake 次数累计 I/O |
| [8.5](ch08.md#sec-cpp-rust.2.8.5) | 「有待检查」由驱动器自己的 `notified` 保存，park 只盖住检查与停放之间的窗口 | 用「Pending 就 park」的极简循环当生产实现 |
| [8.6](ch08.md#sec-cpp-rust.2.8.6) | 7.407 与 0.519 都是批均值/元素；差值拆出的是通知协议动作，不是 OS 切换 | 把批均值 p99 8.326 当成一次 poll 的尾延迟 |
| [8.7](ch08.md#sec-cpp-rust.2.8.7) | 8.241 与 19.817 之差归给「堆申请/释放这一对」，不是 Pin 抽象 | 把 11.6 ns 叫「malloc 税」，或删掉漂移批次只留漂亮均值 |
| [8.8](ch08.md#sec-cpp-rust.2.8.8) | 取消是生命周期事件：`Drop` 清理字段，不回滚已提交的外部副作用 | 超时只丢 Future，以为子进程与两路管道会自己收尾 |

## 一条主线

**先把 async 还原成对象 → 再看编译器在帧里存了什么 → 守住 poll 与唤醒的协议 → 用两个基准把成本拆到可核对的粒度。**

8.1–8.2 回答第一件事：手里拿到的到底是什么，帧（挂起时保存下来的那段状态）里又有什么。
8.3 把它换算成字节，同时划清 Pin 与栈/堆的边界。
8.4–8.5 转向协议：通知存在哪、驱动器凭什么不丢唤醒。
8.6–8.7 用两组对照，把协议成本与存储策略分别量出来。
8.8 收在语言不负责的那一段：取消、阻塞、跨线程与跨进程。

任何一环没走完，后面的纳秒数都只是修辞。

## 能否讲出这几句话

不看书，用自己的话回答。答不上来的，回到对应小节只看那一段。

1. 调用一个 `async fn` 与「启动一件事」差在哪三个时点？函数体没跑，帧里为什么还有东西要销毁？
2. 帧里为什么只放跨 await 存活的字段？poll 入口读判别值之后做了什么，为什么不是「从头重跑」？
3. 4097 与 2 的差能说成「常驻内存省了 4095 字节」吗？为什么缩帧不等于总内存同倍数下降？
4. 丢通知为什么不要求内存乱序？把 ready 换成原子量、再补一条 fence，为什么仍然不够？
5. `notified` 与 park/unpark 令牌各保存什么？7.407 为什么不能读成一次线程切换？
6. 取消是生命周期事件：`Drop` 做完了什么、又没做什么？超时路径至少还要补哪三件事？
