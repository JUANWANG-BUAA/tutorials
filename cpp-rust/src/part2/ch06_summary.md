# 第6章 · 全章总结

这一页只回答一件事：**八节各留下了什么可复用的结论。**IR 摘录、汇编片段与计时表都在[正文](ch06.md)，这里把每条结论压成一句能带走的句子。合上正文再读这页，读不下去的那一行就是断点。

## 八节一览

| 节 | 留下的结论 | 破坏它的最快方式 |
|:--|:--|:--|
| [6.1](ch06.md#sec-cpp-rust.2.6.1) | 后端只优化被保留下来的事实；合法性来自语言语义与引用契约，成本来自目标与循环规模，结论按 MIR、IR、本机汇编、计时四层分别写 | 看到 IR 里一行 `add <2 x i64>` 就宣布「本机用了 SIMD」 |
| [6.2](ch06.md#sec-cpp-rust.2.6.2) | 要防的是冲突访问而不是别名本身；noalias、readonly 与 align 8 是降级到 IR 的事实，各有自己的边界 | 把 align 8 读成「保证 16 字节对齐」，或把 `unsafe` 当成更快的开关 |
| [6.3](ch06.md#sec-cpp-rust.2.6.3) | 向量化要凑齐三件事：长度关系可证、无跨迭代冲突、循环体看得见；主体向量化不等于所有长度都走 SIMD | 删掉 `assert_eq` 只留 zip，把少算尾部当成加速 |
| [6.4](ch06.md#sec-cpp-rust.2.6.4) | 0.376540 ns/元素 的两均值之差属于完整数据通路；它支持「保留调用让本轮总体成本增加」，不支持「裸 call 延迟」 | 把 ns/元素 当单次加法成本，把 21 批的 p99 当尾延迟 |
| [6.5](ch06.md#sec-cpp-rust.2.6.5) | CTFE 是常量上下文的要求、失败即构建错误；常量传播是优化机会；Miri 是另一件工具、另一份覆盖面 | 编译成功就写「Miri 已通过」，把优化器的折叠说成 CTFE |
| [6.6](ch06.md#sec-cpp-rust.2.6.6) | 这张表比的是放置时机：`static_table` 与 `rebuild_table` 的差含构造成本，不等于两种查表指令的比较 | 由 256 字节全域的结果推出「表越大收益越大」 |
| [6.7](ch06.md#sec-cpp-rust.2.6.7) | inline 是提示，边界与体内优化要分别看；CGU 是编译并行单位；本轮只有功能与静态尺寸证据 | 从 `__text` 小 5388 字节推出「ThinLTO 让程序变快」 |
| [6.8](ch06.md#sec-cpp-rust.2.6.8) | 四步 PGO 真实跑通、产物可用、结果未变；profile 是构建输入，不是性能保证 | 拿两侧同一个 checksum 当「PGO 有效」的收益证据 |

6.9 是来源入口，6.10 是十三条陷阱，6.11 是出口检查与复现命令。三节不再产生新机制，只把前八节的结论变成可复核的动作。

## 一条主线

**先问这句话属于哪一层 → 再问合法性是谁给的 → 再问产物里还在不在 → 最后才读计时表。**

6.1 造出这张地图：后端拿到的是事实而不是源码，四层产物各说各的话。6.2 与 6.3 填第一栏事实：别名由引用契约给出，长度由断言给出，可见性由循环结构给出。6.4 与 6.6 把事实换成数字，并立刻说明这数字含什么。6.5 换到编译期，回答「成本在哪个阶段发生」。6.7 与 6.8 改变优化器的视野，然后只报尺寸与功能，不报速度。

任何一环跳过去，后面那句话就只能写成「本轮观察到」。

## 能否讲出这几句话

不看书，用自己的话回答。答不上来的，回到对应小节只看那一段。

1. 合法性与成本为什么是两道门？各举一个本章的否决理由。
2. 别名本身不危险，危险的是什么？为什么「这轮循环恰巧没撞到」不算证明？

4. 完整数据通路包含哪三段？为什么不能把 `fill(0)` 的成本从两边减掉？
5. CTFE、常量传播、Miri 三件事的主体、失败方式和覆盖面各是什么？
