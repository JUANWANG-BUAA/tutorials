# 第5章 · 习题集

共 19 题，分三组。**A 组概念**检验你能否说出名词指的是什么。**B 组推理**检验你能否从数字或产物推出结论。**C 组实操**要求你真的跑命令、在归档里找证据、写结论。全部题目附解答，难题另附提示层。

用法约定：先写下自己的答案，再展开核对。看解答时只看第一行就停住，问自己「接下来那一步是不是我要走的」，再往下读。直接通读解答，得到的只是「看懂了」，不是「会做了」。实验包在 `bench/compiler-lab/`。

### 按主线四步分组

| 步 | 这一章练这一步的题 | 这一步在本章的具体形态 |
|:--|:--|:--|

| ② 这个数是什么 | A1、A3、A4、A5、A7、B8、B9、B11、B13、C17（另见 A6、C16） | 分派与粒度是两件事；`__text` 体积不等于 I-cache 压力；两个机器字各装什么；批均值的分母与计时集合；3008 字节不能除以 15 |

## A 组 · 概念（1–7）

::: ex A1 · 分派与粒度各回答什么（主线 ②） {#ex-5.A.1}

① 写出「分派」的定义，并给出静态与动态的判据。② 为什么「这句话用了 trait」不含任何粒度信息？③ `dyn_batch` 与 `dyn_item` 哪一层相同、哪一层不同？

::: sol 解答

① 分派是把一次方法调用对应到一段具体代码：目标在编译期定死是静态分派，运行时靠元数据查找是动态分派。② 同一个 trait 可以承载两种粒度：`step` 每元素一次，`batch` 每批一次，选哪个是调用点的责任，不是 trait 的属性。③ 相同的是外部擦除与方法集合。不同的是调用粒度：前者只在批次入口动态一次，进入实现后 `Self` 具体；后者把 `step` 放进循环，本轮 16384 个元素就是 16384 次。对照[定义 5.1.1](ch05.md#def-5.1.1)、[定义 5.1.2](ch05.md#def-5.1.2)。

:::

:::

::: ex A2 · 单态化、收集与可达性（主线 ①） {#ex-5.A.2}

① 单态化、单态项收集与可达性各回答什么问题？② 为什么「被 10 个类型使用」推不出「产物里至少 10 份独立代码」？给出三条具体检查。

::: sol 解答

① 单态化回答「按哪些具体参数各生成一份代码」。单态项收集回答「要为哪些具体参数生成」，给出候选集合。可达性回答「哪段代码从入口出发有办法用到」。② 检查一：内联之后可能根本没有独立符号，本轮 `generic_batch` 的 `Affine` 实例就被内联到调用方。检查二：没有被引用且不可达的实例可以整个不生成，`probes/code_size.rs` 正是用 `functions` 表把地址交给产物。检查三：链接与 LTO 还会继续改，many 开 ThinLTO 后 `__text` 是 214768，比普通 many 的 220156 更小。对照[定义 5.1.3](ch05.md#def-5.1.3)、[定义 5.2.1](ch05.md#def-5.2.1)、[例 5.2.1](ch05.md#ex-5.2.1)。

:::

:::

::: ex A3 · 体积口径（主线 ②） {#ex-5.A.3}

① 本章数的是什么？② 列出三种不能替代它的「代码大小」。③ 为什么体积变大不能直接写成「I-cache 压力上升」？

::: sol 解答

① Mach-O 可执行文件里存放机器指令的 `__text` 节的字节数。② rlib 是中间产物；文件长度含所有节与调试信息；`__PAGEZERO` 只是虚拟地址保留区。③ 新增字节可能全在冷路径上，也可能在真实业务里一次都没被执行。本轮没有采集指令缓存缺失、ITLB 缺失与分支目标结构的任何事件。体积证据与缓存性能证据分属两层。对照[定义 5.2.3](ch05.md#def-5.2.3)、[思考 5.2.1](ch05.md#think-5.2.1)。

:::

:::

::: ex A4 · 两个机器字（主线 ②） {#ex-5.A.4}

`&dyn Kernel` 与 `&[u64]` 都是 size 16、align 8。① 两个机器字各装什么？② `Affine` 本体多大、在哪里？③ 为什么不能 `transmute` 互换？

::: sol 解答

① 擦除引用装数据地址与方法元数据；切片引用装数据地址与元素个数。② `Affine` 是两个 `u64`，占 16 字节；本轮两个正式实验里它在栈上，对象本体不搬家。③ 第二个字的语义不同：把长度当元数据用，第一次调用就会去一个不存在表的地方取地址。尺寸相同不代表语义可以互换。对照[定义 5.3.3](ch05.md#def-5.3.3)、[例 5.3.1](ch05.md#ex-5.3.1)。

:::

:::

::: ex A5 · vtable 与 ABI 的分界（主线 ②） {#ex-5.A.5}

① vtable 槽里存什么，除函数地址还有什么？② 本章的 24 与 32 是什么？③ 什么情况下需要 ABI 承诺，本章给了吗？

::: sol 解答

① 槽里存函数地址，此外还有大小、对齐、析构这类类型管理信息。② 它们是本轮目标码里的观察偏移：`ldr x23, [x1, #24]` 取 `step`，`ldr x4, [x1, #32]` 取 `batch`；增删方法、改声明顺序、换优化级别或工具链都可能改变它们。③ ABI 约定独立编译的两段代码之间怎么传参、怎么命名符号、谁负责释放内存。把 trait 对象裸指针交给独立编译的动态库才需要它。本章没有设计跨编译器版本的插件 ABI。对照[定义 5.3.2](ch05.md#def-5.3.2)、[定义 5.3.4](ch05.md#def-5.3.4)、[例 5.3.2](ch05.md#ex-5.3.2)。

:::

:::

::: ex A6 · 去虚化的条件与边界（主线 ①） {#ex-5.A.6}

① 去虚化成立需要哪两类条件？② `visible_dynamic` 与 `dynamic_batch` 的差别落在哪一行？③ `black_box` 是内存同步屏障吗？

::: sol 解答

① 目标集合能收敛到一个实现，且优化器有权看到这一事实。② 落在对象来源：前者形参是 `&Affine`，擦除发生在函数体内，来源就在眼前；后者收到已经擦除的引用，而且入口先过了 `black_box`。③ 不是。它让优化器对这个值的使用保持悲观，只是本章刻意制造的一条保守优化边界，不能当成形式证明，仍要检查产物。对照[定义 5.4.1](ch05.md#def-5.4.1)、[定义 5.4.2](ch05.md#def-5.4.2)、[定义 5.4.3](ch05.md#def-5.4.3)。

:::

:::

::: ex A7 · 批均值与计时集合（主线 ②） {#ex-5.A.7}

① 批均值的分母与单位是什么？② 本章把哪些阶段放在计时之外？③ 为什么表里的 p99 不能当请求 p99？

::: sol 解答

① 分母是重复数 × 输入元素数，单位 ns/输入元素。② 输入构造、对象构造，以及 case 闭包的 `Box`，都在计时前完成。③ 它是 21 个批均值上的 nearest-rank 分位数，p99 恰好是这 21 个数的最大点；请求级 p99 需要到达过程、排队与输出观察，本章没有采集。对照[定义 5.5.1](ch05.md#def-5.5.1)、[定义 5.5.3](ch05.md#def-5.5.3)、[定义 5.8.1](ch05.md#def-5.8.1)。

:::

## B 组 · 推理（8–14）

::: ex B8 · 3008 除以 15（主线 ②） {#ex-5.B.8}

有人从 5.2 的表推出：「16 个实例比 1 个多 3008 字节，所以每个新实例约 200 字节，今后加类型就按 200 字节预算。」指出三处不成立，并写出两句能诚实说的话。

::: hint 提示

分子是「15 个新实例的指令」吗？分母是整个 `__text` 吗？同一份 16 实例换一种构建方式会怎样？

:::

::: sol 解答

不成立在三处。① 分子不是「15 个新实例的指令」：one 与 many 是两个完整构建，差值里还含相关生成形态的变化。② 分母口径不对：表里的字节是整个 `__text`，标准库与启动代码占很大一部分。③ 增量不线性：同一份 16 实例代码在 ThinLTO 下是 214768，比普通 many 的 220156 少 5388。能说的是：本轮口径下 many 比 one 大 3008 字节，约 one 的 1.4%（3008 ÷ 217148）；PGO-use 构建为 220028，介于两者之间。对照[例 5.2.2](ch05.md#ex-5.2.2)。

:::

:::

::: ex B9 · 4.1 倍能不能归因给跳转（主线 ②） {#ex-5.B.9}

`dyn_item` 均值 0.647618、`generic` 0.158334，差 0.489284 ns/元素。① 这笔差值能全记成「一次间接跳转的价格」吗？② 要归因还需要什么实验？本轮做了吗？③ 换成能写的句子。

::: hint 提示

5.5.3 的责任表里，除了跳转，还有哪些阶段跟着一起变了？

:::

::: sol 解答

① 不能。5.5.3 已声明本轮没有构造「只改跳转、其余优化不变」的实验：跨调用边界的内联、展开与归约调度一起变了，代码形态也不同。② 需要一个只改变跳转、其余优化完全相同的对照；本轮没有做。③ 能写的是「粒度从每批改成每元素之后，本轮总体批均值高了约 4.1 倍」，以及它绑定 16384 这个批长与本章的构建配置。对照[例 5.5.1](ch05.md#ex-5.5.1)、[定义 5.8.2](ch05.md#def-5.8.2)。

:::

:::

::: ex B10 · 两个小数各能写什么（主线 ③） {#ex-5.B.10}

① `dyn_batch` 比 `generic` 低 0.001906，能写「动态分派更快」吗？② `opaque_dyn` 比 `known_dyn` 高 0.002170，能写「去虚化让每元素快 0.00217 纳秒」吗？③ 0.002170 乘回 16384 得到什么，这个数有什么资格？

::: sol 解答

① 不能。0.001906 比 `generic` 的 sd 0.008248 与 `dyn_batch` 的 0.004677 都小，本轮又没有区间与配对，方向不可判定。② 也不能。0.002170 小于 `known_dyn` 的 0.004065 与 `opaque_dyn` 的 0.004387，同样只能记成「证据不足」；而两条路径的内联范围也不同。③ 约 36 纳秒，含义是「一次完整遍历 16384 个元素上的均值差」，只能用来检查量级；本章没有单独测量任何一次跳转，无权给它定价。对照[例 5.5.1](ch05.md#ex-5.5.1)、[例 5.6.1](ch05.md#ex-5.6.1)。

:::

::: ex B11 · 均值比中位数还低（主线 ②） {#ex-5.B.11}

`dyn_item` 的均值 0.647618 比它自己的批 p50 0.694790 还低。① 这说明了什么？② 为什么不能顺手写成「大多数批次都比平均慢」？③ 三个 case 的 sd 里，哪一个最能支持你的解释？

::: sol 解答

① 说明 21 个批均值里有若干明显偏快的批把平均数拉到中位数以下。② p50 是中位数，不是「大多数」的计数；能说的只是分布被偏快的批拉低了均值，具体几批要回原始 21 个值里数。③ `dyn_item` 自己的 sd 0.088345，比 `generic` 的 0.008248 与 `dyn_batch` 的 0.004677 都大，说明它的运行条件波动更大。这正是均值与分位数要连着读的原因。对照[例 5.5.1](ch05.md#ex-5.5.1)、[定义 5.5.1](ch05.md#def-5.5.1)。

:::

::: ex B12 · E0038 该修哪一边（主线 ①） {#ex-5.B.12}

`trait Bad { fn apply<T>(&self, value: T); }` 在形成 `&dyn Bad` 时报 E0038。① 错误发生在调用还是构造？② 三种修法各改变什么？③ 为什么没有「用 `unsafe` 强转造一张表」这个选项？

::: hint 提示

一张有限的方法表，怎样容纳无穷多个 `T` 的实例？

:::

::: sol 解答

① 在构造对象类型 `&dyn Bad` 的那一刻，不需要任何调用发生；所以这类失败输入只进编译、不进执行。② (a) 把 `T` 换成具体类型或关联类型，方法表变有限；代价是接口收紧，调用点失去任意类型输入。(b) 给方法加 `where Self: Sized`，`dyn Bad` 能成形；代价是对象路径少一个方法。(c) 放弃 `dyn` 保留泛型，代价转成实例数量，按 `__text` 口径去数。③ 那等于把编译期检查换成未定义行为，得到的不是合法对象。对照[定义 5.7.1](ch05.md#def-5.7.1)、[例 5.7.1](ch05.md#ex-5.7.1)。

:::

:::

::: ex B13 · 测试全绿的接口重构（主线 ②） {#ex-5.B.13}

一次 diff 只做一件事：从 trait 里删掉 `batch`，只留 `step`，调用方改成显式循环。测试全绿，没有 `unsafe`。① 用本章数字说明它把什么变了。② 测试为什么看不见？③ 什么情况下它是正确的设计决策？

::: sol 解答

① 每个元素的动态边界从「无」变成「一次」：16384 个元素上，每批一次是 0.156428 ns/元素，每元素一次是 0.647618；产物层面循环里多出 `blr x23`，跨边界的展开与归约也一起消失。② 语义完全没变，等价性成立，所以功能测试看不见；回归发生在优化边界，而不是内存安全边界。③ 当业务确实需要每元素换策略时，这是忠实表达需求，不该为了表格好看而伪造批不变性。对照[例 5.6.2](ch05.md#ex-5.6.2)。

:::

::: ex B14 · 1.70 与 1.99.0（主线 ④） {#ex-5.B.14}

母本 PDF103 记录 Rust 1.70 时 `&dyn Child` 转不成 `&dyn Parent`；本章在 Rust 1.99.0 上的测试已通过。① 它推翻了哪句话？② 没有推翻哪三句话？③ 读旧母本时要注意什么？

::: sol 解答

① 推翻的是那条**当时**的规则：本轮把 `&dyn Child` 转成 `&dyn Parent` 并调用父 trait 方法，测试通过。② 没推翻：语言支持该转换，不等于应用可以自行解析元数据。`Child: Parent` 这种真实超 trait 关系成立，不等于任意 trait 组合都能互转。本轮通过，不等于未来版本与别的构建仍通过。③ 时间范围本身就是事实的一部分，历史结论只能带时间范围引用。对照[例 5.7.2](ch05.md#ex-5.7.2)。

## C 组 · 实操（15–19）

这一组要求真的动手。命令一律从 `cpp-rust/` 执行；正式脚本要求新归档目录不存在。

::: ex C15 · 复跑本章正式脚本（主线 ④） {#ex-5.C.15}

依次执行 5.11 的四条命令。写下每条命令验证什么，并说明为什么 `run.sh` 的目标目录必须不存在、复跑后要在新归档里核对哪三件事。

::: sol 参考路径

四条命令：

```bash
cargo test --offline --locked --manifest-path bench/compiler-lab/Cargo.toml
cargo clippy --offline --locked \
  --manifest-path bench/compiler-lab/Cargo.toml --all-targets -- -D warnings
bash bench/compiler-lab/run.sh bench/compiler-lab/results/my-trait-run
python3 bench/compiler-lab/extra.py bench/compiler-lab/results/my-trait-extra
```

第一条验证功能与输出校验。第二条验证静态检查。第三条跑六个入口，顺序执行、不并发计时。第四条生成补充尺寸探针的结果。目标目录必须不存在，是为了不覆盖原始测量对象。复跑后核对：每个正式 case 是否保存 21 个原始批次、是否独立预热至少 500ms、归一化除数是否为重复数 × 输入元素数。对照[5.11](ch05.md#sec-cpp-rust.2.5.11)、[5.8](ch05.md#sec-cpp-rust.2.5.8)。

:::

:::

::: ex C16 · 在产物里指出三处形态（主线 ①） {#ex-5.C.16}

在 `results/stable-02/codegen/` 里找到三处：`dynamic_items` 循环内的 `blr x23`、`dynamic_batch` 的 `ldr x4, [x1, #32]` 加 `br x4`、`visible_dynamic` 内部无表调用。各写一句它支持的结论，并说明为什么 `dynamic_batch` 的四条指令不是整个业务。

::: sol 参考路径

`dynamic_items` 支持「本轮循环内每元素一次间接调用」；`dynamic_batch` 支持「每批一次动态进入」；`visible_dynamic` 支持「本地来源使去虚化成立」。`dynamic_batch` 的短入口是尾调用形式的间接分派，目标 `batch` 实现仍会执行全部 16384 个元素的工作，必须继续追踪真实目标。对照[5.3.3](ch05.md#sec-cpp-rust.2.5.3)、[5.4.4](ch05.md#sec-cpp-rust.2.5.4)。

:::

::: ex C17 · 尺寸探针与符号列表（主线 ②） {#ex-5.C.17}

打开 `results/extra-02/` 里的 `*-size.txt` 与 `*-nm.txt`：① 复述四行 `__text` 数字与可达实例数；② 为什么 nm 列表里可能看不到某个泛型实例；③ 为什么不能把 16 与 8 推广到 32 位目标？

::: sol 参考路径

业务批长只有 8 个元素。按实验契约的四组问题写一个扫描设计：固定什么、扫什么、记录什么、不能声称什么。

::: hint 提示

摊薄按 1/n 变化；总工作量要保持可比；等待凑批属于系统夹具，不属于内核计时。

::: sol 参考路径

固定：算子语义、参数、参考结果、构建配置与计时集合；对照必须是同一构建。扫：批长度作为显式因素逐档变化，同时保持总元素数可比。记录：每档 21 个批均值、N−1 sd、批 p50 与 p99，以及是否把凑批等待算进区间。不能声称：不能给「最小批大小是某个常数」的结论。本章只跑了 16384 一种批长，小批量**本节没有采集**。一旦把等待凑批纳入，指标就从吞吐变成延迟，需要另一套系统夹具。对照[例 5.5.2](ch05.md#ex-5.5.2)、[定义 5.6.2](ch05.md#def-5.6.2)。

## 批改时最常给的三条意见

1. **把总体差值当成单条指令的价格。**0.489284 是粒度改变后的总体差，不是一次跳转的价钱。改法：先写「总体代码效果」，再列一起变了的因素。
2. **把「接近」写成「相同」或「更快」。**0.001906 与 0.002170 都小于各自的批间 sd。改法：先摆差值与 sd，再写「方向不可判定」。
3. **跨层搬数字。**体积不能搬到缓存结论，批均值不能搬到请求延迟，16384 不能搬到小批量。改法：每个数字先问它属于哪一层证据，再决定句子。
