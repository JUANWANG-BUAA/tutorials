# 第5章 · 闭卷回忆卡

「看懂」只说明答案在眼前时能识别；考试和评审需要的是从空白纸上提取。这一页把第五章拆成 24 张卡，每张先写卡面问题，合上正文自己答，再展开核对。

**用法与节奏**

| 时点 | 做什么 | 判定 |
|:--|:--|:--|
| 学完当天 | 第一组「定义卡」全部 8 张 | 关键词写全才算 ✓ |
| 第 1 天 | 第二组「结论卡」全部 8 张 | 能说清前提与范围才算 ✓ |
| 第 3 天 | 第三组「第一行卡」全部 8 张 | 写出第一步动作才算 ✓ |
| 第 7 天 | 只重做标成 △ 和 × 的卡 | 全对即可进入第 6 章 |

每张卡给自己一个记号：✓ 一次说对；△ 说对一半或要提示；× 想不起来。只重做 △ 和 ×，不要把整叠卡反复过一遍——那是在读，不是在提取。

## 第一组 · 定义卡（说全称与前提）

::: ex 卡 1 · 分派 {#rc-05-1}

卡面：写出「分派」的定义，并给出静态与动态的判据。

::: sol 核对

分派是把一次方法调用对应到一段具体代码。目标在编译期定死是静态分派；目标要到运行时靠对象自带的元数据查找，是动态分派。分派只说「什么时候确定目标」，既不承诺快慢，也不涉及谁拥有这块内存。对照[定义 5.1.1](ch05.md#def-5.1.1)。
:::

:::

::: ex 卡 2 · 调用粒度 {#rc-05-2}

卡面：什么是分派的「粒度」？为什么同一个 trait 能有两种粒度？

::: sol 核对

粒度是一次分派替多少个元素负责。每个元素一次是逐元素粒度；一整批只在开头进入一次，是每批粒度。粒度由接口形状决定，不由编译器决定：`step` 与 `batch` 同在 `Kernel` 里，选哪个是调用点的责任。对照[定义 5.1.2](ch05.md#def-5.1.2)。
:::

:::

::: ex 卡 3 · 单态化与可达性 {#rc-05-3}

卡面：单态化生成什么？可达性筛掉什么？单态项收集给出的又是什么？

::: sol 核对

单态化针对实际用到的具体类型参数各生成一份代码，运行时没有「正在生成函数」这回事。可达性只保留从入口出发有办法用到的代码：被调用、被取地址，或出现在必须存在的方法表里。单态项收集给的是候选集合，后端与链接器还会继续改。对照[定义 5.1.3](ch05.md#def-5.1.3)、[定义 5.2.1](ch05.md#def-5.2.1)、[定义 5.2.2](ch05.md#def-5.2.2)。
:::

:::

::: ex 卡 4 · `__text` 口径 {#rc-05-4}

卡面：本章的体积口径数的是什么？三种不能替代它的口径各指什么？

::: sol 核对

口径是 Mach-O 可执行文件里 `__text` 节的字节数，这一节存放机器指令。三种错误口径：rlib 是中间产物；文件长度含所有节与调试信息；`__PAGEZERO` 只是虚拟地址保留区。口径没写明的「代码大小」不能拿来比较。对照[定义 5.2.3](ch05.md#def-5.2.3)。
:::

:::

::: ex 卡 5 · trait 对象 {#rc-05-5}

卡面：`&dyn Kernel` 的两个机器字各装什么？它为什么不必来自 `Box`？

::: sol 核对

一个字指向数据本体，一个字是方法元数据；本轮两个正式实验借用的是栈上 `Affine`。`dyn Kernel` 是动态尺寸类型，只能经指针或拥有者使用，`&`、`Box`、`Arc` 只决定所有权那一层。胖指针多出的那个字不是长度，也不是引用计数。对照[定义 5.3.1](ch05.md#def-5.3.1)、[定义 5.3.3](ch05.md#def-5.3.3)、[定义 5.1.4](ch05.md#def-5.1.4)。
:::

:::

::: ex 卡 6 · vtable 与 ABI {#rc-05-6}

卡面：vtable 的槽里存什么？本章的 24 与 32 是什么、不是什么？

::: sol 核对

vtable 按 trait 与方法排槽，槽里存函数地址，此外还有大小、对齐、析构这类类型管理信息。24 与 32 是本轮目标码里的观察偏移，不是跨版本协议。同一工具链、同一构建内部的 `dyn` 调用不需要 ABI 承诺。对照[定义 5.3.2](ch05.md#def-5.3.2)、[定义 5.3.4](ch05.md#def-5.3.4)。
:::

:::

::: ex 卡 7 · 去虚化与可见性 {#rc-05-7}

卡面：去虚化成立的两类条件是什么？`inline(never)` 与 `black_box` 各约束哪一层？

::: sol 核对

条件一是目标集合能收敛到一个实现，二是优化器有权看到这一事实。`inline(never)` 只约束「本函数要不要并入调用方」，不约束函数体内部，所以 `visible_dynamic` 外层留符号、内部照样消解。`black_box` 让优化器对这个值的使用保持悲观，不是内存同步屏障。对照[定义 5.4.1](ch05.md#def-5.4.1)、[定义 5.4.2](ch05.md#def-5.4.2)、[定义 5.4.3](ch05.md#def-5.4.3)。
:::

:::

::: ex 卡 8 · 批均值、计时集合与摊薄 {#rc-05-8}

卡面：批均值的分母是什么？计时集合管什么？摊薄成立的两个前提是什么？

::: sol 核对

批均值是「一批墙钟耗时 ÷（重复数 × 输入元素数）」，单位 ns/输入元素，回答聚合吞吐，不回答单次请求延迟。计时集合声明哪些阶段被算进批次；本章把输入构造、对象构造与 case 闭包的 `Box` 放在计时外。摊薄要求这笔成本与批长无关，且计时集合里没有夹带别的工作。对照[定义 5.5.1](ch05.md#def-5.5.1)、[定义 5.5.3](ch05.md#def-5.5.3)、[定义 5.6.2](ch05.md#def-5.6.2)。
:::

:::

## 第二组 · 结论卡（说清前提与范围）

::: ex 卡 9 · 约 4.1 倍能说什么 {#rc-05-9}

卡面：本轮 `dyn_item` 0.647618、`dyn_batch` 0.156428 ns/元素。能写「慢约 4.1 倍」吗？不能写什么？

::: sol 核对

能写「粒度从每批改成每元素之后，本轮总体批均值高了约 4.1 倍」。不能写「一次间接跳转值 0.489284 ns/元素」。本轮没有构造只改跳转、其余优化不变的对照；跨边界的内联、展开与归约调度一起变了。对照[例 5.5.1](ch05.md#ex-5.5.1)。
:::

:::

::: ex 卡 10 · 两个「接近」都不是方向 {#rc-05-10}

卡面：0.001906 与 0.002170 这两个差值各能写什么？

::: sol 核对

都不能写方向。0.001906 小于 `generic` 的 sd 0.008248 与 `dyn_batch` 的 0.004677；0.002170 小于 `known_dyn` 的 0.004065 与 `opaque_dyn` 的 0.004387。本轮没有算区间、没有配对，只能记成「证据不足」。对照[例 5.5.1](ch05.md#ex-5.5.1)、[例 5.6.1](ch05.md#ex-5.6.1)。
:::

:::

::: ex 卡 11 · 产物不同、时间接近 {#rc-05-11}

卡面：`known_dyn` 与 `opaque_dyn` 的目标码差在哪？这条观察否定哪句话？

::: sol 核对

`known_dyn` 内部没有保留 vtable 调用，目标码直接加载两个参数字段；`opaque_dyn` 保留间接尾跳转，再进入具体 `batch` 实现。所以「时间接近就说明产物相同」不成立，性能表与产物表要互相检查。对照[定义 5.6.1](ch05.md#def-5.6.1)、[例 5.6.1](ch05.md#ex-5.6.1)。
:::

:::

::: ex 卡 12 · 3008 字节不能除以 15 {#rc-05-12}

卡面：为什么「每新增一个实例约 200 字节」不成立？本轮能诚实说出的体积事实是什么？

::: sol 核对

分子里含相关生成形态的变化，分母是整个 `__text`，标准库与启动代码占很大一部分。增量也不线性：同一份 16 实例代码在 ThinLTO 下是 214768，比普通 many 的 220156 少 5388。能说的是 many 比 one 大 3008 字节，约 one 的 1.4%。对照[例 5.2.2](ch05.md#ex-5.2.2)。
:::

:::

::: ex 卡 13 · p99 是批的分位数 {#rc-05-13}

卡面：表里的 p50 与 p99 是什么的分位数？为什么 p99 正好是最大值？

::: sol 核对

它们是 21 个批均值上的 nearest-rank 分位数，p99 就是这 21 个数的最大点。它不描述元素之间，也不描述请求之间；请求级 p99 需要到达过程、队列与输出观察，本章没有采集。对照[定义 5.8.1](ch05.md#def-5.8.1)、[定义 5.5.1](ch05.md#def-5.5.1)。
:::

:::

::: ex 卡 14 · E0038 发生在哪一步 {#rc-05-14}

卡面：`fn apply<T>` 为什么让 trait 不能擦除？错误什么时候发生？三种修法各改变什么？

::: sol 核对

`T` 有无穷多种实例，一张有限方法表排不完。错误在构造 `&dyn Bad` 的那一刻报告，不需要任何调用发生，所以这类失败输入只进编译、不进执行。修法：换成具体类型或关联类型；给方法加 `where Self: Sized`；放弃 `dyn` 保留泛型。没有「用 `unsafe` 造一张假表」这一项。对照[定义 5.7.1](ch05.md#def-5.7.1)、[例 5.7.1](ch05.md#ex-5.7.1)。
:::

:::

::: ex 卡 15 · 测试全绿的重构 {#rc-05-15}

卡面：删掉 `batch` 只留 `step`，功能测试全绿，说明性能没变吗？

::: sol 核对

不说明。逐元素动态边界从「无」变成「一次」：16384 个元素上每批一次是 0.156428 ns/元素，每元素一次是 0.647618。语义确实没变，回归发生在优化边界，而不是内存安全边界。对照[例 5.6.2](ch05.md#ex-5.6.2)。
:::

:::

::: ex 卡 16 · 母本的时间范围 {#rc-05-16}

卡面：Rust 1.70 的 trait upcast 限制，在本轮还能原样引用吗？测试推翻了什么、没推翻什么？

::: sol 核对

不能原样引用。本轮 Rust 1.99.0 上把 `&dyn Child` 转成 `&dyn Parent` 的测试已通过。它没推翻：语言支持该转换，不等于应用可以自行解析元数据。真实的超 trait 关系仍要满足。本轮通过，也不等于未来版本通过。对照[例 5.7.2](ch05.md#ex-5.7.2)。
:::

:::

## 第三组 · 第一行卡（只写第一步）

这一组练的是「一离开答案不知道第一行写什么」那个毛病。每题只写第一行动作，不计算。

::: ex 卡 17 · 体积质疑 {#rc-05-17}

卡面：评审说「这个 crate 有 40 个泛型调用，太膨胀了」。第一行写什么？

::: sol 核对

第一行写口径：数什么——`__text` 字节、符号数，还是 rlib 大小；口径没定的比较直接作废。然后数实际生成的实例，看哪些真的可达。对照[定义 5.2.3](ch05.md#def-5.2.3)、[例 5.2.1](ch05.md#ex-5.2.1)。
:::

:::

::: ex 卡 18 · `dyn` 的断言 {#rc-05-18}

卡面：同事说「这里写了 `dyn`，循环里一定有虚调用」。第一行写什么？

::: sol 核对

第一行：在目标码里找循环内的间接跳转。找到一条就足以否定「这里没有间接调用」；要肯定「没有」，得看完整函数体，不能只看签名。对照[例 5.4.1](ch05.md#ex-5.4.1)、[例 5.3.2](ch05.md#ex-5.3.2)。
:::

:::

::: ex 卡 19 · 千分位之差 {#rc-05-19}

卡面：两个 case 的均值只差 0.002170，讨论区要写「谁更快」。第一行写什么？

::: sol 核对

第一行：把差值与两个 case 各自的批间标准差摆在一起。0.002170 小于 0.004065 与 0.004387，方向不可判定；本轮没有区间与配对，不能升级成百分比结论。对照[例 5.6.1](ch05.md#ex-5.6.1)。
:::

:::

::: ex 卡 20 · 小批报价 {#rc-05-20}

卡面：业务批长是 8，有人要按 0.156428 ns/元素报价。第一行写什么？

::: sol 核对

第一行：问批长还是不是 16384。0.156428 是 16384 个元素摊薄后的批均值；固定成本除以 8 之后，两个 case 的比值不再是 4.1。小批量本章没有采集。对照[例 5.5.2](ch05.md#ex-5.5.2)、[定义 5.6.2](ch05.md#def-5.6.2)。
:::

:::

::: ex 卡 21 · 缓存结论 {#rc-05-21}

卡面：`__text` 多了 3008 字节，报告要写「I-cache 压力上升」。第一行写什么？

::: sol 核对

第一行：查本轮采集了哪些硬件事件。答案是没有：指令缓存缺失、ITLB 缺失、分支目标结构命中率、指令退休数、核心周期都没有采集。体积证据与缓存证据是两个层次。对照[5.8](ch05.md#sec-cpp-rust.2.5.8)、[思考 5.2.1](ch05.md#think-5.2.1)。
:::

:::

::: ex 卡 22 · 跨版本动态库 {#rc-05-22}

卡面：要把策略对象交给独立编译的动态库。第一行写什么？

::: sol 核对

第一行：设计显式函数表与所有权接口，边界只用 C 级类型，不把 trait 对象的裸指针当协议。布局之外还有符号解析、panic 策略与分配器契约。对照[定义 5.3.4](ch05.md#def-5.3.4)、[5.3](ch05.md#sec-cpp-rust.2.5.3)。
:::

:::

::: ex 卡 23 · 改成 enum {#rc-05-23}

卡面：插件框架要接受外部 crate 的实现，评审要求「改成 enum 去掉 `dyn`」。第一行写什么？

::: sol 核对

第一行：问扩展方向——实现集合是否由外部代码增加。会，就保留 `dyn`；enum 是封闭集合，改了就改变业务的扩展性。性能理由要排在接口能否成立之后。对照[定义 5.7.2](ch05.md#def-5.7.2)、[5.7](ch05.md#sec-cpp-rust.2.5.7)。
:::

:::

::: ex 卡 24 · 换构建复现 {#rc-05-24}

卡面：别人换 `LTO=true` 来复现你的结论。第一行写什么？

::: sol 核对

第一行：重取三项——产物对照、同一口径的 `__text`、新构建下的计时协议。三项都要进新归档，不能在旧表上写新句子。对照[定义 5.8.2](ch05.md#def-5.8.2)、[5.8](ch05.md#sec-cpp-rust.2.5.8)。
:::

:::
