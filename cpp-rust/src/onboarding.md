# 第 0 章 · 零基础起步

如果你只学过 Rust 的基本语法——变量、函数、结构体、`Vec`、`for` 循环、`match`——但没学过操作系统、没写过汇编、不知道「缓存」和「线程」在硬件上到底是什么，这一章是为你写的。读完它，你能看懂后面每一章的开头，也知道读不懂时该往哪里退。

## 你只需要会这些

下面这张清单是全书的最低门槛。只要你能独立写出其中每一项，就可以开始：

| 能力 | 一个可以自查的例子 |
|:--|:--|
| 定义函数、传参、返回值 | 写一个 `fn add(a: u64, b: u64) -> u64` |
| 用结构体组织数据 | 定义一个含三个字段的 `struct`，并构造一个实例 |
| 用 `Vec` 与切片 | 创建一个 `Vec<u64>`，用 `&v[..]` 传给别人 |
| 迭代器基本用法 | 用 `iter()`、`map`、`sum` 处理一个数组 |
| 借用与所有权的直觉 | 说清 `let b = a;` 之后 `a` 为什么不能再用（`a` 是 `String` 时） |
| 用 `cargo` 建项目、跑测试 | `cargo new`、`cargo run`、`cargo test` |

**不需要**会：`unsafe`、宏、异步、泛型约束的高级写法、任何 C/C++、任何汇编、任何操作系统课程内容。这些书里都会在用到的地方现讲。

## 这本书不需要你先懂的事

很多人被这类书劝退，不是因为难，而是因为第一页就有五个没解释的词。这本书的处理方式是三条承诺：

1. **每个术语第一次出现时，用一句大白话解释**，并在括号里给出英文原名，方便你另外查。
2. **每条结论都指回一个定义或一次测量**，你可以顺着链接看到它是怎么来的。
3. **没有测量的地方会明说「本节没有采集」**，不会用「据说」「一般来讲」糊过去。

如果你在某一页碰到一个没解释就被使用的词，那是这本书的 bug，不是你的问题。

## 一台电脑上，你的代码经历了什么

先建立一个足够用的画面，四层，从上到下：

| 层 | 你写的东西 | 它变成了什么 |
|:--|:--|:--|
| 源码 | `fn main() { ... }` | 你自己能读的文本 |
| 编译器 | `cargo build --release` | 把文本翻译成机器能执行的指令，顺便做大量改写（第 4 章） |
| 内存 | 变量、`Vec`、结构体 | 一片带编号的存储单元，编号叫地址（第 2 章） |
| 处理器 | 一条条指令 | 真正在运行的东西；它读内存很慢，所以中间有几层更小更快的缓存（第 2 章） |

三个最常见的误解，先在这里拆掉：

- **「`release` 和 `debug` 只是快慢不同」**——不是。它们是两份不同的翻译结果，`release` 会删掉、合并、重排你的代码（第 1、4 章）。所以性能数字必须在 `release` 下测。
- **「变量就在内存里某个格子」**——编译器可以把一个变量放进处理器的寄存器，也可以因为「没人用」而彻底删掉它（第 1 章讲的就是这件事）。
- **「程序按你写的顺序一行行执行」**——单线程大致如此，多线程下不成立（第 7 章）。

这一章之后，你在书里会不断回到这张表：**每一个性能问题，都能落到其中某一层**。

## 六个词的最小版本

后面会反复用到这六个词。这里只给最小解释，真正的定义在各章里。

**编译器**：把 Rust 翻译成机器指令的程序，`cargo` 会调用它。它很聪明，会改写你的代码——这件事既是性能的来源，也是测量出错的来源。

**机器码**：处理器真正执行的指令。你不需要会写它，但第 4 章会教你在关键处读懂几行。

**内存**：一块很大的、按地址编号的存储。读写它比处理器内部运算慢得多，这是后面许多设计的根源。

**缓存**：处理器内部几层很小很快的存储，用来暂存最近用过的内存内容。**你不需要记具体数字**：只需要知道「取过一次的数据，再取会快很多；第一次取最慢」。

**线程**：处理器执行代码的一条流水线。多个线程可以同时跑，代价是它们可能同时改同一份数据（第 7 章）。

**纳秒**：十亿分之一秒，写作 `ns`。书里大量出现「ns/元素」，意思是「平均到每个元素上花了多少纳秒」。**它是一个摊薄后的平均成本，不是某一条指令的耗时**——这条区别是第 1 章的主线。

## 第一个能跑的小实验

不需要跑分工具，只要装了 Rust。新建一个项目，把 `src/main.rs` 换成：

```rust
use std::time::Instant;

fn sum_all(v: &[u64]) -> u64 {
    let mut s = 0u64;
    for &x in v {
        s = s.wrapping_add(x);
    }
    s
}

fn main() {
    let data: Vec<u64> = (0..65536).collect();

    let t0 = Instant::now();
    let s = sum_all(&data);
    let t1 = Instant::now();

    println!("sum = {s}");
    println!("elapsed = {:?}", t1 - t0);
}
```

用 `cargo run --release` 运行（**一定要带 `--release`**）。你会看到两行：一行是求和结果，一行是这次运行花的时间。

这次测量**不合格**，原因有三个，正好对应第 1 章的三个知识点：只测了一次（没有重复）、没有预热（第一次运行包含装载成本）、`s` 被打印出来了但结果没有和任何「参考值」比对（正确性没有验证）。第 1 章会带你把它改成一个能交给别人复核的实验——那也是全书唯一一件必须先学会的事。

**每章固定先读两处**：开头的「先抓住一件事」和末尾的「小结与常见错误」。这两处加起来通常不到一页，却能告诉你这一章在解决什么、最容易错在哪。

## 读不懂的时候，按这三步退

1. **退到定义**：这个术语在本书里第一次出现的地方，通常给了一句大白话（用页面右上角的搜索或[术语表](appendix/glossary.md)找）。看不懂用法，先看定义。
2. **退到先修**：如果卡在「线程」「缓存」「纳秒」这类词上，去[先修工具箱](prerequisite.md)对应的抽屉；如果卡在 Rust 语法，去[《Rust 程序设计语言》](https://rustwiki.org/zh-CN/book/)对应章节，这本书不重复讲语法。
3. **退到最小例子**：把这一节的代码抄到一个空项目里，删到只剩三五行，看它还成不成立。多数「看不懂」其实是「例子太大」。

还有一条：**允许自己暂时不懂某个数字**。这本书的很多结论依赖一台具体的机器（Apple M5 Pro、rustc 1.99.0）。你要带走的是方法与判断顺序，不是那些纳秒值；换一台机器，数字会变，方法不会。
