# 参照主线：把 rCore 当成机制侧的坐标系

这一页回答一个问题：**这本书已经有一条四步证据主线了，为什么还要再挂一条 rCore 的线？** 因为四步主线管的是「一个性能结论凭什么可信」，它不回答「这个代价到底在哪里发生」。后半句需要一个真实存在、能指到类型和常量的机制出处，而这本书选的坐标系是清华大学的中文教材《rCore-Tutorial-Book-v3》。这一页把它的十章逐页映射到本书的章节，并规定这条线**能用来做什么、不能用来做什么**。

<a id="rcore-line-spine"></a>

::: preview 先抓住一件事

- **两条线分工不同，不要混。**四步主线是**证明的顺序**：① 工作真的发生 ② 这个数是什么 ③ 差异不是噪声 ④ 守得住、可复核。rCore 参照线是**机制的层次**：从裸机一路长到一个能跑并发程序的操作系统。
- **参照线只借「机制事实」，不借数字。**rCore 里的 32 字节、100 ticks/s、4 KiB 都是它那个教学内核的**设计常量**，不是测量结果；把它们写进你的性能结论，等于伪造证据。
- **每一站都要落到本书某一节的具体判定上。**落不下来的站，说明你只是路过看了个热闹，那就不算读过。

:::

## 这条线和四步主线怎么分工 {#rcore-line-split}

::: def 定义 F.1 · 参照线与机制侧证据 reference line / mechanism-side evidence {#def-rcore-line-1}

**参照线**（reference line）指一条不由本书自己论证、专门用来回答「机制在哪里发生」的外部线索。本书的四步主线处理**证据**：一个数字能不能信。参照线处理**机理**：一次系统调用、一次上下文切换、一次页表遍历里，代价是在哪一步被创造的，以及那个代价是**设计决定的**还是**环境带来的**。一条机制事实构成**机制侧证据**，当且仅当你能指出它在来源的哪一页、写成哪个类型或常量、以及它约束了本书哪一节的做法。只说「操作系统会做上下文切换」不算证据，那是一句常识。

:::

为什么要单独设这一条线？因为这本书的对象有一个结构性缺口。十七章正文全都在**用户态 Rust** 里打转：你能看到 `Vec` 的容量、`AtomicUsize` 的内存序、`Future` 的状态机，但看不到这些选择最终落在哪块硬件或哪个内核路径上。于是读者容易犯两类错：把「编译器优化掉了」和「内核把你阻塞了」当成同一种现象；把某个库的默认值当成机器的性质。参照线专门补这层。

选 rCore 而不是别的 OS 材料，有三个具体理由，都不是「它有名」：

| 理由 | 具体指什么 | 别家材料的位置 |
|:--|:--|:--|
| **同一种语言** | 内核用 Rust 写，机制直接落在 `TaskContext`、`GlobalAlloc`、`Arc<Mutex<_>>` 这些你已经在读的语法上；你可以把一本书里的类型名和另一本书里的性能现象对上 | 6.S081、OSTEP 用 C，多一层语言翻译成本 |
| **可指到常量** | 每一页都给到具体的量与代码，例如管道的 `RING_BUFFER_SIZE = 32`、`TICKS_PER_SEC = 100`、`BLOCK_CACHE_SIZE` 上限不足会 panic。本书引用它们是为了说明「容量与失败模式都是被写下来的设计决定」 | 讲义常停留在「缓冲区是有限的」这种定性说法 |
| **中文，能直接读** | 参照线要真的被用上，读者得能在三分钟内查完一页；语言门槛会把这条线变成摆设 | 英文材料本书也引，但只作方法与结构来源 |

## 怎么读一页 rCore：以管道那页为例 {#rcore-line-worked}

::: ex 例 F.1 · 把一页参照材料读成三条本书约束 {#ex-rcore-line-1}

假设你在写 [第 17 章](part4/ch17.md) 的准入与取消，或者在做 [第 10 章](part3/ch10.md) 的 worker 输出排空。打开 rCore 的「管道」一节，你只能借机制事实。请写出三条**能落到本书某一节**的读法，并说明每条各挡掉哪一种错误。

::: sol 解答

第一条：**容量是被写下来的，不是环境给的。**那一页把缓冲区直接定义成 `const RING_BUFFER_SIZE: usize = 32;`，并给出 `FULL`/`EMPTY`/`NORMAL` 三个状态。它教你的不是「管道有 32 字节」——这个数字属于那个内核，搬到你的结论里就是伪造——而是：**有界队列必须在代码里写死一个数，并为「满」和「空」分别定义行为**。挡掉的错误：写出「队列会自然背压」这种句子，却没人定义满了以后调用方拿到什么。本书 [@def-9.7.1] 与 [@def-17.6.1] 都要求把这个数与它的来源写进契约。

第二条：**阻塞的两端不对称，所以排空要两路。**读空会等写，写满会等读，两端互相依赖；那一页还专门用 `Option<Weak<Pipe>>` 记录写端是否全部关闭，用来判断「读端还能等到数据吗」。挡掉的错误：只排空 stdout 不排空 stderr，或者只等退出码不等另一端关闭——这正是 [@def-17.7.1] 要求双路排空的原因：一个方向的关闭不代表另一个方向结束了。

第三条：**资源归还的触发点是「最后一个引用」，不是「我以为没人用了」。**那一页明确：所有读端与写端都关闭后，管道的强引用计数归零，缓冲区才被回收；而环里指向写端的那条引用刻意做成 `Weak`，否则会出现循环引用导致泄漏。挡掉的错误：把 `close` 当成装饰性调用，或者在共享结构里到处用强引用形成回边，于是资源永远不归还。这一条落在 [@def-3.4.1] 的销毁责任上。

三条的共同形状是：**问「它把什么写死了」，而不是问「它跑多快」。**这就是参照线唯一正确的用法。

:::
:::

::: think 思考 · 为什么参照线不能让本书少写一章

有人会说：既然 rCore 已经把页表、调度、文件系统讲清楚了，本书直接指向它就好了，为什么还要在第 9、10、12 章里各写一遍机制？因为**参照线给的是「机制存在且是设计决定的」，本书给的是「你在用户态能不能观察到它、以及观察不到时该怎么写结论」**。这两件事的验收方式不同：前者回来源页，后者要回到你自己的实验契约。把前者拿来替代后者，等于用别人的教材冒充自己的证据——四步主线的第 ① 步直接不过。

:::

## 什么时候查它，什么时候别查 {#rcore-line-rule}

::: method 判定流程 · 四问决定要不要引 rCore {#m-rcore-line-1}

1. **我卡住的是「代价在哪发生」，还是「这个数能不能信」？** 前者可以查参照线，后者只能查四步主线和自己采的证据——参照线替你证明不了任何东西。
2. **我能把这条机制事实指到具体一页、一个类型或常量吗？** 指不到就别引；「操作系统一般是这样做的」不是引用，是印象。
3. **引完之后，本书哪一节的写法因此更严格了？** 说不出落点，这条引用就是装饰，删掉。
4. **我有没有把它的数字搬进自己的结论？** 只要出现「rCore 里是 32 字节，所以……」这类推理，停手。可以写「有界容量的取值是设计决定，参照实现里给的是 32 字节（见来源台账）」，不能写「管道缓冲区 32 字节」。

四问全过，才允许进正文；过不了第 3 问的，进[来源与审计台账](appendix/coverage.md)就够了。

:::

## 小结与常见错误 {#rcore-line-summary}

**小结。**这本书有两条线：四步主线负责把一个数字从不可信推到可发布，rCore 参照线负责指出这个数字背后的代价是在哪一层、被哪个设计决定创造的。参照线一共十站，从裸机执行环境一路到设备队列，每一站都必须有一个本书落点；落点不存在，那一站就不该被引用。用法只有一种：问它「把什么写死了」。

::: errata 三个禁忌（也是最常见三种误用）{#e-rcore-line-1}

T-a **搬数字。**把 `TICKS_PER_SEC = 100`、`RING_BUFFER_SIZE = 32` 或 easy-fs 的块大小写进自己的性能结论。这些是别的设计上下文里的常量，与你的机器、你的负载无关；本书[主线页](mainline.md)早就声明「书里的数字只属于一台机器」，参照线的数字连那台机器都不属于。

T-b **把教学内核当生产内核。**rCore 自己写明了简化：目录树被压平到只剩根目录、不做权限与时间戳、块缓存上限不足时内核直接 panic。这些取舍对**理解机制**没有妨碍，但任何「所以系统会怎样」的推断都不能反过来用——真实内核的行为要查真实内核。

T-c **顺着参照线跑题。**读完站点表想去写内核，这很正常，但本书不需要你实现内核。参照线的目标只有一个：让你在看到「尾延迟突然变粗」时，能列出「哪一层的设计决定可能造成它」，然后回到第 13 章把它变成一次可反驳的归因，而不是去补一个 `__switch`。

:::

## 即时自测 {#rcore-line-quiz}

::: method 记忆 / 辨析 / 应用 / 迁移

- **记忆**：不看这一页，说出四步主线和参照线各自回答什么，各举一个它在第 17 章的落点。
- **辨析**：「大页能减轻 TLB 压力、提升 IPC」和「用了大页所以吞吐提升 x%」——哪一句可以引用，为什么另一句不行？（提示：对照 [@def-2.3.2] 的三类陈述。）
- **应用**：你的服务有一个内部队列，同事说「队列满了自然会背压，不用管」。用管道那一页的三条读法，指出这句话缺哪两个定义。
- **迁移**：本书哪些结论会因为你换一台机器而失效？参照线里哪些内容换了机器也不变？写出各两条，并说明它们的检验方式为什么不同。
