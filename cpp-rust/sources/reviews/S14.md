## 原生机制：示例不是装饰

28–35 页是本轮核心：未标语言的块默认 Rust，常规 doctest 要编译且运行成功；assert 才使结果契约可观察。
预处理可注入 crate 与 main；隐藏的 # 行仍参与编译，## 用于展示行首 #；可以隐藏返回 Result 的 main 或用明确的 Ok 错误类型支持 ?。
ignore 不等于编译通过；no_run 只保证编译，不保证运行成功；should_panic 需要运行时 panic；compile_fail 验证拒绝，但未来语言变化可能使原代码可编译。
这些标记绝不能拿来掩盖未验证的生产示例。UB 示例不得运行；本轮也没有运行书中例子。
34–35 页说明 cfg(doctest) 的收集阶段与 README include_str 方案；这与普通 cfg(test) 单元测试不是同一门禁。
25 页 test(attr(...)) 可对 doctest 注入警告策略；39–45 页的 broken links、私有链接、缺文档、代码块属性、HTML 和裸 URL 检查需 rustdoc 阶段，不能只跑 cargo check。
46–47 页强调 cfg(doc) 不传入 doctest；生成文档可不检查所有函数体，cargo doc 成功不能代替 cargo build/test 的平台与 feature 矩阵。
48–58 页列 nightly 和不稳定选项，--show-coverage 只计文档/示例数量，并不是执行覆盖率或原书逐节核读覆盖率。
--persist-doctests、--runtool、edition、目标过滤与示例抓取需固定版本后再验证；此处不伪造已执行记录。
