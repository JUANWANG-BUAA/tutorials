# Rust主线章节协议

本文件定义“教材”的写法。目标读者是已经能读 Rust 代码、但还没有系统性能训练的高年级本科生和研究生。教材必须有课程层、学习目标、例题、实验、习题和答案，不能只给结论和表格。

## 教材体

1. 默认写完整段落，一段 1–4 句、平均 80 字左右（上限 250 字）、一句不超过约 35 字；列表只用于并列项、步骤和检查表。禁止一句一行撑篇幅。
2. 每章开头先给“学习目标、先修知识、引入”。学习目标用可检查的动词：解释、计算、设计、实现、评估，不写“了解”。
3. 每节先给一个具体场景或问题，再定义概念；每个术语第一次出现时给中文、英文和一句话解释。
4. 先建立正面模型，再写边界；每节最多一个“边界”段，不要连续否定。
5. 代码必须能编译，或明确标为伪代码；代码后解释关键行，不能只贴不讲。
6. 每章至少两个例题，用 `::: ex` 盒子，写出题目、解题步骤和答案；例题要能独立读懂。
7. 每章至少两个实验，给出实验目的、步骤、观察量、结果表和解释；实验要能复现。
8. 每一节（H2 的第 1–8 节）按固定骨架推进：**本节回答一个问题 → `::: preview 先抓住一件事` → 若干 `### N.M.k` 小节（术语首现即定义，定义给 `{#def-N.M.k}` 锚点）→ `::: ex` 例题套 `::: sol 解答` → `::: think` 思考盒 → 有判定步骤的给 `::: method 判定流程` → `### N.M.k 小结与常见错误`（`**小结。**` 一行串链 + `::: errata 常见错误清单（N.M 节）` 列 E-a…E-f）→ `::: method 即时自测 · N.M`（记忆 / 辨析 / 应用 / 迁移四题，各折进 `::: sol 第 k 题答案`）**。
9. 章末三节固定为：**N.9 延伸阅读与来源**（只给读者用得上的入口，审计台账留在附录）、**N.10 常见错误索引**（索引各节清单 + 3–4 条跨节错误，不重述 E-x）、**N.11 本章小结与章末件**（`::: note 本章小结` + `### 本章速查` + `### 本章导航`）。
10. 每章另有五页章末件，与章正文同级放在 `src/partX/`：`chNN_summary.md`（全章总结）、`chNN_recall.md`（闭卷回忆卡）、`chNN_exercises.md`（A 概念 / B 推理 / C 实操分层习题，全部附解）、`chNN_exam.md`（限时闭卷自测卷 + 评分标准）、`chNN_checklist.md`（K/S/A 学习目标自检表）。正文只在章末件已存在时链接它们。
11. 章节标题用平实写法，不用文学化隐喻。
12. 删除“本章/本轮/本包/证据/归档/门禁”这类审计口吻；来源信息集中到附录，正文只留“延伸阅读”。
13. 统一人称：用“你”称呼读者，用“我们”表示共同操作；不要混用“笔者/本文/本轮”。
14. 类比只用来解释机制，不用来装饰；每节最多一个。
15. 段落之间要有过渡：上一段的问题由下一段回答，不要只堆结论。

## 写作结构

- 最终16章，每章正文 12000–30000 汉字；不以行数计。单个 H2 小节不超过 5000 汉字（《矩阵论》一节独立成页约 5000–9000 汉字），超了就拆到章末件或压缩叙述。
- 每章1个H1、11个H2：8个专业节 + 延伸阅读与来源 + 常见错误索引 + 本章小结与章末件。
- 显式锚点使用 `sec-cpp-rust.<part>.<chapter>.<section>`，全书唯一。
- 每章至少一张对象/内存/并发图：优先用内联 `<figure><svg role="img">…<title>…<desc>…</svg><figcaption>`（图内不得出现空行，`id` 加本章前缀避免全书冲突），并保留图后的「读图：」说明句。
- 每章至少类型/布局、ABI/代码生成、性能三类表。
- 每章至少两个例题、两项已提供源文件且真正可编译的benchmark、六道习题（概念/编程/测量各至少两道）。
- 每章至少一个UB、数据竞争或性能回退案例；假设案例必须标明，不捏造公司事故。
- C/C++仅用于FFI支持；不写语法、汇编指令集和ABI入门。
- 每章至少有“本章小结”和“本章速查”两项复习工具；习题答案放在同章或附录。

## 证据优先

1. 先实现并编译实验，再写数值结论。
2. 原始批次、环境、编译参数、源码指纹、统计方式与单位一起保留。
3. 结果不支持假设时保留原结果，不制造“理想加速”。
4. 区分批均值分位数与逐请求分位数，区分吞吐倒数与单次延迟。
5. 交叉生成的汇编不等于目标机运行；本机sample不等于Linux perf。
6. 不报告没采集的IPC、cache miss、能耗、频率和CPU周期。
7. 构建后的汇编/IR是固定版本观测，不是语言ABI稳定承诺。
8. 代码摘录允许省略上下文，但完整测试过的源文件必须明确。
9. unsafe必须说明所有权、别名、初始化、同步、销毁与panic边界。
10. benchmark中不执行存在UB的代码来获取“合法预期耗时”。

## 原文核读

- 本地16份母本只读，不修改、不上传、不整本复制入成书。
- PDF使用一基物理页，同时记录文件SHA-256；EPUB使用XHTML定位，不伪造固定页码。
- 目录索引、开篇抽页、全文提取、实际核读、正文映射是不同状态。
- 每条核读记录包含母本节、标题、页、状态、落点、证据。
- 无目录PDF须建立人工逐章索引，不能以0个条目冒充0缺口。
- 不相关语法节也要有明确范围裁决，不能直接从台账消失。
- 课程按实际年份、讲义标题和URL定位；MIT操作系统课程不称Rust专门教程。

## 门禁与审计

预览可只包含本轮完整章，但必须清楚标为未完成全书；禁止创建空章和空项目满足数量。
发布门禁必须覆盖全部17章、三个项目（`agent-runtime`、`ffi-bridge`、`tidekv`）、逐节范围裁决和连续两轮独立审计。
结构门禁按“汉字数、单节体量、可编译代码、练习答案、术语定义、速查表、章末件齐备”检查，不再按行数或陷阱条数作为唯一标准。改造正文时禁止整文件覆盖写入，必须逐节编辑并先跑 `tools/check_loss.py`（对比 git，防止改写过程丢内容）。
机械结构/链接检查不属于独立技术审计。
没有独立审计能力时，明确保留阻塞项，不以自审替代签核。

共享主题与语义盒预处理器复用仓库现有实现，不改其他书配置。

## 2026-10-29 新增契约（教材化改造后生效）

- **主线位置**：每章「新手入口」里必须有一行 `**主线位置**`，写法是「第 X 步为主导——一句为什么；其次 Y 步」。只挂步骤号不写理由，视为未完成。
- **章首三件**：`### 本章路线`（8 行「节 → 回答的问题」+ 章末五页链接 + 一条主线句）与 `### 建议反复做的三道母题` 是硬要求，`textbook_lint.py` 的「路线」「母题」两列必须全绿。
- **章末五页**：总结 / 闭卷回忆卡 / 分层习题集 / 综合自测卷 / 学习目标自检表，缺一即 `check_book.py` 报「章末件不足」。
- **习题按主线分组**：习题集开头有「按主线四步分组」表，每题题号后标主导步骤；某一步在本集没有对应题就写「（本集无）」并说明这一步练在哪儿，不许硬凑，也不许写成「本章不练这一步」——那是对整卷的判断，不是对一页的判断。
- **自测卷按主线归堆（2026-10-29 起进门禁）**：每章 `chXX_exam.md` 必须有「每题落在主线哪一步」一节（题号 → 主导步 → 这一步缺什么 → 答不出回哪一节），`chXX_checklist.md` 必须有指向它的指针。两条都由 `check_book.py` 的 `check_endmatter_contract()` 检查，缺一条即构建失败。设计意图：分数只能说错了几个题，归堆表才说得出缺的是四步里的哪一步；自检表按能力分组、卷子按主线分组，两边各留一份口径会分叉。
- **图示**：一律内联 SVG（`role="img"` + `<title>` + `<desc>` + `figcaption` + 图后「读图：」），`<pre class="layout">` 已全面退役。
- **术语首现**：硬术语在该章**散文**第一次出现处给不超过 20 字的括号释义。`textbook_lint.py` 只看散文行（跳过代码块、表格、标题、盒标题行），口径变更理由写在函数 docstring。
- **盒子写法三条铁律**（都出过事故，本轮又犯了一次）：`{#def-…}` 必须写在 `::: def …` 那一行，另起一段写会被预处理器当成不存在；**新增或改动任何带 id 的盒子之后，必须跑一次 `mdbook build`**——`check_book.py` 是全文扫 `{#…}`，看不出这个错位，只有预处理器会报「引用了不存在的锚点」；`::: ex` 套 `::: sol` 需要**两个** `:::` 收尾；盒标题行不许出现尖括号。
- **子代理安全**：禁止整文件 Write 覆盖既有正文，只许逐处 Edit；每改完一个文件立刻跑 `tools/check_loss.py`；不许并发 `mdbook build`；不许改 `tools/`（本轮已把三个门禁脚本设为只读）。代理报「额度耗尽/超轮次」时，先验四件事再决定是否重跑：H2 数、盒配平、`check_loss`、lint 指标列。

- **预处理器解释器**：`book.toml` 改为 `sh tools/run_mathbook.sh`。PATH 里的 `python3` 可能是刚升级、尚未装 `markdown-it-py` 的 Homebrew 版本，写死 `python3` 会让构建随环境随机失败；启动器会挑第一个装得下依赖的解释器，失败时给出 `pip3 install -r requirements.txt`。

## 2026-10-29 晚 · 借事实、不抄句子

- **覆写规则**：引用外部材料（rCore、MIT 讲义、官方文档）时，**只借机制事实，不借句子**。凡是「机制事实」都能指到来源页的类型、常量或流程；凡是接近原文的整句表达，一律改写成本书自己的话，再把出处标在旁边。
- **门禁**：`tools/check_paraphrase.py --strict --min 10` 已接进 `verify_all.py`。它把书稿散文（跳过代码块、表格、标题、盒标题）与本地归档的正文做中文长片段比对，**≥10 字的逐字重合即失败**；来源标题的正名引用（章节名）自动排除。
- **比对口径的两处细节**：来源只取 `<article>` 正文，不取侧边导航与目录（否则每页都会命中一次目录文字）；标题集合按**全书来源**合并判断（某页的标题出现在别页正文里也算正名）。
- **自检结果**：124 页书稿 × 44 份本地归档，散文重合 0 处。上一轮实测有 7 处（其中 1 处达 15 字），已全部改写；改写时**不删机制事实、不删引用**，只换说法。
- **新增站点也要走这条**：新抓的 rCore 页面进正文时，写完必须跑一次 `--strict --min 10`；先在 10 字阈值上看到 0，才算写完。

## 2026-10-30 · 量尺修了一次自己的错：段均不可跨书比，改用单段预算

**起因**：欠账清单上写着「ch08 段均 53、ch15 段均 76，都在 60–72 带外，要内化」。真去改之前先把尺子拿出来对了一遍，发现这条带站不住。

**实测三件事**（同一函数、同一口径，两本书都跑）：

1. `textbook_lint.py` 旧版把整张项目符号表**并成一个段落**统计。于是「段均」量到的其实是一章里列表的密度，不是行文节奏。修掉之后（列表项各自成段），17 章的段均从 49–76 变成 49–73，排名也变了——第 15 章从「76 偏长」变成 73，第 2 章从 71 掉到 67。
2. 拿同一把尺量《矩阵论》各章正文：**20.6–30.3 汉字/段**（中位约 28）。也就是说「60–72」这条带根本不是从参照书来的，它记在自评文档里，基准是**自家第 1 章**（63）。用自家一章当基准没错，错在把它写成「《矩阵论》语言」并拿去要求别的章。
3. 「句均」这一列跨书是**可比的**，而且已通过：矩阵论中位 29.9，本书中位 30.1。**「否定/千字」也是可比且失败的**：矩阵论 3.2，本书整章口径 7.1、**只看语义盒外的连贯正文 7.8**——正文比 errata 盒还更爱说「不能/不是」，方向正好反了：边界该收进清单盒，连贯正文该写成正面条件。

**这一轮改了什么**：

- **删掉一条无效指标的要求，换一条有效的门禁**。`check_book.py` 新增 `check_paragraph_budget()`：**单段（含语义盒内正文与列表条目）不超过 200 汉字**，超了直接判红。标题、表格、`<desc>` 不计入——`<desc>` 是图片替代文本，天生密。
- 全书正文原先最长一段 **437 汉字**（9.2.3 的内核切换定义盒），现在**全书最长 199**，17 章无一超标。共切开 22 处，全部只插空行、一字未改（核验法：去掉所有空白后与改动前逐字节相同）。
- `textbook_lint.py` 保留段均，但**加了「最长段」与「正文否定」两列**，并把「答案」列从「正文里有没有『参考答案』四个字」改成**逐题核对习题集的 `::: sol` 解答盒**——旧判据把 16 章误报成没有答案，实际 17 页 339 题题题有解答。同一判据也进了 `check_book.py` 的章末件契约：**任何一题没有解答盒，构建判红**。

**下一轮的语气目标（本轮没做，别当成已完成）**：正文否定密度从 7.8 往 **≤5/千字** 走，做法是把能正面化的「不能 X」改成「满足 Y 才成立」，而**不是**把 errata 盒里的禁令改写成肯定句——那里说「不许干什么」正是它的职责。第 8 章正文 10.6、第 4 章 10.0、第 14 章 10.3 是前三名；第 11 章 4.2、第 17 章 4.1 已经在目标内，可作范例。

**一条纪律**：以后凡是「参照某书的语言风格」写进规范的数字，必须在同一条里注明**用哪个脚本、哪个口径、哪一天实测**。否则下一轮就会拿一把没人校准的尺子去改已经写对的地方——本轮若直接照着 60–72 去合并第 8 章的短段，会毁掉它的 errata 列表版式。

## 2026-10-30 晚 · 第二条量尺也撤了：否定密度不可当目标

接上一条的教训，我去查了清单上第二项「正文否定密度 7.8 → ≤5/千字」。做完三件事，结论是**这条目标同样作废**：

1. 按「这条否定有没有承担功能」把全书语义盒外的否定分成三类：**区分句**（「X 不是 Y 而是 Z」）、**带出路的禁令**（同句给了怎么做）、**裸禁令**（只 forbid 不给条件）。只有第三类是缺陷。
2. 把最密集的第 4 章 64 条「裸禁令」逐行读完：`不能从普通共享引用后面移出拥有所有权的 String` 是**语言规则本身**，`不是稳定版编译参数` 是**范围声明**，`这避免重复执行同一计算` 是正面陈述被正则误判。**真正该改的接近零**。
3. 于是本书与参照书的 3.2 之差不是文风失控，是**体裁决定**的：一本以「这句话不能这么写」为主题的性能工程书，否定就是它的教学内容；《矩阵论》讲存在与唯一，天然不必说「不能」。

## 映射登记的回链类型（2026-11-01 起强制）

`sources/sections.json` 里每条 `status="read-mapped"` 的记录必须说明它凭什么算「已核读」，否则附录把它印成「核读映射」就是空头承诺。三类：

| `basis` | 含义 | 必须同时具备 |
|:--|:--|:--|
| `pdf-unit` | 按母本页码核读 | `units` 字段列出同页且状态为 `read-mapped` 的母本单元号；页码范围不得包含被裁决为 `excluded-reviewed` 的页，若包含须在 `pages` 里写明哪几页被排除 |
| `online` | 在线来源核读 | URL 与抓取指纹在 `sources/web.json` 或 `sources/contributions/*-web.json` 里可对核；不写页码单元 |
| `artifact` | 依据本机代码/归档产物 | `evidence` 指向仓库内真实文件；页码只作出处范围，不当逐页核读声明 |

母本侧的 `reason`/`scope` 不得留「某章尚不存在」这类过期裁决——章写出来就要把那句改掉，同时保留原来那条限定（例如「不能推为本机已验证 ESP 支持」仍然成立）。
