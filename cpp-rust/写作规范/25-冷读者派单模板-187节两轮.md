# 冷读者派单模板（187 节两轮正式审计用）

这份模板只为一个目的服务：让**一轮正式审计的 34 名分章冷读者 + 1 名母本读者 + 1 份机械报告**能按同一标准派出去，不靠临场回忆规则。规则本身在 `tools/verify_audits.py` 与 `tools/audit_assemble.py` 里是强制的，这里只是派单文案的单一来源。

## 一轮的构成（缺一都不能组装）

| 层 | 谁 | 数量 | 记账字段 |
|:--|:--|:--|:--|
| 机械层 | `tools/audit_section_check.py`（作者的确定性脚本） | 1 份报告，187 节 + 16 母本 | `layer:"mechanical"`，节条目 `method:"mechanical"` |
| 通读层 | 无上下文子代理，每章两名（x.1–x.6 与 x.7–x.11） | 34 份报告，合计 187 个 `layer:"read"` 且 `method:"read"` 的节判定 | `layer:"read"` |
| 母本层 | 无上下文子代理，逐条回查 S01–S16 | 1 份报告，16 条 `layer:"read"` 的母本判定 | `layer:"read"` |

机械层只证三件事：结构契约齐、`[@id]` 与链接可解析、测量级数字点名了磁盘上真实存在的证据文件。它**不判数字与代码是否相符**，也**不能抵作「有人读过」**——这是 2026-10-31 补上的洞，见自评第十一节。

## 派单前必须换的三样东西

1. **快照串**：先跑 `/usr/bin/python3 tools/audit_snapshot.py --write`（前提：`check_book` 与 `verify_all` 已绿），把打印出来的 sha256 原样写进每张派单，代理不自己算。
2. **章号与节区间**：`part_of(chapter)` 决定锚点里的篇号 —— 1–4 章是 `1`，5–8 章是 `2`，9–12 章是 `3`，13–17 章是 `4`。锚点写错篇号，节判定就落不进 187 个集合里。
3. **报告文件名与 reviewer**：一轮内 reviewer 不许重名，两轮之间也不许重名（门禁把最后两轮的评审者放进同一个集合查重）。命名固定 `sources/audits/round{N}-{ch:02}{a|b}.json` / `reviewer: r{N}-{ch:02}{a|b}`。

## 派单正文（复制即用，替换 `{{}}`）

```
你是冷启动的独立审计员。你没有先前对话上下文，不要假设作者是对的；你的价值在于发现正文与真实证据不符的地方。

仓库：/Users/juanwang/Desktop/tutorials/cpp-rust（mdBook《Rust 底层性能工程》，十七章）
快照（写进报告用这串，不要自己算）：{{SNAPSHOT}}

你负责的节：{{FILE}} 的 {{RANGE}}（锚点 {{ANCHORS}}）。完整读这些节的全部正文与每个语义盒（定义、例题与解答、思考、判定流程、小结、常见错误、即时自测），不要抽样，不要只读标题。

逐条把可对核的断言拿去对真实证据：
- 关于代码的断言 → 打开对应的 .rs/.py/.sh 逐行看，给 file:line。
- 关于测量数字的断言 → 用 /usr/bin/python3 从正文点名的归档文件自己复算，正文给的数不能直接抄。复算不出来的「实测」数字 = P0。
- 关于静态量（字节、容量、对齐、指令数、比例）的断言 → 自己算，算错 = P1。
- 关于外部书/文档的引文 → 在仓库 sources/ 或母本文件里找到那句原文，逐字比对；改动原文或被引作已核实却找不到母本 = P0/P1。
- 统计量要写明分位数定义；正文没交代定义就把 p50/p99 当结论用 = P1。

判级：P0 = 编造的实测、正文与代码事实相反、引用无法落地却被当作已核实；P1 = 正文内部数字矛盾、口径混用、关键断言无出处、引用与母本不符、答案算错；P2 = 表述与教学性问题。

只允许写这一个文件，禁止修改仓库任何其他文件（脚本写到 /tmp）：
/Users/juanwang/Desktop/tutorials/cpp-rust/{{REPORT}}
JSON（严格照此，缺字段整份报告作废）：
{"reviewer":"{{REVIEWER}}","kind":"independent","layer":"read","snapshot_sha256":"{{SNAPSHOT}}","provenance":"一句话说你冷启动实际读了什么","sections":[{"anchor":"{{ANCHOR}}","verdict":"pass","method":"read","notes":"你核对了什么、结论是什么（不许写待审计）","evidence":["文件:行 或 复算得到的数"]}],"sources":[],"findings":[{"anchor":"{{ANCHOR}}","severity":"P0|P1|P2","description":"具体到哪个数、归档里的真值、你怎么算的","evidence":"文件:行 或 复算输出"}]}
规则：verdict 只能 pass 或 finding；判 finding 的节必须在 findings[] 里有对应条目；你负责的每个锚点都要出一条 section 判定。
最后回我 ≤120 字：P0/P1/P2 各几条，最严重一条是什么。
```

## 母本层派单的差异

`sections` 留空、`sources` 给全 16 条（`{"id":"S07","notes":"...","evidence":"..."}`），其余同上；`layer` 仍是 `read`，因为机械层已经给过 16 条 `layer:"mechanical"`，两条都要在才能证明「冷读者也逐条回查过」。

## 回收后的纪律

代理自述不是证据。报告回来后：P0/P1 逐条自己回源码或归档复算，确认成立才改正文；不成立就在自评里记下「评审者误报 + 我据什么判它误报」。改完必跑 `check_book` → `verify_all`，绿了才重新冻结，然后**以新快照重跑整轮**——旧快照上的报告只能当修正输入，不进台账。

## 预算纪律（必须抄进每张派单）

上一轮有一位做同类核查的代理耗尽 150 次工具调用仍未落盘，等于白跑。派单里固定加这三句：

1. 最多 45 次工具调用；到第 30 次就必须开始写报告文件。
2. 先用**一条** python 脚本把整章内容/数字一次性抽出来，不要逐句 grep。
3. 报告宁可覆盖不全也不许不写；没查完的节按 `verdict:"pass"` 也要在 notes 里写清「这一节我只核到 X，Y 没核」。

## 报告落盘之后的事

`tools/audit_assemble.py` 只认 `layer:"read"` 的节判定。代理若忘了写 `layer`，整份报告在组装时会被当作不存在——不要手工补 `layer`（那是改别人的判定），应当重派。

## 短派单（省上下文，代理自己读这份模板）

一轮要派 35 份时，逐份复制上面的长正文会占满派单方的上下文。改用这种形式，每张只写参数：

```
先完整读 /Users/juanwang/Desktop/tutorials/cpp-rust/写作规范/25-冷读者派单模板-187节两轮.md，
按其中「派单正文」的全部规则执行（包括判级、复核纪律、预算纪律与 JSON 字段）。
参数：快照 {{SNAPSHOT}}；文件 {{FILE}}；节区间 {{RANGE}}；锚点 {{ANCHORS}}；
报告 {{REPORT}}；reviewer {{REVIEWER}}。layer 填 read，每条节判定都要带 method:"read"。
只允许写这一个文件，其他文件一律不改；临时脚本放 /tmp。最多 20 次工具调用，第 14 次起必须开始写报告。
```

模板里那条「最多 45 次工具调用」是给整章深审用的；分章冷读者用 20 次上限、第 14 次落盘，这条覆盖模板默认值。
