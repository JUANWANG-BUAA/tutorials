# 教材化改造工单（第 2–16 章）

本工单只描述「怎样把一章改造成与第 1 章同级的教材正文」。基准实现是
[src/part1/ch01.md](../src/part1/ch01.md)，写作契约见 [20-章节协议.md](20-章节协议.md)。

## 0. 先读三样东西

1. [src/part1/ch01.md](../src/part1/ch01.md) 的 **1.7 节**（理论节范例）与 **1.5 节**（实验节范例）。
   这两节就是目标形态，不要凭想象改造。
2. [src/part1/ch01_exercises.md](../src/part1/ch01_exercises.md) 与
   [src/part1/ch01_checklist.md](../src/part1/ch01_checklist.md)，知道章末件承担了什么，
   正文就不必重复。
3. 你要改的那一章的**现有全文**。所有真实数字、文件名、命令、版本、实验结论都在里面，
   它们是证据，不是装饰。

## 1. 硬性红线

- **禁止用 Write 覆盖整章文件。**只用逐节的编辑工具替换，`old_string` 必须覆盖整节。
  已经发生过一次事故：一个 agent 用 Write 重写第 3 章，11 节只剩 2 节，正文少了一半。
  每改完一节立刻跑 `python3 tools/check_loss.py`——它把每章与 git 上一版对比，
  汉字数倒退超过 8% 或 H2 数量减少就报错。**报错就先修复，不许继续往下写。**
- **不许编造数据。**没有实测支持的指标一律不写。IPC、cache miss、周期数、能耗、
  跨机器结论这类本章没采过的量，只能写成「没有采集」，不能写成数字，不能写成趋势。
- **不许改动** `tools/`、`src/SUMMARY.md`、`book.toml`、`theme/`、其他章节、
  `bench/` 里的任何文件。一次只改一个章文件。
- **不许运行 `mdbook build`**（会与其他并行的改造冲突）。验收只用第 4 节的两条命令。
- **保留全部 `sec-cpp-rust.<篇>.<章>.<序>` 锚点**，H2 数量必须正好 11 个，顺序不变。
- **保留 `<div class="chapter-index">`、`<pre class="layout">` 与「读图：」**三件。

## 2. 每一节（H2 的 1–8 节）要走完的骨架

按这个顺序，缺一件就不算完成：

1. 紧接 H2 标题一行：**「本节回答一个问题：**……？**」**——问题必须是这节真正解决的，
   不是标题的换一种说法。
2. `::: preview 先抓住一件事` —— 一段，加粗给出本节的核心判断。肯定它要查全部条件，
   否定它只需一条被破坏的规则，这类「怎么判」的话在这里说。
3. 若干 `### N.M.k` 小节，每个新术语**首次出现就用一句大白话定义**，然后才允许使用。
   定义给锚点：`::: def 定义 N.M.k · 名称 英文 {#def-N.M.k}`。
4. 每个关键结论至少配一道 `::: ex 例 N.M.k · 一句话说清这道题 {#ex-N.M.k}`，
   里面套 `::: sol 解答`。例题要真做一遍（写数字、写命令输出、写判定），
   不能只是「注意某某事项」。
5. 一道 `::: think 思考 · … {#think-N.M.k}`，套 `::: sol 解答`，写一个容易被绕过的前提。
6. 有判定步骤的地方给 `::: method 判定流程 · …`；有对照的地方给表格。
7. `### N.M.k 小结与常见错误`：先 `**小结。**① …（[@def-N.M.k]）；② …` 一行串起本节链条，
   再 `::: errata 常见错误清单（N.M 节）`，列 E-a…E-f（至少 5 条，每条一句「错在哪」+
   一句「先查什么」，可引用 `[@def-…]`）。
8. `::: method 即时自测 · N.M`：**记忆 / 辨析 / 应用 / 迁移**四题，每题一个
   `::: sol 第 k 题答案`，答案里注明对应 `[@def-N.M.k]`。

第 9 节改成 `## N.9 延伸阅读与来源`：只留读者用得上的入口（母本条目、标准库文档链接、
下一步读物），把「哪个文件核读到第几页」这类审计信息留在
[附录来源台账](../src/appendix/coverage.md)，不要搬进正文。

第 10 节改成 `## N.10 常见错误索引`：不再重复各节的 E-x，用一张表说明每节的清单
共同把什么搞错了、出错后先查什么，再加 3–4 条只有整章读完才看得见的跨节错误。

第 11 节改成 `## N.11 本章小结与章末件`：`::: note 本章小结`（5 条以内，各带 `[@def-…]`）+
`### 本章速查`（问题 / 一句话答案 / 详细位置三列）+ `### 本章导航`（学习目标、先修、课时、
实验包、入口、数据、边界）。章末件页面此时还不存在，**不要**链到 `chNN_summary.md`
之类的文件，门禁会检查链接可达性。

## 3. 文风

- 一段平均不超过 80 字，一句不超过 35 字；一段只说一件事。
- 少用「你要 / 必须 / 注意」开头。先给背景，再给动作：读者不知道这个指标是什么时，
  不要直接教他怎么测。
- 不用「显然 / 容易看出 / 众所周知」。写出省略的那一步。
- 术语用中文，括号里给一次英文；数字与单位紧贴证据（「实测」「归档里」「本节表 1」）。
- 每个 `[@id]` 交叉引用要真的指回去，一节里至少出现 3 次指向前文定义的引用。

## 4. 验收（两条命令都必须干净）

```bash
cd cpp-rust
python3 tools/check_book.py
PATH=/usr/bin:$PATH python3 tools/textbook_lint.py src/partX/chYY.md
```

`textbook_lint` 里这一章的「节覆盖」必须是 `8/8`，`preview`、`def`、`ex`、`sol`、`think`、
`errata`、`自测` 各项都非零，`交叉引用` 至少 60。

## 5. 最容易踩的两个坑

1. **重复正文。**用编辑工具替换整节时，`old_string` 必须覆盖**整节**（从 H2 标题到下一节
   标题之前）。只覆盖标题和首段，会把旧内容留在下面，造成两份同名的节和重复的锚点。
   改完先跑一次 `grep -n "^## " src/partX/chYY.md` 确认只有 11 行。
2. **盒子没配平。**`::: ex` 里嵌 `::: sol` 时，需要两个 `:::` 收尾；
   `::: hint` 也要自己先闭合再开 `::: sol`。`check_book.py` 会报「语义盒未闭合」。
3. **盒子标题里不能写泛型。**`::: ex 例 2.1.1 · 一只 \`Vec<u64>\` …` 会让 mdBook 报警：
   标题不做 Markdown 渲染，`<u64>` 被当成 HTML 标签。标题里写「Vec 装 u64」之类，
   泛型留给正文的反引号。
4. **图内的空行会把图撕碎。**CommonMark 把 HTML 块在空行处结束：`<figure>`、`<svg>`
   之内**一行都不能空**，否则 mdbook 构建会 WARN「unexpected HTML end tag」，图渲染成碎块。
   要升级图示时，把 `<pre class="layout">` 换成 `<figure><svg role="img">…<title>…<desc>…
   </svg><figcaption>图 N-M · 一句图题</figcaption></figure>`，保留后面的「读图：」句子，
   并给 SVG 里的 `id` 加上本章前缀（如 `c3-`），否则和其他章的 `id` 冲突。

## 6. 交回什么

不超过 200 字：改了哪几节、新增了多少 `def/ex/think/errata/自测`、
哪一处因为缺少实测数据而写成「未采集」、以及你认为下一轮该补什么。
