在所有算法设计范式中，贪心算法（Greedy Algorithm）以其极致的直观与高效著称。它在每一步决策时，都仅仅关注眼前利益最大化（局部最优），从不回溯，也不考虑后续步骤的连锁反应。

然而，**贪心算法也是算法设计中最危险的陷阱**。直觉在绝大多数复杂的组合空间中都会失效。一个看似无比自然的贪心规则（例如“选当前性价比最高”、“选最短的”、“选耗时最少的”），往往在某些精心构造的输入上表现出灾难性的次优性，甚至与最优解相去甚远。

本章以 Tim Roughgarden《算法详解 卷 3》与 CLRS 第 16 章为母本，不仅系统传授经典贪心算法，更传授**“如何证明贪心正确（交换论证）”**与**“如何证明贪心错误（反例构造）”**的严谨工程与数学方法论。

## 5.1 贪心设计范式与数学基础 {#sec-algorithms.2.5.1}

一个组合优化问题能否使用贪心算法求解，完全取决于它是否同时满足两个数学特征：**最优子结构**与**贪心选择性质**。

::: def 定义 5.1.1 · 最优子结构 (Optimal Substructure) {#def-algorithms.2.5.1.1}

设问题 $P$ 的最优解为 $S$。如果将 $S$ 拆解为针对子问题 $P'$ 的部分解 $S'$，则 $S'$ 必为子问题 $P'$ 的全局最优解。
若反证法成立——假设 $P'$ 存在比 $S'$ 更优的解 $S''$，能与原问题的其余部分拼成超越 $S$ 的解，则称问题具备最优子结构。
:::

::: def 定义 5.1.2 · 贪心选择性质 (Greedy Choice Property) {#def-algorithms.2.5.1.2}

全局最优解可以通过一系列局部最优（贪心）的选择达到。换言之，**存在至少一个全局最优解，包含了算法做出的第一个贪心选择**。
贪心算法与动态规划的根本区别在于：动态规划每一步的选择依赖于所有子问题的解（自底向上），而贪心算法先做出局部最优选择，然后再去解决剩下的唯一一个子问题（自顶向下，绝不回头）。
:::

## 5.2 交换论证法（Exchange Argument）的形式化证明框架 {#sec-algorithms.2.5.2}

证明贪心算法正确性的黄金法则是**交换论证法（Exchange Argument）**。

::: method 方法 5.2.1 · 交换论证四步法模板 {#method-algorithms.2.5.2.1}

1. **设定记号**：设贪心算法生成的解为 $G = (g_1, g_2, \ldots, g_k)$；假设存在一个任意的全局最优解 $O = (o_1, o_2, \ldots, o_m)$。
2. **定位首个分歧**：若 $G = O$，则定理自明。否则，找到第一个使得 $g_i \neq o_i$ 的下标 $i$。
3. **构造局部交换**：在 $O$ 中寻找合适元素，用 $g_i$ 替换该元素（或将其调整位置），构造出一个新的合法解 $O'$。
4. **证明价值不减**：证明新解的目标函数值 $\text{val}(O') \ge \text{val}(O)$（在最大化问题中）或 $\text{val}(O') \le \text{val}(O)$（在最小化问题中）。由于 $O$ 已是最优，故 $\text{val}(O') = \text{val}(O)$，说明 $O'$ 也是最优解，且 $O'$ 与 $G$ 的前 $i$ 项完全一致。通过数学归纳法，可知最终能将 $O$ 变为 $G$ 而不损失最优性，故 $G$ 也是全局最优解。
:::

### 经典案例：区间调度问题（Interval Scheduling）

给定 $n$ 个活动，每个活动有开始时间 $s_i$ 与结束时间 $f_i$。两个活动兼容当且仅当它们的时间区间不重叠。目标是选取最大数量的互不重叠活动。

::: thm 定理 5.2.1 · 最早结束时间优先贪心算法的最优性 {#thm-algorithms.2.5.2.1}

每次在与已有已选活动兼容的剩余活动集合中，选择**结束时间最早（Earliest Finish Time, EFT）**的活动，该贪心策略必能得到互不重叠活动数量的最大化。
:::

::: proof 证明 · 交换论证 {#proof-algorithms.2.5.2.1}

**基步与归纳假设**：
设贪心解为 $G = (g_1, g_2, \ldots, g_k)$，最优解为 $O = (o_1, o_2, \ldots, o_m)$，其中两组活动均已按开始时间从小到大排序。我们希望证明 $|G| = |O|$，即 $k = m$。显然 $k \le m$。

我们通过归纳法证明：对任意 $1 \le r \le k$，存在一个最优解，其前 $r$ 个活动与 $G$ 的前 $r$ 个活动完全相同。

**第 1 步交换**：
考虑 $r=1$。贪心解选择的是全集中结束时间最早的活动 $g_1$，因此 $f(g_1) \le f(o_1)$。
我们将 $O$ 中的首个活动 $o_1$ 替换为 $g_1$，得到新集合 $O' = (g_1, o_2, o_3, \ldots, o_m)$。
由于 $f(g_1) \le f(o_1) \le s(o_2)$，新加入的 $g_1$ 与 $o_2$ 以及后续所有活动互不重叠。
因此 $O'$ 依然是合法兼容的活动集合，且活动总数仍为 $m$。$O'$ 也是一个全局最优解，且首个活动与 $G$ 一致。

**归纳递推**：
假设存在最优解 $O$ 其前 $r-1$ 个活动与 $G$ 完全相同，即 $o_1 = g_1, \ldots, o_{r-1} = g_{r-1}$。
在选择第 $r$ 个活动时，贪心算法从与 $g_{r-1}$ 兼容的所有候选活动中，挑选了结束时间最早的 $g_r$。
因此在相容候选集中，$f(g_r) \le f(o_r)$。
用 $g_r$ 替换 $o_r$ 得到 $O' = (g_1, \ldots, g_{r-1}, g_r, o_{r+1}, \ldots, o_m)$。
因为 $f(g_r) \le f(o_r) \le s(o_{r+1})$，集合中的活动互不冲突。新解 $O'$ 依然合法且大小为 $m$。

**终止与规模相等**：
归纳成立至 $r = k$。如果 $m > k$，则最优解在 $g_k$ 之后还至少存在一个活动 $o_{k+1}$。
这意味着活动 $o_{k+1}$ 与 $g_k$ 兼容，且未被选取。但根据贪心终止条件，贪心算法只有在不存在任何与 $g_k$ 兼容的剩余活动时才会停止。矛盾！
因此必定有 $k = m$。贪心算法得到的解是全局最优解。
:::

## 5.3 单机调度问题与加权排序策略（Smith 规则） {#sec-algorithms.2.5.3}

考虑单台处理器上的单机调度问题（Minimizing Sum of Weighted Completion Times）：
给定 $n$ 个任务，每个任务需要处理时间 $p_i > 0$，具有权重 $w_i > 0$（代表该任务每延迟 1 个单位时间所产生的财务惩罚）。
如果任务的执行次序为排列 $\pi = (\pi(1), \pi(2), \ldots, \pi(n))$，则第 $j$ 个执行的任务的完工时间为 $C_{\pi(j)} = \sum_{k=1}^j p_{\pi(k)}$。
目标是找到一个排列 $\pi$，使得加权完工时间总和最小化：
$$
\min_{\pi} \sum_{j=1}^n w_{\pi(j)} C_{\pi(j)}
$$

### 交换论证推导 Smith 规则

直觉上，我们有两个彼此冲突的贪心启发式：
- 启发式 A：短作业优先（SJF）——让 $p_i$ 小的先跑，能让后续任务的完工时间迅速减小；
- 启发式 B：高权重优先（MWF）——让 $w_i$ 大的先跑，避免大权重的任务遭受漫长等待。

如何在这两个维度之间取得精准平衡？我们直接使用邻项交换论证（Adjacent Exchange Argument）。

::: thm 定理 5.3.1 · Smith 规则（Smith's Rule, 1956） {#thm-algorithms.2.5.3.1}

将所有任务按照比值 $\frac{w_i}{p_i}$ 从大到小降序排列执行，得到的调度方案是全局最优的。
:::

::: proof 证明 · 邻项交换法 {#proof-algorithms.2.5.3.1}

设最优调度方案为 $\pi$。假设在 $\pi$ 中存在相邻两个任务 $i = \pi(j)$ 与 $k = \pi(j+1)$，使得它们不满足贪心比值降序，即：
$$
\frac{w_i}{p_i} < \frac{w_k}{p_k} \iff w_i p_k < w_k p_i
$$
现在构造一个新的调度方案 $\pi'$，仅交换任务 $i$ 与任务 $k$ 的顺序，其余所有任务的位置与顺序保持完全不变。

分析交换对各个任务完工时间与目标函数的影响：
1. 对于排在 $i$ 之前的所有任务 $m \in \{1, \ldots, j-1\}$，完工时间 $C_m$ 完全不受影响。
2. 对于排在 $k$ 之后的所有任务 $m \in \{j+2, \ldots, n\}$，其前面的总耗时依然为 $\sum_{m \le j+1} p_m$，因此其完工时间 $C_m$ 也完全不受影响。
3. 发生变化的仅是任务 $i$ 与任务 $k$ 本身：
   - 交换前：$C_i = t + p_i$，$C_k = t + p_i + p_k$（其中 $t$ 为前 $j-1$ 个任务的总耗时）；
   - 交换后：$C_k' = t + p_k$，$C_i' = t + p_k + p_i$。

计算目标函数的增量差值 $\Delta = \text{Cost}(\pi') - \text{Cost}(\pi)$：
$$
\begin{aligned}
\Delta &= \left( w_k C_k' + w_i C_i' \right) - \left( w_i C_i + w_k C_k \right) \\
&= w_k (t + p_k) + w_i (t + p_k + p_i) - \left[ w_i (t + p_i) + w_k (t + p_i + p_k) \right] \\
&= w_i p_k - w_k p_i
\end{aligned}
$$
由于已知 $w_i p_k < w_k p_i$，故必有：
$$
\Delta = w_i p_k - w_k p_i < 0 \implies \text{Cost}(\pi') < \text{Cost}(\pi)
$$
这意味着交换后的解 $\pi'$ 的总代价严格小于原解 $\pi$！这与 $\pi$ 是最优解的假设相矛盾。
因此，在最优解中不可能存在任何相邻逆序对 $\frac{w_i}{p_i} < \frac{w_k}{p_k}$。当所有比值均严格不同时，按比值降序排列的贪心解是唯一的全局最优解。
:::

## 5.4 Huffman 最优前缀编码与树形贪心 {#sec-algorithms.2.5.4}

数据压缩中的经典问题：给定字母表 $\Sigma$ 及其出现频率 $\{f_c\}_{c \in \Sigma}$，求一个二叉前缀码树，使得编码后的平均文本长度 $\sum_{c \in \Sigma} f_c \cdot d(c)$ 最小化（其中 $d(c)$ 为字符 $c$ 在树中的深度/编码位数）。

::: method 机制 5.4.1 · Huffman 算法步骤 {#method-algorithms.2.5.4.1}

1. 将每个字符看作一个单节点二叉树，权值为其频率 $f_c$。所有节点放入小顶堆中。
2. 当小顶堆中元素个数大于 1 时：
   - 弹出频率最低的两个节点 $x$ 和 $y$；
   - 创建新父节点 $z$，其左孩子为 $x$，右孩子为 $y$，权值 $f_z = f_x + f_y$；
   - 将新节点 $z$ 插回小顶堆。
3. 堆中剩下的最后一个节点即为最优前缀码树的根节点。
:::

::: thm 引理 5.4.1 · 最低频兄弟引理 {#thm-algorithms.2.5.4.1}

设 $x, y$ 是字母表中出现频率最低的两个字符。则必定存在一棵全局最优的前缀码树，其中 $x$ 和 $y$ 是最深同胞兄弟（拥有相同深度的叶子节点，且共享同一个父节点）。
:::

证明思路依然是交换论证：若在某棵最优树中，$x$ 和 $y$ 不是最深兄弟，我们任取最深的一对兄弟 $a, b$。因为 $f_x \le f_a$ 且 $f_y \le f_b$，将 $x$ 与 $a$ 交换、$y$ 与 $b$ 交换，由于把高频字符移动到浅层、低频字符沉到底层，总编码代价必定只减不增。

## 5.5 最小生成树与切分定理 {#sec-algorithms.2.5.5}

连通无向图 $G = (V, E)$ 的最小生成树（MST）是包含所有顶点且边权总和最小的无环子图。

::: def 定理 5.5.1 · 切分定理 (Cut Property) {#def-algorithms.2.5.5.1}

设图 $G$ 的一个割（Cut）为点集的二划分 $(S, V \setminus S)$。若边 $e = (u, v)$ 是所有跨越该割的边中**权值严格最小的横截边（Light Edge）**，则该边必然属于图 $G$ 的某一棵最小生成树。
:::

- **Kruskal 算法**：全局视角。按边权升序排序，每次挑选一条未加入的最小边，若其端点属于不同的连通分量（用并查集判定），则安全加入生成树。
- **Prim 算法**：局部生长视角。从单点集合 $S = \{s\}$ 出发，维护跨越当前割 $(S, V \setminus S)$ 的边集，每次通过优先队列贪心选取权值最小的横截边扩充 $S$。

## 5.6 拟阵系统（Matroid）与贪心代数边界 {#sec-algorithms.2.5.6}

为什么有些子集选择问题贪心绝对正确（如 Kruskal 最小生成树），而另一些子集选择问题贪心彻底崩溃？代数上的解释是**拟阵（Matroid）**。

::: def 定义 5.6.1 · 拟阵公理体系 (Matroid) {#def-algorithms.2.5.6.1}

一个拟阵 $M = (E, \mathcal{I})$ 由有限基础集 $E$ 与独立集族 $\mathcal{I} \subseteq 2^E$ 组成，满足以下三条公理：
1. **非空性**：$\emptyset \in \mathcal{I}$。
2. **遗传性 (Hereditary)**：若 $A \in \mathcal{I}$ 且 $B \subseteq A$，则 $B \in \mathcal{I}$。
3. **交换性 / 增广性 (Exchange Property)**：若 $A, B \in \mathcal{I}$ 且 $|A| < |B|$，则必存在元素 $x \in B \setminus A$，使得 $A \cup \{x\} \in \mathcal{I}$。
:::

::: thm 定理 5.6.1 · Rado-Edmonds 定理 (1971) {#thm-algorithms.2.5.6.1}

设每个元素 $e \in E$ 有正权值 $w(e) > 0$。求一个权重之和最大的独立集 $I \in \mathcal{I}$。
**对于任意权值分配，简单贪心算法（按权重降序尝试加入，只要保持独立性就采纳）均能产生全局最大权独立集，当且仅当 $(E, \mathcal{I})$ 是一个拟阵。**
:::

图的无环边集构成**图形拟阵（Graphic Matroid）**，因此 Kruskal 算法求最小/最大生成树具有理论最优保证；而图的匹配（Matching）不满足增广公理（不是拟阵），因此贪心匹配无法保证最大权。

## 5.7 经典失效案例与系统化反例构造 {#sec-algorithms.2.5.7}

面对一个新问题，如果直觉给出一个贪心算法，我们该如何迅速构造反例把它推翻？

### 反例 1：加权区间调度（Weighted Interval Scheduling）

- **贪心策略**：继续按照最早结束时间（EFT）选择，或者按单位时间权重 $\frac{w_i}{f_i - s_i}$ 排序。
- **反例构造**：
  - 活动 1：$[0, 10]$，权重 $W=100$；
  - 活动 2：$[1, 2]$，权重 $W=10$。
- **失效分析**：EFT 策略会先选活动 2（结束时间 2 < 10），导致高价值的活动 1 被冲突排除。最终收益为 10，而最优解为活动 1（收益 100）。贪心策略在加权场景下彻底失效，必须用动态规划 $O(n \log n)$ 求解。

### 反例 2：找零钱问题（Coin Change Problem）

- **贪心策略**：每次尽量找面值最大的硬币。对于标准人民币/美元币值 $(1, 5, 10, 20, 50, 100)$，由于构成了权威货币系统（Canonical Coin System），贪心是正确的。
- **反例构造**：给定面值体系 $\{1, 3, 4\}$，目标金额为 $6$。
- **贪心执行**：
  1. 选最大面值 $4$，剩余金额 $2$；
  2. 选面值 $1$，剩余金额 $1$；
  3. 选面值 $1$，剩余金额 $0$。
  - 贪心解使用 $3$ 枚硬币：$\{4, 1, 1\}$。
- **最优解**：选择两枚 $3$ 元硬币：$\{3, 3\}$，仅需 $2$ 枚硬币！贪心结果次优度达到 $50\%$。

### 反例 3：0-1 背包问题 vs 分数背包问题

- **贪心策略**：按单位重量价值（性价比 $\frac{v_i}{w_i}$）降序装入。
- **反例构造**：背包容量 $W = 50$。
  - 物品 1：重 10，价值 60（性价比 6.0）；
  - 物品 2：重 20，价值 100（性价比 5.0）；
  - 物品 3：重 30，价值 120（性价比 4.0）。
- **贪心执行**：优先装入物品 1（重 10），再装入物品 2（重 20），此时剩余容量 20 无法容纳物品 3（重 30）。贪心总价值为 $60 + 100 = 160$。
- **最优解**：装入物品 2 和物品 3，总重量 $20 + 30 = 50$，总价值 $100 + 120 = 220$！
- **本质根因**：0-1 背包的离散不可分割性使得贪心留下来的空隙无法被充分利用。只有当物品允许任意切分（分数背包）时，单位价值贪心才成立。

def activity_selection_greedy(activities: list[tuple[int, int]]) -> list[int]:
    """按结束时间升序排序的经典贪心"""
    sorted_act = sorted(enumerate(activities), key=lambda x: x[1][1])
    selected = []
    last_end = -1
    for idx, (start, end) in sorted_act:
        if start >= last_end:
            selected.append(idx)
            last_end = end
    return selected

## 5.9 Agent 陷阱案例：加权完成时间最小化的“直觉坍塌” {#sec-algorithms.2.5.9}

::: errata 真实提示词与生成缺陷分析
**用户 Prompt**：
> “写一个 Python 函数，安排单机上 $n$ 个任务的执行顺序。每个任务有执行时间 `duration` 和延迟惩罚权重 `weight`。请以最快速度最小化所有任务的加权等待与完工时间之和。”

**Agent 生成的典型错误代码**：
```python
def schedule_jobs_faulty(jobs):
    # Agent 直觉：短作业能让后续所有任务受益，所以按时间升序！
    # 如果时间相同，再按权重从大到小排。
    return sorted(jobs, key=lambda j: (j['duration'], -j['weight']))
```

**严重后果与排查流程**：
- *症状*：在简单随机数据集上测试，加权完成时间看起来比乱序执行显著降低；但在真实业务评测中，平均惩罚成本比最优方案高出 25%~40%。
- *根因*：Agent 仅考虑了“减少耗时”，而忽视了一个耗时虽短但权重极低的任务（例如 $p=1, w=1$），会无谓地阻挡一个权重极高但耗时稍长的任务（例如 $p=2, w=100$）。
- *反例数据*：
  - 任务 A: $p_A = 1, w_A = 1$（Agent 优先调度 A）
  - 任务 B: $p_B = 2, w_B = 10$
  - Agent 方案 $(A, B)$：$C_A = 1, C_B = 3$，加权和 $= 1 \times 1 + 10 \times 3 = 31$。
  - 最优方案 $(B, A)$：$C_B = 2, C_A = 3$，加权和 $= 10 \times 2 + 1 \times 3 = 23$。
- *正确修复*：必须严格使用 Smith 规则，以 $\frac{w_i}{p_i}$（或等价于先比较交叉乘积 $w_i p_k$）降序排列：
```python
def schedule_jobs_correct(jobs):
    # 正确做法：按单位时间的惩罚权重降序排列
    return sorted(jobs, key=lambda j: j['weight'] / j['duration'], reverse=True)
```

## 5.11 本章陷阱 {#sec-algorithms.2.5.11}

::: errata 本章陷阱

1. **未证明贪心选择性质就写代码**：直觉看起来对的贪心策略，在 90% 的复杂问题上都有反例。
2. **以为局部最好等同于全局最好**：在图最短路中，局部选权值最小的边（贪心走下一步）会导致陷入死胡同或长环。
3. **加权区间调度误用无权贪心**：活动一旦带权，最早结束时间优先完全失效，必须用动态规划。
4. **找零钱问题硬套贪心**：任意自定义面值体系（非标准权威系统）下找零钱是完全背包的变种，贪心必次优。
5. **0-1 背包套用性价比贪心**：整数不可分割性导致背包剩余容量浪费，只能作为松弛上界，不能作为整数最优解。
6. **忽视浮点除法精度陷阱**：在按比值 $\frac{w_i}{p_i}$ 排序时，由于浮点精度损失导致排序不稳定，应尽量化除为乘比较交叉项。
7. **交换论证中漏掉“解的合法性”验证**：替换元素后只证明了目标函数不减，却忘记证明替换后的新解是否满足原始约束。
8. **把启发式算法误称为贪心算法**：在 TSP 等 NP 难问题上，最近邻居法只是局部搜索启发式，无法保证全局最优甚至无法保证有界近似比。
9. **Kruskal 算法未使用并查集导致退化**：每次判环使用全局 DFS（$O(V)$），使 MST 复杂度从 $O(E \log V)$ 退化到 $O(V \cdot E)$。
10. **小顶堆维护更新时产生死元素**：在贪心合并中直接更新堆元素，破坏了堆的不变性；应采用惰性删除或重入堆。
11. **单机加权调度忽略非整数工时**：在离散调度中遇到平局时未指定稳定的次级排序规则，引发测试不幂等。
12. **二分图最大匹配误用局部贪心**：任意匹配局部边会阻塞全局更优的增广路，必须使用匈牙利算法或网络流。

:::

**题目**：考虑背包容量为 $W=50$ 的 0-1 背包问题。现有三个物品：
- 物品 1：重 $w_1 = 10$，价值 $v_1 = 60$；
- 物品 2：重 $w_2 = 20$，价值 $v_2 = 100$；
- 物品 3：重 $w_3 = 30$，价值 $v_3 = 120$。
1. 请分别计算按“单位重量价值（性价比）贪心”的解与“全局最优解”的物品组合与总价值。
2. 解释为什么性价比贪心在分数背包上完全正确，但在 0-1 背包上会失效？

::: sol

**解答**：
1. **性价比计算**：
   - 物品 1：$v_1 / w_1 = 60 / 10 = 6.0$；
   - 物品 2：$v_2 / w_2 = 100 / 20 = 5.0$；
   - 物品 3：$v_3 / w_3 = 120 / 30 = 4.0$。
   - **贪心策略选择**：优先装入性价比最高的物品 1（占用重量 10，剩余容量 40），随后装入性价比次高的物品 2（占用重量 20，剩余容量 20）。此时剩余容量 20 无法放下重量为 30 的物品 3。
     贪心解总价值为：$60 + 100 = 160$，总重量 30。
   - **全局最优解**：挑选物品 2 和物品 3。总重量 $20 + 30 = 50 \le 50$。
     总价值为：$100 + 120 = 220$！贪心解比最优解低了 $\frac{220 - 160}{220} \approx 27.3\%$。

2. **失效根因分析**：
   - 在分数背包（Fractional Knapsack）中，物品允许任意分割，贪心算法填满物品 1 和物品 2 后，可以将物品 3 切出 $\frac{20}{30}$ 装满剩余 20 的空间，获得额外价值 $120 \times \frac{2}{3} = 80$，总价值 $240$，不会浪费任何一单位的载重能力；
   - 在 0-1 背包中，物品具有离散不可分割性。贪心算法选择物品 1 虽然局部性价比高，但留下了 20 的空隙无法塞入物品 3，空闲载重直接归零浪费，导致单位空闲损失超越了局部性价比优势。
