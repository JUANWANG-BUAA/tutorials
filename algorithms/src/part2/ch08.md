在经典的算法设计中，我们默认拥有**全知视角（Offline Setting）**：全部输入数据在算法启动前就已经静态摆放在内存中（例如对一个已有的数组排序，或在已知全部边权的图上求最短路）。

然而，绝大多数现代工业系统本质上是**在线系统（Online Systems）**：
- 操作系统不知道下一个访问的内存页是哪一个；
- 数据库连接池不知道下一个查询请求何时到达；
- 搜索引擎不知道用户接下来会输入什么关键词；
- 云计算平台必须在不知道未来任务负载的前提下，立即决定是否租用或释放虚拟机。

在未知未来的迷雾中，在线算法必须在每一步输入到达的瞬间，立即做出**不可撤销的决策**。评价这种不确定性决策优劣的核心理论武器就是**竞争分析（Competitive Analysis）**。

本章以 Allan Borodin & Ran El-Yaniv 经典著作《Online Computation and Competitive Analysis》与 CLRS 为母本，建立涵盖滑雪租赁、缓存分页、最优停止与在线匹配的完整在线算法体系。

```text
       时间流 t:  1      2      3      4      5  ......  T
                 │      │      │      │      │          │
                 ▼      ▼      ▼      ▼      ▼          ▼
  在线请求到达:  r_1    r_2    r_3    r_4    r_5 ...... r_T
                 │      │      │      │      │          │
                 ▼      ▼      ▼      ▼      ▼          ▼
  在线算法 (ALG): 立即做决策，不能修改历史，无法预知未来 (未知未来的盲棋)
                 └──────┬───────────────────────────────┘
                        │ 累计代价: Cost_ALG(sigma)
                        │
                        │ 竞争比对比 c = Cost_ALG / Cost_OPT
                        │
                 ┌──────┴───────────────────────────────┐
  全知离线 (OPT): 站在时间终点 T，拥有完整的"后见之明" (Hindsight Oracle)
                 计算全局最完美离线决策序列 -> Cost_OPT(sigma)
```

## 8.1 在线计算模型与竞争分析体系 {#sec-algorithms.2.8.1}

### 1. 竞争比的数学形式化

设输入请求序列为 $\sigma = (r_1, r_2, \ldots, r_m)$。
- $\text{ALG}(\sigma)$ 为在线算法在处理序列 $\sigma$ 时产生的总成本（最小化问题）或总收益（最大化问题）；
- $\text{OPT}(\sigma)$ 为一个拥有全知后见之明（Offline Optimal）的理想离线算法在相同序列 $\sigma$ 上能够取得的最优值。

::: def 定义 8.1.1 · 竞争比 (Competitive Ratio) {#def-algorithms.8.1.1}

对于**最小化成本问题**（如缓存未命中数、租用总金额），若对任意输入序列 $\sigma$，算法 $\text{ALG}$ 均满足：
$$
\text{ALG}(\sigma) \le c \cdot \text{OPT}(\sigma) + b
$$
（其中常数 $b$ 与输入序列长度无关），则称算法 $\text{ALG}$ 是 **$c$-竞争的（$c$-Competitive）**。
称 $c$ 为算法的竞争比。$c$ 越接近 1，算法在最坏情况下的表现越接近全知全能的上帝算法。

对于**最大化收益问题**（如在线拍卖、在线二分匹配），若满足：
$$
\text{ALG}(\sigma) \ge \frac{1}{c} \cdot \text{OPT}(\sigma) - b \quad (c \ge 1)
$$
则称其具有 $\frac{1}{c}$ 竞争比。
:::

### 2. 敌手模型（Adversary Models）

为了对在线算法进行最严酷的压力测试，理论上假设存在一个拥有无穷算力的**对抗敌手（Adversary）**。敌手知晓在线算法的代码逻辑，并针对算法的每一次决策，实时动态构造最恶毒的下一个输入 $r_{t+1}$。
- **遗忘型敌手（Oblivious Adversary）**：必须在实验开始前一次性生成完整的输入序列 $\sigma$；
- **适应型敌手（Adaptive Adversary）**：根据算法之前的实际随机选择，动态决定下一个输入。

## 8.2 滑雪租赁问题（Ski Rental）：租还是买？ {#sec-algorithms.2.8.2}

滑雪租赁是资本投资决策中最经典的在线问题：
去滑雪度假，每天需要雪板。你可以选择：
- **租雪板**：每天租金 1 美元；
- **买雪板**：一次性购买费用 $B$ 美元（购买后终身免费使用）。

困境在于：你**不知道自己未来一共会滑雪多少天（天数 $T$ 未知）**。如果第一天就买，万一第二天受伤不滑了，净亏 $B-1$；如果天天租，万一连续滑了几年，租金累积远超 $B$。

### 1. 最佳确定性在线策略（Break-even 规则）

::: thm 定理 8.2.1 · 滑雪租赁确定性 2-竞争比 {#thm-algorithms.8.2.1}

**最优确定性策略**：连续租用雪板 $B - 1$ 天；如果在第 $B$ 天你依然决定去滑雪，则在第 $B$ 天早晨立即买下雪板。
该策略的竞争比严格为：
$$
c = \frac{2B - 1}{B} < 2
$$
且没有任何确定性在线算法能做到比 $\frac{2B - 1}{B}$ 更好的竞争比！
:::

::: proof 证明 · 分类放缩 {#proof-algorithms.8.2.1}

设实际滑雪天数为 $T$。
- **情形 1：$T < B$（提前结束）**：
  - 在线算法连续租了 $T$ 天，总支出为 $\text{ALG} = T$ 美元。
  - 离线全知算法知道 $T < B$，最优决策显然是天天租，$\text{OPT} = T$。
  - 竞争比：$\frac{\text{ALG}}{\text{OPT}} = \frac{T}{T} = 1$。
- **情形 2：$T \ge B$（长期滑雪）**：
  - 在线算法租了 $B - 1$ 天，并在第 $B$ 天花费 $B$ 购买，后续免费。总支出为：
    $$
    \text{ALG} = (B - 1) + B = 2B - 1
    $$
  - 离线全知算法知道 $T \ge B$，最优决策在第 1 天就直接购买，$\text{OPT} = B$。
  - 竞争比：
    $$
    \frac{\text{ALG}}{\text{OPT}} = \frac{2B - 1}{B} = 2 - \frac{1}{B} < 2
    $$
综上，在所有可能的未知天数下，在线算法的开销永远不会超过上帝最优开销的 2 倍。
:::

### 2. 随机化破界（Karlin et al., 1988）

通过引入随机化策略——以特定概率分布在第 $i$ 天随机买入（概率密度正比于 $\left(\frac{B-1}{B}\right)^{B-i}$），可以将期望竞争比从 $2$ 突破到：
$$
c_{\text{rand}} = \frac{e}{e - 1} \approx 1.58
$$

## 8.3 缓存分页问题（Paging Problem）：下界与策略 {#sec-algorithms.2.8.3}

计算机内存管理中，高速缓存容量为 $k$ 个页面。程序产生一系列页面访问请求 $\sigma = (p_1, p_2, \ldots)$。
当请求的页面 $p_t$ 不在缓存中时，发生**缺页异常（Page Fault）**，必须从慢速磁盘加载该页，并在缓存已满时淘汰（Evict）一个旧页面。
目标是**使总缺页次数最小化**。

### 1. 离线全知最优解：Belady's OPT 算法 (MIN)

1966 年，L. A. Belady 证明离线最优策略是：**淘汰未来下一次被访问时间离当前最遥远的页面**。
Belady 算法是所有缓存策略的理论上限（Oracle）。

### 2. 确定性在线分页算法的不可逾越下界

::: thm 定理 8.3.1 · 确定性分页算法的 k 下界定理 {#thm-algorithms.8.3.1}

设缓存大小为 $k$。对于**任意确定性在线分页算法 $\mathcal{A}$**，其竞争比至少为 $k$：
$$
c_{\mathcal{A}} \ge k
$$
:::

::: proof 证明 · 对抗环路构造 {#proof-algorithms.8.3.1}

敌手只需使用 $k + 1$ 个不同的页面集合 $P = \{1, 2, \ldots, k+1\}$。
在每一步 $t$：
- 确定性算法 $\mathcal{A}$ 的缓存中最多只能容纳 $k$ 个页面，因此在 $k+1$ 个页面中，**必定存在唯一一个不在算法缓存中的页面 $p^*$**。
- 敌手在下一步精确发起对该页面 $p^*$ 的访问请求！
- 算法 $\mathcal{A}$ 被迫发生一次缺页异常，并淘汰一个旧页面。
- 敌手周而复始，使得算法 $\mathcal{A}$ 的**每一次请求都必然发生缺页**！在长度为 $N$ 的请求序列中，$\text{ALG} = N$。

现在分析全知离线算法 $\text{OPT}$ 在相同序列上的表现：
每次 $\text{OPT}$ 发生缺页时，它在剩余的 $k$ 个候选页中，淘汰未来最久才会访问的那个页面。
因为总共只有 $k+1$ 个页面，被 $\text{OPT}$ 淘汰的页面在未来至少 $k$ 步之内绝不会被敌手访问（因为敌手必须先把当前在缓存里的另外 $k-1$ 个页面逐一访问一遍之后，才可能轮到该页面）。
因此，$\text{OPT}$ 每发生一次缺页，至少保证后续 $k$ 步内绝不缺页！
$$
\text{OPT} \le \frac{N}{k}
$$
计算竞争比：
$$
\frac{\text{ALG}}{\text{OPT}} \ge \frac{N}{N / k} = k
$$
证明完毕。
:::

## 8.4 LRU、FIFO 与 LFU 竞争比深度剖析 {#sec-algorithms.2.8.4}

| 算法 | 淘汰准则 | 确定性竞争比 | 工业表现 | 致命弱点 |
|:--|:--|:--|:--|:--|
| **LRU (最近最少使用)** | 淘汰最久未被访问的页 | 严格 **$k$**（达到理论最优） | 优异（强时间局部性） | 周期性全表扫描导致缓存污染 |
| **FIFO (先进先出)** | 淘汰最早进入缓存的页 | 严格 **$k$**（达到理论最优） | 一般 | Belady 异常（增加缓存缺页反增） |
| **LFU (最不经常使用)** | 淘汰历史累计访问频次最低的页 | **无界 ($\infty$)** | 差 | 历史幽灵污染（老热点霸占缓存） |

### 为什么 LFU 的竞争比是无界（$\infty$）的？

很多开发者直觉认为“按访问频度淘汰最科学”。但在对抗分析中，LFU 是最脆弱的算法：
- 敌手在开始阶段对页面 $A$ 和 $B$ 疯狂访问 10,000 次，使它们的计数值膨胀到 10,000；
- 随后，程序进入全新阶段，开始在 $k$ 个新页面之间交替循环；
- 页面 $A$ 和 $B$ 虽然未来再也不会被访问，但由于历史频次极高，LFU 永远不肯淘汰它们，导致可用有效缓存只剩下 $k-2$；
- 竞争比直接发散到无穷大！

## 8.5 随机化标记算法（Marking Algorithm）：突破确定性下界 {#sec-algorithms.2.8.5}

面对确定性算法被敌手卡死的 $k$ 下界，如何破局？答案是**随机化（Randomization）**。

::: method 算法 8.5.1 · 随机化标记算法 (Marking Algorithm, Fiat et al., 1991) {#method-algorithms.8.5.1}

算法将请求流划分为若干个**相（Phases）**。每个缓存槽位有 1 位 `mark` 标记（初始全为 0）：
1. 当请求页面 $p$ 时：
   - 若 $p$ 已在缓存中：将 $p$ 标记为 `mark = 1`；
   - 若 $p$ 发生缺页且缓存有未标记页面：**从所有未标记（`mark == 0`）的页面中，等概率随机挑选一个淘汰**，载入 $p$ 并标记为 `mark = 1`；
   - 若当前缓存中**全部页面都已被标记（全部为 1）**：当前相结束！将所有页面的标记全部清零（`mark = 0`），开启一个全新的相，并将 $p$ 标记为 1。
:::

::: thm 定理 8.5.1 · 标记算法竞争比定理 {#thm-algorithms.8.5.1}

随机化标记算法在任意对抗输入序列上的期望竞争比为：
$$
c_{\text{marking}} \le 2 H_k = 2 \sum_{i=1}^k \frac{1}{i} \approx 2 \ln k + 2\gamma
$$
当缓存容量 $k = 1024$ 时：
- 确定性算法的最坏竞争比为 $k = 1024$；
- 随机化标记算法的竞争比仅为 $2 \ln(1024) \approx 13.8$！
**随机化将竞争比从线性量级压制到了对数级！**
:::

## 8.6 秘书问题与最优停止理论（Secretary Problem） {#sec-algorithms.2.8.6}

### 问题建模

有 $n$ 位求职者按随机顺序逐个进行面试。
- 每面试完一位，你必须**立即决定是否录用她**；
- 一旦拒绝，永远不能反悔召回；一旦录用，面试立刻终止；
- 你的目标只有一个：**以最高概率挑选到全集 $n$ 个人中唯一的那个全局最佳求职者**。

### 最优停止策略：$1/e$ 观察法

先面试前 $k$ 个人，无论她们多么优秀，全部拒绝，仅将其表现作为**基准线（Benchmark）**，记录前 $k$ 个人中的最高分 $M = \max_{1 \le i \le k} \text{score}(i)$。
从第 $k+1$ 个人开始，**只要遇到第一个超越基准线 $M$ 的人，立即录用！**

::: thm 定理 8.6.1 · 最优切分比例与 1/e 概率推导 {#thm-algorithms.8.6.1}

成功挑中最佳候选人的全局概率为：
$$
P(k) = \sum_{j=k+1}^n \Pr(\text{第 } j \text{ 个人是最佳}) \cdot \Pr(\text{在前 } j-1 \text{ 个人中未录用任何人})
$$
第 $j$ 个人是全局最佳的概率为 $\frac{1}{n}$；在前 $j-1$ 个人中未录用任何人，当且仅面前 $j-1$ 个人里的局部最佳出现在前 $k$ 个人中（概率为 $\frac{k}{j-1}$）：
$$
P(k) = \sum_{j=k+1}^n \frac{1}{n} \cdot \frac{k}{j - 1} = \frac{k}{n} \sum_{j=k}^{n-1} \frac{1}{j}
$$
令 $x = \frac{k}{n}$。在大样本 $n \to \infty$ 下，积分化为：
$$
P(x) = x \int_x^1 \frac{1}{t} dt = -x \ln x
$$
求导寻找极值点：
$$
\frac{d P(x)}{dx} = -\ln x - 1 = 0 \implies \ln x = -1 \implies x^* = \frac{1}{e} \approx 0.368
$$
代回概率值：
$$
P(x^*) = -\frac{1}{e} \ln\left(\frac{1}{e}\right) = \frac{1}{e} \approx 36.8\%
$$
**结论**：在面试前 $36.8\%$ 的人建立基准后立即出手，挑中全局最佳的概率高达 $36.8\%$！
:::

## 8.7 在线二分图匹配：KVV Ranking 算法 {#sec-algorithms.2.8.7}

在互联网广告实时竞价（AdWords 投放）中：左侧为广告商（离线已知），右侧为搜索查询词（实时逐个到达）。
每当一个查询词到达时，必须立刻在与其有出边的可用广告商中挑选一个匹配。
- **朴素贪心算法**：任意匹配一条可用边，竞争比仅为 $0.5$；
- **KVV 算法（Karp, Vazirani, Vazirani, 1990）**：在开始前为所有左侧广告商随机分配一个排列次序（Ranking），在线匹配时**永远挑选 Rank 最高的可用广告商**。
  其竞争比数学证明达到严格的：
  $$
  1 - \frac{1}{e} \approx 0.632
  $$

## 8.8 真实访问 Trace 评测实验 {#sec-algorithms.2.8.8}

我们在真实 Redis 缓存仿真器上，测试包含 100,000 次请求的混合负载：

```python
# experiments/ch08/online_cache_benchmark.py 片段
from collections import OrderedDict
import random

class LRUCache:
    def __init__(self, capacity: int):
        self.cap = capacity
        self.cache = OrderedDict()

    def get(self, key: int) -> bool:
        if key not in self.cache:
            return False # Miss
        self.cache.move_to_end(key)
        return True # Hit

    def put(self, key: int):
        if key in self.cache:
            self.cache.move_to_end(key)
        else:
            if len(self.cache) >= self.cap:
                self.cache.popitem(last=False) # 淘汰最久未访问
            self.cache[key] = True
```

## 8.9 Agent 陷阱案例：忽略概念漂移的死锁 LFU {#sec-algorithms.2.8.9}

::: errata 真实生产代码与生成缺陷分析
**用户 Prompt**：
> “为我们的高并发 API 网关设计一个内存缓存。请实现 LFU 算法，保证经常被访问的接口永远常驻内存。”

**Agent 生成的典型错误代码**：
```python
class FaultyLFUCache:
    def __init__(self, capacity: int):
        self.cap = capacity
        self.freq = {}
        self.data = {}

    def get(self, key):
        if key in self.data:
            self.freq[key] += 1
            return self.data[key]
        return None

    def put(self, key, val):
        if self.cap <= 0: return
        if key in self.data:
            self.data[key] = val
            self.freq[key] += 1
            return
        if len(self.data) >= self.cap:
            # 淘汰累积频次最低的 key
            min_key = min(self.freq, key=self.freq.get)
            del self.data[min_key]
            del self.freq[min_key]
        self.data[key] = val
        self.freq[key] = 1
```

**灾难后果与排查流程**：
- *症状*：早晨系统遭遇了一次瞬时爬虫爆刷，某些接口的 `freq` 被刷到 50,000。到了下午，爬虫停止，正常用户的新业务请求涌入。新页面的 `freq` 从 1 开始累加，在缓存已满时，`min_key` 永远是这些刚进来的新页面，导致**新业务请求发生 100% 缓存穿透，系统雪崩**。
- *根因*：经典的 LFU 历史幽灵污染，缺乏**衰减（Decay）或老化（Aging）机制**。
- *正确修复*：工业级实现必须采用 **W-TinyLFU（Caffeine 核心算法）**，引入基于 Count-Min Sketch 的滑动时间窗口衰减机制，或者直接使用 LRU。
:::

## 8.11 陷阱清单 {#sec-algorithms.2.8.11}

::: note 在线算法避坑速查表
1. **朴素 LFU 缺少衰减机制**：历史热点霸占缓存槽位，新热点无法进入，导致缓存穿透雪崩。
2. **在流式数据中盲目假设 IID 分布**：现实请求具有强烈的爆发性（Burstiness）与概念漂移，纯统计均值快速失效。
3. **FIFO 算法遭遇 Belady 异常**：增加缓存大小反而导致总缺页次数增加。
4. **秘书问题基准期做出录用决策**：在建立基准的前 $36.8\%$ 阶段过早出手，丧失了探索价值。
5. **在线推荐中未探索冷门项**：纯利用（Exploitation）导致推荐系统信息茧房与多样性枯竭。
6. **滑雪租赁过早买入**：在极小概率发生的单次任务中过早投入固定资产，导致沉没成本高昂。
7. **对等对抗与自适应对抗混淆**：评估随机化在线算法时，未明确敌手是否能观测到算法的内部随机种子。
8. **LRU 缓存底层使用链表遍历**：查找操作未使用哈希表索引，导致每次 `get` 退化为 $O(k)$ 链表扫描。
9. **在线匹配未去重候选队列**：导致已经匹配成功的资源被重复二次分配引发并发冲突。
10. **误将离线最佳 OPT 当做线上可达目标**：拿只有上帝才能做到的后见之明指标苛求在线系统。
:::
