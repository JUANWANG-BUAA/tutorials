## 10.1 假设检验基础：H0/H1、p 值与错误类型 {#sec-algorithms.10.1}

假设检验是统计推断的核心工具：给定数据，判断一个关于总体的假设是否成立。经典的误区是"p < 0.05 就是对的"——p 值只是在 H0 为真的假设下，观察到当前数据（或更极端）的概率，它不直接告诉你 H0 或 H1 哪个为真。

### 零假设与备择假设

::: def 定义 10.1.1 · 零假设与备择假设 {#def-algorithms.10.1.1}

**零假设（null hypothesis, H0）**：待检验的默认假设，通常表示"无效应"或"无差异"。

**备择假设（alternative hypothesis, H1 或 Ha）**：与 H0 相对的假设，通常表示"有效应"或"有差异"。

检验的目标是判断数据是否提供了足够的证据来**拒绝 H0**。

:::

::: ex 例 10.1.1 · 算法性能比较的假设 {#ex-algorithms.10.1.1}

比较算法 A 和算法 B 的平均运行时间 μ_A 和 μ_B：

- H0: μ_A = μ_B（两个算法性能无差异）
- H1: μ_A ≠ μ_B（两个算法性能有差异）

这是**双侧检验**（two-sided test）。如果只关心"A 是否更快"，则用**单侧检验**（one-sided test）：

- H0: μ_A ≥ μ_B
- H1: μ_A < μ_B

:::

注意逻辑：假设检验永远是「尝试拒绝 H0」，而不是「证明 H1」。未能拒绝 H0 不代表 H0 为真，只是"数据不足以推翻它"。

### p 值的定义

::: def 定义 10.1.2 · p 值 {#def-algorithms.10.1.2}

**p 值（p-value）**：在 H0 为真的假设下，观察到当前检验统计量（或更极端值）的概率。

$$
p = P(\text{观察到} \geq \text{当前统计量} \mid H_0 \text{ 为真})
$$

p 值越小，数据与 H0 的矛盾越大。

:::

**常见误解**：p = 0.03 不是"H0 为真的概率为 3%"，也不是"H1 为真的概率为 97%"。p 值是在 H0 为真的条件下计算的，它不能直接告诉你 H0 或 H1 的后验概率（那需要贝叶斯推断，见第 12 章）。

::: def 定义 10.1.3 · 显著性水平 {#def-algorithms.10.1.3}

**显著性水平（significance level, α）**：预先设定的拒绝 H0 的阈值。若 p < α，则拒绝 H0。

常用 α = 0.05，表示"愿意承受 5% 的 I 类错误率"。

:::

决策规则：

- **p < α**：拒绝 H0，认为数据提供了足够证据支持 H1。
- **p ≥ α**：不拒绝 H0（注意不是"接受 H0"）。

### I 类错误与 II 类错误

假设检验有两种可能的错误：

::: def 定义 10.1.4 · I 类错误与 II 类错误 {#def-algorithms.10.1.4}

|           | H0 为真        | H1 为真        |
|-----------|----------------|----------------|
| 拒绝 H0   | **I 类错误**（α）| 正确决策（power）|
| 不拒绝 H0 | 正确决策       | **II 类错误**（β）|

- **I 类错误（Type I error, false positive）**：H0 为真但被拒绝。概率为 α（显著性水平）。
- **II 类错误（Type II error, false negative）**：H1 为真但未拒绝 H0。概率为 β。
- **统计功效（power）**：H1 为真时正确拒绝 H0 的概率，等于 1 - β。

:::

权衡：降低 α（更严格的阈值）会减少假阳性，但增加假阴性（β 上升）；增加样本量可以同时降低两种错误。

::: ex 例 10.1.2 · 医疗诊断类比 {#ex-algorithms.10.1.2}

- H0：患者健康
- H1：患者患病
- I 类错误：健康的人被诊断为有病（假阳性）
- II 类错误：患病的人未被诊断出来（假阴性）

在算法评估中：

- I 类错误：声称算法 A 更好，但实际无差异（浪费资源切换）
- II 类错误：算法 A 确实更好，但检验未发现（错失优化机会）

:::

### 实验验证：I 类错误率

理论上，当 H0 为真时，使用 α = 0.05 的检验会在 5% 的实验中错误拒绝 H0。我们通过模拟验证：

```python
# experiments/ch10/hypothesis_lab.py
import numpy as np
from scipy import stats

def simulate_type_i_error(n_samples=30, n_experiments=10000, alpha=0.05):
    reject_count = 0
    for _ in range(n_experiments):
        # 从 H0 分布采样：N(0, 1)
        sample = np.random.normal(0, 1, n_samples)
        # 单样本 t 检验：H0: μ = 0
        _, p_value = stats.ttest_1samp(sample, 0.0)
        if p_value < alpha:
            reject_count += 1
    return reject_count / n_experiments
```

运行 10000 次实验，实测 I 类错误率应接近 0.05。

## 10.2 t 检验：单样本、双样本与配对 {#sec-algorithms.10.2}

t 检验是最常用的参数检验方法，适用于比较均值。它假设数据服从正态分布（或样本量足够大，由中心极限定理近似正态）。

### 单样本 t 检验

::: def 定义 10.2.1 · 单样本 t 检验 {#def-algorithms.10.2.1}

检验样本均值 μ 是否等于某个已知值 μ₀。

**检验统计量**：

$$
t = \frac{\bar{x} - \mu_0}{s / \sqrt{n}}
$$

其中：

- $\bar{x}$ 是样本均值
- $s$ 是样本标准差
- $n$ 是样本量

在 H0: μ = μ₀ 下，t 服从自由度为 n - 1 的 t 分布。

:::

::: ex 例 10.2.1 · 检验算法运行时间 {#ex-algorithms.10.2.1}

某算法理论复杂度预测运行时间为 100 ms。实测 10 次：[98, 102, 105, 97, 101, 99, 103, 100, 104, 98]。

- H0: μ = 100
- H1: μ ≠ 100

计算：

```python
data = [98, 102, 105, 97, 101, 99, 103, 100, 104, 98]
t_stat, p_value = stats.ttest_1samp(data, 100)
# t_stat ≈ 0.866, p_value ≈ 0.408
```

p = 0.408 > 0.05，不拒绝 H0，数据与理论预测一致。

:::

### 独立双样本 t 检验

比较两个独立样本的均值。

::: def 定义 10.2.2 · 独立双样本 t 检验 {#def-algorithms.10.2.2}

检验 H0: μ₁ = μ₂（两组均值相等）。

**检验统计量（等方差假设）**：

$$
t = \frac{\bar{x}_1 - \bar{x}_2}{s_p \sqrt{\frac{1}{n_1} + \frac{1}{n_2}}}
$$

其中 $s_p$ 是合并标准差：

$$
s_p = \sqrt{\frac{(n_1 - 1)s_1^2 + (n_2 - 1)s_2^2}{n_1 + n_2 - 2}}
$$

自由度为 $n_1 + n_2 - 2$。

若不假设等方差，使用 **Welch's t 检验**（自由度用 Welch-Satterthwaite 公式近似）。

:::

::: ex 例 10.2.2 · 比较两个算法 {#ex-algorithms.10.2.2}

算法 A 运行时间：[12.3, 15.1, 13.8, 14.5, 16.2, 12.9, 14.1, 13.5, 15.7, 14.3]

算法 B 运行时间：[18.5, 17.2, 19.1, 16.8, 18.9, 17.5, 19.3, 18.1, 17.9, 18.6]

```python
algo_a = [12.3, 15.1, 13.8, 14.5, 16.2, 12.9, 14.1, 13.5, 15.7, 14.3]
algo_b = [18.5, 17.2, 19.1, 16.8, 18.9, 17.5, 19.3, 18.1, 17.9, 18.6]

t_stat, p_value = stats.ttest_ind(algo_a, algo_b)
# t_stat ≈ -9.54, p_value ≈ 1.4e-08
```

p < 0.05，拒绝 H0，两组有显著差异。算法 A 明显更快。

:::

### 配对 t 检验

当两组数据是配对的（如同一组算法在不同输入上的运行时间），应使用配对 t 检验。

::: def 定义 10.2.3 · 配对 t 检验 {#def-algorithms.10.2.3}

对每对观测计算差值 $d_i = x_{1i} - x_{2i}$，然后对差值进行单样本 t 检验：

$$
t = \frac{\bar{d}}{s_d / \sqrt{n}}
$$

其中 $\bar{d}$ 是差值均值，$s_d$ 是差值标准差。

:::

::: ex 例 10.2.3 · 优化前后对比 {#ex-algorithms.10.2.3}

10 个测试用例，优化前后运行时间（毫秒）：

| 用例 | 优化前 | 优化后 | 差值 |
|------|--------|--------|------|
| 1    | 120    | 110    | 10   |
| 2    | 135    | 130    | 5    |
| ...  | ...    | ...    | ...  |

```python
before = [120, 135, 128, 142, 115, 150, 138, 125, 132, 145]
after = [110, 130, 125, 135, 112, 142, 130, 120, 128, 138]

t_stat, p_value = stats.ttest_rel(before, after)
# 检验差值是否显著不为 0
```

配对检验的功效通常高于独立样本检验，因为它消除了个体间的差异。

:::

### 假设检查：正态性与等方差

t 检验假设数据服从正态分布。当样本量较小（n < 30）且数据明显偏态时，t 检验的 I 类错误率可能偏离 α。

**检查方法**：

1. **可视化**：直方图、Q-Q 图
2. **正态性检验**：Shapiro-Wilk 检验（`scipy.stats.shapiro`）
3. **等方差检验**：Levene 检验（`scipy.stats.levene`）

若违反假设，考虑：

- 数据变换（如对数变换）
- 非参数检验（见 §10.3）
- Bootstrap 方法（见第 11 章）

## 10.3 Mann-Whitney U 检验：非参数替代 {#sec-algorithms.10.3}

当数据不满足正态性假设、或为序数数据时，使用非参数检验。Mann-Whitney U 检验（也称 Wilcoxon 秩和检验）是双样本 t 检验的非参数替代。

::: def 定义 10.3.1 · Mann-Whitney U 检验 {#def-algorithms.10.3.1}

检验两组样本是否来自相同分布（不要求正态性）。

**原理**：

1. 合并两组数据并排序
2. 计算每组的秩和（rank sum）
3. 用秩和构造 U 统计量

**零假设**：H0: P(X > Y) = 0.5（两组的中位数相同）

**备择假设**：H1: P(X > Y) ≠ 0.5

:::

::: ex 例 10.3.1 · 比较偏态数据 {#ex-algorithms.10.3.1}

两组运行时间来自指数分布（右偏）：

```python
# 生成偏态数据
group_a = np.random.exponential(2.0, 30)
group_b = np.random.exponential(2.5, 30)

# t 检验
t_stat, p_t = stats.ttest_ind(group_a, group_b)

# Mann-Whitney U 检验
u_stat, p_u = stats.mannwhitneyu(group_a, group_b, alternative='two-sided')
```

对于偏态数据，Mann-Whitney 更稳健，p 值更可信。

:::

**优点**：

- 不假设正态性
- 对异常值不敏感
- 适用于序数数据

**缺点**：

- 功效略低于 t 检验（当数据确实正态时）
- 只检验分布差异，不直接比较均值

**配对版本**：**Wilcoxon 符号秩检验**（`scipy.stats.wilcoxon`）是配对 t 检验的非参数版本。

## 10.4 多重检验校正：Bonferroni 与 FDR {#sec-algorithms.10.4}

当同时测试多个假设时，I 类错误率会累积。如果每个检验的 α = 0.05，测试 20 个假设，至少出现一个假阳性的概率（**家族错误率, FWER**）为：

$$
\text{FWER} = 1 - (1 - \alpha)^m \approx 1 - (0.95)^{20} \approx 0.64
$$

即使所有 H0 都为真，也有 64% 的概率至少错误拒绝一个！

### Bonferroni 校正

::: def 定义 10.4.1 · Bonferroni 校正 {#def-algorithms.10.4.1}

将每个检验的显著性水平调整为 α/m，其中 m 是检验次数。

**调整后拒绝规则**：当 $p_i < \frac{\alpha}{m}$ 时拒绝第 i 个 H0。

**保证**：FWER ≤ α（通过 Bonferroni 不等式）。

:::

::: ex 例 10.4.1 · 比较 20 个算法 {#ex-algorithms.10.4.1}

测试 20 个算法与基线的差异，α = 0.05。

- **无校正**：每个检验用 α = 0.05，期望 20 × 0.05 = 1 个假阳性。
- **Bonferroni 校正**：每个检验用 α = 0.05/20 = 0.0025，FWER ≤ 0.05。

代码：

```python
p_values = [...]  # 20 个 p 值
alpha = 0.05
m = len(p_values)

# Bonferroni 校正
bonf_threshold = alpha / m
rejections = [p < bonf_threshold for p in p_values]
```

:::

**优点**：简单、保守、控制 FWER。

**缺点**：过于保守，当 m 很大时功效很低（II 类错误率高）。

### Benjamini-Hochberg 过程（FDR 控制）

Bonferroni 控制的是 FWER（至少一个假阳性的概率），但在探索性研究中，我们更关心 **假发现率（False Discovery Rate, FDR）**：被拒绝的 H0 中，实际为真的比例。

::: def 定义 10.4.2 · Benjamini-Hochberg 过程 {#def-algorithms.10.4.2}

控制 FDR ≤ α 的步骤：

1. 将 m 个 p 值从小到大排序：$p_{(1)} \leq p_{(2)} \leq \cdots \leq p_{(m)}$
2. 找到最大的 i 使得 $p_{(i)} \leq \frac{i}{m} \alpha$
3. 拒绝对应的前 i 个假设

:::

::: ex 例 10.4.2 · BH 过程示例 {#ex-algorithms.10.4.2}

20 个 p 值，α = 0.05：

```
排序 p 值: 0.001, 0.003, 0.008, 0.012, 0.023, ..., 0.45
临界值:   0.0025, 0.005, 0.0075, 0.01, 0.0125, ...
```

找到最大的 i 使得 $p_{(i)} \leq \frac{i}{20} \times 0.05$：

- i = 1: 0.001 ≤ 0.0025 ✓
- i = 2: 0.003 ≤ 0.005 ✓
- i = 3: 0.008 ≤ 0.0075 ✗

拒绝前 2 个假设。

代码：

```python
from scipy.stats import false_discovery_control

# BH 校正（scipy 1.11+）
rejections = false_discovery_control(p_values, alpha=0.05)
```

或手动实现（见 `experiments/ch10/hypothesis_lab.py`）。

:::

**FDR vs FWER**：

- FWER：家族中至少一个假阳性的概率（严格）
- FDR：被拒绝的假设中假阳性的期望比例（宽松）

BH 过程比 Bonferroni 功效更高，适合探索性研究；Bonferroni 适合确证性研究（confirmatory study）。

### 何时需要校正？

**需要校正**：

- 同时测试多个算法/超参数/数据集
- 多次中期分析（peeking）
- 子组分析（按用户群体、输入类型等分组）

**不需要校正**：

- 预先指定的单一主要假设
- 不同研究的独立假设

**常见错误**：agent 生成的 A/B 测试代码会对多个指标（点击率、转化率、停留时间）分别做检验，但不做多重检验校正，导致假阳性率远超 α。

## 10.5 效应量：统计显著性 vs 实际意义 {#sec-algorithms.10.5}

p < 0.05 只表示"差异不太可能是随机产生的"，但不告诉你"差异有多大"。大样本下，微小的差异也能得到很小的 p 值；小样本下，巨大的差异可能 p > 0.05。

**效应量（effect size）** 量化了差异的实际大小，独立于样本量。

### Cohen's d

::: def 定义 10.5.1 · Cohen's d {#def-algorithms.10.5.1}

双样本 t 检验的标准化效应量：

$$
d = \frac{\bar{x}_1 - \bar{x}_2}{s_{\text{pooled}}}
$$

其中 $s_{\text{pooled}}$ 是合并标准差：

$$
s_{\text{pooled}} = \sqrt{\frac{(n_1 - 1)s_1^2 + (n_2 - 1)s_2^2}{n_1 + n_2 - 2}}
$$

**解释**（Cohen 的经验规则）：

- |d| < 0.2：小效应
- 0.2 ≤ |d| < 0.5：中等效应
- |d| < 0.8：中等偏大效应
- |d| ≥ 0.8：大效应

:::

::: ex 例 10.5.1 · p 值与效应量的关系 {#ex-algorithms.10.5.1}

**场景 1**：n₁ = n₂ = 1000，$\bar{x}_1 = 100$, $\bar{x}_2 = 101$, s = 10

$$
d = \frac{101 - 100}{10} = 0.1 \quad \text{（小效应）}
$$

但 t 统计量 ≈ 2.24，p ≈ 0.025 < 0.05（显著）。

**场景 2**：n₁ = n₂ = 10，$\bar{x}_1 = 100$, $\bar{x}_2 = 110$, s = 10

$$
d = \frac{110 - 100}{10} = 1.0 \quad \text{（大效应）}
$$

但 t 统计量 ≈ 2.24，p ≈ 0.049 勉强显著。

:::

**结论**：报告结果时必须同时给出 p 值和效应量。p < 0.05 但 d = 0.1 意味着"差异在统计上显著，但实际意义很小"。

### 其他效应量

- **Pearson's r**：相关系数，范围 [-1, 1]
- **η²（eta squared）**：ANOVA 中的效应量，解释方差的比例
- **Cliff's Delta**：非参数效应量，适用于序数数据

## 10.6 统计功效与样本量估计 {#sec-algorithms.10.6}

设计实验前应回答：「需要多少样本才能以高概率检测到实际存在的效应？」这需要 **统计功效分析（power analysis）**。

::: def 定义 10.6.1 · 统计功效 {#def-algorithms.10.6.1}

**统计功效（power）**：当 H1 为真时，检验正确拒绝 H0 的概率，记为 1 - β。

$$
\text{Power} = P(\text{拒绝} H_0 \mid H_1 \text{ 为真}) = 1 - \beta
$$

通常要求 power ≥ 0.8（80%）。

:::

功效受四个因素影响：

1. **效应量**：真实效应越大，功效越高
2. **样本量**：n 越大，功效越高
3. **显著性水平 α**：α 越大，功效越高（但 I 类错误增加）
4. **检验类型**：单侧检验功效高于双侧检验

### 样本量估计

给定效应量 d、α 和目标 power，计算所需样本量 n。

**双样本 t 检验的近似公式**：

$$
n \approx \frac{2(z_{\alpha/2} + z_{\beta})^2}{d^2}
$$

其中 $z_{\alpha/2}$ 和 $z_{\beta}$ 是标准正态分位数。

::: ex 例 10.6.1 · 样本量计算 {#ex-algorithms.10.6.1}

检测 Cohen's d = 0.5 的中等效应，α = 0.05，power = 0.8：

$$
n \approx \frac{2(1.96 + 0.84)^2}{0.5^2} \approx \frac{2 \times 7.84}{0.25} \approx 63
$$

每组需要约 63 个样本。

验证：用模拟或 `statsmodels.stats.power` 精确计算。

```python
from statsmodels.stats.power import ttest_power

power = ttest_power(effect_size=0.5, nobs=63, alpha=0.05, alternative='two-sided')
# power ≈ 0.80
```

:::

### 功效曲线

绘制功效随样本量或效应量变化的曲线，帮助理解实验设计的敏感性。

```python
import matplotlib.pyplot as plt
from statsmodels.stats.power import ttest_power

sample_sizes = range(10, 201, 10)
powers = [ttest_power(0.5, n, 0.05) for n in sample_sizes]

plt.plot(sample_sizes, powers)
plt.axhline(0.8, color='r', linestyle='--', label='Target power')
plt.xlabel('Sample size per group')
plt.ylabel('Power')
plt.legend()
plt.show()
```

**实践建议**：

- 根据先导研究或文献估计效应量
- 保守估计效应量（避免高估）
- 考虑预算和时间约束，权衡样本量和功效

## 10.7 Agent 陷阱：p-hacking 与数据窥探 {#sec-algorithms.10.7}

agent 生成的评估代码容易陷入以下陷阱，导致假阳性率远超预期。

### 陷阱 1：p-hacking（反复测试直到显著）

**场景**：

```python
# agent 生成的"优化"代码
def test_until_significant(algo_a, algo_b, max_attempts=20):
    for i in range(max_attempts):
        # 每次用不同的随机种子/子集/变换
        sample_a = resample(algo_a, size=50)
        sample_b = resample(algo_b, size=50)
        _, p = stats.ttest_ind(sample_a, sample_b)
        if p < 0.05:
            return f"显著！(attempt {i+1})"
    return "无显著差异"
```

**问题**：反复测试会极大提高 I 类错误率。即使两组无差异，尝试 20 次后找到 p < 0.05 的概率接近 64%（见 §10.4）。

**正确做法**：

1. **预注册（pre-registration）**：事先声明分析计划（数据集、检验方法、α）
2. **单次检验**：只用全部数据做一次检验
3. **多重检验校正**：若确实需要多次尝试，应用 Bonferroni 或 FDR 校正

### 陷阱 2：数据窥探（peeking）

**场景**：

```python
# 边收集数据边检验
results_a, results_b = [], []
for i in range(100):
    results_a.append(run_algo_a())
    results_b.append(run_algo_b())
    if i % 10 == 0:  # 每 10 次检查一次
        _, p = stats.ttest_ind(results_a, results_b)
        if p < 0.05:
            print(f"提前终止！n = {i+1}")
            break
```

**问题**：每次"偷看"都是一次检验，累积 I 类错误率。10 次偷看使 FWER 远超 0.05。

**正确做法**：

- **预先确定样本量**：做功效分析，收集足够样本后一次性检验
- **序贯检验（sequential testing）**：使用专门的方法（如 O'Brien-Fleming 边界）控制 FWER

### 陷阱 3：子组分析不校正

**场景**：

```python
# 按用户群体分组测试
groups = ['mobile', 'desktop', 'tablet', 'young', 'old', 'male', 'female']
for group in groups:
    data_a = filter_data(algo_a, group)
    data_b = filter_data(algo_b, group)
    _, p = stats.ttest_ind(data_a, data_b)
    if p < 0.05:
        print(f"{group} 组显著：p = {p:.4f}")
```

**问题**：测试 7 个子组，无校正时期望 0.35 个假阳性（7 × 0.05）。

**正确做法**：

- Bonferroni：每组用 α = 0.05/7 ≈ 0.007
- BH：收集所有 p 值后应用 FDR 控制
- 或预先指定主要子组，其余为探索性分析（不依赖其显著性）

### 陷阱 4：忽略效应量

**场景**：

```python
# 大样本测试
_, p = stats.ttest_ind(large_sample_a, large_sample_b)
if p < 0.05:
    print("算法 A 显著优于 B！")
```

**问题**：n = 10000 时，1% 的差异也会 p < 0.001，但实际意义微小。

**正确做法**：

```python
_, p = stats.ttest_ind(large_sample_a, large_sample_b)
d = (np.mean(large_sample_a) - np.mean(large_sample_b)) / np.std(large_sample_a + large_sample_b)
print(f"p = {p:.4f}, Cohen's d = {d:.4f}")
if p < 0.05 and abs(d) >= 0.2:
    print("显著且实际意义足够")
```

### 陷阱 5：选择性报告（cherry-picking）

**场景**：测试 50 个超参数组合，只报告其中 3 个 p < 0.05 的结果。

**问题**：未校正的多重比较，且未披露测试总数。

**正确做法**：

- 报告所有测试的结果（或至少报告总数）
- 应用多重检验校正
- 区分探索性分析和确证性分析

## 10.10 本章陷阱清单 {#sec-algorithms.10.10}

### 概念陷阱

1. **p 值误读**：p = 0.03 不是"H0 为真的概率"，而是"在 H0 为真下，观察到当前数据的概率"。
2. **不拒绝 H0 ≠ 接受 H0**：p > 0.05 只是"证据不足以拒绝 H0"，不是"证明 H0 为真"。
3. **显著性 ≠ 重要性**：p < 0.05 不保证实际意义，大样本下微小差异也显著。
4. **忽略 II 类错误**：只关注 α 而不关心 β，导致低功效实验（高假阴性率）。
5. **混淆单侧/双侧检验**：单侧检验功效高但需事先确定方向，双侧更保守。

### 实现陷阱

6. **未检查正态性假设**：小样本下偏态数据用 t 检验，I 类错误率偏离 α。
7. **假设等方差**：两组方差差异大时用普通 t 检验，应用 Welch's t 检验。
8. **配对数据用独立检验**：降低功效，应用配对 t 检验。
9. **多重检验不校正**：测试 20 个假设用 α = 0.05，FWER ≈ 0.64。
10. **过度校正**：探索性研究用 Bonferroni，功效过低；应用 FDR 控制。

### Agent 陷阱

11. **p-hacking**：反复尝试不同分析方法/子集，直到 p < 0.05。
12. **数据窥探（peeking）**：边收集数据边检验，累积 I 类错误率。
13. **子组分析不校正**：按多个维度分组测试，不做多重检验校正。
14. **只报告显著结果**：测试 50 个模型，只报告 3 个显著的（选择性报告）。
15. **忽略效应量**：只看 p < 0.05，不计算 Cohen's d，导致实际差异微小但"显著"。
16. **功效不足**：未做样本量估计，n 太小导致无法检测到真实效应。
17. **错误链式推理**："A 显著优于 B，B 显著优于 C，所以 A 显著优于 C"——传递性不成立。
18. **后验功效分析**：实验后计算功效是循环论证（observed power 只是 p 值的函数）。

### 报告陷阱

19. **只报告 p 值**：缺少置信区间、效应量、样本量信息。
20. **"趋势显著"**：p = 0.06 不是"接近显著"，要么拒绝要么不拒绝 H0。
21. **因果语言**："算法 A 导致性能提升"——假设检验只能说"关联"，因果需要实验设计（见第 12 章）。
