## 9.1 分类指标：准确率的局限与替代方案 {#sec-algorithms.9.1.1}

分类任务的目标是预测样本的类别标签。最直观的指标是**准确率**（Accuracy），但它在不平衡数据集上会严重误导。本节建立分类指标的基础概念，并展示何时准确率失效。

::: def 定义 9.1.1 · 准确率 {#def-algorithms.9.1.1.1}

设分类器在测试集上正确预测了 n_correct 个样本，测试集总样本数为 n_total，则准确率为：

$$
\text{Accuracy} = \frac{n_{\text{correct}}}{n_{\text{total}}}
$$

直观理解：所有样本中被正确分类的比例。

:::

准确率的**隐含假设**是各类别样本的重要性相同，但实际任务往往不满足：

- 医疗诊断：漏诊癌症（假阴性）比误诊（假阳性）危险得多
- 垃圾邮件过滤：误杀正常邮件（假阳性）比漏过垃圾邮件（假阴性）严重
- 欺诈检测：欺诈交易占比极低（< 1%），但检出每笔欺诈的价值远超正常交易

::: ex 例 9.1.1 · 准确率的陷阱：不平衡数据集 {#ex-algorithms.9.1.1.1}

考虑一个信用卡欺诈检测数据集：

- 正常交易：9900 笔
- 欺诈交易：100 笔

现在有两个分类器：

**分类器 A（愚蠢基准）**：
- 策略：预测所有交易为正常
- 正确预测：9900 笔
- 准确率：9900/10000 = **99%**

**分类器 B（实际有用的模型）**：
- 正确预测正常：9700 笔
- 正确预测欺诈：80 笔
- 准确率：9780/10000 = **97.8%**

从准确率看，A 比 B 好——但 A 完全没有检测出任何欺诈，B 找到了 80% 的欺诈交易。准确率在不平衡数据集上**完全失效**。

:::

**核心问题**：准确率把所有错误一视同仁，但实际任务中不同类型的错误代价不同。需要更细粒度的指标来区分错误类型。

### 二分类的四种预测结果

将预测结果与真实标签交叉，得到 2×2 的混淆矩阵（下节详述）：

| 真实 \ 预测 | 正类 (P) | 负类 (N) |
|:-----------|:--------|:--------|
| 正类 (P)    | TP      | FN      |
| 负类 (N)    | FP      | TN      |

- **TP (True Positive)**：真正类——预测为正，实际也是正
- **FN (False Negative)**：假负类——预测为负，实际是正（**漏报**）
- **FP (False Positive)**：假正类——预测为正,实际是负（**误报**）
- **TN (True Negative)**：真负类——预测为负，实际也是负

准确率可重写为：

$$
\text{Accuracy} = \frac{TP + TN}{TP + FP + FN + TN}
$$

但这个公式仍然把 TP/TN/FP/FN 混在一起。需要分离关注：

- 在正类样本中，我们正确找到了多少？→ **召回率** (Recall)
- 在预测为正的样本中，有多少真的是正类？→ **精确率** (Precision)

## 9.2 精确率、召回率与 F1 值 {#sec-algorithms.9.1.2}

从混淆矩阵出发，定义两个更细粒度的指标：精确率关注预测结果的可靠性，召回率关注真实正例的覆盖度。

::: def 定义 9.2.1 · 精确率（Precision） {#def-algorithms.9.1.2.1}

在所有预测为正类的样本中，真正为正类的比例：

$$
\text{Precision} = \frac{TP}{TP + FP}
$$

直观理解：预测为正的结果中，有多少是对的（查准率）。

:::

::: def 定义 9.2.2 · 召回率（Recall） {#def-algorithms.9.1.2.2}

在所有真实为正类的样本中，被正确预测为正类的比例：

$$
\text{Recall} = \frac{TP}{TP + FN}
$$

直观理解：所有真正的正例中，我们找回了多少（查全率）。

:::

**记忆技巧**：
- Precision 问"预测对了多少"——分母是**预测为正**的总数（TP + FP）
- Recall 问"找回了多少"——分母是**真实为正**的总数（TP + FN）

::: ex 例 9.2.1 · 垃圾邮件过滤的指标权衡 {#ex-algorithms.9.1.2.1}

收到 100 封邮件，其中 20 封是垃圾邮件，80 封是正常邮件。某过滤器将 30 封标记为垃圾，其中：

- 真垃圾：15 封（TP）
- 误杀正常邮件：15 封（FP）
- 漏过的垃圾：5 封（FN）
- 正确放行：65 封（TN）

计算指标：

- 准确率 = (15 + 65)/100 = 80%
- 精确率 = 15/(15 + 15) = **50%**（标记为垃圾的邮件中，只有一半真是垃圾）
- 召回率 = 15/(15 + 5) = **75%**（真垃圾邮件中，找回了 75%）

**解读**：
- 精确率低（50%）意味着误杀严重——用户会在垃圾箱里翻找重要邮件
- 召回率还可以（75%）但不够高——仍有 25% 的垃圾进入收件箱

**权衡**：提高召回率（更激进地标记）会降低精确率（误杀更多）；反之亦然。

:::

### 精确率与召回率的权衡

分类器通常输出概率 p(y=1|x)，通过阈值 θ 决策：

```
if p(y=1|x) > θ:
    预测为正类
else:
    预测为负类
```

调整阈值 θ 会改变精确率和召回率：

- **θ 降低**（更宽松）：预测更多正类 → 召回率↑，精确率↓
- **θ 提高**（更严格）：预测更少正类 → 精确率↑，召回率↓

::: note 极端情况

- θ = 0（预测全为正）：召回率 = 100%，精确率 = P(正类比例)
- θ = 1（预测全为负）：召回率 = 0%，精确率未定义（无预测为正的样本）

:::

**实际决策**：
- 垃圾邮件过滤：优先保证精确率（避免误杀），可容忍低召回率
- 癌症筛查：优先保证召回率（不能漏诊），可容忍低精确率（后续复检排除）

### F1 值：调和平均数

如何在一个指标中平衡精确率与召回率？算术平均数不合适（会被高值主导），使用调和平均数：

::: def 定义 9.2.3 · F1 值 {#def-algorithms.9.1.2.3}

精确率和召回率的调和平均数：

$$
F_1 = \frac{2}{\frac{1}{\text{Precision}} + \frac{1}{\text{Recall}}} = \frac{2 \cdot \text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}}
$$

等价形式：

$$
F_1 = \frac{2 \cdot TP}{2 \cdot TP + FP + FN}
$$

:::

**调和平均的特性**：F1 值更接近两者中的较小值，只有当精确率和召回率都高时，F1 才高。

::: ex 例 9.2.2 · F1 值惩罚不平衡 {#ex-algorithms.9.1.2.2}

两个分类器的精确率和召回率：

| 分类器 | 精确率 | 召回率 | 算术平均 | F1 值 |
|:------|:------|:------|:--------|:-----|
| A     | 0.9   | 0.9   | 0.9     | 0.9  |
| B     | 0.99  | 0.5   | 0.745   | 0.66 |

B 的算术平均更高，但 F1 值更低——因为召回率太低（只找回一半正例）。F1 值迫使模型在两个指标上都做得不错。

:::

**F-beta 值的推广**：

$$
F_\beta = (1 + \beta^2) \cdot \frac{\text{Precision} \cdot \text{Recall}}{\beta^2 \cdot \text{Precision} + \text{Recall}}
$$

- β = 1：标准 F1，精确率与召回率权重相同
- β < 1（如 0.5）：更重视精确率
- β > 1（如 2）：更重视召回率

实际使用中，F1 最常见；特殊场景下调整 β（如医疗诊断用 F2）。

## 9.3 混淆矩阵与多分类 {#sec-algorithms.9.1.3}

混淆矩阵（Confusion Matrix）是分类结果的完整可视化，清晰展示每个类别的预测分布。对于 K 分类任务，矩阵是 K×K 的：

::: def 定义 9.3.1 · 混淆矩阵 {#def-algorithms.9.1.3.1}

混淆矩阵 C 是一个 K×K 矩阵，其中：

$$
C_{ij} = \text{真实类别为 } i \text{ 但被预测为 } j \text{ 的样本数}
$$

对角线元素 C_{ii} 是正确分类的样本数，非对角线元素是分类错误。

:::

**二分类混淆矩阵示例**（正类=1，负类=0）：

|       | 预测=1 | 预测=0 |
|:------|:------|:------|
| 真=1  | 80    | 20    |
| 真=0  | 10    | 890   |

从中可直接读出：
- TP = 80, FN = 20, FP = 10, TN = 890
- 精确率 = 80/(80+10) = 88.9%
- 召回率 = 80/(80+20) = 80%
- 准确率 = (80+890)/1000 = 97%

**三分类混淆矩阵示例**（类别 A/B/C）：

|       | 预测A | 预测B | 预测C |
|:------|:-----|:-----|:-----|
| 真A   | 45   | 3    | 2    |
| 真B   | 5    | 38   | 7    |
| 真C   | 1    | 4    | 45   |

解读：
- A 类的召回率 = 45/(45+3+2) = 90%
- B 类的精确率 = 38/(3+38+4) = 84.4%
- C 类经常被误判为 B（4 次）

### 多分类的精确率与召回率

对每个类别 i，可计算其精确率和召回率：

$$
\text{Precision}_i = \frac{C_{ii}}{\sum_j C_{ji}} \quad (\text{第 } i \text{ 列的正确率})
$$

$$
\text{Recall}_i = \frac{C_{ii}}{\sum_j C_{ij}} \quad (\text{第 } i \text{ 行的正确率})
$$

但如何汇总为全局指标？有两种策略：**宏平均**（Macro）和**微平均**（Micro）。

::: def 定义 9.3.2 · 宏平均与微平均 {#def-algorithms.9.1.3.2}

**宏平均**（Macro-average）：先计算每类指标，再取算术平均：

$$
\text{Precision}_{\text{macro}} = \frac{1}{K} \sum_{i=1}^K \text{Precision}_i
$$

**微平均**（Micro-average）：先汇总全局 TP/FP/FN，再计算指标：

$$
\text{Precision}_{\text{micro}} = \frac{\sum_{i=1}^K TP_i}{\sum_{i=1}^K (TP_i + FP_i)}
$$

:::

**区别**：
- 宏平均：所有类别权重相同，小类别的表现会平等影响结果
- 微平均：样本权重相同，大类别主导结果（等价于全局准确率）

::: ex 例 9.3.1 · 宏平均 vs 微平均 {#ex-algorithms.9.1.3.1}

三分类任务的混淆矩阵：

|       | 预测A | 预测B | 预测C |
|:------|:-----|:-----|:-----|
| 真A   | 90   | 5    | 5    |
| 真B   | 10   | 35   | 5    |
| 真C   | 2    | 3    | 45   |

各类别指标：

| 类别 | TP | FP | FN | 精确率 | 召回率 |
|:----|:---|:---|:---|:------|:------|
| A   | 90 | 12 | 10 | 88.2% | 90%   |
| B   | 35 | 8  | 15 | 81.4% | 70%   |
| C   | 45 | 10 | 5  | 81.8% | 90%   |

**宏平均精确率** = (88.2 + 81.4 + 81.8)/3 = **83.8%**

**微平均精确率**：
- 全局 TP = 90 + 35 + 45 = 170
- 全局 FP = 12 + 8 + 10 = 30
- 微平均精确率 = 170/(170 + 30) = **85%**

微平均更高，因为 A 类样本多（100 个）且精确率最高，主导了结果。宏平均给三个类别相同权重。

:::

**选择建议**：
- 类别重要性相同，样本不平衡 → 宏平均
- 样本级别的整体性能 → 微平均
- 医疗诊断等场景：为每个类别单独报告，不取平均

## 9.4 ROC 曲线与 AUC {#sec-algorithms.9.1.4}

精确率-召回率曲线（PR Curve）和 ROC 曲线（Receiver Operating Characteristic）都是可视化分类器在不同阈值下性能的工具。ROC 曲线在平衡数据集上更常用，PR 曲线在不平衡数据集上更有信息量。

### ROC 曲线的定义

ROC 曲线的 x 轴是**假正率**（FPR），y 轴是**真正率**（TPR，即召回率）：

::: def 定义 9.4.1 · 真正率与假正率 {#def-algorithms.9.1.4.1}

**真正率**（True Positive Rate，TPR）：

$$
\text{TPR} = \frac{TP}{TP + FN} = \text{Recall}
$$

**假正率**（False Positive Rate，FPR）：

$$
\text{FPR} = \frac{FP}{FP + TN}
$$

FPR 表示在所有真负例中，被错误预测为正的比例。

:::

**绘制 ROC 曲线的过程**：

1. 分类器输出样本的预测概率 p(y=1|x)
2. 将样本按概率从高到低排序
3. 遍历概率值作为阈值 θ，计算每个 θ 下的 (FPR, TPR)
4. 将 (FPR, TPR) 点连成曲线

**极端点**：
- θ = 1（全预测为负）：(FPR=0, TPR=0)，原点
- θ = 0（全预测为正）：(FPR=1, TPR=1)，右上角

**随机分类器**：FPR = TPR，对应 y = x 的对角线。

::: ex 例 9.4.1 · 手工绘制 ROC 曲线 {#ex-algorithms.9.1.4.1}

10 个样本的预测概率与真实标签：

| 样本 | 概率 | 真实标签 |
|:----|:-----|:--------|
| 1   | 0.9  | 1       |
| 2   | 0.8  | 1       |
| 3   | 0.7  | 0       |
| 4   | 0.6  | 1       |
| 5   | 0.55 | 1       |
| 6   | 0.54 | 0       |
| 7   | 0.53 | 1       |
| 8   | 0.52 | 0       |
| 9   | 0.51 | 0       |
| 10  | 0.5  | 0       |

真正例 5 个，真负例 5 个。

遍历阈值（以样本概率为候选）：

| 阈值 θ | TP | FP | FN | TN | TPR | FPR |
|:------|:---|:---|:---|:---|:----|:----|
| > 0.9 | 1  | 0  | 4  | 5  | 0.2 | 0   |
| > 0.8 | 2  | 0  | 3  | 5  | 0.4 | 0   |
| > 0.7 | 2  | 1  | 3  | 4  | 0.4 | 0.2 |
| > 0.6 | 3  | 1  | 2  | 4  | 0.6 | 0.2 |
| > 0.55| 4  | 1  | 1  | 4  | 0.8 | 0.2 |
| > 0.54| 4  | 2  | 1  | 3  | 0.8 | 0.4 |
| > 0.53| 5  | 2  | 0  | 3  | 1.0 | 0.4 |
| > 0.52| 5  | 3  | 0  | 2  | 1.0 | 0.6 |
| > 0.51| 5  | 4  | 0  | 1  | 1.0 | 0.8 |
| > 0.5 | 5  | 5  | 0  | 0  | 1.0 | 1.0 |

ROC 曲线经过点：(0,0.2), (0,0.4), (0.2,0.4), (0.2,0.6), (0.2,0.8), (0.4,0.8), (0.4,1.0), (0.6,1.0), (0.8,1.0), (1.0,1.0)。

:::

### AUC：曲线下面积

::: def 定义 9.4.2 · AUC（Area Under the ROC Curve） {#def-algorithms.9.1.4.2}

AUC 是 ROC 曲线下方的面积，取值范围 [0, 1]。

**概率解释**：随机抽取一个正例和一个负例，分类器给正例打分高于负例的概率。

:::

**AUC 的含义**：
- AUC = 0.5：随机猜测（对角线）
- AUC = 1.0：完美分类器（曲线经过左上角 (0,1)）
- AUC < 0.5：比随机猜测更差（通常是预测反了，可通过翻转预测改进）

**优点**：
- 阈值无关：不需要选择具体阈值
- 对类别不平衡不敏感（相比准确率）
- 综合考虑了所有可能的分类阈值

**缺点**：
- 不平衡数据集上可能过于乐观（PR-AUC 更好）
- 不同 ROC 曲线可能有相同 AUC 但性能差异大

::: note PR 曲线 vs ROC 曲线

在极度不平衡数据集（如正类占 1%）上：

- ROC 曲线可能仍然"好看"（因为 TN 很多，FPR 容易保持低）
- PR 曲线更敏感（精确率直接受 FP 影响，少量误报就会拉低精确率）

推荐：不平衡数据集同时报告 ROC-AUC 和 PR-AUC。

:::

## 9.5 排序指标：NDCG、MAP、MRR {#sec-algorithms.9.1.5}

搜索引擎、推荐系统等任务不仅要分类正确，还要**排序**——将最相关的结果排在前面。标准分类指标无法评估排序质量，需要专门的排序指标。

### 核心概念：相关性与位置

排序任务的输入是查询 q，输出是按相关性排序的结果列表 [r₁, r₂, ..., r_n]。每个结果 r_i 有一个相关性标签（二值或分级）：

- **二值相关性**：0（不相关）或 1（相关）
- **分级相关性**：0（不相关）、1（稍微相关）、2（相关）、3（非常相关）

**排序指标的共同原则**：
1. 相关结果应该排在前面
2. 位置越靠前，权重越高（用户更可能点击）
3. 高相关结果比低相关结果更重要

### 平均精确率（MAP）

MAP（Mean Average Precision）是信息检索领域的经典指标，适用于二值相关性。

::: def 定义 9.5.1 · 平均精确率（Average Precision） {#def-algorithms.9.1.5.1}

对单个查询 q，设返回了 n 个结果，其中 k 个相关。在每个相关结果出现的位置 i 计算精确率 P(i)，然后取平均：

$$
\text{AP}(q) = \frac{1}{k} \sum_{i=1}^n \mathbb{1}(\text{rel}_i) \cdot P(i)
$$

其中：
- $\mathbb{1}(\text{rel}_i)$ 是指示函数（第 i 个结果相关时为 1，否则为 0）
- $P(i) = \frac{\text{前 } i \text{ 个结果中相关的数量}}{i}$

**MAP**（Mean Average Precision）：对所有查询的 AP 取平均。

:::

::: ex 例 9.5.1 · 计算 AP {#ex-algorithms.9.1.5.1}

搜索"机器学习"，返回 5 个文档，相关性如下（1=相关，0=不相关）：

| 位置 | 文档 | 相关性 | P@k |
|:----|:----|:------|:----|
| 1   | A   | 1     | 1/1=1.0 |
| 2   | B   | 0     | —   |
| 3   | C   | 1     | 2/3=0.67 |
| 4   | D   | 1     | 3/4=0.75 |
| 5   | E   | 0     | —   |

共 3 个相关文档，AP = (1.0 + 0.67 + 0.75)/3 = **0.81**。

如果相关文档在后面（如位置 3, 4, 5），AP 会更低（如 (0.33 + 0.5 + 0.6)/3 = 0.48）。

:::

**MAP 的特点**：
- 强调相关文档的排名位置
- 对不相关文档的具体位置不敏感（只要它们在相关文档之后）
- 适用于二值相关性（相关/不相关）

### NDCG：归一化折损累积增益

NDCG（Normalized Discounted Cumulative Gain）处理分级相关性，并对位置应用对数折扣。

::: def 定义 9.5.2 · DCG 与 NDCG {#def-algorithms.9.1.5.2}

**折损累积增益**（DCG）在位置 p：

$$
\text{DCG}_p = \sum_{i=1}^p \frac{2^{\text{rel}_i} - 1}{\log_2(i + 1)}
$$

其中 $\text{rel}_i$ 是第 i 个结果的相关性分数（0, 1, 2, 3...）。

**理想 DCG**（IDCG）：将结果按相关性降序排列后的 DCG（最优排序）。

**归一化 DCG**：

$$
\text{NDCG}_p = \frac{\text{DCG}_p}{\text{IDCG}_p}
$$

取值范围 [0, 1]，完美排序时 NDCG = 1。

:::

**公式解读**：
- $2^{\text{rel}_i} - 1$：相关性的指数增益（rel=3 的结果增益是 rel=1 的 4 倍）
- $\log_2(i+1)$：位置折扣（位置 1 无折扣，位置 2 折扣 $\log_2 3 \approx 1.58$）

::: ex 例 9.5.2 · 计算 NDCG@5 {#ex-algorithms.9.1.5.2}

搜索结果的相关性分数（0-3 分级）：

| 位置 | 相关性 rel | 2^rel - 1 | log₂(i+1) | 增益 |
|:----|:----------|:----------|:----------|:-----|
| 1   | 3         | 7         | 0         | 7.0  |
| 2   | 2         | 3         | 1.58      | 1.9  |
| 3   | 3         | 7         | 2.0       | 3.5  |
| 4   | 0         | 0         | 2.32      | 0    |
| 5   | 1         | 1         | 2.58      | 0.39 |

DCG@5 = 7.0 + 1.9 + 3.5 + 0 + 0.39 = **12.79**

理想排序（相关性降序：3, 3, 2, 1, 0）：

IDCG@5 = 7/1 + 7/1.58 + 3/2 + 1/2.32 + 0 = 7 + 4.43 + 1.5 + 0.43 = **13.36**

NDCG@5 = 12.79 / 13.36 = **0.957**

:::

**NDCG 的优点**：
- 处理分级相关性（不只是二值）
- 位置越靠前，权重越高
- 归一化后可跨查询比较

**常用变体**：NDCG@5, NDCG@10（只看前 k 个结果）。

### MRR：平均倒数排名

MRR（Mean Reciprocal Rank）是最简单的排序指标，只关心**第一个相关结果的位置**。

::: def 定义 9.5.3 · 倒数排名（Reciprocal Rank） {#def-algorithms.9.1.5.3}

对单个查询 q，设第一个相关结果出现在位置 k，则：

$$
\text{RR}(q) = \frac{1}{k}
$$

如果没有相关结果，RR = 0。

**MRR**（Mean Reciprocal Rank）：对所有查询的 RR 取平均。

:::

::: ex 例 9.5.3 · MRR 计算 {#ex-algorithms.9.1.5.3}

三个查询的第一个相关结果位置：

| 查询 | 第一个相关位置 | RR |
|:----|:-------------|:---|
| Q1  | 1            | 1.0|
| Q2  | 3            | 0.33|
| Q3  | 2            | 0.5|

MRR = (1.0 + 0.33 + 0.5)/3 = **0.61**

:::

**适用场景**：
- 问答系统（用户只看第一个答案）
- 导航查询（用户只想找一个特定网站）

**局限**：忽略第一个相关结果之后的排序质量。

### 排序指标的选择

| 指标 | 适用场景 | 相关性类型 | 关注点 |
|:----|:--------|:----------|:------|
| MAP | 信息检索 | 二值 | 所有相关结果的位置 |
| NDCG| 推荐、搜索 | 分级 | 高相关结果的前置 |
| MRR | 问答、导航 | 二值 | 第一个相关结果 |

## 9.6 回归指标：MSE、MAE、R² {#sec-algorithms.9.1.6}

回归任务预测连续值（如房价、温度、销量）。常用指标衡量预测值与真实值的偏差。

::: def 定义 9.6.1 · 均方误差（MSE） {#def-algorithms.9.1.6.1}

$$
\text{MSE} = \frac{1}{n} \sum_{i=1}^n (y_i - \hat{y}_i)^2
$$

其中 $y_i$ 是真实值，$\hat{y}_i$ 是预测值。

**均方根误差**（RMSE）：$\text{RMSE} = \sqrt{\text{MSE}}$，单位与 y 相同。

:::

**MSE 的特点**：
- 对大误差敏感（平方放大）
- 可导，便于优化（梯度下降）
- 受离群点影响大

::: def 定义 9.6.2 · 平均绝对误差（MAE） {#def-algorithms.9.1.6.2}

$$
\text{MAE} = \frac{1}{n} \sum_{i=1}^n |y_i - \hat{y}_i|
$$

:::

**MAE vs MSE**：
- MAE 对离群点鲁棒（线性惩罚）
- MSE 对大误差惩罚更重
- MAE 在 0 处不可导，优化稍困难

::: ex 例 9.6.1 · MSE vs MAE 的差异 {#ex-algorithms.9.1.6.1}

5 个预测的真实值与预测值：

| 样本 | 真实 | 预测 | 误差 | 误差² |
|:----|:-----|:-----|:-----|:------|
| 1   | 10   | 10.2 | 0.2  | 0.04  |
| 2   | 20   | 19.5 | 0.5  | 0.25  |
| 3   | 15   | 15.1 | 0.1  | 0.01  |
| 4   | 30   | 28   | 2    | 4     |
| 5   | 25   | 35   | 10   | 100   |

MAE = (0.2 + 0.5 + 0.1 + 2 + 10)/5 = **2.56**

MSE = (0.04 + 0.25 + 0.01 + 4 + 100)/5 = **20.86**

RMSE = √20.86 = **4.57**

样本 5 的大误差主导了 MSE（占总和的 96%），但在 MAE 中只占 78%。

:::

::: def 定义 9.6.3 · 决定系数（R²） {#def-algorithms.9.1.6.3}

$$
R^2 = 1 - \frac{\sum_{i=1}^n (y_i - \hat{y}_i)^2}{\sum_{i=1}^n (y_i - \bar{y})^2}
$$

其中 $\bar{y}$ 是真实值的均值。

**解释**：模型解释了多少比例的方差。

- R² = 1：完美预测
- R² = 0：模型与预测均值一样好
- R² < 0：模型比预测均值还差

:::

**R² 的直观理解**：

分子是模型的残差平方和（RSS），分母是总平方和（TSS）。R² 衡量模型相对于"总是预测均值"的改进程度。

::: ex 例 9.6.2 · R² 计算 {#ex-algorithms.9.1.6.2}

真实值 y = [10, 20, 30, 40, 50]，均值 $\bar{y}$ = 30。

预测值 $\hat{y}$ = [12, 18, 32, 38, 48]。

RSS = (10-12)² + (20-18)² + (30-32)² + (40-38)² + (50-48)² = 4 + 4 + 4 + 4 + 4 = 20

TSS = (10-30)² + (20-30)² + (30-30)² + (40-30)² + (50-30)² = 400 + 100 + 0 + 100 + 400 = 1000

R² = 1 - 20/1000 = **0.98**

模型解释了 98% 的方差。

:::

**选择建议**：
- MSE/RMSE：常规回归任务，需要优化（可导）
- MAE：对离群点敏感的任务（如房价预测）
- R²：解释模型质量（但不能单独用于模型选择）

## 9.7 Agent 常见陷阱与诊断

agent 生成的评估代码常出现以下问题：

::: danger 陷阱 9.7.1 · 不平衡数据集只看准确率

**场景**：欺诈检测数据集，正常交易 99.5%，欺诈 0.5%。agent 报告"模型准确率 99.5%，表现优秀"。

**实际情况**：模型预测全部为正常，召回率为 0，没有检出任何欺诈。

**修复**：
```python
# 错误：只报告准确率
print(f"Accuracy: {accuracy_score(y_true, y_pred):.3f}")

# 正确：同时报告精确率、召回率、F1，并检查类别分布
from sklearn.metrics import classification_report, confusion_matrix

print("类别分布：", np.bincount(y_true))
print(classification_report(y_true, y_pred))
print("混淆矩阵：\n", confusion_matrix(y_true, y_pred))
```

**验证**：检查混淆矩阵的对角线之外是否有大量误分类。

:::

::: danger 陷阱 9.7.2 · ROC 曲线计算错误

**场景**：agent 生成 ROC 绘制代码，但输入的是类别标签而非概率。

**症状**：ROC 曲线只有 3 个点（全预测负、全预测正、混合），而非平滑曲线。

**原因**：`sklearn.metrics.roc_curve` 需要连续的预测分数，不能是 0/1 标签。

**修复**：
```python
# 错误：使用预测类别
y_pred_class = model.predict(X_test)  # 返回 0/1
fpr, tpr, _ = roc_curve(y_true, y_pred_class)  # 错误

# 正确：使用预测概率
y_pred_proba = model.predict_proba(X_test)[:, 1]  # 返回概率
fpr, tpr, _ = roc_curve(y_true, y_pred_proba)  # 正确
```

:::

::: danger 陷阱 9.7.3 · NDCG 归一化错误

**场景**：agent 计算 DCG 但忘记归一化（除以 IDCG），导致不同查询的 DCG 无法比较。

**修复**：
```python
# 错误：只返回 DCG
def dcg_at_k(relevances, k):
    return sum([( 2**rel - 1) / np.log2(i + 2) 
                for i, rel in enumerate(relevances[:k])])

# 正确：归一化
def ndcg_at_k(relevances, k):
    dcg = dcg_at_k(relevances, k)
    ideal_relevances = sorted(relevances, reverse=True)
    idcg = dcg_at_k(ideal_relevances, k)
    return dcg / idcg if idcg > 0 else 0.0
```

:::

::: danger 陷阱 9.7.4 · 多分类宏平均与微平均混淆

**场景**：agent 报告"宏平均精确率 75%"，但未说明样本分布，用户误以为整体性能是 75%。

**问题**：宏平均给小类别高权重，但实际任务可能更关心大类别（微平均）。

**修复**：同时报告两者，并说明差异：
```python
from sklearn.metrics import precision_score

macro_prec = precision_score(y_true, y_pred, average='macro')
micro_prec = precision_score(y_true, y_pred, average='micro')

print(f"宏平均精确率（类别平等权重）: {macro_prec:.3f}")
print(f"微平均精确率（样本平等权重）: {micro_prec:.3f}")

if abs(macro_prec - micro_prec) > 0.05:
    print("警告：宏/微平均差异较大，存在类别不平衡")
```

:::

## 9.8 实验：评估指标计算与可视化 {#sec-algorithms.9.1.8}

### 实验 A：不平衡数据集的陷阱

构造一个信用卡欺诈检测数据集（99% 正常，1% 欺诈），对比三个分类器：

- **Baseline**：全预测为正常

- **Good**：召回率高（找到 80% 欺诈）


**实验目标**：验证准确率在不平衡数据集上的失效，理解精确率/召回率/F1 的作用。

完整代码见 `experiments/ch09/metrics_lab.py`（实验 A 部分）。

关键观察：

### 实验 B：ROC 曲线与 AUC

使用逻辑回归在同一数据集上训练，绘制 ROC 曲线并计算 AUC：

```python
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import roc_curve, roc_auc_score, auc
import matplotlib.pyplot as plt

# 训练模型（对不平衡数据使用 class_weight）
model = LogisticRegression(class_weight='balanced', random_state=42)
model.fit(X_train, y_train)

# 预测概率
y_proba = model.predict_proba(X_test)[:, 1]

# 计算 ROC 曲线
fpr, tpr, thresholds = roc_curve(y_test, y_proba)
roc_auc = auc(fpr, tpr)

# 绘制
plt.figure(figsize=(8, 6))
plt.plot(fpr, tpr, label=f'模型 (AUC = {roc_auc:.3f})', linewidth=2)
plt.plot([0, 1], [0, 1], 'k--', label='随机猜测 (AUC = 0.5)')
plt.xlim([0.0, 1.0])
plt.ylim([0.0, 1.05])
plt.xlabel('假正率 (FPR)')
plt.ylabel('真正率 (TPR / 召回率)')
plt.title('ROC 曲线')
plt.legend(loc="lower right")
plt.grid(alpha=0.3)
plt.savefig('roc_curve.png', dpi=150, bbox_inches='tight')
```

**观察要点**：
- 曲线越靠近左上角，性能越好
- AUC > 0.9 通常表示良好分类器
- 可在曲线上标注关键阈值点（如默认 0.5）

### 实验 C：排序指标对比

模拟搜索引擎返回 10 个结果，计算 NDCG、MAP、MRR：

```python
import numpy as np

def dcg_at_k(relevances, k):
    """计算 DCG@k"""
    relevances = np.array(relevances)[:k]
    if relevances.size == 0:
        return 0.0
    return np.sum((2**relevances - 1) / np.log2(np.arange(2, relevances.size + 2)))

def ndcg_at_k(relevances, k):
    """计算 NDCG@k"""
    dcg = dcg_at_k(relevances, k)
    ideal_relevances = sorted(relevances, reverse=True)
    idcg = dcg_at_k(ideal_relevances, k)
    return dcg / idcg if idcg > 0 else 0.0

def average_precision(relevances):
    """计算 AP（二值相关性：0 或 1）"""
    relevances = np.array(relevances)
    if np.sum(relevances) == 0:
        return 0.0
    
    precisions = []
    num_relevant = 0
    for i, rel in enumerate(relevances):
        if rel == 1:
            num_relevant += 1
            precisions.append(num_relevant / (i + 1))
    
    return np.mean(precisions)

def reciprocal_rank(relevances):
    """计算 RR"""
    for i, rel in enumerate(relevances):
        if rel > 0:
            return 1.0 / (i + 1)
    return 0.0

# 测试三种排序质量
queries = {
    "完美排序": [3, 2, 2, 1, 1, 0, 0, 0, 0, 0],
    "中等排序": [2, 0, 3, 1, 0, 2, 0, 1, 0, 0],
    "糟糕排序": [0, 0, 1, 0, 2, 0, 0, 3, 1, 0],
}

print(f"{'查询':<12} {'NDCG@5':<8} {'NDCG@10':<9} {'MAP':<8} {'MRR':<8}")
print("-" * 50)

for name, rels in queries.items():
    binary_rels = [1 if r > 0 else 0 for r in rels]  # MAP 需要二值
    
    ndcg5 = ndcg_at_k(rels, 5)
    ndcg10 = ndcg_at_k(rels, 10)
    map_score = average_precision(binary_rels)
    mrr_score = reciprocal_rank(rels)
    
    print(f"{name:<12} {ndcg5:<8.3f} {ndcg10:<9.3f} {map_score:<8.3f} {mrr_score:<8.3f}")
```

**预期输出**：

```
查询          NDCG@5   NDCG@10   MAP      MRR
--------------------------------------------------
完美排序      1.000    1.000     1.000    1.000
中等排序      0.876    0.891     0.639    1.000
糟糕排序      0.613    0.682     0.367    0.333
```

**解读**：
- 完美排序：所有指标都是 1.0
- 中等排序：MRR 仍然是 1.0（第一个结果相关），但 MAP 下降（后续结果排序不佳）
- 糟糕排序：MRR 低（第一个相关结果在位置 3），NDCG 和 MAP 也低

## 9.10 本章陷阱清单 {#sec-algorithms.9.1.10}

**分类指标陷阱**：

1. **不平衡数据集只看准确率**（§ 9.1）
   - 症状：模型"高准确率"但在少数类上失效
   - 诊断：检查类别分布，计算每类的召回率
   - 修复：使用 F1 值、平衡准确率，或调整类别权重

2. **混淆精确率与召回率**（§ 9.2）
   - 症状：报告"精确率 90%"但误解为"找回了 90%"
   - 修复：记住分母——精确率看预测为正的总数，召回率看真实为正的总数

3. **F1 值计算错误**（§ 9.2）
   - 症状：使用算术平均而非调和平均
   - 修复：`F1 = 2*P*R / (P+R)`，不是 `(P+R)/2`

**多分类陷阱**：

4. **宏平均与微平均混淆**（§ 9.3）
   - 症状：只报告宏平均，但样本分布不均
   - 修复：同时报告两者，并说明差异原因

**ROC 与 AUC 陷阱**：

5. **ROC 曲线输入错误**（§ 9.4）
   - 症状：使用类别标签而非概率，曲线只有几个点
   - 修复：输入 `predict_proba()` 的结果，不是 `predict()`

6. **不平衡数据集过度依赖 AUC**（§ 9.4）
   - 症状：AUC 很高但精确率很低
   - 修复：同时查看 PR-AUC（Precision-Recall AUC）

**排序指标陷阱**：

7. **NDCG 忘记归一化**（§ 9.5）
   - 症状：不同查询的 DCG 值无法比较
   - 修复：除以 IDCG（理想排序的 DCG）

8. **MAP 与二值相关性的误用**（§ 9.5）
   - 症状：对分级相关性（0/1/2/3）直接用 MAP
   - 修复：MAP 只适用于二值相关性，分级相关性用 NDCG

**回归指标陷阱**：

9. **MSE 单位不匹配**（§ 9.6）
   - 症状：报告"MSE = 100"但无法解释（单位是平方）
   - 修复：报告 RMSE（均方根误差），单位与原始数据一致

10. **R² 用于模型选择**（§ 9.6）
    - 症状：只比较 R²，忽略过拟合风险
    - 修复：结合交叉验证，使用调整 R²（Adjusted R²）

**Agent 代码陷阱**：

11. **测试集泄露到评估**（通用）
    - 症状：在计算评估指标前，代码已经在测试集上调参
    - 修复：使用三分数据（训练/验证/测试），测试集只在最终评估时使用一次

12. **随机种子未固定**（通用）
    - 症状：每次运行指标结果不同
    - 修复：设置 `random.seed()`, `np.random.seed()`, `torch.manual_seed()`

## 附录：实验代码解析 {#sec-algorithms.9.1.12}

完整实验代码位于 `experiments/ch09/metrics_lab.py`，包含三个独立实验。以下是关键代码片段的详细解析。

### 实验 A 代码片段：构造不平衡数据集

```python
# 构造测试集：10000 个样本，9900 正常，100 欺诈
n_samples = 10000
n_fraud = 100
n_normal = n_samples - n_fraud

y_true = np.array([0] * n_normal + [1] * n_fraud)
np.random.shuffle(y_true)

# Baseline 分类器：全预测为正常
y_pred_baseline = np.zeros(n_samples, dtype=int)

# Good 分类器：找到 80% 的欺诈，误报率 2%
y_pred_good = y_true.copy()
fraud_indices = np.where(y_true == 1)[0]
# 漏掉 20% 欺诈
miss_fraud = np.random.choice(fraud_indices, size=int(0.2 * n_fraud), replace=False)
y_pred_good[miss_fraud] = 0
# 2% 误报
normal_indices = np.where(y_true == 0)[0]
false_positives = np.random.choice(normal_indices, size=int(0.02 * n_normal), replace=False)
y_pred_good[false_positives] = 1
```

**关键点**：
- `y_true.copy()` 保证不修改原始标签
- `np.where(y_true == 1)[0]` 获取所有正例的索引
- `np.random.choice(..., replace=False)` 不放回抽样

### 实验 C 代码片段：NDCG 计算

```python
def dcg_at_k(relevances, k):
    """计算 DCG@k"""
    relevances = np.array(relevances)[:k]
    if relevances.size == 0:
        return 0.0
    
    # DCG = Σ (2^rel - 1) / log2(i+2)
    gains = 2**relevances - 1
    discounts = np.log2(np.arange(2, relevances.size + 2))
    return np.sum(gains / discounts)

def ndcg_at_k(relevances, k):
    """计算 NDCG@k"""
    dcg = dcg_at_k(relevances, k)
    ideal_relevances = sorted(relevances, reverse=True)  # 理想排序
    idcg = dcg_at_k(ideal_relevances, k)
    return dcg / idcg if idcg > 0 else 0.0  # 避免除零
```

**陷阱**：忘记归一化（除以 IDCG），导致不同查询的 DCG 无法比较。
