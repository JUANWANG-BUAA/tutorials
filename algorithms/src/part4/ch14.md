## 14.2 模块一：样本量与功效规划器 {#sec-algorithms.14.1.2}

在实验上线前，流水线首先校验当前流量规模是否足以支撑检测目标。

```python
from scipy.stats import norm

class SampleSizePlanner:
    @staticmethod
    def calculate_required_sample_size(config: ExperimentConfig) -> int:
        """
        根据双样本双侧 t 检验计算每组所需样本量
        n = 2 * (Z_{1 - alpha/2} + Z_{power})^2 * sigma^2 / delta^2
        """
        z_alpha = norm.ppf(1.0 - config.alpha / 2.0)
        z_beta = norm.ppf(config.power)
        delta = config.baseline_mean * config.mde_relative
        
        if delta == 0:
            raise ValueError("MDE 相对提升不能为 0")
            
        n_per_group = 2.0 * (z_alpha + z_beta)**2 * config.baseline_variance / (delta**2)
        return int(np.ceil(n_per_group))

    @staticmethod
    def compute_power_curve(config: ExperimentConfig, n_range: np.ndarray) -> np.ndarray:
        """计算不同样本量规模下的统计功效 (Power Curve)"""
        z_alpha = norm.ppf(1.0 - config.alpha / 2.0)
        delta = config.baseline_mean * config.mde_relative
        se = np.sqrt(2.0 * config.baseline_variance / n_range)
        power_values = norm.cdf((delta / se) - z_alpha) + norm.cdf((-delta / se) - z_alpha)
        return power_values
```

## 14.3 模块二：数据健康诊断与 SRM 检测 {#sec-algorithms.14.1.3}

样本比率不匹配（Sample Ratio Mismatch, SRM）是实验数据受损的最显著信号。若分流比例发生偏航，任何后续的均值比较均失去因果有效性。

::: def 检验 14.3.1 · SRM 卡方拟合优度检验 {#def-algorithms.14.3.1.1}

设控制组与实验组的观测样本量分别为 $N_A, N_B$，预设分配比例为 $p_A : p_B$。
计算卡方检验统计量：
$$
\chi^2 = \frac{(N_A - N \cdot p_A)^2}{N \cdot p_A} + \frac{(N_B - N \cdot p_B)^2}{N \cdot p_B} \sim \chi^2(1)
$$
若对应 $p < 0.001$，强烈提示存在系统性分流偏差（如某版本引发闪退导致埋点丢失），实验流水线必须阻断后续分析。
:::

```python
from scipy.stats import chisquare

class HealthDiagnostics:
    @staticmethod
    def check_srm(n_control: int, n_treatment: int, 
                  expected_ratio: Tuple[float, float] = (0.5, 0.5), 
                  threshold: float = 0.001) -> HealthCheckReport:
        total_n = n_control + n_treatment
        expected_counts = [total_n * expected_ratio[0], total_n * expected_ratio[1]]
        observed_counts = [n_control, n_treatment]
        
        stat, p_val = chisquare(observed_counts, f_exp=expected_counts)
        passed = p_val >= threshold
        
        warnings = []
        if not passed:
            warnings.append(f"严重警告: 检测到样本比率不匹配 (SRM)! p值={p_val:.2e} < {threshold}")
            
        return HealthCheckReport(
            srm_passed=passed,
            srm_p_value=float(p_val),
            observed_counts=(n_control, n_treatment),
            expected_counts=(int(expected_counts[0]), int(expected_counts[1])),
            balance_warnings=warnings
        )
```

## 14.4 模块三：CUPED 方差缩减引擎实现 {#sec-algorithms.14.1.4}

```python
class CUPEDEngine:
    @staticmethod
    def adjust(y_control: np.ndarray, y_treatment: np.ndarray,
               x_control: np.ndarray, x_treatment: np.ndarray) -> Tuple[np.ndarray, np.ndarray, float]:
        """
        实施 CUPED 变换
        Y: 实验期观测指标
        X: 实验前历史协变量
        """
        y_all = np.concatenate([y_control, y_treatment])
        x_all = np.concatenate([x_control, x_treatment])
        
        # 计算最优去偏系数 theta
        var_x = np.var(x_all, ddof=1)
        if var_x < 1e-12:
            return y_control, y_treatment, 0.0
            
        cov_xy = np.cov(x_all, y_all, ddof=1)[0, 1]
        theta = cov_xy / var_x
        
        x_mean = np.mean(x_all)
        y_ctrl_adj = y_control - theta * (x_control - x_mean)
        y_treat_adj = y_treatment - theta * (x_treatment - x_mean)
        
        # 计算实测方差减少率
        orig_var = np.var(y_all, ddof=1)
        adj_var = np.var(np.concatenate([y_ctrl_adj, y_treat_adj]), ddof=1)
        reduction_pct = max(0.0, (1.0 - adj_var / orig_var) * 100.0)
        
        return y_ctrl_adj, y_treat_adj, reduction_pct
```

## 14.5 模块四：序贯检验（mSPRT）与安全早停 {#sec-algorithms.14.1.5}

为了解决“偷看仪表盘早停”导致的假阳性爆炸，流水线内置基于正态先验的 **mSPRT（Mixture Sequential Probability Ratio Test）**。

::: thm 定理 14.5.1 · mSPRT 似然比统计量与停止准则 {#thm-algorithms.14.5.1.1}

设两组样本均值差在样本量为 $N$ 时的积累值为 $S_N = \sum_{i=1}^N (Y_{B, i} - Y_{A, i})$。
在连续正态先验 $\tau \sim \mathcal{N}(0, \tau_0^2)$ 下，混合似然比统计量 $\Lambda_N$ 拥有闭式解：
$$
\Lambda_N = \sqrt{\frac{\sigma_0^2}{\sigma_0^2 + N \tau_0^2}} \exp\left( \frac{N^2 \tau_0^2 (\bar{Y}_B - \bar{Y}_A)^2}{2 \sigma_0^2 (\sigma_0^2 + N \tau_0^2)} \right)
$$
根据 Wald 序贯概率比准则，当且仅当：
$$
\Lambda_N \ge \frac{1}{\alpha}
$$
时，可以安全地在任意时间提前拒绝零假设（宣称实验组显著优于控制组），且**全局假阳性率严格保证 $\le \alpha$**！
:::

```python
class SequentialTestingEngine:
    def __init__(self, alpha: float = 0.05, tau0_ratio: float = 0.1):
        self.alpha = alpha
        self.tau0_ratio = tau0_ratio

    def evaluate_msprt(self, diff_samples: np.ndarray, sigma: float) -> Tuple[bool, float]:
        n = len(diff_samples)
        if n < 50:
            return False, 1.0
            
        mean_diff = np.mean(diff_samples)
        tau0 = self.tau0_ratio * sigma
        sigma2 = sigma**2
        tau02 = tau0**2
        
        variance_term = sigma2 / (sigma2 + n * tau02)
        exponent_term = (n**2 * tau02 * (mean_diff**2)) / (2.0 * sigma2 * (sigma2 + n * tau02))
        
        lambda_stat = np.sqrt(variance_term) * np.exp(exponent_term)
        threshold = 1.0 / self.alpha
        
        can_stop = lambda_stat >= threshold
        return can_stop, float(lambda_stat)
```

## 14.6 模块五：多臂老虎机与动态探索（Bandits） {#sec-algorithms.14.1.6}

当算法测试从“离线静态验证”进入“在线收益最大化”阶段时，流水线切换到多臂老虎机引擎（Multi-Armed Bandit, MAB），动态将流量导向当前表现最优的候选算法。

### 三大经典 Bandit 算法实现

```python
class EpsilonGreedyBandit:
    """epsilon-Greedy 算法：平衡探索与利用"""
    def __init__(self, k_arms: int, epsilon: float = 0.1):
        self.k = k_arms
        self.epsilon = epsilon
        self.q_values = np.zeros(k_arms)
        self.counts = np.zeros(k_arms, dtype=int)

    def select_arm(self) -> int:
        if np.random.rand() < self.epsilon:
            return np.random.randint(self.k)
        return int(np.argmax(self.q_values))

    def update(self, arm: int, reward: float):
        self.counts[arm] += 1
        self.q_values[arm] += (reward - self.q_values[arm]) / self.counts[arm]

class UCB1Bandit:
    """UCB1 算法：乐观面对不确定性，具有严格对数后悔上界"""
    def __init__(self, k_arms: int):
        self.k = k_arms
        self.q_values = np.zeros(k_arms)
        self.counts = np.zeros(k_arms, dtype=int)
        self.total_pulls = 0

    def select_arm(self) -> int:
        self.total_pulls += 1
        for arm in range(self.k):
            if self.counts[arm] == 0:
                return arm
                
        confidence_bonus = np.sqrt(2.0 * np.log(self.total_pulls) / self.counts)
        ucb_scores = self.q_values + confidence_bonus
        return int(np.argmax(ucb_scores))

    def update(self, arm: int, reward: float):
        self.counts[arm] += 1
        self.q_values[arm] += (reward - self.q_values[arm]) / self.counts[arm]

class ThompsonSamplingBandit:
    """Thompson Sampling 算法：贝叶斯后验采样，在线表现极佳"""
    def __init__(self, k_arms: int):
        self.k = k_arms
        self.alphas = np.ones(k_arms)
        self.betas = np.ones(k_arms)

    def select_arm(self) -> int:
        sampled_thetas = np.random.beta(self.alphas, self.betas)
        return int(np.argmax(sampled_thetas))

    def update(self, arm: int, reward: float):
        if reward > 0.5:
            self.alphas[arm] += 1.0
        else:
            self.betas[arm] += 1.0
```

## 14.7 模块六：个性化因果推断（CATE & Uplift 建模） {#sec-algorithms.14.1.7}

全量 ATE（Average Treatment Effect）往往掩盖了细分人群的异质性：新算法可能极大促进了年轻用户，却严重劝退了中老年用户。
流水线内置 **Meta-Learners** 计算条件平均处理效应（CATE, Conditional Average Treatment Effect）：
$$
\tau(x) = \mathbb{E}[Y(1) - Y(0) \mid X = x]
$$

### T-Learner（双模型学习器）与增益排序

```python
from sklearn.ensemble import RandomForestRegressor

class TLearnerUplift:
    """
    T-Learner: 分别在控制组和实验组拟合两个独立基模型
    mu_0(x) = E[Y | T=0, X=x]
    mu_1(x) = E[Y | T=1, X=x]
    CATE(x) = mu_1(x) - mu_0(x)
    """
    def __init__(self):
        self.model_ctrl = RandomForestRegressor(n_estimators=50, max_depth=5, random_state=42)
        self.model_treat = RandomForestRegressor(n_estimators=50, max_depth=5, random_state=42)

    def fit(self, X_ctrl: np.ndarray, y_ctrl: np.ndarray,
            X_treat: np.ndarray, y_treat: np.ndarray):
        self.model_ctrl.fit(X_ctrl, y_ctrl)
        self.model_treat.fit(X_treat, y_treat)

    def predict_cate(self, X: np.ndarray) -> np.ndarray:
        pred_treat = self.model_treat.predict(X)
        pred_ctrl = self.model_ctrl.predict(X)
        return pred_treat - pred_ctrl
```

    print(f"CUPED指标检验: 估计效应 = +{np.mean(y_treat_cuped)-np.mean(y_ctrl_cuped):.2f} | p值 = {p_cuped:.4e} (显著性极大增强!)")

## 14.9 边界声明与不提供的保证 {#sec-algorithms.14.1.9}

为避免对流水线产生不切实际的工程幻想，本系统明确声明以下**技术边界与不保证事项**：

::: errata 流水线不提供的保证
1. **不保证防御数据上报通道污染**：若客户端上报埋点本身出现系统性丢包或重复上报，流水线无法自动恢复底层事实。
2. **不替代分布式数仓计算**：本流水线为单机/单节点推断核，针对亿级明细事件的聚合（Aggregation）应由外部 ClickHouse / Flink / Spark 完成后，再将聚合分布特征输入本流水线。
3. **不消除未识别的网络外部性（Spillover）**：若在强双边市场中，实验组与控制组在物理空间争夺相同运力，本流水线不会自动修正网络溢出偏误，需用户在实验设计端采用城市切片。
4. **不替代长周期指标追踪**：基于 14 天实验推导出的因果提升，无法外推预测 1 年后的用户疲劳度与长期留存衰减。
:::

## 14.11 本章陷阱 {#sec-algorithms.14.1.11}

::: errata 本章陷阱

1. **偷看数据直接调用 t 检验早停**：假阳性率从 5% 暴涨至 30% 以上，误将随机波动当成正向收益。
2. **忽视 SRM 样本比率偏航硬跑检验**：分流不平衡说明埋点丢失或存在崩溃 Bug，因果无偏性彻底破坏。
3. **CUPED 引入实验期间新特征**：协变量受到处理变量影响，导致真实的算法增益被当做背景噪声去偏扣除。
4. **比率指标直接求平均**：每个用户的点击率不能直接均值相加，必须使用 Delta 方法推导分子分母的协方差。
5. **小流量测试直接推断大盘承载力**：小规模时网络排队不明显，全量上线后触发线程池排队瓶颈。
6. **多臂老虎机用于长期效应衡量**：Bandit 会过快收敛到短期高频点击策略，损害长期用户留存。
7. **遗忘型敌手与适应型敌手混淆**：在对抗环境中盲目使用静态分配策略导致收益崩溃。
8. **忽略新奇效应直接定论**：新算法上线前三天用户因新奇点击暴涨，第四天回落，必须排除前置预热数据。
9. **CATE 建模未做倾向得分加权**：在观察数据上拟合 Meta-Learner 时忽略选择偏差，导致反事实预测有偏。
10. **A/A 检验未通过即开启 A/B 试验**：分流器本身未对齐即盲目上线，无法排除系统固有硬件偏差。
11. **单指标过度优化破坏护栏指标**：CTR 上升但页面耗时增加 500ms，导致长期流失。
12. **忘记保存实验配置快照**：实验参数在线动态调整未留存历史版本，导致事后无法审计复盘。

:::

::: method 即时自测

**题目**：在一次 A/B 测试中，工程师发现目标指标 $Y$ 与实验前协变量 $X$ 的相关系数为 $\rho = 0.80$。
1. 使用 CUPED 调整后，该指标的方差可以缩减多少百分比？
2. 如果在原始指标下，实验需要运行 20 天才能积累到统计功效达到 80% 所需的样本量，使用 CUPED 后理论上只需要运行多少天？

::: sol

**解答**：
1. **计算 CUPED 方差缩减比例**：
   根据定理 8.3.1 与 14.4.1，CUPED 调整后指标的方差满足：
   $$
   \text{Var}(Y_{\text{CUPED}}) = \text{Var}(Y) \cdot (1 - \rho^2)
   $$
   代入 $\rho = 0.80$：
   $$
   1 - \rho^2 = 1 - 0.8^2 = 1 - 0.64 = 0.36
   $$
   调整后的方差仅为原始方差的 $36\%$！
   **方差缩减比例为：$1 - 36\% = 64\%$！**

2. **计算所需实验天数**：
   在固定最小可检测效应 $\delta$、显著性水平 $\alpha$ 和统计功效 $1-\beta$ 下，所需样本量 $N$ 与指标方差 $\sigma^2$ 严格成正比：
   $$
   N \propto \sigma^2
   $$
   因为方差缩减为原来的 $36\%$，所需样本量也缩减为原来的 $36\%$。
   假设每天流入的新增样本量恒定，则所需实验天数为：
   $$
   \text{Days}_{\text{CUPED}} = 20 \times 36\% = 7.2 \text{ 天}
   $$
   **只需运行约 7~8 天**即可获得相同的检测灵敏度，实验周期直接缩短了近两周！
:::
