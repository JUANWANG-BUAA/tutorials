## 13.1 评测系统全景与状态模型 {#sec-algorithms.13.1.1}

### 判题裁决状态机（Verdict Protocol）

评测系统必须将每次执行归约到互斥且完备的裁决状态。标准状态机如下：

::: def 定义 13.1.1 · 评测裁决状态集 (Verdict Set) {#def-algorithms.13.1.1.1}

评测系统的输出裁决 $V$ 取值于离散集合：
1. **AC (Accepted)**：程序正常退出（exit code = 0），在时限与内存限制内产生与标准输出完全一致的结果。
2. **WA (Wrong Answer)**：程序正常退出且未超限，但输出内容与标准答案不符（且非纯空白字符差异）。
3. **PE (Presentation Error)**：输出仅在行尾空格、空行或换行符格式上有差异，逻辑内容一致。
4. **TLE (Time Limit Exceeded)**：程序消耗的 CPU 时间（用户态 + 内核态）超过题目限定的阈值 $T_{\max}$。
5. **MLE (Memory Limit Exceeded)**：程序在执行期间的常驻物理内存峰值（RSS）超过限制 $M_{\max}$。
6. **OLE (Output Limit Exceeded)**：程序写入 `stdout` 或 `stderr` 的总字节数超过安全上限（防止填满磁盘）。
7. **RE (Runtime Error)**：程序以非 0 状态码退出，或触发内核信号终止（如 SIGSEGV 段错误、SIGFPE 浮点除零、SIGABRT 断言失败）。
8. **CE (Compile Error)**：源代码编译失败，编译器输出了致命语法或符号错误。
9. **SE (System Error)**：判题宿主机内部故障（如沙箱初始化失败、磁盘写满），不计入选手失误。
:::

### 核心安全威胁模型

评测系统面对的代码属于**完全不可信输入（Untrusted Arbitrary Code）**。威胁来源主要分为五大类：

| 威胁类型 | 攻击手段 | 潜在后果 | 防御机制 |
|:--|:--|:--|:--|
| **资源耗尽 (DoS)** | Fork 炸弹、申请海量虚拟内存、死循环 | 宿主机卡死、影响其他并发评测任务 | cgroup v2 `pids.max`、`memory.max`、CPU 配额 |
| **持久化篡改** | 修改测试用例文件、篡改评测程序、植入木马 | 窃取题目数据、破坏裁判系统公信力 | 挂载命名空间（Mount Namespace）、只读根文件系统 |
| **网络渗透** | 向内网机器发送探测请求、连接外部 C&C 服务器 | 泄露服务器内网拓扑、外发评测私钥 | 网络命名空间（Network Namespace, `veth` 断开） |
| **信息刺探** | 读取 `/proc/cpuinfo`、读取同机其他用户目录 | 探测其他选手提交、针对 CPU 缓存发起侧信道 | PID 命名空间隔离、限制 `/proc` 与 `/sys` 可见性 |
| **系统调用滥用** | 调用 `ptrace`、`reboot`、`socket`、`chroot` | 破坏宿主机内核、非法提权 | seccomp-bpf 系统调用白名单过滤 |

## 13.3 安全沙箱核心技术：从 seccomp 到 cgroup v2 {#sec-algorithms.13.1.3}

沙箱是评测系统的心脏。在现代 Linux 系统上，最轻量级且牢不可破的沙箱组合是 **Linux Namespaces + cgroup v2 + seccomp-bpf**。

### 1. 系统调用白名单与 seccomp-bpf

默认情况下，Linux 6.x 内核向用户态暴露超过 450 个系统调用。算法代码在完成计算时，通常只需要不到 20 个系统调用（如 `read`, `write`, `exit_group`, `brk`, `mmap`, `fstat`）。其余所有系统调用（特别是 `execve`, `clone`, `socket`, `kill`, `openat` 写入模式）都应被硬拦截。

::: def 机制 13.3.1 · seccomp 伯克利包过滤器 (seccomp-bpf) {#def-algorithms.13.3.1.1}

seccomp（Secure Computing Mode）允许开发者向内核注册一段编译好的 BPF（Berkeley Packet Filter）字节码。每当受测程序发起系统调用时，内核在特权切换的第一时刻执行该 BPF 规则：
- 若系统调用号位于白名单中：放行（`SECCOMP_RET_ALLOW`）；
- 若系统调用号非法：直接终止进程（`SECCOMP_RET_KILL_PROCESS`）并记录审计日志。
:::

以下是专为算法竞赛受控执行设计的最小 C 语言沙箱启动包装器核心逻辑：

```c
// ... (Linux 专属沙箱系统调用过滤，依赖 <linux/seccomp.h>)
// sandbox_runner.c - 极简高性能沙箱包装器
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <fcntl.h>
#include <sys/prctl.h>
#include <sys/resource.h>
#include <sys/wait.h>
#include <linux/seccomp.h>
#include <linux/filter.h>
#include <linux/audit.h>
#include <sys/syscall.h>

// 构造 BPF 字节码规则：只允许计算与基础 I/O
static int apply_seccomp_filter(void) {
    struct sock_filter filter[] = {
        // 加载系统调用架构
        BPF_STMT(BPF_LD | BPF_W | BPF_ABS, offsetof(struct seccomp_data, arch)),
        // 确保匹配当前机器架构 (x86_64)
        BPF_JUMP(BPF_JMP | BPF_JEQ | BPF_K, AUDIT_ARCH_X86_64, 1, 0),
        BPF_STMT(BPF_RET | BPF_K, SECCOMP_RET_KILL),

        // 加载系统调用号
        BPF_STMT(BPF_LD | BPF_W | BPF_ABS, offsetof(struct seccomp_data, nr)),

        // 基础计算与退出白名单
        BPF_JUMP(BPF_JMP | BPF_JEQ | BPF_K, __NR_read, 11, 0),
        BPF_JUMP(BPF_JMP | BPF_JEQ | BPF_K, __NR_write, 10, 0),
        BPF_JUMP(BPF_JMP | BPF_JEQ | BPF_K, __NR_fstat, 9, 0),
        BPF_JUMP(BPF_JMP | BPF_JEQ | BPF_K, __NR_mmap, 8, 0),
        BPF_JUMP(BPF_JMP | BPF_JEQ | BPF_K, __NR_mprotect, 7, 0),
        BPF_JUMP(BPF_JMP | BPF_JEQ | BPF_K, __NR_munmap, 6, 0),
        BPF_JUMP(BPF_JMP | BPF_JEQ | BPF_K, __NR_brk, 5, 0),
        BPF_JUMP(BPF_JMP | BPF_JEQ | BPF_K, __NR_exit_group, 4, 0),
        BPF_JUMP(BPF_JMP | BPF_JEQ | BPF_K, __NR_exit, 3, 0),
        BPF_JUMP(BPF_JMP | BPF_JEQ | BPF_K, __NR_lseek, 2, 0),
        BPF_JUMP(BPF_JMP | BPF_JEQ | BPF_K, __NR_getrandom, 1, 0),

        // 非白名单系统调用直接 KILL 进程
        BPF_STMT(BPF_RET | BPF_K, SECCOMP_RET_KILL_PROCESS),
        // 白名单通过
        BPF_STMT(BPF_RET | BPF_K, SECCOMP_RET_ALLOW),
    };

    struct sock_fprog prog = {
        .len = (unsigned short)(sizeof(filter) / sizeof(filter[0])),
        .filter = filter,
    };

    // 禁用任何提权能力 (PR_SET_NO_NEW_PRIVS)
    if (prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0) != 0) {
        perror("prctl NO_NEW_PRIVS failed");
        return -1;
    }
    // 载入过滤器
    if (prctl(PR_SET_SECCOMP, SECCOMP_MODE_FILTER, &prog) != 0) {
        perror("prctl SECCOMP failed");
        return -1;
    }
    return 0;
}
```

### 2. cgroup v2 资源精确控制

Linux cgroup v2 提供了一个统一层级文件树。沙箱在启动前为每个评测任务在 `/sys/fs/cgroup/oj/` 下创建一个临时子目录：

- `memory.max`：写入内存硬上限（如 `268435456` 即 256MB）。超出时内核直接杀死触发进程（发送 SIGKILL，`oom_kill` 计数器加 1）。
- `memory.swap.max`：设为 `0`，杜绝程序利用交换分区避开内存检查。
- `pids.max`：设为 `1`（C++程序）或 `64`（JVM 多线程），从根本上粉碎任何 Fork 炸弹。
- `cpu.max`：设置配额带宽，防止死循环耗尽整颗物理核心影响调度。

```bash
# 宿主机上由 Judge Worker 动态配置 cgroup
CG_PATH="/sys/fs/cgroup/oj/task_${SUBMISSION_ID}"
mkdir -p "$CG_PATH"
echo "268435456" > "$CG_PATH/memory.max"
echo "0" > "$CG_PATH/memory.swap.max"
echo "1" > "$CG_PATH/pids.max"
# 将子进程 PID 写入 cgroup.procs 即可自动受控
echo "$CHILD_PID" > "$CG_PATH/cgroup.procs"
```

## 13.4 精确资源采样与比对校验器 {#sec-algorithms.13.1.4}

评测最怕“超时判错”与“内存测量飘移”。评测系统如何排除垃圾回收、初始化开销与操作系统调度噪声？

### 1. 用户态与内核态 CPU 时间提取

不要使用 Wall Clock（挂钟时间）作为评测标准！挂钟时间严重受宿主机其他进程竞争、锁竞争与 I/O 阻塞影响。唯一合法的计时标准是进程及其子树消耗的 **CPU 运行时间（`utime + stime`）**。

```python
import os
import time

def parse_proc_cpu_time(pid: int) -> int:
    """
    通过读取 /proc/[pid]/stat 精确提取进程 CPU 时钟周期
    输出转换为毫秒
    """
    try:
        with open(f"/proc/{pid}/stat", "r") as f:
            stats = f.read().split()
            # stat 第 14 项为 utime (用户态 ticks), 第 15 项为 stime (内核态 ticks)
            utime = int(stats[13])
            stime = int(stats[14])
            clock_ticks_per_sec = os.sysconf(os.sysconf_names['SC_CLK_TCK'])
            total_time_ms = int(((utime + stime) / clock_ticks_per_sec) * 1000)
            return total_time_ms
    except (FileNotFoundError, ProcessLookupError, IndexError):
        return 0
```

### 2. Special Judge 与浮点容差比较算法

标准比赛中常遇到答案不唯一（如输出任意合法路径）或允许浮点误差（如 $|A - B| \le 10^{-6}$）。通用的 Special Judge 比较引擎实现如下：

```python
import math

def float_tolerant_compare(user_output: str, std_output: str, eps: float = 1e-6) -> bool:
    """
    支持浮点相对误差与绝对误差的 Checker
    max(|a - b| / max(1, |b|)) <= eps
    """
    user_tokens = user_output.strip().split()
    std_tokens = std_output.strip().split()

    if len(user_tokens) != len(std_tokens):
        return False

    for u_tok, s_tok in zip(user_tokens, std_tokens):
        try:
            u_val = float(u_tok)
            s_val = float(s_tok)
            abs_err = abs(u_val - s_val)
            rel_err = abs_err / max(1.0, abs(s_val))
            if abs_err > eps and rel_err > eps:
                return False
        except ValueError:
            # 文本 token 精确匹配
            if u_tok != s_tok:
                return False

    return True
```

## 13.5 自动化测试用例生成与对拍验证（Stress Testing） {#sec-algorithms.13.1.5}

没有高质量的测试用例，评测系统就是无源之水。如何构建能瞬间打崩“伪最优算法”的对抗输入？

::: method 方法 13.5.1 · 对拍机制（Stress Testing 管道） {#method-algorithms.13.5.1.1}

构建三个核心脚本：
1. **Generator (`gen.py`)**：参数化随机输入生成器，支持规模从 $N=1$ 到极限规模 $N=10^6$，且能强制生成极端图（链状图、菊花图、稠密完全图）。
2. **Brute Force (`brute.py`)**：暴力搜索或动态规划标准解法，代码简单且保证 100% 正确，但时间复杂度高（作为 Ground Truth Oracle）。
3. **Optimized Solution (`sol.py`)**：待测试的复杂算法（可能是选手提交，或优化后的高级算法）。

自动化对拍器不断循环生成随机与对抗用例，直到捕捉到两者的第一个差异。
:::

```python
import random
import subprocess
import sys

def generate_adversarial_graph(n: int, max_w: int = 1000):
    """
    专门针对错误 Dijkstra / SPFA 生成的对抗图：
    构造一条长链 + 跨层捷径，使得松弛操作次数达到指数级
    """
    edges = []
    for i in range(1, n):
        # 链状主边
        edges.append((i, i + 1, random.randint(1, 10)))
        # 诱骗快速到达的长边
        if i + 2 <= n:
            edges.append((i, i + 2, random.randint(10, max_w)))
    return n, edges

def run_stress_pipeline(rounds: int = 1000):
    print("=" * 60)
    print(f"启动自动对拍流水线 (目标轮数: {rounds})")
    print("=" * 60)

    for r in range(1, rounds + 1):
        n = random.randint(3, 50)
        n, edges = generate_adversarial_graph(n)
        input_data = f"{n} {len(edges)}\n" + "\n".join(f"{u} {v} {w}" for u, v, w in edges) + "\n"

        p_brute = subprocess.run(["python3", "tests/brute.py"], input=input_data, text=True, capture_output=True)
        p_sol = subprocess.run(["python3", "tests/sol.py"], input=input_data, text=True, capture_output=True)

        if p_brute.stdout.strip() != p_sol.stdout.strip():
            print(f"\n[FAIL] 在第 {r} 轮对拍中成功捕获反例！")
            return False

        if r % 100 == 0:
            print(f"  已成功通过 {r} 组随机极端用例...")

    print(f"\n[PASS] 对拍完成，全部 {rounds} 组极端测试用例验证一致！")
    return True
```

## 13.6 代码抄袭检测引擎：Winnowing 指纹算法 {#sec-algorithms.13.1.6}

在竞赛评测中，防作弊与相似度检测是核心功能。经典的朴素编辑距离比较算法对于万行级提交的时间复杂度为 $O(L^2)$，无法实时执行。业界公认的标准是 **Winnowing 局部敏感指纹算法**（Schleimer et al., ACM SIGMOD 2003）。

::: thm 定理 13.6.1 · Winnowing 算法性质 {#thm-algorithms.13.6.1.1}

Winnowing 具备以下三大优异数学特性：
1. **空白与换行无关性**：在提取 token 流前过滤空白、注释，对代码格式重排免疫。
2. **标识符重命名无关性**：将所有用户定义的变量名、函数名替换为统一符号（如 `V`），使得简单的替换变量名作弊失效。
3. **局部敏感保真度**：对于任意长度为 $t$ 的公共子序列，必能在两个文档中选取出至少一个相同的哈希指纹，且两篇文档的指纹交集比例严格渐近于其实际 Jaccard 相似度。
:::

### Winnowing 核心实现

```python
import hashlib
import re
from typing import List, Set

def tokenize_and_normalize(code: str) -> str:
    """词法级归一化：中和注释、空白与标识符变量重命名"""
    code = re.sub(r"#.*", "", code)
    code = re.sub(r"//.*", "", code)
    keywords = {"def", "import", "for", "in", "while", "if", "continue", "return", "as", "float", "len", "range"}
    tokens = re.findall(r"[a-zA-Z_]\w*|[0-9]+|[^\s\w]", code)
    norm = []
    for t in tokens:
        if t in keywords:
            norm.append(t)
        elif t.isdigit():
            norm.append("N")
        elif re.match(r"^[a-zA-Z_]\w*$", t):
            norm.append("V")
        else:
            norm.append(t)
    return "".join(norm)

def compute_k_grams(text: str, k: int = 15) -> List[int]:
    """生成 k-gram 的 64 位整数哈希序列"""
    hashes = []
    for i in range(len(text) - k + 1):
        kgram = text[i:i + k]
        h = int(hashlib.md5(kgram.encode("utf-8")).hexdigest()[:16], 16)
        hashes.append(h)
    return hashes

def winnowing(hashes: List[int], window_size: int = 10) -> Set[int]:
    """滑动窗口选出右侧最小指纹"""
    fingerprints = set()
    n = len(hashes)
    if n < window_size:
        return set(hashes) if hashes else set()

    for i in range(n - window_size + 1):
        window = hashes[i:i + window_size]
        min_val = min(window)
        fingerprints.add(min_val)

    return fingerprints

def compute_similarity(code_a: str, code_b: str, k: int = 12, w: int = 8) -> float:
    norm_a = tokenize_and_normalize(code_a)
    norm_b = tokenize_and_normalize(code_b)

    fp_a = winnowing(compute_k_grams(norm_a, k), w)
    fp_b = winnowing(compute_k_grams(norm_b, k), w)

    if not fp_a or not fp_b:
        return 0.0

    intersection = fp_a.intersection(fp_b)
    union = fp_a.union(fp_b)
    return len(intersection) / len(union)
```

## 13.7 完整评测引擎整合与验收测试 {#sec-algorithms.13.1.7}

轻量级完整评测系统单机原型（包含判题执行、内存监测、Checker 比对与 Winnowing 抄袭检测）：

```python
import sys
import time
import subprocess
from typing import Dict, Any

class LightweightJudge:
    def __init__(self, time_limit_sec: float = 1.0, memory_limit_mb: int = 128):
        self.time_limit = time_limit_sec
        self.memory_limit = memory_limit_mb

    def judge_solution(self, solution_script: str, input_str: str, expected_out: str) -> Dict[str, Any]:
        start_time = time.perf_counter()
        try:
            proc = subprocess.run(
                [sys.executable, solution_script],
                input=input_str,
                text=True,
                capture_output=True,
                timeout=self.time_limit
            )
            elapsed_time = time.perf_counter() - start_time

            if proc.returncode != 0:
                return {
                    "verdict": Verdict.RUNTIME_ERROR,
                    "time_ms": int(elapsed_time * 1000),
                    "stderr": proc.stderr[:200]
                }

            user_ans = proc.stdout.strip()
            expected_ans = expected_out.strip()

            if user_ans == expected_ans:
                return {"verdict": Verdict.ACCEPTED, "time_ms": int(elapsed_time * 1000)}
            elif "".join(user_ans.split()) == "".join(expected_ans.split()):
                return {"verdict": Verdict.PRESENTATION_ERROR, "time_ms": int(elapsed_time * 1000)}
            else:
                return {
                    "verdict": Verdict.WRONG_ANSWER,
                    "time_ms": int(elapsed_time * 1000),
                    "user_out": user_ans[:100],
                    "expected_out": expected_ans[:100]
                }

        except subprocess.TimeoutExpired:
            return {"verdict": Verdict.TIME_LIMIT_EXCEEDED, "time_ms": int(self.time_limit * 1000)}
        except Exception as e:
            return {"verdict": Verdict.SYSTEM_ERROR, "error": str(e)}
```

## 13.8 Agent 陷阱案例：评测系统开发中的 8 大灾难案例 {#sec-algorithms.13.1.8}

::: errata 真实灾难排查台账
1. **直接使用 `subprocess.run(shell=True)`**：用户提交包含 `system("rm -rf /")`，直接获得宿主机 Shell 权限并摧毁磁盘。严禁 `shell=True`。
2. **用 Wall Clock 时间代替 CPU 执行时间判定 TLE**：多核并发负载高时，线程因抢占时间片发生等待，导致随机误判 TLE。必须读取 `/proc/[pid]/stat` 的 `utime + stime`。
3. **内存测量只读退出时的 RSS**：选手程序在执行中间申请 2GB 内存填满数据，退出前调用 `free()` 释放，被错误判为占用极小。必须采样 cgroup `memory.peak` 峰值。
4. **未屏蔽 SIGPIPE 信号导致评测 Worker 闪崩**：受测程序提前退出后，Worker 再次向管道写数据触发 `SIGPIPE` 导致自身终止。必须显式 `signal(SIGPIPE, SIG_IGN)`。
5. **抄袭检测误把算法标程模板当成抄袭证据**：全场选手因使用官方 FastIO 输入输出模板，查重相似度飙升到 85% 以上。必须建立题目级模板黑名单求差集过滤。
6. **临时文件未隔离导致竞态条件（Race Condition）**：多进程 Worker 之间相互覆盖 `test.in` 和 `test.out`，产生神仙级随机判定。必须使用独立 UUID 临时目录。
7. **未设置编译超时导致模板爆炸攻击**：C++ 模板元编程无限递归，导致编译器卡死并耗尽服务器 100% 内存。编译命令必须同样受时限与内存配额保护。
8. **忽略浮点输出的 `-0.0` 符号**：浮点输出中 `-0.000` 与 `0.000` 在直接字符串比对下被误判为 WA。必须用 Token 浮点容差比较器。
:::

## 13.11 本章陷阱 {#sec-algorithms.13.1.11}

::: errata 本章陷阱

1. **直接调用 Shell 传参执行**：使用字符串拼接执行命令，被 `; rm -rf /` 代码注入彻底摧毁宿主机。
2. **挂钟时间代替 CPU 运行时间**：宿主机负载波动引发大面积冤假错案式 TLE。
3. **内存采样在进程退出后提取**：未监控到进程生命周期内部的动态内存分配峰值。
4. **未忽略 SIGPIPE 信号**：受测程序异常退出导致 Worker 自身被内核终止退出。
5. **公共临时目录引发文件名冲突**：并发判题时临时测试文件被彼此覆盖导致随机判定。
6. **Winnowing 未泛化用户标识符**：仅去空格与注释，变量名简单改名即可绕过查重。
7. **未拦截编译期宏展开炸弹**：C++ 模板与嵌套头文件导致编译耗尽内存。
8. **浮点比对未设相对误差**：大数值浮点比对绝对误差超限引发假 WA。
9. **对拍测试生成器用例过于单一**：只生成随机小图，未生成极端长链与完全图，漏过性能退化 Bug。
10. **沙箱未断开外部网络**：选手代码建立 Socket 连接外发题目数据或进行内网端口扫描。
11. **单进程阻塞判题导致队列雪崩**：一个卡死用例阻塞整条流水线，必须配置硬看门狗（Watchdog）。
12. **错误状态码未做信号映射**：将段错误 SIGSEGV（139）误报为普通非零退出码，缺乏诊断透明度。

:::

::: method 即时自测

**题目**：在设计在线评测系统的安全沙箱时，如果仅使用操作系统的 `setrlimit(RLIMIT_AS, &limit)` 来限制进程的最大虚拟内存空间（Address Space），为什么**不足以**安全防御恶意内存消耗攻击？

::: sol

**解答**：
**仅依赖 `RLIMIT_AS` 存在两大致命缺陷**：
1. **JVM / Go 运行时初始化直接崩溃**：
   现代语言运行时（如 Java 虚拟机 JVM 或 Go 运行时）在启动初期就会预先为垃圾回收器、线程栈和元空间分配巨大的虚拟内存地址段（例如 JVM 默认直接向操作系统预留数 GB 的虚拟内存空间，即使实际物理驻留内存 RSS 只有数十 MB）。设置 `RLIMIT_AS` 会导致这些语言的正常合法程序在启动阶段直接因为 `mmap` 失败而闪崩报 RE。
2. **无法阻止 Swap 交换区滥用与内存耗尽攻击**：
   `RLIMIT_AS` 限制的是虚拟地址空间总量，而不是实际物理内存占用。此外，恶意程序可以通过频繁的内存缺页换入换出拖垮宿主机的磁盘 I/O。

**正规防御手段**：
必须使用现代 Linux 内核的 **cgroup v2 内存控制器**：
- 写入 `memory.max`：严格限制实际物理内存占用（RSS）；
- 写入 `memory.swap.max = 0`：彻底关闭受测进程的交换分区使用权；
- 超出配额时由内核 OOM Killer 精确杀死受测进程并记录 `oom_kill` 事件，对外部宿主机及其他并发任务完全零冲击。
:::
