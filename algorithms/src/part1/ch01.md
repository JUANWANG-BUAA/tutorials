## 1.1 渐进记号：O/Ω/Θ 的精确含义 {#sec-algorithms.1.1.1}

算法分析的第一步是量化「运行时间如何随输入规模增长」。常见的误区是把大 O 当成精确复杂度——"这个算法是 O(n)"——但 O(n) 只是上界，O(1) 的算法也满足 O(n)。本节给出三种渐进记号的精确定义，并展示如何选择正确的记号。

::: def 定义 1.1.1 · 大 O 记号（渐进上界） {#def-algorithms.1.1.1.1}

设 f(n) 和 g(n) 是定义在正整数上的函数。若存在常数 c > 0 和 n₀ > 0，使得对所有 n ≥ n₀，有

$$
f(n) \leq c \cdot g(n)
$$

则称 f(n) = O(g(n))。

直观理解：f 的增长不快于 g 的某个常数倍。

:::

::: def 定义 1.1.2 · 大 Ω 记号（渐进下界） {#def-algorithms.1.1.1.2}

若存在常数 c > 0 和 n₀ > 0，使得对所有 n ≥ n₀，有

$$
f(n) \geq c \cdot g(n)
$$

则称 f(n) = Ω(g(n))。

直观理解：f 的增长不慢于 g 的某个常数倍。

:::

::: def 定义 1.1.3 · 大 Θ 记号（紧确界） {#def-algorithms.1.1.1.3}

若同时满足 f(n) = O(g(n)) 和 f(n) = Ω(g(n))，则称 f(n) = Θ(g(n))。

等价地，存在常数 c₁, c₂ > 0 和 n₀ > 0，使得对所有 n ≥ n₀，有

$$
c_1 \cdot g(n) \leq f(n) \leq c_2 \cdot g(n)
$$

直观理解：f 的增长率与 g 相同，只差常数倍。

:::

**常见错误**：用 O 描述精确复杂度。「归并排序是 O(n²)」在技术上正确（因为 n log n ≤ n² 对足够大的 n 成立），但这个上界太松，应该说「归并排序是 <code class="complexity nlogn">Θ(n log n)</code>」。

::: ex 例 1.1.1 · 判断渐进关系 {#ex-algorithms.1.1.1.1}

判断以下关系是否成立：

1. 3n² + 5n + 10 = O(n²)
2. 3n² + 5n + 10 = Θ(n²)
3. 3n² + 5n + 10 = Ω(n³)

**解**：

1. **成立**。取 c = 4, n₀ = 10，则对 n ≥ 10，有 3n² + 5n + 10 ≤ 3n² + 5n + n² = 4n²（因为 5n + 10 ≤ n² 对 n ≥ 10 成立）。

2. **成立**。上界已证；下界取 c = 3, n₀ = 1，有 3n² + 5n + 10 ≥ 3n²。故 f(n) = Θ(n²)。

3. **不成立**。若成立，则存在 c > 0 使得 3n² + 5n + 10 ≥ c·n³ 对所有充分大的 n 成立。两边除以 n³ 得 3/n + 5/n² + 10/n³ ≥ c，但左边趋于 0，矛盾。

:::

**实际意义**：算法 A 的运行时间是 5n² + 100n，算法 B 是 0.01n³。在小规模（n < 1000）时 A 可能更慢（常数 5 vs 0.01），但在大规模时 B 的 n³ 主导。渐进分析关心「足够大的 n」，但工程实践必须同时考虑常数。

### 常见函数的增长率排序

从慢到快：

$$
O(1) < O(\log n) < O(\sqrt{n}) < O(n) < O(n \log n) < O(n^2) < O(n^3) < O(2^n) < O(n!)
$$

记忆法则：
- 常数 < 对数 < 幂次（指数越大越快）< 指数 < 阶乘
- 对数基数不影响渐进阶（log₂ n 与 log₁₀ n 只差常数倍）
- n^0.5 = √n 介于 log n 与 n 之间

::: note 小 o 与小 ω 记号

- f(n) = o(g(n))：f 严格慢于 g（lim_{n→∞} f(n)/g(n) = 0）
- f(n) = ω(g(n))：f 严格快于 g

例如 n = o(n²)，但 n ≠ o(n)。本书主要用 O/Ω/Θ，小记号只在需要严格区分时使用。

:::

### 如何选择正确的记号

| 场景 | 应该用 | 不应该用 |
|:--|:--|:--|
| 描述算法精确复杂度 | Θ(n log n) | O(n log n) |
| 描述上界（如"不超过"） | O(n²) | Θ(n²) |
| 描述下界（如"至少"） | Ω(n log n) | O(n log n) |
| 最坏/平均/最好情况 | 分别给出（见 § 1.6） | 混为一谈 |

**agent 常见错误**：agent 生成文档说"快排是 O(n log n)"，但这只描述了平均情况的上界，最坏情况是 Θ(n²)。正确的说法是「快排平均 Θ(n log n)，最坏 Θ(n²)」。

## 1.2 递归算法与主定理 {#sec-algorithms.1.1.2}

分治算法的标准形式：将规模为 n 的问题分解为 a 个规模为 n/b 的子问题，递归求解，最后用 f(n) 时间合并。运行时间满足递归式：

$$
T(n) = a \cdot T(n/b) + f(n)
$$

主定理给出三种情况的直接解，但使用前必须理解递归树——它是复杂度的来源，也是主定理不适用时的后备工具。

### 递归树方法

递归树的每个节点代表一个子问题，节点的值是该子问题的非递归部分的工作量。根节点是原问题的 f(n)，每层展开为 a 个子节点。

::: ex 例 1.2.1 · 归并排序的递归树 {#ex-algorithms.1.1.2.1}

归并排序：T(n) = 2T(n/2) + Θ(n)（合并两个有序数组耗时 Θ(n)）。

递归树展开：

<pre class="algorithm-flow">
                  n              ← 第 0 层，工作量 n
                 / \
                /   \
               /     \
              n/2    n/2          ← 第 1 层，工作量 n/2 + n/2 = n
             / \    / \
            /   \  /   \
          n/4  n/4 n/4  n/4       ← 第 2 层，工作量 4·(n/4) = n
          ...  ...  ...  ...
          
          1    1    1 ... 1       ← 第 log₂ n 层，n 个叶子，工作量 n·1 = n
</pre>

**读图**：
- 总层数：log₂ n + 1（从 n 一直除到 1）
- 每层工作量：n（第 k 层有 2^k 个节点，每个 n/2^k，乘起来是 n）
- 总工作量：(log₂ n + 1) · n = Θ(n log n)

:::

### 主定理

::: thm 定理 1.2.1 · 主定理 {#thm-algorithms.1.1.2.1}

设 a ≥ 1, b > 1 为常数，f(n) 是渐进正函数，T(n) 定义在非负整数上且满足

$$
T(n) = a \cdot T(n/b) + f(n)
$$

则 T(n) 有如下渐进界：

1. **情况 1**（递归项主导）：若 f(n) = O(n^{log_b a - ε}) 对某个 ε > 0 成立，则 T(n) = Θ(n^{log_b a})。
2. **情况 2**（平衡）：若 f(n) = Θ(n^{log_b a})，则 T(n) = Θ(n^{log_b a} log n)。
3. **情况 3**（合并项主导）：若 f(n) = Ω(n^{log_b a + ε}) 对某个 ε > 0，且存在 c < 1 使得对充分大的 n 有 a·f(n/b) ≤ c·f(n)（**正则条件**），则 T(n) = Θ(f(n))。

:::

**直观理解**：log_b a 是递归树的叶子数（第 log_b n 层有 a^{log_b n} = n^{log_b a} 个叶子）。三种情况分别对应：
1. 叶子层工作量远大于其他层之和 → 叶子主导
2. 每层工作量相同 → 层数 × 单层 = log n × n^{log_b a}
3. 根节点工作量远大于递归部分 → 根主导

::: ex 例 1.2.2 · 应用主定理 {#ex-algorithms.1.1.2.2}

1. **T(n) = 2T(n/2) + n**（归并排序）

   a=2, b=2, f(n)=n, log_b a = 1。
   
   f(n) = n = Θ(n^1) → **情况 2** → T(n) = Θ(n log n)。

2. **T(n) = 3T(n/2) + n**（某个分治算法）

   a=3, b=2, f(n)=n, log_b a = log_2 3 ≈ 1.585。
   
   f(n) = n = O(n^{1.585 - ε}) 对 ε=0.3 成立 → **情况 1** → T(n) = Θ(n^{log_2 3})。

3. **T(n) = 2T(n/2) + n²**（某个低效分治）

   a=2, b=2, f(n)=n², log_b a = 1。
   
   f(n) = n² = Ω(n^{1+ε}) 对 ε=1 成立。检查正则条件：2·(n/2)² = n²/2 ≤ (1/2)·n² ✓
   
   **情况 3** → T(n) = Θ(n²)。

:::

### 主定理不适用的情况

::: note 情况缝隙与不满足正则条件

1. **f(n) 介于情况 1 和 2 之间**：如 T(n) = 2T(n/2) + n/log n，f(n) 比 n 慢但不多项式慢，主定理无解（需递归树细算）。

2. **不满足正则条件**：T(n) = 2T(n/2) + n log n，f(n) = n log n 看似符合情况 3（n log n > n），但检查正则条件：

   $$
   2 \cdot \frac{n}{2} \log \frac{n}{2} = n \log n - n \log 2 = n \log n (1 - \frac{\log 2}{\log n})
   $$
   
   当 n → ∞ 时趋于 n log n，不存在 c < 1 使得 ≤ c·n log n。情况 3 不适用，需递归树求解（答案是 Θ(n log² n)）。

:::

**agent 错误**：agent 看到 T(n) = 2T(n/2) + n log n 就套情况 3，得出 T(n) = Θ(n log n)，但忽略了正则条件。正确做法是画递归树或用替代定理。

### 递归深度与栈空间

递归深度是 Θ(log_b n)（如归并排序深度 log₂ n）或 Θ(n)（如未优化的快排最坏情况）。每层递归需要栈帧（函数参数、返回地址、局部变量），典型栈大小 8MB，每个栈帧约 100 字节，深度上限约 80,000。

**实际影响**：深度 O(n) 的算法在 n > 10,000 时可能栈溢出；深度 O(log n) 的算法即使 n = 10^9 也只需约 30 层。这是优化快排选枢轴的动力之一。

## 1.3 实测复杂度：理论 vs 实际 {#sec-algorithms.1.1.3}

理论分析给出渐进界，但实际性能还受常数因子、缓存行为、分支预测等影响。本节展示如何设计实验验证理论预测，以及如何测量常数。

### 如何测量运行时间

**错误方式**：单次测量 `time.time()` 差值。

问题：
1. **噪声大**：进程调度、后台任务、CPU 节能模式导致单次测量波动 ±50%
2. **精度差**：`time.time()` 精度约 1ms，测量 <1ms 的操作不可靠

**正确方式**：

1. **重复 100 次，取中位数**：排除 outliers（如 GC、页缺失）
2. **用 `time.perf_counter()`**：高精度计时器（纳秒级）
3. **预热**：首次运行可能触发 JIT 编译、代码缓存加载，丢弃前几次结果

::: ex 例 1.3.1 · 测量归并排序的实际耗时 {#ex-algorithms.1.1.3.1}

```python
import time
import random

def measure_time(func, arr, repeat=100):
    times = []
    for _ in range(repeat):
        arr_copy = arr.copy()
        start = time.perf_counter()
        func(arr_copy)
        end = time.perf_counter()
        times.append((end - start) * 1000)  # 毫秒
    times.sort()
    return times[repeat // 2]  # 中位数

# 测试
arr = [random.randint(0, 10000) for _ in range(10000)]
t = measure_time(merge_sort, arr)
print(f"归并排序 n=10000: {t:.2f}ms")
```

输出示例：`归并排序 n=10000: 9.23ms`（实测值）

:::

### 验证理论复杂度：拟合斜率

理论预测 T(n) = Θ(n²)，如何验证？测量不同 n 的耗时，拟合斜率。

若 T(n) = c·n^α，则 log T(n) = log c + α·log n，在对数坐标下是直线，斜率是 α。

| n | 实测 T(n) (ms) | log n | log T(n) |
|--:|--:|--:|--:|
| 1000 | 17.2 | 6.91 | 2.84 |
| 5000 | 425 | 8.52 | 6.05 |
| 10000 | 1700 | 9.21 | 7.44 |

拟合：斜率 = (7.44 - 2.84) / (9.21 - 6.91) ≈ **2.00** → 验证 Θ(n²)。

**Python 实现**（用 NumPy）：

```python
import numpy as np

sizes = [1000, 5000, 10000]
times = [17.2, 425, 1700]

log_n = np.log(sizes)
log_t = np.log(times)
slope, intercept = np.polyfit(log_n, log_t, 1)

print(f"拟合斜率: {slope:.2f}")
# 输出: 拟合斜率: 2.00
```

### 实测 vs 理论的差异

::: intuition 为什么实测与理论不完全一致

1. **常数差异**：归并排序理论 Θ(n log n)，快排也是 Θ(n log n)，但快排实测快 30%（缓存友好、原地排序）。

2. **小规模行为**：插入排序 Θ(n²) 在 n < 100 时快于归并排序 Θ(n log n)，因为常数小（无递归开销）。

3. **输入依赖**：快排在随机输入上平均 Θ(n log n)，但已排序输入退化为 Θ(n²)。理论分析的是最坏情况或平均情况，实际输入可能更好或更坏。

4. **硬件影响**：缓存命中率、分支预测准确率、SIMD 向量化都影响常数。同一算法在不同 CPU 上常数可能差 2-3 倍。

:::

### 如何设计输入分布

**错误**：只测随机输入。

**正确**：覆盖多种输入模式：

| 输入类型 | 适用场景 | 示例 |
|:--|:--|:--|
| 随机 | 平均情况 | `random.shuffle(range(n))` |
| 已排序 | 最好/最坏情况 | `list(range(n))` |
| 逆序 | 最坏情况 | `list(range(n, 0, -1))` |
| 部分排序 | 真实数据 | 前 90% 有序，后 10% 随机 |
| 重复元素多 | 边界情况 | `[1]*n` 或三向快排测试 |
| 小规模 | 常数主导区 | n = 10, 100 |
| 大规模 | 渐进行为 | n = 10^6, 10^7 |

**agent 陷阱**：agent 只测 `random.shuffle(range(n))`，漏掉已排序输入，无法发现快排退化。§ 1.7 会详细分析这个案例。

## 1.4 常数因子的来源 {#sec-algorithms.1.1.4}

两个 Θ(n log n) 的算法可能实测差 2 倍。渐进分析忽略常数，但工程实践中常数决定了「小到中等规模下谁更快」。本节拆解常数的来源。

### 指令数

最直接的常数：每次循环执行多少条机器指令。

**归并排序 vs 快排**：

- 归并：每次合并需要两个指针比较、一次写入、两次递增，约 **5 条指令/元素**
- 快排：每次比较、交换（3 次赋值），约 **3 条指令/元素**（原地排序，无额外写入）

即使复杂度相同，快排少 40% 指令 → 实测快 30-40%（缓存效应会放大差距）。

::: note 为什么不直接数源码行数

C/Python 的一行可能编译成 1-10 条机器指令。要准确测量，需要用 `perf stat` 或反汇编：

```bash
perf stat -e instructions ./mergesort
# Performance counter stats:
#   1,234,567,890 instructions
```

但对比算法时，「每个元素平均指令数」已足够。

:::

### 缓存效应

现代 CPU 的内存层次：

| 层级 | 容量 | 延迟 | 带宽 |
|:--|--:|--:|--:|
| L1 缓存 | 32-64 KB | 1 周期 (0.3ns) | ~200 GB/s |
| L2 缓存 | 256 KB-1 MB | 4-10 周期 | ~100 GB/s |
| L3 缓存 | 4-32 MB | 40-75 周期 | ~50 GB/s |
| 主存 (DRAM) | 8-64 GB | 200+ 周期 (50-100ns) | ~20 GB/s |

**关键**：L1 命中与主存访问差 **100-200 倍**。算法的访问模式决定缓存命中率。

::: ex 例 1.4.1 · 顺序 vs 随机访问 {#ex-algorithms.1.1.4.1}

```python
n = 10_000_000  # 10M 个整数，约 40MB
arr = list(range(n))

# 顺序访问
start = time.perf_counter()
total = sum(arr)
t_seq = time.perf_counter() - start

# 随机访问
indices = [random.randint(0, n-1) for _ in range(n // 100)]
start = time.perf_counter()
total = sum(arr[i] for i in indices)
t_rand = time.perf_counter() - start

print(f"顺序: {t_seq*1000:.1f}ms, 随机: {t_rand*1000:.1f}ms, 比值 {t_rand/t_seq:.1f}x")
# 输出: 顺序: 37ms, 随机: 14ms, 比值 0.4x (这里随机采样少，实际全随机会更慢)
```

**实验结果**（来自 § 1.8）：随机访问慢 **5-10 倍**（缓存命中率低）。

:::

**算法影响**：

- **归并排序**：分治过程中频繁跨越数组边界，缓存局部性差
- **快排（原地）**：划分阶段访问连续内存，缓存友好
- **堆排序**：堆操作频繁跳跃（父子节点距离 n/2），缓存最差

这也是为什么快排实测通常最快，即使三者都是 Θ(n log n)。

### 分支预测

现代 CPU 流水线深度 10-20 级，分支预测错误会清空流水线（损失 10-20 周期）。

**示例**：遍历数组求和，有条件跳过负数：

```c
// ... 代码片段说明分支预测对比
// 版本 1：分支
int sum = 0;
for (int i = 0; i < n; i++) {
    if (arr[i] >= 0)  // 分支
        sum += arr[i];
}

// 版本 2：无分支（位运算技巧）
int sum = 0;
for (int i = 0; i < n; i++) {
    sum += arr[i] & -(arr[i] >= 0);  // 位掩码
}
```

若数组一半正一半负且随机分布，版本 1 的分支预测准确率 ~50%，版本 2 无分支。在 10^8 规模上，版本 2 可能快 **2-3 倍**。

**算法影响**：

- 二分查找：分支可预测（先左后右），预测准确率高
- 快排划分：与数据分布相关，随机输入预测准确率 ~50%

### SIMD 向量化

单指令多数据（SIMD）：一条指令处理 4-16 个数据（如 AVX-512 一次处理 16 个 float）。

现代编译器会自动向量化简单循环，但复杂算法（如快排）难以向量化。归并排序的合并过程可以部分向量化，但收益有限。

**实际影响**：对于数组求和、矩阵乘法等简单操作，SIMD 加速 **4-8 倍**；对于算法（排序、图搜索），SIMD 通常无法应用，主要靠缓存与分支预测。

### 常数的实际测量

本章实验（§ 1.8）测量了归并 vs 快排的常数比：

- 理论：都是 c·n log n
- 实测：快排约快 30%，即 c_快排 ≈ 0.7·c_归并

常数来自：
- 指令数：快排少 40%
- 缓存：快排原地，归并需额外数组
- 分支：两者相当（都是二分递归）

结论：小到中等规模（n < 10^6）时，**常数决定性能**；超大规模时，渐进复杂度才主导。

## 1.5 最坏情况构造 {#sec-algorithms.1.1.5}

算法可能在特定输入上退化。agent 生成的代码通过了随机测试，不代表在所有输入上正确或高效。本节展示如何为常见算法构造最坏情况。

### 快速排序的最坏情况

**标准快排**：选第一个元素为枢轴，划分为小于/等于/大于三部分，递归排序。

**平均情况**：枢轴接近中位数，划分平衡，T(n) = Θ(n log n)。

**最坏情况**：每次枢轴都是最小/最大元素，划分为 0 和 n-1，递归深度 n，T(n) = Θ(n²)。

**构造方法**：

1. **已排序数组**：`[1, 2, 3, ..., n]`，选第一个元素 1，右边 n-1 个全部大于 1，划分极不平衡
2. **逆序数组**：`[n, n-1, ..., 2, 1]`，选第一个元素 n，左边 0 个，右边 n-1 个
3. **所有元素相同**：`[5, 5, 5, ..., 5]`，若实现不当（不用三向切分），划分为空/全部，退化

::: ex 例 1.5.1 · 实测快排退化 {#ex-algorithms.1.1.5.1}

本章实验（§ 1.8）测量了：

- n=500, 随机输入：2.1ms
- n=500, 已排序：26ms（**退化 12 倍**）

原因：递归深度从 log 500 ≈ 9 增加到 500，栈深度和总比较次数都是 O(n) vs O(log n)。

:::

**修复方法**：

1. **随机选枢轴**：`random.randint(lo, hi)`，期望划分平衡
2. **三数取中**：`median(arr[lo], arr[mid], arr[hi])`，避免选到极值
3. **三向切分**：将数组分为 <、=、> 三部分，处理重复元素

### 哈希表的最坏情况

**标准哈希表**：用链表处理冲突，平均 O(1) 插入/查找。

**最坏情况**：所有键哈希到同一个桶，退化为链表，O(n)。

**构造方法**（若哈希函数已知）：

1. **模运算哈希**：`hash(key) = key % m`，构造 `[0, m, 2m, 3m, ...]`，全部冲突
2. **字符串哈希**：若用 `hash(s) = sum(ord(c))`，构造 `["abc", "bca", "cab"]`，和相同

**实际威胁**：
- 攻击者构造恶意输入，使服务器哈希表退化，DoS 攻击
- Python 3.3+ 引入随机哈希种子，每次运行不同，防止攻击

::: note 加密哈希函数不可构造

SHA-256、MD5 等加密哈希无已知方法构造冲突（除非破解算法本身）。用于安全场景（如密码存储）时，无最坏情况构造问题。

:::

### 二分查找的边界情况

二分查找本身无最坏情况（始终 O(log n)），但**实现错误**可能导致死循环或越界。

**常见错误**：

```python
def binary_search(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2  # 正确
        # mid = (lo + hi) / 2  # 错误：浮点数
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            lo = mid  # 错误：应该 mid + 1，否则 lo=mid 时死循环
        else:
            hi = mid - 1
    return -1
```

**构造触发输入**：`arr = [1, 2]`, `target = 2`，若 `lo = mid` 未 +1，则 `lo=0, hi=1, mid=0` 无限循环。

**测试策略**：
- 空数组
- 单元素（target 存在/不存在）
- target 在首/尾/中
- target 小于最小值/大于最大值

### 图算法的退化情况

**DFS/BFS**：在稠密图（边数 m ≈ n²）上复杂度 O(n + m) = O(n²)，无法避免（必须访问所有边）。但若图是链状（n 个顶点，n-1 条边，排成一条链），DFS 递归深度 O(n)，可能栈溢出。

**Dijkstra**：若所有边权相等，退化为 BFS；若有负权边，算法错误（需 Bellman-Ford）。

**构造方法**：
- 链状图：触发 DFS 栈溢出
- 负权环：使最短路径无定义
- 完全图（n² 条边）：测试稠密图性能

agent 生成图算法时，常只测小图（n ≤ 10）或稀疏图，漏掉稠密图和特殊拓扑。

## 1.6 平均情况分析 {#sec-algorithms.1.1.6}

最坏情况给出安全的性能保证，但许多算法在平均情况下表现更好。平均情况分析需要对输入分布建模，计算期望复杂度。

### 定义与前提

::: def 定义 1.6.1 · 平均情况复杂度 {#def-algorithms.1.1.6.1}

设算法 A 在输入 I 上的运行时间为 T(I)，输入空间为 Ω，输入分布为 P。平均情况复杂度定义为：

$$
T_{\text{avg}}(n) = \mathbb{E}_{I \sim P, |I|=n} [T(I)] = \sum_{I \in \Omega, |I|=n} P(I) \cdot T(I)
$$

若输入是均匀分布（每个长度为 n 的输入等概率），则

$$
T_{\text{avg}}(n) = \frac{1}{|\{I : |I|=n\}|} \sum_{I, |I|=n} T(I)
$$

:::

**关键假设**：输入分布 P 必须符合实际。若假设均匀分布，但真实输入总是已排序，平均情况分析无意义。

### 快速排序的平均情况

**假设**：输入是 `[1, 2, ..., n]` 的随机排列，每种排列等概率（n! 种）。

**分析**（递归方程）：

设 T(n) 是平均比较次数。选枢轴后，枢轴排名为 k（1 ≤ k ≤ n）的概率是 1/n，此时左子数组 k-1 个元素，右子数组 n-k 个元素。

$$
T(n) = n - 1 + \frac{1}{n} \sum_{k=1}^{n} [T(k-1) + T(n-k)]
$$

- n-1：划分阶段的比较次数
- T(k-1) + T(n-k)：左右子问题的期望复杂度

化简（利用对称性，$\sum_{k=1}^{n} T(k-1) = \sum_{k=1}^{n} T(n-k)$）：

$$
T(n) = n - 1 + \frac{2}{n} \sum_{k=0}^{n-1} T(k)
$$

**解法**（猜测并验证，或主定理变体）：T(n) = Θ(n log n)。

::: ex 例 1.6.1 · 快排平均 vs 最坏 {#ex-algorithms.1.1.6.1}

| 情况 | 复杂度 | 输入 |
|:--|:--|:--|
| 最坏 | Θ(n²) | 已排序、逆序 |
| 平均 | Θ(n log n) | 随机排列 |
| 最好 | Θ(n log n) | 枢轴总是中位数（理论上界） |

平均与最好同阶，说明快排对大多数输入高效。

:::

### 随机化算法

若无法控制输入分布，可以**随机化算法本身**：在算法内部引入随机性，使期望复杂度不依赖输入。

**随机化快排**：

```python
def quicksort_random(arr, lo, hi):
    if lo < hi:
        pivot_idx = random.randint(lo, hi)  # 随机选枢轴
        arr[lo], arr[pivot_idx] = arr[pivot_idx], arr[lo]
        pivot_idx = partition(arr, lo, hi)
        quicksort_random(arr, lo, pivot_idx - 1)
        quicksort_random(arr, pivot_idx + 1, hi)
```

**保证**：对**任意**输入（包括已排序、对抗性构造），期望复杂度 Θ(n log n)。最坏情况仍是 Θ(n²)（如果随机数生成器极度不幸，每次都选最小元素），但概率极小（约 1/n!）。

::: intuition 随机化 vs 平均情况

- **平均情况分析**：假设输入随机，算法确定
- **随机化算法**：输入任意（甚至对抗），算法内部随机

随机化算法更强：不依赖输入分布假设，对抗性攻击者无法构造最坏输入（除非预测随机数）。

:::

### 如何测量平均性能

1. **生成随机输入**：`random.shuffle(range(n))`，重复 1000 次
2. **测量每次耗时**，计算均值和标准差
3. **验证分布**：绘制直方图，检查是否接近正态分布（中心极限定理）

::: ex 例 1.6.2 · 测量快排平均性能 {#ex-algorithms.1.1.6.2}

```python
times = []
for _ in range(1000):
    arr = list(range(1000))
    random.shuffle(arr)
    t = measure_time(quicksort, arr, repeat=1)
    times.append(t)

mean = np.mean(times)
std = np.std(times)
print(f"平均: {mean:.2f}ms ± {std:.2f}ms")
# 输出: 平均: 1.23ms ± 0.15ms
```

**解释**：标准差 0.15ms << 均值 1.23ms，说明性能稳定；若标准差很大（如 ±50%），说明性能不可预测。

:::

| 堆排序 | O(n log n) | O(n log n) | 最坏保证，但常数大 |

## 1.7 摊还分析 {#sec-algorithms.1.1.7}

有些操作单次可能很慢，但**均摊到多次操作后**平均很快。摊还分析（amortized analysis）计算一系列操作的**平均代价**，而非单次最坏情况。

### 动态数组的扩容

**问题**：Python 的 `list`、Java 的 `ArrayList` 初始容量有限，满了需要扩容。

**策略**：容量满时，分配 **2 倍** 原容量的新数组，复制旧元素，释放旧数组。

| 操作 | 单次最坏 | 摊还 |
|:--|:--|:--|
| `append` (未满) | O(1) | O(1) |
| `append` (扩容) | O(n) | **O(1)** (摊还) |

::: thm 定理 1.7.1 · 动态数组摊还复杂度 {#thm-algorithms.1.1.7.1}

从空数组开始，连续 n 次 `append`，总代价 O(n)，摊还每次 O(1)。

**证明（聚合法）**：

设容量从 1 → 2 → 4 → 8 → ... → 2^k ≥ n，扩容发生在第 1, 2, 4, 8, ..., 2^k 次插入。

每次扩容复制的元素数：

$$
1 + 2 + 4 + ... + 2^{k-1} = 2^k - 1 < n
$$

总代价：n 次插入 + 至多 n 次复制 = 2n → O(n)。摊还每次 O(1)。

:::

**关键**：扩容因子必须 > 1（如 2 或 1.5），不能每次只增加固定量（如 +100），否则扩容次数 O(n)，总代价 O(n²)。

### 三种摊还分析方法

#### 1. 聚合法（aggregate method）

计算 n 个操作的总代价 T(n)，摊还代价 = T(n) / n。

上面动态数组就是聚合法：T(n) = 2n → 摊还 O(1)。

#### 2. 核算法（accounting method）

给每个操作分配「预算」，可能多于实际代价（多的部分存为「信用」），也可能少于（从信用中扣除）。

**规则**：信用永远 ≥ 0（不能透支）。

**动态数组示例**：
- 普通插入：实际 O(1)，预算 3 单位（1 用于插入，2 存为信用）
- 扩容：实际 O(n)，从之前存的信用中扣除（每个已有元素贡献 2 单位）

总预算：3n，信用非负，摊还 O(1)。

#### 3. 势能法（potential method）

定义「势函数」Φ，表示数据结构的「势能」（类似物理的势能）。

摊还代价 = 实际代价 + ΔΦ（势能变化）

**动态数组示例**：定义 Φ = 2 × (元素数 - 容量/2)

- 普通插入：实际 1，ΔΦ = +2，摊还 3
- 扩容：实际 n，ΔΦ = -(n-2)，摊还 2

势能法最灵活，适合复杂数据结构（如斐波那契堆）。

::: ex 例 1.7.1 · 栈的 MultiPop {#ex-algorithms.1.1.7.1}

栈支持三种操作：

- `push(x)`：O(1)
- `pop()`：O(1)
- `multipop(k)`：弹出 k 个元素（或栈空为止），单次 O(min(k, s))，s 是栈大小

**问题**：n 个操作（包含 `multipop`），总代价？

**错误分析**：每次 `multipop` 最坏 O(n)，n 个操作 → O(n²)。

**正确分析（聚合法）**：每个元素最多 `push` 一次、`pop` 一次，总共 2n 次操作 → O(n)，摊还 O(1)。

:::

### 摊还 vs 平均的区别

| 概念 | 定义 | 前提 |
|:--|:--|:--|
| 平均情况 | 对输入分布取期望 | 假设输入随机 |
| 摊还分析 | 对操作序列取平均 | 不假设输入分布 |

**关键**：摊还是**最坏情况保证下的平均**（worst-case amortized），而平均情况是**期望的最坏**（average-case worst）。

## 1.8 agent 陷阱：只测随机输入的快排 {#sec-algorithms.1.1.8}

**agent 做了什么**：agent 生成了一个快速排序实现，选择第一个元素作为枢轴，通过了 10 组随机测试。

**现象**：在已排序数组 `[1,2,3,...,1000]` 上，耗时 15 秒；而归并排序只需 0.02 秒。

**根因**：每次递归都选最小元素，划分极不平衡（0 vs n-1），递归深度 O(n)，总复杂度退化为 O(n²)。

**如何发现**：用本章实验脚本 `--worst-case` 模式生成已排序输入，测量实际耗时，发现 n=1000 时已超过 O(n²) 预测的 10 倍。

**修复**：改用三数取中（median-of-three）选枢轴，或随机选择。验证：在 10,000 组输入（包括已排序、逆序、重复元素）上，耗时均在 O(n log n) 范围内。

## 1.11 本章陷阱 {#sec-algorithms.1.1.11}

::: errata 本章陷阱

1. **混淆 O 与 Θ**：说「快排是 O(n log n)」技术上正确（它确实 ≤ c n log n 在平均情况），但不精确；应该说「平均 Θ(n log n)，最坏 Θ(n²)」。O 是上界，Θ 是紧确界。

2. **忽略常数导致错误优化**：看到两个算法都是 O(n log n)，选了理论上「更优」的算法（如堆排序），但实测慢 2 倍，因为常数大。始终测量，不要只看渐进复杂度。

3. **单次测量**：用 `time.time()` 测一次就得出结论，实际上进程调度、GC、缓存状态都会导致 ±50% 波动。必须重复 100+ 次取中位数。

4. **只测小规模**：n=100 时 O(n²) 可能比 O(n log n) 快（常数小），但 n=10000 时慢 100 倍。必须测多个规模，验证增长率。

5. **只测随机输入**：快排在随机输入上表现好，但已排序输入退化。必须构造最坏情况输入，测试边界行为。

6. **把摊还当硬实时保证**：动态数组 append 摊还 O(1)，但偶尔 O(n)，不能用于硬实时系统（如音频处理）。摊还是平均，不是每次的上界。

7. **忘记递归深度限制**：DFS 在链状图上递归深度 O(n)，Python 默认栈深度 1000，会 `RecursionError`。要么改迭代，要么 `sys.setrecursionlimit(n+100)`。

8. **误解平均情况前提**：说「哈希表查找 O(1)」，实际上是「在均匀分布和好哈希函数下期望 O(1)」。对抗性输入可以构造冲突，退化为 O(n)。

9. **缓存不友好的算法选择**：堆排序理论 O(n log n)，但频繁跳跃访问（父子节点距离 n/2），缓存命中率低，实测比快排慢 3 倍。

10. **过早优化**：看到代码是 O(n²)，立刻重写成 O(n log n)，但实际 n < 100，O(n²) 版本更简单且足够快。先测量，再优化瓶颈。

11. **忽略隐藏的复杂度**：写 `if x in lst`（Python list），看起来 O(1)，实际上 `in` 是 O(n) 线性扫描。应该用 `set` 或 `dict`。

12. **混淆排序稳定性与复杂度**：快排不稳定，归并稳定，两者都 O(n log n)。若需要稳定性（如多关键字排序），必须用归并，即使快排更快。

:::

### 即时自测

::: method 即时自测

**1. 判断正误**：

a. 若 f(n) = O(g(n))，则 g(n) = Ω(f(n))  
b. 快排平均 O(n log n)，所以最坏也是 O(n log n)  
c. 摊还 O(1) 意味着每次操作都 ≤ c  

::: sol 答案

a. **对**。O 与 Ω 互为对偶。  
b. **错**。快排最坏 O(n²)（已排序输入）。  
c. **错**。摊还是平均，单次可能 O(n)（如扩容）。

:::

**2. 分析复杂度**：

```python
def mystery(n):
    i = 1
    while i < n:
        for j in range(i):
            print(j)
        i *= 2
```

::: sol 答案

外层：i = 1, 2, 4, 8, ..., 共 log n 次  
内层：每次打印 i 次，总共 1 + 2 + 4 + ... + n/2 = n-1  
**答案：Θ(n)**

:::

**3. 实验设计**：如何验证「算法 A 比算法 B 快 2 倍」？

::: sol 答案

1. 固定 n（如 10000），重复 100 次取中位数  
2. 计算比值 t_A / t_B，检查是否 ≈ 0.5  
3. 测试多个 n（1000, 2000, 4000），验证比值稳定  
4. 用同一台机器、同一时间段、关闭后台任务

:::
