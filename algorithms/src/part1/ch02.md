分治法（Divide and Conquer）是计算机科学史上最具革命性的思想武器之一。它的哲学极其单纯：**将一个难以直接解决的大规模问题，递归分解为若干个规模较小但形式完全相同的子问题；独立求解子问题后，再将子问题的解合并为原问题的全局解**。

然而，许多开发者对分治法的理解仅仅停留在“归并排序的教科书伪代码”。在真实的高性能工业计算中，分治法面临着严峻的系统级现实：**每一次递归调用都伴随着调用栈分配、寄存器保存、以及由于子数组切片引发的内存分配与缓存行失效**。

本章以 Tim Roughgarden《算法详解 卷 1》与 CLRS 为母本，不仅系统推导 Karatsuba、Strassen、逆序对、中位数选择与最近点对的精妙算法，更从系统底层剖析“理论复杂度”到“实际机器执行耗时”之间的鸿沟，建立科学的分治工程调优直觉。

<pre class="layout">
                  [规模为 n 的原始问题实例]
                              │
               ┌──────────────┼──────────────┐
               │  分解 (Divide, 开销 D(n))   │
               ▼                             ▼
       [子问题 1: 规模 n/b]           [子问题 a: 规模 n/b]
               │                             │
               │  解决 (Conquer, 递归调用)    │
               ▼                             ▼
       [子问题 1 的局部解]            [子问题 a 的局部解]
               │                             │
               └──────────────┬──────────────┘

                              ▼
                  [原问题的全局最优解]
</pre>
读图：分治由三阶段组成。当子问题规模降至基情况阈值 $n \le n_0$ 时，必须截断递归切换为朴素硬件优化算法，以消除深层调用栈开销。

## 2.1 分治设计范式与主定理推导 {#sec-algorithms.1.2.1}

分治算法的运行时间 $T(n)$ 可以形式化表达为递归方程：
$$
T(n) = a \cdot T(n/b) + f(n)
$$
其中 $a \ge 1$ 为子问题数量，$b > 1$ 为子问题规模缩小比例，$f(n) = D(n) + C(n)$ 为分解与合并的总开销。

### 1. 递归树展开与三类主导模式

将递归树展开到第 $j$ 层（根节点为第 $0$ 层），该层共有 $a^j$ 个节点，每个节点的输入规模为 $n / b^j$。该层的计算工作量为：
$$
W(j) = a^j \cdot f\left(\frac{n}{b^j}\right)
$$
递归树的最大深度为 $L = \log_b n$。叶子节点的总数量为 $a^{\log_b n} = n^{\log_b a}$。

::: thm 定理 2.1.1 · 主定理 (Master Theorem) 完整表述 {#thm-algorithms.1.2.1.1}

设 $a \ge 1, b > 1$ 为常数，$f(n)$ 为渐进正函数。对递归式 $T(n) = a T(n/b) + f(n)$：
1. **叶子主导（Leaf-dominated）**：若存在常数 $\epsilon > 0$，使得 $f(n) = O(n^{\log_b a - \epsilon})$，则：
   $$
   T(n) = \Theta(n^{\log_b a})
   $$
2. **完全平衡（Balanced across levels）**：若存在常数 $k \ge 0$，使得 $f(n) = \Theta(n^{\log_b a} \log^k n)$，则：
   $$
   T(n) = \Theta(n^{\log_b a} \log^{k+1} n)
   $$
3. **根节点主导（Root-dominated）**：若存在常数 $\epsilon > 0$，使得 $f(n) = \Omega(n^{\log_b a + \epsilon})$，且满足正则性条件（Regularity Condition，对充分大的 $n$ 存在常数 $c < 1$ 使得 $a f(n/b) \le c f(n)$），则：
   $$
   T(n) = \Theta(f(n))
   $$
:::

::: proof 证明 · 递归树求和推导 {#proof-algorithms.1.2.1.1}

对整棵树的所有层级工作量求和：
$$
T(n) = \Theta(n^{\log_b a}) + \sum_{j=0}^{\log_b n - 1} a^j f(n / b^j)
$$
当 $f(n) = \Theta(n^d)$ 时，第 $j$ 层的工作量为：
$$
W(j) = a^j \cdot \left(\frac{n}{b^j}\right)^d = n^d \cdot \left(\frac{a}{b^d}\right)^j
$$
括号内的公比 $q = \frac{a}{b^d}$ 决定了级数的几何发散特性：
- 若 $q < 1 \iff \log_b a < d$：公比小于 1，有限等比数列和受控于首项 $j=0$，总耗时由根节点工作量 $\Theta(n^d)$ 主导；
- 若 $q = 1 \iff \log_b a = d$：公比为 1，每一层工作量严格恒定为 $n^d$，总耗时为层数乘以单层开销，即 $\Theta(n^d \log_b n)$；
- 若 $q > 1 \iff \log_b a > d$：公比大于 1，最后一层叶子节点占据了绝大多数计算量，总耗时由叶子总数 $\Theta(n^{\log_b a})$ 主导。
:::

### 2. Akra-Bazzi 方法：非均匀分治的终极武器

在很多高级分治中，子问题的规模并不对称，例如 $T(n) = T(n/3) + T(2n/3) + \Theta(n)$。标准主定理对此无能为力。

::: thm 定理 2.1.2 · Akra-Bazzi 递归求解定理 (1998) {#thm-algorithms.1.2.1.2}

对于形如 $T(n) = \sum_{i=1}^k a_i T(b_i n + h_i(n)) + g(n)$ 的分治递归式，其中 $a_i > 0, 0 < b_i < 1$：
1. 求解唯一的实数 $p$，使得：
   $$
   \sum_{i=1}^k a_i \cdot b_i^p = 1
   $$
2. 递归式的紧确渐进解为：
   $$
   T(n) = \Theta\left( n^p \left( 1 + \int_1^n \frac{g(u)}{u^{p+1}} du \right) \right)
   $$
:::

**应用示例**：对于 $T(n) = T(n/3) + T(2n/3) + n$：
令 $\left(\frac{1}{3}\right)^p + \left(\frac{2}{3}\right)^p = 1$。显然当 $p = 1$ 时，$\frac{1}{3} + \frac{2}{3} = 1$ 成立！
代入积分公式：
$$
T(n) = \Theta\left( n^1 \left( 1 + \int_1^n \frac{u}{u^2} du \right) \right) = \Theta(n (1 + \ln n)) = \Theta(n \log n)
$$
无需画出极其倾斜的非对称递归树，代数方法一击必杀。

## 2.2 大整数乘法：Karatsuba 的代数奇迹 {#sec-algorithms.1.2.2}

给定两个 $n$ 位十进制大整数 $X$ 与 $Y$。小学传统逐位相乘算法的时间复杂度为 $\Theta(n^2)$。数千年来，人们一度认为没有比平方阶更快的乘法。

### 1. 朴素分治的停滞

将 $X$ 和 $Y$ 沿中点切分为高半部分和低半部分：
$$
X = 10^{m} a + b, \quad Y = 10^{m} c + d \quad (m = \lceil n/2 \rceil)
$$
展开乘积：
$$
X \cdot Y = (10^m a + b)(10^m c + d) = 10^{2m} (ac) + 10^m (ad + bc) + (bd)
$$
朴素分治需要递归计算 4 个规模为 $n/2$ 的子乘法：$ac, ad, bc, bd$。
递归式为：
$$
T(n) = 4 T(n/2) + \Theta(n)
$$
代入主定理：$a = 4, b = 2, f(n) = \Theta(n^1)$。因为 $\log_2 4 = 2 > 1$，属于叶子主导：
$$
T(n) = \Theta(n^2)
$$
算法复杂度并未获得任何改善。

### 2. Karatsuba 代数恒等式

1960 年，23 岁的苏联数学家 Anatoly Karatsuba 发现，中间交叉项 $ad + bc$ 可以不用分别计算 $ad$ 和 $bc$：
1. 递归计算 $z_2 = a \cdot c$；
2. 递归计算 $z_0 = b \cdot d$；
3. 递归计算两部分之和的乘积：
   $$
   z_1 = (a + b) \cdot (c + d) = ac + (ad + bc) + bd
   $$
4. 通过两次减法提取中间交叉项：
   $$
   ad + bc = z_1 - z_2 - z_0
   $$

原本需要 4 次递归乘法，现在**仅需 3 次递归乘法**（$z_0, z_2, z_1$）！其余加减法与基数移位只需线性时间 $\Theta(n)$。

::: thm 定理 2.2.1 · Karatsuba 算法复杂度 {#thm-algorithms.1.2.2.1}

递归方程满足：
$$
T(n) = 3 T(n/2) + \Theta(n)
$$
由主定理第 1 种情况，其时间复杂度为：
$$
T(n) = \Theta(n^{\log_2 3}) \approx \Theta(n^{1.585})
$$
:::

```python
def karatsuba_multiply(x: int, y: int, cutoff: int = 32) -> int:
    """
    工业级带阈值切换的 Karatsuba 乘法实现
    cutoff: 小于该位数时切换为原生 CPU 指令乘法
    """
    if x < 10**cutoff or y < 10**cutoff:
        return x * y

    str_x, str_y = str(x), str(y)
    n = max(len(str_x), len(str_y))
    m = n // 2

    high_x, low_x = divmod(x, 10**m)
    high_y, low_y = divmod(y, 10**m)

    # 3 次核心递归
    z0 = karatsuba_multiply(low_x, low_y, cutoff)
    z2 = karatsuba_multiply(high_x, high_y, cutoff)
    z1 = karatsuba_multiply(low_x + high_x, low_y + high_y, cutoff) - z2 - z0

    return z2 * (10**(2 * m)) + z1 * (10**m) + z0
```

### 3. 多路分治推广：Toom-Cook 算法

Karatsuba 将多项式拆为 2 段。如果将多项式拆为 3 段（Toom-Cook 3 路），通过插值法可以用 5 次乘法完成，复杂度进一步下降到 $O(n^{\log_3 5}) \approx O(n^{1.465})$。当 $n$ 达到数万位时，基于快速傅里叶变换（FFT）的 Schönhage–Strassen 算法可达 $O(n \log n \log \log n)$，而 2019 年 Harvey & van der Hoeven 实现了理论极限 $O(n \log n)$。但在数千位规模内，带阈值的 Karatsuba 依然是工程统治者。

## 2.3 矩阵乘法：Strassen 算法原理与完整构造 {#sec-algorithms.1.2.3}

对于两个 $n \times n$ 的方阵 $A$ 和 $B$，定义其乘积矩阵 $C = A \cdot B$，其中 $C_{ij} = \sum_{k=1}^n A_{ik} B_{kj}$。
朴素三重循环需要执行 $n^3$ 次标量乘法与 $n^2(n-1)$ 次标量加法，时间复杂度为 $\Theta(n^3)$。

### 1. 分块矩阵的 8 次乘法困境

将 $A, B, C$ 划分为四个 $(n/2) \times (n/2)$ 的子矩阵：
$$
\begin{bmatrix} C_{11} & C_{12} \\ C_{21} & C_{22} \end{bmatrix} = \begin{bmatrix} A_{11} & A_{12} \\ A_{21} & A_{22} \end{bmatrix} \begin{bmatrix} B_{11} & B_{12} \\ B_{21} & B_{22} \end{bmatrix}
$$
展开得到：
$$
\begin{aligned}
C_{11} &= A_{11} B_{11} + A_{12} B_{21} \\
C_{12} &= A_{11} B_{12} + A_{12} B_{22} \\
C_{21} &= A_{21} B_{11} + A_{22} B_{21} \\
C_{22} &= A_{21} B_{12} + A_{22} B_{22}
\end{aligned}
$$
每个子矩阵的乘积需要 2 次子乘法，总共 8 次递归调用。递归式为：
$$
T(n) = 8 T(n/2) + \Theta(n^2) \implies T(n) = \Theta(n^{\log_2 8}) = \Theta(n^3)
$$
分治依旧停留在三次时间。

### 2. Strassen 的 7 次乘法构造

1969 年，Volker Strassen 发现了类似于 Karatsuba 的代数技巧：可以用 7 次子矩阵乘法和 18 次子矩阵加减法表达 $2 \times 2$ 块的相乘结果。

定义 7 个中间乘积矩阵 $M_1, \ldots, M_7$：
$$
\begin{aligned}
M_1 &= (A_{11} + A_{22})(B_{11} + B_{22}) \\
M_2 &= (A_{21} + A_{22}) B_{11} \\
M_3 &= A_{11} (B_{12} - B_{22}) \\
M_4 &= A_{22} (B_{21} - B_{11}) \\
M_5 &= (A_{11} + A_{12}) B_{22} \\
M_6 &= (A_{21} - A_{11})(B_{11} + B_{12}) \\
M_7 &= (A_{12} - A_{22})(B_{21} + B_{22})
\end{aligned}
$$
结果子矩阵由上述 7 个矩阵直接加减求得：
$$
\begin{aligned}
C_{11} &= M_1 + M_4 - M_5 + M_7 \\
C_{12} &= M_3 + M_5 \\
C_{21} &= M_2 + M_4 \\
C_{22} &= M_1 - M_2 + M_3 + M_6
\end{aligned}
$$

::: thm 定理 2.3.1 · Strassen 矩阵乘法复杂度 {#thm-algorithms.1.2.3.1}

由于子矩阵加减法的时间为 $\Theta((n/2)^2) = \Theta(n^2)$，递归式满足：
$$
T(n) = 7 T(n/2) + \Theta(n^2)
$$
由主定理第 1 种情况，因为 $\log_2 7 \approx 2.807 > 2$：
$$
T(n) = \Theta(n^{\log_2 7}) \approx O(n^{2.8074})
$$
:::

### 3. 完整 Strassen 实现与非 2 的幂处理

```python
import numpy as np

def strassen_multiply(A: np.ndarray, B: np.ndarray, cutoff: int = 64) -> np.ndarray:
    """带动态阈值切断的高性能 Strassen 矩阵乘法"""
    n = A.shape[0]
    
    # 核心阈值切断：小规模立即切换为底层高度优化的密集矩阵乘法
    if n <= cutoff:
        return np.dot(A, B)

    # 处理奇数阶矩阵：边缘补零 (Padding) 到偶数阶
    if n % 2 != 0:
        A_pad = np.pad(A, ((0, 1), (0, 1)), mode='constant')
        B_pad = np.pad(B, ((0, 1), (0, 1)), mode='constant')
        C_pad = strassen_multiply(A_pad, B_pad, cutoff)
        return C_pad[:n, :n]

    mid = n // 2
    A11, A12 = A[:mid, :mid], A[:mid, mid:]
    A21, A22 = A[mid:, :mid], A[mid:, mid:]
    B11, B12 = B[:mid, :mid], B[:mid, mid:]
    B21, B22 = B[mid:, :mid], B[mid:, mid:]

    # 7 次递归调用
    M1 = strassen_multiply(A11 + A22, B11 + B22, cutoff)
    M2 = strassen_multiply(A21 + A22, B11, cutoff)
    M3 = strassen_multiply(A11, B12 - B22, cutoff)
    M4 = strassen_multiply(A22, B21 - B11, cutoff)
    M5 = strassen_multiply(A11 + A12, B22, cutoff)
    M6 = strassen_multiply(A21 - A11, B11 + B12, cutoff)
    M7 = strassen_multiply(A12 - A22, B21 + B22, cutoff)

    # 组装结果块
    C = np.zeros((n, n), dtype=A.dtype)
    C[:mid, :mid] = M1 + M4 - M5 + M7
    C[:mid, mid:] = M3 + M5
    C[mid:, :mid] = M2 + M4
    C[mid:, mid:] = M1 - M2 + M3 + M6
    return C
```

## 2.4 性能反转与阈值调优（Cutoff Tuning） {#sec-algorithms.1.2.4}

理论上 $O(n^{2.807}) < O(n^3)$，但为什么在真实工业工程（如 BLAS 库、PyTorch、Eigen）中，小矩阵乘法从不使用纯 Strassen 算法？

### 1. 隐藏常数与内存开销剖析

- **算术常数**：朴素矩阵乘法执行 $2n^3$ 次浮点运算；Strassen 虽然减少了乘法，但执行了大量的矩阵加减法（单层 18 次），其常数因子比朴素算法高出数倍；
- **内存分配开销**：每一次递归调用，都需要在堆上开辟临时矩阵来存放 $(A_{11} + A_{22})$ 等中间结果。频繁的内存申请与释放会彻底击穿操作系统的内存分配器；
- **CPU 缓存失效**：朴素算法通过分块循环（Cache Tiling）能够实现对 L1/L2 缓存行的高效预取；而递归切分会导致内存访问跨步剧增，引发严重的 L1 Data Cache Miss。

### 2. 阈值调优实验验证

我们执行实验脚本 `experiments/ch02/divide_conquer_lab.py`，记录不同矩阵规模与切换阈值下的实测耗时：

## 2.5 逆序对计数：MergeSort 的拓扑副产物 {#sec-algorithms.1.2.5}

在推荐系统、排名评估（Rank Correlation）中，经常需要计算一个排列与标准顺序的偏差。
给定数组 $A[0..n-1]$，若 $i < j$ 且 $A[i] > A[j]$，则称 $(i, j)$ 为一个逆序对。逆序对数量的最大值为 $\frac{n(n-1)}{2} = \Theta(n^2)$（完全逆序序列）。

### 1. 分治拆解

将数组从中间平分为左半部分 $L$ 与右半部分 $R$。原数组中的所有逆序对可以互斥且完备地划分为三类：
1. **左半部逆序对**：$i, j \in L$（递归解决）；
2. **右半部逆序对**：$i, j \in R$（递归解决）；
3. **跨半部逆序对（Split Inversions）**：$i \in L$ 且 $j \in R$。

### 2. 在归并阶段实现线性计数

关键引理：**若子数组 $L$ 和 $R$ 已经各自排好序，跨半部逆序对可以在一次标准的双指针归并过程中以 $O(n)$ 时间全部统计完毕！**

::: thm 定理 2.5.1 · 跨半部逆序对计数引理 {#thm-algorithms.1.2.5.1}

设归并指针分别为 $p$（指向 $L$）与 $q$（指向 $R$）。
当 $L[p] > R[q]$ 时：由于数组 $L$ 已处于升序状态，因此 $L$ 中位于 $p$ 之后的所有元素（从下标 $p$ 到末尾 $\text{len}(L)-1$）必然全部严格大于 $R[q]$。
因此，当前元素 $R[q]$ 能够与 $L$ 中剩余的全部元素**一次性产生 $(\text{len}(L) - p)$ 个跨半部逆序对**！
:::

```python
def count_split_inversions(left: list[int], right: list[int]) -> tuple[list[int], int]:
    merged = []
    i = j = 0
    split_inv = 0
    len_l, len_r = len(left), len(right)

    while i < len_l and j < len_r:
        if left[i] <= right[j]:
            merged.append(left[i])
            i += 1
        else:
            # left[i] > right[j], 发现跨半部逆序对
            merged.append(right[j])
            split_inv += (len_l - i)
            j += 1

    merged.extend(left[i:])
    merged.extend(right[j:])
    return merged, split_inv
```

时间复杂度满足 $T(n) = 2 T(n/2) + \Theta(n)$，总耗时为严格的 $\Theta(n \log n)$，比两重循环暴力检查的 $O(n^2)$ 提速数千倍。

### 3. 数据分析应用：Kendall 秩相关系数

计算两个长度为 $n$ 的偏好排名列表的相似度时，Kendall 秩相关系数定义为：
$$
\tau = 1 - \frac{4 \cdot \text{Inversions}}{n(n - 1)}
$$
- 若两序列完全一致：$\text{Inversions} = 0 \implies \tau = 1.0$；
- 若两序列完全相反：$\text{Inversions} = \frac{n(n-1)}{2} \implies \tau = -1.0$。
分治归并计数是大数据集中实时计算 $\tau$ 相关性的核心底座。

## 2.6 顺序统计量：快速选择算法（QuickSelect） {#sec-algorithms.1.2.6}

选择问题（Selection Problem）：输入 $n$ 个无序互异元素及整数 $k \in [1, n]$，要求输出该集合中第 $k$ 小的元素。
若先排序再索引，时间复杂度为 $O(n \log n)$。我们能否在**严格线性时间 $O(n)$** 内完成查找？

### 1. 期望线性时间：QuickSelect 算法

借用快速排序的 Partition 原理：
1. 从当前区间选取一个主元（Pivot）$v$；
2. 围绕主元重排区间，主元最终落位下标为 $p$：
   - 左侧所有元素 $< v$；
   - 右侧所有元素 $> v$；
3. 判断目标排名 $k$ 与主元位置 $p$：
   - 若 $k = p + 1$：主元恰好为第 $k$ 小元素，直接返回；
   - 若 $k < p + 1$：第 $k$ 小元素必然在左半部，**仅递归左侧**；
   - 若 $k > p + 1$：第 $k$ 小元素必然在右半部，**仅递归右侧**。

```python
import random

def quick_select(arr: list[int], left: int, right: int, k: int) -> int:
    """原址快速选择算法，平均时间复杂度 O(n)"""
    if left == right:
        return arr[left]

    # 三数取中 (Median-of-three) 防退化
    mid = (left + right) // 2
    if arr[left] > arr[mid]: arr[left], arr[mid] = arr[mid], arr[left]
    if arr[left] > arr[right]: arr[left], arr[right] = arr[right], arr[left]
    if arr[mid] > arr[right]: arr[mid], arr[right] = arr[right], arr[mid]
    arr[mid], arr[right] = arr[right], arr[mid]
    
    pivot = arr[right]
    i = left
    for j in range(left, right):
        if arr[j] <= pivot:
            arr[i], arr[j] = arr[j], arr[i]
            i += 1
    arr[i], arr[right] = arr[right], arr[i]

    # i 为主元最终落位
    rank = i - left + 1
    if k == rank:
        return arr[i]
    elif k < rank:
        return quick_select(arr, left, i - 1, k)
    else:
        return quick_select(arr, i + 1, right, k - rank)
```

::: thm 定理 2.6.1 · QuickSelect 期望时间复杂度 {#thm-algorithms.1.2.6.1}

在平均情况下，随机主元将区间均分为 $\frac{n}{2}$ 大小。递归式为：
$$
T(n) = T(n/2) + \Theta(n) \implies T(n) = \Theta(n)
$$
但是在最坏情况下（例如主元总是选到区间极值），递归深度为 $n$，时间退化为 $\Theta(n^2)$。
:::

## 2.7 确定性最坏线性选择：BFPRT 算法 {#sec-algorithms.1.2.7}

1973 年，五位大师 Blum、Floyd、Pratt、Rivest 与 Tarjan 提出了 **BFPRT 算法（又称中位数之中位数算法，Median-of-Medians）**，彻底攻克了选择问题在最坏情况下的线性时间保证。

### 1. BFPRT 算法五步法

::: method 方法 2.7.1 · BFPRT 主元选择协议 {#method-algorithms.2.7.1.1}

1. **分组**：将 $n$ 个元素划分为 $\lceil n/5 \rceil$ 个子组，除最后一组外每组恰好 5 个元素；
2. **组内求中位数**：对每组的 5 个元素进行简单插入排序，取出各组的中位数（每组常数时间 $O(1)$，共 $\lceil n/5 \rceil$ 个中位数）；
3. **递归求主元**：对这 $\lceil n/5 \rceil$ 个中位数递归调用 BFPRT 算法，求出它们的**中位数之中位数 $x$**；
4. **全量划分**：以 $x$ 为主元，对原始数组执行双向 Partition 划分；
5. **单侧递推**：根据 $x$ 最终落位与目标排名的关系，仅递归左半部或右半部。
:::

### 2. 为什么必须选 5 个一组？

::: proof 证明 · BFPRT 最坏情况线性复杂度推导 {#proof-algorithms.2.7.1.1}

在中位数构成的集合中，至少有一半的中位数 $\ge x$。在这些组中，每组至少有 3 个元素大于等于本组中位数，因而必然 $\ge x$。
因此，在全量 $n$ 个元素中，至少有：
$$
3 \cdot \left( \frac{1}{2} \cdot \left\lceil \frac{n}{5} \right\rceil - 2 \right) \ge \frac{3n}{10} - 6
$$
个元素必然 $\ge x$。同理，至少有 $\frac{3n}{10} - 6$ 个元素必然 $\le x$。
这意味着在第 4 步以 $x$ 为主元划分后，**任何一侧的剩余待选元素数量至多不超过 $\frac{7n}{10} + 6$**！

列出算法整体的时间递推式：
$$
T(n) \le T(n/5) + T(7n/10) + c \cdot n
$$
其中 $T(n/5)$ 为第 3 步在 $\lceil n/5 \rceil$ 个中位数中寻找主元的递归开销，$T(7n/10)$ 为最坏情况下进入较大一侧子区间的递归开销，$c \cdot n$ 为分组与划分的线性工作量。

使用代入法证明 $T(n) \le C \cdot n$：
$$
T(n) \le C \cdot \frac{n}{5} + C \cdot \frac{7n}{10} + c \cdot n = C \cdot \frac{9n}{10} + c \cdot n
$$
为了使 $C \cdot \frac{9n}{10} + c \cdot n \le C \cdot n$ 成立，只需：
$$
C \cdot \left(1 - \frac{9}{10}\right) \ge c \iff \frac{C}{10} \ge c \iff C \ge 10c
$$
只要常数 $C \ge 10c$，不等式严格成立！
**关键核心**：系数之和 $\frac{1}{5} + \frac{7}{10} = \frac{9}{10} < 1$。
若改为 3 个一组，递推式变为 $T(n) \le T(n/3) + T(2n/3) + O(n)$，系数之和 $\frac{1}{3} + \frac{2}{3} = 1$，会导致总复杂度发散为 $\Theta(n \log n)$！
:::

## 2.8 平面最近点对问题（Closest Pair of Points） {#sec-algorithms.1.2.8}

给定二维平面上的 $n$ 个点集合 $P = \{p_1, \ldots, p_n\}$，求欧几里得距离最近的两个点之间的距离：
$$
d_{\min} = \min_{p_i \neq p_j} \|p_i - p_j\|_2
$$
暴力计算每对点间距离需要 $O(n^2)$。

### 1. 分治设计与 7 点几何稀疏性引理

1. 将所有点按横坐标 $x$ 预排序。取中线 $x = x_{\text{mid}}$ 将点集划分为左右两半 $P_L$ 和 $P_R$；
2. 递归求出左侧内部最近距离 $d_L$ 和右侧内部最近距离 $d_R$。取较小者 $\delta = \min(d_L, d_R)$；
3. **跨中线点对检查**：潜在更近的点对必须位于距离中线两侧 $\delta$ 宽度的狭长垂直带状区域内：
   $$
   \text{Strip} = \{ p \in P \mid |p.x - x_{\text{mid}}| < \delta \}
   $$
4. 将带状区域内的所有点按纵坐标 $y$ 排序。

::: thm 定理 2.8.1 · 几何稀疏性定理（7点引理） {#thm-algorithms.1.2.8.1}

对于带状区域内按纵坐标排序后的任意点 $p_i$，**只需向后检查最多 7 个点**（纵坐标差距不超过 $\delta$ 的点）。
**几何证明**：在右侧 $\delta \times \delta$ 的正方形区域内，由于右半部分任意两点间距离均 $\ge \delta$，该正方形内最多只能塞入 4 个点（4个角各1个）。双侧正方形内最多容纳 8 个点，排除自身后，最多只需与 7 个邻居点比对距离！
:::

因此，跨中线的合并检查时间严格受控在 $\Theta(n)$，整体时间复杂度为 $\Theta(n \log n)$。

### 2. 完整算法实现

```python
import math
from typing import List, Tuple

Point = Tuple[float, float]

def dist(p1: Point, p2: Point) -> float:
    return math.hypot(p1[0] - p2[0], p1[1] - p2[1])

def closest_pair_rec(pts_by_x: List[Point], pts_by_y: List[Point]) -> float:
    n = len(pts_by_x)
    if n <= 3:
        # 小规模暴力求解
        d = float('inf')
        for i in range(n):
            for j in range(i + 1, n):
                d = min(d, dist(pts_by_x[i], pts_by_x[j]))
        return d

    mid = n // 2
    mid_point = pts_by_x[mid]

    left_x = pts_by_x[:mid]
    right_x = pts_by_x[mid:]

    # 预按 y 拆分，避免每层排序
    mid_x_val = mid_point[0]
    left_y = [p for p in pts_by_y if p[0] <= mid_x_val]
    right_y = [p for p in pts_by_y if p[0] > mid_x_val]

    d1 = closest_pair_rec(left_x, left_y)
    d2 = closest_pair_rec(right_x, right_y)
    delta = min(d1, d2)

    # 收集跨带点
    strip = [p for p in pts_by_y if abs(p[0] - mid_x_val) < delta]

    # 7 点检查核心循环
    strip_len = len(strip)
    for i in range(strip_len):
        j = i + 1
        while j < strip_len and (strip[j][1] - strip[i][1]) < delta:
            delta = min(delta, dist(strip[i], strip[j]))
            j += 1

    return delta
```

## 2.9 Agent 陷阱案例：分治中的深层隐式复制 {#sec-algorithms.1.2.9}

::: errata 真实生产代码与生成缺陷分析
**用户 Prompt**：
> “用 Python 实现一个快速排序算法，要求代码尽可能简练清晰。”

**Agent 生成的典型错误代码**：
```python
def quicksort_faulty(arr):
    if len(arr) <= 1:
        return arr
    pivot = arr[len(arr) // 2]
    # 致命陷阱：三次列表推导式创建三个全新的堆内存列表！
    left = [x for x in arr if x < pivot]
    middle = [x for x in arr if x == pivot]
    right = [x for x in arr if x > pivot]
    return quicksort_faulty(left) + middle + quicksort_faulty(right)
```

**灾难后果与排查流程**：
- *症状*：对 $1,000$ 个随机整数排序耗时 0.8ms，看起来优雅无瑕；当数据量上升到 $10^7$ 时，进程被操作系统内核 OOM Killer 强行杀死。
- *根因*：
  1. 每一层递归都创建了 `left`, `middle`, `right` 三个全新的列表对象，产生了大量的临时内存分配与垃圾回收（GC）压力；
  2. 每一层遍历了原始数组 3 次；
  3. 递归树深度为 $\log_2 n$ 时，额外空间开销达到 $\Theta(n \log n)$（而非标准快排的 $O(\log n)$ 栈深度）。
- *正确修复*：必须使用原址指针交换（Lomuto 或 Hoare 划分），彻底消除堆分配。
:::

## 2.11 本章陷阱 {#sec-algorithms.1.2.11}

::: errata 本章陷阱

1. **切片语法引发内存暴涨**：在分治递归参数中使用 `arr[:mid]`，隐式触发 $O(n)$ 全量数组内存深拷贝。
2. **基情况遗漏或递归步长为零**：子问题规模划分出现 $n/b = n$（如空划分），导致调用栈死循环直至溢出。
3. **主定理连续性与正则性忽视**：在 $f(n)$ 与 $n^{\log_b a}$ 差距非多项式阶时（如相差 $\log n$）盲目套用第 1 或第 3 情况。
4. **小规模矩阵强套 Strassen**：在 $n \le 64$ 时递归分块，加减法常数与缓存破坏导致性能比朴素算法慢 10 倍以上。
5. **快速选择未做就地交换**：使用过滤列表实现划分，破坏 $O(1)$ 辅助空间界限。
6. **逆序对统计合并漏算同值**：当 $L[i] == R[j]$ 时误将其计为逆序对，导致统计数值偏大。
7. **BFPRT 分组大小选为 3**：导致系数和等于 1，递归树每层不收敛，算法退化为 $O(n \log n)$。
8. **最近点对跨中线带未按 y 预排序**：在合并阶段每次重新全局排序，使复杂度从 $O(n \log n)$ 恶化为 $O(n \log^2 n)$。
9. **数值乘法中间项溢出**：Karatsuba 计算 $(a+b)(c+d)$ 时未考虑两个 $n/2$ 位数相加可能产生溢出位进位。
10. **浮点运算累积误差**：Strassen 算法的矩阵乘法数值稳定性比朴素算法差，大条件数下需监测舍入误差。
11. **单线程纯分治未利用多核**：分治子任务完全独立，顶层未采用任务并行池（Fork-Join）利用 CPU 多核心。
12. **极端逆序数组击穿快排**：未采用三数取中或随机化主元，导致快速排序退化为平方阶。

:::

::: method 即时自测

**题目**：考虑分治递归式 $T(n) = 4 T(n/2) + n^2 \log n$。
1. 该递归式能否直接使用经典主定理的三大基础情况得出渐进紧确解？
2. 请使用递归树方法求解该递归式的精确渐进复杂度 $\Theta(\cdot)$。

::: sol

**解答**：
1. **无法直接应用经典主定理的三种基础情况**。
   因为 $a = 4, b = 2$，临界指数为 $\log_b a = \log_2 4 = 2$。
   对比项为 $n^{\log_b a} = n^2$。驱动函数为 $f(n) = n^2 \log n$。
   虽然 $f(n)$ 渐进大于 $n^2$，但由于 $\frac{n^2 \log n}{n^2} = \log n$，两者的比值呈对数增长，不存在任何常数 $\epsilon > 0$ 使得 $f(n) = \Omega(n^{2 + \epsilon})$（多项式阶差距）。因此落入主定理情况 2 与情况 3 之间的“空隙”。

2. **递归树法精确求解**：
   递归树共有 $L = \log_2 n$ 层。在深度为 $j$ 的层级上，共有 $4^j$ 个子问题，每个子问题规模为 $n / 2^j$。
   该层的所有节点合并总工作量为：
   $$
   W(j) = 4^j \cdot f\left(\frac{n}{2^j}\right) = 4^j \cdot \left(\frac{n}{2^j}\right)^2 \log\left(\frac{n}{2^j}\right) = 4^j \cdot \frac{n^2}{4^j} \cdot (\log n - j) = n^2 (\log n - j)
   $$
   对整棵树的所有层级求和（从 $j = 0$ 到 $\log_2 n - 1$）：
   $$
   \sum_{j=0}^{\log_2 n - 1} W(j) = n^2 \sum_{j=0}^{\log_2 n - 1} (\log n - j) = n^2 \sum_{k=1}^{\log_2 n} k = n^2 \cdot \frac{\log n (\log n + 1)}{2} = \Theta(n^2 \log^2 n)
   $$
   加上叶子节点工作量 $\Theta(n^{\log_2 4}) = \Theta(n^2)$，总复杂度为：
   $$
   T(n) = \Theta(n^2 \log^2 n)
   $$
:::
