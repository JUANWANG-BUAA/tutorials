# 章节写作协议（作者与代理共同遵守）

本文件是《算法、评估与因果》每一章的硬契约。结构检查器 `tools/check_book.py` 只机械执行其中一部分；技术正确性由作者与 `CHECK-algorithms.md` 负责。

## 1. 基本参数

- 正文语言：简体中文，术语首次出现给英文。
- 每章 **1000–1400 行**（`wc -l`，含空行）。目标 1150–1300，不要靠空行凑数。
- 每章 1 个 H1；10–12 个 H2（骨架给了 11 个：8 个内容节 + 母本 + 陷阱 + 出口）。
- 每章开头必须有 `chapter-index`，写清「本章回答 / 读完你会」。
- 章首 3–4 段导语：上一章留下什么、本章解决什么、在全书的路径、一个具体反例或问题。
- 不要写「本章将介绍」「综上所述」「让我们」；不要 emoji。
- 人称用「你」，句子短；每个结论带条件与证据。

## 2. 固定的 11 个 H2

骨架已经给出编号与锚点。不要改编号，不要改锚点，不要删 H2；可以增加 H3。

```text
c.1 … c.8   内容节（每节 90–140 行）
c.9          母本对应
c.10         本章陷阱（8–15 条）
c.11         本章出口检查
```

章节的 c 是全书章号 1–14；锚点为 `sec-algorithms.<part>.<c>.<sec>`：

| 文件 | part | c |
|:--|--:|--:|
| part1/ch01–ch04 | 1 | 1–4 |
| part2/ch05–ch08 | 2 | 5–8 |
| part3/ch09–ch12 | 3 | 9–12 |
| part4/ch13–ch14 | 4 | 13–14 |

每个内容 H2 必须有：一个具体问题、机制、边界、至少一个表/代码/命令/图。不要在多个章重复同一段解释；跨章用一句话引用。

## 3. 每章必须出现的六件

1. **复杂度图/算法流程/实验设计图**：至少一个 `<pre class="layout">…</pre>` 或 `<pre class="algorithm-flow">…</pre>`。不要用 Mermaid（构建器不保证渲染）。图后必须有一句「读图：…」，说明从图中能得出什么结论。
2. **一个可运行例子**：本章实验在 `experiments/chNN/`。正文必须给出实际命令、真实输出或可验证的预期输出；脚本必须能在 macOS/Linux + Python 3.11+ 跑通（Linux 专属要明确标注）。不要链接不存在的文件。
3. **一个 agent 生成代码出错案例**：写清「agent 做了什么 → 现象 → 根因 → 如何用本章的工具发现 → 修复」。不要泛泛说「agent 可能犯错」。每章的案例必须不同，且与该章核心机制直接相关。
4. **母本对应表**：4–7 行，列「母本 / 章节或条目 / 本书落点 / 程度（完整/精选/背景/交叉引用/淘汰）」。
5. **本章陷阱**：8–15 条编号列表，每条按「现象 → 原因 → 修复/验证」写。必须放在 `::: errata 本章陷阱` 盒子里，编号列表紧跟在陷阱 H2 后、下一个 H2 前。检查器按 `^\d+\.` 计数。
6. **出口检查**：一个「检查项 / 达标线 / 没达标去哪」表，外加一个 `::: method 即时自测`，内部可嵌 `::: sol`。

## 4. 语义盒

只允许：`def`、`thm`、`ex`、`intuition`、`method`、`errata`、`note`、`proof`、`sol`。

- 每章至少 `def`、`ex`、`errata`、`method` 各 1 个；建议总数 12–20。
- 锚点全书唯一。建议格式：
  - `{#def-algorithms.<part>.<c>.<sec>.<n>}`
  - `{#ex-algorithms.<part>.<c>.<sec>.<n>}`
  - `{#thm-algorithms.<part>.<c>.<sec>.<n>}`
- 盒子必须闭合；不要嵌套 `proof`/`sol` 以外的盒子；`proof` 里不要再嵌盒子。
- 标题格式：`::: def 定义 1.2.1 · 大 O 记号 {#def-algorithms.1.1.2.1}`。

## 5. 代码与命令

- 代码围栏必须标语言：`python`、`bash`、`text`、`json`、`c`、`rust`。
- Python 代码必须能通过 `python3 -m py_compile`（除非标 `text` 的纯片段）；优先使用类型标注。
- C/Rust 示例需注明编译器版本；算法伪代码用 `text`。
- 每段代码前一句「这段验证什么」，后一句「预期输出/关键行」；不要贴无法运行的大段代码。
- `bash` 代码块用 `bash -n` 静态检查；不确定的终端会话用 `text`。
- **性能测试输出必须标注**：
  - 运行环境（CPU 型号、内存、OS）
  - 测量方式（wall time / CPU time / perf stat）
  - 重复次数与统计量（中位数 / 均值±标准差）
  - 示例：`n=10000, 100 次重复, 中位数 47.3ms (±2.1ms)`

## 6. 边界与回归

本书只写：算法设计与分析、性能评估、统计推断、因果推断入门、工程实践（评测系统、A/B 测试）。

以下只可交叉引用，不展开：
- 概率论基础（期望、方差、中心极限定理）→ 引用概率统计教材
- 线性代数（矩阵乘法、特征值）→ 引用《矩阵论》
- 编译器优化（循环展开、向量化）→ 引用《编译器与程序分析》

算法复杂度必须给出：
- 时间复杂度（最坏/平均/最好，如适用）
- 空间复杂度
- 常数因子的实际意义（如"归并排序常数约为快排的 1.5 倍"）

统计推断必须给出：
- 置信水平（如 95%）
- p 值与统计量
- 效应量（Cohen's d / 相对提升百分比）
- 样本量与检验力

## 7. 实验规范

每章实验脚本（`experiments/chNN/xxx_lab.py`）必须：

1. **可独立运行**：`python3 experiments/ch01/asymptotic_lab.py` 零参数启动
2. **固定随机种子**：`random.seed(42)` 与 `np.random.seed(42)`，保证可复现
3. **输出可验证**：打印关键数值（如"理论预测 O(n²)，实测斜率 1.97"）
4. **失败明确**：断言失败时打印详细信息，exit 1
5. **注释充分**：每个函数有 docstring，关键步骤有行内注释
6. **依赖声明**：脚本开头注释列出所需库（如 `# Requires: numpy, scipy, matplotlib`）

实验类型示例：

- **复杂度验证**：对比理论 vs 实测，拟合斜率
- **正确性对拍**：两种算法实现在随机输入上结果一致
- **性能剖析**：测量不同实现变体的耗时分布
- **反例构造**：生成让某算法失败的输入
- **统计模拟**：蒙特卡洛验证理论结果（如假阳性率）

## 8. agent 陷阱案例规范

每章必须有一个 agent 生成代码的失败案例，结构为：

```markdown
### c.X agent 陷阱：[简短标题]

**agent 做了什么**：agent 生成了一个 [算法/数据结构] 的实现，代码看起来正确...

**现象**：在 [特定输入/测试用例] 上，[预期结果 vs 实际结果]。

**根因**：[技术层面的原因，如"未处理循环回边的 phi 节点"]。

**如何发现**：用本章的 [工具/方法]，如 [具体命令或验证步骤]。

**修复**：[正确的实现方式，给出关键代码片段]。
```

**每章案例必须不同**：

| 章 | agent 错误类型 |
|--:|:--|
| 1 | 只测随机输入，忽略最坏情况（如快排退化） |
| 2 | 阈值未调优（如 Strassen 在小矩阵上慢） |
| 3 | 数据结构选择错误（如未用 decrease-key 的堆） |
| 4 | 未处理边界情况（如哈希表负载因子过高） |
| 5 | 贪心策略在精心构造的输入上失败 |
| 6 | 只返回最优值，无法重建最优解序列 |
| 7 | 声称启发式好，但没有最优解基准 |
| 8 | 在线算法未计算竞争比 |
| 9 | 只跑一次就报告性能，忽略噪声 |
| 10 | 多重比较未校正，假阳性膨胀 |
| 11 | 在测试集上调超参，过乐观估计 |
| 12 | 观察研究忽略混淆，因果推断错误 |
| 13 | 评测系统未隔离子进程，fork 炸弹 |
| 14 | 序贯检验未用 alpha spending，假阳性膨胀 |

## 9. 质量红线

- 不复制母本原文、代码、图；例子自己设计。
- 不写无法验证的绝对断言（「总是」「绝不」），改成有条件的表述。
- 不把理论复杂度当实际性能；任何性能断言必须有实测数据支持。
- 不把统计显著当实际重要；必须报告效应量。
- 不链接不存在的页面；跨书引用用书名+章节，或绝对 URL。
- 不在正文留 `TODO`、骨架注释、占位符、空表格。
- 每章必须有至少 2 个 H3 或表格之外的「可操作细节」（命令、参数、失败模式、数据）。
- 不允许用同一段文字换说法重复凑行；如行数不足，补充边界、反例、对照表、实测输出。

## 10. 特殊约定：复杂度标记

使用内联 HTML 标记复杂度（用于高亮显示）：

```markdown
归并排序的时间复杂度是 <code class="complexity nlogn">O(n log n)</code>。
```

可用类名：
- `const`：O(1)
- `log`：O(log n)
- `linear`：O(n)
- `nlogn`：O(n log n)
- `quadratic`：O(n²)
- `exponential`：O(2^n)
