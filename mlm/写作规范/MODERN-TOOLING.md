# MODERN-TOOLING：现代工具层写作规范

## 0. 为什么要这一层

原著写作于 19 世纪：没有计算机，没有照片和视频，没有代码，没有大数据，也没有 AI。这带来三类真实的限制，不是「时代的浪漫」，是可以指认的缺口：

| 限制 | 原著的表现 | 今天的做法 |
|:--|:--|:--|
| 算术只能手算 | 算例只能选能被心算整除的数字；复杂模型（如周转、再生产平衡）只能定性 | 代码算到底，可以做上千种情形的扫描 |
| 数据只能靠官方报告 | 引用视察员报告时只能摘几段，无法做全样本统计 | 可以把报告里的数字整理成表、画成时间序列、算趋势 |
| 图像只能靠文字描述 | 工作日长度、健康退化、寿命只有形容词 | 画出来，让读者看见《资本论》里的「数字暴力」 |
| 反事实无法检验 | 「如果不限制工时，资本会延长到什么程度」只能推断 | 仿真：设定参数，跑一遍，看结果 |
| 文本只能线性读 | 全书上百个概念，读者无法一眼看结构 | 交互图、可拖动的参数、能点开的概念网络 |

但必须说清一件事：**这一层的任务不是「让马克思主义看起来高级」，而是补原著做不到的功课。** 每个现代工具都必须回答「原著在这里为什么做不到，我多做了什么」。

## 1. 五类工具与各自的门槛

### 1.1 数据表（data table）

**做什么**：把原著正文里的数字整理成可比较的表。

**门槛**：
- 每一行必须有印刷页码出处；
- 表里的合计必须由脚本核对，不能手工加；
- 如果原著数字本身有取整（如「约 342 镑」），表里要保留原著的取整值，并在脚注说明精确值。

### 1.2 可视化（visualization）

**做什么**：把「时间序列」「分布」「比例结构」画成 SVG 图。

**门槛**：
- 图必须画**原著里的真实数字**，不许用示意曲线；
- 图要有可替代文本（`<title>`），禁用 JS 时能降级成表格；
- 内联 SVG，不请求网络，不引第三方库；
- 每张图下面必须有一句「这张图说明了什么」，且这句结论在原著里没有明说——否则图是多余的。

### 1.3 代码仿真（simulation）

**做什么**：把原著的一个机制写成可运行的模型，让读者改参数看结果。

**门槛**：
- 模型必须对应原著的**一个具体机制**（不是泛泛的「资本主义模拟」）；
- 参数必须有原著依据或标明是「教学设定」；
- 仿真结论必须能反过来印证或修正原著的一个论断；
- 代码要能在浏览器里直接跑（不依赖 numpy/pandas），或给出可在本地跑的 Python 脚本；
- 必须交代模型的**局限**：它省略了什么，省略之后结论还成立吗。

### 1.4 AI 视角（AI lens）

**做什么**：用今天才知道的东西，回看原著的一个判断。

**门槛**：
- 必须指出原著受限于时代的具体点（不知道什么、为什么不知道）；
- 必须给出「今天知道之后，结论是加强了、修正了、还是被证伪了」的明确判断；
- 不许用「马克思早就预言了」这类话术；预言与事后附会是两回事。

### 1.5 当代材料（contemporary）

**做什么**：接上今天的事实——平台经济、算法管理、零工、数据劳动。

**门槛**：
- 不许编造数据。没有可靠来源的数字宁可不写；
- 引用当代材料必须标明来源与时间，并说明「这是一个案例，不是一个统计总体」；
- 必须回到原著的概念去解释它，而不是让案例自己讲故事。

## 2. 章节里的形式约定

### 2.1 盒子类型

在现有盒子（`arg` `def` `src` `debate` `errata` `note` `ex` `sol`）之外，新增四类：

| 盒子 | 用途 | 必含 |
|:--|:--|:--|
| `::: data 数据 · 标题` | 整理后的数据表 | 出处列、合计核对说明 |
| `::: viz 可视化 · 标题` | SVG 图 | 图 + 一句结论 + 降级表格 |
| `::: sim 仿真 · 标题` | 可运行模型 | 模型说明、参数、代码、局限 |
| `::: lens 今日视角 · 标题` | AI / 现代科学回看 | 「原著不知道什么」+ 判断 |

### 2.2 密度上限（防止喧宾夺主）

- 每个现代工具盒子，正文篇幅不得超过**所在节篇幅的 30%**；
- 一章内 `sim` 不超过 2 个，`lens` 不超过 2 个，`viz` 不超过 4 个；
- **任何一节的中心论证必须由原文与推导承担，现代工具只能补充或检验，不能替代。**

理由：这本书首先是马克思主义原著的导读，不是数据科学演示。工具层是脚手架，不是主体。

### 2.3 代码块约定

- 浏览器内可跑的仿真用 `js` 代码块 + `<details>` 折叠，配一个「运行」按钮（`mlm.js` 提供）；
- 需要重算的账目给 Python 脚本路径（`.work/mlm-depth/verify_chNN.py`），正文只放结果表；
- 代码里所有数字都要能追溯到原著页码，注释写清。

## 3. 落地顺序

1. 一章里先有完整的原文—推导—算例骨架（六步齐）；
2. 再从 §1 的五类里挑 2–3 个**真正能补缺**的点插入；
3. 最后写「今日视角」收尾——如果这章没有值得说的地方，就不写，不许凑。
