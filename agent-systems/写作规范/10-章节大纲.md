## 第 1 篇 · 机制与边界

### 第 1 章 Agent 的本质：循环、状态与工具（part1，章号 1）

**论点**：agent 不是「更长的 prompt」，而是一个带状态与预算的闭环控制器；一次模型调用只是其中一步。

- 1.1 一次调用不是 agent：三个判据（闭环、工具、状态）— `sec-agent-systems.1.1.1`
- 1.2 循环：观察、决策、行动、更新 — `...1.1.2`
- 1.3 状态：世界、任务、会话、控制 — `...1.1.3`
- 1.4 工具：从函数到动作接口（前置条件、效果、可逆性、幂等键）— `...1.1.4`
- 1.5 控制：预算、终止、死循环检测、目标漂移 — `...1.1.5`
- 1.6 失败案例：一个停不下来的 agent（真实轨迹 + 修复）— `...1.1.6`
- 1.7 最小内核：可运行的 120 行 Python（确定性 mock 模型）— `...1.1.7`
- 1.8 观测：一条轨迹的解剖（run/step/tool 三类记录）— `...1.1.8`

实验：`experiments/ch01/mini_loop.py`（无网络，确定性）。图：ASCII 循环 + canvas 动画。
交叉引用：DL 书注意力/上下文；Linux 2.7 fork/wait 只作类比。

### 第 2 章 工具协议（part1，章号 2）

**论点**：协议的价值不是「让模型会调函数」，而是让三方（模型/宿主/工具）对能力、输入、结果、错误和权限有同一份契约。

- 2.1 三方与分层：模型只产出意图，宿主负责执行 — `2.2.1`
- 2.2 JSON Schema：required、additionalProperties、strict、2020-12 — `2.2.2`
- 2.3 function calling：tools、tool_choice、parallel、流式增量、tool_call_id — `2.2.3`
- 2.4 MCP 原语：tools/resources/prompts 与能力协商 — `2.2.4`
- 2.5 生命周期：2025-11-25 的 initialize 与 2026-07-28 的无状态/MRTR — `2.2.5`
- 2.6 传输与可靠性：stdio、Streamable HTTP、取消、超时、重试 — `2.2.6`
- 2.7 结果与错误：content/structuredContent/isError、JSON-RPC 错误分区 — `2.2.7`
- 2.8 授权：OAuth 2.1、RFC 8707、RFC 9728、confused deputy、token 透传 — `2.2.8`
- 2.9 互操作与迁移：版本矩阵、弃用、失败复盘 — `2.2.9`

实验：`experiments/ch02/mcp_stdio_server.py` + `mcp_client.py`（手写 JSON-RPC，不用 SDK）。
图：ASCII 三层协议栈 + SVG `fig-protocol.md`。必须写清两个版本的差异，不能把 initialize 当永恒。

### 第 3 章 沙箱（part1，章号 3）

**论点**：沙箱是四层边界的组合，不是一条命令；每层挡不同事故，缺一层就有对应的逃逸路径。

- 3.1 威胁模型：代码 agent 能做什么 — `3.3.1`
- 3.2 进程边界：fork/exec/wait、进程组、超时、收尸、wait status（0x2a00）— `3.3.2`
- 3.3 文件边界：rootfs、pivot_root、bind mount、openat2、临时目录 — `3.3.3`
- 3.4 网络边界：netns、veth、DNS 重绑定、egress allowlist — `3.3.4`
- 3.5 资源边界：rlimit 软/硬、cgroup v2（cpu/memory/pids）、墙钟 — `3.3.5`
- 3.6 组合：从 rlimit 到 OCI config.json 的字段映射 — `3.3.6`
- 3.7 失败案例：fork 炸弹、磁盘写满、子进程逃逸 — `3.3.7`
- 3.8 观测：/proc、waitid、cgroup.events、pipefail 和 ulimit 的真实语义 — `3.3.8`
- 3.9 实验：Python 沙箱 runner（限额、超时、收尸）— `3.3.9`

实验：`experiments/ch03/sandbox_runner.py` + `test_sandbox.py`。必须写 `status=0x2a00 → WEXITSTATUS=42`。

### 第 4 章 权限（part1，章号 4）

**论点**：真正的最小权限是「按次序把不必要的权力一层层丢掉」，次序错了，后面每一步都可能失败或失效。

- 4.1 权限模型：UID/GID、capability、最小权限 — `4.4.1`
- 4.2 capability 五集合、文件 capability、降权顺序 — `4.4.2`
- 4.3 seccomp-bpf：过滤器、RET_*、白名单、user notification、TSYNC — `4.4.3`
- 4.4 landlock：ABI 1–6、路径/网络规则、继承、无特权 — `4.4.4`
- 4.5 user namespace：uid_map/gid_map、root in ns、限制与陷阱 — `4.4.5`
- 4.6 组合顺序与 clone 可变参数（parent_tid→tls→child_tid）— `4.4.6`
- 4.7 失败案例：先 seccomp 后 prctl、cap 未 drop、no_new_privs 遗漏 — `4.4.7`
- 4.8 观测：/proc/self/status（CapEff/Seccomp/NoNewPrivs）、landlock 自检 — `4.4.8`
- 4.9 实验：C 加固程序（Linux）+ Python 检查器 — `4.4.9`

实验：`experiments/ch04/harden.c` + `verify-linux.sh` + `inspect_linux.py`。本机只做检查器与语法检查。

### 第 7 章 规划（part2，章号 7）

- 7.5 反思：Reflexion、自我批评、经验回写 — `7.7.5`

- 11.3 数据外泄：通道、markdown 图片、工具参数、DNS — `11.11.3`
- 11.4 工具投毒与供应链：描述注入、schema 陷阱、registry — `11.11.4`
- 11.5 防御组合：能力隔离、双 LLM、内容净化、出口过滤、人工确认 — `11.11.5`
- 11.6 失败案例：网页注入 + MCP server 投毒 — `11.11.6`
- 11.7 红队：测试集、评分、回归 — `11.11.7`
- 11.8 实验：出口守卫 + 注入检测 — `11.11.8`

实验：`experiments/ch11/guard.py` + `attack_cases.json`。图：ASCII 信任边界。

- 12.2 审计：事件、不可篡改、保留期、证据链 — `12.12.2`

- 12.5 策略即代码：OPA/Cedar 思路、决策日志 — `12.12.5`
- 12.6 合规映射：NIST AI RMF、ISO 42001、EU AI Act — `12.12.6`
