# 《Agent 系统工程》写作契约

> 所有作者（人或代理）动笔前必须读完本文件与 `10-章节大纲.md`，并按 §9 自检。
> 这不是建议，是构建门禁：`tools/check_book.py` 会机械检查其中大部分条款。

## 1. 这本书写什么

把 agent 当成**一个有状态、有工具、有预算、可审计的系统**来造。全书只写模型之外的新增层：

```text
循环与状态 → 工具协议 → 沙箱与权限 → 上下文与记忆 → 规划与多智能体
           → 评估 → 可观测性 → 安全 → 治理 → 两个可运行项目
```

**不写**：进程/信号/IPC/socket 的教科书讲解、namespace/cgroup/seccomp 的原理课、TCP/IP、
容器编排、神经网络/训练/反向传播。这些是《Linux 系统与内核》与《深度学习导论》的领土。
本书只在 agent 需要做决策的地方引用它们，并写清「为什么这个边界会影响 agent」。

判断标准：如果一段话删掉「agent / 工具 / 轨迹 / 预算 / 评估」仍然成立，它大概不属于本书。

## 3. 锚点：全局唯一，格式固定

| 对象 | 格式 | 示例 |
|:--|:--|:--|
| H2 小节 | `{#sec-agent-systems.<part>.<chapter>.<section>}` | `{#sec-agent-systems.1.3.4}` |
| def/thm/ex 盒子 | `{#<type>-agent-systems.<part>.<chapter>.<section>.<box>}` | `{#def-agent-systems.1.1.3.1}` |
| 其他盒子 | 建议同格式；可省略 | `{#note-agent-systems.1.3.1}` |

- `<part>` 是篇号 1–4；`<chapter>` 是全书章号 1–14；`<section>` 从 1 开始。
- 第 5 章属于第 2 篇：小节锚点 `sec-agent-systems.2.5.1`，盒子 `def-agent-systems.2.5.3.1`（第 3 节第 1 个盒子）。
- H2 标题必须以 `章号.节号 ` 开头，且与锚点最后两段一致：`## 5.3 压缩 {#sec-agent-systems.2.5.3}`。
- 锚点全书唯一；不要用 `sec-3.1.1` 这种不带书名的短锚点。
- 交叉引用用 `[@def-agent-systems.1.3.1.1]` 或 `[@sec-agent-systems.1.3.2]`；构建期解析，写错会失败。

## 4. 盒子：只用九种

允许：`def`、`thm`、`ex`、`intuition`、`method`、`errata`、`note`、`proof`、`sol`。

禁止：`warning`、`caution`、`tip`、`danger`、`think`、`prop`、`cor`、`lem`、`preview`、`meta`。
（`warning/caution` 是明确禁用；其余类型本书未启用，构建会报未知类型。）

每章最低配置：

| 类型 | 数量 | 用途 |
|:--|--:|:--|
| `def` | 3–5 | 精确定义：状态、轨迹、工具契约、预算、策略 |
| `thm` | 1–3 | 可证明的保证或边界（终止、配额、置信区间） |
| `ex` | 2–4 | 走查、复盘、失败案例 |
| `intuition` | 2–4 | 白话解释「为什么」 |
| `method` | 1–3 | 步骤、清单、排障顺序；每个 `method` 内嵌 2–3 个 `sol` |
| `errata` | 2–3 | 常见误解，每组 3–6 条 |
| `note` | 1–3 | 版本、工具、延伸 |
| `proof` | 按需 | 只嵌在 `ex`/`thm`/`method` 内，里面不再嵌盒子 |

盒子标题写全编号：`::: def 定义 3.1.1 · 沙箱边界 {#def-agent-systems.1.3.1.1}`（第 3 章第 1 节第 1 个盒子）。
盒子必须平铺闭合；不要连续空行贴边。

## 5. 篇幅与密度

- 每章 **1000–1400 行**（目标 1120–1280，留修改余量）。项目章同。
- 8–12 个 H2（推荐 9–11），其中最后三个固定为「母本对应」「本章陷阱」「本章出口检查」。
- 每个 H2 约 110–150 行；每 15–25 行必须有一个信息点：事实、代码、命令、图、表、边界。
- 禁止为凑行数重复定义、复述上一节、写「综上所述」「值得注意的是」「让我们」。
- 句子短，一段只讲一件事；结论带条件（版本、平台、负载）。

## 6. 每章必须有的五样东西

1. **机制图**：至少一个 `<pre class="layout">` 或 `{{#include ../assets/figures/xxx.md}}`，
   图后必须有「读图：」段落，给出一个可验证的结论。
2. **可运行实验**：正文至少引用一次 `experiments/chNN/`（13/14 章可用 `projects/`），
   并有 `bash` 围栏展示运行方式与预期输出。实验代码必须真的在仓库里。
3. **失败案例**：一个具体的事故/翻车复盘（`ex` 盒子或 H2），含触发条件、观测证据、修复。
4. **观测命令**：至少一条真的能跑的 `ps`/`strace`/`jq`/`curl`/`cat /proc/...` 类命令。
5. **章末三件套**：母本对应表、8–15 条陷阱表、出口检查表 + 即时自测。

## 7. 代码、命令、公式

- 代码围栏必须标语言：`bash`、`python`、`c`、`json`、`text`、`yaml`、`http`、`toml`、`sql`、`diff`。
  伪代码用 `text`，不要假装能编译。
- Python：3.11+，只用标准库（除非该章明确说明依赖）；每个实验目录含 `README.md` 与可执行入口。
- C：C17 + POSIX；本机可编译的必须用 `cc -std=c17 -Wall -Wextra -Werror` 通过。
  Linux 专属代码（seccomp/landlock/clone）标注「Linux 6.8 · Ubuntu 24.04」，并提供
  `experiments/chNN/verify-linux.sh`；不得伪称在 macOS 上运行过。
- Bash：示例必须能通过 `bash -n`；脚本首行 `#!/usr/bin/env bash`，建议 `set -euo pipefail`。
- 命令输出用注释或 `text` 块给出**真实**输出；不要编造版本号与路径。
- 公式：行内 `$...$`，块级 `$$...$$`。数学里的 `<`、`>` 写成 `\lt`、`\gt`；
  字面美元写 `\$`；反斜杠命令不要放在 Markdown 链接文字里。
- JSON 示例不写注释；需要解释时在块后用表格。

## 8. 图、表、链接

- 机制图优先 ASCII（`<pre class="layout">`），可复制、可 diff、无外部依赖。
- 需要 SVG 时由 `tools/build_figures.py` 生成到 `src/assets/figures/`，页面用
  `{{#include ../assets/figures/name.md}}` 引入；SVG 的 `id` 必须带 `as-` 前缀且全局唯一。
- 每张图必须有 `<title>`、`<desc>`、图注；图注以 `<b>读图：</b>` 开头。
- 表头必须有单位或说明；数值列右对齐。表后写一句「这张表说明什么」。
- 站内链接只链已存在的页面/锚点：同篇 `[3.2](ch03.md)`，跨篇 `[5.1](../part2/ch05.md)`，
  锚点 `[定义 3.1.1](ch03.md#def-agent-systems.1.3.1.1)`。
- 不链接到 `experiments/` 或仓库外路径（mdBook 不发布它们）；用代码块写命令。

## 10. 五条历史错误：本书必须写对

这五条来自前几本书的真实错误。它们分别落在指定位置，写作时**不得写反**：

| 错误 | 正确写法 | 本书位置 |
|:--|:--|:--|
| 把 `/proc/PID/stat` 的字段当低 8 位退出码 | `wait` status 是内核编码：低 7 位是信号，`WIFEXITED` 后用 `WEXITSTATUS`。示例：`status = 0x2a00` → 退出码 `0x2a = 42`；低字节 `0x00` 只说明「正常退出」，不是退出码本身 | 3.2、附录 B |
| `mq_open`/`sem_open` 写成固定四参数 | 原型是 variadic：`mqd_t mq_open(const char *name, int oflag, ...);`，只有带 `O_CREAT` 时才传 `mode, attr`；`sem_open(const char *name, int oflag, ...)` 同理，带 `O_CREAT` 时传 `mode, value`，无 `O_CREAT` 时两参数 | 8.3、8.5、附录 B |
| `clone` 的 `child_tid` 参数错位 | `clone(fn, stack, flags, arg, ...)` 的可变参数顺序是 `parent_tid → tls → child_tid`；只传 `CLONE_CHILD_SETTID` 时第三个可变参数才是 `child_tid` | 4.6、附录 B |
| 把 `TZ` 空值当系统时区 | `TZ` 为空串、无法解释、或 tzdata 缺失时，`tzset` 的行为是 **UTC**；缺失 tzdata 是静默 UTC，不报错 | 10.7、附录 B |
| `pipefail`/`ulimit`/`jobs` 语义写反 | `pipefail` 让管道状态取**最右非零**；`PIPESTATUS` 保留每一段。`ulimit` 默认改软限制，`-H` 改硬限制，软不得超过硬。`jobs` 是当前 shell 的作业表，子 shell 看不到父 shell 的作业 | 3.2、3.5、13.6、附录 B |

附录 B 会给出可运行的验证程序与真实输出；正文引用它，不要另造一套说法。

## 11. 禁止事项

- 禁止大段摘录母本、规范或论文原文；用自己的话重写，例子自己设计。
- 禁止把 API 文档抄成参数列表；每个接口要讲「何时用、失败长什么样、和谁容易混」。
- 禁止无版本的绝对断言；禁止「据说」「网上说」「业界普遍认为」。
- 禁止在正文写「如图所示」而不给读图结论。
- 禁止 emoji 装饰正文；禁止把安全拆成互相重复的卷。
- 禁止修改 `shared/`、根 `tools/`、其他书的 `SUMMARY.md`/`book.toml`。
- 禁止新增未在 SUMMARY 中的页面；需要新页先改 SUMMARY 并说明理由。
