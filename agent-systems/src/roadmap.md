## 3. 每章怎么读

每章的结构是固定的，可以按同一节奏读：

1. **章首 chapter-index**：先看「本章回答」与「读完你会」，判断是否需要读。
2. **导语与机制图**：建立全局图景，不要急着看代码。
3. **定义与定理**：这是骨架；跳过定义会让后面的代码失去约束。
4. **失败案例**：先看事故，再看修复；事故比成功更有信息量。
5. **实验**：一定自己跑一遍；输出与书里不一致时，先查环境与版本。
6. **章末陷阱表**：复习时只看这张表；每一条都能回到正文。
7. **出口检查**：做不出来的题，回到对应小节，不要往下翻。

## 5. 先修与补课

| 你缺什么 | 先读 | 补到什么程度 |
|:--|:--|:--|
| 进程/信号/文件描述符 | 《Linux 系统与内核》2.7–2.10 | 能解释 fork/exec/wait、进程组、SIGKILL |
| 文件系统与挂载 | 同书 2.5–2.6、3.9–3.10 | 能解释 chroot/pivot_root/mount namespace |
| 权限与 capability | 同书 2.9、3.9 | 能解释 UID/GID 与 capability 的区别 |
| 上下文与注意力 | 《深度学习导论》第 2 讲 | 能解释 token、窗口、位置编码的工程含义 |
| 统计基础 | 任意概率论教材的区间估计 | 能解释置信区间与配对检验 |

补课的原则是「够用就停」：你不需要会写内核模块，只需要知道沙箱的边界在哪；不需要会训练模型，只需要知道 token 与上下文成本怎么算。
