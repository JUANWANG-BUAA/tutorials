## B.1 六条历史错误

| # | 历史错误 | 正确结论 | 本书位置 | 证据/边界 |
|--:|:--|:--|:--|:--|
| 1 | 栈对齐多减 8，callee 入口 mod 16 错 | `call` 前 `%rsp % 16 == 0`；`call` 压入返回地址后 callee 入口为 8；`push %rbp` 后为 0；`sub` 必须是 16 的倍数 | 8.2、8.5、13.5 | rsp 逐步图；项目一汇编 + `llvm-objdump` |
| 2 | `movq 8(%rdi),%eax` 非法 | 32 位目的必须用 `movl`；`movq` 的寄存器目的必须是 64 位 | 8.6、13.5 | `llvm-mc`/clang 汇编失败与 `movl` 成功对照 |
| 3 | 说 `add` 目的不能是内存 | `add` 可读改写内存；限制是两个操作数不能同时为内存 | 8.6 | 汇编/反汇编 + 运行结果 |
| 4 | 把 `x30` 当 callee-saved | `x30` 是 link register，由 `bl` 写入；callee-saved 列表按 AAPCS64 | 8.4 | ARM64 汇编对照；不重写 ABI 基础 |
| 5 | PLT 懒绑定跳 `_init` | 懒绑定经 PLT0 解析，不是跳到 `_init` | 8.1（交叉引用 Linux 1.7） | 本书不重写链接；给出 `llvm-readelf` 检查方法 |
| 6 | 分配器漏 footer | `need = align_up(n + HDR + FTR, ALIGN)`，112B 用例回归 | 8.1（交叉引用 Linux 9.9.6） | 本书不重写 malloc；只引用回归条件 |

::: note 为什么编译器书要收录这六条
第 1–4 条直接出现在代码生成与 ABI 合规测试里：生成器一旦写错，优化器再正确也会产出崩溃的程序。第 5–6 条属于链接器与分配器，本书不展开，但它们提醒一件事：**编译器的输出不是终点**。代码生成正确，只是把程序交给了下一层；下一层的合同同样要验证。
:::

## B.3 与其他书的边界

| 主题 | 本书 | 去哪里读 |
|:--|:--|:--|
| 指令集/寄存器/调用约定基础 | 只用于代码生成与验证 | Linux 1.14–1.16 |
| ELF/链接/PLT | 只用于解释生成物的消费 | Linux 1.7 |
| 分配器实现 | 只引用 footer 回归 | Linux 9.9.6 |
| OS 进程/文件/网络 | 只用于沙箱边界 | Linux 第 2–4 篇 |
| C 语法/指针/数组 | 只用于类型/UB 建模 | C 语言现代方法 |
| Rust 所有权/生命周期 | 只用于检查器接口 | Rust Reference |
| C++ 模板/移动/重载 | 只用于实例化/优化边界 | C++ PL / Effective Modern C++ |

> 发现错误请附环境、命令、真实输出、期望行为四项。没有这四项，很难判断是书错还是环境差异。
