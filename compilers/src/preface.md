## 0.1 三个不满

第一，很多编译原理教材停在「算法正确」，不进入「工程可运行」。读者能背出 LL(1) 的 FIRST/FOLLOW，却没有写过一个能编译 `while (i < n) sum += a[i];` 的完整后端；能画出活跃变量方程，却不知道线性扫描分配器在调用点会怎样溢出。

第二，很多程序分析教材把「检测」与「证明」混为一谈。静态分析报告一个 warning，不等于程序有 bug；sanitizer 没报，不等于没有 UB；fuzzer 跑了 24 小时没崩，不等于正确。本书反复区分：**观察到的、可推断的、已证明的**。

第三，agent 生成代码已经是日常工程事实，但多数团队只有「跑一下测试」这一道门。测试通过不代表没有策略违规；编译通过不代表 ABI 正确；沙箱里跑过不代表资源边界安全。编译器与程序分析恰好提供了一套可复用的证据链：词法/语法门禁、类型检查、静态规则、编译、差分、sanitizer、受限执行。这本书把这条链做成项目二。

## 0.2 与已有教材的关系

本书把母本当作**知识坐标系**，不复制原文、代码或图。母本包括：

- 《自制编译器》（青木峰郎）：用一个可运行的小语言编译器串起词法、语法、类型、IR 与代码生成。本书借用「从零实现」的路线，但语言、IR、优化、后端与验证全部重新设计。
- Rust Reference 与 Rustc Dev Guide：借用「类型/借用/UB/MIR/查询系统」的工程视角，不写成 Rust 语法书。
- 《C 语言现代方法》：借用 C 的声明、作用域、类型转换与 UB 视角，不重讲 C 语法。
- 《C++ 程序设计语言》与《Effective Modern C++》：借用重载、模板实例化、移动语义、内联与零开销抽象的边界，不重讲 C++ 语法。

本书与《Linux 系统与内核》的分工是硬边界：

| 主题 | 去哪里读 | 本书只写 |
|:--|:--|:--|
| x86-64 / ARM64 / RISC-V 指令、寄存器、调用约定细节 | Linux 第 1.14–1.16 章 | 代码生成器如何选择与验证这些约定 |
| ELF、链接、重定位、PLT/GOT | Linux 第 1.7 章 | 编译器生成的符号与重定位如何被链接器消费（只给证据） |
| 操作系统进程、内存、文件、网络 | Linux 第 2–4 篇 | 沙箱执行所需的边界与 JIT 的代码内存问题 |

## 0.3 一条可验证的路线

每章遵循同一个节奏：

1. **问题**：先给一个会失败的具体场景，而不是定义堆。
2. **机制**：用图、伪代码、最小实现解释它为什么工作。
3. **边界**：什么条件下不成立；代价是什么。
4. **证据**：一条能跑的命令、一个能对照的输出、一个能复现的错误。
5. **agent 错误**：一个 LLM/编码 agent 常犯的实现错误，以及怎样在门禁里抓住它。

章末固定三节：母本对应、8–15 条陷阱、出口检查。出口检查不是选择题，而是「能否在不看书的情况下完成某个动作」。

::: method 怎样读效果最好
1. 先读章首的「本章回答」，用一句话写下你的当前答案。
2. 跑该章 `experiments/chNN/` 的实验，先看失败输出，再读机制。
3. 动手改一个参数或一行代码，让实验从通过变失败，再从失败变通过。
4. 做章末自测；答不出时回到对应 H2，而不是重读全章。
5. 每读完一篇，回到项目里跑一次 `verify.sh`，确认你不仅「看懂了」。
:::

## 0.4 入学诊断

以下 8 题不要求全对。能答对 5 题，说明你可以直接进入第 1 章；否则先补对应基础。

| # | 问题 | 答不出时补什么 |
|--:|:--|:--|
| 1 | `a[i]` 的地址怎样用「基址 + 变址 × 元素大小」表示？ | Linux 1.14 的寻址模式 |
| 2 | 函数调用前为什么要求 `%rsp` 16 字节对齐？ | Linux 1.15 的栈帧 |
| 3 | 有符号整数溢出的 C 行为是什么？ | 第 9 章；C 标准 6.5 |
| 4 | 正则表达式为什么不能直接处理嵌套括号？ | 第 2 章的 CFG 与下推自动机 |
| 5 | 活跃变量分析的「活」是什么意思？ | 第 5 章 |
| 6 | SSA 的 phi 指令解决什么问题？ | 第 4 章 |
| 7 | sanitizer 没报错，能否说明程序没有 UB？ | 第 9 章 |
| 8 | 沙箱里 `timeout` 杀掉了进程，能否说明代码安全？ | 第 12 章 |

::: note 诊断题的用法
不要查答案后自我评分。先写下你的答案与置信度（高/中/低），读完对应章节再回来改。置信度高但答错的题，才是你真正需要动手实验的地方。
:::

## 0.5 本书不承诺的事

- 不承诺 14 章读完就能写工业级 LLVM 替代品。项目一是**教学级但完整**的编译器，规模与边界在 13.2 明确列出。
- 不承诺一个静态分析器能证明任意程序正确。第 9、11 章会反复说明可判定性与近似。
- 不承诺沙箱是绝对安全边界。第 12、14 章把「资源限制」「策略拒绝」「隔离」分开讨论。
- 不承诺所有代码在 Windows 原生运行。实验以 macOS/Linux + Python 3.11+ 为基线；C 代码用系统 clang/cc，跨架构汇编用 LLVM 工具核对。
