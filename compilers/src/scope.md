## 0.1 覆盖原则

一本书的边界不是「我想写什么」，而是「读者学完能做什么，以及哪些前提不在本书重复」。本书按四个圈层组织：

| 圈层 | 内容 | 处理方式 |
|:--|:--|:--|
| 核心 | 词法/语法/AST、类型/作用域、IR/SSA、数据流、优化、寄存器分配、指令选择、代码生成、UB/sanitizer、fuzz/差分、形式化入门、JIT 边界 | 完整章节 + 可运行实验 |
| 项目 | 迷你 C 编译器、agent 代码验证器 | 完整源码 + 测试 + 验收 |
| 交叉引用 | x86-64/ARM64/RISC-V 汇编、ABI、ELF、链接、重定位、OS 进程/内存/网络 | 只引用《Linux 系统与内核》，不重写基础 |
| 淘汰 | 已不再作为主流的算法细节（如手工 LR 表构造的完整推导、旧式 peephole 的逐条清单） | 只留背景与选择理由 |

## 0.2 明确不重写

以下内容在《Linux 系统与内核》已有系统讲解，本书只在需要时引用：

| 主题 | 已有位置 | 本书的使用方式 |
|:--|:--|:--|
| 三套 ISA 的寄存器、指令、寻址 | Linux 1.14 | 代码生成示例只展示选择结果，不教指令语义 |
| 调用约定、栈帧、callee-saved | Linux 1.15 | 第 8 章只讲代码生成器如何满足与验证 |
| ELF、链接、重定位、PLT/GOT | Linux 1.7 | 第 8 章只讲编译器产出的符号/重定位如何被消费 |
| 进程、虚拟内存、文件、socket | Linux 第 2–4 篇 | 第 12/14 章只讲沙箱与 JIT 边界 |
| C 语法、指针、数组、结构体 | 《C 语言现代方法》 | 第 3/9 章只讲类型系统与 UB 的建模 |
| C++ 重载、模板、移动语义 | 《C++ 程序设计语言》《Effective Modern C++》 | 第 3/6 章只讲实例化、内联与零开销抽象的编译视角 |
| Rust 所有权、借用、生命周期 | Rust Reference | 第 3/9 章只讲类型检查与 UB 的接口 |

::: note 为什么把汇编基础拿掉
把「寄存器表 + 指令表 + ABI 规则」再写一遍，会产生两本互相矛盾的参考书：读者不知道哪本是最新、哪条规则适用于哪个目标。本书把基础留给专门的系统书，自己只负责编译器侧的**选择、生成、验证**。这是一种减少重复、提高可维护性的取舍。
:::

## 0.3 覆盖矩阵的分类

附录 A 的覆盖矩阵把每个母本单元标成五类之一：

- **完整**：本书有独立小节讲机制、边界与例子；
- **精选**：只讲与编译器/分析相关的部分，其余交叉引用；
- **背景**：为理解主线提供最少背景，不展开；
- **交叉引用**：本书不写，指向已有章节；
- **淘汰**：只解释为什么不再作为主线。

「缺口 0」的定义是：每个登记单元至少有一个落点，且落点章节存在、锚点可达。它不是「每个母本段落都逐字覆盖」——那既不可能，也没有必要。

## 0.4 版本与平台

| 对象 | 基线 | 说明 |
|:--|:--|:--|
| Python | 3.11+ | 项目与多数实验 |
| C | C17 | `cc -std=c17 -Wall -Wextra -Werror` |
| Rust | 2021 edition，rustc 1.75+ | 只在类型/UB/验证例子中使用 |
| x86-64 | System V AMD64 ABI（Linux/macOS 差异单独标注） | 代码生成主目标 |
| ARM64 | AAPCS64 | 只做对照与 `x30` 回归 |
| LLVM | 17+（本机 22） | `llvm-mc`、`llvm-objdump`、`llvm-readelf` |
| mdBook | 0.5.x | 构建与预处理器 |

版本会变。正文把版本写在句子里；读到时先确认它是否仍适用于你的环境。

## 0.5 本书的「不写」

- 不写「C 语言从入门到指针」；不写「Rust 所有权教程」；不写「C++ STL 用法」。
- 不贴大段 LLVM/GCC/Rustc 源码；只保留能说明接口的 5–20 行，并标文件与函数。
- 不把某个优化器的实现细节当成语言规范；规范与实现分开引用。
- 不承诺所有实验在 Windows 原生运行；涉及 POSIX 的代码会标注平台。
- 不用「据说」「网上说」支撑结论；每个断言附标准条款、源码位置或可复现实验。
