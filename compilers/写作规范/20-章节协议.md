# 章节写作协议（作者与代理共同遵守）

本文件是《编译器与程序分析》每一章的硬契约。结构检查器 `tools/check_book.py` 只机械执行其中一部分；技术正确性由作者与 `CHECK-compilers.md` 负责。

## 1. 基本参数

- 正文语言：简体中文，术语首次出现给英文。
- 每章 **1000–1400 行**（`wc -l`，含空行）。目标 1150–1300，不要靠空行凑数。
- 每章 1 个 H1；10–12 个 H2（骨架给了 11 个：8 个内容节 + 母本 + 陷阱 + 出口）。
- 每章开头必须有 `chapter-index`，写清「本章回答 / 读完你会」。
- 章首 3–4 段导语：上一章留下什么、本章解决什么、在全书的路径、一个具体反例或问题。
- 不要写「本章将介绍」「综上所述」「让我们」；不要 emoji。
- 人称用「你」，句子短；每个结论带条件与证据。

## 2. 固定的 11 个 H2

骨架已经给出编号与锚点。不要改编号，不要改锚点，不要删 H2；可以增加 H3。

```text
c.1 … c.8   内容节（每节 90–140 行）
c.9          母本对应
c.10         本章陷阱（8–15 条）
c.11         本章出口检查
```

章节的 c 是全书章号 1–14；锚点为 `sec-compilers.<part>.<c>.<sec>`：

| 文件 | part | c |
|:--|--:|--:|
| part1/ch01–ch04 | 1 | 1–4 |
| part2/ch05–ch08 | 2 | 5–8 |
| part3/ch09–ch12 | 3 | 9–12 |
| part4/ch13–ch14 | 4 | 13–14 |

每个内容 H2 必须有：一个具体问题、机制、边界、至少一个表/代码/命令/图。不要在多个章重复同一段解释；跨章用一句话引用。

## 3. 每章必须出现的六件

1. **IR/数据流/机制图**：至少一个 `<pre class="layout">…</pre>`。不要用 Mermaid（构建器不保证渲染）。图后必须有一句「读图：…」，说明从图中能得出什么结论。
2. **一个可运行例子**：本章实验在 `experiments/chNN/`。正文必须给出实际命令、真实输出或可验证的预期输出；脚本必须能在 macOS/Linux + Python 3.11+ 跑通（Linux 专属要明确标注）。不要链接不存在的文件。
3. **一个 agent 生成代码出错案例**：写清「agent 做了什么 → 现象 → 根因 → 如何用本章的工具发现 → 修复」。不要泛泛说「agent 可能犯错」。
4. **母本对应表**：4–7 行，列「母本 / 章节或条目 / 本书落点 / 程度（完整/精选/背景/交叉引用/淘汰）」。
5. **本章陷阱**：8–15 条编号列表，每条按「现象 → 原因 → 修复/验证」写。必须放在 `::: errata 本章陷阱` 盒子里，编号列表紧跟在陷阱 H2 后、下一个 H2 前。检查器按 `^\d+\.` 计数。
6. **出口检查**：一个「检查项 / 达标线 / 没达标去哪」表，外加一个 `::: method 即时自测`，内部可嵌 `::: sol`。

## 4. 语义盒

只允许：`def`、`thm`、`ex`、`intuition`、`method`、`errata`、`note`、`proof`、`sol`。

- 每章至少 `def`、`ex`、`errata`、`method` 各 1 个；建议总数 12–20。
- 锚点全书唯一。建议格式：
  - `{#def-compilers.<part>.<c>.<sec>.<n>}`
  - `{#ex-compilers.<part>.<c>.<sec>.<n>}`
  - `{#thm-compilers.<part>.<c>.<sec>.<n>}`
- 盒子必须闭合；不要嵌套 `proof`/`sol` 以外的盒子；`proof` 里不要再嵌盒子。
- 标题格式：`::: def 定义 4.2.1 · 支配关系 {#def-compilers.1.4.2.1}`。

## 5. 代码与命令

- 代码围栏必须标语言：`c`、`rust`、`python`、`bash`、`asm`、`text`、`json`、`toml`、`yaml`。
- C 代码必须能通过 `cc -std=c17 -Wall -Wextra -Werror`（除非标 `text` 的纯片段）；Rust 示例标注 edition；Python 只用标准库。
- 汇编只展示**代码生成结果**，不教指令集。不要重写 Linux 1.14–1.16 的寄存器表、调用约定表、ELF/链接/重定位教程。
- 每段代码前一句「这段验证什么」，后一句「预期输出/关键行」；不要贴无法运行的大段代码。
- `bash` 代码块用 `bash -n` 静态检查；不确定的终端会话用 `text`。

## 6. 边界与回归

本书只写：词法/语法/AST、类型/作用域、IR/SSA、优化、代码生成/ABI、UB/sanitizer、静态分析、fuzzing、沙箱。

以下只可交叉引用《Linux 系统与内核》第 1.14–1.16 章：x86-64/ARM64/RISC-V 指令语义、ABI 基础、ELF、链接、重定位、PLT/GOT 机制。若必须展示，聚焦「编译器生成/验证」而不是「指令怎么用」，并在母本表标「交叉引用」。

第 8 章必须显式处理六条历史错误（不得重犯）：

| # | 错误 | 正确写法 |
|--:|:--|:--|
| 1 | 栈对齐多减 8 | 画 rsp：call 前 0 mod 16，callee 入口 8；prologue 的 `sub` 是 16 的倍数 |
| 2 | `movq 8(%rdi),%eax` | 32 位目的必须 `movl`；给 `llvm-objdump` 证据 |
| 3 | 说 add 目的不能是内存 | `add` 可读改写内存；两个操作数不能同时为内存 |
| 4 | x30 是 callee-saved | x30 是 link register；ARM64 的 callee-saved 列表按 AAPCS64 |
| 5 | PLT 懒绑定跳 `_init` | 必须跳 PLT0；用 `llvm-readelf`/`llvm-objdump` 验证（本书只交叉引用） |
| 6 | alloc.c 漏 footer | 不重写分配器；交叉引用 Linux 9.9.6，记 `need=align_up(n+HDR+FTR)` 与 112B 用例 |

## 7. 质量红线

- 不复制母本原文、代码、图；例子自己设计。
- 不写无法验证的绝对断言（「总是」「绝不」），改成有条件的表述。
- 不把静态分析当证明；不把 sanitizer 没报当无 UB；不把 fuzz 没找到当正确。
- 不链接不存在的页面；跨书引用用书名+章节，或 `/tutorials/linux/...` 绝对 URL。
- 不在正文留 `TODO`、骨架注释、占位符、空表格。
- 每章必须有至少 2 个 H3 或表格之外的「可操作细节」（命令、参数、失败模式、数据）。
- 不允许用同一段文字换说法重复凑行；如行数不足，补充边界、反例、对照表、实测输出。
