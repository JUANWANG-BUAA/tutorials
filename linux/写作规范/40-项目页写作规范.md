> 四篇项目页（`projects/pa.md`…`pd.md`）是本书的「压舱石」。它们不是练习答案，而是**可复现的工程记录**：目标、架构、分阶段代码、验证、压测、故障注入、复盘。

## 2. 每个 Stage 必须有的六件

1. **目标**：一条命令 + 预期输出，说明「做到什么算过」。
2. **关键概念**：回看正文的章号/锚点；不要重复讲理论。
3. **代码**：完整可编译的核心片段（函数级），不是伪代码；标注文件名。
4. **验证**：`make`、运行命令、预期输出、失败时查什么。
5. **常见错误**：3–6 条，含真实报错文本与修复。
6. **下一步**：这一 Stage 留下的债务/扩展点。

## 3. 代码纪律

- C17 + POSIX；`-D_GNU_SOURCE -Wall -Wextra -Werror -O2 -g`。
- 每个系统调用检查返回值；处理 `EINTR`、短读/短写、`EAGAIN`。
- 资源清理：`goto cleanup` 或统一 `struct ctx` 析构；不泄漏 fd/内存。
- 并发：锁顺序写清楚；共享状态用 `atomic` 或互斥锁；不写「假并发」。
- 容器/网络实验要 root 的，命令前标 `sudo`，并给清理命令。
- 不把整份项目贴成 2000 行代码墙：每段 20–80 行，前后有解释；完整文件放 `code/` 或附录链接。
- 代码块语言标 `c`、`bash`、`makefile`、`dockerfile`；伪代码标 `text`。

## 4. 测试与压测

每个项目至少：

| 层 | 要求 |
|:--|:--|
| 单元测试 | 核心数据结构/解析器有 `assert` 测试，`make test` 可跑 |
| 集成测试 | 起服务、发请求/建连接、比对输出，脚本自清理 |
| 故障注入 | 至少 2 类：fd 耗尽、磁盘满、网络丢包、`kill -9`、OOM |
| 压测 | 有基线、并发梯度、P50/P99、错误率、资源占用 |
| sanitizer | ASan/UBSan 通过；并发项目加 TSan |

压测命令与报告模板见 [工程手册](engineering.md)。

## 5. 四条主线的必讲点

### A 云原生

- **A1 容器运行时**：`clone/unshare` + namespace（pid/mnt/net/uts/ipc/user）、cgroups v2（`cpu.max`/`memory.max`/`pids.max`）、`pivot_root`、overlayfs、OCI `config.json`、runc 生命周期、信号与 PID 1、安全（capabilities/seccomp/no_new_privs）。
- **A2 HTTP 服务器**：epoll（LT/ET）、非阻塞 accept、HTTP/1.1 解析（请求行/头/体、keep-alive、chunked）、静态文件 `sendfile`、线程池/多 reactor、超时与优雅关闭、`SO_REUSEPORT`、压测与 `perf`。
- **A3 eBPF**：bpftrace 快速原型 → kprobe/tracepoint → map 聚合 → libbpf 用户态加载 → 导出 Prometheus → 追踪 `openat` 与 TCP 收包。

### B 存储

- **B1 Redis**：RESP 协议、事件循环、命令表、字符串/哈希/列表/有序集合、过期、RDB/AOF、主从复制、压测（`redis-benchmark` 对照）。
- **B2 存储引擎**：页格式、buffer pool、B+ 树插入/分裂/删除/合并、WAL、崩溃恢复、事务/隔离级别、`fio` 压测、`kill -9` 注入。

### C 网络

- **C1 用户态 TCP/IP**：以太网/ARP/IP/UDP/TCP 状态机、校验和、重传/窗口、socket API、TUN/TAP 对接、与 Linux 栈互通。
- **C2 反向代理**：epoll、上游连接池、负载均衡、健康检查、超时/重试、零拷贝、TLS 一句带过、`wrk` 压测。
- **C3 抓包分析器**：`AF_PACKET`、以太网/IP/TCP/UDP 解析、流重组、统计、pcap 导出、与 tcpdump 对照。

### D 工具链

- **D1 POSIX Shell**：词法/展开、内建命令、管道/重定向、作业控制、信号、脚本执行、`sh` 兼容性测试。
- **D2 BusyBox 工具集**：`applet` 框架、`ls/cat/cp/mv/rm/find/grep/wc/head/tail`、选项解析、测试。
- **D3 Git 对象库**：blob/tree/commit/tag、SHA-1/256、索引、`add/commit/log/checkout`、与真 git 互操作、packfile 一句带过。

## 6. 验收清单（每个项目页末尾）

- [ ] Stage 0–N 全部有目标、代码、验证
- [ ] 至少 1 个完整可运行的最小版本
- [ ] 单元测试 + 集成测试 + 2 类故障注入
- [ ] 压测有基线、梯度、P99、资源数据
- [ ] ASan/UBSan（并发加 TSan）零报告
- [ ] README 能让陌生人 10 分钟跑起来
- [ ] 复盘：最难 bug、性能瓶颈、如果重做

## 7. 篇幅

单个项目页 1600–2400 行；三个子项目均分。若超过 2600 行，拆成 `pa1.md`/`pa2.md`/`pa3.md` 并更新 SUMMARY（需主线程同意）。

## 8. 禁止

- 禁止只有架构图没有代码；禁止只有代码没有验证。
- 禁止把「理论上可以」写成「已验证」；没跑过的命令标「未实测」。
- 禁止用玩具输入冒充压测（如 10 个请求）。
- 禁止复制现成项目源码；可以读其设计，代码自己写。
