# 子代理派单模板（Linux 教材化改造）

> 用法：复制下面整段，替换 `<<篇>>`、`<<章号>>`、`<<章名>>`、`<<文件路径>>`、`<<书与页码>>` 五处。一次只派一章；同一章同一时间只允许一个代理写。

---

你在改造一本中文教程《Linux 系统与内核 · 从命令行到云原生》（mdBook，`/Users/juanwang/Desktop/tutorials/linux`）。

**先读三份文件，再动笔：**

1. `写作规范/70-教材化改造总纲.md`（施工图，优先于旧总则）
2. `写作规范/00-写作总则.md`（代码、盒子、链接、图的底线）
3. 本章的 `src/part<<篇>>/ch<<章号>>-overview.md` 与 `src/part<<篇>>/ch<<章号>>.md`

**任务**：只改 `<<文件路径>>`（`<<章名>>`）。按小节顺序，一次只改一个 H2 小节，把它改到「rustwiki 体」：先场景后定义、短段、术语首现解释、代码先跑再讲、每节小结与即时自测。其他文件一律不碰。

**安全红线（本仓库发生过整章丢失事故）**

1. **禁止对该文件使用 Write 整文件覆盖。只用 Edit。** `old_string` 从 `## ` 标题覆盖到下一个 `## ` 标题之前；单次 `new_string` 不超过约 120 行。超过就拆成多次 Edit，每次替换一个明确的子块。
2. 每改完一节，在工作目录 `linux` 下跑：

   ```bash
   python3 tools/check_loss.py
   grep -c '^## ' <<文件路径>>
   ```

   它对比 git HEAD：H2 减少或汉字数倒退超过 8% 即失败。失败先修，不要继续写。

3. 语义盒必须配平：`::: def`/`::: ex`/`::: method` 都要有对应的 `:::`；`::: method` 里套 `::: sol` 时先关 `sol` 再关 `method`。
4. 锚点沿用原编号（`sec-<<章号>>.x`、`def-<<章号>>.x`），不要新建重复锚点；`[@id]` 只能引用已经存在的锚点。
5. 不碰 `SUMMARY.md`、`tools/`、`theme/`、其他章；不跑 `mdbook build`（并行会互相清空 `book/`）。
6. 不编造任何命令输出、版本号、性能数字；已有实测值原样保留；没实测的写「未实测」。

**每节骨架**（详见 70 号文件第 4 节）

```markdown
## <<章号>>.x 标题 {#sec-<<章号>>.x}

这一节回答：……

::: preview 先抓住一件事
……
:::

（场景：一条能跑的命令 / 一段真实输出 / 一个报错。先让读者看见现象。）

（机制：从现象推到结构；需要时用 `::: def`。）

（例子：先猜输出，再解释关键行。）

::: errata 常见误解
1. ……
:::

### <<章号>>.x 小结

……；如果只记住一件事，那就是……。

::: method 即时自测 · <<章号>>.x
**Q1（记忆）** ……
**Q2（辨析）** ……
**Q3（应用）** ……

::: sol 答案
**A1** ……
**A2** ……
**A3** ……
:::
:::
```

**语言要求**

- 用「你」称呼读者，需要共同操作时用「我们」；不用「笔者」「本文」「读者」。
- 一段 1–4 句，平均 60–120 字；一句话只说一件事。
- 术语第一次出现给：中文（English，缩写）+ 一句大白话 + 一个最小例子。
- 先给命令/输出/报错，再给定义；不要先堆三个抽象名词。
- 每节最多一个比喻；不用 emoji；不用「小伙伴们」。
- 正文里不写「母本」「本轮」「门禁」「证据链」这类审计口吻。

**原著核读（硬要求）**

- 先按 `70-教材化改造总纲.md` 第 1.1 节确定主干：第 0/2 篇先读 **Kerrisk**，第 1 篇先读 **CSAPP**；第 3/4 篇先读内核/网络书，再回读 Kerrisk/CSAPP。**Kerrisk 与 CSAPP 的对应页必须读**，不能只读鸟哥或博客。
- 在 `写作规范/source-toc/` 找到本节对应的母本章节与 PDF 页码，只抽目标页：

  ```bash
  pdftotext -f 100 -l 112 -layout "/Users/juanwang/E-Book/LinuxOS/书名.pdf" -
  ```

- 读完合上 PDF，用自己的话写；不摘录原文。
- 每节至少回答一次「非科班读者缺的那一层」：他可能没学过页表、中断、inode、fd、TCP 窗口中的哪一个？本节用哪 2–3 句补上？
- 如果本节命中 `写作规范/CHECK-*-ERRORS.md` 的 B 表条目，把条目号写进交回报告；能补就补，补不了说明原因。
- 交回时报告：读了 `<<书与页码>>`、改了哪几节、补了哪些 B 表条目、**非科班补了什么**、哪些写成「未实测」、下一轮该补什么。

**验收**（工作目录 `linux`）

- `python3 tools/check_loss.py` 通过；
- `python3 tools/check_book.py` 对本章零报错（其他章的报错忽略）；
- `grep -c '^## ' <<文件路径>>` 不少于改造前；
- 每节都有「这一节回答」、`preview`、小结、即时自测；
- 交回 200 字以内。

## 批次大小（两次实测后定下的硬上限）

代理会在 150 轮上限处被切断，而且是在**写作完成之后、交回报告之前**断的——所以断掉不等于没写完，但也确实有代理停在第 4 节开头。按已观测的工作量定死：

| 批次类型 | 一节要求 | 每批最多 |
|:--|:--|:--|
| 需要本机实测（跑命令、跑程序、复现报错） | 900–1500 汉字 + 实测输出 | **3–4 节** |
| 以叙述与表格为主（概念、速查、边界） | 900–1400 汉字 | **5–6 节** |
| 尾部三节（实验 / 脚本 / 本章小结） | 同上，但盒子较少 | 单独一批 |

派单里必须写清「上一批实际停在第几节」，让新代理从盘上的真实状态接续，而不是从工单假设的状态接续。代理报失败时，先验四件事：行数、汉字数、`grep -c '^## '`、盒子配平 + `check_book`——0.7 与 0.4 两次都是「报告阶段超时、正文已写完」。

## 派单前必做的两件核对

1. **母本能不能抽页**。先看 `70-教材化改造总纲.md` §1.1.1 的实测表：Kerrisk、OSTEP、鸟哥、奔跑吧内核、深入理解 Linux 网络、两本命令行书可直接 `pdftotext`；CSAPP 中文第 3 版、谢希仁《计算机网络》、李治军《操作系统原理、实现与实践》是纯扫描版且本机 `tesseract` 没有 `chi_sim`，**不能声称读过具体句子与页内数字**，派单里必须写清这条约束与替代证据口径。
2. **一次一个代理一个文件**。同一章同一时间只允许一个代理写；并行时按文件切开，`SUMMARY.md`、`tools/`、`theme/`、章末件页由主会话登记，代理只能在交回报告里给出建议文本。

## 并发与停滞的观测（2026-10-29）

同时跑 12–15 个代理时出现的现象，记录以免每次重新猜：

- 代理报「超 150 轮」常常只是**报告阶段**被切，正文已写完——先验四件事再决定重派。
- 文件 1.5–2.5 小时没有写入 ≠ 卡死：VM 上有该代理留下的实验产物、且没有残留编译进程，说明它在长验证或长写作阶段。判据是「盘上有没有它的现场」，不是「mtime 新不新」。
- 一次派单里同时开 8 个以上正文代理时，交回会成批延迟；宁可分两波。
- VM 临时文件必须按「篇+章」双位前缀（`lab0c12_` vs `lab1c02_`），否则两章代理会在同一台机器上互相覆盖。
- **不能只等完成通知**：2026-10-29 有 10 个代理在没有任何 completed/failed 通知的情况下静默消失（文件 4–5 小时零写入）。探活办法是 `TaskStop <id>`：报「No task found」就是已经不在了，报成功说明还活着。每轮开工先探一轮再派新单，否则「在跑」是幻觉。
- **撞车之后最好的处置是「转复核」，不是「抢着改」**（2026-10-29 晚三起）：0.6、0.8、0.9 各出现两个代理写同一批节。三个后到的代理都自发改成了独立复跑——0.8 的复核者抓出写者两处事实错（数组切片「洞也占 `length`」、二次 `wait` 返回值），0.9 的复核者订正三处（`pidfd_open` 引入版本、`popen` 不推迟 SIGINT/QUIT、BSD `ulimit -f` 单位是 1024 字节），0.6 的复核者补了写者漏掉的 `N`/`P`/`D` 例子并订正 0.6.9 标题为「从最左最长」。**所以派单里要显式写这条规则**：开工先扫目标节骨架，若已完成，立刻转成「独立复跑 + 只报差异 + 补缺口」，不要重写。主线程另要防另一种失败：代理可能 0 次工具调用就「完成」（2026-10-29 晚 0.8.13 批第一次派单即如此，3 秒返回一句计划），判据是 `tool_uses=0` 且文件 mtime 未变，直接重派。
