# 第 2 篇 · Unix/Linux 系统编程

::: preview 这一篇在讲什么
会用 `open/read/write` 不等于会写系统程序。真正的系统程序要处理短读短写、`EINTR`、信号、`fork/exec` 的失败路径、文件锁、线程同步、socket 超时与 `epoll` 的边界。这一篇以 Kerrisk 为主干、CSAPP 为底座，把「API 怎么调」推进到「程序为什么正确、为什么可移植、为什么可观测」。
:::

## 读完这一篇你会

- 写出对 `EINTR`、短读、短写、`EAGAIN` 都正确的 I/O 循环。
- 解释 `open`/`read`/`write`/`close` 的返回值承诺与 `errno` 边界。
- 用 `fork`/`execve`/`wait4` 写进程管理工具，处理信号、定时器与守护进程。
- 用 pthread 写线程池，用互斥锁/条件变量/原子操作避免数据竞争。
- 用管道、FIFO、共享内存、消息队列、信号量做 IPC。
- 用 socket、`select/poll/epoll`、`io_uring` 写高并发服务器，并知道各自的边界。
- 用 `strace`、`/proc`、`gdb`、`valgrind` 定位 fd 泄漏、死锁与内存错误。

## 入口与出口

| 项 | 内容 |
|:--|:--|
| **入口** | 会 C，但没写过真正的系统程序；遇到 `EINTR`、短读、`fork` 失败、死锁、fd 泄漏就卡住。 |
| **出口** | 能写正确、可移植、可观测的系统程序；能用 `strace`/`/proc`/`gdb` 解释一次故障。 |

## 与前后篇的接口

- **第 1 篇 → 本篇**：1.3 汇编、1.7 链接、1.8 异常、1.10 I/O 是 2.7、2.10、2.12 的底座。
- **本篇 → 第 3 篇**：2.7–2.13 的进程、信号、线程、同步是调度器、内存管理、并发原语的前置。
- **本篇 → 第 4 篇**：2.16–2.18 的 socket 与 I/O 多路复用是协议栈与 `epoll` 的入口。
- **本篇 → 第 5 篇**：2.19 的 daemon/终端与 2.9 的凭证是容器生命周期与安全的前置。
- **本篇 → 项目**：A2（`myhttpd`）、B1（`myredis`）、C2（`myproxy`）都直接使用本篇。

## 怎么读这一篇

- **第一次读**：按 2.1 → 2.19 顺序；2.1–2.4 的代码必须自己编译运行，不能只看。
- **只想写服务器**：2.1–2.4、2.7–2.13、2.16–2.18；2.14–2.15 可后补。
- **想读内核**：2.1–2.4、2.7–2.13、2.16–2.18；2.5–2.6 可后补。
- **卡住时**：先回[先修工具箱](../prerequisite.md)补 fd/inode/进程/线程，再回到对应小节。
