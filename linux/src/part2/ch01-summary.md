# 2.1 章末总结

## 三段主线：三个单元，一条因果链

**第一段，边界与成本（2.1.1–2.1.2，第一个单元）。** 用户程序不能直接调内核函数，CPU 只给一个受控入口：一条陷入指令（x86-64 `syscall`、ARM64 `svc #0`、RISC-V `ecall`、i386 `int 0x80`）把特权级切到内核态，内核按**调用号查表**决定做什么。于是一次 `read` 里有两次翻译：内核用**负返回值**表示错误（`-ENOENT`），libc 把它变成 C 世界的 `-1` 加 `errno`；参数与调用号住在哪个寄存器是架构 ABI，源码看不出来。所以不要自己写陷入指令，也不要写死编号。第二层分工是「谁保证语义」：`printf` 的格式化与缓冲在 libc，`write` 才进内核；`malloc` 在堆上切块，`mmap` 才找内核；`getpid` 每次都进内核（glibc 2.25 起不再缓存），`clock_gettime` 常走 **vDSO**（内核映射进每个进程的一小段只读代码，读共享数据页，不陷入）。判据只有一条：**这个函数是否执行了那条陷入指令**。正文那组「几百纳秒对约二十纳秒」是 x86-64 的量级示例，**要记的是「一次陷入 ≈ 一百到几百纳秒、一次 vDSO 读 ≈ 十几纳秒」这个量级关系**，绝对值属于那台机器；本书的 aarch64 虚拟机上重跑同一个程序得到 138 / 139 / 13.6 ns——比例仍然成立（约 10 倍），绝对值是正文那组的一半多一点，见[勘误页](ch01-errata.md)第 2 节。

**第二段，失败怎么报告（2.1.3–2.1.4、2.1.10，第二个单元）。** C 没有异常，失败靠「特殊返回值 + `errno`」，而 `errno` 是个**线程局部**的左值（glibc 里展开为 `(*__errno_location())`），成功时**不保证清零**。由此得出七条规则：判断只看返回值；要复用就先 `errno = 0`；它不是进程级状态；`fprintf`/`strerror`/`free` 都可能改写它，所以错误处理函数第一句是 `int saved = errno;`；不是所有函数都设它（`pthread_*` 直接返回错误码，`snprintf` 截断不设）；`EINTR` 是「被打断」不是「失败」，要重试而不是报错；`strerror` 不保证线程安全，多线程用 `strerror_r`/`strerror_l`，而 `strerror_r` 有 GNU（返回 `char *`）与 XSI（返回 `int`）两个不兼容签名。工程写法压成三层：`errMsg` 打印并返回且保留 `errno`、`errExit` 打印后 `exit(EXIT_FAILURE)`、`errExitEN` 接收显式错误码给 `pthread_*` 那类接口；中间层一律透传 `-1` 让调用者决定。对外还要把错误码翻译成协议语义：`ENOENT`→404、`EACCES`/`EPERM`→403、`EMFILE`/`EAGAIN`→503 带退避、`ETIMEDOUT`→504、`EIO`→500 加告警，`EINTR` 不该走到这一层；进程退出码走 `sysexits.h`，且退出码只有 8 位，`exit(256)` 会变成 0。

**第三段，不把平台写死（2.1.5–2.1.9、2.1.11–2.1.17，第三个单元）。** 头文件只在你声明了标准等级时才暴露对应接口：特性测试宏必须在**第一个系统头之前**（写在源文件里已经晚了），`_GNU_SOURCE` 隐式打开 POSIX/XOPEN/BSD/GNU 全套，而一旦显式定义 `_POSIX_C_SOURCE`，glibc 就不再默认给 `_DEFAULT_SOURCE`，`accept4`/`pipe2`/`strdup` 失去声明——最坏结果是「隐式声明 + 链接成功 + 运行时按错误的返回类型与参数解释」。宏不只控制声明，还控制类型与结构体布局：`_FILE_OFFSET_BITS=64` 把 `off_t` 与 `stat` 换成 64 位版本，`_TIME_BITS=64` 必须和它一起定义；把假设写成 `_Static_assert(sizeof(off_t) == 8, "...")` 比运行时报错早得多。限制一律运行时查：`sysconf`/`pathconf`/`fpathconf` 的 `-1` 有二义性（`errno == 0` 是「不确定」），所以调用前清 `errno`；`_SC_OPEN_MAX` 在 glibc 上只是本进程 `RLIMIT_NOFILE` 软限制的投影，`nr_open`/`file-max` 才是系统侧的数，`_PC_NAME_MAX` 随文件系统变。ABI 那一侧要记住：参数寄存器只有六个，超了就改传带 `size` 字段的结构体（`clone3`、`openat2`、`io_uring_setup`、`bpf`），`size` 让新字段能追加而不破坏旧程序；坏指针不产生 `SIGSEGV` 而是 `-EFAULT`，因为内核用 `copy_from_user`/`copy_to_user` 捕获缺页。取证的两端也定好了：`strace` 只看系统调用边界（`vfs_read` 之类要 `perf probe`/`bpftrace`，本机的 `sudo` 与 `perf` 都不可用），`/proc/self/fdinfo/N`、`/proc/self/syscall`、`/proc/PID/limits` 是免 root 的读数来源；而容器里「`openat` 突然 `EPERM`」常常是 seccomp 而不是权限。

一句话主线：**先把「谁进内核、谁翻译错误、谁保证语义」三层分开，再把所有写死的常数改成运行时查询、所有「`errno != 0` 就报错」改成先看返回值、所有「我这能编」改成显式声明标准等级并编两次；剩下的分歧交给 `strace` 与 `/proc` 的读数，而不是交给运气。**

## 只记一件事

**`errno` 只在返回值表明失败之后才有意义，而且随时可能被下一次调用改写。** 这一条同时解释本章另外三件事：为什么 `sysconf` 之前要 `errno = 0`（`-1` 有二义性）、为什么 `errExit` 第一句要存 `errno`、为什么 `pthread_mutex_lock(&m) == -1` 永远不成立（它返回错误码，不碰 `errno`）。记不住别的东西没关系，这一条记反了，后面 18 章会一路用错。
