# 2.3 学习目标自检表

这张表接管 [2.3.19 本章出口检查](ch03.md#sec-2.3.19)：左列是达标项，中列是「怎样算达标」，右列是「没达标回到哪一节」。正文出口检查只有九行，这里按**概念（K）、动手（S）、实验取证（E）、口径（B）**四组展开成 21 条；达标线都写成能当场做的动作，做不到就回右列重读那一段，不要从头再读整章。

## 没达标怎么办

- **K 组卡住（概念行）**：先讲一句完整因果，例如「因为记录锁归进程 + inode，所以关掉同一文件的另一个 fd 会把它名下所有锁一并释放——这就是双实例事故的全部机制」。讲不出因果就回对应小节的 errata 盒和「即时自测」，不要靠多读几遍。
- **S 组卡住（动手行）**：拿纸画两张图——「fd 表 → 打开文件描述 → inode → page cache → 磁盘」五层，以及「加锁 → 写 → `fflush` → 解锁」四步；再合上正文默写原子发布四步与 3×3 锁矩阵。默写不出的那一步，回 [2.3.6](ch03.md#sec-2.3.6)/[2.3.7](ch03.md#sec-2.3.7)/[2.3.15](ch03.md#sec-2.3.15) 重跑对应 C 组实验。
- **E 组卡住（取证行）**：先确认环境边界再动手：`sudo`、`perf` 事件计数、`strace -p` 附着、`dmesg`、`fincore` 在本机都不可用，观察一律改成「在 strace 下启动」「读 `/proc/self/...`」「`getrusage` 替代计数」。报不出读数就降级成「未实测 + 原因」，不要用别的机器的数字顶。
- **B 组卡住（口径行）**：把「规范条款 / 本机实测 / 另一台机器的形状 / 未实测」四类分开记；判断错误码写名字、要限制运行时查、要读数回本机取。[勘误页](ch03-errata.md)的「复跑校正」与「本章未实测项」先读一遍再勾这两行。
- **只有 K 组全对**：说明你还停在「会读」。本章要求会跑、会取证、会判断现象归哪层；把 S 组与 E 组做完再来勾这一页。

全部达标后，往下的接口有三处：[2.4 缓冲与 stdio](ch04.md) 接走 `dup2`/`fflush` 与「加锁→写→解锁」的缓冲尾巴。[2.5 文件属性](ch05.md) 把 `st_size` 与 `st_blocks` 摊到 `stat` 全表，inode（索引节点）的完整属性也在那一章讲。[2.15 共享内存与信号量](ch15.md) 把 `MAP_SHARED` 与 `memfd` 扩成正式的跨进程共享内存。
