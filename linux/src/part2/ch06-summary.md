# 2.6 章末总结

## 三段主线：三个单元，一条因果链

**第一单元，名字的两层结构（2.6.1–2.6.3）。** 目录是「名字 → inode 号」的映射表：目录在磁盘上是一串目录项，`st_size` 是项占的字节数而不是「目录里文件的总大小」，目录的 `r`/`w`/`x` 分别管「列名字 / 增删项 / 穿过」。读目录有四条纪律：`readdir` 返回 NULL 前先 `errno=0` 区分 EOF 与错误；`d_name` 在下一次调用时被覆盖（libc 复用同一个 `struct dirent`），要留就 `strdup`；顺序不保证（ext4 htree 按哈希序）；`d_type` 可能是 `DT_UNKNOWN`，用 `fstatat(dirfd(dir), name, ..., AT_SYMLINK_NOFOLLOW)` 补齐。链接有两种且结构不同：硬链接是**同一个 inode 的第二个名字**，`nlink` 计数、地位平等、不能跨文件系统也不能对目录建（inode 号只在单文件系统内唯一、目录硬链会成环）；符号链接是**独立 inode**，内容是路径字符串（相对路径以链接自身位置为参照），不计入目标 `nlink`、可以悬空。`unlink` 删名字不减数据：inode 的 `nlink` 降到 0 **且**没有进程持有打开 fd，数据才释放——`rm` 后空间不降与「`tmpfile()` 式临时文件」是同一枚硬币的两面。`rename` 只改目录项不搬数据：同文件系统原子、目标存在则覆盖、old 与 new 是同一文件时成功且无变化、两个参数都不解引用符号链接、跨文件系统 `EXDEV`（`mv` 退化为复制+删除）。

**第二单元，锚定与改名语义（2.6.4–2.6.10）。** 遍历整棵树别手写递归：`nftw` 封装了符号链接（`FTW_PHYS`）、挂载点（`FTW_MOUNT`）、深度（`nopenfd` 超限关重开）、前序/后序（`FTW_DEPTH`）；要跳子树用 glibc 的 `FTW_ACTIONRETVAL` + `FTW_SKIP_SUBTREE`。`*at` 家族把「相对路径以谁为基准」从进程 `cwd` 换成目录 fd：动机一是 TOCTOU（`open` 检查路径与实际打开之间目录前缀可被替换），二是每线程虚拟工作目录（`cwd` 是进程级共享的，线程里 `chdir` 会互相干扰）。`renameat2` 补了两种原语：`RENAME_NOREPLACE`（目标存在 `EEXIST`，原子地「不覆盖别人」，是先 `access` 再 `rename` 做不到的）与 `RENAME_EXCHANGE`（两边都存在，原子互换——版本发布的底层操作）。`fs.protected_hardlinks`/`protected_symlinks` 站在攻击者对面：`/tmp` 这类全局可写 sticky 目录里，建硬链接要属主或有读写权、跟随符号链接看链接/目标属主——这是 `open` 报 `EACCES` 而不是 `ENOENT` 的隐藏出处之一。

**第三单元，事件订阅（2.6.5、2.6.11–2.6.14）。** inotify 把「文件变了」变成「fd 可读」，但它是**事件通知不是消息队列**，三个限制各有后果：① 尾部合并——新事件与队列尾 `wd/mask/cookie` 全同则丢弃，同一文件连写 100 次可能只收 1 次 `IN_MODIFY`，不能计数；② 队列溢出——`max_queued_events`（默认 16384）满后事件丢失、放入 `IN_Q_OVERFLOW`（`wd=-1`），正确反应是全量重扫而不是继续增量；③ 非递归——`inotify_add_watch` 只管指定目录本身，新建子目录要靠 `IN_CREATE|IN_ISDIR`/`IN_MOVED_TO|IN_ISDIR` 事件补加 watch（且「先 readdir 再 add」之间有竞态窗口，加完再扫一遍才稳）。另外两条容易踩的语义：`inotify_add_watch` 的读权限是**一次性检查**——watch 建立后即便权限被收走事件照发；`wd` 会被复用——收到 `IN_IGNORED` 立即删 `wd→path` 映射（`IN_ONESHOT` 触发后没有 `IN_IGNORED`），否则新 watch 的事件会被认成旧路径。内核侧：watch 挂在 **inode** 上而不是路径上，所以 rename 后 watch 仍有效；`read` 缓冲区至少 `sizeof(struct inotify_event)+NAME_MAX+1`，小于一个事件返回 `EINVAL`，遍历按 `sizeof+ev->len` 推进。

一句话主线：**名字与内容是两层——`rm`/`mv`/`link`/`rename` 全部只动名字层，inode 与数据有自己的生命周期（`nlink` + 打开 fd 双计数）；inotify 订阅的是名字层的变化，但它是通知不是队列：会合并、会溢出、不递归。**

## 只记一件事

**`rm` 删的是名字，不是数据；inotify 订阅的是名字的变化，不是可靠的日志。** 这两句共用同一个根：**名字层与内容层各有各的生命周期**——`nlink` 降 0 且无 fd 才释放数据，所以有 `lsof +L1` 这种排查；事件会合并、会溢出、不递归，所以有「溢出全量重扫」这种恢复。这一条记反，本章其余结论都会跟着错位。
