# 0.7 章末总结

## 五单元一览

| 单元 | 核心问题 | 关键结论 | 典型陷阱 |
|:--|:--|:--|:--|
| **一、骨架与变量**（0.7.1–0.7.2） | 脚本怎样写、变量怎样管？ | shebang + `set -euo pipefail` + `usage`/`main` + 退出码；变量默认全局，`local` 限函数，`export` 进环境，`readonly` 禁改。 | 不加引号；`local` 写在函数外；把环境变量当普通变量；忘记 `export`。 |
| **二、引号、展开与算术**（0.7.3–0.7.5） | 三种引号差在哪？ | 无引号会分词/通配；单引号全字面；双引号展开变量/命令但不分词。`$(...)` 命令替换，`$((...))` 算术。 | `$var` 不加引号；`"$@"` 写成 `"$*"`；在单引号里写变量。 |
| **三、条件、分支与退出码**（0.7.6–0.7.8） | 条件怎样写？`set -e` 什么时候不生效？ | `[` 是命令，`[[` 是 bash 关键字（支持 `&&`/`||`/正则），`(( ))` 做算术。`if/case/for/while/until` 控制流程；`set -e` 在 `if`/`while`/`&&`/`||`/`!`/管道等语境有例外。 | `[ $x = y ]` 空变量报错；`set -e` 以为万能；管道退出码只看最后一段。 |
| **四、展开顺序与全表**（0.7.9–0.7.14） | 一行命令执行前发生了什么？ | 展开顺序：大括号 → 波浪号 → 参数/变量 → 命令替换 → 算术 → 分词 → 通配 → 去引号。参数展开全表能替代很多 `sed`/`cut`；`getopts` 解析短选项，`trap` 做清理/ERR。 | 展开顺序记反；`${var#prefix}` 与 `${var##prefix}` 混；`getopts` 不处理长选项。 |
| **五、实验与脚本**（0.7.15–0.7.18） | 怎样证明脚本可靠？ | `set -x` 看展开，`bash -n` 挡语法错，再按 0.7.15 的六步手工体检（`shellcheck` 两台机器都没装，装上更好）；脚本要有 `usage`、`--dry-run`、日志、清理、退出码。 | 不 `bash -n`、不手工体检；不 dry-run；`trap` 顺序错；清理函数里再触发 `ERR`。 |

## 一条主线

这一章分两遍。**第一遍先会用**：写脚本骨架、管变量与引号，用参数展开/命令替换/算术处理数据，用 `test`/`[`/`[[` 与分支循环控制流程，理解退出码与 `set -e` 例外。**第二遍看展开与边界**：展开顺序、参数展开全表、三套条件的差异、`select`/`read`/`getopts`、`ERR` trap。**最后用 `set -x` 与 `bash -n` 的实验（两台机器都没装 `shellcheck`，走 0.7.15 的手工六步）、三个脚本与陷阱清单收口。**所有实测都在写作机 macOS（bash 5.3.20，正文称「本机」）与 Ubuntu 24.04.5 虚拟机（bash 5.2.21，称「VM」）上各跑一遍，只在其中一台成立的结论正文逐处标明。

## 看到问题先选工具

| 症状 | 第一动作 | 为什么 |
|:--|:--|:--|
| 变量为空导致 `[` 报错 | 用 `[[ ]]` 或 `"${var:-}"` | `[` 是命令，空变量会被当成少参数；`[[` 是关键字，更安全。 |
| 路径拼接多了/少了斜杠 | `${dir%/}/${file}` | 参数展开能去尾部 `/`，不用 `sed`。 |
| 参数解析越写越乱 | `getopts` + `shift` | 短选项标准解析；长选项用 `case`/`--` 手写。 |
| 脚本出错却继续跑 | `set -euo pipefail` + `trap ERR` | 默认 shell 不因命令失败退出；要显式开启并处理例外。 |
| 脚本退出后留下临时文件 | `trap cleanup EXIT INT TERM` | 清理逻辑集中，异常退出也能跑。 |
| 管道退出码总是 0 | `set -o pipefail` + `PIPESTATUS` | 默认只看最后一段。 |
| 循环读文件丢最后一行 | `while IFS= read -r line \|\| [[ -n $line ]]` | 文件末尾没有换行时 `read` 返回非零但仍有内容。 |
| 变量里带空格被拆开 | 加双引号 `"$var"` | 无引号会分词/通配。 |
| 脚本在 macOS 上跑不了 | 检查 bash 版本与 GNU 工具 | macOS 默认 bash 3.2、BSD sed/grep；用 `#!/usr/bin/env bash` 并避免 GNU 专有选项。 |
| 不知道哪一行展开错了 | `set -x` / `bash -x script` | 打印展开后的命令；配合 `PS4` 加行号。 |

## 能否讲出这八句话

1. 脚本第一行是 shebang，正文先 `set -euo pipefail`，再写 `usage`/`main`，最后显式 `exit`。
2. 变量默认全局；函数里用 `local`；要传给子进程用 `export`；不想被改用 `readonly`。
3. 无引号会分词与通配；单引号全字面；双引号展开变量/命令但保留一个参数。`"$@"` 保留每个参数，`"$*"` 合成一个。
4. `${var:-default}` 给默认值，`${var#prefix}`/`${var%suffix}` 去前后缀，`${var/old/new}` 替换，`${#var}` 取长度。
5. `[` 是命令，`[[` 是 bash 关键字（支持 `&&`/`||`/正则），`(( ))` 做算术；条件里优先 `[[ ]]`。
6. 展开顺序是大括号 → 波浪号 → 参数 → 命令替换 → 算术 → 分词 → 通配 → 去引号；顺序记反就会写出“看起来对、跑起来错”的脚本。
7. `set -e` 在 `if`/`while`/`until`/`&&`/`||`/`!`/管道等语境有例外；不要把它当万能错误处理。
8. `getopts` 解析短选项，`trap ... EXIT/ERR/INT/TERM` 做清理与错误处理；静态检查走 `bash -n` 加 0.7.15 的手工六步——本书两台机器都没装 `shellcheck`，装了更好。
