# 0.1 章末总结

## 五单元一览

| 单元 | 核心问题 | 关键结论 | 典型陷阱 |
|:--|:--|:--|:--|
| **一、先看见分层**（0.1.1–0.1.4） | Linux 到底是什么？ | Linux 严格说是内核；完整系统 = 内核 + GNU 用户态 + 包管理 + 默认配置，也就是发行版。内核提供机制，发行版决定策略。 | 把发行版当内核；把 `-45-generic` 当上游第 45 版；以为容器有自己的内核。 |
| **二、标准与身份**（0.1.5–0.1.7） | 换个系统，程序还要不要改？ | POSIX 保证源码级接口，不保证性能、扩展与默认配置；FHS 是目录约定，不是内核强制；ABI 决定二进制能不能跑。 | 把 POSIX 当「行为完全一致」；把 `4096` 当页大小常量；忽略 amd64/arm64 差异。 |
| **三、一条命令的四层**（0.1.8–0.1.10） | `ls` 从按键到输出经过什么？ | Shell → `execve` → 动态加载器 → libc → 系统调用 → 内核；`strace` 能把每一层变成证据。 | 把 `ls` 快当成磁盘快；把「能编译」当「能随便分发」；读错 man 区。 |
| **四、内核如何被扩展、启动、进入**（0.1.11–0.1.14） | 内核怎样被加载、启动和调用？ | 模块与内建代码同跑在 ring 0；启动分固件、引导器、内核、initramfs、init 五段；系统调用是唯一合法入口；FHS 用可变性分目录。 | `lsmod` 看不到内建模块；直接改 `grub.cfg`；以为 `syscall()` 返回的 -1 是内核原样返回。 |
| **五、把地图变成路线**（0.1.15–0.1.16） | 接下来怎么学？ | 六个阶段每阶段都要有可展示的产物；十个跨层误判可以用一条命令验证。 | 只背名词不动手；没写过 `fork` 就读调度器；没抓过包就学 eBPF。 |

## 一条主线

这一章只做一件事：把「Linux 系统」拆成可指认的层。**先分清内核与用户态**，你就知道 `printf` 的 bug 不该去查内核；**再分清发行版与上游**，你就知道 `uname -r` 和 `/etc/os-release` 各自回答什么；**然后用 `strace` 追一条命令**，你就能把「Shell 展开、加载器找库、libc 包装、内核执行」变成可见的证据；**最后看模块、启动和系统调用**，你就能解释「为什么容器换不了内核」「为什么 `lsmod` 看不到 ext4」「为什么 `syscall()` 和 `write()` 的返回值不一样」。

## 看到问题先选工具

| 症状 | 第一动作 | 为什么 |
|:--|:--|:--|
| 命令找不到 | `type -a <cmd>`、`echo "$PATH"` | 可能是别名、函数、内建或路径问题，不一定是没装。 |
| 版本对不上 | `uname -r` + `cat /etc/os-release` | 前者是内核，后者是用户态发行版；两者可以独立变化。 |
| 二进制报 `not found` | `file <bin>` 看 `interpreter` | 多半是动态加载器路径不存在，不是文件不存在。 |
| 模块加载失败 | `modinfo -F vermagic <m>`、`dmesg` | 版本不匹配、符号缺失、依赖未加载都会报 `Unknown symbol`。 |
| 开机卡住 | 按五段链路找「最后一段有证据的地方」 | 日志服务没起来时，`journalctl` 当然没有记录。 |
| 配置改了不生效 | `systemctl cat <unit>`、`systemd-analyze cat-config` | `/etc` 覆盖 `/usr/lib`，drop-in 还会叠加。 |
| 容器里内核版本不对 | 在宿主机看 `uname -r` | 容器共享宿主机内核，镜像只换用户态。 |
| 系统调用返回 -1 | 区分裸 `syscall()` 与 libc 包装 | 内核返回 `-errno`，glibc 翻译成 `-1` 并设置 `errno`。 |
| 页大小相关崩溃 | `getconf PAGE_SIZE`、`sysconf(_SC_PAGESIZE)` | 页大小随架构和内核配置变化，不是 ABI 常量。 |
| 不知道目录放什么 | 问「可变吗、要备份吗、重启要清吗」 | `/etc` 配置、`/var` 持久状态、`/run` 本次启动、`/usr` 只读程序。 |

## 能否讲出这八句话

合上正文，用自己的话补完；任何一句卡住，就回到对应小节，不要重读整章。

1. Linux 严格来说是**内核**，你在服务器上用的完整系统是**发行版**；`uname -o` 输出 `GNU/Linux` 就是在提醒这一点。
2. 内核提供**机制**，发行版决定**策略**；同一个 `open` 在 Ubuntu 和 Alpine 上语义相同，默认 `umask`、挂载选项和防火墙规则可以不同。
3. 三个版本号各管一件事：`uname -r` 是内核，`ldd --version` 是 libc，`/etc/os-release` 是发行版。
4. POSIX 保证**源码级**接口可移植，不保证性能、错误文本、扩展接口和默认配置；`epoll`、`grep -P`、systemd 都不在 POSIX 里。
5. 一条 `ls` 的关键路径是：Shell `fork` + `execve` → 加载器 `openat` 找 libc → `ls` 打开目录 → `getdents64` 读目录项 → `write` 输出。
6. 内建模块编在 `vmlinuz` 里，不出现在 `lsmod`；判断要看 `modules.builtin` 或 `modinfo -F filename`。
7. 启动链路是**固件 → 引导器 → 内核 → initramfs → init**；每段都有自己的持久产物和证据命令。
8. `syscall()` 返回 -1 是 glibc 的翻译；内核返回的是 `-errno`，裸汇编里没有 `errno`，只有返回寄存器里的负值。
