# 0.6 章末总结

## 五单元一览

| 单元 | 核心问题 | 关键结论 | 典型陷阱 |
|:--|:--|:--|:--|
| **一、方言与语法骨架**（0.6.1–0.6.2） | 正则有几种方言？元字符怎么写？ | BRE 用 `\(`/`\)`/`\{`/`\}`，ERE 直接用 `()`/`{}`/`+`/`?`/`|`，PCRE 再加 `\d`/`\w`/环视/懒惰量词。锚点、字符类、量词、分组、反向引用是骨架。 | 把 ERE 写法直接塞进 BRE；忘记转义；贪婪量词吃掉过多内容。 |
| **二、grep/sed/awk 三件套**（0.6.3–0.6.7） | 三者各做什么？怎么选？ | grep 筛行/计数，sed 按「地址 + 命令」流编辑，awk 按「记录 + 字段」做统计报表。筛选用 grep，改流用 sed，算结构化数据用 awk。 | 用 grep 做替换；用 sed 做列统计；awk 里忘了 `-F`；grep 退出码 1 当错误。 |
| **三、实战**（0.6.8） | 日志统计/批量改名怎样拆？ | 先明确输入格式，再用 `grep`/`awk` 筛出字段，`sort`/`uniq` 统计，`sed`/`awk` 改名；每步先 `-n`/`--dry-run` 试运行。 | 文件名带空格/换行；locale 影响排序/匹配；直接 `sed -i` 不留备份。 |
| **四、引擎、选项与工具链**（0.6.9–0.6.15） | 为什么匹配慢/结果怪？ | 回溯引擎在嵌套量词下可能灾难性回溯；`grep` 有 `-F`/`-E`/`-P` 与退出码 0/1/2；sed 有 hold space/分支；awk 有数组/内建函数；sort/uniq/cut/tr/paste/join/diff 各有边界。 | 灾难性回溯；`sed -i` 改 inode；awk 浮点累加；`sort` 受 locale 影响。 |
| **五、实验与脚本**（0.6.16–0.6.19） | 怎样证明？ | `LC_ALL=C` 通常更快；`sed -i` 用临时文件 + rename，断硬链接；`sed -n l` 看不可见字符；awk `%d` 向零截断。 | 把 `sed -i` 当“原地改同一个 inode”；用浮点算金额；不检查 locale。 |

## 一条主线

这一章分两遍。**第一遍先会用**：分清 BRE/ERE/PCRE 与语法骨架，用 grep 筛、sed 改、awk 算，知道三者怎么选，再用日志统计/批量改名串起来。**第二遍看引擎与全表**：回溯、贪婪/懒惰、grep 退出码、sed 的模式空间与 hold space、awk 的数组/内建函数、sort/uniq/cut/tr/paste/join/diff 的边界。**最后用 locale、`sed -i`、awk 精度实验与三个脚本收口。**

## 看到问题先选工具

| 症状 | 第一动作 | 为什么 |
|:--|:--|:--|
| 只想找包含某模式的行 | `grep -n` / `grep -c` | grep 专做筛行与计数，比 sed/awk 直接。 |
| 要按列统计/求和 | `awk '{s+=$3} END{print s}'` | awk 的字段模型天然适合列数据。 |
| 要批量替换/删除/插入 | `sed -n` 先看，再 `sed -i.bak` | sed 的地址 + 命令模型适合流编辑。 |
| 想去重/排序 | `sort` + `uniq -c` | 先排序才能让 `uniq` 正确计数。 |
| 想取第 2、4 列 | `cut -d, -f2,4` 或 `awk -F, '{print $2,$4}'` | cut 简单，awk 更灵活（分隔符/空字段）。 |
| 想比较两个文件 | `diff -u a b` | 生成可读补丁；`cmp` 只看字节差异。 |
| 匹配很慢/CPU 飙高 | 检查嵌套量词，改 `grep -F` 或简化正则 | 回溯引擎在 `(a+)+b` 这类模式上会爆炸。 |
| 文件里有看不见的字符 | `sed -n l file`、`od -c file` | 显示 tab/行尾/控制字符。 |
| `sed -i` 后硬链接断了 | 用 `sed ... > tmp && cat tmp > file` 保持 inode | GNU sed 用临时文件 + rename，inode 会变。 |
| 金额统计有小数误差 | 用整数分，不用浮点累加 | awk 浮点是二进制近似，`0.1+0.2` 不精确。 |

## 能否讲出这八句话

1. BRE 的 `()`/`{}`/`+`/`?` 要转义，ERE 不用；PCRE 再加 `\d`/`\w`/环视/懒惰量词。
2. `grep` 退出码 0 表示匹配、1 表示没匹配、2 表示出错；脚本里不要把 1 当错误。
3. `sed` 的执行模型是「读一行到模式空间 → 按地址选命令 → 执行 → 输出」，`-n` 关闭默认输出。
4. hold space 是 sed 的第二个缓冲区，`h/H/g/G/x` 在模式空间与 hold space 之间搬运。
5. `awk` 把每行当记录 `$0`，按 `FS` 切字段 `$1..$NF`；`BEGIN`/`END` 与模式块组成程序。
6. 筛选用 grep，流编辑用 sed，结构化统计用 awk；不要用一把锤子敲所有钉子。
7. 回溯引擎在嵌套量词下可能灾难性回溯；`grep -F` 和 `LC_ALL=C` 通常更快。
8. `sed -i` 用临时文件 + rename，会改 inode、断硬链接；awk `%d` 向零截断，金额用整数分。
