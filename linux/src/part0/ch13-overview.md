# 0.13 网络配置与排障 · 本章导航

::: preview 这一章在讲什么
`ping` 通但 `curl` 不通，问题在哪一层？`ss` 的四个数字各是什么？DNS 解析慢/失败怎么分？防火墙、NAT、路由、netns 怎样把包拦住？这一章先把链路、地址、路由三层与配置工具讲清，再用 `ss`/DNS/`ping`/`mtr`/`nc`/`curl`/`tcpdump`/防火墙按故障树排查；第二遍看策略路由/netns、DNS 记录/`ndots`、TCP 状态机、nftables/NAT、BPF 过滤与 SSH。目标是**按层拿证据，不靠重启网络**。
:::

## 读完你会

- 分清链路、地址、路由三层，用 `ip`/`ss`/`resolvectl` 看状态。
- 配 netplan/NetworkManager/systemd-networkd，知道谁在管网络。
- 读 `ss` 的 Recv-Q/Send-Q/Local/Peer 与 TCP 状态。
- 用 `dig`/`getent`/`resolvectl` 分 DNS 失败类型，理解 `ndots`/search domain。
- 用 `ping`/`mtr`/`nc`/`curl` 分层验证连通性。
- 用 `tcpdump`/BPF 过滤抓包，用 `ufw`/`nftables` 看/配防火墙与 NAT。
- 用故障树「链路→地址→路由→端口→应用」定位问题。
- 配 SSH 密钥/跳板/端口转发，写网络巡检脚本，做 veth/netns 实验。

## 先修与预计学时

- 先修：读完 [0.12 systemd、启动、日志与定时任务](ch12.md)；会 `ip`、`ping`、`ss`。**不需要**学过网络协议；链路/地址/路由的白话解释在本章开头。
- 阅读：约 120–150 分钟；实验与抓包：约 60 分钟；章末习题：约 60 分钟。

## 怎么读

- **第一次读**：0.13.1–0.13.8 按顺序；每节先做「即时自测」，再去下一节。`ip`/`ss`/`tcpdump` 要自己在虚拟机里试。
- **只想排障**：0.13.1、0.13.3–0.13.8、0.13.17；按故障树逐层验证。
- **想配网络/防火墙**：0.13.2、0.13.7、0.13.9、0.13.12；先 `netplan try`/`nft -c` 预演。
- **想抓包/SSH**：0.13.6、0.13.13–0.13.14；先小过滤、再放大。
- **卡住时**：先回[先修工具箱](../prerequisite.md)补 IP/端口/TCP，再回到对应小节。
