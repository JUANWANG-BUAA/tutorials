管道把数据交给下一个命令，接下来要回答的是：**怎样描述你想要的文本**。正则表达式是描述工具，grep、sed、awk 是三种执行模型：筛选、流编辑、记录处理。它们共享一部分语法，但方言与边界不同。

这一章不追求正则大全。目标是把三类任务分清：**找**（grep）、**改**（sed）、**算**（awk）。每个工具给五到八个真实任务，并说明失败模式。掌握这些之后，你写的命令会更短，也更容易被别人读懂。

本章有两台真机器：一台是 Ubuntu 24.04.5 LTS 虚拟机，GNU grep 3.11、GNU sed 4.9、bash 5.2.21；它的 `awk` 经 `/etc/alternatives` 指向 **mawk 1.3.4**，`gawk` 默认没装（`command -v gawk` 无输出；要用得 `sudo apt install gawk`，本书未装，相关例子不标实测）。另一台是开发机 macOS，BSD grep 2.6.0、BSD sed、awk 20200816。正文的实测标注分两种：「本机实测」指 macOS 的 BSD 工具，「Ubuntu 实测」指那台 Ubuntu 24.04 上 GNU 工具的原样输出；两侧都跑过的会分开写清。你照抄命令前先想清楚自己在哪一侧：用 `command -v awk`、`awk --version`、`grep --version`、`sed --version` 各看一眼即可。BSD 与 GNU 的差别在本章不是脚注，而是主线的一部分：`sed -i` 的后缀是否必填、`grep -P` 存不存在、`2~5` 这类步长地址认不认、`awk` 是 mawk 还是 gawk，恰好都是同一条命令在两种系统上真的不一样。读 Linux 运维文档时按 GNU 口径理解。

## 0.6.1 三种方言：BRE、ERE、PCRE {#sec-0.6.1}

这一节回答：为什么同一条模式交给 `grep`、`grep -E`、`sed`、`awk`、`perl`，行为会不一样？

::: preview 先抓住一件事
正则表达式（regular expression，regex）不是通用语言，而是写给某一台「引擎」看的模式说明。POSIX 标准定义了 BRE 与 ERE 两台引擎，Perl 带来第三套实现 PCRE。结果不对时，先确认模式交给了哪台引擎，再怀疑模式本身。
:::

**先建正面模型：正则是一台在文本上跑的小状态机。** 引擎逐字读文本，模式描述允许走通的路径：写模式=描述路径，引擎=走路径。引擎之间的分歧，多数出在同一个字符能不能「开门」：有的引擎里 `+` 是一扇「重复上一项」的门，有的引擎里它只是普通的砖。

先跑一组，看「同一个意图、三种写法」。准备输入：

```bash
printf '2024-10-17\n2024-1-7\ntoday is 2024-10-17 ok\n9999-12-31\n' > /tmp/dates.txt
```

意图：只取整行恰好是「年-月-日」的行。三种写法（本节以下输出都是本机实测，即 macOS 的 BSD grep 2.6.0、BSD sed、awk 20200816；本机 `grep` 没编入 PCRE，所以 PCRE 用 `/usr/bin/perl` 演示——在 Ubuntu 上这活直接归 `grep -P`，见下文）：

```bash
grep    '^[0-9]\{4\}-[0-9]\{2\}-[0-9]\{2\}$' /tmp/dates.txt   # BRE
grep -E '^[0-9]{4}-[0-9]{2}-[0-9]{2}$'       /tmp/dates.txt   # ERE
perl -ne 'print if /^\d{4}-\d{2}-\d{2}$/'    /tmp/dates.txt   # PCRE
```

三条的输出完全相同：

```text
2024-10-17
9999-12-31
```

`2024-1-7` 因为月、日只有一位被拒；`today is ...` 因为 `^` 和 `$` 两个锚把整行夹住被拒。差别只在写法：BRE 必须把 `{` `}` 写成 `\{` `\}`，PCRE 可以直接用 `\d`。在同一台机器上敲 `grep -P '^[0-9]{4}' /tmp/dates.txt`，得到的是 `grep: invalid option -- P`，退出码 2。换成 Ubuntu 24.04 再敲同一条（GNU grep 3.11），直接放行，输出 `2024-10-17`、`2024-1-7`、`9999-12-31` 三行；把三分法里的 `perl -ne` 换成 `grep -P '^[0-9]{4}-[0-9]{2}-[0-9]{2}$'`，输出与 BRE、ERE 完全相同的两行（以上均 Ubuntu 实测，输入还是 `/tmp/dates.txt`）。`-P` 可不可用，在程序编译时就定了，与你的模式无关。

::: def 定义 0.6.1 · BRE / ERE / PCRE {#def-0.6.1}
**BRE**（basic regular expression，基础正则表达式）是 POSIX 从 `ed` 与早期 `grep` 继承的旧方言，元字符只有 `^ $ . [ ] *` 加反斜杠。**ERE**（extended regular expression，扩展正则表达式）在此之上把 `( ) { } ? +` 和竖线直接升为元字符，对应当年的 `egrep`。**PCRE**（Perl compatible regular expression）不是 POSIX 标准，是 Perl 系引擎的语法，带数字简写、懒惰量词、环视。工具各自表态：`sed` 默认 BRE（`-E` 切到 ERE），`awk` 用 ERE，`grep` 默认 BRE、用 `-E`/`-P` 换引擎。
:::

转义规则是三方言最核心的差异，一张短表：

| 引擎 | 分组 | m 到 n 次 | 一次或多次 | 数字简写 |
|:--|:--|:--|:--|:--|
| BRE | `\(ab\)` | `\{2,3\}` | `\+`（POSIX 未定义） | 无，写 `[0-9]` |
| ERE | `(ab)` | `{2,3}` | `+` | 无，写 `[[:digit:]]` |
| PCRE | `(ab)` | `{2,3}` | `+` | `\d` |

差异核心就是反斜杠：BRE 里加了 `\` 才有元字符含义，ERE 里 `\` 反而让 `( ) { }` 变回字面字符。竖线同理：ERE 用它连接分支，BRE 里它是普通字符（GNU 的「反斜杠加竖线」是实现扩展）。

**为什么 BRE 把 `{` `(` 当普通字符？** 因为它是被标准化的旧语法。`grep`（1973 年）和 `ed` 先设计，那时模式里没有分组和区间；POSIX 后来把 `egrep` 的新符号定为 ERE，又不能改变已有 BRE 脚本的行为，于是新符号在 BRE 里一律要靠反斜杠才生效。这可以直接验证：

```bash
printf 'aa{2}\naaa\n' > /tmp/lit.txt
grep 'a{2}' /tmp/lit.txt      # 只输出 aa{2}：花括号被当字面字符
grep -E 'a{2}' /tmp/lit.txt   # 两行都输出：花括号成了区间
```

本机实测：第一条只输出 `aa{2}`，第二条输出两行。ERE 一侧同样可验证：`grep -E '\(ab\)'` 匹配的是带字面括号的那一行。

至于 BRE 里的 `\+` `\?` 与「反斜杠加竖线」，POSIX 未定义其含义，是实现层扩展：本机 BSD grep 认（实测 `grep 'a\+'` 匹配 `aaa`），GNU grep 也认——Ubuntu 24.04 上把 `aaa`、`a+`、`abc` 三行喂给 `grep 'a\+'`，三行全部输出（Ubuntu 实测；`a+` 这行入选是因为行里有一个 `a`，与例 0.6.1 的 ERE 行为一致）。结论：需要这些语义就写 `-E`，别把可移植性押在扩展上。

**补一层「方言从哪来」。** POSIX 标准化的其实是两样东西：正则 API（`regcomp()`/`regexec()`，指定 BRE 或 ERE）与标准工具的行为。1980 年代 UNIX 厂商各改各的版本、互不兼容，IEEE 1003（POSIX）随后把工具行为收回一套标准；GNU 的 grep、sed、gawk 再以 POSIX 为底线叠加自家扩展。所以「同一条模式行为不同」不是缺陷，而是分层的必然：语法层（谁认识哪些元字符）、实现层（BSD/GNU/PCRE 库）、环境层（locale 影响字符类与排序，0.6.2 现场对比）。

::: ex 例 0.6.1 · 一条模式，四种去向
`/tmp/plus.txt` 的内容是三行：`aaa`、`a+`、`abc`。先猜下面四条命令各输出什么，再跑：

```bash
grep     'a+'     /tmp/plus.txt
grep -E  'a+'     /tmp/plus.txt
awk      '/a+/'   /tmp/plus.txt
sed -n '/a\{1,\}/p' /tmp/plus.txt
```

本机实测输出：第一条只有 `a+`——BRE 把 `+` 当字面加号。后三条都是 `aaa`、`a+`、`abc` 三行：`grep -E` 与 `awk` 按 ERE 走「一个或多个 a」；第四条用 BRE 的标准区间写法 `a\{1,\}` 表达同一语义。第二条里 `a+` 这行也被选中，因为模式只要求行内出现一个 `a`，后面的加号不参与匹配。

结果和预期不符时，按这个顺序排查：先确认工具默认引擎，再检查 shell 引号是否吃掉反斜杠，最后才怀疑模式本身。
:::

::: errata 常见错误清单
1. **「`grep 'a+'` 匹配一个或多个 a」**——BRE 里 `+` 是普通字符，本机实测只匹配字面 `a+`；改 `grep -E 'a+'`。
2. **「模式一样，结果就该一样」**——`sed` 默认 BRE、`awk` 默认 ERE，同一个 `a+` 在两边语义不同。
3. **「`grep -P` 到处能用」**——本机 BSD grep 直接报 invalid option 并退出码 2；busybox 的精简构建同样没有：Ubuntu 24.04 自带的 busybox 1.36.1 执行 `busybox grep -P` 报 `grep: invalid option -- 'P'`、退出码 2，其 usage 行里只有 `-F` 与 `-E`（Ubuntu 实测）。
4. **「BRE 里 `(ab)` 也是分组」**——本机实测匹配的是带字面括号的 `(ab)`；要分组写 `\(ab\)`。
5. **「`\+` 是 BRE 标准写法」**——POSIX 未定义 `\+`，它是 BSD/GNU 实现都认的扩展；可移植脚本改用 `-E` 或 `\{1,\}`。
:::

### 0.6.1 小结

先认清模式交给谁：BRE、ERE、PCRE 三台引擎对同一串字符开不同的门。BRE 把 `{` `(` 当普通字符，是旧语法在标准化时被固定的结果，可直接用命令验证。如果只记住一件事，那就是：**换工具等于换引擎，结果不对先查引擎，再改模式。**

::: method 即时自测 · 0.6.1
**Q1（记忆）** POSIX BRE 的元字符有哪些？ERE 在此之上直接加入了哪五个？

**Q2（辨析）** 为什么本机 `grep 'a{2}'` 匹配 `aa{2}` 却不匹配 `aaa`，而 `grep -E 'a{2}'` 两行都匹配？

**Q3（应用）** 在一台 `grep` 没编入 `-P` 的机器上，要匹配「整行恰好三位数字」，给出两种可移植写法。

**Q4（迁移）** `awk '/a+b/'` 用的是哪台引擎？在默认配置下让 `sed` 做同样的匹配，命令怎么写？

::: sol 答案
**A1** BRE 的元字符只有 `^ $ . [ ] *`（外加反斜杠本身）；ERE 直接把 `( ) { } ? +` 和竖线升为元字符。
**A2** BRE 里 `{` 是普通字符，`a{2}` 要求出现字面的 `a{2}`；ERE 里 `{2}` 是区间，要求连续两个 `a`，`aaa` 里含有这样的片段。
**A3** `grep -E '^[0-9]{3}$'`，或 BRE 写法 `grep '^[0-9]\{3\}$'`。
**A4** awk 用 ERE。`sed` 默认 BRE，直接加 `-E` 写 `sed -E '/a+b/'` 最稳；不想开 `-E` 就写区间形式 `sed -n '/a\{1,\}b/p'`（本机实测可行）。
:::
:::

## 0.6.2 语法骨架：锚点、字符类、量词、分组 {#sec-0.6.2}

这一节回答：锚点、字符类、量词、分组这四件套，各自的「写错版本」长什么样？

::: preview 先抓住一件事
四件套各管一件事：锚点管位置，字符类管「这一格允许哪些字符」，量词管重复几次，分组把多个字符捆成一个整体。还有一个必须提前知道的规则：POSIX 引擎一律贪婪，非贪婪只有 PCRE 有。
:::

先看一次翻车。想从一行里提取两个 `<b>` 标签，直觉写法（本机实测，下同）：

```bash
printf '<b>a</b> <b>b</b>\n' | grep -oE '<b>.*</b>'
```

输出不是两个标签，而是整段 `<b>a</b> <b>b</b>`。原因在 `.*`：贪婪（greedy）量词先尽量向前吃，吃到行尾再回头找能接上 `</b>` 的最远位置——POSIX 的约定就是「最左最长」。两种修法：

```bash
printf '<b>a</b> <b>b</b>\n' | grep -oE '<b>[^<]*</b>'   # 可移植：用排除类
printf '<b>a</b> <b>b</b>\n' | perl -pe 's{<b>.*?</b>}{X}g'  # PCRE 懒惰：X X
```

第一条输出两行 `<b>a</b>`、`<b>b</b>`；第二条依赖 PCRE，`?` 才是「够用就停」。注意别在 ERE 里写 `.*?`：本机 `grep -oE '<.*?>'` 对同一行输出 `<b>`、`</b>`、`<b>`、`</b>` 四段，跟「懒惰」毫无关系——POSIX ERE 没有这个概念。

**锚点：`^` 行首，`$` 行尾。** 对含 `book books`、`book`、`sbook` 三行的文件，写错的版本 `grep 'book'` 三行全命中；写对的版本 `grep '^book$'` 只留一行（本机实测）。两条规则要记住：锚点按「每条输入行」生效，不是文件首尾；`^` 出现在模式中间就退回普通字符，`grep 'a^b'` 匹配的是字面的 `a^b`（本机实测）。另外 `.` 不跨换行：`printf 'a\nb\n' | awk '/a.b/'` 什么都不输出，跨行匹配要靠 sed 的 `N` 或 awk 的 `RS`（0.6.5 起讲）。

**字符类：`[...]` 选一格，`[^...]` 排除。** 版本号 `1.2` 写错成 `grep '1.2'`，`1x2` 也会命中——点号是「任意单字符」；正确写法 `grep '1\.2'` 或 `grep '1[.]2'`，后者不依赖转义，最稳。POSIX 还给了命名类 `[[:digit:]]` `[[:alpha:]]` `[[:space:]]`，比 PCRE 的 `\d` 可移植。类里出现 locale 陷阱，我们当场对比：

```bash
printf 'B\nb\nA\na\n' | LC_ALL=C sort
printf 'B\nb\nA\na\n' | LC_ALL=en_US.UTF-8 sort
```

本机实测第一条输出 `A B a b`（按字节），第二条输出 `a A b B`（按英文 collation 交替）。排序规则变了，字符类变不变？Ubuntu 24.04 上拿 GNU grep 3.11 现场判定：对 `B`、`b`、`A`、`a` 四行文件执行 `LC_ALL=en_US.UTF-8 grep '[a-z]'`，只输出 `b` 和 `a`，`B` 没有匹配（Ubuntu 实测；先 `locale -a` 确认 `en_US.utf8` 已生成再用）。旧稿「glibc 按 collation 展开会把 B 算进去」的推测到此证伪。那 collation 到底影响什么？同一台 Ubuntu 上：`é` 单行文件在 `LC_ALL=C` 下不匹配 `[a-z]`（退出码 1），在 `en_US.UTF-8` 下匹配（退出码 0）——字符类范围按 collation 展开，落在 26 个基本字母「之间」的重音字母会被算进来；而大小写是更靠后的区分层级，`[a-z]` 不会因此吃掉 `B`。跨大小写的写法反而更危险：`LC_ALL=en_US.UTF-8 grep '[A-z]'` 直接报 `Invalid range end`、退出码 2（Ubuntu 实测；同一条在 `LC_ALL=C` 下合法，还能匹配到 `_` 和 `` ` `` 这些 punctuation）。结论不变且更强：日志、协议字段、编号一律前缀 `LC_ALL=C`，按字节、可复现。

**量词：`*` 零或多次、`+` 一次或多次（ERE）、`?` 零或一次、`{m,n}` 次数区间。** 写错的版本：匹配「三位数字」写 `grep -E '[0-9]{3}'`，对 `223001`、`22203` 两行都命中——行里存在连续三位数字就成立；写对的版本 `grep -E '^[0-9]{3}$'` 两行都不命中（本机实测：前者 2，后者 0）。量词管「次数」，锚点管「整行」，两者几乎总是搭配出现。

**分组与反向引用：`(...)` 捆整体，`\1` 回看第 1 组。** 在 BRE 里写 `(ab)+` 不匹配任何东西（本机实测退出码 1，括号是字面字符）；ERE 写 `grep -E '(ab)+'` 正常。反向引用是分组独有的能力：`grep -E '(ab)\1'` 匹配 `abab` 与 `xxabab`，不匹配 `abx`——第二组必须和第一组内容一模一样，这是任何「通配」写法都表达不了的。

::: method 判定流程 · 结果不对劲时按顺序查
1. 输出比预期长、一次吃掉多个同类片段：贪婪在作怪，把 `.*` 换成 `[^分隔符]*`。
2. 用了 `+` `?` `|` `()` 却没生效：确认工具引擎是不是 BRE（回 0.6.1）。
3. 命中了不该命中的行：缺锚点，或 `.` 忘了转义。
4. 换机器结果不同：加 `LC_ALL=C` 再试，差异多半来自 locale。
5. 改完先跑三个输入：正常行、相邻双匹配行、不匹配行。三个都对才算写完。
:::

::: ex 例 0.6.2 · 从日志行里抠出 IP 和状态码
输入一行：`log 192.168.1.1 got 404 size 99`。先猜两条命令的输出：

```bash
printf 'log 192.168.1.1 got 404 size 99\n' > /tmp/ip.txt
grep -oE '[0-9]+' /tmp/ip.txt
grep -oE '([0-9]{1,3}\.){3}[0-9]{1,3}' /tmp/ip.txt
```

本机实测：第一条输出六行 `192 168 1 1 404 99`（每个数字串一行），第二条只输出一行 `192.168.1.1`。区别在分组：`([0-9]{1,3}\.){3}` 把「数字加点」捆成一项再重复三次，IP 才不会被散开的量词拆碎。但要注意这条模式的边界：`999.999.999.999` 同样通过——正则适合「筛」，不适合「校验」，0 到 255 的判断该交给程序。
:::

::: errata 常见错误清单
1. **「`.` 能匹配换行」**——这些工具默认逐行，`.` 不含换行；本机 `awk '/a.b/'` 对 `a`、`b` 两行不匹配。跨行用 sed 的 `N` 或 awk 的 `RS`。
2. **「`.*?` 到处都能当懒惰用」**——POSIX 引擎没有懒惰量词；本机 ERE 下 `<.*?>` 输出四段碎片。要么 `[^x]*`，要么 PCRE。
3. **「`[a-z]` 就是 26 个 ASCII 小写字母」**——区间含义随 locale 与引擎变；本机 `sort` 顺序随 locale 改变已实测，Ubuntu 实测 GNU grep 在 `en_US.UTF-8` 下 `[a-z]` 会把 `é` 这类重音字母算进来（`LC_ALL=C` 不算），但不会吃进大写 `B`；`[A-z]` 在 `en_US.UTF-8` 下直接报 Invalid range end。日志处理加 `LC_ALL=C`。
4. **「写一条严格 IPv4 正则就够了」**——`([0-9]{1,3}\.){3}[0-9]{1,3}` 不做 0–255 校验；严格校验换程序。
5. **「双引号包模式和单引号一样」**——bash 在双引号里仍会展开 `$` 与命令替换，模式默认用单引号，需要插值时才双引号并检查 `$`。
:::

### 0.6.2 小结

四件套各司其职：锚点定位置、字符类定成分、量词定次数、分组定整体；POSIX 的贪婪是承诺不是缺陷，可移植的对策是排除类而不是 `.*?`。如果只记住一件事，那就是：**先让模式在「正常、相邻双匹配、不匹配」三个输入上都对，再投产。**

::: method 即时自测 · 0.6.2
**Q1（记忆）** 四件套分别管什么？POSIX 对 `.*` 的默认策略是什么？

**Q2（辨析）** `grep -E '[0-9]{3}'` 与 `grep -E '^[0-9]{3}$'` 对文件 `223001`、`22203` 各命中几行？为什么？

**Q3（应用）** 提取一行里所有 `<i>...</i>` 标签内容，写一条可移植的 ERE（不许用 PCRE）。

**Q4（迁移）** 同事在 Ubuntu 上用 GNU grep 写的 `'[a-z]+'` 统计脚本，拿到别的 locale 的机器上结果变了。给出最小修复并说明原因。

## 0.6.3 grep：筛选与计数 {#sec-0.6.3}

这一节回答：怎样把 `grep` 当「筛子」用——常用选项各筛什么，退出码怎么拿来做脚本判定？

::: preview 先抓住一件事
`grep` 的模型只有一句：逐行匹配，命中就把整行送到 stdout。但它的退出码有三个档位——0 有匹配、1 无匹配、2 出错——这才是脚本里做判定的依据；只看「有没有输出」会漏掉错误。
:::

先看一组「先跑再看」。准备日志与两个配置：

```bash
printf 'ERROR disk full\nINFO ok\nERROR net down\nWARN slow\nerror lowercase\n' > /tmp/app.log
printf '[error] boom\nrun fast zzz\n' > /tmp/err.txt
mkdir -p /tmp/sub/other
printf 'listen 80\n'  > /tmp/sub/a.conf
printf 'listen 443\n' > /tmp/sub/other/b.conf
```

下面每条都是本机实测输出：

```bash
grep -c ERROR /tmp/app.log        # 2        命中行数
grep -n ERROR /tmp/app.log        # 1:ERROR disk full / 3:ERROR net down
grep -i -c error /tmp/app.log     # 3        忽略大小写后多了一行小写
grep -v ERROR /tmp/app.log        # 剩下三行  反向筛选
grep -F '[error]' /tmp/err.txt      # 固定串：只输出字面那行
grep -oE '[a-z]+ (full|down)' /tmp/app.log   # 只输出命中的片段
grep -n -B1 -A1 WARN /tmp/app.log # 命中行连同上下文
grep -rl --include='*.conf' listen /tmp/sub  # 两个 .conf 的路径
```

选项不用背全表，按「三问」记：问输入（搜文件还是管道，递归加 `-r`，限定文件用 `--include`），问匹配（固定串 `-F`、ERE `-E`、忽略大小写 `-i`、整词 `-w`、反向 `-v`），问输出（要行 `-n`，要片段 `-o`，要计数 `-c`，只要文件名 `-l`，反过来要「没有命中的文件名」是 `-L`）。`-A/-B/-C n` 给上下文，多段上下文之间用 `--` 分隔。

**退出码是脚本判定的一等公民。** 本机实测三个档位；同样三条命令在 Ubuntu 24.04（GNU grep 3.11）上依次得到 0、1、2（Ubuntu 实测）——这一对语义两侧一致：

| 退出码 | 含义 | 本机复现命令 |
|:--|:--|:--|
| 0 | 至少一行命中 | `grep -q ERROR /tmp/app.log` |
| 1 | 一行都没命中 | `grep -q NOTHING /tmp/app.log` |
| 2 | 出错：文件不存在、模式非法 | `grep -q ERROR /tmp/no_such` |

所以「存在性判断」写 `if grep -q 模式 文件; then ...`；但 1 和 2 是两回事——「配置里没有这行」和「配置文件根本没读到」应该走不同分支，后者要单独看 `$? -eq 2`。用 `[ $? -ne 0 ]` 一把抓，会把读不到文件当成「没有这行」，这是事故来源。

**先固定串，再正则。** 这是取舍，也是正确性纪律。搜字面 `[error]`，写 `grep '[error]' /tmp/err.txt` 会把 `run fast zzz` 也捞出来——方括号在正则里是字符类，这条模式的真实含义是「含 e、r、o 任一字母的行」；写 `grep -F '[error]'` 只输出那一行（本机实测）。`-F` 不启动正则引擎，逐字节比较，理论上总是更省；两边各实测一次同一条 5 百万行、261 MB 的合成日志、都加 `LC_ALL=C`：Ubuntu 上 `grep -F 'uuid-0000none'` real 0.081 s，等价写法 `grep -E 'uui[d][0-9]none'` real 0.140 s（Ubuntu 实测），差距清晰；macOS 上同样两条模式分别是 0.87 s 与 0.85 s（本机实测），BSD grep 里几乎看不出差别。所以别背「总是快多少倍」的数字：`-F` 的优势在 GNU 侧实测成立、在 BSD 侧实测不明显，但「能用 `-F` 就别用正则」依旧成立——它同时是最快与最不易错的选择。绝对速度上 GNU grep 比本机 BSD grep 快出一个量级，这属于工具实现的差距，比较只在同一台机器上做才有效。配合 `LC_ALL=C` 按字节处理，大日志上还能再省一截。

**和 `ripgrep`/`ag` 的边界。** 它们在搜大型代码库时有两个结构性优势：自动遵守 `.gitignore`、默认跳过二进制与隐藏文件；`grep` 要你自己拼 `--exclude-dir`。但它们不是 POSIX 工具、系统不预装：本机 `command -v ag` 无输出、`rg` 只来自某个工具的附带目录（不算系统自带）；本书那台 Ubuntu VM 上 `command -v rg` 给出 `/usr/bin/rg`、`ag` 没有（Ubuntu 实测）——那是 VM 准备者自己装的，rg 在 Ubuntu 软件仓库里、但不在最小安装里。写可移植脚本就留在 `grep`；天天在仓库里交互搜索，再考虑换。

::: method 判定流程 · 一条 grep 命令的三问
1. 输入是谁？单文件、多文件、目录（加 `-r`）还是管道？管道没有文件名前缀问题，文件多时留意 `-h`/`-H`。
2. 匹配是什么？有元字符歧义吗？纯字面串就 `-F`；需要区间、多选就 `-E`；别默认 `-P`。
3. 输出要什么？整行（默认）、片段（`-o`）、计数（`-c`，按行）、文件名（`-l`）、只要成败（`-q`）。选定后再决定要不要接 `sort`/`uniq`。
:::

::: ex 例 0.6.3 · 计数到底数的是谁
输入 `/tmp/cc.txt` 两行：`a a` 和 `b`。先猜两条命令的输出：

```bash
grep -c 'a' /tmp/cc.txt
grep -o 'a' /tmp/cc.txt | wc -l
```

本机实测：第一条是 1，第二条是 2。`-c` 数「命中行数」，同一行里两次 `a` 只算一行；要数「命中次数」，得 `-o` 把每个匹配拆成单独一行再 `wc -l`。写监控脚本时这两种口径混用，图表就会差一倍。
:::

::: errata 常见错误清单
1. **「`-c` 是命中次数」**——它是命中行数；次数要 `-o` 配 `wc -l`（本机实测 1 对 2）。
2. **「`$? -ne 0` 就是没匹配」**——退出码 2 是出错；不区分 1 和 2，脚本会把「文件没读到」当成「配置项不存在」。
3. **「搜 `[error]` 就写 `grep '[error]'`」**——方括号被当字符类；字面串用 `-F`。
4. **「`-l` 也能拿来统计文件数」**——`-l`/`-q` 找到第一个命中就停止读该文件，判定快，但配合 `-v` 语义完全不同（`-L` 才是「不含匹配的文件」）。
5. **「二进制文件搜不出来就是没匹配」**——默认输出 `Binary file ... matches` 一行摘要；要逐行处理用 `-a`（本机实测）。
:::

### 0.6.3 小结

`grep` 是筛子不是计算器：选项决定「筛什么、怎么筛、输出什么形状」，退出码 0/1/2 撑起脚本判定。如果只记住一件事，那就是：**字面串一律 `-F`，判定一律 `-q` 加三分支，计数先想清楚数的是行还是次数。**

::: method 即时自测 · 0.6.3
**Q1（记忆）** 退出码 0、1、2 分别代表什么？哪两个必须分开处理？

**Q2（辨析）** `grep -c ERROR log` 与 `grep -o ERROR log | wc -l` 什么时候不相等？

**Q3（应用）** 写三行脚本：判断 `/etc/ssh/sshd_config` 里是否存在 `PermitRootLogin yes`，并区分「不存在」与「文件读不到」两种失败。

**Q4（迁移）** 为什么可移植脚本里不用 `grep -r` 配 `--exclude-dir` 假装等价于 `rg`？给出你不换 `grep` 的两个理由。

::: sol 答案
**A1** 0 至少一行命中；1 无命中；2 出错（文件不存在、模式非法）。1 与 2 必须分开，否则错误被当成「没有」。
**A2** 当某一行里 `ERROR` 出现多次时：`-c` 记 1 行，`-o` 拆成多次。
**A3** `if grep -q '^PermitRootLogin yes' /etc/ssh/sshd_config; then echo allowed; elif [ $? -eq 1 ]; then echo denied-or-absent-line; else echo "cannot read config" >&2; exit 2; fi`。
**A4** 一是 `rg` 非 POSIX、系统不预装，CI 与精简镜像里没有；二是默认行为不同（遵守 `.gitignore`、跳过二进制），换成 `rg` 等于改了「搜哪些文件」的语义，结果差异不是性能而是范围。
:::
:::

## 0.6.4 sed：流编辑器的执行模型 {#sec-0.6.4}

这一节回答：为什么给 `sed` 一个空脚本它照样输出全文？`-n`、`p`、`d` 的组合到底谁在打印？

::: preview 先抓住一件事
`sed` 只有一个循环：读一行进**模式空间**（pattern space，暂存「当前这一行」的工作缓冲区），按脚本顺序执行命令，除非加了 `-n` 就把模式空间自动打印，然后丢弃、读下一行。本节的目标就是把这四个动作钉进你的手，`s///` 的细节都排在它后面。
:::

证明「默认每行都会打印」，用空脚本和一行脚本就够（输入 `/tmp/w1.txt`：`alpha`、`beta`、`gamma`）：

```bash
printf 'alpha\nbeta\ngamma\n' > /tmp/w1.txt
sed ''    /tmp/w1.txt     # 三条命令都没有，仍原样输出三行
sed -n '' /tmp/w1.txt     # 什么都没了
sed '2p'  /tmp/w1.txt     # beta 出现两次
sed '2d'  /tmp/w1.txt     # beta 消失，只剩 alpha gamma
sed -n '2p' /tmp/w1.txt   # beta 恰好一次
```

本机实测输出依次是：原样三行；空；`alpha beta beta gamma`；`alpha gamma`；`beta`。逐条对应循环的四步：空脚本什么都不改，自动打印照常；`-n` 关掉自动打印，`p` 不出现就全哑；`2p` 对第二行多打一次，自动打印没关，所以 `beta` 两次；`d` 直接丢弃模式空间并跳到下一轮，自动打印被跳过。

循环画出来是这样：

<pre class="layout">
输入流 ──► 读一行入模式空间（去行尾换行） ──► 地址命中的命令按顺序改写
                                                  │
              下一行 ◄── 清空 ◄── 自动打印(+换行) ◄┘   ← sed -n 关掉这一步
输出流 ◄──────────── 显式 p/d 也从这里进出
</pre>

看懂这张图，三个推论立刻成立：`sed` 默认不碰文件，改的是 stdout，落盘要靠 `-i` 或重定向；处理逐行进行，它天生是流水线；`q` 提前退出时当前行仍会被自动打印（本机 `sed 'q'` 只输出 `alpha` 一行），`-n q` 才是安静退出（本机 `sed -n '2p;2q'` 恰好一个 `beta`）。

**`s/模式/替换/flags` 是循环里最常用的改写命令。** 定界符不必是斜杠，替换路径用 `s|/old|/new|` 少一层转义（本机实测 `printf 'a/b/c\n' | sed 's|/b/|/B/|'` 输出 `a/B/c`）。flags 里要紧的四个：`g` 一行全换，不加只换第一个（`s/o/X/g` 把 `one two three` 变成 `Xne twX three`）；`p` 打印发生过替换的行，配 `-n` 就是「只输出改过的行」；`I` 忽略大小写（本机支持）；数字表示只替换第 n 次出现。替换串里 `&` 代表整个匹配，`\1` 到 `\9` 回看分组；想要字面 `&` 必须写 `\&`。本机对照：

```bash
printf '%s\n' '50% off' | sed 's/%/&/'     # 50% off   ：& 就是刚才的 %
printf '%s\n' '50% off' | sed 's/%/\&/'    # 50& off   ：\& 是字面与号
```

**地址决定「命令作用在哪些行」。** 最短的四种：行号 `2d`、最后一行 `$d`、正则 `/^#/d`（删注释行）、范围 `2,$p`。正则范围 `/re1/,/re2/` 从命中 `re1` 的行开始，到之后第一条命中 `re2` 的行结束（含该行）；结束后，下一条命中 `re1` 的行会再开一扇窗。用它截取 ini 文件的段落（本机实测）：

```bash
printf '[web]\nport=80\n[database]\nhost=localhost\nuser=app\n[cache]\nttl=60\n' > /tmp/app.ini
sed -n '/^\[database\]/,/^\[/p' /tmp/app.ini
```

输出四行，末尾混进下一段的头 `[cache]`——范围把结束行也包含在内；想只留段内行，要在范围内部再过滤一次（见本节自测第 3 题，实测输出三行）。取反地址 `/^#/!p` 表示「非注释行才执行」；`2~5` 这类步长地址是 GNU 扩展，Ubuntu 24.04 实测 `seq 6` 管道给 `sed -n '2~5p'` 恰好输出一个 `2`（第 2 行起、步长 5；改 `1~2p` 输出 `1`、`3`、`5`）。BSD 侧本机实测直接报错退出码 1（`invalid command code ~`），Ubuntu 自带的 busybox sed 1.36.1 也不认（`sed: unsupported command ~`，退出码 1，Ubuntu 实测）。脚本别依赖步长地址，除非你确认了 sed --version 是 GNU。

**`-i` 的原地编辑要先立纪律。** 本机是 BSD sed：`-i` 后面必须紧跟备份后缀，`printf '2024-10-17\n' > /tmp/editme.txt` 后执行 `sed -i.bak 's/2024/2025/' /tmp/editme.txt`，生成 `editme.txt.bak` 并改原文件（实测）；把 `-i` 裸用，它会把下一个参数 `s/a/b/` 当后缀吃掉、再把文件名当脚本，报出莫名其妙的 `invalid command code e`（实测）。GNU sed 侧现在 Ubuntu 24.04 实测：同样的准备，执行不带后缀的 `sed -i 's/2024/2025/' /tmp/editme.txt`，退出码 0，内容变成 `2025-10-17`，再用 `ls` 查看——只有文件本身，一个备份都不生成（Ubuntu 实测）。也就是说 `-i` 裸用在一侧是报错、在另一侧是「不留后路地直接改」，比报错更危险。所以跨平台的操作纪律只有一条：**任何 `-i` 前，先不带 `-i` 跑一遍看 stdout，再用 `-i.bak` 落盘，确认无误后才删 `.bak`。**

::: method 判定流程 · 改文件的三步纪律
1. 预览：`sed -E '脚本' 文件`，只看 stdout，确认行数与内容都对。
2. 落盘：`sed -i.bak -E '脚本' 文件`，保留备份；`diff 文件 文件.bak` 再确认一次。
3. 收尾：确认后删 `.bak`；要跨平台就 `-i` 分支处理，或改管道 `sed ... f > tmp && mv tmp f`。
:::

::: ex 例 0.6.4 · 交换日期字段
输入 `/tmp/dates2.txt` 两行：`2024-10-17`、`1999-01-01`。先猜输出：

```bash
printf '2024-10-17\n1999-01-01\n' > /tmp/dates2.txt
sed -E 's/^([0-9]{4})-([0-9]{2})-([0-9]{2})$/\3\/\2\/\1/' /tmp/dates2.txt
```

本机实测：`17/10/2024`、`01/01/1999`。三个分组 `\1` `\2` `\3` 被替换串倒置顺序；两个锚保证只动「整行就是日期」的行。再试 env 文件：`sed -E 's/^([A-Za-z_][A-Za-z0-9_]*)[[:space:]]*=[[:space:]]*(.*)$/export \1=\2/'` 把 `KEY_ONE = value1` 变成 `export KEY_ONE=value1`，`bad-line` 不匹配、原样通过（实测）。这就是 sed 的甜区：行内改写、格式互换；要跨行状态就换 awk。
:::

::: errata 常见错误清单
1. **「加了 `p` 就只输出命中行」**——不配 `-n` 时自动打印还在，`sed '2p'` 会双打第 2 行（实测）。
2. **「`sed` 会直接改文件」**——默认只改 stdout；文件变动是 `-i` 或重定向造成的。
3. **「替换串里的 `&` 是普通字符」**——`&` 代表整个匹配，字面与号要写 `\&`（实测 `s/%/&/` 等于没换）。
4. **「不写 `g` 就是全行替换」**——一行的第一个匹配换完就停（实测 `one two three` 只变一处）。
5. **「`-i` 的写法到处一样」**——本机 BSD sed 的 `-i` 必须带后缀；GNU 可选（Ubuntu 24.04 实测：不带后缀直接改、不生成任何备份）；跨平台脚本先探测再分支。
6. **「`1~2` 能用」**——GNU 扩展（Ubuntu 实测 `2~5` 可用）；本机 BSD sed 直接报错，busybox sed 也不认。
:::

### 0.6.4 小结

把循环背下来：读一行、改写、默认打印、丢弃。`-n` 关自动打印、`d` 跳过打印、`p` 额外打印，三者的一切组合都能从这四步推出来；`s///` 再长也只是「改写」那一步。如果只记住一件事，那就是：**先不带 `-i` 看输出，再谈原地编辑。**

::: method 即时自测 · 0.6.4

## 0.6.5 hold space：sed 的第二个缓冲区 {#sec-0.6.5}

这一节回答：sed 每轮循环就把当前行丢掉，它凭什么还能倒序输出整个文件？

::: preview 先抓住一件事
模式空间每轮结束就被清空，sed 默认是「逐行失忆」的。保持空间（hold space）是 sed 里唯一跨轮次存活的缓冲区，`h/H/g/G/x` 五条命令在它和模式空间之间搬运；但它至多能装下「整个文本」，复杂一点就超支——这一节同时划出 sed 的极限。
:::

`G` 的定义：把保持空间追加到模式空间、自带一个换行；而保持空间的初始值是**空**。跑一条最短的跨行现象：

```bash
printf 'A\nB\nC\n' > /tmp/abc.txt
sed 'G' /tmp/abc.txt
```

本机实测：每行后面多一个空行。多出来的换行，正是 `G` 把空保持空间垫出来的结果——两个缓冲区的状态就此可见。

| 命令 | 对两个缓冲区做什么 |
|:--|:--|
| `h` | 模式空间 复制到 保持空间（覆盖） |
| `H` | 模式空间 追加到 保持空间（前面带换行） |
| `g` | 保持空间 复制到 模式空间（覆盖） |
| `G` | 保持空间 追加到 模式空间（前面带换行） |
| `x` | 两者互换 |

最小验证「存进去、还能取回来」（四行文件，第 2 行是 `First Data Line`）：

```bash
printf 'Header Line\nFirst Data Line\nSecond Data Line\nEnd\n' > /tmp/hd.txt
sed -n '/First/ {
h
p
n
p
g
p
}' /tmp/hd.txt
```

本机实测输出三行：`First Data Line`、`Second Data Line`、再来一遍 `First Data Line`。`h` 把当前行存进保持空间，`n` 读下一行把它挤了出去，`g` 又取回来。**没有保持空间，sed 没有任何地方放「刚才那行」。**

### 0.6.5.1 三个经典输出

保持空间的招牌用法是倒序输出（逐步走一遍见例 0.6.5）：

```bash
sed -n '1!G;h;$p' /tmp/abc.txt
```

实测输出 `C`、`B`、`A`。机制一句话：`G` 把「累积的历史」垫到当前行下面，`h` 再把新版本存回保持空间，到 `$` 一次打印。

**把两行并成一行**用的是 `n`/`N`——不碰保持空间，而是往模式空间里塞第二行：

```bash
sed '$!N;s/\n/ /' /tmp/abc.txt      # 本机实测：A B 与 C 两行
```

`$!N` 是「不是最后一行才追加下一行」，`s/\n/ /` 把模式空间里的换行换成空格。输出第二行只剩 `C`：它没有下一行可并。

**去重相邻行**把 `N`、`P`、`D` 凑齐（输入 `/tmp/dup.txt` 为 `A A B B B C`）：

```bash
sed -n '$!N;/^\(.*\)\n\1$/!P; D' /tmp/dup.txt
```

本机实测输出 `A`、`B`、`C`。逐轮读：`N` 把两行叠进模式空间；`^\(.*\)\n\1$` 判断两行是否相同；不同则 `P` 只打印第一行；`D` 删去第一行并**回到脚本开头、不读新行**，剩下的第二行等着下一轮。单行、两行、`A A A` 三种输入也试过，输出分别是 `A`、`A B`、`A`（实测）。

第四种常见用法是用 `H` 把整个文件压成一行（本机 BSD sed 要求花括号换行书写）：

```bash
printf 'para one line1\npara one line2\n\npara two line1\n' > /tmp/p2.txt
sed -n '1h
1!H
${
g
s/\n/ /g
p
}' /tmp/p2.txt
```

输出一整行（实测；段间空行留下一个双空格）。保持空间里装的现在是**整个文件**——这类玩法把全文读进内存，大文件请换工具。

::: ex 例 0.6.5 · 逐步走一遍倒序
`sed -n '1!G;h;$p'`，输入 `/tmp/abc.txt`（`A`、`B`、`C`）。先猜输出，再看状态表（本机实测输出 `C`、`B`、`A`）：

| 轮次 | 进入时模式空间 | `1!G` 后 | `h` 后保持空间 | `$p` |
|:--|:--|:--|:--|:--|
| 第 1 行 A | A | （跳过） | A | 否 |
| 第 2 行 B | B | B，换行，A | B，换行，A | 否 |
| 第 3 行 C | C | C，换行，B，换行，A | C，换行，B，换行，A | 打印 |

读表一句话：`h` 之前 `G` 已经把「历史」垫在当前行下面，`h` 再把新版本存回去；历史每轮长一行，到 `$` 时正好是整个文件的倒序。

第 1 行为什么跳过 `G`？保持空间初始为空，执行它只会多垫一个换行；`1!G` 用取反地址特判初始态。
:::

::: method 判定流程 · 这活该不该留在 sed
1. 只改当前行、删行、按范围打印：留在 sed（0.6.4 的循环够用）。
2. 需要「和上一行比较」这类跨一行状态：`N`/`D`/保持空间还能做，脚本控制在一行内。
3. 需要累积全文（倒序、压段落）：sed 能做，但吃内存、难读懂，大文件直接换工具。
4. 需要计数、去重（不限相邻）、连接两个文件：这是「状态」而不是「缓冲区」，直接 awk（下一节）。
:::

::: errata 常见错误清单
1. **「`h` 会清空模式空间」**——它是复制，当前行还在原地；想换出来用 `x`。
2. **「`sed 'G'` 多出的空行是 bug」**——保持空间初始为空，`G` 追加的就是一个换行（实测）。
3. **「倒序 sed 适合大文件」**——保持空间随文件线性膨胀；系统里现成的 `tac` 才是正路。
4. **「`N` 在最后一行也安全」**——读到文件尾没有下一行时 GNU 与 BSD 行为不同，现已两侧实测：对 `A`、`B`、`C` 三行执行不带 `$!` 的 `sed 'N;s/\n/ /'`，GNU（Ubuntu 实测）输出 `A B` 和 `C`、退出码 0，最后一行仍被自动打印；BSD（本机实测）只输出 `A B`——`C` 被吞掉，退出码却仍是 0。加上 `$!N` 两侧行为一致，所以照旧用它。
5. **「hold space 就是 awk 的数组」**——它只有两格缓冲区，没有「按下标找任意一行」的能力，复杂度差一个量级。
:::

### 0.6.5 小结

保持空间补上了 sed「逐行失忆」的缺口：`h/H/g/G/x` 搬运，`n/N/P/D` 跨行，倒序、并段、去重都凑得出来——每个惯用法同时是警告：这里是 sed 的极限区。如果只记住一件事，那就是：**一旦发现自己要在两个缓冲区里推演三轮以上，停下，换 awk。**

::: method 即时自测 · 0.6.5
**Q1（记忆）** 写出五条搬运命令及各自的方向。

**Q2（辨析）** `sed 'G'` 输出的空行从哪来？`sed -n '1!G;h;$p'` 里 `1!G` 换成 `G` 会怎样？

**Q3（应用）** 用一行 sed 写出「相邻两行互换位置」的思路，并说明它为什么比倒序简单。

**Q4（迁移）** 相邻去重，用 `uniq` 给出更省心的写法（awk 的写法见 0.6.6）。

::: sol 答案
**A1** `h`：模式→保持（覆盖）；`H`：模式→保持（追加）；`g`：保持→模式（覆盖）；`G`：保持→模式（追加）；`x`：互换。
**A2** 来自把空的保持空间追加进模式空间（`G` 自带一个换行）。去掉 `1!` 后第 1 行的累积体末尾多一个换行，最终输出变成 `C`、`B`、`A` 再加一个尾随空行（本机 `od` 实测）。
**A3** `sed -n 'N;s/\(.*\)\n\(.*\)/\2\n\1/p'`：`N` 凑两行，分组交换顺序。只需一个模式空间装两行，不用维护随文件增长的状态。注意本机实测三行输入只输出 `B`、`A`——奇数行时落单的最后一行被吞掉，这正是它只能当玩具的原因。
**A4** `uniq /tmp/dup.txt` 直接得到 `A`、`B`、`C`（实测）——`uniq` 本来就只删相邻重复；要删「任意位置的重复」才需要 `sort | uniq` 或 awk 数组。

## 0.6.6 awk：记录、字段与报表 {#sec-0.6.6}

这一节回答：已经有 `sed` 了，为什么 `awk` 非要把一行切成「字段」再编程？

::: preview 先抓住一件事
`sed` 按行改写，`awk` 按字段编程。它把输入看成一条条**记录**（默认一行一条），记录再按分隔符切成**字段**：`$1` 到 `$NF`。配上变量（`NR`、`NF`）、数组和 `BEGIN`/`END`，「算」这件事才第一次有了趁手工具。
:::

先跑三个立刻有用的例子。输入 `/tmp/cols.txt` 三行（姓名加四个数字，我们关心第 1 列和第 5 列）：

```bash
printf 'alice 12 3.5 8 100\nbob 4 1.5 2 50\ncarol 7 2.0 9 25\n' > /tmp/cols.txt
printf 'dev\nops\ndev\ndev\nqa\n' > /tmp/roles.txt
awk '{s += $5} END {print s}' /tmp/cols.txt          # 175
awk '!seen[$1]++' /tmp/roles.txt                      # dev ops qa（去重保序）
awk 'BEGIN {OFS = "|"} {print $1, $5, $2}' /tmp/cols.txt
```

本机实测：第一条输出 `175`；第二条对 `dev ops dev dev qa` 五行输出 `dev`、`ops`、`qa`（首次出现顺序）；第三条把每行重排成 `alice|100|12` 这样的三列（实测）。三条共同点：谁都没数「第几个字符到哪」，用的全是 `$字段号`——这就是按字段编程省下来的东西。

**模型：`pattern { action }` 的循环。** awk 每读一条记录，依次问每条规则「模式命中吗」，命中就执行动作；`BEGIN` 块在读任何输入前跑一次，`END` 块在全部输入读完后跑一次。省略动作就默认打印整条记录，省略模式就表示每条记录都执行——所以 `awk '{s+=$5}'` 是「对每一行累加」，`awk '$9 ~ /^5/ {...}'` 只对状态码 5 字头的行执行。常用的内建变量只有这几个（全表在 0.6.13）：

| 变量 | 含义 | 默认值/备注 |
|:--|:--|:--|
| `FS` | 输入字段分隔符 | 空白，且压缩连续空白 |
| `OFS` | 输出字段分隔符 | 空格；只在打印「带逗号」时插入 |
| `NF` | 当前记录的字段数 | `$NF` 是最后一个字段 |
| `NR` | 已读记录总数 | 跨文件累计 |
| `FNR` | 当前文件的记录号 | 每个文件重新从 1 开始 |

两条容易忽略的规则，本机都验证过。其一：`print $1, $5` 里的逗号才会插入 `OFS`，`print $1 $5` 是直接拼接；并且一旦给某个字段赋值（如 `$2="X"`），`$0` 会按当前 `FS` 重建——`awk 'BEGIN{OFS="--"} {$2="X"; print}'` 对 `a b c` 输出 `a--X--c`。其二：字段自动转数值，`awk 'BEGIN{print "10"+1}'` 得 `11`；但比较规则有隐式转换，涉及编号时显式 `$3 + 0` 更稳。

先补一句「`!seen[$1]++` 为什么能去重」：`seen[$1]` 从未出现过时是未定义值，按 `0` 处理，`!0` 为真——没有动作的模式默认就是打印整行；后缀 `++` 随后把计数加一。同一列第二次出现时 `!1` 为假，跳过。一行 awk 就是一个「模式-动作」判断句。

**`awk`、`gawk`、`mawk` 是一个东西吗？** 不是。语言本身由 POSIX 定义；GNU 的 gawk 加了一堆扩展（`gensub`、`FPAT`、`IGNORECASE`、按序遍历数组），mawk 走精简求快路线。两台机器默认装的还不是同一款，先各自确认：本机 macOS 的 `ls -l $(command -v awk)` 指向 `/usr/bin/awk`，`awk --version` 输出 `awk version 20200816`，属 Kernighan 的 one true awk 系，`command -v gawk mawk` 均无输出；Ubuntu 24.04 的 `/usr/bin/awk` 经 `/etc/alternatives/awk` 指向 `/usr/bin/mawk`，`awk --version` 输出 `mawk 1.3.4 20240123`，`command -v gawk` 无输出——**gawk 在 Ubuntu 上也不预装**，要用得 `sudo apt install gawk`，本书没装，gawk 独有的写法在两台机器上都无法实测（Ubuntu 实测）。实测边界在哪？本机：`awk 'BEGIN{print gensub(/a/,"b","g","aaa")}'` 直接报 `calling undefined function gensub`（退出码 2）；`IGNORECASE` 存在但按空值处理。Ubuntu 的 mawk 侧（全部 Ubuntu 实测）：`gensub`、`asort`、`strtonum`、`and`、`or`、`xor` 一律报 `function ... never defined`（退出码 2）；`-i inplace` 报 `awk: not an option: -i`；`PROCINFO["sorted_in"]` 赋个值不报错，但纯属无效——键 3、1、2 设了 `@ind_num_asc` 再遍历仍是无序；`IGNORECASE=1` 后 `"ABC" ~ /abc/` 不匹配，它只是个普通变量；`nextfile` 更干脆，`syntax error at or near nextfile`。意外的反例是时间函数：`systime`、`strftime`、`mktime` 在 mawk 1.3.4 上都能跑（`mktime("2024 10 17 12 0 0")` 返回 `1729137600`）——「gawk 独有」的名录里混着几个 mawk 也实现的。POSIX 子集（`$n`、数组、`BEGIN`/`END`）两台机器行为一致：本节标「本机实测」的例子——求和 175、`!seen[$1]++` 去重、`OFS` 重建、`NR==FNR` 联表——在 Ubuntu 的 mawk 上逐一复现（Ubuntu 实测；`for (k in a)` 的「无序」则是各哈希各的无序）。写可移植脚本就只碰 POSIX 子集；引用 gawk 特性前想清楚目标机上装的是谁。

::: method 判定流程 · 这个活归谁
1. 只看「这一行长什么样、改成什么样」：sed（0.6.4）。
2. 要按第 N 列做加减、分组计数、记住见过什么：awk——数组和 `BEGIN`/`END` 就是为它准备的。
3. 字段里有引号、转义、内嵌换行（真 CSV/JSON）：都别硬扛，换 `python3 -c` 或 `mlr`。
:::

::: ex 例 0.6.6 · 用 NR==FNR 连接两张表
`/tmp/users.txt` 两行 `alice admin`、`bob dev`；`/tmp/orders.txt` 三行，含一条没主子的 `carl 7`。先猜输出：

```bash
printf 'alice admin\nbob dev\n' > /tmp/users.txt
printf 'alice 100\nbob 50\ncarl 7\n' > /tmp/orders.txt
awk 'NR == FNR {role[$1] = $2; next} {print $1, $2, role[$1]}' /tmp/users.txt /tmp/orders.txt
```

本机实测输出：`alice 100 admin`、`bob 50 dev`、`carl 7`（末尾带一个空字段分隔符）。关键在 `NR == FNR` 只在**第一个**文件成立：`NR` 跨文件累计、`FNR` 每个文件归零，两个计数器只在第一个文件里相等。于是第一轮把用户表装进数组，`next` 跳到下一条记录；处理订单表时按 `$1` 查表。`carl` 查不到，未定义的数组元素按空串打印——这既是便利也是坑：拼错表名不会报错，只会静默出空格。
:::

::: errata 常见错误清单
1. **「`for (k in sum)` 按插入顺序」**——关联数组遍历无序：本机对 alice/bob/carol 分组求和，实测输出顺序是 `carol`、`bob`、`alice`；Ubuntu 的 mawk 对 alice/bob 输出 `bob`、`alice`（Ubuntu 实测），各家哈希各乱各的。要排序就管道给 `sort`；设 `PROCINFO["sorted_in"]` 在 mawk 上不报错也不生效（Ubuntu 实测），只有装了 gawk 才是排序开关。
2. **「`print $1 $2` 和 `print $1, $2` 一样」**——逗号才插 `OFS`，不加就粘连。
3. **「`printf "%.2f"` 是十进制四舍五入」**——按二进制浮点舍入，本机实测 `1.005` 打成 `1.00`；金额用整数分。
4. **「`awk -F,` 能处理 CSV」**——字段内含逗号、引号、换行时列号全错位；`-F,` 只适合「字段里保证没有逗号」的数据。
5. **「gawk 教程里的写法到哪都行」**——`gensub` 在本机 awk 直接报未定义函数（实测退出码 2）；Ubuntu 24.04 默认 awk 是 mawk 1.3.4，同样报 `function gensub never defined`（Ubuntu 实测），gawk 得自己装。脚本先确认 `awk --version`。
:::

### 0.6.6 小结

awk 的三件套是「字段化 + 状态 + 收尾」：`$n`/`NF` 把行变成数据，数组把跨行状态变成可能，`END` 把累计变成报表。上一节 hold space 里那些憋屈的惯用法，在这里都是一行。如果只记住一件事，那就是：**要「算」就交给 awk，要「改」才想 sed；数据一旦带结构（CSV/JSON），awk 也到站。**

::: method 即时自测 · 0.6.6
**Q1（记忆）** `NR` 与 `FNR` 什么时候不相等？`NF` 是什么？

**Q2（辨析）** `awk '!seen[$0]++'` 与 `sort -u` 的去重结果有什么区别？

**Q3（应用）** 对 `200 301 200 500 200 404` 六个状态码（每行一个）统计每个码出现次数，输出一行一个「码 次数」。

**Q4（迁移）** 0.6.5 的「倒序输出」用 awk 数组怎么写？它比 sed 版好在哪？

::: sol 答案
**A1** 读第二个及以后文件时不相等（`NR` 继续累计，`FNR` 归零重数）。`NF` 是当前记录的字段数，`$NF` 即最后一个字段。
**A2** `!seen[$0]++` 保留首次出现的顺序、只删完全相同的整行；`sort -u` 会重排全文再合并，顺序和行号信息都丢了。
**A3** `awk '{c[$1]++} END {for (k in c) print k, c[k]}'`；输出顺序不保证，要按次数排就再接 `sort -nr`。
**A4** `awk '{a[NR] = $0} END {for (i = NR; i >= 1; i--) print a[i]}'`：数组按行号随机存取，不必像 sed 那样把历史压在一个缓冲区里推演；代价同样是全文进内存，但表达直观得多。
:::
:::

## 0.6.7 三者怎么选 {#sec-0.6.7}

这一节回答：同一个文本任务摆在面前，凭什么说这件该 `grep`、那件该 `sed`、另一件该 `awk`？

::: preview 先抓住一件事
三个工具的分界不在「谁会替换、谁会匹配」这些重叠功能上，而在各自看得见什么：`grep` 看得见一整行，`sed` 看得见一整行并且能改写它，`awk` 还看得见行里的字段，并且能跨行记住状态。先问「这件活要看得见什么」，选择自己就掉出来了。
:::

### 0.6.7.1 找、改、算：三问各自的判据

按「你要的输出长什么样」分三类，每类给能拍板的判据。

**找**：输出是若干整行或若干文件名，内容一个字不改。归 `grep`。代价：判定对象只能是整行，第几列它不知道。

**改**：输出行数与输入一致，只有部分行的内容变了，而且不需要记住上一行。归 `sed`。代价：没有跨行状态，0.6.5 那些憋出来的惯用法就是这句话的代价清单。

**算**：要计数、去重、分组、求和，要按第 N 个字段判定，要记住「刚才见过什么」。归 `awk`。代价：一旦给 `$0` 或某个字段赋值，整行就按当前 `FS`/`OFS` 重建，纯排版改写不如 `sed` 稳。

::: method 判定流程 · 三问按顺序问
1. 需不需要跨行记住东西？需要 → awk。不需要 → 下一问。
2. 需不需要改内容？需要 → sed。不需要 → grep。
3. 判定对象是整行还是第 N 列？是第 N 列 → 要么用 awk 的 `$N`，要么在 grep 的模式里把列位置翻译成结构锚；翻译不出来就退回第一问按 awk 做。
:::

第三问最容易混，下面那 864 行的差就是它造成的。

### 0.6.7.2 同一件活，三种写法

输入是 0.6.8 那份合成日志：200000 行、19 MB，`$9` 状态码、`$10` 字节数。Ubuntu 24.04 实测，时间取 `TIMEFORMAT=%R`；本机 BSD 侧跑的是同一份文件。

**活一：找出 4xx/5xx 的行。**

```bash
grep -E ' (4|5)[0-9]{2} ' access.log | wc -l      # 20950 行   0.018 s
sed -nE '/ (4|5)[0-9]{2} /p' access.log | wc -l   # 20950 行   0.035 s
awk '$9 >= 400 && $9 < 600' access.log | wc -l    # 20086 行   0.031 s
```

awk 那条少 864 行，不是谁算错：整行正则把响应字节数当成了状态码——`... 200 404 ...` 里 ` 404 ` 前后都是空格，照样命中。给模式补上结构锚，`grep -cE '" [45][0-9]{2} '` 输出 20086，与 awk 一致（Ubuntu 实测）。本机 BSD 侧三条依次是 20950、20950、20086，补锚后同样 20086。选 grep 的代价在这里现形：你得在模式里手工重建「第 9 列」。

**活二：把没注释的 `timeout = 30` 改成 `timeout=60`。**

```bash
sed -E '/^[[:space:]]*#/!s/^[[:space:]]*timeout[[:space:]]*=[[:space:]]*[0-9]+/timeout=60/' conf.ini
awk '/^[[:space:]]*#/ {print; next}
     /^[[:space:]]*timeout[[:space:]]*=/ {$0 = "timeout=60"} {print}' conf.ini
```

输入是 `# timeout=30`、`timeout=30`、`port=80`、`timeout = 30` 四行，两条命令的输出都是 `# timeout=30`、`timeout=60`、`port=80`、`timeout=60`（Ubuntu 与本机各跑一遍，一致）。`grep` 在这里只能做前半件：`grep -E '^[[:space:]]*timeout' conf.ini` 打印后两行，改不动任何东西。

为什么这件归 sed：`s///` 只替换命中的那一段，行里其余字节原样通过。awk 那条是对 `$0` 赋值，整行被重建，所以键名两侧的空格是被「抹平」掉的——如果保留原格式才是需求，awk 就得改用 `sub()` 而不是写 `$0`。

**活三：状态码分布。**

```bash
awk '{c[$9]++} END {for (k in c) printf "%6d  %s\n", c[k], k}' access.log | sort -nr
cut -d' ' -f9 access.log | sort | uniq -c | sort -nr
grep -oE ' [0-9]{3} ' access.log | sort | uniq -c | sort -nr
```

三条输出的分布一致：`163850 200`、`16064 301`、`10063 404`、`6046 403`、`2948 500`、`1029 503`（Ubuntu 实测）。sed 在这件活上直接出局——它没有跨行状态，计数没地方放。耗时两侧不一样：Ubuntu 上依次 0.033 s、0.065 s、0.293 s；本机 BSD 上依次 0.277 s、0.119 s、0.223 s（本机实测）。也就是说「awk 一定比管道组合省」在这台 Mac 上不成立。能站住的只有两条：按字段判定时 awk 只写一遍表达式；`grep -o` 那种「先把候选片段全打出来再排序计数」多出一整趟管道，两台机器上都最慢。


### 0.6.7.3 什么时候必须换 Python

不是「看着复杂就换」。下面四条里踩中任意一条就换，四条都没踩中就留在三件套里。

1. **数据带结构**：字段里可能出现引号、转义或内嵌换行（真 CSV、JSON、XML）。实测一张两列的表：`name,note` 加一行 `"Smith, John","x, y"`，`awk -F, '{print NF ": [" $2 "]"}'` 对第二行输出 `4: [ John"]`——本该 2 列的记录被切成 4 列，`$2` 拿到的是半个人名（Ubuntu 与本机一致）。同一份文件交给 `python3 -c` 的 `csv.reader`，输出 `2 'x, y'`。
2. **需要嵌套状态**：缩进层级、括号配对、块内条件依赖。判据是具体的：一旦你要为「现在处于第几层」维护一个变量，而这个变量的进出要靠成对符号互相匹配，正则加逐行循环已经表达不了。
3. **要的不只是「键到计数」**：Top-N 堆、区间合并、多键分组、日期对象比较。awk 只有拿字符串当下标的关联数组，没有排序容器，也没有日期类型。
4. **产物要给别的程序用**：需要异常、需要被 import、需要单元测试、需要结构化日志。shell 的 `$?` 只有三档，装不下这些语义。

反过来，两件活常被误判成「该换语言」，其实 awk 就够：两张表的联查（键唯一时用 `NR==FNR`，见例 0.6.6）和按小时聚合（0.6.8 现场跑）。换语言的真实成本不是代码行数，是依赖：目标机上有没有那个解释器、是哪个版本、能不能不带第三方包跑完。

::: ex 例 0.6.7 · 864 行的差从哪来
活一里 awk 比 grep 少 864 行。不要猜，把差集取出来看。先猜最后一条命令在打印什么：

```bash
grep -E ' (4|5)[0-9]{2} ' access.log > g.txt
awk '$9 >= 400 && $9 < 600' access.log > a.txt
sort g.txt a.txt a.txt | uniq -u > only_g.txt; wc -l < only_g.txt
awk '{print $9, $10}' only_g.txt | sort | uniq -c | head -5
```

::: sol 解答
`a.txt` 被喂给 `sort` 两次，所以「只在 g.txt 里」的行最终计数是 1，被 `uniq -u` 留下；「两边都有」的行计数是 3，被丢掉——这是取两文件差集的常见写法（`comm -23` 也能做，但要求文件已按同规则排序）。第三条输出 864。最后一条在 Ubuntu 实测输出 `6 200 400`、`6 200 401`、`1 200 402`、`3 200 404`、`7 200 405`：全是状态码 200、字节数正好落在 400 到 599 的行。

诊断的收获不是「哪个工具对」，而是这条顺序：结果不一致时，先把差集落成文件、再看差掉的那些行**长什么样**，判定对象的差异一眼就能读出来。把 grep 的模式补成 `'" [45][0-9]{2} '`，20950 变 20086，与 awk 一致（Ubuntu 与本机各验一遍）。
:::
:::

::: errata 常见错误清单（0.6.7 节）
1. **「grep 也能改文件」**——它没有任何改写输出的选项，`-o` 只是把命中的片段单独打印一行；改内容要么 sed 要么 awk。
2. **「sed 也能统计」**——模式空间每轮清空，它只有 0.6.5 那种「再开一个缓冲区」的写法，没有计数、也没有按键查找。
3. **「awk 一定比 grep+cut+sort 省」**——Ubuntu 上省（0.033 s 对 0.065 s），本机 BSD 上反过来（0.277 s 对 0.119 s），同一份文件实测。别把一台机器的数字当结论。
4. **「三个工具结果不一样，说明有一个坏了」**——先对齐判定对象（整行还是第 9 列），再比数字。
5. **「写不出正则才需要换语言」**——上面四条边界跟正则会不会写无关；等你被迫用正则去数括号层数时，已经晚了。
:::

### 0.6.7 小结

三问的顺序是「要不要跨行状态 → 要不要改内容 → 判定对象是整行还是第 N 列」，前两条定工具，第三条定成败：活一的 864 行差就是整行判定与字段判定混用造成的，两侧机器都能复现。换 Python 看四条硬边界，不看代码长度。如果只记住一件事，那就是：**先说清这个任务要「看得见」一整行、一行里的第几列、还是前面几行，工具选择跟着走。**

::: method 即时自测 · 0.6.7
**Q1（记忆）** 三问按什么顺序问？各对应哪个工具？awk 的代价是什么？

**Q2（辨析）** 活一里 grep 与 awk 差 864 行，为什么 sed 与 grep 反而一致？给出只改 grep 模式的修法。

**Q3（应用）** 「按小时统计请求数和总字节」归谁？为什么不是 sed？为什么不到换 Python 那条线？

**Q4（迁移）** 同事说「这段 awk 以后要加 Top 10，先改成 Python」。按本节的判据回答他改得对不对，并说明你反问的第一个问题。

::: sol 答案
**A1** 一、要不要跨行记住东西（要 → awk）；二、要不要改内容（要 → sed）；三、判定对象是整行还是第 N 列。awk 的代价是给 `$0` 或字段赋值后整行按 `FS`/`OFS` 重建，纯排版改写不如 sed 保真。
**A2** 因为 sed 和 grep 用的是同一把尺：都按整行找 ` 4xx/5xx `，所以一起多算那 864 行；awk 按第 9 列判，才是少的一个。修法是把列位置翻译成结构锚：`grep -E '" [45][0-9]{2} '`，实测 20086，与 awk 相同。
**A3** 归 awk：它要跨行累加计数与字节和，还要把结果按小时分组，这正是「记住见过什么」。不是 sed，因为 sed 没有跨行状态。不到换 Python 那条线，因为状态只是「小时 → 两个累加值」，一个关联数组装得下，既不需要嵌套层级也不需要排序容器。
**A4** 按边界三，Top-N 要的是「排序容器 + 只留前 N」，awk 只有字符串下标的关联数组，遍历顺序还不保证（0.6.6 实测各家哈希各乱各的）——所以这个理由成立，但只在真做 Top 10 之后成立。第一个反问：现在这一步的输入是什么、输出是什么、中间要记住什么？如果只要「计数」，先 awk 落地；把 Top 10 写成 awk 的 `for (k in c) print c[k], k` 再管道给 `sort -nr | head`，比提前换语言少一层依赖。
:::
:::

## 0.6.8 实战：日志统计与批量改名 {#sec-0.6.8}

这一节回答：一份 NCSA 访问日志怎么变成三张表，一个「把整个目录的 `.JPG` 改成 `.jpg`」的活怎么不毁掉别人的文件？

::: preview 先抓住一件事
两件活共用一条纪律：先造一份能复现的输入，再让每一步单独可验证，最后才允许它碰真数据。日志这条线你会看到 200000 行怎么在 0.1 秒内变成三张表；改名这条线你会看到朴素写法怎么静默地留下三个没改动的文件、又怎么覆盖掉一份唯一的内容。
:::

### 0.6.8.1 先把输入摆稳：一份合成日志

下面的数字全部来自现场跑的合成数据，不是任何真实站点的日志。生成器就是一条 awk，`srand` 定死种子，所以任何人重跑得到同一份文件：

```bash
mkdir -p /tmp/lab && cd /tmp/lab
awk 'BEGIN {
  srand(20241017)
  split("/index.html /api/v1/orders /api/v1/users /static/app.js /login /healthz /admin/config /images/logo.png", P, " ")
  split("192.168.1.10 10.0.0.23 172.16.4.9 203.0.113.77 198.51.100.5 192.0.2.14", H, " ")
  for (i = 1; i <= 200000; i++) {
    ip = H[int(rand()*6)+1]; hh = int(rand()*24); mm = int(rand()*60); ss = int(rand()*60)
    path = P[int(rand()*8)+1]; r = rand()
    st = (r<0.82) ? 200 : (r<0.90) ? 301 : (r<0.95) ? 404 : (r<0.98) ? 403 : (r<0.995) ? 500 : 503
    by = 200 + int(rand()*40000)
    printf "%s - - [17/Oct/2024:%02d:%02d:%02d +0800] \"GET %s HTTP/1.1\" %d %d \"-\" \"curl/8.5.0\"\n", \
           ip, hh, mm, ss, path, st, by
  }
}' > access.log
```

Ubuntu 实测：`time` 报 0.458 s，产出 200000 行、19 MB，第一行是

```text
198.51.100.5 - - [17/Oct/2024:13:51:16 +0800] "GET /admin/config HTTP/1.1" 200 14649 "-" "curl/8.5.0"
```

NCSA combined 格式（也叫 Apache combined 日志，指「公共日志格式再加 referer 和 UA 两段」）的字段位置是：`$1` 客户端 IP、`$7` 请求路径、`$9` 状态码、`$10` 响应字节数。时间戳那一串 `[17/Oct/2024:13:51:16 +0800]` 中间有空格，所以它占了两个字段，`$9` 之前的编号才会往后挪。

拿到日志的第一步不是统计，是数一遍字段：

```bash
awk '{print NF}' access.log | sort -u      # 本机与 Ubuntu 都只输出 12
```

`12` 恒定才说明「按字段号取值」这件事安全。这个 12 是靠 UA 里没空格换来的：我写的 UA 是 `"curl/8.5.0"`，真实日志里常见的是 `"Mozilla/5.0 (X11; Linux x86_64)"`，里面两个空格，`NF` 立刻不恒定、`$10` 之后全错位。所以字段号要先验证，再使用。

### 0.6.8.2 三张表

**表一：状态码分布。**

```bash
awk '{c[$9]++} END {for (k in c) printf "%6d  %s\n", c[k], k}' access.log | sort -nr
```

Ubuntu 实测输出，耗时 0.034 s：

```text
163850  200
 16064  301
 10063  404
  6046  403
  2948  500
  1029  503
```

数组 `c` 的下标是状态码字符串，`END` 块把累计倒出来，排序交给 `sort -nr`——awk 自己的遍历顺序不保证（0.6.6 实测过各家哈希各乱各的）。

**表二：Top URL。** 同一件活两种切法，差的是 fork 与排序趟数：

```bash
awk '{print $7}' access.log | sort | uniq -c | sort -nr | head -5
awk '{n[$7]++} END {for (p in n) printf "%6d  %s\n", n[p], p}' access.log | sort -nr | head -5
```

两条的名单和计数一致：`/static/app.js` 25460、`/images/logo.png` 25175、`/api/v1/users` 25121、`/healthz` 25002、`/login` 24949（Ubuntu 实测）。耗时第一条 0.095 s、第二条 0.032 s；本机 BSD 侧反过来，第一条 0.359 s、第二条 0.265 s（本机实测，同一份文件）。这台 Mac 上的 `sort` 快、one-true-awk 慢，所以「awk 一定省」这句话在这台机器上不成立，能说的只有：第二条少两趟进程。

**表三：按小时聚合请求数与字节数。**

```bash
awk '{split($4, a, ":"); h = a[2]; c[h]++; b[h] += $10}
     END {for (k in c) printf "%s %6d %12d\n", k, c[k], b[k]}' access.log | sort
```

`$4` 是 `[17/Oct/2024:13:51:16`，按冒号切开后 `a[2]` 才是小时。Ubuntu 实测耗时 0.080 s，前六行：

```text
00   8206    165368170
01   8217    165676420
02   8274    166166652
03   8430    170481230
04   8314    167341163
05   8234    165720645
```

本机 one-true-awk 对同一份文件的输出逐行一致（本机实测）。顺手把「哪几个小时最忙」排出来：`awk '{...} END {for (k in c) printf "%6d %12d %s\n", c[k], b[k], k}'` 再管道给 `sort -nr | head -3`，Ubuntu 与本机都给出 `8559 173418167 21`、`8557 173216011 08`、`8430 170481230 03`。另外 5xx 比例一条：`awk '$9 >= 500 {bad++} {all++} END {printf "5xx=%d total=%d rate=%.3f%%\n", bad, all, 100*bad/all}'` 实测 0.029 s，输出 `5xx=3977 total=200000 rate=1.988%`，两侧一致。

### 0.6.8.3 这条线上 mawk 与 one-true-awk 的差别

上面四条命令用到的东西全在 POSIX 子集里：`$n`、`NF`、`split`、关联数组、`for (k in a)`、`printf`、`srand`/`rand`。所以两台机器的每个数字都相同——这正是可移植子集的意义。

出界的地方有两处，都当场验过。其一，时间函数：本机 `awk 'BEGIN{print systime()}'` 报 `calling undefined function systime`；Ubuntu 的 mawk 1.3.4 上 `systime`、`strftime`、`mktime` 可用（0.6.6 实测）。要在日志里算「距今多少分钟」，跨平台别把这段写进 awk，让 `date` 算好再用 `-v` 传进来。其二，`PROCINFO["sorted_in"]`：两侧都不报错也都不生效（本机与 Ubuntu 实测），排序一律走 `sort`。纪律是一句话：**写日志统计只碰 POSIX 子集，动手前先 `awk --version` 认一下对面是谁。**


### 0.6.8.4 批量改名：朴素写法怎么坏

造四个名字，故意带空格和一个单引号——这是 0.3.7 里那条「文件名可以含除 `/` 和 NUL 之外任何字节」的日常版：

```bash
mkdir -p /tmp/lab/rename && cd /tmp/lab/rename
touch 'Photo 001.JPG' 'Photo 002.JPG' "my  trip'.JPG" 'normal.JPG'
```

最直觉的写法是让 shell 拼字符串、`sed` 出新名字：

```bash
for f in *.JPG; do
    new=$(echo $f | sed 's/\.JPG$/.jpg/')
    mv $f $new
done
```

Ubuntu 实测（bash 5.2.21）：三行报错 `mv: target '001.jpg': No such file or directory`、`mv: target '002.jpg': ...`、`mv: target "trip'.jpg": ...`，跑完只剩 `normal.jpg` 被改掉，三个带空格的名字原地不动——**而整个循环的退出码是 0**。本机 BSD 侧用 bash 5.3.20 跑同一份脚本，报的是 `mv: 001.jpg is not a directory`，退出码 1，同样有两个文件没改（本机实测）。

还有一层更隐蔽的：同样这几行在本机 zsh 里跑通了，四个文件全部改名、退出码 0（本机实测）。差别不在 `mv`，在 shell——zsh 默认不对未加引号的参数展开做词分割（word splitting，把展开结果按空白拆成多个参数的步骤），`$f` 保持成一个整体；bash 会拆，于是 `mv` 收到四个参数、把最后一段当目标目录。这就是「在我这儿好好的」的机制解释：**脚本的成败取决于 shell 是否词分割，而不是文件名碰巧长什么样。** 回指 [0.3.7](ch03.md#sec-0.3.7)。

### 0.6.8.5 正确写法：全程 NUL，先出清单

名字里的空格杀不死 NUL，因为文件名里不可能有 NUL。所以把分隔符从换行换成 NUL，整条链路就稳了：

```bash
find . -maxdepth 1 -type f -name '*.JPG' -print0 |
  xargs -0 -n1 bash -c 'printf "mv -- %q -> %q\n" "$0" "${0%.JPG}.jpg"'
```

Ubuntu 实测这条试运行输出：

```text
mv -- ./Photo\ 001.JPG -> ./Photo\ 001.jpg
mv -- ./normal.JPG -> ./normal.jpg
mv -- ./Photo\ 002.JPG -> ./Photo\ 002.jpg
mv -- ./my\ \ trip\'.JPG -> ./my\ \ trip\'.jpg
```

`-print0` 用 NUL 结尾、`xargs -0` 按 NUL 切（0.3.15），`%q` 把空格和引号显式转义出来，让你肉眼就能核对清单；`${0%.JPG}` 是 bash 的后缀删除，不必再叫一个 `sed` 进程。看清清单后把 `printf` 换成 `mv --` 就是真执行：

```bash
find . -maxdepth 1 -type f -name '*.JPG' -print0 |
  xargs -0 -n1 bash -c 'mv -- "$0" "${0%.JPG}.jpg"'
```

Ubuntu 与本机都四个文件全部改成功、退出码 0（实测）。不想用 `xargs` 的话，纯 bash 循环同样安全，因为循环变量始终带引号：

```bash
shopt -s nullglob
for f in *.JPG; do printf 'mv -- %q -> %q\n' "$f" "${f%.JPG}.jpg"; done
```

`nullglob` 那一条也不能省。Ubuntu 实测：目录里没有 `.JPG` 时，不设 `nullglob` 的循环执行了一次，`$f` 是字面量 `*.JPG`、`[ -e "$f" ]` 为 no，循环退出码仍是 0；设了 `nullglob` 之后循环次数为 0（本机实测一致）。少了这一步，后面的命令就会拿 `*.JPG` 当真实文件名去操作。

**还有一件试运行挡不住的事：目标已经存在。** 同一目录里同时有 `Photo.JPG`（内容 `NEW content`）和 `Photo.jpg`（内容 `OLD content, unique`）时，上面那条真执行会静默地把后者的唯一内容覆盖掉，Ubuntu 实测只剩一行 `Photo.jpg: NEW content`，退出码 0、一个警告都没有。加一道存在性检查就好：

```bash
find . -maxdepth 1 -type f -name '*.JPG' -print0 | xargs -0 -n1 bash -c \
  't="${0%.JPG}.jpg"; if [ -e "$t" ]; then printf "SKIP(目标已存在) %q -> %q\n" "$0" "$t"; else mv -n -- "$0" "$t"; fi'
```

实测输出 `SKIP(目标已存在) ./Photo.JPG -> ./Photo.jpg`，两个文件都还在。补一个本机侧的事实：本机的 APFS 卷不区分大小写，`Photo.JPG` 与 `Photo.jpg` 是同一个 inode（`ls -li` 实测两个名字同一个号），这台 Mac 上根本存不下两份内容，所以覆盖演示只能在 Ubuntu 侧做——而你的脚本迟早要跑在区分大小写的 ext4 上。

::: method 判定流程 · 改名四步纪律
1. 试运行：把 `mv` 换成 `printf 'mv -- %q -> %q\n'`，核对清单的行数和每一个目标名。
2. 查冲突：目标已存在的先跳过或加后缀；别指望 `mv` 提醒你，它覆盖成功时退出码是 0（Ubuntu 实测）。
3. 真执行：全程 NUL 分隔（`find -print0` 配 `xargs -0`，或 `while IFS= read -r -d ''`），`mv` 一律带 `--` 防止名字以 `-` 开头。
4. 复查：数一遍改名前后的文件总数，必须相等。
:::

有 `rename` 命令（Perl 的 `File::Rename` 那个包）时，第 1 步可以直接用它自带的试运行：`rename -n` 或 `rename -t`/`--trial` 打印清单不动文件。但本书这两台机器上 `command -v rename` 都没有输出（Ubuntu 与本机实测），装它又要动包管理，所以上面自己造试运行。顺带记一个易混点：`mv -t DIR` 是「指定目标目录」，跟试运行无关，别把它当预览开关。

::: ex 例 0.6.8 · 一个要三张表都要不到的问题
「5xx 最多的五个客户端是谁？」先猜输出，再跑：

```bash
awk '$9 >= 500 {c[$1]++} END {for (k in c) printf "%6d  %s\n", c[k], k}' access.log \
  | sort -nr | head -5
```

::: sol 解答
Ubuntu 实测输出五行：`693 10.0.0.23`、`673 192.168.1.10`、`672 203.0.113.77`、`658 172.16.4.9`、`649 192.0.2.14`；本机 one-true-awk 对同一份文件输出完全相同。

关键在于 `$9 >= 500 {c[$1]++}` 只有一对模式与动作：模式是「第 9 列不小于 500」，动作是「按第 1 列累加」。字段是数值，所以 `$9 >= 500` 会把它当数字比，`503` 与 `500` 都算，不必写成 `$9 ~ /^5/`。这两种写法在这份日志上结果相同（`awk '$9 ~ /^5/'` 也计到 3977），但在有 `999` 这类非法状态码的真实日志上不一样——`~ /^5/` 会把它排除，`>= 500` 会收进来。先想清楚你的口径是「数字区间」还是「首位是 5」。
:::
:::

::: errata 常见错误清单（0.6.8 节）
1. **「日志的字段号是固定的」**——`$9` 是状态码的前提是格式为 combined 且 UA 里没有空格。先跑 `awk '{print NF}' | sort -u`：本例恒为 12，真实 UA 一进来就不恒定了。
2. **「`for f in *.JPG` 没匹配时会报错」**——不会，通配符原样留着，循环执行一次、`$f` 就是字面量 `*.JPG`，退出码还是 0（Ubuntu 实测）。要么 `shopt -s nullglob`，要么 `[[ -e $f ]] || continue`。
3. **「朴素循环的问题在 `sed`」**——问题在 `$f` 没加引号被词分割；`sed` 那步只是把整串名字换了下标。同一脚本在 zsh 下「成功」，只是把 bug 藏起来了。
4. **「`-print0` 加了就安全」**——还要 `xargs -0`；`xargs` 默认按空白切，照样把 `Photo 001.JPG` 拆成两段。
5. **「mv 会提醒我覆盖」**——默认静默覆盖并返回 0（Ubuntu 实测）；`-n` 只在不带 `--force` 别名时管用，最稳的是自己先 `[ -e "$t" ]`。
6. **「awk 的时间函数哪台机器都有」**——本机报 calling undefined function，mawk 却支持（0.6.6 实测）；跨平台把时间换算交给 `date` 加 `-v`。
:::

### 0.6.8 小结

日志这条线是「先验证字段（`NF` 恒 12）→ 再统计（数组加 `END`）→ 排序交给 `sort`」；改名这条线是「先出清单 → 查目标冲突 → 全程 NUL → 事后复查」。两侧机器的每个统计数字都一致，因为只用了 POSIX 子集；不一致的地方全在引号、词分割和 inode 这些工具之外。如果只记住一件事，那就是：**批量操作的第一条命令必须是不写盘的预览，而预览和真执行之间隔着一道「目标已存在」的检查。**

::: method 即时自测 · 0.6.8
**Q1（记忆）** 拿到一份 combined 日志，统计之前先跑哪一条命令？它输出 12 说明什么？

**Q2（辨析）** 同一份脚本在 bash 下坏三行、在 zsh 下全对，为什么？两种 shell 都没改文件名规则。

**Q3（应用）** 写出「试运行 + 真执行」两条命令，把 `/srv/img` 下所有 `.PNG` 改成 `.png`，要求跳过目标已存在的情况。

**Q4（迁移）** 老板要「每天 5xx 比例」的日报，数据源是 200 个按小时轮转的日志。按 0.6.7 的三问回答该用哪个工具，并说清哪一步会让你必须换 Python。

::: sol 答案
**A1** `awk '{print NF}' access.log | sort -u`。只输出一个 `12`，说明每行都被切成 12 个字段，`$9`、`$10` 这些编号在全文一致，按字段号取值才安全；出现两个以上数字说明有行的空格数不同，字段号不能用。
**A2** 因为 zsh 默认不对未加引号的参数展开做词分割，`mv $f $new` 在 zsh 里仍是两个参数；bash 会按 `$IFS` 拆分，`Photo 001.JPG` 变成两个参数，`mv` 收到四个参数就把最后一段当目标目录。文件名规则两边一样，坏的是展开规则。
**A3** 试运行：`find /srv/img -type f -name '*.PNG' -print0 | xargs -0 -n1 bash -c 't="${0%.PNG}.png"; if [ -e "$t" ]; then printf "SKIP %q\n" "$0"; else printf "mv -- %q -> %q\n" "$0" "$t"; fi'`。真执行：把内层 `printf "mv --` 换成 `mv --`。核对行数一致后再动手。
**A4** 归 awk：要跨行累加、按「日期」分组，还要记住每个日期的两个数——三问第一问就命中。200 个文件一起喂给 awk 也没问题，`NR`/`FNR` 会自动区分文件（0.6.6）。必须换 Python 的那一步是「同时把访问日志和后端错误日志按 request id 关联」：两侧都不止一个键、还要保留双方全部列，这是多表 join 与数据结构，不是「键到计数」。
:::
:::

## 0.6.9 正则引擎：从最左最长到回溯 {#sec-0.6.9}

上一遍的 0.6.1 排清了「谁认识哪些元字符」，0.6.2 处理了贪婪 `.*` 怎么修。这一遍只看引擎层：同一条**合法**的模式交给不同的匹配策略，答案和耗时都能差出一个量级。

这一节回答：为什么 `(a+)+$` 在 `grep -E` 里是 0.001 秒、在 `awk`（本机是 mawk）里是 8 秒、在 `grep -P` 里是 0.01 秒加一个错误退出？

::: preview 先抓住一件事
POSIX 引擎承诺「最左最长」：同一出发地要把所有走得通的路径比完，取最长那条。Perl 系引擎承诺「最左优先」：按你写分支的先后顺序试，第一条走通就返回。实现跟着承诺走——前者把「此刻可能在哪些位置」打包同时推进，耗时跟文本长度成正比；后者逐条试、走不通就退回上一个岔口，耗时跟模式的**路径数**成正比。嵌套量词把路径数变成指数，本节那串数字就是这么来的。
:::

### 0.6.9.1 同一条模式，两种答案

先跑。输入一行 `aaab`，模式是两个分支：`a`，或者「至少两个 `a`」。

```bash
printf 'aaab\n' > /tmp/lab0c06_alt.txt
grep -oE 'a|a+a' /tmp/lab0c06_alt.txt   # ERE
grep -oP 'a|a+a' /tmp/lab0c06_alt.txt   # PCRE
```

Ubuntu 实测：第一条输出 `aaa`，第二条输出三行 `a`。ERE 把所有走得通的路径比完，`a+a` 能吃到三个 `a`，于是取最长；PCRE 从第一个分支 `a` 试起，一试就中，剩下两个 `a` 各自再从头来一遍。反方向的分支顺序同样改答案：`a|ab` 对 `ab`，ERE 给 `ab`、PCRE 给 `a`（Ubuntu 实测）。`awk` 在 POSIX 一侧，能直接把「最长」读出来：`awk 'match($0, /a|a+a/) {print RSTART, RLENGTH}'` 输出 `1 3`（Ubuntu 实测）。

本机 BSD 侧没有 `-P`（`invalid option`、退出码 2，本机实测，与 0.6.1 同一结论）。用 `/usr/bin/perl` 跑同一条模式代替：`aaab` 得到三行 `a`、`ab` 得到一行 `a`（本机实测），和 GNU 的 `-P` 一侧对齐。**分歧不在操作系统，在引擎。** 0.6.2 说的「POSIX 一律贪婪」是这条承诺的表层；这一节补它的代价：要「最长」就得比较所有路径，问题只在于怎么比较。

::: def 定义 0.6.9 · 最左最长与最左优先 {#def-0.6.9}
**最左最长**（leftmost-longest）：先在所有能匹配的位置里取最靠左的起点，同一起点下取跨度最长的匹配。**最左优先**（leftmost-first）：同样取最左起点，但同一起点下按分支先后与量词倾向取**第一条**成功路径。DFA（deterministic finite automaton，确定性有限自动机：把「此刻可能处于哪些位置」这个集合展开成一个状态来跑）能在一次线性扫描里给出最长匹配；**回溯**（backtracking）引擎逐个试分支，走不通就退回上一个岔口换一条。差别在失败时最要命：回溯引擎要说「不匹配」，必须把岔口全部试完。懒惰量词、环视、原子组这些构造只有 PCRE 有，POSIX 侧没有对应写法。
:::

### 0.6.9.2 灾难性回溯：把耗时量出来

`(a+)+` 对连续 n 个 `a` 有 2^(n-1) 种切分：外层 `+` 决定切几段，内层 `+` 决定每段多长。匹配**成功**时引擎拿到第一条通路就返回；**失败**时它必须把 2^(n-1) 种切分全试完，才有资格说「不匹配」。所以灾难的配方是两条：嵌套量词，加一个必定接不上的尾巴。下面的输入是 n 个 `a` 跟一个 `!`——`(a+)+` 能吃掉所有 `a`，可 `$` 怎么都接不上那个 `!`。

计时用 bash 内建 `time` 取 real（Ubuntu 24.04 的 bash 5.2 与本机 macOS 的 bash 5.3 同一套命令）。这台 VM 是共享机器，数字看量级别抠末位。

| 引擎（机器） | n=20 | n=22 | n=24 | n=26 | n=28 |
|:--|---:|---:|---:|---:|---:|
| GNU grep 3.11 `-E`（Ubuntu 实测） | 0.001 | 0.001 | 0.001 | 0.001 | 0.000 |
| GNU grep 3.11 `-P`（Ubuntu 实测） | 0.007 | 0.018 | 0.011 | 0.011 | 0.010 |
| mawk 1.3.4（Ubuntu 实测） | 0.032 | 0.136 | 0.513 | 2.101 | 8.363 |
| Python 3.12 `re`（Ubuntu 实测） | 0.044 | 0.150 | 0.585 | 2.724 | 9.563 |
| BSD grep 2.6.0 `-E`（本机实测） | 0.006 | 0.005 | 0.005 | 0.005 | 0.005 |
| one-true-awk 20200816（本机实测） | 0.011 | 0.011 | 0.012 | 0.011 | 未实测 |

单位是秒；BSD 侧的 sed 同样平坦，n=20 到 n=26 都在 0.004–0.005 秒（本机实测）。三件事要从这张表里读出来。

`-E` 与 BSD 三件套不吃亏：把可能位置并成一个集合往前推，文本读一遍就完，耗时跟行长线性，哪怕模式里全是嵌套量词。

mawk 每多两个 `a` 涨四倍，即每多一个字符翻一倍，这正是 2^(n-1) 的形状：n=28 已经 8 秒，按同一斜率外推 n=40 是几小时量级（未实测）。这一格最容易被读反——**「最左最长」是答案的承诺，不是耗时的承诺**，mawk 用回溯实现照样满足它，而 0.6.6 里你那台机器的 `awk` 正是这一款。

`grep -P` 那行最特殊：从 n=24 起退出码变成 2、报 `exceeded PCRE's backtracking limit`，耗时反而固定在 0.01 秒上下——行尾加长到 n=30、60、120、400，四次都是约 0.011 秒加同一句报错（Ubuntu 实测）。PCRE2 的 match limit 是一层熔断：不给你答案，也不让你把 CPU 跑满。

嵌套量词不一定写作 `(a+)+`，把 `a` 换成 `.*` 是同一个形状：`grep -P '(.*)*[^a!]'` 对 n=24 那一行退出码 2、报错同上，同一条模式交给 `grep -E` 正常返回退出码 1（Ubuntu 实测）。日志里最常见的怪物正是 `(\s|\w)*`、`(.*x)*` 这种「量词套量词」。

::: ex 例 0.6.9 · 一行输入让 grep -P 报错、让 awk 跑两秒 {#ex-0.6.9}
先猜再跑。输入是 26 个 `a` 加一个 `!`，模式 `(a+)+$`：

```bash
python3 -c "import sys;sys.stdout.write('a'*26 + '!\n')" > /tmp/lab0c06_bf.txt
TIMEFORMAT='%R real'
time grep -E '(a+)+$' /tmp/lab0c06_bf.txt   # 猜测：？
time grep -P '(a+)+$' /tmp/lab0c06_bf.txt   # 猜测：？
time awk   '/(a+)+$/' /tmp/lab0c06_bf.txt   # 猜测：？
```

Ubuntu 实测依次是 0.001 秒（无输出，退出码 1）、0.011 秒加超限报错（退出码 2）、2.101 秒（无输出，退出码 0）。三条的**结论**一致——这行不匹配——差别全在花掉的时间和一个报错。

把 `!` 去掉让模式真能匹配：同一行 30 个 `a` 喂给 `grep -P '(a+)+$'`，立刻输出那一行、退出码 0（Ubuntu 实测）。危险不在嵌套量词本身，而在**嵌套量词加匹配失败**这个组合：样例跑通一百条，只要没测过失败输入，你就不知道自己写了个定时器。
:::

### 0.6.9.3 改写、熔断，以及为什么应用层也要管

改写有三条路，按优先级排。**其一，问嵌套是不是多余的**：`(a+)+$` 想说的就是「一串 `a` 一直到行尾」，`a+$` 是同一个语言，Ubuntu 实测 0.001 秒。绝大多数嵌套量词属于这类——外层没增加任何表达能力，只是把同一段字符切了两遍。

**其二，真需要嵌套就把内层变成不可回退的整体**。原子组（atomic group，写作 `(?>...)`：一旦走出去就不许回头把内层的成果借给别人）和所有格量词（possessive quantifier，写作 `a++`：吃掉的不吐出来）直接砍掉「同一位置再试一种切法」这条分支：n=30 那一行喂给 `(a++)+$` 与 `(?>a+)+$`，都在 0.001 秒内返回、退出码 1（Ubuntu 实测）。两者都是 PCRE 独有。

**其三，换承诺**：要「线性加最长」就留在 `-E`、`sed`、`awk`，但 mawk 那一格已经说明 POSIX 不替你保证线性；要环视和懒惰量词才上 `-P`，并把「它可能以退出码 2 熔断」写进错误处理。GNU 侧 `-E` 之所以稳，实现注脚是用 DFA 做快速扫描、遇到反向引用这类 DFA 处理不了的构造才回退到带回溯的正则库（此句是实现说明，本书未单独实测回退路径）。选择顺序仍是 0.6.3 那条：`-F` → `-E` → 需要环视/懒惰才 `-P`。

还有一个变量影响的不是耗时而是「一格允许哪些字符」，就是 locale：`é` 在 `en_US.UTF-8` 下算进 `[a-z]`、`LC_ALL=C` 下不算（Ubuntu 实测，见 0.6.2）。本节的计时都在默认 locale 下取。

**「我只写应用层，为什么也要懂」。** 上表最贵的一格不是命令行，是 Python 3.12 的 `re`：n=26 花 2.724 秒、n=28 花 9.563 秒（Ubuntu 实测）；本机 macOS 的 Python 3.15 跑同一条模式是 0.069、0.193、0.722 秒（n=20/22/24，本机实测）。命令行里跑两秒你看得见、会按 Ctrl-C；服务里跑两秒，是别人发给你一个 30 字符的字段、你让出一个工作进程。这就是 ReDoS（正则表达式拒绝服务，regular expression denial of service）的形状：输入规模由别人决定，指数由你写。`grep -P` 至少有 match limit 兜底，多数语言的正则库连这层都没有。

::: errata 常见误解
1. **「POSIX 引擎用 DFA，不会指数爆炸」**——mawk 的 ERE 匹配对 n=28 花 8.363 秒（Ubuntu 实测）。标准管答案形状，不管耗时。
2. **「报 `exceeded PCRE's backtracking limit` 说明这台机器没 PCRE」**——恰恰相反，它证明有，而且熔断替你挡了一次；`invalid option -- P` 才是没编进来（0.6.1 两侧都实测过）。
3. **「样例全过了，模式就安全」**——回溯的成本来自**失败**输入，见例 0.6.9。每条正则至少配一个「必定不匹配」的用例。
4. **「加个超时就行」**——超时保住请求，保不住那个 CPU 核；熔断也不是到处都有。真正的修复是把嵌套量词写掉。
5. **「`.*` 只是慢一点」**——`(.*)*` 与 `(a+)+` 同形状：`grep -P '(.*)*[^a!]'` 同一行退出码 2、报同一句超限（Ubuntu 实测）。
:::

### 0.6.9 小结

承诺决定实现，实现决定成本：POSIX 要比出最长，PCRE 只要第一条；把可能位置并起来推进的引擎按文本长度收费，一条条试的引擎按路径数收费。mawk 的 8 秒、`grep -P` 的 0.011 秒熔断、Python 的 9.5 秒，都落在「嵌套量词加一个必定失败的尾巴」这条线上。如果只记住一件事，那就是：**别赌引擎善良——`(x+)+` 先问能不能写成 `x+`，失败输入一定要测。**

::: method 即时自测 · 0.6.9
**Q1（记忆）** 「最左最长」和「最左优先」各承诺什么？给出一条能看出差别的命令和两侧输出。

**Q2（辨析）** mawk 和 GNU `grep -E` 都在 POSIX 一侧，为什么一个爆一个不爆？

**Q3（应用）** 面对 `(a+)+$` 的三条对策是什么？哪两条不能写进可移植脚本？

**Q4（迁移）** 你的服务用 Python 校验用户输入，模式是 `(.*)*:`。给出排查步骤和两条修复，并说明哪条是根治。

::: sol 答案
**A1** 前者在同一起点取最长跨度，后者按分支顺序取第一条成功路径。`grep -oE 'a|a+a'` 对 `aaab` 输出 `aaa`，`grep -oP 'a|a+a'` 输出三行 `a`（Ubuntu 实测）。
**A2** 「最左最长」只约束**结果**：mawk 用回溯实现也能给出最长匹配，只是失败时要把 2^(n-1) 种切分试完；GNU grep 的 ERE 走 DFA，一次线性扫描。标准没规定实现，所以同一条方言在两台机器上耗时能差四个数量级。
**A3** 等价改写 `a+$`；内层不可回退 `(?>a+)+$` 或 `(a++)+$`；留在 `-E`/`awk` 并保证失败输入也测过。后两条是 PCRE 独有，`sed`、`awk`、`grep -E` 都不认。
**A4** 排查：造一条不含冒号的长输入实测耗时，若随长度成倍增长即命中。修复：`.*` 换成排除类 `[^:]*`（0.6.2 的可移植写法），或去掉外层 `(...)*`；再给输入设长度上限。上限只缩小指数，改写才是根治。
:::
:::

## 0.6.10 grep 的完整选项表与退出码 {#sec-0.6.10}

0.6.3 已经把「三问」和退出码 0/1/2 立起来了。这一遍不再讲模型，只做两件更细的事：把选项按四组摊全并标清两侧差异，把退出码写成脚本里真能用的判据。

这一节回答：这一长串选项里，哪些会改变**匹配集合**（换机器就可能变结果），哪些只改变**输出形状**（照抄安全）？`grep` 的 1 和 2 又怎么在脚本里分开接住？

::: preview 先抓住一件事
按「改动的是什么」分四组：匹配行为（选哪台引擎、怎么算命中）、筛选（哪些文件参与）、输出（打印成什么形状）、性能（什么时候能提前停）。判据很干脆：会改匹配集合的选项，两侧都要实测过才敢写进脚本；只改输出形状的，BSD 与 GNU 基本一致。上一节 `grep -P` 的超限报错也归在这里——它是退出码 2 的一个来源。
:::

### 0.6.10.1 匹配行为：这一组会改结果

| 选项 | 作用 | 边界（两侧实测口径） |
|:--|:--|:--|
| `-G` / `-E` / `-F` | BRE / ERE / 固定串 | 两侧都有（实测）；`-F` 的取舍见 0.6.10.5 |
| `-P` | PCRE | GNU 3.11 可用（Ubuntu 实测）；busybox 1.36.1 与 BSD 2.6.0 都报 `invalid option`、退出码 2（Ubuntu、本机实测） |
| `-i` | 忽略大小写 | 两侧都有；`-I` 是「跳过二进制」，别记混 |
| `-w` | 全词匹配 | 词边界是字母数字下划线；实测 `-ow error` 只给 `error`，同一行里的 `ERROR` 不算 |
| `-x` | 整行匹配 | 等价于把模式夹进 `^…$`；实测 `grep -xc aaa` 命中 1 行 |
| `-v` | 反向选择 | **配 `-o` 时两侧不同**：GNU 输出空，BSD 输出不匹配的整行（Ubuntu、本机实测） |
| `-e PATTERN` | 给一个模式，可重复 | 模式以 `-` 开头时必须用它；实测 `-e ERROR -e alpha` 计 2 行（两侧同） |
| `-f FILE` | 从文件读模式，一行一个 | **空行也是一个模式，且匹配一切**：含一个空行的模式文件对 6 行输入计 6（两侧同，实测） |
| `-m NUM` | 每文件命中 NUM 行后停 | 与 `-c` 同时用时计数被截断：实测 `-m1 -c ERROR` 得 1（两侧同） |

三条要记住的分歧。`-v` 配 `-o`：想取「不匹配的整行」就只写 `-v`。`-f` 的空行：脚本生成的模式列表里混进一个空行等于全表命中，`-c` 的结果会突然变成总行数——对模式文件先跑一次 `grep -c '^$'` 看看有没有空行。`-P`：它不只「有没有」的问题，还能以退出码 2 熔断（0.6.9），用了它就必须处理第三种结局。

### 0.6.10.2 筛选：哪些文件参与

| 选项 | 作用 | 边界（两侧实测口径） |
|:--|:--|:--|
| `-r` | 递归目录 | 只跟随**命令行上给出的**链接：把链接目录当起点给它会进去，递归途中遇到的链接子目录不进（Ubuntu 实测） |
| `-R` | 递归并跟随所有链接 | GNU 实测比 `-r` 多出一条 `link/c.conf`；本机 BSD 的 `-r` 与 `-R` 都只给真实目录那一条（本机实测） |
| `--include=GLOB` | 只搜名字匹配的文件 | 作用于 basename；两侧实测可用 |
| `--exclude=GLOB` | 排除文件 | 可重复；实测 `--exclude=c.conf` 把唯一命中排掉、退出码 1（两侧同） |
| `--exclude-dir=DIR` | 排除目录 | 搜代码库必备；实测两侧都生效 |
| `-l` / `-L` | 列出有 / 无匹配的文件 | 找到第一个命中就停止读该文件；`-l` 是判定不是统计 |
| `-H` / `-h` | 加 / 去文件名前缀 | 多文件默认带前缀；管道里没有前缀可加 |
| `-a` / `-I` | 二进制当文本 / 跳过二进制 | 默认只给一行 `Binary file ... matches` 摘要 |
| `-Z` / `--null` | 文件名后放 NUL | 配 `xargs -0`；实测两侧都能正确接力 |

`-r` 与 `-R` 的差别只在「递归途中遇到的符号链接跟不跟」：GNU 的 `-R` 会跟，实测同一棵目录树里多出一条 `link/c.conf`（Ubuntu 实测）。脚本默认用 `-r`，需要跟随链接时再显式换 `-R` 并限定起点。

### 0.6.10.3 输出：打印成什么形状

| 选项 | 作用 | 边界（两侧实测口径） |
|:--|:--|:--|
| `-n` | 带行号 | 从 1 开始；实测 `grep -n WARN` 得 `4:WARN slow`（两侧同） |
| `-b` | 带字节偏移 | 与 `-o` 组合定位每段命中：实测 `0:ERROR`、`24:ERROR`（两侧同） |
| `-o` | 只输出命中片段 | 每个命中一行；空匹配也输出空行 |
| `-c` | 计数**行** | 不是次数（0.6.3 实测 1 对 2）；多文件时逐文件给数，实测 `file1:1`、`file2:0` |
| `-A` / `-B` / `-C N` | 后 / 前 / 上下 N 行 | 不相连的两段上下文之间插一行 `--`（本机实测） |
| `--group-separator=SEP` | 换掉那个 `--` | **GNU 有、BSD 没有**：本机 `unrecognized option`、退出码 2（实测） |
| `-q` | 静默，只给退出码 | 找到即退出，可能让上游收到 `SIGPIPE`，见 0.6.10.4 |
| `-s` | 抑制错误消息 | **不改退出码**：实测文件不存在时仍退出 2（两侧同） |
| `--line-buffered` | 每行立刻吐出 | 影响输出不影响读；接实时下游才需要 |
| `--color=auto/always/never` | 高亮 | 实测 `--color=always` 两侧都往 stdout 写转义序列；管道里默认 `auto` 会自动关 |

这组选项两侧行为基本一致，可以放心照抄——它们不改匹配集合。例外是 `--group-separator`：GNU 侧接受这个选项（Ubuntu 实测命令正常返回），本机直接 `unrecognized option`、退出码 2（本机实测）。还有一处教训：BSD 的 usage 文本只列了七个长选项，可 `--include`、`--exclude`、`--exclude-dir` 在本机实测都可用——**usage 不能当能力清单用，能实测就实测。**

### 0.6.10.4 退出码：脚本里的一等公民

| 码 | 含义 | 实测复现（两侧同） |
|:--|:--|:--|
| 0 | 至少一行命中 | `grep -q ERROR 存在的文件` |
| 1 | 一行都没命中 | `grep -q NOPE 存在的文件` |
| 2 | 出错：文件读不到、模式非法、`-P` 不支持或熔断 | `grep -q ERROR 不存在的文件` |

三个档位在两台机器上都得 0/1/2（Ubuntu 实测、本机实测），这是少数 BSD 与 GNU 完全一致的语义，所以可以放心当判据。但「没命中」和「读不到」是两种世界：**配置里没有这行**说明功能被关掉了，**配置文件根本没读到**说明你的判定什么都没做。用 `[ $? -ne 0 ]` 一把抓，就把后者当成了前者。

三分支写法，先跑再看。输入是 6 行日志（含 `ERROR`）：

```bash
f=/tmp/lab0c06_g.txt
if grep -q ERROR "$f"; then echo hit
elif [ $? -eq 1 ]; then echo absent
else echo unreadable; fi
```

Ubuntu 实测：模式 `ERROR` 得 `hit`；换成 `NOPE` 得 `absent`；把 `$f` 换成不存在的文件得 `unreadable`（本机实测三条相同）。要注意 `elif [ $? -eq 1 ]` 里的 `$?` 靠的是「`if` 命令的状态还没被别的命令覆盖」这条约定——实测两侧都成立，但 `then` 与 `elif` 之间一旦插进任何命令就失效。更稳的写法是先存下来：`grep -q ERROR "$f"; rc=$?` 再 `case $rc in 0) …;; 1) …;; 2) …;; esac`。

「模式非法」也落在 2，而且要看引擎：`grep -cE '('` 在 GNU 报 `Unmatched ( or \(`、BSD 报 `parentheses not balanced`，两侧退出码都是 2（实测）；同一条括号交给 BRE 的 `grep '('` 却是合法的——`(` 在 BRE 里是普通字符，于是返回 1（0.6.1 的结论，两侧实测）。所以「看到 2 就当成文件问题」也不对，2 里面还混着「你的模式这台引擎不认」。

最后是 `-q` 的一个副作用：它找到第一个命中就退出，上游还在写时会被 `SIGPIPE` 打死。`set -o pipefail` 之下这条管道整体返回 141（`yes | grep -q y`，Ubuntu 与本机实测都是 141；不加 `pipefail` 时是 0，因为只看最后一个命令）。141 是 128+13，是**上游**的信号状态，不是 `grep` 出错——脚本里若对非零一律报错，就要在这一处放行。

::: def 定义 0.6.10 · grep 的退出码 {#def-0.6.10}
0 表示「至少一行命中」，1 表示「读完全部输入、没有命中」，2 表示「没能正常完成判定」——文件读不到、模式非法、`-P` 不可用或被 PCRE 熔断都归进 2。三者要分开接：0 是证据，1 是反证，2 是没有证据。管道里出现的 141、143 这类值是上游进程收到的信号（128+N），不属于这三个档位。
:::

### 0.6.10.5 性能：什么时候值得换 `-F`

| 手段 | 省下的是什么 | 实测口径 |
|:--|:--|:--|
| `-F` | 不启动正则引擎，只做定长比较 | 20 万行、约 7 MB、`LC_ALL=C`：Ubuntu `-F` 0.003 秒、`-E` 0.006 秒；本机 0.045 秒对 0.045 秒 |
| `LC_ALL=C` | 按字节比较，不做 collation | 0.6.3 的 0.081 秒对 0.140 秒就是在这一条件下取的（Ubuntu 实测） |
| `-m N` | 够数就停，后面的输入不再读 | 实测 `-m1 -c ERROR` 把 2 截成 1（两侧同） |
| `-q` / `-l` | 第一个命中即退出 | 判定场景首选；代价是上游可能吃 `SIGPIPE`（141） |
| `--exclude-dir`、限定起点 | 少读文件 | 递归撞上 `/proc`、`/sys` 会表现为卡住或 `No such device`（0.6.3） |
| 先粗筛再精算 | 把复杂正则只留给小数据 | `grep -F` 筛一遍再交给 `awk`，同 0.6.8 的实战路子 |

0.6.3 那次是 500 万行、261 MB 的合成日志（`LC_ALL=C`，Ubuntu：`-F` 0.081 秒对 `-E` 0.140 秒；本机同样两条模式 0.87 与 0.85 秒）；本次换到 20 万行再量一遍，得到上表左两列。两组数字合起来只说明一件事：**差别的来源不是常数**。`-F` 根本不启动正则引擎——不建自动机、不为每个起点维护「可能处于哪些位置」，只做「先按首字节跳、再定长比较」这一类文本查找；`-E` 每读到一个字符都要推进一遍状态集合（0.6.9 里正是这一侧的线性）。BSD 的 grep 给正则路径另做了一套快速通道，所以那一侧看不出 `-F` 的便宜。结论因此不是「`-F` 总是快几倍」，而是「`-F` 把引擎从关键路径上拿掉了」——它省的不只是时间，还有 0.6.2 那一类元字符误判。

::: ex 例 0.6.10 · 把四组选项串回一次真实判定 {#ex-0.6.10}
先猜：这四个选项里，哪一个会改变退出码、哪一个只改变输出？先写下判断，再看判定。

任务：确认某台机器的 sshd 配置允许 root 登录，并把「不允许」和「读不到配置」分开上报。

```bash
conf=/etc/ssh/sshd_config
grep -qsE '^[[:space:]]*PermitRootLogin[[:space:]]+yes' "$conf"; rc=$?
case $rc in
  0) echo 'allowed'     ;;
  1) echo 'not allowed' ;;
  2) echo 'cannot read config' >&2; exit 2 ;;
esac
```

逐行看清各选项在干什么：`-q` 属于输出组，只要退出码不要内容；`-s` 属于输出组，抑制「文件不存在」那行噪声，但**不改退出码**（实测仍是 2）；`-E` 与 `[[:space:]]` 属于匹配行为组，前者定引擎、后者跨 locale 稳定；`^[[:space:]]*` 挡住了缩进写法（0.6.2 的锚点）。把 `conf` 换成一个不存在的文件跑，本机与 Ubuntu 都上报 `cannot read config` 并以 2 退出（实测）——这就是 1 与 2 分开接的价值。
:::

::: errata 常见误解
1. **「`-c` 是命中次数」**——它数行；次数要 `-o` 接 `wc -l`（0.6.3 实测 1 对 2）。多文件时 `-c` 还会逐文件给数，不是一个总数。
2. **「非零就是没匹配」**——2 里混着「文件读不到」和「这台引擎不认你的模式」；`if grep -q` 之后一律报「配置项不存在」的脚本，会在配置文件路径写错时自信地给出错误结论。
3. **「`-s` 表示静默所以无所谓」**——`-s` 只压错误消息，`-q` 才只留退出码；实测两者同时用仍能区分 1 和 2（两侧同）。
4. **「`--include`、`--group-separator` 这类长选项到处都有」**——BSD grep 的长选项只有七个左右，`--group-separator` 直接报 unrecognized option（本机实测）；可移植脚本里长选项要先 `grep --help` 确认。
5. **「`-F` 只是快一点」**——它换掉的是实现路径（不启动引擎），同时消灭了元字符误判；`grep '[error]'` 与 `grep -F '[error]'` 的差是正确性，不是性能（0.6.3 实测）。
:::

### 0.6.10 小结

四组选项按「改的是什么」记：匹配行为和筛选范围会改匹配集合，两侧必须实测；输出形状只改外观，照抄安全；性能组的答案很朴素——字面串用 `-F`、判定用 `-q`、限定范围再递归。退出码那三个档位是本节真正要装进手里的东西：0 是证据，1 是反证，2 是没有证据。如果只记住一件事，那就是：**先把 1 和 2 分开接，再谈你的脚本读不读得懂配置。**

::: method 即时自测 · 0.6.10
**Q1（记忆）** 0、1、2 各代表什么？哪两类原因都会落到 2？

**Q2（辨析）** `grep -ovE 'ERROR' f` 为什么在 GNU 上什么都没输出、在本机 BSD 上输出了不匹配的整行？这算 bug 吗？

**Q3（应用）** 一行命令列出 `/etc` 下所有含 `listen` 的 `.conf` 文件，并说明哪个选项负责范围、哪个负责输出形状。

**Q4（迁移）** 你的 CI 里 `set -o pipefail` 之后 `producer | grep -q READY` 让流水线以 141 失败。给出两种处理并说明为什么不该把 141 当成 `grep` 的错。

::: sol 答案
**A1** 0 至少一行命中、1 全部读完没命中、2 没能正常完成判定。2 的两类常见原因是输入读不到（文件不存在、不可读）和模式不被该引擎接受（非法正则、`-P` 不存在或超限熔断）。
**A2** 不算，两侧各自一致，只是组合语义不同。对两行输入 `abc`、`xyz`：GNU 实测 `grep -ov b` 输出**空**（两个变体都是空），BSD 实测输出 `xyz`、也就是被 `-v` 选中的整行——等于它在 `-v` 时忽略了 `-o` 的「只输出片段」。所以要「取不匹配的整行」就只写 `-v`，别指望 `-o` 参与。
**A3** `grep -rl --include='*.conf' listen /etc`。`-r` 与 `--include` 负责范围（筛选组），`-l` 负责输出形状（输出组），`-r` 用 `-r` 而不是 `-R` 是为了不跟随递归途中的符号链接（GNU 实测两者差一条结果）。
**A4** 一是判定改用退出码而不是管道：先 `grep -q READY < <(producer)` 或直接给 `producer` 加超时；二是在这一处局部关掉 pipefail，或把 141 明确放行（`rc=$?; [ $rc -eq 0 ] || [ $rc -eq 141 ]`）。141 是上游被 `SIGPIPE`（13）打死的记账，`grep` 自己返回的是 0——它已经找到了 READY。
:::
:::

## 0.6.11 sed 的执行模型与命令全表 {#sec-0.6.11}

0.6.4 已经把循环四步、`s///`、四种最短地址和 `-i` 的纪律立起来了。这一遍不再讲模型，只补两件事：把命令摊成一张全表，并把每个 GNU 扩展在本机 BSD 上实测一遍——看清楚它是**报错**还是**静默给你另一个结果**。

这一节回答：sed 的一轮循环里能站上哪些命令，以及你写的这一条在 BSD 上会怎样？

::: preview 先抓住一件事
sed 只有那一圈循环，其余全是挂在四个位置上的命令：改写模式空间（`s`、`y`、`a/i/c`）、决定打印与否（`p`、`P`、`d`、`D`、`=`、`l`、`q`/`Q`）、跨行与搬运（`n`/`N`、`h/H/g/G/x`、`r`/`w`）、控制流（`:`、`b`、`t`、`T`、`{}`）。这张表真正要读的是最后一列：GNU 4.9 认的 `-z`、`Q`、`F`、`z`、`R`、`W`、`a` 的一行写法、`s` 的 `e`/`M` 标志、`0,/re/`、`1~2`、`,+N`，在本机 BSD 上有的是当场报错，有的静默给出不同输出——**静默那一类才是事故来源**。
:::

### 0.6.11.1 命令行选项：先确认可用面

循环是 `读入 → 改写 → 打印 → 丢弃`（0.6.4 的四步）。脚本之外还有一层进程启动时的选项，实测对照如下。

| 选项 | 作用 | GNU 4.9 / BSD 实测反应 |
|:--|:--|:--|
| `-n` | 关掉自动打印 | 两侧一致，`sed -n -E 's/a/A/;p'` 只出被改写过又显式 `p` 的行 |
| `-e SCRIPT` | 给一段脚本，可重复 | 两侧一致；两段脚本按给出顺序拼成一个脚本 |
| `-f FILE` | 从文件读脚本 | 两侧一致。**BSD 上想写标签、花括号块、`a\` 多行文本，就靠它**（下文有实测） |
| `-E` | 用 ERE | 两侧都有；GNU 另有同义的 `-r`，本机 `-r` 也认（实测） |
| `-i[SUFFIX]` | 原地编辑 | GNU 可裸用且不留备份；BSD 必须紧跟后缀（0.6.4 实测）。同一条 `sed -i '' x`：GNU 把 `''` 当脚本、`x` 当文件，实测报 `can't read x`、退出码 2；BSD 把 `''` 当空后缀、`x` 当脚本，于是从标准输入读，实测报 `-i may not be used with stdin` |
| `-z` | 用 NUL 当行分隔符 | GNU 有（实测 `a\0b` 被当成一行处理）；BSD 报 `illegal option -- z` |
| `-s` | 各输入文件独立处理，不连成一条流 | GNU 有（实测 rc=0）；BSD 报 `illegal option -- s` |
| `-u` | 输出不缓冲 | 两侧都认（实测） |
| `--follow-symlinks`、`--sandbox`、`--posix` | GNU 的额外开关 | GNU 实测 rc=0；BSD 一律 `illegal option -- -` |
| `-l` | GNU 是缓冲区大小（`-l N`）；BSD 是另一个含义 | 实测 BSD `sed -l 10 's/a/A/'` 把 `10` 当脚本、报 `command expected`——同一个字母两侧不兼容 |

这十条里只有前四条是两台机器都能直接抄的。`-i`、`-z`、`-s`、`-l` 和长选项这一组在跨平台脚本里要先探测（`sed --version` 有输出即 GNU），或者干脆绕开：落盘改用管道 `sed ... f > tmp && mv tmp f`，NUL 分隔的数据交给 `tr` 或 `awk`。

### 0.6.11.2 地址：谁说了算

| 地址 | 例子 | 含义与两侧实测 |
|:--|:--|:--|
| 行号 | `3d` | 第 3 行；两侧一致 |
| 末行 | `$d` | 最后一行；两侧一致 |
| 正则 | `/^#/d` | 命中的行；两侧一致 |
| 换分隔符 | `\#^/etc#d` | 模式里含 `/` 时改用 `#` 夹住；两侧一致（实测同样有效） |
| 行号范围 | `2,5p` | 第 2 到 5 行；两侧一致 |
| 正则范围 | `/BEGIN/,/END/p` | 从命中 `BEGIN` 的行到**之后**第一条命中 `END` 的行；两侧一致 |
| 取反 | `/^#/!p` | 非注释行才执行；两侧一致 |
| 命令组 | `1,10{/foo/d}` | 范围内再筛一次。**GNU 一行写得完；BSD 要求块内命令各占一行、`}` 顶格**，否则报 `extra characters at the end of p command`（本机实测） |
| 步长 | `1~2p` | 第 1 行起、每两行一次。GNU 实测输出三行；BSD 报 `invalid command code ~`（本机实测，0.6.4 也测过 `2~5`） |
| 从 0 起 | `0,/re/p` | 从第一行到第一次命中。GNU 实测输出前 3 行；**BSD 不报错却一行都不输出**（本机实测） |
| 相对范围 | `/re/,+1p` | 命中行及其后一行。同一份五行输入，GNU 实测输出 3 行、BSD 输出 2 行，两边都不报错 |
| 到下一个倍数 | `/re/,~5p` | 到下一个 5 的倍数行。GNU 实测可用；BSD 报 `expected context address` |

范围的两条规则两侧一样：结束地址从**下一行**才开始判定，所以 `/re/,/re/p` 永远圈不住单独一行；结束模式从头到尾没命中，范围就一直开到文件尾。`0,/re/` 解决的是一件小事——第一次命中正好落在第一行。

最后四行才是本节的重点：**同一个地址写法在 BSD 上可能不报错、却少给你几行**。这种静默差异只能靠换台机器把输出行数 diff 一遍来发现，报错反倒不用担心。跨平台的 sed 脚本因此要守住 POSIX 那半张表：行号、`$`、正则、`!`、范围、`{}`（且用 `-f` 写多行）。

| `y/abc/xyz/` | 逐字符映射，长度必须相同 | 一致（实测 `alpha` → `xlphx`） |

| `d` / `D` | 删除并跳下一轮 / 删到第一个换行并从脚本开头重来 | 一致；`D` 不读新行（0.6.5 实测） |
| `n` / `N` | 打印当前行并读下一行顶替 / 把下一行追加进来 | `N` 在最后一行两侧不同（0.6.5 实测：GNU 打印当前行，BSD 吞掉仍返回 0） |
| `a\文本` / `i\文本` / `c\文本` | 行后追加 / 行前插入 / 整行替换 | POSIX 写法（反斜杠加换行）两侧都认；**一行式 `1a hello` 只有 GNU 认**，BSD 报 `command a expects \ followed by text`（本机实测）。GNU 的一行式还会**吃掉本行余下的全部内容**：实测 `sed -n '1a hi;2p'` 输出的那行插入文本是 `hi;2p`，后面的命令全被当字符串 |
| `r FILE` / `R FILE` | 把整个文件追加进输出 / 每轮只追加一行 | `r` 一致；`R` 是 GNU 扩展，BSD 报 `invalid command code R` |
| `w FILE` / `W FILE` | 写出模式空间 / 只写到第一个换行 | `w` 两侧都有；`W` 是 GNU 扩展。**两者的文件名会吃掉本行余下的内容**：实测 `1w f;2w f` 被当成一个怪文件名并报错 |

| 命令 | 做什么 | 两侧实测差异 |
|:--|:--|:--|
| `=` | 打印当前行号 | 一致；GNU 还能配范围（实测 `2,4=` 出 `2`、`3`、`4`），BSD 报 `command = expects up to 1 address(es)` |
| `l` | 以可见形式打印不可见字符（行尾 `$`、`\t`） | 一致（实测 `alpha$`）；GNU 可带长度参数 |
| `q [退出码]` | 立刻退出，当前行仍会自动打印 | 一致的部分是 `q`；**带退出码的 `1q 7` 只有 GNU 认**（实测 rc=7），BSD 报 `extra characters at the end of q command` |

### 0.6.11.4 `s` 的 flags：一条一条实测

替换串里 `&` 代表整个匹配、`\1`…`\9` 回看分组，两侧一致；分隔符可以换成 `|` 或 `#`（0.6.4 实测）；数字表示只换第 n 次出现，两侧一致（实测 `s/a/A/2` 只动第二个 `a`）。flags 的可用面差异最大，实测下来是这样：

- **两侧都认**：`g`（全行）、`p`（改过就打印）、`i`/`I`（忽略大小写）、数字、`w FILE`。
- **只有 GNU 认**：`e`——把替换结果当命令执行，实测 `s/alpha/echo hi/e` 真的打印出 `hi`；`M`——让 `^` 与 `$` 在模式空间内部的换行处生效。BSD 对这两个一律报 `bad flag in substitute command`。
- **GNU 4.9 也不认**：`n`、`s`、`x`、`E` 四个都报 `unknown option to \`s'`（实测）。别照某些手册写 `s///s`，那台 GNU 上就跑不通。

`\L`、`\U`、`\E` 是第三个层次：它们不报错，但只有 GNU 生效。同一条 `s/(beta)/\U\1/` 实测 GNU 输出 `BETA`、BSD 输出 `Ubeta`——反斜杠被吃掉、`U` 当字面字符留下。**这类「两侧都不报错、结果不同」的构造最危险**，`sed -i` 之前一定要 `diff`。

`e` 值得单独一句警告：它等于给 sed 开了一个 shell。脚本里只要有一处 `s/.../.../e`，你就要保证替换串里不含任何外部输入——否则一行日志就能变成一条命令。

### 0.6.11.5 原地编辑还是那一套纪律

`-i` 是原地编辑。GNU 的 `-i.bak` 先写临时文件再 `rename`，原文件的 inode 会变（想保住符号链接要用 `-i --follow-symlinks`，GNU 实测接受这个长选项）；BSD 的 `-i` 必须紧跟后缀，写成 `-i ''` 才是「不备份」。`sed -i` 会尽量保留 mode/owner，但**硬链接会断**：另一个名字仍指向旧 inode。这不是推测——同一实验在两台机器都实测过：Ubuntu 的 GNU sed 与 macOS 的 BSD sed（`-i.bak`）都把 inode 换号、硬链接数从 2 降到 1、`.bak` 与旧 inode 的内容不变（见 0.6.16 实验二）。需要保留硬链接时，改写临时文件再 `cat` 回原文件，或者接受断链。

::: def 定义 0.6.11 · POSIX 子集与 GNU 扩展 {#def-0.6.11}
把 sed 的写法分成三档：**POSIX 子集**——本节两张表里标「一致」的那些命令与地址，加上反斜杠换行式的 `a\`/`i\`/`c\`，多行脚本用 `-f` 或真实换行；**GNU 扩展**——`-z`、`-s`、`R`、`W`、`Q`、`z`、`F`、`q` 的退出码、`0,/re/`、`1~N`、`,+N`、`,~N`、`s` 的 `e`/`M`、`\L`/`\U`/`\E`、一行式 `a`；**静默分歧**——同一写法两侧都接受但结果不同（`\U`、`0,/re/`、`,+N`、`N` 在末行）。跨平台脚本只在第一档里写；第二档用来写只跑 Linux 的运维脚本，并且先 `sed --version` 探测；第三档一律不用。
:::

::: ex 例 0.6.11 · 一段「在 Linux 上没事」的脚本 {#ex-0.6.11}
下面四条在 Ubuntu 上都按预期工作，原样拿到 macOS 的 CI 里就有两条响、两条哑。先猜每条的结局，再对照实测（输入是 `name: old`、`versions:`、两行缩进、`foo: x`）。

```bash
sed -i 's/^name: .*/name: \U&/' f.yml     # 1 原地改并把值转大写
sed -n '0,/versions/p' f.yml              # 2 打到第一次命中
sed -e '1a hello' -e '$p' f.yml           # 3 首行后插一行
sed -n '/^versions/,+2p' f.yml            # 4 命中行及其后两行
```

Ubuntu 实测：1 退出码 0，文件变成 `name: NAME: OLD`；2 输出到 `versions:` 那行为止；3 在首行后插入 `hello`；4 输出三行。本机 BSD 实测：1 的 `-i` 把整段脚本当成了备份后缀、把文件名当成了脚本，于是报出一条与正则毫无关系的错误 `extra characters at the end of l command`（0.6.4 记过同型报错）；2 退出码 0、**一行都不输出**；3 报 `command a expects \ followed by text`；4 这一份输入恰好也出三行——但换 0.6.11.2 那份五行输入实测 GNU 三行、BSD 两行，同样不报错。

也就是说：`-i` 和 `a` 的缺项会自己喊出来，`0,/re/`、`,+N`、`\U` 不会。**改法是退回 POSIX 那一档**：`-i.bak` 落盘并先不带 `-i` 预览；`0,/re/` 换成范围加计数器或 `awk`；`1a hello` 改成 `-f` 脚本里的 `a\` 换行写法；大小写交给 `tr` 或 `awk` 的 `toupper()`。最后同一份输入在两台机器各跑一遍、比 `wc -l`——这是最便宜的静默差异探测器。
:::

::: errata 常见误解
1. **「sed 报错才算不兼容」**——本机 BSD 对 `0,/re/` 与 `,+1p` 都不报错、只少输出（实测）；`-l` 还会把你的数字当成脚本。
2. **「`a`/`i`/`c` 一行写完到处都行」**——`1a hello` 是 GNU 扩展，BSD 要 `a\` 加换行（实测）；放进 `-f` 脚本文件是两边通吃的写法。
3. **「手册里列的 s 标志都能用」**——本机与 Ubuntu 实测 `s///s`、`s///n` 都失败，只有 `e`、`M` 是 GNU 独有。
4. **「`\U` 会统一转大写」**——BSD 把它当字面字符输出 `Ubeta`（实测），不报错。
5. **「`q` 和 `Q` 一样，都是退出」**——`q` 会把当前行自动打印出去（0.6.4 实测），`Q` 不打印而且是 GNU 扩展；`q 7` 带退出码也只认 GNU。
:::

### 0.6.11 小结

命令全表读两遍：第一遍看「这条命令挂在循环的哪一步」，第二遍只看最后一列的实测差异。sed 的 POSIX 子集两侧通用，GNU 扩展的一半会报错、另一半静默给不同结果，而跨平台脚本的价值就在于只写前者。如果只记住一件事，那就是：**扩展不是不能写，是不能没实测就写——换台机器 `wc -l` 一遍，比读手册可靠。**

**Q4（迁移）** 你要在 CI 里保证一段 sed 脚本 GNU/BSD 行为一致。除了读手册，给出成本最低的一招并说明它能抓到哪一类问题。

::: sol 答案
**A1** 读一行进模式空间（去换行）→ 执行地址命中的命令 → 除非 `-n` 自动打印并补换行 → 清空读下一行。`-n` 关第三步，`p` 是额外打印，`d` 跳过本轮剩余命令并跳过自动打印，`D` 只删到第一个换行且不读新行、回到脚本开头。
**A2** GNU 的 `-l` 需要一个数值参数（缓冲区大小），BSD 的 `-l` 是布尔开关，于是 `10` 落到了脚本位置、被当成 sed 脚本解析。属于「同一字母两侧语义不同」那一档，比单纯缺失更糟——它连报错信息都在误导你。
**A3** 用 `-f` 脚本文件：把 `a\` 与文本分两行写、`}` 顶格、块内命令各占一行（实测这两点在 BSD 上都成立）。命令本身不变，只是写法退回 POSIX。
**A4** 同一份输入在两台机器上各跑一次，比较 `wc -l` 与 `md5`/`cksum`。它能抓到「不报错但结果不同」这一整类（`0,/re/`、`,+N`、`\U`、末行 `N`），而这些正是读手册最容易漏的。
:::
:::

## 0.6.12 sed 进阶：hold space、分支与循环 {#sec-0.6.12}

0.6.5 已经把保持空间（hold space，sed 里唯一跨轮次存活的第二个缓冲区）和 `h`/`H`/`g`/`G`/`x` 五条搬运命令讲过一遍。这一遍只看两件事：分支与循环（`:标签`、`b`、`t`、`T`）的真实用途，以及 sed 在哪个位置到达极限。

这一节回答：两个缓冲区加上跳转到底能写出什么真东西；写到哪里时该停下来换 awk？

::: preview 先抓住一件事
分支给 sed 补了两样循环里原本没有的东西：**条件**（`t`/`T` 按上一次 `s` 的成败决定跳不跳）和**回到脚本开头**（`b` 带标签）。于是它能做续行合并、相邻去重、多行记录这类「跨行」的事。但它的记忆只有两格缓冲区：要「记住任意多行」，就得把整份文件压进保持空间再用循环逐行比对——技术上可行、工程上没人读得懂。本节两个例子都能在两侧跑通，末尾给一条判据：**脚本里出现两个以上标签，或者你需要在脑子里推三轮缓冲区状态，就换 awk。**
:::

### 0.6.12.1 搬运的两种编排：`h` 存、`g` 取、`x` 换

0.6.5 那张五行表这里不重复，只把它变成推演工具。倒序 `sed -n '1!G;h;$p'` 的编排是「**每轮都让历史垫在当前行下面，再整份存回去**」：`G` 追加历史（自带换行），`h` 覆盖保存新版本，`$p` 在最后一行一次打印。逐轮状态见 0.6.5 的例 0.6.5，本节补一个方向相反的编排——**保持空间只存「上一行」**，用来做「打印命中行的下一行」：

```bash
printf 'alpha\nERROR x\nbeta\ngamma\nERROR y\n' > /tmp/lab0c06_h.txt
sed -n 'x; /^ERROR/{g;p}; x; h' /tmp/lab0c06_h.txt
```

五行输入推三轮就够：每轮开头 `x` 把「当前行」和「上一行」对调，于是模式空间里躺着上一行；它命中 `ERROR` 就用 `g` 把当前行取回来打印；结尾的 `x` 与 `h` 保证下一轮的保持空间里是这一行的当前行。**`g` 之后两个缓冲区装着同一个东西，所以末尾那次 `x` 不影响结果**——这一句是读懂这类脚本的关键。

同一条脚本在 GNU 上一行写得跑通（Ubuntu 实测输出 `beta`），本机 BSD 却报错 `extra characters at the end of p command`——花括号块里的命令必须各占一行（0.6.11.3 实测）。退到脚本文件就两侧一致：

```bash
printf 'x\n/^ERROR/{\ng\np\n}\nx\nh\n' > /tmp/lab0c06_after.cmd
sed -n -f /tmp/lab0c06_after.cmd /tmp/lab0c06_h.txt   # 两侧实测都只输出 beta
```

等价写法当然是 `grep -A1 ERROR`（本机实测输出 `ERROR x`、`--`、`ERROR y`），sed 版存在的意义是让你能顺手改写那行内容。

### 0.6.12.2 `H` 保序、`G` 倒序：一个字母之差

倒序靠的是 `G`（把历史垫在当前行**下面**）；改用 `H` 就是另一种故事。同一份五行输入，脚本文件写成 `H` / `$!d` / `x` / `p` 四行：

```bash
printf 'H\n$!d\nx\np\n' > /tmp/lab0c06_order.cmd
sed -n -f /tmp/lab0c06_order.cmd /tmp/lab0c06_h.txt
```

两侧实测输出一致：开头多一个空行，其余按**原顺序**列出五行。差别全在方向——`H` 是「当前行接到历史**后面**」，追加顺序就是文件顺序；`G` 是「历史接到当前行后面」，于是最新的一行永远在最上面。`$!d` 让中间每一轮都不打印，最后一轮 `x` 换出来一次打印。开头那个空行是保持空间初始值为空、`H` 自带一个换行的结果（0.6.5 实测过同型现象）。

**方向记住了，压段落就自己推得出来。** 0.6.5 里那条 `1h;1!H;${g;s/\n/ /g;p}`（BSD 要换行写）就是按顺序把全文堆进保持空间再取回；awk 用 `BEGIN{RS=""}` 一行做完同一件事，读起来不必推演。

`n`、`N`、`P`、`D` 这四个跨行命令和保持空间管的不是同一件事：它们只往模式空间里塞第二行，不留下任何历史。

`n` 打印当前行（除非 `-n`）后用下一行顶替；`N` 追加下一行、中间留一个换行；`P` 只打印到第一个换行；`D` 删到第一个换行，若还有剩余就**回到脚本开头**且不读新行。

`$!N` 是「不是最后一行才 `N`」，防的就是 0.6.5 实测过的末行分歧：GNU 在末行 `N` 后仍打印当前行、BSD 直接吞掉且退出码还是 0。

### 0.6.12.3 分支三件套：`b` 无条件、`t` 成功跳、`T` 失败跳

三条命令的形状都是 `[地址]命令 [标签]`：地址决定**哪一行**触发，标签决定**跳到哪**，两者都能省。

| 命令 | 什么时候跳 | 跳到哪里 | 两侧实测 |
|:--|:--|:--|:--|
| `b` | 无条件 | 脚本末尾，本轮剩余命令不执行 | 一致：`{2,3b` 与 `s/Line/Replacement/` 组成的脚本，两侧都跳过第 2、3 行的替换（输出四行相同） |
| `b 标签` | 无条件 | 该标签之后 | 一致；BSD 要求标签独占一行 |
| `t` | 上一次 `s` 成功 | 脚本末尾 | 一致（见下面的 if/then-else） |
| `t 标签` | 上一次 `s` 成功 | 该标签之后 | 一致；标签没定义时 GNU 报 `can't find label for jump to`、退出码 4，BSD 报 `undefined label` |
| `T 标签` | 上一次 `s` **失败** | 该标签之后 | **GNU 4.9 有、BSD 没有**（`invalid command code T`，实测） |

`t` 与 `T` 给 sed 补的是 if/else，而这两条正好是「一对反面」。同一份三行输入（`alpha`、`ERROR x`、`beta`），脚本文件写成五行：`s/^ERROR/E:/`、`t hit`、`s/^/X /`、`:hit`、`p`。含义是「命中 `ERROR` 的改写前缀，**没命中的**再加一个 `X `」——两侧实测输出都是 `X alpha`、`E: x`、`X beta`。把第二行的 `t` 换成 `T`，条件就翻过来：GNU 实测输出 `alpha`、`X E: x`、`beta`，也就是只有命中行拿到 `X `；同一条在本机 BSD 上直接不认 `T`（实测）。不带标签的 `t` 更省：`{s/First/Matched/` 换行 `t` 换行 `s/Line/Replacement/` 换行 `}` 这个「成了第一个就不做第二个」的写法，两侧实测输出同样逐行相同。

写法上有个坑：`t hit` 这类带标签的跳转在 GNU 上可以挤在一行，在 BSD 上标签会把整行吃完，于是报 `undefined label 'hit;s/^/X /;:hit;p'`（本机实测）。跨平台就用 `-f` 或真实换行。标签长度按 7 个字符以内写最稳——那台 BSD 只对没被引用的标签给 `unused label` 警告（实测），并没有替你拦住过长的标签。

### 0.6.12.4 循环：终止条件必须自己造

真实用途是把以反斜杠结尾的续行读平。输入四行——`a=1\`、`more2`、`more3`、`b=2`，第一行行尾是一个反斜杠；脚本文件四行：

```text
:a
/\\$/N
s/\\\n//
ta
```

逐轮读：标签 `a`；行尾是反斜杠就 `N` 把下一行追加进来；`s/\\\n//` 删掉「反斜杠加换行」；`ta` 在这次 `s` 成功时跳回标签。**终止条件由 `ta` 自带**——某一行不再以反斜杠结尾，`s` 就失败，跳转不发生，循环自然收。两侧实测 `-f` 版本输出都是 `a=1more2`、`more3`、`b=2`。

同一条脚本在 GNU 上写成一行 `sed ':a;/\\$/N;s/\\\n//;ta'` 结果相同（Ubuntu 实测）；本机 BSD 把 `:a` 之后的整行当成标签名，报 `unused label 'a;/\$/N;s/\\\n//;ta'` 然后**原样输出没合并的内容**（本机实测）。这是 0.6.11.2 那一类：不报错、静默给错答案。

死循环是分支唯一的真危险。拿「反复删掉第一个逗号并打印」当例子，脚本三行：`:start`、`s/,//1p`、`b start`。每轮确实删掉了一个逗号，但它既不读新行也不结束本轮，于是停不下来——两侧实测都在 3 秒报警处被掐掉（退出码 142）。把第三行换成 `/,/b start`，跳转就带上了条件：行里再没有逗号就不跳，脚本正常收尾，同一份输入两侧实测都是 6 行、逗号逐行减少（本机与 Ubuntu 输出相同）。同一个循环体，多一个 `/正则` 就是两种命运。所以循环必须三选一：靠 `t`/`T` 的成败收敛、用 `/正则/b` 做守卫、或者在体内放 `d`/`q`。

**`D` 的日常用法不需要标签，它自己就是循环。** 配置文件里成片空行难看，`sed '/^$/d'` 一刀切又太狠——段落之间那个分隔空行也没了（实测把 `line1`、`line2`、空、`line3`、两个空、`line4` 收成四行相连、一个空行都不剩）。让 `N` 和 `D` 搭一对：

```bash
printf 'a\n\n\n\nb\n' > /tmp/lab0c06_sq.txt
sed '/^$/N;/^\n$/D' /tmp/lab0c06_sq.txt
```

逐轮读：`/^$/N` 是「当前是空行就把下一行并进来」，于是模式空间里有两行；`/^\n$/D` 只在「并进来的那行也是空行」时成立，`D` 删掉模式空间的第一行并回到脚本开头，**且不读新行**——剩下那一行空行再走一遍同样的两条命令。三个连续空行就这样被吃掉两个。Ubuntu 与本机的输出逐字相同，都是 `a`、一个空行、`b`（Ubuntu 实测、本机实测）。

同一条规矩还有另一条不碰 `D` 的写法：`sed '/./,/^$/!d'`，意思是「从有内容的行到第一个空行这段区间之外的行全删」，也就是区间外的第二、第三个空行被删掉。实测两侧输出与上面那条完全一致（Ubuntu 实测、本机实测）。区间写法只有一条规则，不用推缓冲区，日常维护选它；`N`/`D` 那一版的价值是让你看清 `D` 的「原地重跑」——0.6.5 的相邻去重用的正是同一个形状。要反过来给每行下面加一个空行，则是 `sed '/^[[:space:]]*$/d; $!G'`：先删干净再统一补，实测同一份输入出 `line1`、空、`line2`、空、`line3`、空、`line4`，行间恰好一个空行、文件尾不多（两侧实测）。一句话记法：`D` 循环管**压**，`G` 管**加**。

::: def 定义 0.6.12 · 分支与循环 {#def-0.6.12}
`:label` 定义一个跳转点，标签本身不执行任何动作。`b` 与 `b label` 无条件跳转，`t [label]` 在「自上一轮或上一次跳转以来有一次 `s` 成功」时跳转，`T [label]`（GNU）条件相反。跳转不读新行、不清空模式空间，所以它既可以当 if/else 用，也可以当循环用；**当循环用时，进度必须由某个会失败的命令来保证**，否则脚本永远停在同一行上。
:::

::: ex 例 0.6.12 · 一行 if/else 的 sed 版 {#ex-0.6.12}
需求：给配置文件里**没有** `=` 的行前面加 `# SKIP `，同时把 `key = value` 的空格去掉。先猜输出再跑。

```bash
printf 'a=1\nbad line\nkey = 2\n' > /tmp/lab0c06_ie.txt
cat > /tmp/lab0c06_ie.cmd <<'CMD'
s/^[^=]*$/# SKIP &/
t done
s/[[:space:]]*=[[:space:]]*/=/
:done
p
CMD
sed -n -f /tmp/lab0c06_ie.cmd /tmp/lab0c06_ie.txt
```

`&` 是被整个匹配吃掉的原行（0.6.4），`s/^[^=]*$/.../` 只在整行不含等号时成立；`t done` 一成功就跳过第二条 `s`，于是两条 `s` 变成了互斥的两支。两侧实测输出都是 `a=1`、`# SKIP bad line`、`key=2`。

同一道题在 awk 里是 `awk '{ if ($0 !~ /=/) print "# SKIP " $0; else { gsub(/ *= */,"="); print } }'`，两侧实测输出逐行相同（本机与 Ubuntu 各跑过），却不用推标签、也不用脚本文件。sed 五行、awk 一行——**这就是分支的位置：它让 sed 做到了 if/else，也做到顶了。**
:::

### 0.6.12.5 到站信号：这件事交给 awk

相邻去重 0.6.5 已经跑通（`$!N` 加 `D`，实测输出 `A`、`B`、`C`）。真正常见的需求是「删除**任意位置**的重复、保留首次出现的顺序」：sed 要做到就得把见过的每一行都堆进保持空间，再回到脚本开头逐行比对——两个缓冲区、至少一个标签、逐轮推演。本书不给这个 sed 版本，因为它不可维护；同一件事 awk 是一行，`awk '!seen[$0]++'` 对 `one one two one three two` 实测输出 `one`、`two`、`three`（本机与 Ubuntu 一致，见 0.6.6）。

倒序也是同一类：`sed -n '1!G;h;$p'` 把整份文件压进保持空间，而系统里已经有现成的工具——Ubuntu 实测 `/usr/bin/tac` 可用，本机没有 `tac`（`command not found`，实测），BSD 的对应命令是 `tail -r`。

::: errata 常见误解
1. **「`t` 是「测试为真就跳」」**——它测的是**上一次 `s` 有没有成功**，不是某个条件表达式；`T`（GNU）条件相反。两条一起才凑成 if/else（两侧实测对照见 0.6.12.3）。
2. **「标签可以用分号连着写」**——只有 GNU 这样宽松。本机 BSD 把标签之后的整行都算进标签名，结果是 `unused label` 加**原样输出**（实测）。
3. **「循环总会跑完」**——`b` 不带守卫就是死循环，两侧都到超时才停（本书用 3 秒报警掐掉，实测退出码 142）。进度必须来自会失败的 `s` 或显式的 `/re/b`。
4. **「保持空间能当数组用」**——它只有两格，没有「按行号取任意一行」的能力（0.6.5 已对比过）。任意位置去重、跨行计数、按 key 关联，都是 awk 的活。
5. **「sed 脚本越长越省」**——超过一个标签、或要在脑子里推三轮缓冲区状态，就该换 awk 或 Python；sed 的价值是「一趟、无状态、启动快」。
:::

### 0.6.12 小结

保持空间加上 `:`/`b`/`t`/`T`，sed 就凑齐了「跨行 + 条件」，续行合并、行后上下文、单行 if/else 都能写实并两侧跑通；但这套东西的记忆容量只有两个缓冲区，标签在 BSD 上还有独占一行的硬约束。如果只记住一件事，那就是：**分支是用来读懂 sed 的，不是用来写生产脚本的——需要记住任意多行时，一行 awk 就赢了。**

::: method 即时自测 · 0.6.12
**Q1（记忆）** `b`、`t`、`T` 各自的跳转条件是什么？哪一条 BSD 不认？

**Q2（辨析）** 倒序为什么必须用 `G` 而不是 `H`？把 `H;$!d;x;p` 的输出和 `1!G;h;$p` 对照说明。

**Q3（应用）** 用 `t`/`T` 各写一版「命中行加 `X ` 前缀」，并指出哪一版在 macOS 上跑不了。

**Q4（迁移）** 同事交了个 sed 脚本：三个标签、保持空间里堆全文、按行号取第 N 行。给出你的评审意见和替换方案。

::: sol 答案
**A1** `b` 无条件；`t` 在上一次 `s` 成功时跳；`T` 在失败时跳，是 GNU 扩展（本机 BSD 报 `invalid command code T`，实测）。
**A2** `H` 是「当前行接到历史之后」，堆出来就是原顺序，实测 `H;$!d;x;p` 输出空行加原序五行；`G` 是「历史接到当前行之后」，最新行永远在最上面，所以 `1!G;h;$p` 得到倒序（0.6.5 实测）。一个字母之差决定顺序还是倒序。
**A3** 命中行加前缀：`s/^ERROR/E:/` 之后接 `T hit`（失败就跳到 `:hit`，跳不过去的才执行 `s/^/X /`），Ubuntu 实测输出 `alpha`、`X E: x`、`beta`。`T` 那一版在 macOS 上跑不了（本机报 `invalid command code T`），BSD 侧要退回取反地址 `/^ERROR/!{…}` 或者直接交给 awk。
**A4** 三个标签加「全文进保持空间」说明已经在跟两个缓冲区较劲；按行号随机取行更是 awk 数组的本职工作。建议改写：取第 N 行用 `awk 'NR==n'`，去重与分组用 `seen[key]` 数组，倒序用 `tac`/`tail -r`。评审判据就一句：**推演超过三轮，或者标签超过一个，就重写。**
:::
:::

## 0.6.13 awk 的程序模型：记录、字段与变量 {#sec-0.6.13}

0.6.6 带你写出了第一个 awk 报表，0.6.7 讲了三件工具怎么选。这一节补上一直没正面讲的那层：awk 按什么顺序执行你的代码、变量从哪来、「一行」在它眼里到底是什么。

这一节回答：为什么 `awk 'BEGIN{print x}' x=42 file` 打出来是空的，同一条赋值正文却能拿到 42？`{sum+=$1} END{print sum}` 凭什么跨行累加？

::: preview 先抓住一件事
awk 是一台两遍扫描的小机器：先跑一次 `BEGIN`；把输入切成**记录**（record，默认一行一条），每条记录按 `FS` 切成**字段**（field），再自上而下套用你写的每个 pattern-action 对；全部读完跑一次 `END`。变量全是全局的，跨记录存活——所以求和不需要缓冲区也不需要标签，`{sum+=$1}` 一行就够。理解了这台机器，`-v` 的时机差、`$1=$1` 的重建、隐式类型转换，都只是推论。
:::

### 0.6.13.1 先跑出现象：同一个变量，BEGIN 里空、正文里 42

先猜这两条各打印什么，再跑：

```bash
printf 'a,100\nb,50\n' > /tmp/lab0c06_t1.csv
awk 'BEGIN{print "BEGIN x=["x"]"} {print "body x=["x"]"; exit}' x=42 /tmp/lab0c06_t1.csv
awk -v min=100 'BEGIN{print "min=["min"]"}' /dev/null
```

Ubuntu 实测：第一条先打 `BEGIN x=[]`、再打 `body x=[42]`；第二条打 `min=[100]`。差别在赋值落在参数表的哪个位置：awk 按顺序消费参数，`x=42` 排在那个文件**之后**，要等文件处理完才生效；`-v` 则在 `BEGIN` 之前就把值摆好。带默认值的脚本最常踩这条：想拿 `BEGIN` 里的值做默认，入参必须用 `-v` 传。

::: def 定义 0.6.13 · awk 的执行模型 {#def-0.6.13}
awk 程序是 pattern-action 对的列表。执行顺序：`BEGIN` 跑一次 → 对每条记录（由 `RS` 切，默认换行）先按 `FS` 切字段（`$1`…`$NF`，`$0` 是整条记录，`NF` 是字段数），再自上而下套用每一对，pattern 为真才执行 action → 输入读完 `END` 跑一次。`NR`（全局记录号）、`FNR`（当前文件内记录号）、`FILENAME` 由引擎维护；用户变量一律全局、跨记录存活。
:::

### 0.6.13.2 两遍扫描的用武之地：一条命令合两个文件

::: ex 例 0.6.13 · 谁在第一个文件里出现过，就带出它的答案 {#ex-0.6.13}
先猜：下面这条对两个文件打印几行、打印什么？

```bash
printf 'u1 10\nu2 20\n' > /tmp/lab0c06_a.txt
printf 'u1 x\nu3 y\n' > /tmp/lab0c06_b.txt
awk 'NR==FNR {v[$1]=$2; next}
     $1 in v  {print $1, $2, v[$1]}' /tmp/lab0c06_a.txt /tmp/lab0c06_b.txt
```

Ubuntu 实测只输出一行 `u1 x 10`。拆开读：读第一个文件时 `NR` 与 `FNR` 永远相等，换到第二个文件 `FNR` 从 1 重来、`NR` 继续涨——两个文件共三条记录时第三条打出 `FNR=1 NR=3`（两侧实测，Ubuntu 与本机一致）。所以 `NR==FNR` 就是「还在读第一个文件」的判据：第一个文件建表，`next` 拦住它不往下走，第二个文件才来查表。去掉 `next`，第一个文件的行也会拿自己查自己，答案立刻多出来。
:::

### 0.6.13.3 记录与字段都可以重定义

内建变量的常用面先摆一张表，重点看「默认/注意」列：

| 变量 | 含义 | 默认/注意 |
|:--|:--|:--|
| `FS` | 输入字段分隔符 | 空白，且压缩连续空白；`-F` 是它的快捷方式 |
| `OFS` | 输出字段分隔符 | 空格；只被 `print` 的逗号触发，`printf` 不经过它 |
| `RS` | 输入记录分隔符 | 换行；`RS=""` 是段落模式；可以是正则（见下） |
| `ORS` | 输出记录分隔符 | 换行；`print` 每条结尾插一次 |
| `NF` | 当前字段数 | 赋值可以截断字段并重建 `$0` |
| `NR`/`FNR` | 全局/当前文件记录号 | `FNR` 每个文件重置 |
| `FILENAME` | 当前文件名 | stdin 时随实现而定 |
| `ARGC`/`ARGV` | 参数个数/数组 | `ARGV[0]` 是 awk；**脚本本身不算参数**（Ubuntu 实测 `ARGC=2 ARGV[0]=awk ARGV[1]=文件名`） |
| `ARGIND` | 当前文件在 `ARGV` 中的下标 | gawk；Ubuntu 默认的 mawk 把它当普通变量，读出来是空（实测） |
| `ENVIRON` | 环境变量的关联数组 | 两侧都有（实测：`ENVIRON["HOME"]` 各打出本机的家目录） |
| `RSTART`/`RLENGTH` | `match()` 的起点/长度 | 未匹配时 0/-1 |
| `SUBSEP` | 多维下标分隔符 | 默认 `\034`（见 0.6.14） |
| `CONVFMT`/`OFMT` | 数字转字符串/输出格式 | 默认 `%.6g`；影响数组键（见 0.6.13.4） |
| `IGNORECASE` | 忽略大小写 | gawk 扩展；mawk 上赋值不报错但完全无作用（实测） |

改 `RS` 就是改「一条记录是什么」。段落模式（空行分隔记录）与一行多字段的配合：

```bash
printf 'l1\nl2\n\nl3\n' | awk 'BEGIN{RS=""; FS="\n"} {print NR": "NF" ["$1"]"}'
```

Ubuntu 实测输出 `1: 2 [l1]`、`2: 1 [l3]`——两条记录，第一条里的两行变成了两个字段。旧稿说「正则 `RS` 是 gawk 特性」，这次实测改口：`RS="[0-9]+"` 处理 `ab12cd34`，Ubuntu 的 mawk 与本机 BSD awk 都给 `[ab][cd][换行]`（两侧实测）——正则记录分隔符不需要 gawk。真正离不开 gawk 的只有 `FIELDWIDTHS`（按列宽切分）与 `FPAT`（按「字段长什么样」切分）：这两条 `gawk` 命令本书未装 gawk、没有实测记录；更要小心 mawk 不报错——把 `FIELDWIDTHS="2 5"` 交给 `awk`，它悄悄忽略设置、整行原样当 `$1`（Ubuntu 实测），静默不生效比报错难发现，用 gawk 特性前先 `command -v gawk`。带引号的 CSV 谁也别拿这些选项硬解，交给 Python `csv` 或 `mlr --csv`。

字段可以截断，也可以重建：`{NF=3}` 把 `a b c d` 截成 `a b c`（Ubuntu 实测）；想让 `OFS` 生效必须**给某个字段赋值**触发重建——`BEGIN{OFS="_"} {$1=$1; print}` 对 `a  b   c` 打出 `a_b_c`，顺手把连续空白压掉（Ubuntu 实测）。旧稿写 `$0=$0` 触发重建，mawk 实测不成立：同一条输入 `$0=$0` 原样输出空白，一个字都不动（Ubuntu 实测）。

跳转类命令里有一处要勘误。`next` 跳过当前记录余下的规则；`exit` 跳进 `END` 并且 `END` 照常执行——`awk '{exit 3} END{print "in END"}'` 实测打出 `in END`、退出码 3（Ubuntu）。`nextfile` 则两台机器的默认引擎都不认：mawk 报 `syntax error at or near nextfile`、本机 one true awk 报 `bailing out`，退出码都是 2（两侧实测），旧稿「gawk/BSD awk 支持」里 BSD 这半句是错的；gawk 侧未实测。想「跳到下一个文件」，把逻辑写在 `NR==FNR` 上就行。

`getline` 的三种形式语义不同，返回值必须检查：

| 形式 | 读自 | 更新 `NR/FNR` | 失败 |
|:--|:--|:--|:--|
| `getline` | 主输入下一行 | 是 | 返回 0/EOF，-1 出错 |
| `getline var` | 主输入下一行到 var | 是 | 同上 |
| `getline < file` | 文件 | 否 | 返回 0/EOF，-1 出错 |
| `cmd \| getline` | 命令输出 | 否 | 同上，用完 `close(cmd)` |

实测样本：`(getline g)>0` 在主循环里拿到下一行后，这条记录不会再重读它（Ubuntu）；`"printf hi" | getline v` 两侧都拿到 `v=[hi]`（实测）。一个要留神的地方：`getline < "/nope_zzz"` 返回 -1 没错，但 `ERRNO` 两台机器都是空的（两侧实测）——别指望它替你打印原因，那是 gawk 的用法（未实测）。不要写 `while (getline line)` 而不处理 -1，否则错误会被当成 EOF 悄悄吞掉。

### 0.6.13.4 隐式类型转换：一个变量同时是两个值

这是没学过类型系统的人最容易缺的一层。awk 不声明类型，未赋值的变量**同时**满足「等于空串」和「等于 0」：`x==""` 与 `x==0` 一起打出 `1 1`（Ubuntu 实测）。比较时的规则是：两边里只要有一边是数字或「看起来是数字的字符串」（字段、`-v` 传入的值就是这种），就按数值比；两边都是普通字符串才按字典序。所以 `"10" < "9"` 打出真（字典序 `'1'<'9'`），`10 < 9` 打出假，而 `$1 < 10` 把字段 `9` 当数字 9 用（三条全部 Ubuntu 实测）。转换还有记忆：`"3a"+4` 得 7、`"apple"+1` 得 1（Ubuntu 实测），做过算术的值退回普通字符串。数字被迫当字符串时按 `CONVFMT`（默认 `%.6g`）格式化——把 `1.555555555` 当数组下标，键存成 `1.55556`（两侧实测），两个靠得近的数就会撞进同一个格子（0.6.14）。拿不准就先 `$1 + 0` 强制数值。

`print` 与 `printf` 的分工：`print` 的参数用逗号就插 `OFS`、连着写就拼接（`[$1$2][$1,$2]` 实测输出 `[ab][a b]`，Ubuntu）；`printf` 走 C 式格式串，`%s`、`%d`、`%.2f`、`%10s`、`%-10s` 都有（`sprintf("%-6s|%5.1f","x",3.14)` Ubuntu 实测）。`%d` 截小数、`%.2f` 按二进制浮点舍入，`1.005` 可能打成 `1.00`（见 0.6.16 实验三）——金额用整数分或 `bc`，别用浮点累加。

::: errata 常见误解
1. **「awk 是逐行处理」**——它按 `RS` 切记录，默认才恰好是行；段落模式里一条记录包含四行（Ubuntu 实测）。
2. **「文件名前的赋值 `BEGIN` 能用」**——实测 `BEGIN` 拿到空、正文才拿到值；要进 `BEGIN` 用 `-v`。
3. **「未赋值的变量只是空串」**——它跟 0 比较也为真（实测 `1 1`），`if (x)` 判空靠的就是这点。
4. **「`nextfile` 是 awk 标准配置」**——mawk 与本机 BSD awk 都报语法错误、退出码 2（两侧实测）。
5. **「`$0=$0` 会重建字段」**——mawk 实测原样输出；重建用 `$1=$1`。
:::

### 0.6.13 小结

awk 的三拍是 `BEGIN`、每条记录套用规则、`END`；变量全局存活，记录与字段都能用 `RS`/`FS` 重定义，`NR==FNR` 把两遍扫描变成了「两表连接」的命令。如果只记住一件事，那就是：**先问这条命令跑在哪个拍子上**——`-v` 在第一拍之前、文件名前的赋值在文件之后、`END` 只在流读完才到。

**Q2（辨析）** 为什么 `NR==FNR` 能当「还在读第一个文件」的判据？把它的动作去掉 `next` 会发生什么？

**Q3（应用）** 写一条 `awk` 筛选 CSV 第 3 列大于 `min` 的行、`min` 要求 `BEGIN` 里就能拿到，说出为什么不能用「文件名前赋值」。

**Q4（迁移）** 同事写了 `awk 'BEGIN{OFS="_"} {$0=$0} {print}'` 想压缩空白，实测原样输出。给出错在哪、怎么改。

**A3** `awk -F, -v min=100 '$3 > min {print}' sales.csv`。`x=42` 式赋值按参数表顺序生效、排在文件之后，`BEGIN` 里看不到（Ubuntu 实测空值）；`-v` 在 `BEGIN` 之前完成赋值（实测 `[100]`）。
**A4** mawk 实测 `$0=$0` 不触发重建，打印走的还是原始行；改成 `$1=$1` 才按 `FS` 切、按 `OFS` 拼回，`a  b   c` 变 `a_b_c`（Ubuntu 实测）。

## 0.6.14 awk 数组、内建函数与自定义函数 {#sec-0.6.14}

0.6.13 立起了三拍模型，变量全局、跨记录存活。这一节把「存活」用起来：数组是 awk 里唯一能记住任意多东西的结构，函数把重复的形状从一行里拽出来——0.6.12 末尾说「要记住任意多行就换 awk」，靠的就是这两样。

这一节回答：数组遍历到底有没有顺序？为什么一句像在做存在性检查的 `print a["miss"]`，其实往数组里添了一个元素？

::: preview 先抓住一件事
awk 的数组是**关联数组**（associative array，下标是任意字符串的哈希表，不要求连续）：`for (k in a)` 的顺序由实现决定；数字下标先转成字符串再入表；**引用一个不存在的元素会当场创建它**。三条里最疼的是最后一条——它让「顺手判断一下」变成「污染计数」。
:::

### 0.6.14.1 先跑出现象：遍历顺序与「顺手创建」

```bash
awk 'BEGIN{for(i=1;i<=6;i++) a["k"i]=i; for(k in a) printf "%s ", k; print ""}'
```

`for` 的圆括号里只有一个变量，它装的是**下标**不是值，取值要再写一次 `a[k]`。Ubuntu 实测上面的输出是 `k1 k2 k5 k6 k3 k4`——既不是插入顺序也不是字典序，但每个键都能取回自己的值。

::: ex 例 0.6.14 · 猜这两行打印什么 {#ex-0.6.14}
先猜：这个程序输出几行、各是什么？

```bash
awk 'BEGIN{a["k"]=1; print a["miss"]; print length(a)}'
```

两侧实测一字不差：先一个空行，再一个 `2`。`a["miss"]` 不是检查，是引用——元素被当场创建，`length(a)` 从 1 变 2。换成判断句式 `("miss" in a)`，查完 `length(a)` 仍是 1（两侧实测）。典型翻车是拿 `if (seen[$1] == 0)` 做存在性判断、又用 `length(seen)` 报去重数量——数出来的永远偏大。存在性只配 `in`。
:::

### 0.6.14.2 键的本质是字符串

`a[1]` 与 `a["1"]` 是同一个格子：下标入表前按 `CONVFMT`（默认 `%.6g`）转字符串。两侧实测 `a[1]="one"` 之后，`("1" in a)` 打出 1、`a["1"]` 与 `a[1.0]` 都取回 `one`。所以浮点当键会合并相近值（0.6.13.4 的 `1.55556`），要区分先改 `CONVFMT="%.10g"`（Ubuntu 实测键变完整）。

多维数组是同一个机制的把戏：`a[i,j]` 实际键是 `i SUBSEP j`（`SUBSEP` 默认 `\034`，普通文本碰不到的控制符）；存在性判断要把双下标整个括进括号 `(i,j) in a`。Ubuntu 实测 `a["x",1]=1` 后 `("x",1) in a`、`("x",2) in a` 打出 `1 0`，遍历时把 `SUBSEP` 替换成 `|` 就还原出两个键。

删元素 `delete a[k]`；清空整数组 `delete a` 不在 POSIX 里，但「gawk 扩展」这个标签容易误导：Ubuntu 实测 mawk 1.3.4 的 `delete a` 之后 `length(a)` 为 0，本机 one true awk 同样支持（本机实测），`split("", a)` 在两台机器也都能清空。保守写法仍是 `split("", a)`，因为最小公倍数在 POSIX，而不是「非 gawk 即报错」。

去重惯用法 `!seen[$0]++`（未定义按 0、`!0` 为真、后缀 `++` 置 1，保留首次出现顺序，0.6.6 两侧实测）和计数是同一个形状：`{cnt[$1]++} END{for(k in cnt) print k, cnt[k]}`——顺序照旧随机，要排名就在行尾接 `| sort -k1,1nr`，排序这件事从来不属于 awk（0.6.15）。

### 0.6.14.3 内建函数四类与自定义函数

| 类别 | 函数 | 备注（两侧实测口径） |
|:--|:--|:--|
| 字符串 | `length`、`substr(s,i,n)`、`index(s,t)`、`split(s,a[,r])`、`sub(r,s[,t])`、`gsub`、`match(s,r)`、`sprintf`、`tolower`、`toupper`；`gensub` 为 gawk（mawk 报 `function gensub never defined`，Ubuntu 实测） | 下标 1 起；`sub`/`gsub` **返回替换次数**并原地改第 3 参（Ubuntu 实测 `gsub(/[0-9]/,"#",s)` 返回 3、`s` 变 `a#b##`，`sub` 同理返回 1）；`substr("hello",2,3)` 得 `ell`、省略第三参取到末尾（实测）；`split` 第三参可给正则 |
| 数学 | `int`、`sqrt`、`exp`、`log`、`sin`、`cos`、`atan2`、`rand`、`srand` | 只有双精度浮点；`int()` 向零截断（`int(-5.6)` 得 -5，Ubuntu 实测）；`srand(42)` 之后 `rand()` 序列固定可复现（实测） |
| 时间 | `systime()`、`strftime(fmt[,ts])`、`mktime("YYYY MM DD HH MM SS")` | 常整体标 gawk，实际 mawk 1.3.4 三个都有，`mktime("2023 11 15 06 13 20")` 打出 1700000000（Ubuntu 实测）；本机 one true awk 对 `strftime`/`systime` 报 `calling undefined function`（本机实测）——时间函数是「mawk 有、one-true-awk 没有」，别按 gawk 一个维度想 |
| 位运算 | `and`、`or`、`xor`、`compl`、`lshift`、`rshift` | gawk；Ubuntu 实测 mawk 对 `and`、`or`、`xor` 全报未定义函数 |

`substr(s, 0, 2)` 起点越出 1 之后属未定义行为——Ubuntu 实测 mawk 给 `ab`（`substr("abc",0,2)`），gawk 未装无从对照，按 1 起写别赌默认。`match(s,r)` 设置 `RSTART`/`RLENGTH`（实测 `match("hello world",/o w/)` 返回 5、两变量是 5 和 3）；第三个参数放捕获组是 gawk 扩展——mawk 对 `match(s,r,m)` 直接 `syntax error`、退出码 2（Ubuntu 实测），连解析都过不了。`for (k in a)` 的排序指望 gawk 的 `asort`/`PROCINFO["sorted_in"]` 也一样：mawk 报 `function asort never defined`、`PROCINFO` 赋值不报错但毫无作用（均 Ubuntu 实测，gawk 本书未装）。

自定义函数：

```awk
function pct(part, total,    p) {     # 参数列表里的空位是局部变量
    if (total == 0) return 0
    p = 100 * part / total
    return p
}
{ bad += ($9 ~ /^5/); all++ }
END { printf "5xx=%.2f%%\n", pct(bad, all) }
```

awk 没有 `local` 关键字：参数列表里用空格隔开的多余变量就是局部变量；函数内其他变量是全局的。标量按值传递——Ubuntu 实测函数里把形参改成 99，调用处的变量仍是 21；数组正相反，按引用传递，函数里填的键出来就认（实测 `fill(b)` 后 `b[1]` 有值、`length(b)` 为 1），要「返回数组」就传数组进去填。递归可以写，两台引擎的栈上限本书未实测。`printf`/`sprintf` 的 `%d` 与 `int()` 一样向零截断，金额比较别依赖浮点相等（0.6.13.4、实验三）。

::: errata 常见误解
1. **「`for (k in a)` 按插入顺序」**——实测输出 `k1 k2 k5 k6 k3 k4`，既非插入也非字典序；要顺序就接 `sort`。
2. **「`a[k]` 读一下不损失什么」**——不存在就创建，`length` 随之变大（两侧实测）；判断存在性只用 `k in a`。
3. **「数字下标占数字索引」**——键一律先转字符串，`a[1]` 就是 `a["1"]`（两侧实测），浮点键受 `CONVFMT` 合并。
4. **「`delete a`、时间函数都是 gawk 专属」**——`delete a` 两台默认引擎都支持（实测）；时间函数 mawk 有、one-true-awk 没有（均实测），矩阵是三家的，不是一维的。
5. **「函数里的变量默认是局部的」**——恰恰相反，默认全局，局部要靠参数列表多留几个坑位（Ubuntu 实测形参改动不影响实参）。
:::

### 0.6.14 小结

数组给了 awk「记住任意多行」的能力，代价是键全为字符串、顺序不可依赖、引用即创建；函数给了复用，代价是默认全局加坑位式局部变量。如果只记住一件事，那就是：**存在性判断永远写 `in`，把排序交给 `sort`，把顺序假设从脑子里删掉。**

::: method 即时自测 · 0.6.14
**Q1（记忆）** `for (k in a)` 循环变量里装的是什么？顺序由谁决定？

**Q2（辨析）** `a["miss"]` 和 `("miss" in a)` 对数组的影响有什么不同？给实测数字。

**Q3（应用）** 用一行 awk 统计日志第 1 列出现次数、按次数从高到低输出，写出完整管道。

**Q4（迁移）** 你把「每请求计数」写成 `if (cnt[$1]==0) first++` 再 `cnt[$1]++`，同事说数组虚胖。解释原因并给改法。

**A1** 装的是下标（键），取值要 `a[k]` 再引一次；顺序由哈希实现决定，两侧实测都不是插入顺序（Ubuntu 输出 `k1 k2 k5 k6 k3 k4`）。

## 0.6.15 sort、uniq、cut、tr、paste、join、diff 速查 {#sec-0.6.15}

0.6.13 和 0.6.14 用 awk 把「编程」补全了，可管道里一半的活不用正则、也不用编程——数数、排序、切列、对差，各有各的专门命令。这一节是那箱工具的速查表，但速查不靠背选项：先钉住「按行/字节工作、不理解数据」这条边界，表就只剩查的作用。

这一节回答：为什么 `sort -k2` 和 `sort -k2,2` 能对同一份输入给出相反的顺序？哪些命令看着像「懂字段」，其实只懂字节？

::: preview 先抓住一件事
这一组工具的共同契约：**把输入当一行一行的字节串**。`cut` 不认识引号包裹的字段，`column` 也一样，`sort` 的键默认从起点延伸到**行尾**而不是那个字段为止，`uniq` 只删相邻重复。键宽、相邻、字节这三个词覆盖了本节大多数事故；把「谁不理解数据」记住，比背 13 个选项重要。
:::

### 0.6.15.1 先猜：同一个键，两种顺序

::: ex 例 0.6.15 · 两条「猜输出」 {#ex-0.6.15}
先猜第一问：输入两行 `a 2 z`、`b 2 y`，`sort -k2` 和 `sort -k2,2` 输出一样吗？再猜第二问：`printf '中文x\n' | cut -c2` 切出哪个字符？

```bash
printf 'a 2 z\nb 2 y\n' > /tmp/lab0c06_k.txt
sort -k2 /tmp/lab0c06_k.txt     # 键 = 第 2 字段到行尾
sort -k2,2 /tmp/lab0c06_k.txt   # 键 = 只有第 2 字段
printf '中文x\n' | cut -c2
```

两问的答案都不是直觉到的那个。第一问：Ubuntu 与本机实测输出**相反**——`-k2` 比的是 `2 y` 对 `2 z`，`b 2 y` 在前；`-k2,2` 键相等，`sort` 默认拿整行做最后决胜，`a 2 z` 在前（两侧一致）。第二问：`cut -c` 数的是**字节**，`中` 占三个字节，第二字节切出来是残缺序列，两台机器都给你一份乱码（两侧实测）。一个逗号、一个字节宽度，就是这组工具的边界所在。
:::

### 0.6.15.2 sort 与 uniq

| 选项 | 作用 | 注意 |
|:--|:--|:--|
| `-n` | 数值排序 | 只认行首/键开头的数字 |
| `-g` | 通用数值（科学计数） | 比 `-n` 慢 |
| `-h` | 人类可读（K/M/G） | 两侧实测都认（BSD sort 也支持） |
| `-V` | 版本号排序 | `1.10 > 1.9` |
| `-r` | 降序 | |
| `-k Start[,End]` | 键范围 | `-k2,2` 只按第 2 字段；不写 `End` 延伸到行尾（见例 0.6.15） |
| `-t SEP` | 字段分隔符 | 默认空白 |
| `-u` | 去重 | 依据整个键 |
| `-s` | 稳定排序 | 禁用最后的整行比较 |
| `-f` | 忽略大小写 | 受 locale 影响 |
| `-b` | 忽略前导空白 | |
| `-o FILE` | 输出到文件 | 可与输入同文件 |
| `--parallel=N` | 并行排序 | GNU |
| `-z` | NUL 分隔 | 配 `-print0` |

`sort` 默认按 locale 排序，`LC_ALL=C` 才按字节；日志、ID、协议字段用 C，人名目录留 locale。`-k3.7n`（第 3 字段第 7 个字符起按数值）这类写法可读性差，复杂排序交给 awk。

| 选项 | 作用 |
|:--|:--|
| `-c` | 前缀计数 |
| `-d` | 只输出重复行 |
| `-D` | 输出所有重复行（GNU） |
| `-u` | 只输出不重复行 |
| `-i` | 忽略大小写 |
| `-f N` | 跳过前 N 个字段 |
| `-s N` | 跳过前 N 个字符 |
| `-w N` | 只比较前 N 个字符 |
| `-z` | NUL 分隔 |

`uniq` 只删**相邻**重复，必须先 `sort`。`sort -u` 通常比 `sort | uniq` 快，但 `uniq -c` 的计数是 `sort -u` 给不了的。

### 0.6.15.3 cut 与 tr

| 选项 | 作用 | 注意 |
|:--|:--|:--|
| `-d CHAR` | 分隔符 | 只能是单个字符 |
| `-f LIST` | 字段 | `1,3-5`；默认 tab |
| `-c LIST` | 字符位置 | 按字节，UTF-8 下会切坏（实测切坏 `中` 的第二字节） |
| `-b LIST` | 字节位置 | 与 `-c` 类似 |
| `--complement` | 取反 | |
| `-s` | 没有分隔符的行不输出 | 默认原样输出 |
| `--output-delimiter=STR` | 输出分隔符 | |

`cut -d ' '` 不压缩连续空格，`last` 这类多空格对齐的输出会切错；用 awk 的默认空白分词。CSV 的引号字段不能用 `cut`，用 Python `csv`。

| 写法 | 作用 |
|:--|:--|
| `tr 'a-z' 'A-Z'` | 大小写转换 |
| `tr -d '\r'` | 删除 CR |
| `tr -s ' '` | 压缩连续空格 |
| `tr -d '[:digit:]'` | 删除数字 |
| `tr -c '[:print:]' '\n'` | 非打印字符换成换行 |
| `tr -cd '[:alnum:]'` | 只保留字母数字 |

`tr` 按字节工作，不支持多字节字符；`tr 'a-z' 'A-Z'` 在 UTF-8 下只影响 ASCII。它没有文件名参数，只能读 stdin。

### 0.6.15.4 nl、column、fold、fmt：把已有输出排成版式

这一组不改内容，只改「长什么样」：给行加编号、把列对齐、把长行折断，常垫在管道最后一步。

| 命令 | 作用 | 注意 |
|:--|:--|:--|
| `nl -ba f` | 给所有行编号（默认**不**编空行） | `-ba` 连空行一起编；编号后接 `sed -n '10,20p'` 指认行号 |
| `column -t` | 把空白分隔的文本按列对齐 | `-s,` 指定分隔符；`mount \| column -t` |
| `fold -w 80` | 硬折行到固定宽度 | `-s` 只在空白处断，避免切断单词 |
| `fmt -w 72 f` | 重排段落（合并短行、拆长行） | 会破坏代码缩进，只用于自然语言文本 |
| `printf '%s\n' "$x"` | shell 内建的格式化输出 | 不解释反斜杠；`%s` 引号探针用法见 [0.7.9](ch07.md) |

其中三条在两台机器上实测过同一组小样本：`nl -ba` 对 `x`、空行、`y` 都打出三行编号（编号与正文之间是 tab），`column -t -s,` 把两行 CSV 对齐成两列，`fold -s -w 7` 在空白处断行——两侧输出逐字一致（两侧实测）。`fmt` 本书未实测，风险记住一条就够：它会重排缩进，别喂代码。`pr`（分页加页眉）是打印时代的产物，现代终端与管道里几乎不用，知道名字即可。这些工具都按行/字节工作，`column -t` 不理解引号包裹的字段，CSV 带引号时仍要用专门的解析器。

### 0.6.15.5 paste、join、comm、diff

| 命令 | 作用 | 关键选项 |
|:--|:--|:--|
| `paste a b` | 按行横向拼接 | `-d` 分隔符、`-s` 每个文件压成一行 |
| `join a b` | 按公共键连接 | `-1 N`、`-2 N`、`-t`、`-a`、`-v`、`-o`、`-e` |
| `comm a b` | 比较两个有序文件 | `-1`、`-2`、`-3`、`--total` |
| `diff a b` | 逐行差异 | `-u`、`-r`、`-q`、`-N`、`-w`、`-B` |
| `patch -p1 < d.patch` | 应用补丁 | `-p` 去掉几层目录 |

`join` 要求两个文件都按连接键排序，默认空白分隔、第一字段为键；`-t,` 指定逗号，`-1 2 -2 1` 指定不同键。`comm` 也要求排序，输出三列：只在 A、只在 B、两边都有，`-12` 只显示共同行。`diff` 的退出码：0 相同，1 不同，2 出错；脚本里 `if diff -q a b; then` 天然把「不同」和「出错」分开了，别用 `$? -ne 0` 把它们混在一起。

```bash
# 两个有序 TSV 按第 1 列连接，缺失填 NA
join -t "$(printf '\t')" -a 1 -e NA -o '1.1,1.2,2.2' users.tsv orders.tsv

# 只显示两个文件的共同行
comm -12 <(sort a) <(sort b)

# 生成并应用补丁
diff -u old.conf new.conf > conf.patch
patch -p0 < conf.patch
```

第一条的实样：`users.tsv` 两行 `u1 10`、`u2 20`，`orders.tsv` 里只有 `u1 A`，Ubuntu 实测输出 `u1	10	A` 与 `u2	20	NA`——`-a 1` 保住左表全部行，`-e NA` 补右表缺失。注意 `-t` 的 tab 要真的传进去（`$'\t'` 或 `$(printf '\t')`），写成 `-t \t` 传的是反斜杠加 t。

`diff -u` 的 `---`/`+++` 行包含时间戳，打补丁时 `patch` 会忽略；`-N` 把新文件当空文件比较，适合生成「新增文件」的补丁。二进制文件用 `cmp`，不要用 `diff`；`cmp a b` 报第一个不同字节的偏移（`-l` 列出所有差异），正好用于核对「两个 tar 包是否完全一致」。

打补丁的完整动作是「演练→应用→看残留」：`patch --dry-run -p1 < d.patch` 先不动文件；正式应用时补不上的块写进 `*.rej`，`-b` 会把原文件留成 `*.orig`——脚本里必须检查 `.rej` 是否存在，否则「部分应用」会被当成成功。回滚同一条补丁用 `patch -R -p1 < d.patch`。

::: def 定义 0.6.15 · 行/字节工具的共同契约 {#def-0.6.15}
这组命令把输入当作**行的序列**（`tr`、`fold` 甚至只当字节流），不理解引号包裹的字段，也不理解「记录」——那是 awk（0.6.13）的事。比较默认走 locale 排序，`LC_ALL=C` 才按字节；`sort` 的键默认延伸到行尾、键相等默认整行决胜（`-s` 关掉）；`uniq` 只看相邻；`join`/`comm` 要求预先按同一套规则排序。跨工具传数据前，先问一句：两边对「一行、一个字段、一次比较」的定义一致吗？
:::

::: errata 常见误解
1. **「`sort -k2` 就是按第 2 字段排」**——键从第 2 字段起、到**行尾**止；只按该字段要写 `-k2,2`，且键相等时默认还有整行决胜（例 0.6.15 两侧实测顺序相反）。
2. **「`uniq` 能全局去重」**——它只删相邻重复；不排序先去重，`sort | uniq -c` 的计数就是错的。全局去重保留首序，交给 `awk '!seen[$0]++'`（0.6.6）。
3. **「`cut -f` 和 awk 的 `$n` 等价」**——`-d` 只能是单个字符、不压缩连续空白，对齐输出的 `last` 一类会切错；带引号的 CSV 两个都不许碰。
4. **「`column -t` 能排 CSV」**——它按空白/单字符分隔对齐，不理解引号，字段里有逗号就错位。
5. **「`cut -c` 数的是字符」**——两侧实测按字节，UTF-8 汉字被拦腰切断；要按字符切，用 awk 或 Python。
:::

### 0.6.15 小结

这箱工具的选项表很长，契约只有一条：按行/字节工作、不理解数据。键宽（`-k2` 对 `-k2,2`）、相邻（`uniq`）、预排序（`join`/`comm`）、字节（`cut -c`、`tr`）四个词把绝大多数事故圈住了。如果只记住一件事，那就是：**数据一旦带引号、多空格或逗号，就离开这箱工具，换 awk 或专门的解析器。**

::: method 即时自测 · 0.6.15
**Q1（记忆）** `uniq` 使用前必须做什么？`join` 和 `comm` 对输入有什么共同要求？

**Q2（辨析）** 同一份 `a 2 z`、`b 2 y`，`sort -k2` 与 `sort -k2,2` 谁先把 `b` 排前面？为什么？

**Q3（应用）** 给一段逗号分隔、字段里带引号逗号的数据，判断 `cut -d,` 会错在哪，改用什么。

**Q4（迁移）** 你要把 `du` 的输出生成按大小排名的报表，写出命令链，并说明不这么做会踩什么坑。

::: sol 答案
**A1** `uniq` 只比较相邻行，必须先 `sort`；`join` 与 `comm` 都要求输入按连接/比较键**用同一套排序规则**预先排好。
**A2** `sort -k2` 把 `b 2 y` 排前面：键延伸到行尾，比的是 `2 y` 对 `2 z`；`-k2,2` 键相等，整行决胜让 `a 2 z` 在前（两侧实测）。
**A3** `cut -d,` 会把引号里的逗号当分隔符、字段错位；改用 Python `csv` 或 `mlr --csv`，`column -t` 也不行（它同样不懂引号）。
**A4** `du -h dir/* | sort -rh`。坑在不用 `-h` 时：字典序会把 `9K` 排到 `10M` 后面；`-h` 按 K/M/G 的数值比（Ubuntu 与本机实测都认），`-r` 让大的在前。
:::
:::

## 0.6.16 实验：locale、`sed -i` 与 awk 精度 {#sec-0.6.16}

前面十五节的版本差异，不该只停在「书上是这么说的」。这一节给你四个能整段复制、三十秒跑完的实验：locale 对匹配的影响、`sed -i` 对硬链接做的事、awk 的浮点怪癖，最后补一个计时与日期换算的——`time` 和 `date` 是本章所有测时数据的出处，值得单独钉一遍。

这一节回答：`sed -i` 到底动了文件的什么？`awk` 把 `1.005` 打成 `1.00` 是谁的 bug？还有，`time` 的统计行为什么掉进你重定向的文件里？

::: preview 先抓住一件事
四颗雷各有一个反直觉的核心：locale 改变的不只是速度，还有「字符类算哪些字符」；`sed -i` 是「写临时文件再 rename」，文件内容改了、文件的**身份**（inode）也换了，硬链接跟不过去；`%.2f` 舍入到 `1.00` 是 IEEE 754 双精度的通用行为，两侧一字不差；`time` 是 shell 关键字不是命令，它的统计打在 shell 的 stderr 上，重定向只归命令、不归它。
:::

### 0.6.16.1 实验一：locale 与匹配引擎的代价

```bash
python3 - <<'PY' > /tmp/lab0c06_big.log
import random
random.seed(7)
for i in range(300000):
    print(f"10.0.0.{i%255} GET /p/{i%1000} {random.choice([200,301,404,500])} {i%5000}")
PY
for loc in C en_US.UTF-8; do
    printf '%s: ' "$loc"
    /usr/bin/time -f '%e s' env LC_ALL=$loc grep -c 'ERROR' /tmp/lab0c06_big.log
done
/usr/bin/time -f 'F %e s' grep -F ' 500 ' /tmp/lab0c06_big.log >/dev/null
/usr/bin/time -f 'E %e s' grep -E ' (4|5)[0-9]{2} ' /tmp/lab0c06_big.log >/dev/null
```

结论应该是：`LC_ALL=C` 通常更快，`grep -F` 比 `grep -E` 快。Ubuntu 实测的坑是**样本太小量不出来**：30 万行时 `-F` 与 `-E` 都报 0.00 s，locale 的差距要到字符类才现形——`LC_ALL=C grep -c '[[:alpha:]]'` 是 0.00 s，换成 `LC_ALL=en_US.UTF-8` 变 0.02 s（Ubuntu 实测）；把文件放大到 261 MB 再比，`-F` 0.081 s 对 `-E` 0.140 s（Ubuntu 实测，见 0.6.3）。绝对秒数取决于机器与缓存，同一台机器上的相对值才有意义；跑之前确认 `locale -a | grep -i en_US` 有 `en_US.utf8`，没有就先 `locale-gen`（Ubuntu 实测该 locale 已生成）。

### 0.6.16.2 实验二：`sed -i` 改了 inode，也改了硬链接关系

```bash
cd /tmp && printf 'localhost\n' > lab0c06_sedfile && ln lab0c06_sedfile lab0c06_sedfile.hard
ls -li lab0c06_sedfile lab0c06_sedfile.hard
stat -c 'inode=%i links=%h mode=%a' lab0c06_sedfile
sed -i 's/localhost/localhost.localdomain/' lab0c06_sedfile
ls -li lab0c06_sedfile lab0c06_sedfile.hard
stat -c 'inode=%i links=%h mode=%a' lab0c06_sedfile lab0c06_sedfile.hard
cat lab0c06_sedfile.hard
```

注意这串用的是不带后缀的裸 `sed -i`，只能在 GNU 侧跑；BSD sed 要把最后几步改成 `-i.bak`（0.6.4）。Ubuntu 实测：`sed -i` 后 `lab0c06_sedfile` 的 inode 换号（本次 2883591 变 2883592）、链接数从 2 变 1，`lab0c06_sedfile.hard` 仍指向旧 inode，`cat` 出来还是 `localhost`；mode 664 前后不变。同一实验在 macOS 用 `sed -i.bak` 重做，inode 同样换号、硬链接同样断开（本机实测）——「断链」不是 GNU 独有的坑，只是 GNU 的机制是「写临时文件 + rename」。需要保留链接时，用 `sed ... > tmp && cat tmp > file`（保持 inode）或接受断链。权限同理：GNU sed 会尽量复制原文件的 mode/owner，但 ACL/xattr 不一定保留；`stat -c '%a %U:%G'` 对比前后。

### 0.6.16.3 实验三：`sed -n l` 与 awk 的浮点

```bash
printf 'a\tb  \n' | sed -n 'l'
# a\tb  $
printf 'a\tb  \n' | od -c | head -2
awk 'BEGIN { printf "%.2f %.2f %.0f\n", 1.005, 2.675, 2.5 }'
awk 'BEGIN { printf "%d %d\n", 3.9, -3.9 }'
```

`sed -n l` 把 tab 显示成 `\t`、行尾显示成 `$`，是排查「看不见的字符」最快的方法。后面两条才是重点：`printf "%.2f"` 按二进制浮点舍入，`1.005` 打成 `1.00`；`%d` 向零截断，`3.9` 得 3、`-3.9` 得 -3。这五条输出两台机器都实测过：GNU 与 BSD 的 `sed -n l` 都给 `a\tb  $`；Ubuntu 的 mawk 与本机 one true awk 对两条 `awk printf` 给出一字不差的 `1.00 2.67 2` 和 `3 -3`（Ubuntu 实测）。浮点怪癖是 IEEE 双精度的通用行为，**不是某家 awk 的 bug**——金额用整数分，不要用浮点累加。

### 0.6.16.4 实验四：`time` 是关键字，`date` 双向换算

::: ex 例 0.6.16 · 先猜：统计行去哪了 {#ex-0.6.16}
先猜这两条能否藏住 `time` 的统计行（Ubuntu 与本机的 bash 里各跑一遍）：

```bash
bash -c 'time sleep 0.1 > /dev/null 2>&1'      # 猜测：统计行还出现吗？
bash -c '{ time sleep 0.1; } 2>/dev/null'      # 猜测：这条呢？
```

两侧实测：第一条照样打出 `real/user/sys` 三行——重定向归 `sleep`，不归 `time`；第二条安静了——花括号把统计行一起交给 `/dev/null`。`time` 是 shell 关键字，统计由 shell 打到自己的 stderr 上。想控制形状：bash 内建用 `TIMEFORMAT='%R'`（Ubuntu 实测打出 `0.303`），要峰值内存就换 GNU 的 `/usr/bin/time -v`（实测 `Maximum resident set size (kbytes): 1724`，值随机器变）；本机的 BSD `time` 不认 `-f`（实测 `illegal option`），只有 `-l` 给 maxrss（本机实测，单位字节）。

日期时间也走一遍闭环：`date +%s` 两侧都打出 epoch 秒（实测）；epoch 换回人话，GNU 写 `date -d @1700000000 '+%F %T'`、BSD 写 `date -r 1700000000 '+%F %T'`，同一台机器上答案一致（两侧实测均为 `2023-11-15 06:13:20`，东八区）；相对解析 GNU 用 `-d '2 hours ago'`、BSD 用 `-v-2H`（各自实测，结果同为两小时前）。时区一条两侧都成立：`date -u` 出 UTC、`TZ=Asia/Tokyo date` 出 JST（Ubuntu 实测）。`sleep 0.5` 两侧都接受小数（实测）；`cal` 本机可用（`cal -3` 实测），Ubuntu 那台 VM 没装（`command -v cal` 为空，实测）——跨机脚本别把它当标配。
:::

::: def 定义 0.6.16 · 计时与原地编辑的真实动作 {#def-0.6.16}
bash 的 `time` 是**保留字**：`time 命令` 之后，重定向、管道都属于那条命令，统计行由 shell 写到 shell 自己的 stderr；要一起收集就 `{ time ...; } 2>log`，或用独立的 `/usr/bin/time`（GNU 认 `-f`/`-v`，BSD 认 `-l`）。`sed -i` 的真实动作是「新建临时文件、写完后 rename 覆盖」：新内容、新 inode、旧名字，凡是从旧 inode 受益的东西（硬链接、开着 fd 的进程）都留在原地。原地编辑之前先 `ls -li` 看一眼链接数，是三十秒的保险。
:::

::: errata 常见误解
1. **「`sed -i` 是打开文件改内容」**——它换的是文件身份：inode 变号、硬链接断开，两侧实测一致（实验二）；想保住 inode 用 `cat tmp > file`。
2. **「`awk` 打印 `1.00` 是这台机器的 bug」**——两台 awk、两家实现、一字不差（实测）；那是 1.005 在二进制里没有「四舍五入的进位点」。
3. **「`time` 的统计能靠 `> file 2>&1` 收走」**——收不走，那是关键字，重定向归后面的命令（两侧实测）；用 `{ time ...; } 2>file`。
4. **「BSD 的 `time` 也认 `-f`」**——本机实测 `illegal option -- f`；BSD 侧用 `-l`，字段名和单位都不同。
5. **「locale 只影响速度」**——它还影响 `[a-z]` 这类字符类「算谁」；测时与测匹配集合是两件事，别混着下结论（0.6.2、0.6.9）。
:::

### 0.6.16 小结

四个实验把本章的三句口号变成了可复现的动作：换 locale 再计时、`sed -i` 前后 `ls -li`、两台机器对同一行 `printf` 的输出逐字比对、用花括号摆弄 `time` 的 stderr。如果只记住一件事，那就是：**「改文件」不等于「改内容」，「量时间」不等于「量命令」——先弄清动的是哪一层，数字才有意义。**

### 脚本一：`logstat.sh`——awk 数组、函数与外部排序

```bash
#!/usr/bin/env bash
# logstat.sh — 统计 access log 的状态码、5xx 比例、Top IP
# 用法: logstat.sh ACCESS_LOG [TOP]
set -euo pipefail

log=${1:?usage: logstat.sh ACCESS_LOG [TOP]}
top=${2:-10}
[[ -r $log ]] || { printf 'not readable: %s\n' "$log" >&2; exit 2; }
[[ $top =~ ^[1-9][0-9]*$ ]] || { printf 'TOP must be positive\n' >&2; exit 2; }

reader=(cat --)
[[ $log == *.gz ]] && reader=(gzip -cd --)

tmp=$(mktemp "${TMPDIR:-/tmp}/logstat.XXXXXX")
trap 'rm -f -- "$tmp"' EXIT

"${reader[@]}" "$log" | LC_ALL=C awk '
    function pct(part, total) {
        if (total == 0) return 0
        return 100 * part / total
    }
    {
        ip[$1]++
        status[$9]++
        if ($9 ~ /^5/) bad++
        all++
    }
    END {
        printf "META\t%d\t%d\n", all, bad
        for (s in status) printf "STATUS\t%d\t%s\n", status[s], s
        for (i in ip)     printf "IP\t%d\t%s\n", ip[i], i
    }' >"$tmp"

awk -F'\t' '$1 == "META" { printf "total=%d 5xx=%d (%.2f%%)\n", $2, $3, ($2 ? 100*$3/$2 : 0) }' "$tmp"
printf '== status ==\n'
awk -F'\t' '$1 == "STATUS" { printf "%6d %s\n", $2, $3 }' "$tmp" | sort -k1,1nr
printf '== top %d ips ==\n' "$top"
awk -F'\t' '$1 == "IP" { printf "%6d %s\n", $2, $3 }' "$tmp" | sort -k1,1nr | head -n "$top"
```

关键点：awk 只做一次扫描，把三类结果以 `TAG\tcount\tkey` 写入临时文件；排序交给 `sort`，避免在 awk 里调用多个 `sort` 管道。`pct()` 是自定义函数，`total==0` 的除零保护是必需的。`reader` 数组让 `.gz` 与普通文件走同一路径，读法只有一处。拿一份 6 行、含两条 5xx 的日志跑一遍（Ubuntu 实测）：

```text
$ bash logstat.sh access.log 3
total=6 5xx=2 (33.33%)
== status ==
     3 200
     1 404
     1 500
     1 503
== top 3 ips ==
     3 10.0.0.5
     2 10.0.0.9
     1 10.0.0.7
```

三处判读：`total=6` 说明只扫了一遍；`5xx=2` 里 500 与 503 各一条，百分比由 awk 的 `pct()` 算，不是 shell 里再除一次；IP 计数降序是 `sort -k1,1nr` 的功劳，`head -n "$top"` 只负责截断，改 `top` 参数不影响排序口径。"${reader[@]}"` 保留参数边界。`LC_ALL=C` 让 `$9` 的匹配与排序按字节，日志字段不受 locale 影响。

### 脚本二：`rename-regex.sh`——sed 生成新名，先查冲突

```bash
#!/usr/bin/env bash
# rename-regex.sh — 用 sed 表达式批量改名；默认 dry-run
# 用法: rename-regex.sh [-y] DIR 's/\.JPG$/.jpg/'
set -euo pipefail
usage() { printf "usage: %s [-y] DIR 's/REGEX/REPL/'\n" "${0##*/}" >&2; }
die()   { printf 'error: %s\n' "$*" >&2; exit 2; }

apply=0
while getopts ':yh' opt; do
    case $opt in
        y) apply=1 ;;
        h) usage; exit 0 ;;
        \?) die "unknown option -$OPTARG" ;;
    esac
done
shift $((OPTIND - 1))
dir=${1:-} expr=${2:-}
[[ -n $dir && -n $expr ]] || { usage; exit 2; }
[[ -d $dir ]] || die "not a directory: $dir"
[[ $expr == s/* || $expr == s\|* || $expr == s#* ]] || die "expression must start with s/ s| or s#"

mapfile -d '' -t files < <(find "$dir" -maxdepth 1 -type f -print0)
declare -A target=()
plan=()
for f in "${files[@]}"; do
    base=${f##*/}
    new=$(printf '%s\n' "$base" | sed -E "$expr") || die "sed failed for $base"
    [[ $new == "$base" ]] && continue
    [[ -n $new && $new != */* ]] || die "invalid target name: $new"
    if [[ -e $dir/$new || -n ${target[$new]:-} ]]; then
        die "collision: $new（一个都没改）"
    fi
    target[$new]=$f
    plan+=("$f" "$dir/$new")
done
for ((i = 0; i < ${#plan[@]}; i += 2)); do
    printf 'mv -- %q %q\n' "${plan[i]}" "${plan[i+1]}"
    if (( apply )); then mv -n -- "${plan[i]}" "${plan[i+1]}"; fi
done
```

关键点：`find -print0` + `mapfile -d ''` 处理空格/换行；`sed -E` 只作用于 basename，不碰目录；`declare -A target` 记录本轮已生成的目标名，防止 `a.JPG` 与 `a.jpg` 同时改成 `a.jpg`；`[[ -e ... ]]` 检查磁盘上已存在的目标；`mv -n` 再兜底，绝不覆盖。

**这里是两遍，不是一遍。** 第一遍只算新的名字、把所有冲突查完，攒进 `plan` 数组；第二遍才真正 `mv`。一遍到底的写法（算一个新的就改一个）看着更短，但**中途撞上冲突时，前面已经改掉的文件回不去**——作者第一版就踩了这个坑：目录里同时有 `a.JPG`、`b.JPG`、`a.jpg`，`-y` 跑完 `b.JPG` 已经变成 `b.jpg`，到 `a.jpg` 才报冲突退出。改成两遍之后，冲突在动手前就暴露（Ubuntu 实测）：

```text
$ bash rename-regex.sh . 's/\.JPG$/.jpg/'
error: collision: a.jpg（一个都没改）
rc=2
$ bash rename-regex.sh -y . 's/\.JPG$/.jpg/'
error: collision: a.jpg（一个都没改）
rc=2
$ ls
a.jpg  a.JPG  b.JPG
```

`ls` 的三行就是判据：加了 `-y` 也一样，`b.JPG` 没被动过。默认 dry-run，`-y` 才执行；sed 表达式由调用者提供，脚本只校验前缀，不防恶意正则——这是「可信运维脚本」的边界。

### 脚本三：`join-report.sh`——排序校验 + join + 缺失值

```bash
#!/usr/bin/env bash
# join-report.sh — 按第 1 列连接两个 TSV，缺失值填 0
# 用法: join-report.sh USERS.tsv ORDERS.tsv OUT.tsv
set -euo pipefail
users=${1:?usage: join-report.sh USERS.tsv ORDERS.tsv OUT.tsv}
orders=${2:?usage: join-report.sh USERS.tsv ORDERS.tsv OUT.tsv}
out=${3:?usage: join-report.sh USERS.tsv ORDERS.tsv OUT.tsv}
for f in "$users" "$orders"; do
    [[ -r $f ]] || { printf 'not readable: %s\n' "$f" >&2; exit 2; }
    LC_ALL=C sort -c -t $'\t' -k1,1 -- "$f" 2>/dev/null ||
        { printf 'not sorted by key: %s\n' "$f" >&2; exit 2; }
done

tmp=$(mktemp "${TMPDIR:-/tmp}/join.XXXXXX")
trap 'rm -f -- "$tmp"' EXIT

{
    printf 'user\tname\tamount\n'
    LC_ALL=C join -t $'\t' -a 1 -e 0 -o '1.1,1.2,2.3' -- "$users" "$orders"
} >"$tmp"
mv -- "$tmp" "$out"
printf 'wrote %s (%d rows)\n' "$out" "$(wc -l <"$out")"
```

关键点：`join` 要求两个输入按连接键排序，脚本先用 `sort -c` 验证，避免「看起来有输出但连接错位」；`-t $'\t'` 指定 tab，`-a 1` 保留左表全部行，`-e 0` 填缺失，`-o '1.1,1.2,2.3'` 明确输出列——**列号写错不会报错，只会输出错的内容**，作者第一版写成 `2.2`，表头是 `amount`、值却是 `sku`。`trap` 清理临时文件，`mv` 在同一目录内原子替换。若左表有重复键，`join` 会输出笛卡尔积；脚本不处理这种情况，需要时先用 `sort -u` 或 awk 聚合。

跑一遍（Ubuntu 实测）：

```text
$ bash join-report.sh users.tsv orders.tsv out.tsv
wrote out.tsv (5 rows)
$ cat out.tsv
user	name	amount
u1	Ada	3
u1	Ada	1
u2	Bob	2
u3	Cy	0
```

`u3` 没有任何订单，`-a 1` 让他留在结果里、`-e 0` 把缺的列填成 `0`；`u1` 两笔订单各占一行，这是 `join` 的语义而不是重复。行数 5 = 表头 1 + 数据 4。

CSV 的边界用 Python 演示，不要硬写 awk：

```bash
python3 - <<'PY'
import csv, sys
with open('in.csv', newline='', encoding='utf-8') as f, \
     open('out.tsv', 'w', newline='', encoding='utf-8') as g:
    r = csv.reader(f)
    w = csv.writer(g, delimiter='\t', lineterminator='\n')
    for row in r:
        w.writerow(row)
PY
```

`csv` 模块处理引号、转义、字段内换行；`awk -F,` 在这些情况下必然错位。判断标准：数据里出现引号或换行，就换工具。

::: errata 两个真犯过的错
1. **一遍到底的批量改名**。算一个新的改一个，遇到冲突时前面已经改完，回不去。改法是先攒 `plan` 再动手——本节脚本二就是这么改的。
2. **`join -o` 的列号写错不报错**。`2.2` 与 `2.3` 差一个数字，输出的却是一个字符串 vs 一个数字；表头对不上值时，第一件事是数 `-o` 里的列号，而不是怀疑 `join` 有 bug。
:::

### 0.6.17 小结

三个脚本共用同一套骨架：参数校验 → 预演（dry-run）→ 真正执行 → 用退出码说明结果。如果只记住一件事，那就是**先算完再动手**：无论改名、连接还是清理，只要动作不可回退，就先把它算成一份计划，检查完再执行。

**Q3（应用）** 你要写一个「把目录里所有 `.log` 按日期归档到 `logs/YYYY/MM/`」的脚本，按本节骨架，哪一步必须是「第一遍只算不动手」？

::: sol 答案
**A1** 都是「输入不合格、没有做任何改动」：参数缺失或不可读、目标名非法、目标已存在。dry-run 与 `-y` 的差别只在第二遍那一行——`(( apply ))` 为真才 `mv`，计划与打印完全一样。

**A2** 因为总数 `all` 只在 awk 的一次扫描里知道。拿到 shell 里算，要么再扫一遍文件，要么把 100 万行的计数传出来；写成函数就地计算，扫描次数保持一次。

**A3** 第一步：算出每个文件的目标路径，检查目标是否已存在、是否两个源文件撞到同一个目标、目录是否需要创建。这一步只读文件系统、不 `mv`；确认无误后再统一执行。
:::
:::

## 0.6.18 陷阱清单 {#sec-0.6.18}

这一节回答：这十四个坑里，哪几个会让你「命令跑通了、结果却是错的」？每一条的现象、原因与修法各是什么？

0.6.1–0.6.16 是按工具讲的；这一节按**症状**重排，把同一条误解在不同工具里的表现放在一起。读的时候先看粗体那句话能不能骗到你——骗到了，再去右边找修法。

::: preview 先抓住一件事
最贵的错不是报错，是**静默出错**：`grep -o` 少算一次重叠、`uniq` 没先排序、`diff` 把「有差异」当成失败。这一类错误都不会让脚本停下。
:::

::: errata 关于正则匹配的误解
1. **`grep 'a+'` 不匹配一个或多个 a**——BRE 里 `+` 是字面量；用 `grep -E 'a+'` 或 `grep 'a\+'`。
2. **`.` 不匹配换行**——sed/awk 默认逐行；跨行用 `N`、`RS` 或 PCRE `(?s)`。
3. **`grep -o` 不输出重叠匹配**——`echo aaa | grep -o 'aa'` 只出一个；需要重叠时用 PCRE 环视或自己写循环。
:::

::: errata 关于 sed 与 awk 的误解
1. **`sed -i` 在 GNU/BSD 上参数不同**——GNU `-i.bak` 可选后缀，BSD 必须 `-i ''`。
2. **`sed -i` 会断开硬链接**——它写临时文件再 rename；`ls -li` 能看到 inode 变化。
3. **`G` 在 hold space 为空时会加一个空行**——`sed 'G'` 每行后加空行，末行也会多一个换行。
4. **`/a/,/b/` 会反复进入范围**——每次匹配 `/a/` 都重新开始，直到下一次 `/b/`；不是只匹配第一次。
5. **awk 数组遍历无序**——`for (k in a)` 不保证插入顺序；排序交给 `sort`。gawk 的 `asort` 在 Ubuntu 默认的 mawk 上报未定义函数、`PROCINFO["sorted_in"]` 设了也不生效（Ubuntu 实测），想用它们得先 `apt install gawk`。
6. **遍历中 `delete a[k]` 行为未定义**——先收集键，再删；POSIX 不保证边遍历边删。
:::

::: errata 关于 sort、uniq 与 diff 的误解
1. **`sort` 默认按 locale**——`LC_ALL=C` 才是字节序；日志/ID 必须固定 locale。
2. **`uniq` 只删相邻重复**——不 `sort` 就 `uniq` 等于没删。
3. **`diff` 退出 1 是「有差异」不是错误**——`if diff -q a b; then` 只判断相同；错误是 2。
:::

### 0.6.18 小结

十四个坑可以归成两类：**语法层面的**（BRE 与 ERE 的元字符、`.` 不跨行、`sed -i` 的参数）与**语义层面的**（`uniq` 只删相邻、`diff` 的退出码、awk 遍历无序）。语法坑会报错或明显不对；语义坑不报错，只会给你一份看起来正常的错结果。如果只记住一件事，那就是**先问「这个命令失败时会怎么告诉我」**——不吭声的那个最危险。

::: method 即时自测 · 0.6.18
**Q1（记忆）** `uniq` 为什么要先 `sort`？`diff -q` 的三个退出码各表示什么？

**Q2（辨析）** `grep -o 'aa'` 对 `aaa` 只输出一次——是 bug 还是语义？想要两次该怎么写？

**Q3（应用）** 一个脚本用 `sed -i` 改配置文件，在 macOS 与 Ubuntu 上都要能跑。你至少要处理哪一处差异？

::: sol 答案
**A1** `uniq` 只比较相邻行，不相邻的重复它看不到，所以要先让相同行挨在一起。`diff`：0 = 相同，1 = 有差异，2 = 出错（文件不存在、权限等）。

**A2** 是语义：`grep -o` 找的是**不重叠**的匹配，从左到右吃掉 `aa` 后剩下的 `a` 不够再匹配一次。要两次就用 PCRE 环视 `grep -P '(?=(aa))'`，或自己写循环推进偏移。

**A3** `-i` 的可选后缀：GNU `sed -i.bak` 直接可用，BSD 必须写成 `sed -i ''`（或 `-i '.bak'`）。跨平台脚本里通常先判断 `sed --version`，或改用临时文件 + `mv`。
:::
:::

## 0.6.19 本章小结 {#sec-0.6.19}

这一节回答：这一章学完，你能独立做到哪几件事？哪些地方还只是「会用」，没到「能解释」？

这一章的骨架是**两层工具、一条主线**：正则决定「什么算匹配」，grep/sed/awk 决定「匹配到之后做什么」。前八节按工具讲用法，后八节按引擎与命令模型讲边界——BRE 与 ERE 的差别、sed 的地址与 hold space、awk 的数组与函数，最后用三个脚本把它们拼成流程。

::: preview 先抓住一件事
检验这一章有没有学会，不看你能背多少选项，而看**给你一份没见过的日志，你能不能一次写对那条流水线，并说清每一步为什么用它**。
:::

逐条打勾的达标表在[学习目标自检表](ch06-checklist.md)，那里每一行都写了「怎样算达标」和「没达标回到哪一节」。这里只留一条主线和一个判据：

- **主线**：能用正则描述你要找的东西 → 能选对工具（grep 筛、sed 改、awk 算）→ 能把它写成带参数校验与退出码的脚本。
- **判据**：给你一份没见过的日志，你能在不查手册的情况下写出「按状态码统计 5xx 比例、按 IP 排前 N」这一条流水线，并说清每个阶段为什么不用别的工具。

如果只记住一件事，那就是**先看数据长什么样，再选工具**：字段里带引号或换行就别用 `awk -F,`，要跨行匹配就别指望 `.`，要重叠匹配就别用 `grep -o`。

::: method 即时自测 · 0.6
**Q1** `grep '^a+' file` 为什么匹配不到 `aaa`？给出两种正确写法。

**Q2** `sed -n '1!G;h;$p'` 的作用是什么？如果文件只有一行，输出是什么？

**Q3** `awk '{c[$1]++} END {for (k in c) print c[k], k}'` 的输出顺序稳定吗？怎样得到按次数降序的结果？

**Q4** 要统计 CSV 第三列的总和，什么情况下 `awk -F,` 会算错？应该换什么工具？

::: sol 答案
**A1** 默认是 BRE，`+` 被当成普通字符，所以模式是「行首 a 后跟一个字面加号」。正确：`grep -E '^a+' file`，或 `grep '^a\+' file`（GNU BRE 扩展），或 `grep -P '^a+' file`。

**A2** 倒序输出文件。`1!G` 从第二行起把 hold space 追加到模式空间，`h` 把当前累积写回 hold，`$p` 在最后一行打印。只有一行时，`1!G` 跳过，`h` 保存该行，`$p` 打印，输出仍是这一行。

**A3** 不稳定。awk 的关联数组遍历顺序未定义，取决于哈希实现与键。要按次数降序：把输出交给 `sort -nr`，或在 gawk 里用 `PROCINFO["sorted_in"]`（非 POSIX；Ubuntu 默认 awk 是 mawk，这个设置不报错也不生效，见 0.6.6 的 Ubuntu 实测）。

**A4** 当字段内包含逗号且被引号包围时，`-F,` 会把一个字段拆成多个，列号错位；字段内有换行时更糟。用 Python 的 `csv` 模块、`mlr --csv` 或 `xsv`，不要用 `split`/正则硬解析。
:::
:::
