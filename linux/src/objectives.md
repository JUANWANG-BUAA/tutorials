## 2. K / S / A 三层目标

### K（Knowledge，知道什么）

- 掌握 Linux 的文件、进程、线程、内存、信号、IPC、socket 抽象及其边界；
- 掌握 x86-64 机器级程序的读法，能看懂编译器输出与崩溃栈；
- 掌握虚拟内存、页表、缺页、page cache、slab 的作用与相互关系；
- 掌握 TCP/IP 分层、TCP 状态机与拥塞控制、Linux 收发包路径；
- 掌握 namespace/cgroups/overlayfs 如何组成容器；
- 知道哪些内容是历史、为什么被替代。

### S（Skill，会做什么）

- 写正确、可移植、可观测的 C 系统程序；
- 用 `/proc`、`strace`、`perf`、`bpftrace`、`ss`、`tcpdump` 做排障；
- 读内核源码的关键路径，能定位函数与数据结构；
- 实现一个能跑的项目：容器运行时、HTTP 服务器、Redis、TCP 栈、Shell、Git 对象库等；
- 做压测、分析瓶颈、写复盘。

### A（Attitude，形成什么习惯）

- **证据优先**：先观测，再假设，再验证；不凭印象下结论；
- **边界意识**：每个 API 都问「失败时是什么语义」「并发时是否原子」；
- **最小权限**：默认不用 root，能用 capability 就不用 setuid；
- **可复现**：实验有脚本、有版本、有预期输出；
- **不迷信**：文档、博客、甚至本书都可能错，以规范和实验为准。

## 3. 三种掌握程度

每个知识点按三级要求：

| 级别 | 要求 | 检验方式 |
|:--|:--|:--|
| **L1 识别** | 听到名词知道在哪、干什么 | 选择题、术语表 |
| **L2 解释** | 能画出路径、说清边界、举出反例 | 简答、白板、回忆卡 |
| **L3 迁移** | 能在新场景里使用、排障、改造 | 项目、压测、故障注入 |

正文的 <span class="tag core">核心</span> 内容要求 L3；<span class="tag opt">选读</span> 要求 L2；<span class="tag legacy">历史</span> 只要求 L1。

## 4. 章节出口检查

每章末尾有一个「出口检查」小表，形式如下：

| 检查项 | 达标线 | 没达标去哪 |
|:--|:--|:--|
| 能说出 `write()` 返回后的三种可能状态 | 三种都说全 | 回看 2.2.4 |
| 能解释 `O_APPEND` 的原子性 | 能说出与 `lseek` 的区别 | 回看 2.3.1 |
| 能写出带 `EINTR` 重试的 `read` 循环 | 代码通过编译与测试 | 做 2.2 习题 C1 |

出口检查不是考试，而是**定位器**：没达标就回到指定小节，不要带着缺口往下走。

## 6. 学完后的自述

如果达到目标，你应该能用自己的话讲清下面这段，而不只是背名词：

> 我在终端敲下 `curl`，Shell 做变量与通配符展开，`fork` 出子进程，`exec` 加载 `curl`；动态链接器解析 `libcurl.so`，`curl` 调用 `socket/connect`，内核分配 `struct socket`，TCP 三次握手后把请求写进发送队列；网卡驱动通过 DMA 读走 `sk_buff`，对端回包触发中断，NAPI 轮询把包送进协议栈，`tcp_v4_rcv` 找到 socket，唤醒 `epoll_wait`；`curl` 把响应写进 stdout，`write` 进入 page cache，终端驱动把字节送到 pty。任何一步变慢，我都能用 `strace`、`perf`、`ss`、`tcpdump`、`/proc` 找到证据。

这段话就是全书的压缩版。学完后，回到这里再读一遍，看看哪些环节你还能讲得更细。
