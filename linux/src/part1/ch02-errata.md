# 1.2 勘误与版本注记

这一页收本章最容易「记成永久真理」的版本敏感事实与表示陷阱。正文里的 `errata` 盒讲理解陷阱；这一页讲**换编译器、换架构、换语言后要复核什么**。

**本章基线**：Ubuntu 24.04、gcc 13.2、glibc 2.39、x86-64 LP64、C17。换环境时逐条复核。

## 1. 整数与位运算

| # | 看起来像 | 实际是 | 怎么验证 |
|--:|:--|:--|:--|
| 1 | `int` 永远是 4 字节 | C 标准只给最小范围；LP64/ILP32/LLP64 不同 | `sizeof(int)`、`getconf LONG_BIT` |
| 2 | 补码范围对称 | `[-2^(w-1), 2^(w-1)-1]`，负数多一个 | `limits.h`、`-INT_MIN` 测试 |
| 3 | 有符号溢出会回绕 | 有符号溢出是 UB；无符号才回绕 | UBSan、`-ftrapv` |
| 4 | 移位只是乘除 2 | 移位数负数/≥位宽是 UB；有符号右移实现定义 | `1<<32`、`-1>>1` 测试 |
| 5 | `int` 与 `unsigned` 比较安全 | 整数提升/转换会把负数变大正数 | `-1 < 1u` 测试 |
| 6 | `x & -x` 只是取负 | 取出最低位 1；`x=0` 时为 0 | 打印位模式 |

## 2. 字节序、布局与浮点

| # | 看起来像 | 实际是 | 怎么验证 |
|--:|:--|:--|:--|
| 7 | 内存按大端排 | x86-64/ARM64 通常小端；网络字节序大端 | `xxd`/`od`、union |
| 8 | 结构体大小=字段和 | 有对齐/padding/尾部 padding | `sizeof`、`offsetof`、`pahole` |
| 9 | `#pragma pack` 总是安全 | 可能破坏对齐/性能/原子性；跨平台不一致 | `alignas`、`offsetof` |
| 10 | float 指数偏置是 128 | float 127、double 1023 | `float.h`、位模式 |
| 11 | 非规格化数没用 | 表示 0 附近/逐渐下溢；影响精度 | `%a`、位模式 |
| 12 | NaN 等于自己 | NaN 与任何值比较都为假 | `isnan`、`x==x` |
| 13 | `0.1+0.2` 应该等于 0.3 | 二进制浮点不能精确表示；舍入 | 打印 `%.17g`、ULP |
| 14 | `-0.0 == 0.0` 不成立 | 比较为真，但符号位不同 | `1/x`、`signbit` |
| 15 | `repr(C)` 只是优化 | 固定 C 布局，FFI 必须；默认 Rust 可重排 | `offsetof`/`sizeof` 两边对比 |
| 16 | C 的 UB 在 Rust 也一样 | Rust 安全代码禁止 UB；`checked_*` 明确 | Miri/UBSan |

## 3. 工具与观测

| # | 看起来像 | 实际是 | 怎么验证 |
|--:|:--|:--|:--|
| 17 | `gdb` 看到的就是源码值 | 优化会改变量/重排；本机 gdb 15.1 + aarch64 无 SVE 时连变量/`info locals` 都报 SVE 错误 | `-O0 -g`、UBSan、`offsetof`、DWARF |
| 18 | `objdump` 的常量就是源码 | 编译器可能优化/合并/重排 | `-O0`/`-O2` 对比 |
| 19 | `pahole` 到处能用 | 需要调试信息；不同版本输出不同 | `pahole --version` |
| 20 | 对齐只影响性能 | 还可能影响原子性/ABI/FFI 正确性 | `alignas`、`static_assert` |
| 21 | `int` 宽度跨平台一样 | Windows LLP64 的 `long` 是 4 字节 | `sizeof`、`stdint.h` |
| 22 | 浮点结果跨平台一致 | 依编译器/FP 模式/架构（x87/SSE/NEON） | 固定 `-ffp-contract`/`-frounding-math` |

## 4. 本章未实测项

以下结论来自文档与常见行为，但未在本书写作环境逐条复跑；在别的编译器/架构上使用前先验证：

- C 标准只规定最小范围/UB；具体宽度/补码/右移依实现（C23 起补码更明确）。
- `float`/`double` 的 IEEE 754 依平台；x87 80 位扩展精度可能影响中间结果。
- 结构体布局/对齐依 ABI（SysV/Windows）；`repr(C)`/`bindgen` 为准。
- `pahole`/`gdb`/`objdump` 的输出依版本/调试信息。
- Rust 的 `repr(C)`/`repr(align)`/UB 规则依版本；Miri 能查部分 UB，不是全部。

## 5. 发现新问题怎么记

如果你在别的编译器/架构上发现本章结论不成立，按「现象 → 命令/输出 → 版本/架构 → 建议改法」记到 issue 或笔记里；不要只写「我这里不对」。这张表下一轮会按同一格式增补。
