## A. 组成、ISA 与契约

::: method 回忆 1 · 组成的最小模型与执行循环
一台能跑 Linux 的机器，抽象到足够写系统程序，最少要有哪五件东西？程序执行的最小循环是什么？为什么说乱序执行没有破坏「顺序语义」？
::: sol 答案
五件：寄存器文件（16/31/32 个通用寄存器 + PC + 标志）、ALU/乘法器/浮点单元、控制单元（取指、译码、发射、退休）、MMU（页表基址、TLB、权限检查）、存储与 I/O 通路（L1 I/D → L2 → L3 → DRAM，外接中断控制器 APIC/GIC/PLIC 与定时器、设备）。最小循环：`PC → 取指 → 译码 → 取操作数 → 执行 → 访存 → 写回 → PC+4/跳转`。现代 CPU 把这条顺序流水拆成十几级并允许乱序，但**退休必须按程序顺序**，异常和中断看到的仍是顺序状态；编译器和内核依赖这个假象，只有屏障、原子指令和 `volatile`/`asm!` 才需要关心真实顺序。
:::
:::

::: method 回忆 2 · ISA 规定哪五类东西，三套骨架差在哪
ISA 作为软硬件契约，规定哪五类内容？x86-64、ARM64、RISC-V 64 在指令长度、通用寄存器、链接寄存器、零寄存器、特权级上各是什么？
::: sol 答案
五类：有哪些寄存器及位宽用途；指令如何编码（定长/变长）与寻址方式；哪些指令只能在特权级运行（`syscall`/`svc`/`ecall`、`in`/`out`、页表写）；内存模型、原子指令、异常/中断入口；调用约定虽不属于 ISA，但由寄存器与栈规则派生。骨架：x86-64 变长 1–15 字节、16 个通用寄存器、返回地址在栈上、无零寄存器、ring 0–3；ARM64 定长 4 字节、31 个（`x0`–`x30`）、链接寄存器 `x30`、零寄存器 `xzr`、EL0–EL3；RISC-V 64 定长 4 字节（C 扩展可 2 字节）、32 个（`x0`–`x31`，`x0` 恒 0）、`ra` 即 `x1`、`x0` 为零寄存器、M/S/U。
:::
:::

::: method 回忆 3 · `sum3` 的三套汇编与字节数
`long sum3(long a,long b,long c)` 在三套 ISA 上各编成什么？各多少字节？差别到底在哪？三种 `ret` 分别做什么？
::: sol 答案
x86-64：`lea (%rdi,%rsi),%rax; add %rdx,%rax; ret`，8 字节；ARM64：`add x0,x0,x1; add x0,x0,x2; ret`，12 字节；RISC-V：`add a0,a0,a1; add a0,a0,a2; ret`，12 字节（默认 `rv64gc` 含压缩指令时 6 字节）。差别不在加法，在参数放哪（`rdi/rsi/rdx` 对 `x0/x1/x2` 对 `a0/a1/a2`）、返回值放哪（`rax`/`x0`/`a0`）、返回地址放哪（栈 / `x30` / `ra`）。三种 `ret`：x86 从栈顶弹出返回地址到 `rip`；ARM64 跳到 `x30`；RISC-V 是伪指令，展开成 `jalr x0, 0(ra)`。
:::
:::

::: method 回忆 4 · 三张调用约定表
整数参数、浮点参数、返回值、被调用者保存、调用者保存、返回地址、栈对齐、红区，三套 ABI 各是什么？
::: sol 答案
整数参数：`rdi,rsi,rdx,rcx,r8,r9` / `x0`–`x7` / `a0`–`a7`。浮点：`xmm0`–`xmm7` / `v0`–`v7` / `fa0`–`fa7`。返回：`rax`（`rdx:rax`）/ `x0`（`x1:x0`）/ `a0`（`a1:a0`）。被调用者保存：`rbx,rbp,r12–r15` / `x19`–`x29` / `s0`–`s11`。调用者保存：其余 / `x0`–`x18` / `t0`–`t6` 与 `a0`–`a7`。返回地址：栈（`call` 压入）/ `x30` / `ra`（`x1`）。栈对齐都是 16 字节（ARM64 要求任何时刻）。红区：x86-64 128 字节，叶函数可用；ARM64/RISC-V 没有，`sp` 以下不可写。
:::
:::

::: method 回忆 5 · 三条陷入指令与系统调用号
`write(1,msg,len)` 在三套 ISA 上各用什么指令、号放哪、参数放哪、失败怎么表示？为什么号不同？x86 系统调用的第 4 个参数为什么不是 `rcx`？
::: sol 答案
x86-64：`syscall`，号在 `rax`（`write`=1），参数 `rdi,rsi,rdx,r10,r8,r9`；ARM64：`svc #0`，号在 `x8`（`write`=64），参数 `x0`–`x5`；RISC-V：`ecall`，号在 `a7`（`write`=64），参数 `a0`–`a5`。返回分别在 `rax`/`x0`/`a0`，失败统一写成 `-errno`。号是内核 ABI 不是 ISA：同一台机器上 x86-64 的 `write` 是 1，ARM64 与 RISC-V 遵循 asm-generic 是 64；`openat` 等编号可能不同，跨架构用 `SYS_write`/`syscall()`，不要硬编码。x86 的 `syscall` 会把 `rcx`（返回地址）和 `r11`（标志）覆盖，所以第 4 个参数改用 `r10`——这是函数调用表与系统调用表最容易混的一格。
:::
:::

::: method 回忆 6 · 交叉编译工具链与读汇编的顺序
把 `sum3.c` 编到三套架构，有哪几条命令？没有硬件时怎么跑？拿到一段陌生汇编，按什么顺序读？
::: sol 答案
本机：`cc -O2 -S sum3.c -o sum3.s`；交叉 gcc：`aarch64-linux-gnu-gcc -O2 -S ...`、`riscv64-linux-gnu-gcc -O2 -S ...`；Clang 直接指定 target：`clang --target=aarch64-linux-gnu -O2 -S ...`、`clang --target=riscv64-linux-gnu ...`（没有完整 sysroot 也能看汇编，但不能链接）。反汇编与 ELF：`objdump -d sum3`、`readelf -h sum3`。没有硬件用 QEMU 用户态：`qemu-aarch64 -L /usr/aarch64-linux-gnu ./sum3`、`qemu-riscv64 -L ...`。读汇编五步：先按 ABI 表找参数寄存器；再找返回值寄存器与 `ret`/`jr ra`；再找栈调整（`sub rsp`/`stp x29,x30`/`addi sp,sp,-N`）画栈帧；再找内存访问（`[]`/`()`/`lw/sw`）确认基址与偏移；最后才看算术与分支。
:::
:::

## B. 频率、流水线、乱序与 cache

::: method 回忆 7 · 频率上限与 241 ps
`T_clk` 的不等式是什么？7 nm 例子 `T_cq=30 ps`、14 级 FO4（每级 9 ps）、连线 40 ps、`T_setup=20 ps`、skew 15 ps、jitter 10 ps，频率上限是多少？为什么 7 nm 表里的频率只是量级？
::: sol 答案
`T_clk ≥ T_cq + T_logic,max + T_setup + T_skew + T_jitter`。代入：30 + 126 + 40 + 20 + 15 + 10 = 241 ps，`f_max ≤ 1/241 ps ≈ 4.15 GHz`。后两项是物理税：时钟树到达不同触发器的时间不一致（skew），电源噪声与温度让周期抖动（jitter），设计必须按最坏情况留余量，所以标称 5 GHz 的芯片可持续频率往往只有 4.2–4.6 GHz。7 nm 表里的 4.2–5.0 GHz、Vdd 0.75–0.85 V、漏电 25–40% 是公开资料的数量级；具体库、电压点、温度会让结果偏移 20% 以上，工艺节点名（Intel 7、TSMC N7、Samsung 7LPP）也不是同一个物理量。
:::
:::

::: method 回忆 8 · 功耗的两项与两个数
总功耗公式是什么？3 GHz、1.0 V、等效开关电容 200 nF、活动因子 0.1 的芯片，动态功耗多少？漏电占 25% 时总功耗多少？电压降到 0.85 V 后动态功耗多少？
::: sol 答案
`P_total = α C_eq V² f + I_leak V`，前一项动态、后一项静态。动态：`0.1 × 200 nF × 1² × 3 GHz = 60 W`；漏电占 25% 意味着总功耗 `60 / 0.75 = 80 W`（漏电 20 W）。电压降到 0.85 V，动态按 `V²` 变成 `60 × 0.7225 ≈ 43 W`；但 `f_max` 也会下降，降压与提频不能同时要。只降频不降压时，静态功耗占比反而上升，所以「降频一定省电」不成立。
:::
:::

::: method 回忆 9 · 五级流水的周期数与 CPI
`n` 条指令、`k` 级流水、无停顿的周期数公式是什么？5 条指令、1000 条指令各多少周期、CPI 多少？相对非流水线（每条 5 拍）的加速比是多少？三类冒险各举一例与一个解法。
::: sol 答案
`cycles = k + (n−1) + stalls`，`CPI = 1 + stalls/n`（无停顿时 CPI = 1 + (k−1)/n）。5 条：9 周期；1000 条：1004 周期，CPI 1.004；非流水线 5000 周期，加速 4.98 倍，极限是 5。冒险：结构（取指与访存抢端口、除法器只有一个；解法：分离 I/D cache、多端口、加执行单元）；数据 RAW（`add %rax,%rbx` 后紧跟 `mov %rbx,%rcx`；转发可免停顿，load-use 要停 1 拍）；控制（分支结果未出，惩罚 15–20 拍；分支预测、延迟槽、谓词执行）。WAW/WAR 在寄存器重命名后消失。
:::
:::

::: method 回忆 10 · 两位预测器与 CPI 表
两位饱和计数器有哪四个状态、怎么迁移？分支占 20%、误预测惩罚 15 拍，准确率 99%/95%/90%/80% 时总 CPI 各是多少？99%→90% 与 5%→1% 的收益为什么不对称？
::: sol 答案
四状态：强不跳、弱不跳、弱跳、强跳；实际方向每次移动一格，只有跨过中点才改变预测。两位让循环边界只错两次（进入与退出）。误预测率 = 1−准确率；额外 CPI = 0.20 × 误预测率 × 15。99% → 0.030 → 1.03；95% → 0.150 → 1.15；90% → 0.300 → 1.30；80% → 0.600 → 1.60（这是 `n→∞` 的渐近值，有限 `n` 还要加流水线填充）。99%→90% 性能损失 `1.30/1.03 − 1 ≈ 26%`；5%→1% 只收回 `1.15/1.03 − 1 ≈ 12%`。原因是前者把误预测率翻了三倍，后者只是从 5% 压到 1%，而基数已经很小——优化要挑「占比大、惩罚重」的那一项。
:::
:::

::: method 回忆 11 · 乱序窗口与依赖链
乱序执行的前端/后端各做什么？ROB、保留站、物理寄存器堆、加载/存储缓冲的典型容量是多少？整数 add、imul、浮点 add、L1 加载的延迟与吞吐各是多少？为什么四条累加链比一条快？
::: sol 答案
前端按程序顺序取指、译码、重命名；后端在操作数就绪时乱序发射，但退休按程序顺序，异常也按序。Skylake 级容量：µop cache 1536 µops、ROB 224 条、保留站约 97 项、物理寄存器 168 整数 + 168 向量、加载/存储缓冲 72/56。延迟/吞吐：整数 add 1 拍/4 条每拍；imul 3 拍/1 条；浮点 add/mul 4 拍/2 条；FMA 4 拍/2 条；L1 加载 4–5 拍/2 条。`sum += a[i]` 若是 `float`，每次加法等上一次的 4 拍，吞吐被压到 0.25 条/拍；拆成 4 条独立链可 4 拍后各自出结果，平均 1 条/拍；拆成 8 条达到 2 条/拍的发射上限。重命名消除 WAW/WAR，RAW 依赖链仍串行。
:::
:::

::: method 回忆 12 · 32 KiB、8 路、64 B 的地址拆分
组数、offset、index、tag 各多少位？地址 `0x0000_7fff_1234_5678` 的三个字段各是什么？为什么 9 个相距 4 KiB 的数组会冲突？怎么改？
::: sol 答案
组数 `32 KiB / (8 × 64 B) = 64`；offset `log2 64 = 6`；index `log2 64 = 6`；tag `48 − 6 − 6 = 36`。地址低 12 位是 `0x678`：offset `0x678 & 0x3f = 0x38`（56），index `(0x678 >> 6) & 0x3f = 25`，tag `0x7fff12345678 >> 12 = 0x7fff12345`。同一组只要求 index 相同，也就是低 12 位中的第 6–11 位相同；4 KiB 的整数倍只改 tag、不改 index，8 路只能放 8 个 tag，第 9 个流会把最早的那个挤出去，之后每次访问都 miss——这是冲突缺失，容量明明够却用不上。改法：数组间距改成 4 KiB + 64 B（改变 index），或把 9 个流分块处理。
:::
:::

::: method 回忆 13 · AMAT 与局部缺失率
AMAT 的递归公式是什么？L1 4 拍、局部缺失率 5%，L2 12 拍、20%，L3 40 拍、10%，DRAM 200 拍，AMAT 多少？L1 缺失率降到 2%、L2 命中时间降到 8 拍，各变成多少？
::: sol 答案
`AMAT = t_L1 + m_L1(t_L2 + m_L2(t_L3 + m_L3 × t_DRAM))`。代入：`4 + 0.05 × (12 + 0.2 × (40 + 0.1 × 200)) = 4 + 0.05 × 24 = 5.2` 拍。L1 缺失率 2%：`4 + 0.02 × 24 = 4.48` 拍，快约 14%；L2 命中时间 8 拍：`4 + 0.05 × (8 + 0.2 × 60) = 5.0` 拍，只快约 4%。降低缺失率通常比降低命中时间更划算，因为缺失代价被放大了一次。式中的 `m` 必须是**局部缺失率**（本层 miss / 本层访问），用全局缺失率会把 AMAT 算小。
:::
:::

## C. 栈帧、编码、内存模型与实验

::: method 回忆 14 · 第 7、8、9 个参数与红区
一个函数有 9 个 `long` 参数，第 7、8、9 个在三种 ABI 下分别从哪里取？x86-64 的红区是什么？ARM64/RISC-V 为什么不能往 `sp` 以下写？
::: sol 答案
x86-64 只有 6 个整数参数寄存器：第 7–9 个走栈，入口时 `[rsp+8]`/`[rsp+16]`/`[rsp+24]`（`call` 先压了 8 字节返回地址），`push rbp` 建帧后是 `[rbp+16]`/`[rbp+24]`/`[rbp+32]`。ARM64 有 8 个：第 7、8 个仍在 `x6`/`x7`，第 9 个在入口 `[sp]`，建帧后 `[sp+32]`。RISC-V 也有 8 个：第 7、8 个在 `a6`/`a7`，第 9 个在入口 `0(sp)`，建帧后 `32(sp)`。红区是 x86-64 SysV 允许叶函数在 `rsp` 以下 128 字节内暂存、不调整 `rsp` 的约定，信号处理会避开；ARM64/RISC-V 的 ABI 没有这个约定，`sp` 以下不保证安全，任何写栈都要先减 `sp`。**注意：正文 1.14.11 的表把第 7、8 参数写成 ARM64/RISC-V 的栈参数，那是按 x86 的 6 个寄存器上限套过来的；以 1.14.4 与 1.14.16 的 A2 为准，实测见勘误页第 1 条。**
:::
:::

::: method 回忆 15 · 结构体按值传递的分类
≤16 B 的结构体、>16 B 的结构体、HFA、小结构体返回、可变参数，三套 ABI 各怎么处理？
::: sol 答案
≤16 B 的整数/指针结构体：x86-64 拆成 1–2 个八字节、按 INTEGER 类走寄存器（浮点字段走 SSE）；ARM64 按 8 B 对齐放 `x0`–`x7`；RISC-V 按 XLEN 放 `a0`–`a7`。>16 B：三家都走内存，传隐式指针（RISC-V 的门槛是 >2×XLEN）。HFA（1–4 个 `float`/`double`）：x86-64 用 SSE 寄存器，ARM64 `v0`–`v3`，RISC-V `fa0`–`fa3`。小结构体返回：`rax:rdx` / `x0:x1` / `a0:a1`。可变参数：x86-64 用 `%al` 记录用了多少个向量寄存器，ARM64/RISC-V 无特殊要求。判据是分类规则，不是字节数一个数。
:::
:::

::: method 回忆 16 · 三种编码手算
`mov 0x10(%rdi,%rsi,4),%eax` 的四个字节是什么？`add x0,x0,x1`、`ldr x0,[x1,#8]`、`add x0,x0,#1` 的 32 位字面值是什么？RISC-V 六种格式的立即数范围与 `add a0,a0,a1`、`addi a0,a0,1`、`sd ra,8(sp)` 的编码是什么？
::: sol 答案
x86：`8b 44 b7 10`；`8b` 是 opcode，`44` 是 ModR/M（mod=01、reg=000、r/m=100 有 SIB），`b7` 是 SIB（scale=2 即 ×4、index=110 即 `rsi`、base=111 即 `rdi`），`10` 是 disp8；有效地址 `rdi + rsi×4 + 0x10`。ARM64：`add x0,x0,x1` = `0x8B010000`；`ldr x0,[x1,#8]` = `0xF9400420`（imm12=1，按 8 缩放）；`add x0,x0,#1` = `0x91000400`（立即数版是另一编码族）。RISC-V：R 型无立即数；I 型 12 位有符号（±2048）；S 型 12 位有符号；B 型 13 位有符号、2 的倍数（±4 KiB）；U 型 20 位左移 12；J 型 21 位有符号、2 的倍数（±1 MiB）。`add a0,a0,a1` = `0x00B50533`；`addi a0,a0,1` = `0x00150513`；`sd ra,8(sp)` = `0x00113423`（imm 拆成 `imm[11:5]` 与 `imm[4:0]`）。
:::
:::

::: method 回忆 17 · 三套内存模型与屏障
x86-64（TSO）、ARM64、RISC-V（RVWMO）各允许哪些重排？Dekker litmus 的 `r1=r2=0` 在三种架构上各靠什么指令排除？为什么 QEMU 不能验证弱内存模型？
::: sol 答案
TSO：禁止 Load→Load、Load→Store、Store→Store，只允许 Store→Load；ARM64 与 RVWMO 四类都允许。Dekker（P0: `X=1; r1=Y`，P1: `Y=1; r2=X`）在 x86 上要 `mfence`（或把 store 换成 `xchg` 等 `lock` 指令），ARM64 用 `dmb ish`，RISC-V 用 `fence rw,rw`（或带 acquire/release 语义的指令）。C11 写 `atomic_store_explicit(..., relaxed)` + `atomic_thread_fence(seq_cst)` 可以跨架构。QEMU 用户态不是架构内存模型的参考实现，真机碰运气也不严谨；严谨验证用 `herd7` 的架构模型（如 `x86tso.cat`）。`volatile` 只约束编译器，不是 CPU 屏障。
:::

::: method 回忆 18 · 三架构实验的产物与原子指令
`sum3` 三套目标文件的指令条数与字节数各是多少？ELF `Machine` 号、`write`/`exit` 的调用号各是多少？`size_lab` 的预期量级是多少？原子加、CAS、全屏障在三套 ISA 上各是什么指令？
::: sol 答案
`sum3` 都是 3 条：x86-64 8 字节，ARM64 12 字节，RISC-V 12 字节（默认 `rv64gc` 6 字节）。`Machine`：x86-64 62、ARM64 183、RISC-V 243。`write` 号 1/64/64，`exit` 号 60/93/93。`size_lab` 预期量级：x86-64 的 `sum_array` 约 30–40 字节，ARM64 约 40–48 字节，RISC-V 开 RVC 约 24–32 字节；展开版更大但循环开销更少，是否更快必须实测。原子加：`lock add` / `ldadd`（或 `ldxr+stxr`）/ `amoadd.w/d`；CAS：`lock cmpxchg` / `cas`（或 `ldaxr+stlxr`）/ `lr+sc`；全屏障：`mfence` / `dmb ish` / `fence rw,rw`。原子指令的代价在缓存行独占，多核 CAS 同一行会来回弹跳；用分片计数器、per-CPU 变量或 RCU 绕开，`perf c2c` 看 HITM（本环境 `perf` 不可用，按未实测）。
