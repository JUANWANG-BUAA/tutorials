# 1.13 章末总结

## 五段浓缩

| 单元 | 小节 | 核心问题 | 关键结论 | 最容易错的地方 |

| **一、地图与三件事** | 1.13.1 | 操作系统同时在解决哪三类矛盾？机制与策略怎么分工？ | 三大主题是虚拟化（CPU + 内存）、并发、持久化。虚拟化 CPU 的机制是「受限直接执行 + 定时器中断 + 上下文保存」，策略是调度；虚拟化内存的机制是「页表 + TLB + 缺页异常」，策略是页替换；并发的机制是「原子指令 + 等待队列」，策略是锁粒度与等待方式；持久化的机制是「DMA + 中断 + 日志」，策略是布局与回写时机。三块代码互相调用：缺页要用进程上下文，page cache 属于虚拟内存，锁要用原子指令。 | 把三块当成三个互不相干的模块；只记名词不记「机制/策略」的归属；以为启动流程与三件事无关（启动顺序正是页表 → init → 驱动与根文件系统）。 |
| **二、虚拟化 CPU** | 1.13.2、1.13.9 | 周转与响应怎样互相拉扯？按权重分配为什么选 `vruntime`？ | 周转 = 完成 − 到达，响应 = 首次运行 − 到达。A(0,10)、B(1,5)、C(2,2) 三个任务：FIFO 平均周转 13、平均响应 7.33；SJF 12 与 6.33；RR(片长 2) 11 与 1。FIFO 的护航效应、SJF 的预知要求、RR 的片长两难，最后都落到 MLFQ 的五条规则上，其中「周期提升」防饥饿与 gaming，不是可选项。彩票调度靠抽签、份额有 `1/sqrt(n)` 量级的抖动；步长调度确定性收敛；CFS 用 `vruntime += delta × (NICE_0_LOAD / weight)` 选最小者，nice 每差 1 权重约乘 1.25，nice −20 与 19 的权重是 88761 与 15。多核还有 SQMS、MQMS、work stealing 三选一。 | 拿周转时间比较 RR 与 CFS；以为 MLFQ 的参数可以随便砍；以为彩票调度的短期偏差是 bug；以为「加核」一定更快（亲和性与负载均衡另有代价）。 |
| **三、虚拟化内存** | 1.13.3、1.13.3.1、1.13.3.2、1.13.10 | 分段/分页/交换各还什么债？页框多了缺页为什么还多？ | 分段还「代码/堆/栈分开」的债，代价是外部碎片；分页消灭外部碎片，代价是页表空间与 TLB 压力；交换把「物理内存不够」变成「缺页 + I/O」，代价是几十微秒到几毫秒。换入路径五步：present=0 → 查 swap 槽 → 分配物理页 → 读回并改 PTE → 用户态重试。同一套机关还派生三个技巧：按需清零、写时复制、聚簇换入。EMAT 算式把 TLB 命中率换算成纳秒：99% 命中约 102 ns，掉到 90% 约 111 ns。替换算法里 OPT/LRU 是栈算法，FIFO 不是，所以 Belady 异常只出现在非栈算法上：经典引用串在 3 个页框下 FIFO 缺页 9 次，4 个页框下 10 次。 | 以为 LRU 能直接上硬件（没有精确时间戳）；把 `mmap` 当「立刻分配物理页」；以为 swap 越大越不卡（工作集超物理内存就是 thrashing）；把 Clock 当严格 LRU（它只是近似，本例与 FIFO 同为 9→10）。 |
| **四、机制补全与持久化** | 1.13.4、1.13.5、1.13.5.1–1.13.5.3、1.13.8、1.13.11 | PCB 与 PTE 的哪些位在起作用？一次随机读的 12 ms 花在哪？日志的提交点为什么是唯一分界？ | 并发 bug 分五类：原子性违反、顺序违反、死锁、活锁、饥饿，各有典型修法。磁盘一次 4 KiB 随机读 = 寻道 8 ms + 旋转 4.17 ms + 传输 0.04 ms ≈ 12 ms（约 83 IOPS），顺序读只要 0.04 ms，差两个数量级——这是 WAL、LSM、LFS 存在的理由。RAID 0/1/5/6/10 在容量、容错、写代价上各让一步，且 RAID 不是备份。PCB 的字段按生命周期分四组（状态、身份与地址空间、资源、调度），`R` 同时表示「在跑」与「在队列里等」。PTE 的低 12 位里，`P` 触发缺页、`RW` 支撑 COW、`A/D` 由 CPU 置位给 Clock 与回写用、`NX` 支撑 W^X。redo 日志四步：写日志 → 写提交记录（唯一原子分界）→ checkpoint → 回收；恢复只有两条规则：有提交就重放（必须幂等），没有就丢弃。 | 把 `data=ordered` 当「数据一定落盘」（它只保证数据先于元数据提交）；`rename` 之后忘记 `fsync` 目录；把 `fsync(fd)` 当「整个文件系统都安全」；以为日志能保证应用语义（它只保证结构一致）；把 `R` 当「正在使用 CPU」。 |
| **五、落点与小内核** | 1.13.6、1.13.7、1.13.12–1.13.16 | 8 个项目各改哪个结构？OSTEP 的 50 章落在哪？实验能观测到什么？ | 李治军的 8 个项目从引导扇区一路做到驱动，每个都有「目标 / 关键结构 / 实现路径 / 验收证据」：启动看 `%cr0.PE`，系统调用看 `sys_call_table` 与 `-ENOSYS`，多进程看 COW，切换看 `%esp` 与 `switch_to`，同步看 `sleep_on/wake_up`，共享看 PFN，换入换出看 `pswpin/pswpout`，驱动看 `dd` 校验与中断计数。OSTEP 50 章按四档落点：虚拟化密集落在 1.1、1.9、1.13；并发落在 1.12；持久化落在 1.13.5 与 1.13.11；分布式 46–50 超出主线。xv6 的 `proc.c`/`vm.c`/`log.c` 三份文件覆盖进程、内存、持久化，是「验证你懂了」的最短路径。 | 通读 OSTEP 50 章；把「小内核」当「简单内核」（它们省略了性能与硬件多样性）；以为 8 个项目只是课堂作业（每个都对应一个 Linux 子系统的骨架）；跳过 OSTEP 的模拟器作业。 |

## 一条主线

这一章从「六个切面」走到「一张总图」：**先把操作系统压成三件事，并给每件事配上「机制 / 策略」两个抽屉（1.13.1）；再沿 CPU → 内存补策略侧——调度用指标取舍，页替换用命中率取舍（1.13.2、1.13.9、1.13.3、1.13.10）；然后把策略钉回机制：PCB 的字段决定状态机怎么走，PTE 的位决定缺页与 COW 怎么发生，日志的提交点决定崩溃后重放还是丢弃（1.13.8、1.13.5、1.13.11）。**最后用 8 个项目、两个小内核、三个实验与十五条陷阱，把「模型」变成「代码」再变成「证据」（1.13.6、1.13.13、1.13.14、1.13.15）。

如果只记一句话：**看到一个操作系统问题，先问它属于哪件事（虚拟化 / 并发 / 持久化），再问它卡在机制还是策略，最后问证据在哪。**

这三问覆盖本章大多数场景：CPU 分不匀是策略（1.13.2、1.13.9），内存见底是机制与策略同时到界（1.13.3、1.13.10），文件"写成功却没了"是持久化的边界（1.13.11），容器里限额不生效是策略被换了一套表达（1.13.15 与第 5 篇的 cgroup）。**三件事之间还有两条暗线**：page cache 让持久化借用虚拟内存的页，锁让并发借用虚拟化的原子指令；读第 3 篇时会反复回到这两条线上。

## 症状 → 机制 → 命令

| 症状 | 机制 | 先跑什么 |
|:--|:--|:--|
| 两个不同 nice 的忙循环各占 100% CPU，权重像没生效 | 每个核一个运行队列，两个进程被分到不同核，各自跑满 | `taskset -c 0` 绑到同一个核再比。VM 实测 nice 0 与 nice 10 为 90.1% 与 9.7%，`se.sum_exec_runtime` 9034.216380 ms 对 974.130957 ms（9.3 倍） |
| 改了 nice，份额仍不变 | 容器 `cpu.max` 限流、cgroup `cpu.weight` 覆盖，或父进程的 `vruntime` 被继承 | `cat /proc/<pid>/cgroup` 找到自己的 cgroup，再读 `cpu.max`、`cpu.weight`、`cpu.stat` 的 `throttled_usec`；VM 实测会话 scope 是 `max 100000`、`cpu.weight 100` |
| `nproc` 说 4 核，进程只跑出 1 核的量 | `sysconf`/`nproc` 读的是宿主或 affinity，不是配额 | 读 `cpu.max` 的 quota/period 算核数；`taskset -pc $$` 看亲和性 |
| 内存一直降，`si`/`so` 持续非零 | 工作集超过物理内存，开始 thrashing | `vmstat 1` 看 `si/so` 与 `free`；`/proc/vmstat` 的 `pswpin/pswpout` 是累计页数（不是字节） |
| 页框从 3 加到 4，缺页反而多一次 | FIFO 不是栈算法，Belady 异常 | 跑 `page_repl.c`：VM 实测 FIFO 9→10、OPT 7→6、LRU 10→8、Clock 9→10 |
| `mmap` 完 RSS 就涨了，以为分配了物理页 | 惰性分配，第一次写才缺页补页 | 读 `/proc/self/stat` 的 minflt（第 10 字段）前后差值。VM 实测 64 MiB 映射只多 11 次 fault，逐页写后正好多 16384 次，RSS 从 1340 kB 到 66944 kB |
| 程序说写成功，断电后文件没了 | 只落到 page cache；没有 `fsync`，或没有 `fsync` 目录 | `strace -f -e trace=%file ./aw data.bin x`：VM 实测两次 `fsync`（文件 fd 3、目录 fd 3）+ 一个 `renameat`；`filefrag -v` 确认 extent 已分配 |
| `rename` 报 `EXDEV`，跨目录"替换"没生效 | `rename` 只在同一文件系统内原子，跨挂载点不成立 | `df -T 源 目标` 或 `findmnt -T`；把临时文件建在与目标同一目录 |
| 日志开着，崩溃后仍读到旧数据 | `data=writeback` 不保证数据先于元数据，只保证元数据一致 | `findmnt -no OPTIONS /`；`/proc/fs/ext4/<dev>/options` 只列出非默认项，`data=ordered` 看不到（VM 实测只显示 `rw`、`bsddf`、`nogrpid`） |
| `fsync` 之后文件名又变回旧的 | 目录项是另一个对象，没同步父目录 | 在 `strace` 里数 `fsync` 的对象：目录 fd 有没有出现；`open(dir, O_DIRECTORY)` + `fsync` |
| `ps` 显示 `R`，但 CPU 不高 | `R` 包含「在 runqueue 上等 CPU」 | 两次采样 `/proc/<pid>/stat` 第 39 字段（CPU 号）是否变化；读 `/proc/pressure/cpu` 的 `some avg10` |
| `dd` 报 3.9 GB/s，应用却还是很慢 | `dd` 写进 page cache，只有结尾一次 flush | `iostat -x 1 3`：VM 实测 100 MiB `dd conv=fsync` 期间 `w/s 27`、`wkB/s 102496`、`w_await 4.63 ms`、`f/s 2`，设备侧远慢于 `dd` 的报数 |
| `cat /sys/fs/cgroup/pids.max` 报不存在 | 根 cgroup 没有限额文件，要读自己所在的 scope | `cat /proc/self/cgroup` 拼出 `/sys/fs/cgroup<路径>` 再读；VM 实测该 scope 里 `pids.max` 为 `max`、`pids.current` 为 4 |

## 能否讲出这八句话

1. **三件事，两个抽屉。** 虚拟化、并发、持久化；每件事都分机制（怎么做）与策略（选哪个）。混在一起，就会出现「给策略打补丁却改坏了机制」。
2. **周转与响应不可兼得。** A(0,10)、B(1,5)、C(2,2)：FIFO 13/7.33，SJF 12/6.33，RR(2) 11/1。批处理看周转，交互看响应，真实系统用 MLFQ 与权重折中。
3. **周期提升是 MLFQ 的命门。** 没有规则 5，长任务永远沉底；有了它，短任务又会被打断。参数决定系统性格，不是实现细节。
4. **按权重分 CPU，等于让 `vruntime` 相等。** 步长调度把这一点做成确定性；CFS 用权重缩放 `delta`；彩票用概率换来简单。VM 实测 1 万次抽签的份额是 50.2/24.6/25.2，步长是精确的 50/25/25，三者 `pass` 都收敛到 5,000,000。
5. **内存虚拟化是三次还债。** 分段还隔离的债（外部碎片），分页还碎片的债（页表空间），交换还容量的债（I/O 延迟）。三个技巧——按需清零、COW、聚簇换入——都是把成本推到真正需要时。
6. **Belady 异常只属于非栈算法。** FIFO 在 3 个页框缺页 9 次、4 个页框 10 次；OPT 与 LRU 不会。Clock 是近似 LRU，本例与 FIFO 同结果，说明「近似」不保证栈性质。
7. **持久化的唯一分界是提交记录。** 有提交就重放（幂等），没有就丢弃。`fsync` 只保证一个对象，`rename` 只保证同一文件系统内原子，目录项要单独同步——这三条缺一条，"原子写"就不成立。
8. **模型不是内核。** CFS 从 6.6 起是 EEVDF；Linux 普通调度类没有固定时间片；精确 LRU 不存在；aarch64 的 PTE 位号与 x86-64 不同。引用字段与位号前先在本机 `grep` 一遍。
