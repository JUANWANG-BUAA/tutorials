## 没达标怎么办

- **K 组卡住（概念行）**：先讲一句完整因果，例如「因为 `close` 之后 fd 已释放，重试可能关掉别人的 fd，所以 C 版本只 `close` 一次并保存首个错误」。讲不出因果就回对应小节的「即时自测」，不要靠多读几遍。
- **M 组卡住（动手行）**：拿纸画两张图——「`open` → `read` → `write` → `close`」四格与「`lock` → 临界区 → `unlock`」三格；再合上正文默写 `errno == EINTR` 的重试骨架与 `write_all` 的循环。写不出就把 1.17.4 的 C 版本抄一遍再默写。
- **S 组卡住（实验行）**：先确认环境边界。VM 上 `cc`/`strace`/`nc`/`readelf` 可用，`sudo` 不可用，**Rust 工具链没有**；报不出环境就把结论降级成「未实测 + 原因」，不要用一次 `strace` 推一个常数。
- **A 组卡住（口径行）**：把「条款 / 工具输出 / 量级示例 / 未实测」四类分开记；`strace` 的行数不是性能指标，`size` 的 `text` 不是文件大小，Rust 在 Linux 上的 ELF 形状本环境没有读数。[勘误页](ch17-errata.md)的「本章未实测项」先读一遍。
- **只有 K 组全对**：说明你还停在「会读」。本章要求会写、会跑、会取证；把 M 组与 S 组做完再来勾这一页。

全部达标后，往下的接口有三处：[1.18 RISC-V 裸机](ch18.md) 把 `no_std`、所有权与 FFI 放进没有操作系统的环境（[1.18.1](ch18.md#sec-1.18.1) 起）；[1.16.7 FFI 与 ABI](ch16.md#sec-1.16.7) 是本章符号与布局规则的上游；项目侧的多阶段镜像构建会把「fd 继承与 `O_CLOEXEC`」再考一遍。
