## 没达标怎么办

- **K 组卡住（概念行）**：先讲一句完整因果，例如「因为 FIFO 不是栈算法、页框数为 n 时的命中集合不保证是 n+1 的子集，所以加页框可能改变替换顺序，出现 Belady 异常」。讲不出因果就回对应小节的「即时自测」，不要靠多读几遍。
- **M 组卡住（动手行）**：拿纸笔画甘特图与三块地图；模拟器不要只看结论，把 `QUANTA` 从 10000 改成 100、把页框从 3 改成 5、把崩溃点从 0 枚举到 3，观察哪一列变、为什么变。写不出就把正文的 `lottery.c` 与 `page_repl.c` 各抄一遍再合上默写。
- **S 组卡住（实验行）**：先确认环境边界。本书 VM 上 `vmstat`、`iostat`、`strace`、`filefrag`、`taskset` 可用，`stress-ng`/`fio` 未装，`perf sched` 因 tracefs 权限报 `can't access trace events`，`sudo dumpe2fs`/`debugfs` 不可用。把「哪台机器、哪个内核、哪个文件系统、什么挂载选项」写在结论旁边；报不出环境就把结论降级成「未实测」。
- **A 组卡住（口径行）**：把「模拟器输出 / VM 实测 / 形状示例 / 未实测」四类分开记，不要用一次读数推一个常数，更不要把 `dd` 的 page cache 带宽当设备带宽。[勘误页](ch13-errata.md)的「本章未实测项」先读一遍。
- **只有 K 组全对**：说明你还停在「会读」。本章要求会算、会跑、会取证；把 M 组与 S 组做完再来勾这一页。
