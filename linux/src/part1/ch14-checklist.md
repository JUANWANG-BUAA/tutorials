## 没达标怎么办

- **K 组卡住（概念行）**：先讲一句完整因果，例如「因为 4 KiB 的整数倍只改 tag 不改 index，9 个流落在同一组，8 路放不下，所以第 9 个流一进来就冲突缺失」。讲不出因果就回对应小节的「即时自测」，不要靠多读几遍。
- **M 组卡住（动手行）**：拿纸笔画三张图——组成最小模型、`sum3` 的三套栈、32 KiB/8 路的地址拆分；再合上正文默写 `hello` 的六条指令。写不出就把 1.14.3/1.14.5 的代码各抄一遍再默写。
- **S 组卡住（实验行）**：先确认环境边界。本书 VM 上 `cc`/`as`/`objdump`/`readelf`/`getconf` 可用，`sudo` 与 `perf` 不可用；`qemu-aarch64`、`qemu-riscv64`、交叉 gcc、`llvm-mc` 未确认。报不出环境就把结论降级成「未实测」，不要用一次计时推一个常数。
- **A 组卡住（口径行）**：把「公式 / 工具输出 / 量级示例 / 未实测」四类分开记；`size` 的 `text` 不是纯指令字节，`perf` 的 miss 数不能凭时间差反推，`qemu -strace` 的系统调用名不能当内核实现。[勘误页](ch14-errata.md)的「本章未实测项」先读一遍。
- **只有 K 组全对**：说明你还停在「会读」。本章要求会算、会跑、会取证；把 M 组与 S 组做完再来勾这一页。

全部达标后，往下的接口有三处：[1.15.1 调用的契约](ch15.md#sec-1.15.1) 与 [1.15.5 参数传递](ch15.md#sec-1.15.5) 会把栈帧与参数规则扩到完整函数；[2.1.1 一次系统调用穿过什么](../part2/ch01.md#sec-2.1.1) 与 [3.3.5 从 `syscall` 指令到 C 函数](../part3/ch03.md#sec-3.3.5) 会把三条陷入指令变成内核路径。项目侧从 A1 `mycontainer` 的 [Stage 0 骨架](../projects/pa.md#sec-a.1.3) 接手，多架构镜像会把本章的 ABI 差异再考一遍。
