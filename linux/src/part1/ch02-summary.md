# 1.2 章末总结

## 五单元一览

| 单元 | 核心问题 | 关键结论 | 典型陷阱 |
|:--|:--|:--|:--|
| **一、位与整数**（1.2.1–1.2.5） | 二进制/补码/整数运算怎样工作？ | 位/字节/字/十六进制；补码表示有符号；扩展/截断/转换有规则；有符号溢出是 UB，无符号是回绕；移位有边界。 | 把 `0xFFFFFFFF` 当 -1；有符号溢出当回绕；移位超过位宽；类型转换想当然。 |
| **二、字节序、布局与浮点**（1.2.6–1.2.8） | 多字节怎样排？浮点怎样表示？ | 小端/大端；对齐/padding；IEEE 754 符号/指数/尾数；舍入/ULP/非规格化/NaN；浮点比较用容差。 | 忽略字节序；结构体布局想当然；`0.1+0.2` 直接比较；NaN 当普通值。 |
| **三、手算与全规则**（1.2.9–1.2.11） | 能不能不靠计算器？ | 进制/补码/移位/溢出手算；IEEE 754 逐字段；布局完整规则（对齐/`offsetof`/`repr(C)`）。 | 手算补码符号错；ULP 算错；padding 漏算。 |
| **四、程序与实验**（1.2.12–1.2.17） | 怎样用证据验证？ | 位操作工具箱、浮点位模式分析器、汇编字节序验证；`gdb`/`objdump` 实验；12 个陷阱。 | 只读不跑；不看汇编/内存；陷阱只背不验证。 |
| **五、C/Rust 与出口**（1.2.18–1.2.19） | 语言之间语义差在哪？ | C 的 UB/实现定义 vs Rust 的安全/checked；`repr(C)`/对齐/FFI；本章小结。 | 把 C 的 UB 带到 Rust；FFI 布局不一致。 |

## 一条主线

这一章从“位”走到“表示语义”：**先建立位/字节/补码/整数运算（1.2.1–1.2.5），再看字节序/对齐/浮点（1.2.6–1.2.8），用手算与全规则收第一遍（1.2.9–1.2.11）。第二遍用三个完整程序、两个 `gdb`/`objdump` 实验、12 个陷阱与 C/Rust 对照验证（1.2.12–1.2.18）。** 核心纪律：**看到二进制/十六进制/浮点数字，先问“它的类型、宽度、字节序、对齐、边界是什么”，再算。**

## 看到问题先选工具

| 症状 | 第一动作 | 为什么 |
|:--|:--|:--|
| 想看十六进制/二进制 | `printf '%x'`、Python `hex/bin` | 快速对照位模式。 |
| 怀疑整数溢出 | `-fsanitize=undefined`/`-ftrapv`、`gdb` | 有符号溢出是 UB，要工具抓。 |
| 想看结构体布局 | `offsetof`、`sizeof`、`pahole` | padding/对齐/字段偏移。 |
| 想看浮点位模式 | `memcpy` 到 `uint64_t`、`%a`、`gdb` | 符号/指数/尾数。 |
| 想看字节序 | `xxd`/`od`、union、汇编 | 内存里的字节顺序。 |
| 想看常量/浮点指令 | `objdump -d`/`readelf` | 编译器怎样表示常量。 |
| 想比浮点 | 容差/ULP，不用 `==` | 二进制浮点不精确。 |
| 想 C/Rust 互操作 | `repr(C)`、`bindgen`、Miri/UBSan | 布局/UB 边界。 |

## 能否讲出这八句话

1. 位/字节/字/十六进制；LP64 下 `long`/指针是 8 字节，ILP32 是 4 字节。
2. 补码：`-x = ~x + 1`；有符号范围不对称（`INT_MIN` 没有正对应）。
3. 有符号溢出是 UB；无符号回绕；移位超过位宽/负数是 UB。
4. 字节序有小端/大端；结构体有对齐/padding；`offsetof`/`repr(C)` 看布局。
5. IEEE 754：符号/指数/尾数；规格化/非规格化/NaN/Inf；ULP 是最小间距。
6. `0.1+0.2 != 0.3`；浮点比较用容差；NaN 与任何值比较都为假。
7. 手算补码/移位/溢出；用 `gdb`/`objdump` 验证，不靠猜。
8. C 的 UB/实现定义 vs Rust 的安全/checked；FFI 用 `repr(C)` 对齐。
