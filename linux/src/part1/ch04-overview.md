# 1.4 处理器体系结构：从 Y86-64 到乱序执行 · 本章导航

::: preview 这一章在讲什么
一条 `addq` 在哪个周期读寄存器、哪个周期写回？紧跟它的那条指令要用这个结果，硬件是等、是绕过去、还是先猜？这一章把处理器拆开回答：先用教学 ISA Y86-64 建立「指令—编码—HCL 控制逻辑—五级流水线」的骨架，再用转发、暂停和分支预测算清三类冒险的代价，然后升级到现代乱序执行（重命名、保留站、ROB、超标量）与真实处理器（x86-64、ARM Cortex-A、RISC-V），最后用两个完整程序和 `perf stat` 把结论变成能跑的观测。Y86-64 不是真硬件，它只给你一张没有历史包袱的图纸；读完你要能在自己的机器上说清「流水线停在哪一级、为什么停」。
:::

## 读完你会

- 区分 ISA 与微架构，各举一例，说清为什么同一个 ISA 能有好几种实现。
- 手编并手拆 Y86-64 指令：`icode:ifun`、`rA:rB`、8 字节小端常量，判断每条指令占几个字节。
- 读懂 HCL 控制等式，解释「漏掉默认分支会综合出锁存器」为什么在 C 里不会发生。
- 画出五级流水线时序表，判断哪些依赖能靠转发解决、哪些必须暂停一拍插气泡。
- 用 CPI 公式估算分支预测失败的代价，说清准确率 90%→99% 为什么值两成多性能。
- 解释重命名、保留站、ROB、超标量各解决什么，并用 N = T × L 估一个程序的 IPC 上限。
- 跑通 Y86-64 解释器并核对 `steps=43`、`rax=55`；跑通依赖链与分支预测两个基准。
- 用 `perf stat` 的 IPC、`branch-misses`、前端停顿判断程序是前端、后端还是分支受（这是通用方法；本书的 aarch64 VM 没有指令计数器、macOS 没有 `perf`，所以正文只给纸面推算与不依赖计数器的代理实验）限。
- 说出 x86-64、AArch64、RV64GC 在前端宽度、条件码与分支惩罚上的差别。

## 先修与预计学时

- 先修：读完 [1.3 机器级程序：x86-64 汇编](ch03-overview.md)，认全寄存器与 `cmp`/`jcc`；会 C 的循环和指针。**不需要**学过数字逻辑或组成原理；HCL、流水线、ROB 的白话解释都在第一次出现处。
- 阅读：约 130–160 分钟；机器码与流水线手算：约 60 分钟；两个程序与 `perf` 实验：约 60 分钟；章末习题：约 60 分钟。

## 怎么读

- **第一次读**：1.4.1–1.4.8 按顺序，每节先做「即时自测」。重点是把两笔账算顺：load-use 停一拍、分支预测错一次付十几周期。
- **只想看懂性能现象**：1.4.6、1.4.8、1.4.15；先跑 [1.4.15](ch04.md#sec-1.4.15) 的分支预测实验，再回来看预测器为什么需要历史。
- **想自己搭处理器或做课后题**：1.4.2、1.4.9、1.4.10、1.4.11 是一套——编码全表给字节，HCL 给控制信号，时序表给周期。
- **想理解乱序、Spectre 与内存屏障**：1.4.7、1.4.12、[1.4.16](ch04.md#sec-1.4.16)，再跳 [1.12.9 原子操作与内存序](ch12.md#sec-1.12.9)。
- **卡住时**：先回 [1.3.4 条件码与跳转](ch03.md#sec-1.3.4) 确认标志位的语义，再回到对应小节；缓存那一段的疑问留给 [1.6](ch06.md)。

## 路线标签与项目回链

- 应用/运维：**可后补**（看 1.4.6、1.4.8 就够：分支可预测性影响你的热点循环，`perf stat` 是你唯一要用熟的工具）。
- 系统编程：**必读**（1.4.1–1.4.8、1.4.15；系统调用、上下文切换和信号的成本最终都要落到流水线上）。
- 内核/性能：**必读**（整章，尤其 1.4.7、1.4.11–1.4.12、1.4.16；ROB 窗口与 IPC 上界是性能分析的地基）。
- 项目回链：A2（`myhttpd`）压测时用 IPC 与 `branch-misses` 定位热点；A3（`mybpf`）用硬件事件做可观测；B1（`myredis`）事件循环的热路径靠依赖链拆解。优化手法接 [1.5.5 循环展开与多累加器](ch05.md#sec-1.5.5)，见[项目总览](../projects/overview.md)。
