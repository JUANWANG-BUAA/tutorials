# 1.15 汇编与调用约定：三架构并排 · 本章导航

::: preview 这一章在讲什么
[1.3](ch03.md#sec-1.3.1) 用 x86-64 讲过栈帧，[1.14](ch14.md#sec-1.14.1) 把三套 ISA 并排放在一起；但「知道寄存器名字」不等于「会读一次真实调用」。这一章按「调用发生的一瞬间」组织：返回地址放在哪、谁保存哪些寄存器、序言为什么长这样、第 7 个参数什么时候改用栈、`_start` 为什么不能 `ret`、内联汇编要告诉编译器什么。读完你能拿任意一段陌生汇编，先找参数寄存器，再找栈调整，最后才看算术。
:::

## 本章回答什么

- **控制怎么转移**：x86-64 的 `call` 把返回地址压栈，ARM64 的 `bl` 写 `x30`，RISC-V 的 `jal`/`call` 写 `ra`；非叶函数因此要保存 LR/`ra`，叶子函数可以完全不碰栈（1.15.1）。
- **寄存器由谁负责**：参数、返回值、调用者保存、被调用者保存各是哪几个；`x30` 为什么单列，ARM64 的 `v8`–`v15` 为什么只保证低 64 位，RISC-V 的 `gp`/`tp` 为什么不能当临时变量（1.15.2）。
- **同一操作三种写法**：加载、存储、加法、立即数、比较跳转、调用、返回、栈分配、取地址、系统调用、屏障、原子操作各长什么样；AT&T 的「源在前」与 ARM/RISC-V 的「目标在左」怎么不混（1.15.3）。
- **序言与尾声**：`push %rbp`、`stp x29,x30,[sp,#-16]!`、`sd ra,...(sp)` 分别在保存什么；为什么 `-O2` 下很多函数没有帧指针；栈图上的三个偏移怎么读（1.15.4）。
- **寄存器用完以后**：第 7、8、9 个整数参数在三套 ABI 下分别在哪；≤16 字节结构体怎么拆；可变参数的 `%al`、ARM64 的匿名栈参数、RISC-V 的 `va_list` 保存区差在哪（1.15.5）。
- **三个完整程序**：不依赖 libc 的 `_start` 怎么用 `write`/`exit`；C 的 `asm volatile` 与 Rust 的 `asm!` 怎么声明输入输出、`memory` 与 `nostack`；裸系统调用失败为什么返回 `-errno`（1.15.6–1.15.7）。
- **怎样拿证据**：用 `objdump`/`readelf` 看符号、重定位、序言与参数寄存器；用 `gdb` 看入口 `sp`、返回地址与保存区；`perf` 不可用时怎么降级（1.15.8–1.15.9）。
- **哪些结论会搬家**：十二条汇编与 ABI 陷阱，以及三套汇编不可互搬、交叉汇编不等于交叉运行、第 7/9 个参数的寄存器数量差异（1.15.10–1.15.11）。

## 读完你会

- 在白纸上画出三套调用链：`call` 压栈 / `bl` 写 `x30` / `jal` 写 `ra`，并说出非叶函数各要保存什么。
- 默写寄存器责任表：整数/浮点参数、返回值、被调用者保存、调用者保存、栈对齐、返回地址、红区。
- 把「加载 8 字节、存 8 字节、加法、立即数加法、比较跳转、调用、返回、栈分配、取地址、系统调用」十条操作写成三套汇编。
- 对 `framed` 画出三张栈图，标出返回地址、保存的 FP/LR、保存的 `rbx`/`x19`/`s1`、局部变量与 16 字节对齐。
- 写一个 9 个 `long` 参数的函数，指出 x86-64 的第 7–9 个在栈上，ARM64/RISC-V 的第 7、8 个仍在 `x6`/`x7`、`a6`/`a7`，第 9 个才在 `[sp]`。
- 说清 x86-64 入口 `rsp % 16 == 8`、`call` 前要 `0`，以及 `movaps` 段错误与红区失效的因果。
- 手写 aarch64 的 `_start`，用 `cc -nostdlib -static` 链接并跑出指定退出码；用 `objdump` 找到两次 `svc #0` 与 `x8=64/93`。
- 写出 C 的 `asm volatile` 系统调用包装，声明 `"memory"` 与 `rcx`/`r11`；写出等价的 Rust `asm!`，说明 `lateout`、`inout`、`options(nostack)` 各做什么。
- 用 `readelf -sW`/`-rW` 判断跨文件调用与重定位，用 `gdb` 的 `x/6gx $sp` 核对返回地址与保存区。
- 对任何「三架构应该一样」的说法，先问：哪层契约（ISA/ABI/内核 ABI）、哪个寄存器数量、能不能真的链接运行。

### 环境与口径

- **VM**：Ubuntu 24.04.5（aarch64、GCC 13.3.0、4 vCPU，`sudo` 不可用）。`cc`/`gcc`、`as`、`objdump`、`readelf` 可用；**`perf` 不可用**，1.15.9 的 `perf stat`/`perf record` 按「未实测」读，替代做法是 `clock_gettime` 计时。`gdb`、`cargo`、交叉 gcc 是否安装未确认，先 `command -v` 再决定。
- **写作机**：macOS arm64 + clang 21。`--target=x86_64-linux-gnu` 与 `--target=riscv64-linux-gnu` 能交叉汇编（`-S`/`-c` 出汇编与 ELF 目标文件），但**不能链接、不能运行**；`aarch64-linux-gnu` 同理。C4 只做汇编与 `readelf`，执行部分标「未实测 + 原因」。
- **口径**：正文的指令条数、字节数、寄存器编号与重定位名是工具输出或 ABI 条款；C 组只把工具输出当读数，先写预期再跑。凡是本机没有证据的 `perf`、`cargo asm`、`gdb` 交互，一律不编造输出。

## 怎么读

- **第一次读**：1.15.1–1.15.5 一口气读完，边读边在纸上画 `framed` 的三张栈图；这三节是同一件事的四个切面。然后跳到 1.15.6 手抄 `_start`，再读 1.15.8 的实验。
- **正在排一个具体故障**：返回地址错乱看 1.15.1 与 1.15.10；第 7 个参数读成返回地址看 1.15.5；`movaps` 段错误看 1.15.10；内联汇编只在 `-O2` 出错看 1.15.7；系统调用没输出看 1.15.6 与[勘误页](ch15-errata.md)。
- **准备面试或课程考试**：寄存器责任表（1.15.2）、三张栈图（1.15.4）、第 7/9 参数（1.15.5）、`syscall` 的 `r10`（1.15.6）是四处必答；先做[习题集](ch15-exercises.md) A 组，再做 B 组。
- **怕数字搬家**：寄存器编号、栈偏移、重定位名都可复算；`gdb`/`perf`/`cargo asm` 的输出没有本机证据，统一记在[勘误页](ch15-errata.md)的「本章未实测项」。
