# 第 1 篇 · 计算机系统

::: preview 这一篇在讲什么
程序在机器上到底怎么跑？一个 `int` 为什么会有溢出，`for` 循环为什么有时快有时慢，链接器为什么报 `undefined reference`，虚拟内存为什么能让每个进程都以为自己独占内存？这一篇用 CSAPP 的路径回答这些问题：从源文件到进程，从数据表示到汇编、缓存、链接、异常、虚拟内存、I/O、网络与并发，最后用 OSTEP 与多架构/Rust/RISC-V 把视角拉宽。
:::

## 读完这一篇你会

- 画出 `hello.c` 从编译、链接、加载到进程退出的完整生命周期。
- 解释整数溢出、浮点精度、字节序、对齐与未定义行为。
- 读懂 x86-64 汇编与调用约定，知道栈帧、寄存器与 `objdump` 的基本用法。
- 解释缓存层次、局部性、链接与加载、异常控制流、虚拟内存、系统级 I/O 与并发。
- 用 OSTEP 的视角把进程、调度、内存、文件系统串成 OS 理论骨架。
- 知道 x86-64/ARM64/RISC-V 的差异，能用 Rust 写系统代码，理解 rCore 的任务/地址空间/文件系统。

## 本篇路线：五段，一条主线

| 段 | 章节 | 这一段回答什么 |
|:--|:--|:--|
| **一、程序与机器** | [1.1](ch01-overview.md)–[1.5](ch05-overview.md) | 源文件怎样变成进程？数据怎样表示？汇编与处理器怎样执行？程序为什么快/慢？ |
| **二、存储、链接与异常** | [1.6](ch06-overview.md)–[1.8](ch08.md) | 缓存怎样影响性能？链接与加载怎样工作？进程、信号与异常控制流是什么？ |
| **三、虚拟内存、I/O、网络、并发** | [1.9](ch09.md)–[1.12](ch12.md) | 虚拟内存怎样映射？系统级 I/O 与网络编程怎样写？并发与同步的基本模型是什么？ |
| **四、OS 理论** | [1.13](ch13.md) | 虚拟化、并发、持久化的理论骨架是什么？ |

一句话主线：**先看程序的生命周期（1.1），再补数据、汇编、处理器与性能（1.2–1.5）；然后用缓存、链接、异常把程序放进系统（1.6–1.8），用虚拟内存、I/O、网络、并发把系统讲全（1.9–1.12），用 OSTEP 收成理论（1.13）；最后用多架构、Rust、RISC-V 与 rCore 把「会读」推进到「会写」（1.14–1.19）。**

## 分岔点：读完 1.3 就可以离开这一篇

这一篇有 19 章，但它不是一条必须走到底的路。第 1 篇内部有一个明确的分岔：

| 标记 | 章节 | 性质 |
|:--|:--|:--|
| **1A · 程序底座** | 1.1–1.13 | 全书公共底座。第 2 篇系统编程、第 3 篇内核、第 4 篇网络都从这里取前置。 |
| **1B · 多架构与实现** | 1.14–1.19 | 方向选修。走内核/性能（路线 C）或要做 rCore、Rust 系统编程的人读；走应用与运维（路线 A）的人可以整体跳过，不必有心理负担。 |

1A 里再挑最小集：[1.1](ch01-overview.md) 讲程序的一生，[1.2](ch02-overview.md) 讲数据为什么会算错，[1.3](ch03-overview.md) 讲机器级程序怎么读。**打算走系统编程或内核方向的人，读完这三章就可以先进第 2 篇动手**——现在的线性目录容易让人以为要读完 19 章才算「学过第 1 篇」，不是的。剩下的 1.4 处理器、1.5 优化、1.6 缓存、1.7 链接、1.8 异常、1.9 虚拟内存、1.10 I/O、1.11 网络、1.12 并发、1.13 OS 理论，按你的路线按需取；只做应用与运维的人，按下面的路线表走 1.1 与 1.9 也够用。

判断自己该不该继续留在这一篇，问一句：**我现在的问题是「看不懂程序在机器上做了什么」，还是「想读懂内核与硬件」？** 前者读完 1.1–1.3 就该去第 2 篇动手；后者才需要 1.4、1.6、1.9、1.13。

## 与前后篇的接口

- **第 0 篇 → 本篇**：0.1 的分层、0.5 的 fd 表、0.3 的文件与 inode 是 1.1、1.9、1.10 的入口。

- **本篇 → 第 5 篇**：1.9 地址空间与 1.12 并发是 namespace/cgroup 的前置。

## 怎么读这一篇

- **第一次读**：按 1.1 → 1.13 顺序读；1.14–1.19 可以等做完第 2 篇再回来。
- **只想写系统程序**：1.1–1.3、1.6–1.9；1.4–1.5 可后补。
