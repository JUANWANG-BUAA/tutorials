# 1.5 程序性能优化 · 本章导航

::: preview 这一章在讲什么
「我把循环改短了，怎么没变快？」——这一章回答这个问题。凭直觉改代码是最常见的错法：直觉盯着指令条数，而现代 CPU 的瓶颈通常在依赖链、缓存缺失、分支预测失败和访存带宽上，这四者跟指令条数关系都很弱。这一章先给你一把能比较的尺子（每元素周期数 CPE，就是「处理一个元素摊掉几个时钟周期」），再按 CSAPP 第 5 章的顺序把改写手段排开：删重复计算、省调用与内存引用、展开与多累加器、分支友好、分块与 SoA、别名与 `restrict`；最后用 `perf` 和两个实测程序把「我以为快了」变成「测出来快了」。
:::

## 读完你会

- 用 CPE 与 $T(n)=c+kn$ 比较两个实现，说清固定开销和斜率分别从哪来。
- 用延迟和吞吐算出一个循环的 CPE 下界，判断还剩多少可优化空间。
- 说出编译器在 `-O2` 下敢做什么、因为什么不敢做：别名、未定义行为、外部调用。
- 改写循环：外提不变量、把 `*dest` 提升进寄存器、展开配多累加器、AoS 换 SoA。
- 写无分支代码并判断它什么时候反而更慢。
- 给矩阵乘做循环交换与分块，并按缓存容量估块大小。
- 读 `perf stat` 的 IPC、缓存缺失、分支失败、前端/后端停顿，按顺序排除瓶颈。
- 解释 `restrict` 删掉了哪几条指令，以及违反承诺为什么是未定义行为。
- 复现本章两个实测程序，区分「正文实测数值」和「你自己机器上的数值」。

## 先修与预计学时

- 先修：[1.2 信息的表示与运算](ch02-overview.md) 的浮点舍入（1.2.7、1.2.8，决定哪些重排不允许）；[1.3 机器级程序](ch03-overview.md) 的汇编读法（要能在 `-S` 输出里认出 load/store/跳转）；[1.4 处理器体系结构](ch04.md) 的乱序执行与依赖链（1.4.7、1.4.14）是最好用的前置，只学过流水线也够读。
- 阅读：约 150–180 分钟（17 节）；跑两个程序与两个实验：约 90 分钟；章末习题：约 60 分钟。
- 环境：计时类实验在 macOS 与 Linux 都能做；`perf` 与 `cachegrind` 需要 Linux，见[实验环境](../env.md)。

## 怎么读

- **第一次读**：按段顺序走，1.5.1 和 1.5.6、1.5.10 三处的手算务必在纸上做一遍；下界算不出来，后面的改写就只是背口诀。
- **只想解决一个具体的慢**：先看 [1.5.9](ch05.md#sec-1.5.9) 的排查顺序，再按结论跳回 1.5.5（依赖链）、1.5.7（分支）或 1.5.8（局部性）。
- **怕改错**：先读章首的正确性提醒与 [1.5.16](ch05.md#sec-1.5.16) 十二条陷阱，尤其是 `-ffast-math`、求和顺序、`restrict` 三条。
- **想复现实测**：1.5.12 与 1.5.13 的源码完整可编译，直接抄走跑；跑完先比相对关系，再比绝对数值。
- **卡住时**：回[先修工具箱](../prerequisite.md)补浮点与汇编，再回对应小节。
