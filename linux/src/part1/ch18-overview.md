# 1.18 RISC-V 裸机：SBI、三特权级与 trap · 本章导航

::: preview 这一章在讲什么
[1.15](ch15.md) 讲了 RISC-V 汇编与调用约定，[1.16](ch16.md) 讲了链接脚本与 ELF 布局。这一章把两者接上特权级：一块没有操作系统的板子，上电后从哪条指令开始，谁把特权级从 M 降到 S，内核第一行代码为什么必须通过 `ecall` 请固件帮忙打印。核心不是背 CSR 编号，而是**把「上电 → 固件 → 内核 → 用户 → trap → 返回」变成一条能用 `objdump`/GDB/串口输出复核的因果链**；SBI、`sscratch`、`TrapFrame`、时钟中断都挂在这条链上。
:::

## 本章回答什么

- **寄存器与 CSR 各是什么**：`x0`–`x31` 与 ABI 别名；`mstatus/mepc/mtvec/mcause/mtval` 与 S 态对应物；`csrrw/csrrs/csrrc` 怎么读写（1.18.1）。
- **三个特权级的分工**：M 跑 OpenSBI、S 跑内核、U 跑应用；`ecall` 向上、`sret`/`mret` 向下；一次 trap 硬件自动做哪五件事（1.18.2）。
- **SBI 到底是什么**：它是 S 态调用 M 态固件的 ABI，不是系统调用、不是硬件、也不是内核的一部分；EID/FID 怎么放，`a0` 与 `a1` 谁是错误码（1.18.3）。
- **最小的 Rust 裸机程序长什么样**：链接脚本把 `.text.entry` 钉在 `0x8020_0000`；`_start` 清 `.bss`、设 `sp`、跳 `rust_main`；`#![no_std]` + `#![no_main]` + `panic_handler` 三件套（1.18.4）。
- **启动链与内存地图**：ZSBL → OpenSBI → 内核 → 用户；`0x1000_0000` 的 UART0、`0x0200_0000` 的 CLINT、`0x8000_0000` 起的 DRAM 各放什么；C 版与纯汇编版如何共用同一套入口（1.18.5）。
- **不用 SBI 怎么输出**：16550A 的 `THR`/`LSR`/`LCR` 偏移与位；为什么要轮询 `THRE`；`volatile` 只防优化、不当屏障（1.18.6）。
- **trap 现场怎么保存**：34 槽 `TrapFrame` 的偏移表；`sscratch` 换栈；保存 31 个有值寄存器与 `sepc/sstatus`；`sret` 前必须写回 `sstatus`（1.18.7）。
- **三个特权级怎么串起来**：M 配 PMP、`medeleg` 委托 `ecall-from-U`，`mret` 到 S，`sret` 到 U，U 的 `ecall` 进 S，S 的 `ecall` 进 M（1.18.7）。
- **时钟中断怎么变成 tick**：CLINT 的 `mtime/mtimecmp`、SBI `TIME` 写绝对时间、`sie.STIE` 与 `sstatus.SIE` 两道门、handler 里必须重新上弦（1.18.8）。
- **怎样取证、边界在哪**：`llvm-readelf`/`llvm-objdump` 看入口与段；QEMU `-s -S` + GDB 看 PC；本机没有 RISC-V 硬件与 QEMU 运行链路，所有运行输出只作形状（1.18.9–1.18.10）。

## 读完你会

- 画出 M/S/U 三层与 `ecall`/`sret`/`mret` 的方向，说清哪条指令只能从哪一级发出、回到哪一级。
- 说出一次 trap 的硬件动作顺序：写 `sepc`、写 `scause`/`stval`、跳 `stvec`、清 `SIE`、切特权级；并指出通用寄存器硬件一个都不保存。
- 从 `scause` 的最高位判断中断还是异常，说出 `8`/`9`/`11`（三种 `ecall`）与 `5`/`7`（S/M 定时器）各是什么。
- 用 `sbi_call(eid, fid, arg0, arg1)` 的寄存器约定解释一次 `putchar` 与一次 `SRST` 关机，并指出 `a0` 是错误码、`a1` 是值。
- 写出最小链接脚本的骨架：`ENTRY(_start)`、`BASE_ADDRESS = 0x80200000`、`.text.entry` 最先、`sbss/ebss` 作为清零边界。
- 解释 `_start` 的三件事与 `la` 的展开（`auipc` + `addi`），以及为什么 `satp=0` 时链接地址就是物理地址。
- 为 16550A 写出「初始化 `LCR/FCR/IER` → 轮询 `LSR.THRE` → 写 `THR`」的发送路径，并说明 `\r\n` 与 `volatile` 的必要性。
- 按偏移表写出 `TrapFrame` 并用 `#[repr(C)]` 对齐，解释为什么 `x2` 要从 `sscratch` 取、`x0` 不用存。
- 说出 `sscratch`、`stvec`、`sie.STIE`、`sstatus.SIE` 的初始化顺序，以及「先设入口再开门」的理由。
- 遇到「QEMU 无输出」「`ecall` 死循环」「tick 只来一次」「S 态写 CLINT 报 fault」时，按「现象 → 原因 → 修复」给出可复核的答案。
- 如实说明本章哪些结论有本机证据、哪些只是规范与形状：**裸机运行全部未实测**。

### 环境与口径

- **本机没有 RISC-V 硬件，也没有可用的 QEMU 运行/调试链路**：`qemu-system-riscv64` 与 `gdb-multiarch` 不在本章实验环境中。1.18.4、1.18.5、1.18.7、1.18.8、1.18.9 的所有「预期输出」都是**形状示例**，不是会话记录；`Entry point address: 0x80200000`、`hello, myrcore`、`tick 1`–`tick 5`、`M: hello from M-mode` 均标「未实测」。
- **交叉编译的天花板是 `.s` 与 `.o`**：命令形状如 `clang --target=riscv64-unknown-elf -march=rv64gc -mabi=lp64d -S/-c`，只产出汇编或目标文件；没有 riscv64 链接器与运行时，**不能链接成 ELF，更不能执行**。本机这一步也未实测（工具链后端未确认），正文与套件只给命令与判据，不抄输出。
- **Rust 侧未实测**：`rustup target add riscv64gc-unknown-none-elf`、`cargo build --release`、`rustc --target ...` 只在正文出现命令形状；本环境未确认该 target 可用，P1/P2/P3 的构建与运行都按「未实测 + 原因」处理。
- **口径分四类**：RISC-V 特权级规范与 SBI 规范的条款；工具输出形状（`readelf` 的 `Entry`、`objdump` 的第一条指令）；量级示例（`mtime` 10 MHz、10 ms = 100 000 tick、TrapFrame 272 字节）；未实测（全部 QEMU/GDB 运行、Rust 构建）。
- **不编造**：凡是本机没有证据的寄存器值、串口输出、`scause` 数值与 GDB 会话，一律不写成「实测」。

## 怎么读

- **第一次读**：1.18.1–1.18.3 一口气读完，在纸上画「U → S → M」三格与两条回程箭头；再读 1.18.4，把链接脚本的四个符号（`skernel/sbss/ebss/ekernel`）标在内存图上。
- **正在 bring-up 一块板子 / 一个 QEMU 镜像**：先看 1.18.10 的十一条陷阱，按「无输出 → 反复 reset → 第一字符后卡死 → 只来一次 tick」的顺序排查；对应小节回 1.18.4、1.18.6、1.18.8。
- **准备面试或课程考试**：三特权级与 `ecall/sret/mret`（1.18.2）、SBI 返回值约定（1.18.3）、`scause` 编码（1.18.7）、`sscratch` 换栈（1.18.7）是四处必答；先做[习题集](ch18-exercises.md) A 组。
- **怕把示例当读数**：本章所有运行结果都没有本机证据；`sstatus = 0x...`、`tick` 时间戳、GDB 的 `info registers` 都只表示「应该看到什么形状」。环境边界统一记在[勘误页](ch18-errata.md)的「本章未实测项」。

## 路线标签与项目回链

- **应用/运维：可后补** 1.18.4、1.18.6。日常排障用不到 SBI，但「固件—内核—用户」的分层能解释容器为什么看不到 `/dev/mem`；**必读** 1.18.2（特权级直觉）。
- **系统编程：必读** [1.18.2](ch18.md#sec-1.18.2)、[1.18.3](ch18.md#sec-1.18.3)、[1.18.7](ch18.md#sec-1.18.7)。系统调用的「用户态陷入内核」与这里的 `ecall` 是同一套硬件机制；**可后补** 1.18.6（UART 细节）。
- **内核/嵌入式：必读** 1.18.1–1.18.8 全读。链接地址、PMP、`sscratch`、时钟中断是 bring-up 的四道门；1.18.9 的 GDB 单步在真机上同样适用。
- **项目回链**：本章的 P1（SBI 打印 + 关机）、P2（M→S→U 三特权级）、P3（tick 抢占雏形）是 [1.19 从 rCore 看内核](ch19.md) 的前置骨架；1.19 只是把「打印 tick」换成「切换任务」，把「关机」换成「调度」。
