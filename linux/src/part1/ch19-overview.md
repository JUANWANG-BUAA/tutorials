# 1.19 从 rCore 看内核：任务、地址空间与文件系统 · 本章导航

::: preview 这一章在讲什么
[1.18](ch18.md) 把一块 RISC-V 板子从 M 态带到 S 态，做出了「能 trap、能打印、能被时钟打断」的骨架。这一章不再加新硬件，而是回答一个更大的问题：**一个内核是怎样被应用需求一步步逼出来的**。rCore 教程 chapter1–8 提供了一条现成的顺序：裸机 → 批处理 → 多任务 → 抢占 → 地址空间 → 进程 → 文件系统 → IPC/并发。本章借用这条顺序，换成自己的 `myrcore` 叙事，把每个阶段落到「应用需求、硬件机制、内核抽象、Rust 类型、典型失败」五栏上，最后用一次 `read` 把八层串起来。它是第 1 篇的收口章：前面 18 章分别讲机器、工具、OS 概念与裸机，这一章把它们装进一个教学内核的框架里，再交给第 2 篇的系统编程。
:::

## 本章回答什么

- **八个阶段各自解决什么**：裸机、批处理、多任务、抢占、地址空间、进程、文件系统、IPC/并发；每个阶段新增的硬件机制与内核抽象分别是什么（1.19.1）。
- **批处理怎么把应用关进 U 态**：应用镜像为什么放在 `0x8040_0000`、内核在 `0x8020_0000`；加载器的六步；第一次 `sret` 前必须设好 `sscratch` 与用户栈（1.19.2）。
- **多任务为什么只保存 14 个 `usize`**：`TaskContext` 只有 `ra/sp/s0–s11`；caller-saved 已由编译器保存在各自内核栈上；`__switch` 的 `ret` 其实返回到另一个任务（1.19.3）。
- **抢占与协作差在哪**：`yield` 是主动让出，时钟中断把「让出」变成「必须让出」；tick handler 只做重新上弦、计数、置 `need_resched`，不在中断里直接切换（1.19.3）。
- **Sv39 怎么把 39 位 VA 拆成四段**：`VPN[2]/VPN[1]/VPN[0]` 与页内偏移；`satp` 的 `MODE=8` 与 44 位 PPN；PTE 的 `V/R/W/X/U/G/A/D` 与叶子判定；大页翻译为什么不能把 `mask` 写成 `0xfff`（1.19.4）。
- **地址空间在内核里是什么类型**：`PageTable` 拥有页表页，`MemorySet` 拥有 `MapArea`，数据页由 `Arc<Frame>` 共享；COW 的 PTE 改权限仍要 `unsafe`（1.19.4）。
- **fork/exec/wait 的所有权**：fork 复制 `MemorySet` 与 fd 表但共享打开文件；exec 先建新地址空间再原子替换；wait 回收 zombie；`parent` 用 `Weak`、`children` 用 `Arc`（1.19.5）。
- **最小文件系统长什么样**：超级块、inode 位图、数据位图、inode 区、数据区；`File` trait 与 `Arc<dyn File>`；一次 `read` 从 `ecall` 走到 virtio 块设备中断的 11 层（1.19.6–1.19.8）。
- **教学内核与 Linux 差在哪**：rCore、Linux 6.8、`myrcore` 在调度、地址空间、页表、进程、文件、同步六个维度的对照；Rust 所有权在哪些地方帮忙、哪些地方必须 `unsafe`（1.19.9）。
- **哪些能取证、哪些不能**：`objdump`/GDB/QEMU 实验的命令形状与判据；本章所有运行输出都没有本机证据（1.19.10–1.19.11）。

## 读完你会

- 用一张表说出八个阶段的「应用需求 → 硬件机制 → 内核抽象 → Rust 类型 → 典型失败」，并指出哪个阶段开始需要 `sscratch`、哪个阶段开始需要 `satp`。
- 画出批处理内核的地址布局（内核 `0x8020_0000`、app0 `0x8040_0000`），写出加载器六步，并解释第 3 步 `sscratch` 漏设会怎样。
- 写出 `TaskContext` 的 14 个字段与 `__switch` 的保存/恢复顺序，解释为什么 `a0–a7`、`t0–t6` 不用进 `TaskContext`。
- 说出抢占式调度与协作式调度的差别，以及为什么 tick handler 里不能直接 `__switch`。
- 手算任一 39 位 VA 的三级索引与页内偏移；由根页表物理地址写出 `satp`；判断一个 PTE 是叶子、非叶子还是保留组合。
- 解释 `MapArea`、`MemorySet`、`PageTable`、`FrameAllocator` 四者的所有权边界，以及 `PageTable::drop` 为什么不能见到 PTE 就释放数据页。
- 把 fork/exec/wait 各写成「复制什么、共享什么、失败回滚什么」三句话；指出 `parent` 用 `Arc` 会造成什么后果。
- 画出 `myfs` 的五段磁盘布局，算出根目录项与 `hello.txt` 内容落在第几块；解释 inode 的四个直接块号够不够用。
- 从用户 `read(fd, buf, len)` 一路说到 `BlockDevice::read_block` 与中断唤醒，指出每一层可能返回的错误码。
- 用 rCore、Linux、`myrcore` 三列对照表解释「教学内核删掉的是工程复杂度，不是机制」。
- 如实说明本章的证据边界：**本机没有 RISC-V 硬件与 QEMU，rCore 只能读源码对照；所有构建、串口、GDB 输出都未实测**。

### 环境与口径

- **本机没有 RISC-V 硬件，也没有可用的 QEMU/GDB 运行链路**：`qemu-system-riscv64`、`gdb-multiarch` 不在本章实验环境里。1.19.2 的 `batch: load app`、1.19.4 的 Sv39 输出、1.19.6 的 `myfs` 输出、1.19.10 的 GDB 断点，全部只作**形状示例**，不是本机会话记录。
- **rCore 只能读源码对照**：本章不附带 rCore 仓库、不构建 rCore、不运行 rCore。所有「rCore 怎么做」都是按公开教程的组织与概念对照，代码独立重写；不复制 GPLv3 代码。
- **写作机可交叉汇编，但不能运行**：最多做到 `clang --target=riscv64-unknown-elf ... -S/-c` 的 `.s`/`.o` 级检查，没有 RISC-V 链接器与运行时，不能链接成 ELF，更不能执行。本套件没有把交叉汇编输出当作证据。
- **主机示例也未复跑**：1.19.4 与 1.19.6 声称可在主机 `rustc` 直接跑；本套件没有复跑，引用时只把它当「代码形状 + 预期输出形状」。即便主机能跑，也不证明内核里能跑。
- **口径分四类**：rCore 教程的章节组织（只对照主题，不绑定 commit）；RISC-V 特权级规范与 Linux 6.8 的结构事实；量级示例（512 字节块、32 字节 inode、4 KiB/2 MiB 页）；未实测（全部构建、QEMU、GDB、串口输出）。
- **不编造**：凡是本机没有证据的构建结果、寄存器值、断点命中与文件系统镜像字节，一律不写成「实测」。

## 怎么读

- **第一次读**：先读 1.19.1 的八阶段表，在纸上抄下五列，然后按 1.19.2 → 1.19.3 → 1.19.4 的顺序填；每填一格，问自己「上一阶段缺了什么，才需要这一格」。
- **已经写过 rCore 或 xv6**：直接跳到 1.19.4–1.19.6，重点看 `MapArea`/`MemorySet` 与 `PageTable` 的所有权分层、fork 的 fd 表语义、`myfs` 的块号；再回 1.19.9 的对照表检查自己是否把 rCore 当成了「小 Linux」。
- **准备面试或课程设计**：八阶段（1.19.1）、`TaskContext` 与 `__switch`（1.19.3）、Sv39 手算（1.19.4）、fork/exec 差异（1.19.5）、一次 `read` 的路径（1.19.8）是五处必答；先做[习题集](ch19-exercises.md) A 组。
- **怕把示例当读数**：本章所有运行结果都没有本机证据；`batch: app exit`、`VA 0x... -> PA 0x...`、`hello, myfs!` 都只表示「应该看到什么形状」。环境边界统一记在[勘误页](ch19-errata.md)的「本章未实测项」。
- **读不进去时**：先合上正文，只看 1.19.1 的表，用「如果我是应用，我现在缺什么」自问一遍；卡在页表就回 [1.9 虚拟内存](ch09.md)，卡在 `Arc`/`Weak` 就回 [1.17 Rust 系统编程](ch17.md)。

## 路线标签与项目回链

- **应用/运维：可后补** 1.19.2–1.19.4 的实现细节；**必读** [1.19.8 一次 `read` 的完整路径](ch19.md#sec-1.19.8) 与 [1.19.9 设计对照](ch19.md#sec-1.19.9)。它们能解释 `strace` 里一次 `read` 为什么有时快、有时阻塞，以及容器里的「文件系统」被换掉了哪一层。
- **系统编程：必读** [1.19.5](ch19.md#sec-1.19.5)、[1.19.6](ch19.md#sec-1.19.6)、[1.19.8](ch19.md#sec-1.19.8)。fork 的 fd 语义、`Arc<dyn File>` 的共享、`read` 的返回值与错误码，直接对应第 2 篇的 `fork`/`exec`/`read`/`write`。
- **内核/嵌入式：必读** 1.19.1–1.19.9 全读，尤其是 Sv39、`satp`、`sfence.vma`、`__switch` 与 COW；1.19.10 的 GDB 断点方法在真机上同样适用。
- **项目回链**：1.18 的 P1（SBI 打印 + 关机）、P2（M→S→U 三特权级）、P3（tick 抢占雏形）是本章的前置骨架；本章把「打印 tick」换成「切换任务」，把「关机」换成「调度」，把「一个应用」换成「进程与文件」。
- **下一站**：[第 2 篇导览](../part2/overview.md) 与 [2.1.1 一次系统调用穿过什么](../part2/ch01.md#sec-2.1.1)。本章在 RISC-V 上讲 `ecall`，第 2 篇在本机 x86-64 上讲 `syscall`，两者是同一条「用户态陷入内核」的两种编码。
