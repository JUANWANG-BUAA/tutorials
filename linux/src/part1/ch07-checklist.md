# 1.7 学习目标自检表

这张表接管 [1.7.17 本章小结](ch07.md#sec-1.7.17)：左列是达标项，中列是「怎样算达标」——全部写成可当场验证的动作，不写「理解」；右列是正文依据与对应习题、回忆卡。本章是两遍式，达标项也分层：判读行（链接四步、报错分类、搜索顺序、打桩边界）考第一遍，手算与字节行（重定位算术、`nm` 字母、ELF 逐字段对账）考第二遍。卡住时回到依据列重读那一段，不要从头再读整章。

**使用建议**：先做[习题集](ch07-exercises.md)的 A 组定位概念缺口，B 组查「会不会分层选命令」，最后跑 C 组。凡是带「跑通」「复现」的达标线，必须在自己机器上真跑出结果才算勾；macOS 上没有 `readelf` 与 `ldd`，这些行只能在 Linux 虚拟机上勾，口径见[勘误与版本注记](ch07-errata.md)第 1 节。

## 没达标怎么办

- **概念行卡住**（四步、七步、五步搜索顺序、谁用 `NEEDED`）：回到对应小节的「小结」与「即时自测」，先口头讲一句完整因果——「因为链接期只记 soname，所以报错文本里出现的是 `libfoo.so.1`」这类。讲不出因果就还没到线，多读几遍不解决问题。
- **手算行卡住**（`S + A - P`、类型算式）：拿 [1.7.4](ch07.md#sec-1.7.4) 的两个数值在铅笔上重算一遍，再对 [1.7.11](ch07.md#sec-1.7.11) 的类型表逐条写算式。算不对通常是两处：把 `P` 当成指令首地址而不是位移字段地址，或者忘了 `call` 走的是 `L + A - P` 里的 `L`。
- **实验行卡住**（归档顺序、`LD_PRELOAD`、`RUNPATH`）：先确认环境口径再怀疑自己。macOS 上没有 `readelf` 与 `ldd`，这些行必须在 Linux 虚拟机上跑；Ubuntu 24.04 默认编译就带立即绑定，「第一次调用才解析」的现象要显式 `-Wl,-z,lazy` 才看得到；`ls`、`cat` 配钩子没有输出是 `LD_PRELOAD` 的正常边界而不是打桩失败。全部差异记在[勘误与版本注记](ch07-errata.md)。
- **判断行卡住**（B 组七题有答不顺的）：强迫自己写「发生在哪一层、先跑哪条命令、看到什么算确认、改哪一处」四段——这是[习题集](ch07-exercises.md)「怎么用」第 3 条的口径，少一段就是没定位完。
- **只有 A 组全对**：说明你还停在第一遍。本章是两遍式，手算行与 ELF 字节行（重定位算术、`nm` 字母、`elfdump` 对账）必须落笔、落终端过，口述不算达标。

全部达标后，进入 [1.8 异常控制流](ch08.md)：程序装好、跑起来之后，一个除零、一次缺页、一个 `Ctrl-C` 在内核里走哪条路径；`execve` 的系统调用语义在 [2.8.1](../part2/ch08.md#sec-2.8.1) 展开。
