# 1.15 章末总结

## 三段主线：三个单元，一条因果链

**第一段，控制与责任（1.15.1–1.15.2）。** 一次调用先要解决「回来时从哪继续」：x86-64 的 `call` 把返回地址压进栈，ARM64 的 `bl` 写 `x30`，RISC-V 的 `jal`/`call` 写 `ra`（`x1`）。因此 x86-64 的返回地址天然在内存里，ARM64/RISC-V 的在寄存器里；非叶函数必须自己把 LR/`ra` 存栈，否则下一次调用会覆盖。控制转移定下来后，ABI 用一张寄存器责任表分工：谁传参、谁返回、谁保存、栈怎么对齐、红区存不存在。把这张表背成「参数 → 返回值 → 被调用者保存 → 调用者保存」四行，读汇编时先查表再猜指令。

**第二段，指令、栈帧与参数（1.15.3–1.15.5）。** 三套指令的算术语义相同，差异集中在操作数方向、定长/变长、寻址方式与返回机制。序言只做三件事：腾局部空间、保存本函数要用的被调用者保存寄存器、在需要时建立帧指针；尾声按相反顺序恢复。`framed` 的三张栈图证明：返回地址在 x86-64 是硬件压的、在 ARM64/RISC-V 是软件存的；被调用者保存区一定在调用者栈帧之上；局部变量夹在 `sp` 与保存区之间。参数超过寄存器数量后才走栈：x86-64 只有 6 个整数参数寄存器，第 7 个起走栈；ARM64 与 RISC-V 有 8 个，第 9 个才走栈。结构体按分类规则拆寄存器，可变参数在 x86-64 还要用 `%al` 报向量寄存器个数。

**第三段，完整程序与证据（1.15.6–1.15.11）。** `_start` 没有调用者，所以不能 `ret`，结束必须 `exit`/`exit_group`；裸系统调用失败返回 `-errno`，不是 `-1`。内联汇编的难点不是指令，而是把「改了哪些寄存器、碰没碰内存、碰没碰栈」告诉编译器：C 用输出/输入/`"memory"` clobber，Rust 用 `in`/`lateout`/`inout` 与 `options(nostack)`。最后用 `objdump` 看序言与参数寄存器，用 `readelf -sW`/`-rW` 看符号与重定位，用 `gdb` 的 `x/6gx $sp` 核对返回地址与保存区；`perf` 不可用时只报时间与几何，不报 miss 数。

一句话主线：**先把「返回地址在哪 → 谁保存 → 栈帧怎么长 → 参数从哪取」四层规则分开，再把规则放进 `_start` 与内联汇编，最后用工具读数收口；看到一个调用，先问「返回地址在哪」，再问「谁保存」，最后问「参数从哪取」。**

## 表 1：寄存器与参数对照

| 项 | x86-64 SysV | ARM64 AAPCS64 | RISC-V 64 psABI |
|:--|:--|:--|:--|
| 整数参数 | `rdi,rsi,rdx,rcx,r8,r9`（6 个） | `x0`–`x7`（8 个） | `a0`–`a7`（8 个） |
| 浮点参数 | `xmm0`–`xmm7` | `v0`–`v7` | `fa0`–`fa7` |
| 返回值 | `rax`；128 位 `rdx:rax` | `x0`；128 位 `x1:x0` | `a0`；128 位 `a1:a0` |
| 被调用者保存 | `rbx,rbp,r12`–`r15` | `x19`–`x29`；`v8`–`v15` 低 64 位 | `s0`–`s11`（`x8,x9,x18`–`x27`） |
| 调用者保存 | `rax,rcx,rdx,rsi,rdi,r8`–`r11` | `x0`–`x18` | `a0`–`a7`、`t0`–`t6` |
| 返回地址 | 栈（`call` 压入） | `x30`（LR） | `ra`（`x1`） |
| 栈对齐 | 调用前 16 字节；入口 `rsp % 16 == 8` | 公共接口 16 字节 | 16 字节 |
| 第 7、8 个整数参数 | 栈：入口 `[rsp+8]`/`[rsp+16]`；建帧后 `[rbp+16]`/`[rbp+24]` | 仍在寄存器：`x6`/`x7` | 仍在寄存器：`a6`/`a7` |
| 第 9 个整数参数 | 栈：入口 `[rsp+24]`；建帧后 `[rbp+32]` | 入口 `[sp]`；建帧后 `[sp+32]` | 入口 `0(sp)`；建帧后 `32(sp)` |
| 红区 | 128 字节（叶子函数可用） | 无 | 无 |

这张表最容易照抄错的是第 8 行：**只有 x86-64 是 6 个整数寄存器，ARM64 与 RISC-V 都是 8 个**。第 7、8 个参数在 ARM64/RISC-V 上仍在寄存器里，第 9 个才进栈。

## 表 2：指令族对照

| 操作 | x86-64（AT&T） | ARM64 | RISC-V 64 |
|:--|:--|:--|:--|
| 加载 8 字节 | `mov 8(%rdi), %rax` | `ldr x0, [x1, #8]` | `ld a0, 8(a1)` |
| 存 8 字节 | `mov %rax, 8(%rdi)` | `str x0, [x1, #8]` | `sd a0, 8(a1)` |
| 加法 | `add %rsi, %rax` | `add x0, x0, x1` | `add a0, a0, a1` |
| 立即数加法 | `add $16, %rsp` | `add sp, sp, #16` | `addi sp, sp, 16` |
| 比较并跳转 | `cmp %rsi, %rdi; jg L` | `cmp x0, x1; b.gt L` | `bgt a0, a1, L` |
| 调用 | `call foo` | `bl foo` | `call foo`（`auipc`+`jalr`） |
| 返回 | `ret` | `ret`（`br x30`） | `ret`（`jalr x0,0(ra)`） |
| 栈分配 | `sub $32, %rsp` | `sub sp, sp, #32` | `addi sp, sp, -32` |
| 取地址 | `lea 8(%rdi), %rax` | `add x0, x1, #8` | `addi a0, a1, 8` |
| 系统调用 | `syscall` | `svc #0` | `ecall` |
| 内存屏障 | `mfence` | `dmb ish` | `fence rw, rw` |
| 空操作 | `nop` | `nop` | `addi x0, x0, 0` |

RISC-V 的 `sh1add`/`sh2add`/`sh3add` 属于 Zba 扩展，不是基线；ARM64 的 `casal` 需要 ARMv8.1-LSE；x86-64 的 `cmpxchg` 不加 `lock` 只是单核原子。

## 表 3：陷阱清单

| 陷阱 | 看起来像 | 实际是 | 当场怎么验证 |
|:--|:--|:--|:--|
| 三套汇编可以互搬 | 改改寄存器名就行 | 操作数个数、寄存器集合、`ret` 语义都不同；x86 两操作数，ARM/RISC-V 三操作数 | 把 x86 的 `sum3` 交给 `clang --target=aarch64-linux-gnu -c`，看未知寄存器报错 |
| 交叉汇编等于交叉运行 | `clang --target -c` 成功就能跑 | 没有 sysroot、`crt1.o`、`-lc` 与目标链接器；ELF 在 macOS 上也不能执行 | `-c` 成功后试 `-o`；`file`/`readelf -h` 看架构，但别把「能出目标文件」当「能运行」 |
| 第 7 个参数总在栈上 | 三套 ABI 都是 6 个寄存器参数 | x86-64 是 6 个，ARM64/RISC-V 是 8 个；第 9 个才在栈上 | 写 9 参数函数，`cc -O0 -S` 看第 7、8 个从 `x6`/`x7`、`a6`/`a7` 取 |
| `ret` 在 ARM64 上也弹栈 | 和 x86 一样从栈顶取地址 | `ret` 是 `br x30`；`stp x29,x30` 保存的是当前函数的 FP/LR，不是硬件压的返回地址 | 看 `bl` 后 `x30` 的变化；看 `ret` 的机器码是 `d65f03c0` |
| x86 系统调用第 4 个参数用 `rcx` | 函数调用表里第 4 个就是 `rcx` | `syscall` 用 `rcx` 保存返回 `rip`、`r11` 保存 `rflags`，第 4 个参数必须用 `r10` | 查 `syscall(2)`；写 4 参数 `write`，把 `r10` 改成 `rcx` 看 fd 是否写错 |
| `write` 的号到处是 1 | x86 是 1，别的也该是 1 | ARM64/RISC-V 遵循 asm-generic，`write`=64；ARM64 的 1 是 `io_destroy` | `grep -E '__NR_(write|io_destroy)' /usr/include/asm-generic/unistd.h` |
| x86 有红区，三家都能用 | 叶子函数都能往 `sp` 以下写 | 红区只有 x86-64 有 128 字节；ARM64/RISC-V 没有，写栈必须先减 `sp` | 看序言有没有 `sub`；在 ARM64 上写 `sp` 以下会踩调用者数据 |
| 内联汇编在 `-O0` 对就行 | 不加约束也能跑 | 缺 `"memory"`/clobber 时编译器会重排或复用寄存器，问题只在 `-O2` 出现 | 同一段 C 用 `-O0` 与 `-O2` 各编一次，比较输出与汇编 |
| 裸 `syscall` 失败返回 `-1` | 和 libc 一样设 `errno` | 裸系统调用返回 `-errno`；`errno` 是 libc 包装做的 | 故意传坏 fd，检查返回值是否 `-EBADF` |
| CSAPP 扫描版能引页码 | 中文第 3 版和英文版一样 | 纯扫描版没有文本层，页码也不对应；只能按目录与章节号核对 | 在 PDF 里选中文字，复制为空或 `pdftotext` 无输出即是扫描版 |
