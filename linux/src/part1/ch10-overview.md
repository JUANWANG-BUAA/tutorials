# 1.10 系统级 I/O · 本章导航

::: preview 这一章在讲什么
`read(fd, buf, 4096)` 为什么可能只返回 100 字节？`write` 返回成功时，数据到底在用户缓冲区、page cache 还是磁盘？`printf`、`write`、`mmap`、`sendfile` 该怎么选？这一章不按 API 手册逐条背，而是把三个问题压成一条主线：**fd 是进程 fd 表的下标，返回值是接口契约，缓冲是分层的事实**。先用 1.10.1–1.10.7 建立句柄、元数据、目录与缓冲的判读；再用 1.10.8–1.10.10 把 fd 拆成「fd 表项 → 打开文件描述 → inode」三层，补齐 `dup2`、`O_CLOEXEC`、`EMFILE`、`close` 的边界；然后用三个完整程序（1.10.11–1.10.13）把短读、短写、`EINTR`、`EAGAIN`、`openat` 遍历写成能编译的代码；最后用 `strace`、`dd`、`/proc` 做两个实验（1.10.14–1.10.15），让「缓冲、落盘、对齐」变成可核对的读数。

## 这一章回答什么

三个词先记住：**fd** 是进程 fd 表的下标；**打开文件描述**（open file description）是 `open` 创建、保存偏移与状态标志的内核对象；**inode** 是文件系统里代表文件的对象，保存元数据与数据块位置。**page cache** 是内核用空闲内存缓存文件页的那一层，`read`/`write` 大多先经过它。

- **返回值到底承诺了什么**：`read` 的 0、短计数、`-1/EINTR`、`-1/EAGAIN`、`-1/EPIPE` 各是什么，`write` 为什么也会短写，`close` 成功为什么不等于落盘。
- **数据在哪一层**：stdio 的用户态缓冲区、内核 page cache、块层与设备缓存各在哪一段；`fsync`、`fdatasync`、`O_SYNC`、`O_DIRECT` 分别把边界画在哪里。
- **接口怎么选**：原生 fd、stdio、RIO、`mmap`、`sendfile`、`splice`、`copy_file_range`、`io_uring`（异步 I/O 接口）、`epoll`（事件通知接口）各自适合什么，哪些限制会让它在你的场景里失效。

## 读完你会

- 用 `open`、`read`、`write`、`lseek`、`close` 与 fd 0/1/2 解释任意重定向组合，并说清 `cmd >out 2>&1` 与 `cmd 2>&1 >out` 的差别。
- 把 `read`/`write` 的返回值拆成七种情形，写出同时处理短读、短写、`EINTR`、`EAGAIN` 的 `read_full`/`write_full`。
- 用 `stat`、`lstat`、`fstatat` 读元数据，解释 `st_size` 与 `st_blocks`、`st_blksize`、`st_ctim` 各是什么，以及符号链接跟随与否。
- 用 `opendir`/`readdir`/`closedir` 遍历目录，处理 `DT_UNKNOWN`、`readdir` 返回指针被覆盖、目录项名字长度有限这三件事。
- 画出 fd → 打开文件描述 → inode 的三层结构，说明 `open` 两次、`dup`、`fork`、`SCM_RIGHTS` 四种情况下偏移与状态标志是否共享。
- 用 `dup2`/`dup3` 做原子重定向，用 `/proc/self/fd` 查 fd 目标，并从 `(deleted)` 后缀判断「磁盘空间为什么没释放」。
- 解释 `write` 成功、进程崩溃、机器掉电三种「成功」的差别，写出「临时文件 → `fsync` → `rename` → `fsync` 目录」的持久化顺序。
- 说清 stdio 的三种缓冲、`fork` 后缓冲区被复制两次、stdio 与 `read` 混用为什么会丢数据。
- 按场景在 stdio、RIO、`mmap`、`sendfile`、`splice`、`copy_file_range`、`io_uring` 之间选型，并说出零拷贝省掉的是哪一次拷贝。
- 用 `strace -y`、`strace -c`、`dd iflag=direct` 与 `/proc/self/io` 把缓冲、短写、对齐与 page cache 变成可复现的证据。

## 先修与预计学时

- 先修：[0.5.1 三个 fd 与文件描述符表](../part0/ch05.md#sec-0.5.1) 与 [0.5.8 fd 表的内核结构](../part0/ch05.md#sec-0.5.8)——本章会把那张表拆成三层；[0.5.11 管道的内核语义](../part0/ch05.md#sec-0.5.11) 的 `PIPE_BUF` 与 `SIGPIPE` 是 1.10.9 的直接前身；[0.9.10 信号的处置、阻塞与排队](../part0/ch09.md#sec-0.9.10) 里的 `SIGPIPE` 处置决定 `write` 返回 `EPIPE` 还是进程直接终止。
- 进程侧从 [1.1.4 从 shell 到进程：fork、exec、wait](ch01.md#sec-1.1.4) 的 `fork`/`execve`/`wait` 接过来；`execve` 成功后 `_start` 的现场（`argc`/`argv`/`envp`/auxv）在 [1.1.20 `_start` 的现场](ch01.md#sec-1.1.20)，本章不再重讲加载，只讲程序拿到的 fd 表与缓冲区。
- 内存侧只需知道 [1.9.5 Linux 地址空间与 mmap](ch09.md#sec-1.9.5)：`mmap` 把文件页映射进地址空间，读写触发缺页（访问尚未驻留的页时陷入内核）；page cache 与文件映射的完整关系在 1.10.6 与 1.10.15 展开。
- 阅读：约 140–170 分钟（17 节）；抄三个完整程序并跑通：约 90 分钟；两个实验：约 45 分钟；章末习题：约 60 分钟。
- 环境：本章实验在 Linux 上做。本书的复现环境是 Ubuntu 24.04.5 虚拟机（aarch64、内核 7.0.0-38-generic、GCC 13.3.0、glibc 2.39、strace 6.8）。`/tmp` 支持 `O_DIRECT`，`/proc/self/fd` 与 `/proc/self/io` 可读；`sudo` 不可用，所以 1.10.15 的 `drop_caches` 那一步不能照跑，替代做法见[习题集](ch10-exercises.md) C4。macOS 没有 `/proc` 与 `O_DIRECT`，BSD 与 GNU 的差异见[勘误与版本注记](ch10-errata.md)。

## 怎么读

- **第一次读**：按段走 1.10.1–1.10.10，每节做完即时自测再往下。1.10.8 与 1.10.9 是全章的脊梁：前者解释「fd 是什么」，后者解释「返回值是什么」；这两节没读懂，后面的程序只会变成抄代码。
- **正在排一个具体的故障**：先看[章末总结](ch10-summary.md)的「症状 → 机制 → 命令」表，再跳到对应小节。日志丢最后几行看 1.10.6，`read` 只拿到一部分看 1.10.9，`df` 不降看 1.10.10，`accept` 报 `EMFILE` 看 1.10.8。
- **要动手**：1.10.11–1.10.13 的三个程序都能直接编译，先跑通再看解释；1.10.14 与 1.10.15 的实验要按顺序做，先数 `write` 次数，再动 `O_DIRECT`，否则分不清是缓冲还是对齐。
- **准备做题或面试**：1.10.9 的返回值表、1.10.10 的重定向顺序、1.10.2 的四个字段是三处必答；把[习题集](ch10-exercises.md) A 组做完，再做 B 组。
- **怕数字搬家**：1.10.12 的参考吞吐属于正文标注的 NVMe/ext4 机器，1.10.13 的目录统计是形状示例；本书虚拟机的实测覆盖 1.10.11 的 `EINTR` 输出、`strace` 的 `write` 次数、`O_DIRECT` 的 `EINVAL`、`/proc/self/io` 的 page cache 计数。哪些没测，统一记在[勘误与版本注记](ch10-errata.md)。

## 前后接口

- **上游**：[0.5](../part0/ch05.md#sec-0.5.1) 给的是 shell 视角的 fd 表与 `dup2`，本章把它换成内核对象；[0.9.10](../part0/ch09.md#sec-0.9.10) 给的是 `SIGPIPE` 的处置，本章把它接到 `write` 的 `EPIPE` 返回值；[1.1.4](ch01.md#sec-1.1.4) 给的是 `fork`/`execve`/`wait`，本章接住「`execve` 之后 fd 表原样保留」这一半，`_start` 的栈现场在 [1.1.20](ch01.md#sec-1.1.20)。
