# 1.1 计算机系统漫游：从源文件到进程 · 本章导航

::: preview 这一章在讲什么
一个 `hello.c` 从文本到进程，中间经历了什么？为什么 `printf` 最终变成 `write`？`fork`/`execve`/`wait` 各做什么？进程看到的“内存”是什么？缓存为什么能让程序快几十倍？这一章用 CSAPP 第 1 章的路径走一遍：源文件 → 四阶段 → ELF → 进程 → 内存 → 存储层次 → OS 抽象 → 网络 → Amdahl；第二遍再下潜到 `execve` 时间线、`_start`/auxv、静态/动态链接、重定位、PLT/GOT、Little 定律与 CPI。目标是**把“程序怎么跑”变成一条能指认证据的链路**。
:::

## 读完你会

- 说出预处理/编译/汇编/链接四阶段各做什么，`gcc -E/-S/-c` 各停在哪。
- 读 ELF 的段/节，知道“可执行文件里有什么”。
- 解释 Shell → `fork` → `execve` → `wait` 的进程创建链路。
- 画出进程的地址空间：代码/数据/堆/栈/共享库/内核。
- 用存储层次解释缓存命中、局部性与性能差距。
- 说出 OS 的三个抽象（进程、虚拟内存、文件）与网络作为 I/O 设备。
- 用 Amdahl 定律判断“优化哪一段值得”。
- 用 `strace`/`readelf`/`objdump`/`perf` 串出证据链；解释 `_start`/auxv、重定位、PLT/GOT、静态/动态链接。
- 比较 x86-64/ARM64/RISC-V 三份 hello 的入口与 ELF 差异。

## 先修与预计学时

- 先修：读完 [第 0 篇](../part0/overview.md)；会 C、`gcc`、`gdb` 基础。**不需要**学过组成原理；ELF/链接/缓存的白话解释在本章开头。
- 阅读：约 120–150 分钟；实验与工具链：约 90 分钟；章末习题：约 60 分钟。

## 怎么读

- **第一次读**：1.1.1–1.1.10 按顺序；每节先做「即时自测」。`gcc`/`readelf`/`strace` 要自己跑。
- **只想理解“程序怎么跑”**：1.1.1–1.1.8；先建立链路，不急着看链接器。
- **想读链接/加载**：1.1.11–1.1.20；先 `readelf`/`objdump` 看证据。
- **想做性能**：1.1.6、1.1.9、1.1.21–1.1.22；先量再算。
- **卡住时**：先回[先修工具箱](../prerequisite.md)补 C/进程/缓存，再回到对应小节。
