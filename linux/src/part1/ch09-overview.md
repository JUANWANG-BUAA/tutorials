# 1.9 虚拟内存 · 本章导航

::: preview 这一章在讲什么
你已经知道进程手里有一张自己的地址清单（[1.1.5](ch01.md#sec-1.1.5)），也知道一次访存要先过缓存和 TLB（[1.6.7](ch06.md#sec-1.6.7)）。这一章把中间那一步拆开：一个 48 位虚拟地址怎样被切成四段索引加 12 位偏移，页表项里每一位管什么，缺页时内核凭什么决定「分配、换入还是发 `SIGSEGV`」。然后把镜头拉到用户态：`/proc/self/maps` 里的 VMA、`mmap` 的四种组合、`malloc` 背后的空闲链表与 tcache，最后用一个约 100 行的分配器和一个会触发 `SIGBUS` 的 `mmap` 程序把机制跑出来。16 节里有三对主题各讲了两遍（1.9.3 与 1.9.8、1.9.5 与 1.9.9、1.9.6 与 1.9.10）：第一遍建骨架，第二遍要求你会算、会跑；[勘误页](ch09-errata.md)记了这处合并稿留下的重叠。
:::

## 读完你会

- 分清虚拟地址（VA）、物理地址（PA）、页框号（PFN）与页内偏移，并说清「地址空间大小与物理内存大小无关」到底免掉了哪几件事。
- 把缺页分成次缺页、主缺页与无效缺页，指出哪一类要读存储、哪一类只能发信号，以及为什么「minor 就是只填 PTE」是错的。
- 手算一次四级页表遍历：从 `CR3` 出发，按 9/9/9/9/12 拆索引，算出表项地址、下一级基址和最终物理地址。
- 解释多级页表为什么省内存、单级页表在 48 位下要 512 GiB、大页把 TLB 覆盖范围放大多少倍，以及 TLB shootdown 为什么让 `munmap` 不是免费的本地操作。
- 读懂 `/proc/self/maps` 与 `smaps`：每个 VMA 的权限与路径、`Rss` 和 `Pss` 的差别、`VmSize` 为什么不能当内存用量。
- 说清 `mmap` 六个参数、`MAP_PRIVATE`/`MAP_SHARED` 与文件/匿名的四种组合、常见 `errno`，以及 `SIGBUS` 与 `SIGSEGV` 各在什么条件下出现。
- 画出一个带边界标记的空闲块，完成一次「请求 → 向上取整 → 分裂 → 返回 payload」和一次「释放 → 前后合并」的手算。
- 讲出 glibc `malloc` 的 tcache、fastbins、small/large bins、unsorted bin、top chunk、arena 与 128 KiB `mmap` 阈值各自解决什么问题。
- 用 ASan、Valgrind、`MALLOC_CHECK_` 与 `si_addr` 把「崩溃点」和「出错点」分开，并在没有 `perf` 的机器上写下降级路径。
- 对照 C 的 `malloc/free`、Rust 的所有权与 `Drop`、以及保守/精确 GC，说明「谁在什么时候释放这块内存」。

## 先修与预计学时

- 先修：[1.1.5 进程眼中的内存](ch01.md#sec-1.1.5)——地址空间、`maps` 的三段布局与 `SIGSEGV` 的第一次见面；[1.6 存储层次与缓存](ch06-overview.md)，特别是 [1.6.7 TLB、页与 NUMA](ch06.md#sec-1.6.7)——页是缓存块、TLB 是页表项的缓存，这两句话是本章的入口。**不需要**先学汇编或内核源码：PTE 的每一位、VMA、`brk` 与 `mmap` 的分工都会在第一次出现处解释。
- 会一点 C 就够了：本章的程序只用 `mmap`、`malloc`、`sigaction`、`mincore` 这些 libc 接口；Rust 对照节只要求读懂 `Vec` 与 `Drop` 的作用域。
- 阅读：约 170–200 分钟（16 节，含三对「速览 → 深挖」）；两处手算（1.9.3、1.9.8）约 40 分钟；两个完整程序与章末实验约 70 分钟；章末习题约 60–75 分钟。
- 环境：页表数字按 x86-64、4 KiB 页、48 位虚拟地址、四级页表讲；本书的 Ubuntu 24.04.5 虚拟机是 aarch64、内核 7.0.0-38、页大小 4096（`getconf PAGE_SIZE` 实测）、glibc 2.39、GCC 13.3.0，`sudo` 不可用。Apple Silicon 的页大小是 16 KiB，凡是写死 4096 的偏移都会差 4 倍，见[勘误与版本注记](ch09-errata.md)。

## 怎么读

- **第一次读**：按五段顺序走。1.9.3 与 1.9.8 是同一道手算题的两种深度，先读 1.9.3 把 9/9/9/9/12 拆熟，再读 1.9.8 补 PTE 位表与 canonical 判断；1.9.5 与 1.9.9、1.9.6 与 1.9.10 同理，不要把配对当成新主题。
- **只想排障**：进程被杀先看 [1.9.7](ch09.md#sec-1.9.7) 的 `si_addr` 与 ASan；RSS 不降先看 [1.9.13](ch09.md#sec-1.9.13) 的 `smaps_rollup` 与 [1.9.15](ch09.md#sec-1.9.15) 的第 10 条；`mmap` 返回 `MAP_FAILED` 直接查 [1.9.9](ch09.md#sec-1.9.9) 的 errno 表。
- **准备面试或考试**：三处必须落笔——1.9.3 的 walk、1.9.4 的 1 GiB 页表账、1.9.6 的分裂与合并；配[习题集](ch09-exercises.md)的 B 组与[回忆卡](ch09-recall.md)的 B 组。
- **怕结论搬家**：本章的数字分三类——x86-64 的教学条件（48 位、4 KiB、四级）、某台机器的读数（1.9.11、1.9.12、1.9.13 的输出）、以及本机读不到的计数器（1.9.13 的 `perf`）。换机器先重测页大小与 THP，再谈偏移与 `SIGBUS`。

## 前后接口：从哪来、到哪去

- **从哪来**：[1.1.5](ch01.md#sec-1.1.5) 给了「进程以为自己独占内存」的正面模型与 `maps` 的第一眼；[1.6.7](ch06.md#sec-1.6.7) 给了页、TLB 与 NUMA 的缓存视角。本章把这两块接起来：1.9.2 说明页为什么是「磁盘地址空间的缓存块」，1.9.3 与 1.9.8 说明 TLB 未命中之后那 4 次访存到底读什么。
- **并发侧**：线程共享地址空间，所以同一个 VMA 会被多个线程同时碰——[1.12.2](ch12.md#sec-1.12.2) 讲共享带来的自由与麻烦，[1.12.10](ch12.md#sec-1.12.10) 的 futex 就建在共享匿名映射上，[1.12.11](ch12.md#sec-1.12.11) 的 RCU 则解释内核为什么能不靠 GC 延迟回收。
- **系统调用侧**：本章只讲 `mmap` 的语义与失败路径；它在内核里怎样建 VMA、缺页时怎样走到文件系统，留给第 2 篇的 [2.3.4 `mmap`](../part2/ch03.md#sec-2.3.4) 与 [2.3.16 内核路径](../part2/ch03.md#sec-2.3.16)，共享内存接口的全表在 [2.15.8](../part2/ch15.md#sec-2.15.8)。
- **正文下一站**：文件页与匿名页的另一半是 page cache，[1.10 系统级 I/O](ch10.md) 接着讲 `read`/`write` 与 [1.10.15](ch10.md#sec-1.10.15) 的 page cache 证据；更理论化的分段、交换与页替换策略在 [1.13.3](ch13.md#sec-1.13.3) 与 [1.13.10](ch13.md#sec-1.13.10)。

## 路线标签与项目回链

- 应用/运维：**可后补**，优先 [1.9.5](ch09.md#sec-1.9.5)、[1.9.7](ch09.md#sec-1.9.7)、[1.9.15](ch09.md#sec-1.9.15)。会看 `maps`/`smaps`、知道 `VmSize` 不等于内存用量、能区分 OOM 与泄漏，已经够处理大多数线上问题；页表手算可以等需要时再回来。
- 系统编程：**必读** [1.9.3](ch09.md#sec-1.9.3)、[1.9.5](ch09.md#sec-1.9.5)、[1.9.6](ch09.md#sec-1.9.6)、[1.9.9](ch09.md#sec-1.9.9)、[1.9.10](ch09.md#sec-1.9.10)、[1.9.11](ch09.md#sec-1.9.11)、[1.9.7](ch09.md#sec-1.9.7)。`mmap` 的四种组合、`MAP_FAILED`、`SIGBUS`、`malloc` 的 128 KiB 阈值与 UAF，都是写 C 就会遇到的接口层事实。
- 内核/性能：**必读**全章，尤其 [1.9.4](ch09.md#sec-1.9.4)、[1.9.8](ch09.md#sec-1.9.8)、[1.9.13](ch09.md#sec-1.9.13)。TLB shootdown 接多核同步与大页，VMA 与缺页路径接第 3 篇的内存管理，`/proc` 下的读数接容器内存限制与 OOM 取证。
- 项目回链：A1 `mycontainer`（cgroup v2 的 `memory.max` 与 OOM、进程地址空间与 `fork`/`exec`）、A2 `myhttpd`（每连接缓冲区的 `malloc/free` 与 RSS）、B1 `myredis`（`fork` + COW 做 RDB 快照、碎片与 `malloc_trim`）、B2 `mydb`（4 KiB 页、buffer pool、文件 `mmap` 与页对齐）、C2 `myproxy`（零拷贝与 `sendfile`/`mmap` 的取舍）。见[项目总览](../projects/overview.md)与[项目 A](../projects/pa.md)、[项目 B](../projects/pb.md)、[项目 C](../projects/pc.md)。
