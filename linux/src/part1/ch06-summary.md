# 1.6 章末总结

## 五单元一览

| 单元 | 小节 | 核心问题 | 关键结论 | 典型陷阱 |
|:--|:--|:--|:--|:--|
| **一、介质与层次** | 1.6.1 → 1.6.9 | 每一层慢多少、为什么慢？ | 层次就是「上层是下层的缓存」；一次缺失搬一整行（通常 64 B），顺序访问能把一次缺失摊到 8 个 `double` 上，随机访问摊不掉。换算口径：一次 DRAM 约等于 100 次 L1 命中，一次 SSD 随机读约等于 1000 次 DRAM，一次 HDD 寻道约等于 10 万次 DRAM。SRAM 用 6 管不需刷新，DRAM 用 1 管 1 电容要刷新、还有行缓冲，NAND 按页读写按块擦除、有写放大与 TRIM。 | 把两张表的「典型值」当规格承诺；以为 SSD 没有寻道所以随机读写一样快；只优化命中率不想「一次命中能用掉几个字节」。 |
| **二、局部性与组相联** | 1.6.2、1.6.3 → 1.6.10、1.6.12 | 数据在内存里怎么排、地址怎么被硬件切开？ | 时间局部性让同一个块多待一会儿，空间局部性让一次取块覆盖多次访问，步长是天敌。三参数 $C=S\times E\times B$，地址拆成标记/索引/偏移三段：`offset` $=\log_2 B$、`index` $=\log_2 S$、`tag` 是剩余高位。32 KiB、8 路、64 B 得 $S=64$、6/6/20 位，`0xA5C8` 落在标记 `0xA`、第 23 组、块内偏移 8。12 次访问的 4 组 2 路表给出命中率 41.7%，只用 6 个块却互相驱逐——**冲突缺失与容量无关**。模拟器的 miss 率正好是 $64/\text{stride}$：步长 1 是 1.6%，步长 32 是 50%，步长 64 起 100%。 | 以为标记要比完整地址；把 4 KB 步长的极慢归因于「数组太大」；相联度调到很高却不看访问模式的映射；只看容量不看块内利用率。 |
| **三、缺失、替换、写与一致性** | 1.6.4 → 1.6.11 | 缺了怎么办、满了换谁、写什么时候到内存、多核看到同一份吗？ | 3C 用模拟器分开：随容量下降的是容量性、随相联度下降的是冲突性、剩下的下限是强制性。AMAT = 命中时间 + 缺失率 × 缺失代价，多级时把下层的 AMAT 当上层的代价；缺失代价是命中的 20 倍时，降缺失率远比降命中时间划算。替换靠伪 LRU 或 RRIP，且 LRU 只在组内有意义。现代 CPU 是写回 + 写分配，所以「写一次不再读」的 store 会先 RFO 读整行。MESI 的核心是**写之前必须拿到独占权**，S 到 M 要等其他核确认失效；同一行两个核各写各的就是伪共享。 | 以为缓存只有 L1/L2/L3（TLB、uop cache、store buffer 都各有缺失代价）；以为缺失率高就是代码写得差（流式负载天然高）；以为 write-back 总是更快；以为多核共享内存没有代价。 |
| **四、把结论变成代码与字节账** | 1.6.5、1.6.6 → 1.6.13、1.6.16 | 怎么改代码，省下多少字节？ | 循环顺序决定块内复用：`ijk` 里 `B[k][j]` 每次跳 $n\times 8$ 字节，$n=1024$ 时上界 68 GB；`ikj` 让 B 与 C 各约 $N^3/8$，总缺失约 $N^3/4$，只交换循环就少 8 倍。分块把三个 $b\times b$ 子矩阵压进 L2：$b \le \sqrt{\text{L2}/24}$，256 KiB 时 104、取 64；流量降到约 410 MB，纸面上是 1/166，实测远小于此，因为计算成了新瓶颈。三招是连续访问、分块、预取，再加对齐与 SoA。AoS 每粒子 16 B 只用 4 B，字节数差 4 倍，正文实测时间只差 1.69 倍。 | 分块大小靠直觉而不是容量反推；以为块越大越好；把某台机器的倍数抄成结论（L2 很大的那台机器上 `block64` 就没赢过 `ikj`）；不测就先改布局。 |
| **五、地址翻译与取证** | 1.6.7、1.6.8 → 1.6.14、1.6.15 | 缓存之外还有哪一层会缺、怎么把判断变成读数？ | TLB 是页表项的缓存：64 项乘 4 KiB 页只覆盖 256 KiB，换 2 MiB 大页覆盖 128 MiB，扩大 512 倍；四级页表一次遍历可能带来 4 次内存访问。NUMA 让「内存」不再是单一延迟，远程约 1.5–2 倍。工具分工：`cachegrind` 确定、可到行、但慢且模拟几何未必等于你的机器，只看相对；`perf` 是真实计数，但依赖硬件事件与权限。先读 sysfs 与 `getconf` 确认几何，别靠猜。 | 把 `perf` 那两段输出当自己机器会给的读数；容器或虚拟机里 miss 数为 0 就当没缺失；`getconf` 报 0 时继续用容量估算；只跑矩阵乘不画内存山。 |

## 一条主线

这一章从「一次访存要多久」走到「一次访存搬了多少无用字节」：**先建立层次和量级（1.6.1），才知道摊薄与预取为什么有意义；再看局部性（1.6.2），把注意力放到步长与布局；接着用三个参数把地址切开（1.6.3），于是缺失分成强制、冲突、容量三类（1.6.4），每类有自己的对策；对策落到代码就是循环顺序、分块、SoA、预取（1.6.5、1.6.6），落到地址翻译就是 TLB、大页与 NUMA（1.6.7）；最后用 `perf` 与 `cachegrind` 把这一切变成可核对的读数（1.6.8）。第二遍（1.6.9–1.6.16）不引入新主题，只把同一批主题换成能算与能跑的形式：数量级换算、12 次访问的地址表、可配置模拟器、AoS/SoA 程序、矩阵乘的字节流量、sysfs 与内存山实验；1.6.15 用 12 条陷阱收口，1.6.17 的达标自检由[自检表](ch06-checklist.md)接管。** 看任何一段慢代码，固定问三件事：**缺在哪一层？为什么缺（强制、冲突还是容量）？少搬多少字节？**

## 看到问题先选工具

| 症状 | 第一动作 | 为什么 |
|:--|:--|:--|
| 只知程序慢，不确定是不是访存 | `perf stat -d ./prog`；拿不到硬件事件就 `valgrind --tool=cachegrind ./prog` | 先把「慢」拆成缺失计数与时间，再决定往哪一层查。 |
| 二维数组按列或大跳访问慢 | 算一个块里被用到几个元素：$64/\text{stride}$（字节步长） | 决定缺失数的是块内利用率，不是数组大小。 |
| 数组不大却几乎每次必缺 | 怀疑冲突：检查步长是否是 4 KB 的因子；把 [1.6.12](ch06.md#sec-1.6.12) 的模拟器改成 `ways=1` 复现 | 同一组的地址互相驱逐，扩容量不解决问题，填充或换访问顺序才解决。 |
| 工作集明显大于 L2/L3 | 按 [1.6.16](ch06.md#sec-1.6.16) 的 $b \le \sqrt{\text{L2}/24}$ 选块，再上下试两档 | 分块针对容量性缺失；块大小由目标层容量反推。 |
| 结构体数组只读其中一两个字段 | 先测 `D1mr`/`DLmr`，再做 AoS 与 SoA 的 A/B（[1.6.13](ch06.md#sec-1.6.13)） | 布局改动的收益取决于每行有效载荷，且倍数依机器而变。 |
| 线程加到 2 个就变慢 | 把热点写变量拆到不同缓存行（`alignas(64)`）前后各计时一次；有 PMU 时用 `perf c2c` | 伪共享把每次写变成一致性事务，逻辑上不共享也没用。 |
| `memset` 或大块写很慢 | 确认是否 RFO：改用非临时存储或 `madvise` 路径，先测再改 | 写分配会先把整行读进来再改，纯写负载白读一遍。 |
| 大步长、跨页扫描变慢，缓存缺失解释不了 | 算 TLB 覆盖范围（项数 × 页大小），用 `/proc/self/smaps_rollup` 的 `AnonHugePages` 验证大页 | 缺的是地址翻译不是数据；大页是否生效有免特权的验法。 |
| 缓存层级参数不确定 | `getconf LEVEL1_DCACHE_LINESIZE`、`/sys/devices/system/cpu/*/cache/index*`、`lscpu` 三路对照，并把拿不到的字段记下来 | 估算块大小与别名都要真实几何；虚拟机会给出空字段，此时不要沿用别人的数。 |
| 换一台机器结论翻转 | 报出机器、内核与工具版本，只比自己与自己的差 | 本章的倍数（8 倍、1.69 倍、1/166）各自属于不同前提与不同机器。 |

## 能否讲出这八句话

1. 缓存与内存之间传输的最小单位是一行（通常 64 B），所以「顺序访问」把一次缺失摊到 8 个 `double` 上，随机访问摊不掉——层次表里的延迟差最终都体现在「每字节有用信息搬了多少无用字节」上。
2. 三个参数决定一切：$S=C/(E\times B)$、`offset` 占 $\log_2 B$ 位、`index` 占 $\log_2 S$ 位、`tag` 是剩余高位；32 KiB/8 路/64 B 是 20/6/6，`0xA5C8` 命中第 23 组、标记 `0xA`、偏移 8，而标记只比高位。
3. 缺失分三类，区分方法是拿模拟器扫两个维度：随容量下降的是容量性，随相联度下降的是冲突性，剩下的下限是强制性；4 KB 步长那个例子说明冲突缺失和缓存大小无关。
4. AMAT = 命中时间 + 缺失率 × 缺失代价，多级时逐层嵌套；命中 1 ns、缺失率 10%、代价 20 ns 得 3 ns，缺失率降到 2% 得 1.4 ns——缺失代价越大，优化缺失率越划算。
5. 替换只在组内发生，硬件用伪 LRU 或 RRIP 而不是真 LRU；写策略是写回加写分配，所以纯写的 store 会先触发 RFO 读整行，非临时存储才适合写一次不再读的数据。
6. MESI 保证一个核写某行前必须让别人的副本失效；两个核写同一行里的不同变量就是伪共享，逻辑独立也没用，修法是把它们放到不同行或按线程分片。
7. 矩阵乘的差距是搬出来的不是算出来的：`ijk` 在 $n=1024$ 时对 B 的流量上界约 68 GB，`ikj` 只交换循环就少 8 倍，分块到 $b=64$ 后约 410 MB；但实测加速比远小于纸面的 1/166，因为分块后计算成了瓶颈，而 L2 很大的机器上循环交换已经够用。
8. 地址翻译是另一条缺失链：64 项 TLB 配 4 KiB 页只覆盖 256 KiB，2 MiB 大页覆盖 128 MiB；`cachegrind` 能给到行的相对缺失数但模拟几何不等于真机，`perf` 是真实计数却依赖事件与权限——所以先用 sysfs 确认几何，再决定读哪个工具。
