# 1.8 异常控制流：进程与信号 · 本章导航

::: preview 这一章在讲什么
程序里的 `%rip` 只该沿编译器铺好的轨道走：顺序、分支、调用、返回。可它会被外力掰弯——一次缺页、一个 `Ctrl-C`、子进程退出、定时器到期。这一章把这几条弯道拆开：谁在什么时刻把控制权交给内核（1.8.1、1.8.8），内核给程序的容器长什么样（1.8.2、1.8.9），信号怎样产生、被挡住、再递送（1.8.4、1.8.10），跳回旧栈帧与按作业切前台各自要付什么账（1.8.5、1.8.12、1.8.6、1.8.14）。[1.1.4](ch01.md#sec-1.1.4) 已经给过 `fork/exec/wait` 的形态，[0.9.5](../part0/ch09.md#sec-0.9.5) 给过「先 TERM 再 KILL」，这一章回答它们背后那句「为什么」。结构是**两遍式**：1.8.1–1.8.7 建概念、给判读标准，1.8.8–1.8.14 重讲同一批主题，这一遍要求你会读 `strace`、会手拆 `status`、会写不丢信号的循环。
:::

## 读完你会

- 用「返回哪一条指令」把异常分成中断、故障、陷阱、终止，并说清缺页为什么必须重试当前指令。
- 说清一次 `syscall` 进内核时 `%rcx`、`%r11` 各存了什么，参数第四位为什么用 `r10` 而函数调用用 `rcx`。
- 说清 `fork` 之后哪些东西共享（文件偏移）、哪些复制（fd 表）、哪些清空（pending 信号），以及写时复制省掉的是哪一次拷贝。
- 用状态宏把 `status` 拆开，解释子进程 `exit(7)` 为什么整数值是 1792。
- 写出不会被「检查—睡眠」空窗坑到的等待：先阻塞、再用 `sigsuspend`，并说清它凭什么原子。
- 解释 `SA_RESTART` 重启哪些系统调用、不重启哪些，并写出 `EINTR` 重试循环。
- 说清标准信号「不排队」的后果：3 个子进程可能只来 2 次 `SIGCHLD`，所以要循环 `waitpid(-1, ..., WNOHANG)`。
- 用 `sigsetjmp(env, 1)`/`siglongjmp` 从处理函数跳出，并说清它没有恢复什么（锁、堆、打开的文件）。
- 从 `ps -o pid,ppid,pgid,sid,tpgid` 读出会话、进程组与前台组，复述 `Ctrl-Z` 的整条链路。
- 用 `strace`、`/proc/<pid>/status`、`ps` 三件工具，把「收不到信号 / 退出码不对 / 僵尸不消失」定位到具体一步。

## 先修与预计学时

- 先修：[1.1.4 从 shell 到进程](ch01.md#sec-1.1.4) 的五状态表与 `fork/exec/wait` 用法、[1.1.11 完整时间线](ch01.md#sec-1.1.11) 的 `execve`（本章默认你知道 `_start` 之前发生过什么）。**不需要**学过中断控制器、也不必读过内核源码：`task_struct`、IDT、`swapgs`、`sigaltstack` 第一次出现处都有大白话解释。
- 最省力的前置是 [0.9.10 信号的处置、阻塞与排队](../part0/ch09.md#sec-0.9.10)：那里从运维视角讲「为什么 `kill` 了没反应」，本章把它换成 API 与内核路径，并把「没反应」拆成掩码、pending、递送三件事。
- 阅读：约 150 分钟（17 节，含第二遍）；四个完整程序（1.8.11、1.8.12、1.8.13 的实验、1.8.15 的 Rust 对照）约 60 分钟；章末习题约 60 分钟。
- 环境：本章的 C 程序只用 POSIX 接口，macOS（arm64）与 Linux 都能编译运行；`strace`、`/proc`、`ps -o` 只在 Linux 上有。本书的 Ubuntu 24.04.5 虚拟机（aarch64、GCC 13.3.0、glibc 2.39、strace 6.8、`sudo` 不可用）上有三条限制：`dmesg` 被 `dmesg_restrict=1` 挡住、没有 `coredumpctl`、没有 Rust 工具链。它们决定了 1.8.7 与 1.8.15 该怎么读，详见[勘误与版本注记](ch08-errata.md)。

一句话主线：**先在纸上分清「谁把控制权交给谁」——异常是硬件交给内核、进程是内核给程序的容器、信号是内核通知进程的接口（1.8.1–1.8.7）；再把同一批主题换成能读的 trace、能拆的状态字、能跑的程序（1.8.8–1.8.14）；遇到任何「跳走了 / 收不到 / 退不掉」，固定问三件事——谁发的、发给谁、处理了没有。**

1.8.15 是 Rust 侧的对照（`Command`、`Child::wait` 自动处理 `EINTR`、`signal_hook` 的自管道），只有一遍；[1.8.17 本章小结](ch08.md#sec-1.8.17) 由[学习目标自检表](ch08-checklist.md)接管，正文只剩一张七行的引子。

往下的接口有两处。**缺页的下半场交给 [1.9 虚拟内存](ch09-overview.md)**：本章只讲到「内核修好页表就让指令重试」，页从哪来、满了换出谁、四级页表怎么走，从 [1.9.3 手算一次四级页表](ch09.md#sec-1.9.3) 与 [1.9.4](ch09.md#sec-1.9.4) 接走。**并发交给 [1.12](ch12.md#sec-1.12.2)**：本章的「进程级信号递给任意未阻塞线程」与「`fork` 之后只许调异步信号安全函数」，在讲线程创建与 `pthread_sigmask` 时会再出现一次（[1.12.8](ch12.md#sec-1.12.8)、[1.12.9](ch12.md#sec-1.12.9)）。

## 怎么读

- **第一次读**：按段走，每段先读第一遍、紧跟着读它的第二遍配对。只读第一遍会得到「信号会被合并」这类口号；配上 1.8.10 的标志表与 1.8.11 的循环收割，才知道该写哪一行。
- **只想排障**：从 [1.8.7](ch08.md#sec-1.8.7) 的三组命令开始——`strace -f -e trace=process,signal`、`/proc/<pid>/status` 的 `Sig*` 五字段、`ps -o ... tpgid`。确认「谁发的」再回 [1.8.4](ch08.md#sec-1.8.4) 判处置，改法看 [1.8.10](ch08.md#sec-1.8.10) 与 [1.8.16](ch08.md#sec-1.8.16)。
- **写 shell 或容器运行时**：[1.8.6](ch08.md#sec-1.8.6) → [1.8.14](ch08.md#sec-1.8.14) 是作业控制那条线，[1.8.9](ch08.md#sec-1.8.9) 的 subreaper 与孤儿回收是 PID 1 那条线，两条都要读。
- **准备做题或面试**：1.8.3 的复制/共享表、1.8.9 的状态宏、1.8.10 的 `SA_RESTART` 边界、1.8.12 的 `volatile` 是四处必答点，配[习题集](ch08-exercises.md)的 A 组与 B 组。
- **怕结论搬家**：[1.8.7](ch08.md#sec-1.8.7) 的 `dmesg`、`coredumpctl`、`(core dumped)` 在这一章的环境里都不按书上那样工作；动手前先读[勘误与版本注记](ch08-errata.md)。
