# 1.14 计算机组成与三套 ISA：x86-64 / ARM64 / RISC-V 64 · 本章导航

::: preview 这一章在讲什么
你已经在 aarch64 上写过程序、用 `objdump` 看过几次反汇编，但读到 `%rdi/%rsi`、`x0/x1`、`a0/a1` 时仍要靠猜；同一段 C 编译到三套 ISA 后，参数寄存器、栈帧偏移、指令字节全变了。这一章给一张「组成 → ISA → ABI → 机器码」的地图，再用流水线、cache 与内存模型解释「同一条指令为什么有快有慢」。读完你能读三套汇编、手算栈帧与 AMAT，并用 `objdump`/`readelf` 拿出证据。
:::

## 本章回答什么

先记住两条边界：**ISA 是软件与硬件的契约**（寄存器、指令编码、特权级、内存模型），**ABI 是 ISA 之上的一层约定**（谁传参、谁保存、栈怎么对齐、结构体怎么分类）。三套 ISA 的加法语义相同，差异几乎都落在这两层与内核 ABI 上。

- **一台机器最少由什么组成**：寄存器文件、ALU/FPU、控制单元、MMU、存储层次与中断控制器。程序员可见的语义仍是「一条指令接一条指令」，乱序与预测都藏在这层假象之下（1.14.1）。
- **同一段 C 为什么有三种写法**：`sum3` 在 x86-64 上是 `lea`/`add`/`ret`，在 ARM64 与 RISC-V 上是两条 `add` 加 `ret`。差别不在加法，在参数放哪、返回值放哪、返回地址放哪（1.14.3–1.14.4）。
- **系统调用怎么进内核**：`syscall`/`svc #0`/`ecall` 三条指令，号分别在 `rax`/`x8`/`a7`；号是内核 ABI，不是 ISA（1.14.5）。
- **一条指令的时间下限**：`T_clk` 由触发器延迟、关键路径、建立时间、skew 与 jitter 相加决定；频率上不去不是「厂商不努力」，是物理税（1.14.7）。
- **CPI 为什么大于 1**：五级流水的理想周期是 `k + (n−1)`，真实值还要加结构、数据、控制三类冒险；分支误预测一次十几拍，cache miss 一次上百拍（1.14.8–1.14.10）。
- **栈帧、编码与内存模型**：第 7、8、9 个参数在哪，`add x0,x0,x1` 的 32 位怎么拼，x86 的 TSO 为什么仍允许 Store→Load 重排——这三件事分别对应 ABI、ISA 与内存模型（1.14.11–1.14.13）。
- **怎样拿证据**：同一段 C 编到三套架构，比较指令条数与字节数；不依赖 libc 写 `hello`，用 QEMU 看系统调用；用 `getconf` 与计时验证 cache 几何（1.14.14–1.14.15.1）。

这一章是第 1 篇里唯一同时横跨「硬件、编译器、内核入口」的一章。它上接 [1.3 汇编基础](ch03.md#sec-1.3.1)，下接 [1.15 汇编与调用约定](ch15.md#sec-1.15.1)，也是第 3 篇读 `entry_SYSCALL_64` 与 `el0_svc` 的地基。

## 读完你会

- 在白纸上画出组成的最小模型（寄存器文件、ALU、控制、MMU、存储层次、中断控制器），并写出取指到写回的最小循环。
- 不查表说出三套 ISA 的指令长度、通用寄存器数、链接寄存器、零寄存器、特权级与系统调用入口。
- 对 `sum3` 写出三套汇编，指出参数、返回值、返回地址各在哪，并说清为什么 x86 版本只要 8 字节、ARM64 要 12 字节。
- 默写三张调用约定表的前六行：整数/浮点参数、返回值、被调用者保存、调用者保存、栈对齐、返回地址、红区。
- 写出一段 9 个 `long` 参数的函数，在三种 ABI 下指出第 7、8、9 个参数的位置；说清 x86-64 的 128 字节红区为什么另外两家没有。
- 用 `T_clk` 公式手算一个 7 nm 核的频率上限（本书例子是 241 ps → 4.15 GHz），并用 `P = αCV²f + I_leakV` 解释降压为什么比只降频省电。
- 算 5 级流水 `n` 条指令的周期数与 CPI，把分支误预测率代进 CPI；说清 99%→90% 为什么损失约 26%。
- 把 48 位地址拆成 `tag/index/offset`（32 KiB、8 路、64 B → 64 组、6/6/36 位），并算多层 AMAT（本书例子 5.2 拍）。
- 手算 `add x0,x0,x1`（`0x8B010000`）、`ldr x0,[x1,#8]`（`0xF9400420`）、`add a0,a0,a1`（`0x00B50533`）的编码，并用汇编器对答案。
- 说出 x86-64/ARM64/RISC-V 各允许哪些重排、各用什么屏障，以及为什么 QEMU 不能当内存模型的参考实现。
- 用 `cc -S`、`objdump -d`、`readelf -h`、`getconf` 在本机 aarch64 上取证；知道哪些实验因 `perf` 缺失只能标「未实测」。

### 环境与口径

- 环境：本书复现环境是 Ubuntu 24.04.5 虚拟机（aarch64、内核 7.0.0-38-generic、GCC 13.3.0、4 vCPU，`sudo` 不可用）。`cc`/`gcc`、`as`、`objdump`、`readelf`、`getconf` 可用；**`perf` 不可用**，所以 1.14.7 实验 A、1.14.8 的分支对照、1.14.10 实验 B 的 `perf stat`、1.14.15 的 `perf stat`/`perf c2c` 全部按「未实测」读，替代做法见[勘误与版本注记](ch14-errata.md)。
- 写作机是 macOS arm64 + Apple clang 21：`--target=x86_64-linux-gnu` 与 `--target=aarch64-linux-gnu` 能出汇编与 ELF 目标文件，但**不能链接**（`ld: unknown options: --hash-style=gnu --eh-frame-hdr`），也不能运行。`clang --print-targets` 在这台机器上没有注册 riscv64，所以 RISC-V 的汇编与 `llvm-mc` 核对按「未实测」处理；命令形状不变，换一台带 RISC-V 后端的 LLVM 即可复核。`llvm-mc`、`llvm-objdump`、`llvm-size` 不在本机 PATH 上；`/usr/bin/objdump` 能读 x86-64 与 aarch64 的 ELF 目标文件。
- 口径：本章的数字分四类——公式结果（241 ps、4.15 GHz、5.2 拍）、模型算式（12 ms 那类不在本章，本章是 CPI/AMAT）、工具输出（指令条数、字节数、`Machine` 号）、量级示例（7 nm 频率表、`size_lab` 的 30–40 字节）。C 组只把工具输出当读数，其余先写预期再跑。

## 怎么读

- **第一次读**：1.14.1–1.14.6 一口气读完，中间不要停；这三节是同一件事的三个切面。然后跳到 1.14.11 画栈帧，再读 1.14.14 的实验。1.14.7–1.14.10 可以在第二遍读，它们是「性能三笔账」，不依赖后面的实验。
- **正在排一个具体的故障**：汇编读不懂、参数对不上，先看 1.14.4 与 1.14.11；程序在 ARM64 上系统调用失败，看 1.14.5 与[勘误页](ch14-errata.md)的「系统调用号」；多线程出现「看起来不可能」的读到旧值，看 1.14.13 与 1.14.15.1；性能不对，先分频率、CPI、miss 三笔账（1.14.7–1.14.10），不要直接换编译器。
- **准备面试或课程考试**：三张表（1.14.4、1.14.11）、三种编码（1.14.12）、AMAT 手算（1.14.10）、内存模型表（1.14.13）是四处必答；先把[习题集](ch14-exercises.md) A 组做完，再做 B 组。
- **怕数字搬家**：本章的公式与工具输出可复算；7 nm 频率表、`size_lab` 的字节范围、1.14.15 的「预期量级」都是形状示例。`perf` 相关读数在本环境没有证据，统一记在[勘误页](ch14-errata.md)的「本章未实测项」。
