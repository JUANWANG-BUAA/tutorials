## 没达标怎么办

- **K 组卡住（概念行）**：先讲一句完整因果，例如「因为共享库要加载到任意地址，绝对地址重定位不能用，所以进 `.so` 的 `.o` 必须 `-fPIC`」。讲不出因果就回对应小节的「即时自测」，不要靠多读几遍。
- **M 组卡住（动手行）**：拿纸画两张图——「源码 → `.o` → `.a`/`.so` → 进程」四格，以及「调用点 → PLT → GOT → libc」三段；再合上正文默写 `ar rcs` 与 `cc -shared -Wl,-soname`。写不出就把 1.16.3 的构建段抄一遍再默写。
- **S 组卡住（实验行）**：先确认环境边界。VM 上 `cc`/`ar`/`readelf`/`nm`/`size`/`strip` 可用，`sudo` 与 `perf` 不可用，Rust 工具链没有；报不出环境就把结论降级成「未实测 + 原因」，不要用一次计时推一个常数。
- **A 组卡住（口径行）**：把「ELF/ABI 条款 / 工具输出 / 量级示例 / 未实测」四类分开记；`size` 的 `text` 不是文件大小，`nm` 的符号数不是质量指标，`perf` 的读数本环境没有。[勘误页](ch16-errata.md)的「本章未实测项」先读一遍。
- **只有 K 组全对**：说明你还停在「会读」。本章要求会造、会跑、会取证；把 M 组与 S 组做完再来勾这一页。

全部达标后，往下的接口有三处：[1.17 Rust 系统编程](ch17.md) 会把本章的 FFI 与工具链放进文件、线程与 socket；[2.1.1 一次系统调用穿过什么](../part2/ch01.md#sec-2.1.1) 会把链接好的二进制送进内核路径；项目侧的多阶段镜像构建会把「静态链接还是动态链接、基础镜像里有没有 `ld.so`」再考一遍。
