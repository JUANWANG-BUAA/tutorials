# 1.5 闭卷回忆卡

这一页不是摘要，而是一组**检索练习**。先只看问题，合上正文，开口说或落笔写；「看着熟」不算会。每张卡答完再展开核对。

建议在学完当天、隔天、第 3 天、第 7 天各做一次。每次只记三种结果：✓ 能完整写出；△ 有关键词但缺条件；× 完全想不起。下一轮只重做 △ 和 ×。算下界的那几张（回忆 3、7、9）要真的动笔，别只在脑子里过。

## A. 第一遍：度量、编译器与循环改写

::: method 回忆 1 · CPE 与固定开销

CPE 是什么，为什么比总时间好用？$T(n)=c+kn$ 里的 $c$ 和 $k$ 分别从哪来？测 CPE 时有哪三条最低要求？

::: sol 答案

CPE（每元素周期数）= 总周期数除以元素个数，把循环的启动开销摊到每个元素上，不同规模的实现才能直接比。$c$ 是固定开销（冷缓存、循环建立、调用与计时本身），$k$ 是每元素成本；$n$ 越大，CPE 越接近 $k$。三条要求：$n$ 足够大、重复多次取最小值（不是取平均）、打印一个校验值防止整个循环被编译器删掉。用 `perf stat` 看周期数可以绕开频率漂移。
:::
:::

::: method 回忆 2 · 延迟、吞吐、CPE 三件事

分别说出延迟、吞吐、CPE 的含义，并各举一个正文里的数。哪个决定依赖链，哪个决定独立操作的并行度？

::: sol 答案

延迟是一条操作从输入到输出的时间（`add` 1 周期、`imul` 3 周期、L1 load 4–5 周期、浮点乘加 4 周期）；吞吐是每周期能完成几条（整数加 4 条/周期、浮点 2 条/周期、load 2 条/周期）；CPE 是每元素实际消耗。延迟决定依赖链的界，吞吐决定独立操作能并行多少；CPE 的下界取「链上延迟之和」与「吞吐的倒数」中较大的那个。
:::
:::

::: method 回忆 3 · 关键路径与下界手算

`s += a[i] * b[i]` 的浮点循环，单累加器和 4 个累加器的 CPE 下界各是多少？写出算式。再往上加累加器为什么不继续降？

::: sol 答案

单累加器：每次加法依赖上一次，界就是加法延迟 4。4 个累加器：界是 $\max(4/4,\ 1/2)=1$，前者是拆成 4 条链后的延迟约束，后者是浮点加法吞吐 2 条/周期。累加器加到 8 个时延迟项变 0.5，但 load 吞吐与 FMA 吞吐都在 0.5 附近，界不再下降——**优化的每一步是换一个更低的界，直到撞上下一个资源**。
:::
:::

::: method 回忆 4 · 编译器的三条边界

编译器在 `-O2` 下会做哪些优化？它不敢做的三件事分别卡在哪一步？

::: sol 答案

会做：常量传播、死代码消除、公共子表达式消除、强度削减、循环不变量外提、内联、指令调度，向量化在 `-O3`/`-ftree-vectorize` 下更积极。不敢做的三条边界都来自同一条底线：不能改变可观察行为。① 指针别名（`a` 与 `b` 可能重叠，写 `a[i]` 会改 `b[i+1]`，所以每次迭代都得重读）；② 未定义行为与浮点语义（不授权就不重结合，`a*a*a*a` 不会自动变成 `(a*a)*(a*a)`）；③ 外部调用与 `volatile`（不能证明被调函数不改内存，就不敢提升或外提）。
:::
:::

::: method 回忆 5 · 循环里哪些工作是白做的

列出消除循环低效的三类常见来源。`for (i = 0; i < strlen(s); i++)` 慢在哪，编译器什么条件下才敢只算一次？

::: sol 答案

三类：循环不变量（每次迭代算同一个值）、重复调用（`strlen`/`sqrt`/`malloc`）、低效抽象（取模做环形缓冲、带边界检查的访问、循环里拼字符串）。`strlen` 版本每次迭代都可能重扫一遍字符串，复杂度从 $O(n)$ 变成 $O(n^2)$；只有当编译器能证明 `s` 指向的内容在循环里不变（无别名、无外部调用改写、无 `volatile`）才会把它提到循环外，否则必须每次重算。手写的修法就是先存 `size_t n = strlen(s)`。
:::
:::

::: method 回忆 6 · 省内存引用与换布局

`for (…) *dest += src[i];` 为什么慢？改写之后长什么样，这个变换叫什么？AoS 换 SoA 换来什么、付出什么？

::: sol 答案

`dest` 可能与 `src` 重叠，编译器不敢把 `*dest` 缓存在寄存器里，于是每次迭代一读一写。改写成先 `acc = *dest`、循环里只加 `acc`、结束 `*dest = acc`：累加留在寄存器，一次写回。这个变换叫「把内存变量提升为寄存器变量」（标量替换）；能证明无别名时编译器自动做，否则 `restrict` 或局部变量是手动版。AoS 换 SoA：同样 64 字节的缓存行（一次从内存搬进缓存的那一整块）能装 16 个同类型字段而不是被相邻字段占掉，SIMD 也不必 gather；代价是「一条记录的所有字段」不再连续，跨字段操作多几次访存。**布局取决于访问模式，没有绝对优劣。**
:::
:::

## B. 第二遍：机器视角、定位与实测

::: method 回忆 7 · 展开与多累加器各解决什么

循环展开本身能打破依赖链吗？展开的收益上限由什么决定？手写展开的六步检查清单说得出几条？

::: sol 答案

不能，展开只减少循环控制开销（比较、跳转、指针更新）并给调度腾空间；破链要多累加器。上限来自寄存器压力、代码体积与 I-cache 缺失，还要处理尾部；通常展开 2–8 次配 2–8 个累加器。清单：确认迭代间无真依赖；展开因子乘单次操作数不超过可用寄存器；用 $k$ 个独立累加器最后合并；尾部另用小循环；`-O2` 与 `-O2 -fno-tree-vectorize` 各测一次，把展开收益和向量化收益分开；检查汇编，确认累加器没被重新并回一条链。
:::
:::

::: method 回忆 8 · 分支的三种手法与一个反例

优化分支的三个方向是什么？无分支绝对值怎么写？什么时候无分支反而更慢？

::: sol 答案

三个方向：让分支可预测（热路径在前、按条件排序数据后再处理）；消除分支（掩码、`cmov`、查表、算术）；把分支移到循环外做特化。无分支绝对值：`mask = x >> 31; return (x ^ mask) - mask;`——负数掩码全 1，取反加一；非负掩码全 0，值不变（`INT_MIN` 那条取负仍是未定义行为）。反例：无分支要把两边的结果都算出来，如果一边很贵，比如除法、函数调用，或者会缺页（那一页还没装进物理内存，要由内核把那页装进来）的访存，就一定不划算；而且编译器常已经把小 `if` 编成 `cmov`，手写未必更快，得看汇编。
:::
:::

::: method 回忆 9 · 存储层次三招与块大小估算

分块、SoA、预取各自解决什么问题？块大小怎么估？预取什么时候无效？非临时存储适合什么场景？

::: sol 答案

分块让一块 A、一块 B、一块 C 同时驻留 L1/L2，把「每次乘加都缺缓存」变成块内复用；SoA 提高每行缓存的有效载荷；预取把访存等待提前发出，让它被别的工作盖住。块大小按「几个块同时装得下」估：三个 $B_s \times B_s$ 的双精度块约 $3B_s^2 \times 8$ 字节，要不超过目标层级容量——256 KiB 时 $B_s$ 约 100，取 64 或 96。预取对顺序/固定步长无效（硬件已能识别，白加指令），对指针追逐、哈希表、稀疏矩阵则硬件预测不到，才需要软件预取，且距离要够又不太远。非临时存储（x86 的 `movntdq`）跳过读缓存行那一步，适合写一次不再读的大数组，随后要读的数据不能用。
:::
:::

::: method 回忆 10 · 读 perf 的七个字段与排查顺序

`perf stat` 之后按什么顺序排除瓶颈？IPC 大概怎么判读？LLC 缺失高、L1 缺失高但 LLC 低、后端停顿高各说明什么？

::: sol 答案

顺序：① 先确认基准可信（定频、绑核、多次取最小值、清负载）；② 看 IPC；③ 看缓存（LLC 缺失高就分块/SoA/预取或缩小工作集，L1 高而 LLC 低多半是访问模式或对齐）；④ 看分支失败率；⑤ 看前端停顿（代码体积、I-cache、内联过度）；⑥ 用 `perf annotate` 落到最热的指令；⑦ 一次只改一个变量，重测 CPE 与 IPC。IPC 判读：接近 0.2 是严重停顿，1–2 说明流水线较满，大于 2 说明超标量真的吃上了。
:::
:::

::: method 回忆 11 · Amdahl 与优化顺序

写出 Amdahl 定律，$p=0.9$、$s=10$ 时整体加速比是多少？正文给出的优化顺序是什么，为什么不能颠倒？

::: sol 答案

$S = 1/((1-p)+p/s)$，代入得约 5.26 而不是 10——非热点的 $(1-p)$ 决定天花板，找热点就是在找 $p$。顺序：换算法/数据结构 → 减少内存流量 → 提高缓存局部性 → 打破依赖链 → 消除不可预测分支 → 减少调用与边界检查 → 最后才手写 SIMD/汇编。算法是 $O(n^2)$ 时先做向量化等于给拖拉机换轮胎；每一层都要用 CPE 或 `perf` 量化，否则说不清收益来自哪一次改动。
:::
:::

::: method 回忆 12 · 别名、restrict 与两处实测

`restrict` 承诺了什么，违反会怎样？它除了删掉运行时重叠检查，还解锁了微架构上的哪件事？正文 1.5.12 与 1.5.13 各测出什么结论？

::: sol 答案

承诺是「在指针生命周期内，所指对象只通过它及其派生指针访问」；违反是未定义行为，不是「结果可能不对」。它还解锁了 store/load 的重排：写 `a[i]` 之后的读 `b[i]` 必须等 store 地址确定才能判定不冲突，`restrict` 让编译器敢把 load 提前、批量向量化。1.5.12（Apple M1、clang 15、`-O2`）：`ikj` 比 `ijk` 快一个数量级（$n=1024$ 时 0.258 s 对 4.568 s，约 8.32 对 0.47 GFLOP/s，折合约 0.77 对 13.6 周期/乘加），差距来自缓存而非 ALU；分块在这台 L2 很大的机器上没赢；`block4` 与 `block64` 几乎一样，因为内层已被自动向量化。1.5.13：同一份三数组相加，`plain` 8.830 ms、`restrict` 2.430 ms，校验一致。这些数值属于那台机器，换机器要重测。
:::
:::
