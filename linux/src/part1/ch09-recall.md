## A. 概念与判读

::: method 回忆 1 · 虚拟内存的三个角色

虚拟内存常被说成「内存不够时用磁盘顶替」。这句话漏了什么？说出它的三个真正角色，并解释为什么没有 swap 的系统也能正常工作。

::: sol 答案

漏了「swap 只是页回收的一个去处」。三个角色是：**缓存**——把物理内存当作磁盘上地址空间的缓存，页是缓存块，缺页就是缓存未命中；**管理**——每个进程一套独立地址空间，链接器不必预知加载地址，堆和栈可以各自生长；**保护**——页级权限位让进程之间、用户态与内核之间互相隔离。swap 只是在物理内存紧张时把冷页换出去的策略；没有 swap，内核仍然可以按需分配、COW、文件映射，只是内存压力下只能回收干净的文件页或触发 OOM。把虚拟内存等同于 swap，就会把「地址翻译与保护」这一整套机制漏掉。

:::
:::

::: method 回忆 2 · 三种缺页与成本

次缺页、主缺页、无效缺页各是什么？哪一类要读存储？「minor 就是只填 PTE」为什么不对？`/usr/bin/time -v` 的哪两个计数对应它们？

::: sol 答案

**次缺页（minor）**：处理时不需要从存储设备读页，例如文件页已在 page cache、匿名页首次按需分配、私有页写时复制；后两种仍可能分配、清零或复制物理页，所以不是「只填 PTE」。**主缺页（major）**：页不在内存，要读磁盘/SSD 或从 swap 换入，毫秒级。**无效缺页**：地址不在任何 VMA，或权限不符，内核发 `SIGSEGV`/`SIGBUS`，没有「修复」。`/usr/bin/time -v` 的 `Minor (reclaiming a frame) page faults` 与 `Major (requiring I/O) page faults` 就是这两类计数。一个刚 `fork` 的程序次缺页多，通常是 COW；一个冷启动程序主缺页多，通常是冷读大量文件页。

:::
:::

::: method 回忆 3 · PTE 的字段与「磁盘位置」

页表项里 `P`、`PFN`、`RW`、`US`、`A`、`D`、`NX`、`PS` 各管什么？页不在内存时，磁盘地址为什么不写在页表里？

::: sol 答案

`P` 表示页是否在物理内存，0 触发缺页；`PFN` 是物理页框号，和页内偏移拼成物理地址；`RW` 控制可写，写只读页触发保护故障；`US` 控制用户态可访问，内核页设为 0；`A` 是访问位，供页面回收判断冷热；`D` 是脏位，换出/回写时决定是否要写磁盘；`NX` 禁止取指，是 W^X 的落地；`PS` 在上级表项里表示 2 MiB/1 GiB 大页。页不在内存时，PTE 的 PFN 字段可以被内核复用为 swap 槽号或文件位置，但具体格式由内核决定；对用户态来说唯一可见的是「访问会触发缺页，内核负责弄回来」。文件页的磁盘位置由 `address_space` 与 inode 的映射维护，匿名页的 swap 位置由 swap 子系统维护——页表只负责「VA → PA」和权限。

:::
:::

::: method 回忆 4 · 多级页表、TLB 与 shootdown

单级页表在 48 位下为什么不可行？多级页表省在哪、代价是什么？TLB shootdown 是什么，PCID 省掉了哪一部分？

::: sol 答案

48 位地址、4 KiB 页有 $2^{36}$ 个页，每项 8 字节，单级页表要 $2^{39}$ 字节 = 512 GiB，而且每个进程一份。多级页表把大表拆成树，只给已映射的区间分配下级表；代价是每次 TLB 未命中要走 4 级、最多 4 次表项访存（中间级通常被缓存）。改页表后，其他核 TLB 里的旧翻译必须失效：单核用 `invlpg`，多核要发处理器间中断让所有相关核执行失效，这就是 TLB shootdown，是 `munmap`、`mprotect`、页迁移的隐性成本。PCID 给 TLB 项打地址空间标签，省掉上下文切换时的整体冲刷；但同一地址空间内的页表修改仍然要 shootdown。

:::
:::

::: method 回忆 5 · VMA、maps 与 smaps

内核用什么结构描述地址空间与区间？`maps` 一行有哪几列？`Rss`、`Pss`、`VmSize` 三个数分别说明什么？

::: sol 答案

`mm_struct` 描述一个进程的地址空间，一组 `vm_area_struct`（VMA）描述其中连续的区间；每个 VMA 记录起止地址、权限、是否文件映射、文件与偏移、操作函数表。`maps` 一行是「起始-结束 权限 偏移 设备 inode 路径」，例如 `55d0...-55d0... r-xp 00001000 08:01 1234567 /usr/bin/cat`。`Rss` 是常驻集，即实际占着的物理页；`Pss` 把共享页按共享进程数均摊，排查「内存去哪了」时更准；`VmSize` 是虚拟大小，包含保留但未提交的映射，通常大得吓人但没有意义。容器内存限制看 `Rss`/`Pss`，不要看 `VSZ`。

:::
:::

::: method 回忆 6 · 分配器的四条约束与家族

分配器必须满足哪四条约束？隐式、显式、分离、伙伴、slab 各解决什么问题？glibc `malloc` 的快速路径按什么顺序走？

::: sol 答案

四条约束：**对齐**（返回指针满足 `max_align_t`，x86-64 通常 16 字节）、**不重叠**、**不移动已分配块**、**及时复用**。隐式空闲链表把空闲块也顺序放在堆里，靠头/脚边界标记合并，查找 O(总块数)；显式链表把空闲块用 `next/prev` 串起来，只遍历空闲块；分离链表按大小分桶（16、32、64、…），分配近似 O(1)，是现代分配器主流；伙伴系统按 2 的幂分裂合并，用于内核页分配；slab/slub 为内核对象做缓存，不合并。glibc 的典型路径：tcache（每线程 64 桶，≤1032 B）→ fastbins（≤128 B，不合并）→ smallbin → unsorted → largebin → top chunk → `brk`/`mmap`；`free` 走 tcache（未满）→ fastbin → 合并 → unsorted。

:::
:::

## B. 手算

::: method 回忆 7 · 拆一个 48 位地址

VA `0x00007f3c5d2e8a40`：四级索引与页内偏移各是多少？写出每段的移位与掩码。

::: sol 答案

按 9/9/9/9/12 位切：

| 字段 | 计算 | 值 |
|:--|:--|--:|
| PML4 索引 | `(VA >> 39) & 0x1ff` | 254（`0xfe`） |
| PDPT 索引 | `(VA >> 30) & 0x1ff` | 241（`0xf1`） |
| PD 索引 | `(VA >> 21) & 0x1ff` | 233（`0xe9`） |
| PT 索引 | `(VA >> 12) & 0x1ff` | 232（`0xe8`） |
| 页内偏移 | `VA & 0xfff` | `0xa40` |

核对方法：五段加起来正好 48 位；索引都在 0–511；偏移小于 4096。这个地址是 `0x00007f...`，bit 47 为 0、高位全 0，是规范地址。

:::
:::

::: method 回忆 8 · 走一次四级页表

设 `CR3 = 0x1a000`，PML4[254] = `0x1b2067`、PDPT[241] = `0x1c3067`、PD[233] = `0x1d4067`、PT[232] = `0x2e8a0067`。求 VA `0x00007f3c5d2e8a40` 的物理地址，并说出每级表项地址怎么算。

::: sol 答案

每级表项地址 = 表基址 + 索引 × 8：PML4 表项在 `0x1a000 + 254×8 = 0x1a7f0`，读出 `0x1b2067`，去掉低 12 位标志得下一级基址 `0x1b2000`；PDPT 表项在 `0x1b2000 + 241×8 = 0x1b2788`，得 `0x1c3000`；PD 表项在 `0x1c3000 + 233×8 = 0x1c3748`，得 `0x1d4000`；PT 表项在 `0x1d4000 + 232×8 = 0x1d4740`，读出 `0x2e8a0067`，页框号 `0x2e8a0`，基址 `0x2e8a0000`。最后 `PA = 0x2e8a0000 + 0xa40 = 0x2e8a0a40`。低 12 位 `0x67 = 0b1100111` 说明 `P=1`、`RW=1`、`US=1`、`A=1`、`D=1`；普通 4 KiB 叶 PTE 的 bit 7 是 PAT，不是 PS，PS 在上级 PD/PDPT 项里。

:::
:::

::: method 回忆 9 · 1 GiB 匿名区要多少页表

一个进程映射 1 GiB 连续匿名内存，按 1 GiB 边界对齐，全部建立 4 KiB 页映射、不用大页、不计其他 VMA。四级页表占多少内存？只预留未访问时能直接套这个结果吗？

::: sol 答案

1 GiB / 2 MiB = 512 个 PT 页；每个 PT 页 512 项 × 8 B = 4 KiB，共 2 MiB。再加一个 PD 页、一个 PDPT 页、一个 PML4 页，各 4 KiB，共 515 页 = 2 MiB + 12 KiB。这是题设下页表本身的开销，不含数据页。只 `mmap` 预留地址不会立刻建齐这些页表：内核通常等第一次访问、缺页时才逐级分配；未按 1 GiB 对齐时还可能跨越额外的上级表，不能无条件套 515。

:::
:::

::: method 回忆 10 · 一次分裂与合并

64 KiB 空闲块，头部 16 B、脚部 8 B、块大小按 16 字节对齐，最小块 32 B。请求 100 B 返回多大的块、剩余多少？再请求 200 B 呢？释放第一个块后能合并吗？再释放第二个呢？

::: sol 答案

100 B 需要 `100 + 16 + 8 = 124`，向上取整到 128；原块 65536 ≥ 128，剩余 65408 ≥ 32，分裂；返回块 128 B，剩余 65408 B 变空闲块，用户指针 = 块起始 + 16。200 B 需要 `200 + 24 = 224`（恰是 16 的倍数），从剩余块头部切 224。此时释放第一个 128 B 块：前邻是堆头，后邻是已分配的 224 B 块，不能合并，只标记为空闲。再释放 224 B 块：两者相邻且都空闲，合并成 352 B 的空闲块，又可以满足更大的请求。这就是「四种合并情况」里的两种：前后都不空、只有后空/前空、都空。

:::
:::

::: method 回忆 11 · TLB 覆盖范围

64 项 L1 dTLB、1536 项 L2 STLB、2048 项 STLB 分别配 4 KiB 与 2 MiB 页，各覆盖多少地址范围？这解释了大页的什么收益？

::: sol 答案

覆盖 = 项数 × 页大小。64 × 4 KiB = 256 KiB；64 × 2 MiB = 128 MiB，放大 512 倍。1536 × 4 KiB = 6 MiB；1536 × 2 MiB = 3 GiB。2048 × 4 KiB = 8 MiB；2048 × 2 MiB = 4 GiB。大页的收益是同样的 TLB 项覆盖更大的工作集，随机访问大数组时 TLB 未命中大减；代价是内部碎片（最后一页没用满也要占 2 MiB）与分配/规整难度。注意「TLB 未命中」不等于「缺页」：未命中先走页表，目标页 present 且权限允许时不会触发缺页。

:::
:::

::: method 回忆 12 · 规范地址

x86-64 的规范地址（canonical address）要求什么？`0x00007f8c12345678`、`0x0000800000000000`、`0xffff800000000000` 各是不是规范地址？访问非规范地址会怎样？

::: sol 答案

要求第 63–47 位全部等于第 47 位（bit 47 是符号扩展位）。`0x00007f8c12345678` 的 bit 47 是 0，高位全 0，合法；`0x0000800000000000` 的 bit 47 是 1，但 bits 63:48 是 0，高位不等于 bit 47，属于非规范地址；`0xffff800000000000` 的 bit 47 是 1，高位全 1，是合法的内核半区地址。访问非规范地址会立刻触发通用保护故障 `#GP`，根本走不到页表；用户态指针被截断或符号扩展错时，常看到 `0x0000...` 与 `0xffff...` 混用导致的 `SIGSEGV`。

:::
:::

## C. 程序、工具与陷阱

::: method 回忆 13 · mmap 的参数、组合与失败

写出 `mmap` 的六个参数与各自的约束。四种「私有/共享 × 文件/匿名」组合在写时分别发生什么？`EINVAL`、`EACCES`、`ENOMEM` 各从哪来？`SIGBUS` 与 `SIGSEGV` 怎么分？

::: sol 答案

签名是 `void *mmap(void *addr, size_t length, int prot, int flags, int fd, off_t offset)`。`addr` 为 NULL 让内核选；`length` 必须 > 0，内核按页向上取整；`prot` 是 `PROT_NONE/READ/WRITE/EXEC` 的组合；`flags` 必须在 `MAP_SHARED` 与 `MAP_PRIVATE` 中二选一；`fd` 在 `MAP_ANONYMOUS` 时忽略；`offset` 必须是页大小的倍数。四种组合：私有文件映射写时 COW、不写回；共享文件映射写 page cache、其他映射可见；私有匿名是 COW 零页，`malloc` 大块走这里；共享匿名在 `fork` 后父子仍共享。`EINVAL`：length=0、offset 未页对齐、flags 冲突；`EACCES`：文件权限与 `prot` 冲突（只读 fd 上 `PROT_WRITE` + `MAP_SHARED`）；`ENOMEM`：地址空间不足、超过 `RLIMIT_AS`、overcommit 拒绝。失败返回 `MAP_FAILED`（`(void *)-1`），不是 NULL。`SIGSEGV` 是地址不在映射内或权限不符；`SIGBUS` 是映射存在但底层数据不可用，典型是访问完全在 EOF 之后的页、文件被截断。

:::
:::

::: method 回忆 14 · 64 MiB 与 100 KiB 的 malloc

`malloc(64 * 1024 * 1024)` 在 glibc 上通常走 `brk` 还是 `mmap`？`malloc(100 * 1024)` 呢？两者 `free` 之后，内存会立刻还给内核吗？

::: sol 答案

64 MiB 远大于 `mmap_threshold`（默认 128 KiB，动态调整），glibc 通常直接 `mmap` 一块匿名内存；`free` 时这块会 `munmap` 还给内核。100 KiB 小于阈值，通常从堆/arena 分配，底层可能是一次 `brk` 扩展；`free` 只回到 tcache/空闲链表，RSS 不一定下降，只有 top chunk 收缩或 `malloc_trim` 才可能把堆顶还给内核。用一个最小程序加 `strace -e trace=brk,mmap ./prog` 就能看到：64 MiB 那次出现一条约 64 MiB 的 `mmap`，100 KiB 那次多半只是 `brk` 增长。地址与具体阈值随 glibc 版本和分配历史变，不要写死。

:::
:::

::: method 回忆 15 · SIGBUS 与 mincore

1.9.12 的 `mapfile` 为什么要多映射一页？`body` 怎么算？为什么访问 `p[body]` 会 `SIGBUS`，而 `p[len]` 不会？`mincore` 的 `resident` 能保证什么、不能保证什么？

::: sol 答案

`body = ceil(len / page_size) * page_size`，是文件占用的整页数；`maplen = body + page_size`，多映射一页，专门用来撞「完全在 EOF 之后」的页。文件最后一页的尾部由内核零填充，所以 `p[len]`（在最后一页内）读到 0，不会 `SIGBUS`；`p[body]` 落在第一整页都在 EOF 之后的页，映射存在但没有文件数据，触发 `SIGBUS`（有的实现/条件也可能是 `SIGSEGV`，程序两个都捕获）。`mincore` 只回答「这一页当前是否在 page cache」，不保证下一秒还在；`MADV_DONTNEED` 之后会立刻变 0。本书 VM 实测：`/etc/hostname` 21 字节、页 4096，`caught at p[4096]`、`pages=1 resident=1`；Apple Silicon 16 KiB 页上边界是 16384。

:::
:::

::: method 回忆 16 · ASan 与 Valgrind 怎么选

ASan 与 Valgrind 的插桩方式、开销、能否不重编译各是什么？看到 `SIGSEGV` 先看哪两个字段？为什么「崩溃点」经常不是「出错点」？

::: sol 答案

ASan 是编译期插桩（`-fsanitize=address`），开销约 2 倍，能给出「哪一行写了哪个对象的哪一个字节」，适合定位越界与 UAF；Valgrind 是动态二进制翻译，开销 10–50 倍但不需要重编译，`--leak-check=full --show-leak-kinds=definite` 适合泄漏。看到 `SIGSEGV` 先看 `si_addr`（访问了哪个地址）与 `si_code`（是缺页、权限还是对齐），再对照 `/proc/$pid/maps`；不要直接归因空指针，`si_addr` 可能是 `0x0`、`0x10`、已 `munmap` 的地址或栈溢出附近。崩溃点离出错点远，是因为越界写 1 字节通常只破坏相邻块的 header 或另一个对象，直到 `free` 或下一次分配才被发现；ASan 的红区与影子内存把检查提前到写入处。

:::
:::

::: method 回忆 17 · 十二条陷阱里任选六条

从 1.9.15 的十二条里任选六条，按「现象 → 原因 → 修复」说完整。至少包含：双重释放、越界写 1 字节、`mmap` offset 未对齐、访问 EOF 之后的页、`fork` 后 COW 卡顿、RSS 不降。

::: sol 答案

① 重复 `free` → double free，glibc 报 `SIGABRT` → 置空指针后不再 free，用 ASan 复现。② 越界写 1 字节 → 破坏下一块 header → ASan；`malloc_usable_size` 不是容量承诺。③ `mmap` offset 非页对齐 → 内核返回 `EINVAL` → `offset % sysconf(_SC_PAGESIZE) == 0`。④ 访问文件 EOF 之后的页 → `SIGBUS` → 按 `st_size` 截断访问，捕获/处理 `SIGBUS`。⑤ `fork` 后子进程写大缓冲区卡顿 → COW 复制页表/物理页 → `posix_spawn`/`vfork`，减少 fork 前的大内存。⑥ RSS 不降、OOM 被杀 → 分配器缓存/`MADV_FREE`/碎片 → `malloc_trim`、`MADV_DONTNEED`、调 arena 数。其余六条：UAF、free 非堆指针、`realloc` 后用旧指针、`MAP_FIXED` 覆盖堆、大页没生效、`malloc(0)` 返回 NULL 被当失败。

:::

::: method 回忆 18 · 释放点放在哪里

C、Rust、引用计数、追踪 GC 各把「释放」交给谁？Rust 的 `Vec` 扩容与分配失败分别是什么语义？保守 GC 与精确 GC 的差别在哪？

::: sol 答案

C 把释放点交给程序员（`free`），代价是泄漏、悬垂、双重释放；Rust 把释放点交给作用域，`Drop` 在离开作用域时自动调用，移动后旧变量失效，安全代码里不会有悬垂；引用计数（`Rc`/`Arc`）把释放点交给计数归零，代价是循环引用与原子开销，循环要用 `Weak` 打破；追踪 GC 把释放点交给可达性，从根集（寄存器、栈、全局、TLS）出发标记可达对象，清扫不可达对象。`Vec` 扩容按几何增长（通常 2 倍），可能搬家并复制，`with_capacity` 可以避免多次搬家；Rust 分配失败默认 `handle_alloc_error`（abort），需要可失败分配时用 `try_reserve`。保守 GC 把每个落在堆范围内的字都当潜在指针，宁可误保留；精确 GC 依赖编译器生成栈图与写屏障，能移动对象、做并发回收。GC 只回收不可达对象，救不了 UAF，也挡不住全局缓存与未注销回调造成的泄漏。
