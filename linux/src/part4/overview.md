# 第 4 篇 · 网络

::: preview 这一篇在讲什么
一次 HTTP 请求从浏览器到服务器，经过 DNS、TCP、IP、网卡、内核协议栈、socket、`epoll`；任何一层都可能让请求超时。这一篇先用谢希仁/CSAPP 把协议分层讲清，再用《深入理解 Linux 网络》与内核源码把收包、发包、socket、`epoll`、百万连接的路径讲透。目标不是背首部字段，而是能用 `ss`/`tcpdump`/`bpftrace` 定位一次真实的网络故障。
:::

## 读完这一篇你会

- 画出一次 HTTP 请求经过的协议栈与内核路径。
- 解释以太网/ARP/VLAN/PPP、IP/路由/分片、UDP/TCP、三次握手/四次挥手、可靠传输/拥塞控制。
- 解释 HTTP、DNS、TLS 的关键机制与常见超时原因。
- 读懂内核收包/发包路径：NAPI、sk_buff、协议栈、qdisc、网卡驱动。
- 解释 socket 与 `epoll` 的内核协作、连接队列、loopback、百万连接的资源账。
- 用 `ss`、`tcpdump`、`perf`、`bpftrace` 定位超时、丢包、重传与队列溢出。
- 理解容器网络与常见调优参数的边界。
