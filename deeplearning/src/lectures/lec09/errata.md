## 二、术语与常见译误

用法：**当你在「同一个词指向两件事」上卡住时来查**。以下八条都是本讲内部就构成实际困惑的对比。

| 术语 | 常见误用／误译 | 正确理解 |
|:--|:--|:--|
| **DP vs DDP** | 把两者当同义词，于是「DP 省显存」这类话开始流传 | **DP** 是并行范式的名字（每卡一份完整模型状态、切数据）；**DDP** 是它的一个具体实现（PyTorch 的 `DistributedDataParallel`，反向中分桶异步 All-Reduce 梯度）。DP **不省显存**——它要求每卡都装得下完整模型状态（[定义 9.2.1](sec92.md#def-9.2.1)） |
| **shard vs partition** | 中文一律译「分片」，于是「流水线把层分片」这种说法出现 | **shard（分片）**指把**同一份张量 / 状态**切成 $1/k$ 各存一份（ZeRO / FSDP 的用法）；**partition（划分）**用于**把层或数据分配给不同卡**（流水线的 stage、数据分区）。流水线切的是层（划分），FSDP 切的是状态（分片），两者可以叠加但机制不同 |
| **ZeRO stage 与 FSDP 的关系** | 以为 FSDP 是「第四级 ZeRO」或「另一个 ZeRO」 | FSDP = **ZeRO-3 语义在 PyTorch 原生实现里的落地**（分片持有 + 按需 all-gather + 用完即散）（[定义 9.2.4](sec92.md#def-9.2.4)）。ZeRO-1/2/3 是**分片粒度递进**的命名；FSDP2 是后续重写（逐参数 DTensor 分片，见第三节）。说「FSDP 就是 ZeRO-3 的工程版」可以，说「第四阶段」不行 |
| **micro-batch vs global batch** | 把两者混用，于是等效批算错、学习率缩放改错 | **micro-batch** 是**一次前向真正吃进去的那一小批**（决定激活显存）；**global batch（等效批）** 是一次优化器更新累计的样本总数 $B_{\text{global}}=K\times M\times B_{\text{micro}}\times k$（[定义 9.2.2](sec92.md#def-9.2.2)、[方法 9.4.2](sec94.md#method-9.4.2)）。学习率只跟等效批联动，显存只跟 micro-batch 联动 |
| **tensor parallel vs model parallel** | 用「模型并行」统称 TP 与 PP，于是通信与气泡的代价说不清 | 早期文献的 **model parallelism** 泛指「切开模型」（含 TP 与 PP 两种）；本讲一律用精确词：**TP** 切**层内**权重与激活（每层都要通信、延迟敏感）、**PP** 切**层**（段间 P2P、气泡大）（[9.3](sec93.md)、[9.4](sec94.md)） |
| **activation vs model state** | 说「显存不够就分片」，不区分缺的是哪一本账 | **模型状态** = 参数 + 梯度 + 优化器状态 + 主权重，$\propto N$、与批大小无关（[定义 9.1.1](sec91.md#def-9.1.1)）；**激活** = 前向中间张量，$\propto B_{\text{micro}}T\,L$、用完可释放。分片 / 8-bit 优化器**只动状态**，梯度累积 / 重计算**只动激活**（[9.1.1](sec91.md#sec-9.1.1)、[9.1.3](sec91.md#sec-9.1.3)） |
| **loss scaling vs FP8 缩放** | 以为「都用缩放」，可以照搬 fp16 的配方 | fp16 的 **loss scaling** 是**一个标量乘在损失上**（把整条反向的梯度抬离下溢区）；FP8 的缩放是**逐张量（甚至逐块）一个因子**，且要用上一步统计量做**延迟缩放**（[定义 9.5.1](sec95.md#def-9.5.1)、[定义 9.5.2](sec95.md#def-9.5.2)） |
| **模型字节数 $P$ vs 参数量 $N$** | 通信量公式里把 $P$ 与 $N$ 混用，导致结果差 2 倍 | $N$ 是**参数个数**；$P$ 是这些参数占的**字节数**（bf16 下 $P=2N$）。梯度 All-Reduce 的通信量写作 $\approx2S$，其中 $S$ 是**被归约张量的字节数**（bf16 梯度时 $S=2N=14$ GB，$k$ 较大时每卡 $\approx2S=28$ GB 量级；正文 [例 9.2.2](sec92.md#ex-9.2.2) 用的是含 $(k-1)/k$ 因子的精确式，得 24.5 GB） |

## 三、时效补注

本讲涉及的默认答案是**硬件与框架的函数**，不是数学结论。下表按「主题 / 早期口径 / 截至 2025 年的实践 / 本教程的处理」列出；**凡涉及版本与倍数的条目一律以官方文档与你自己的实测为准**。

| 主题 | 早期口径 | 截至 2025 年的实践 | 本教程的写法 |
|:--|:--|:--|:--|
| 分片的框架形态 | ZeRO 阶段由 DeepSpeed 配置驱动（2019–2021 年代） | PyTorch 原生路线：FSDP 之后是 **FSDP2**（`fully_shard` + 逐参数 DTensor 分片，2024 年起，**无对应论文**，以官方文档为准） | [定义 9.2.4](sec92.md#def-9.2.4) 给 FSDP2 的三点变化，代码片段标「字段随版本变化，需核实」 |
| 低精度训练 | fp16 + 动态损失缩放 | **BF16 是安全默认**；**FP8**（E4M3 / E5M2，NVIDIA + Arm + Intel 联合定义，2022；Hopper 及之后原生支持张量核心）成为「有硬件 + 有官方配方」时的加速项 | [9.5.1](sec95.md#sec-9.5.1) 讲位布局，[9.5.2](sec95.md#sec-9.5.2) 讲 FP8 的缩放与门槛 |
| 流水线调度 | GPipe（先全前向再全反向）→ 1F1B → 交错调度 | **zero-bubble**（把反向拆成输入梯度与权重梯度、用后者填空档，2024）成为拓展方向 | [方法 9.4.1](sec94.md#method-9.4.1) 三种手段并列，并注明 zero-bubble 属拓展内容、收益须实测 |
| 跨机通信优化 | 直接 All-Reduce / Reduce-Scatter | **ZeRO++**（分层分区、量化梯度、二级分区，2023）与「用节点内带宽换跨机带宽」的思路 | [9.6.2](sec96.md#sec-9.6.2) 的拓展 `note` 给出三条思路，标「需按你的环境实测」 |
| 优化器状态压缩 | 全部 fp32 | **8-bit 优化器**（分块量化的 `m,v`，`bitsandbytes` 一类实现）在单卡微调里近乎默认，$16N\to10N$ | [9.5.4](sec95.md#sec-9.5.4) 给定义与代价，并在 [方法 9.5.1](sec95.md#method-9.5.1) 的对照表里给 7B 的 $112\to70$ GB |
| 微调范式 | 全参微调为主 | **LoRA / QLoRA** 成为受限显存下的默认（QLoRA 2023；主干 4 bit + 低秩适配器） | [定义 9.5.5](sec95.md#def-9.5.5)、[例 9.5.4](sec95.md#ex-9.5.4) 给出可复算账本 |
| 大规模故障率 | 「坏了重启」 | 万卡级训练把中断视为工程常量，公开报告（如 Llama 3 技术报告，2024）给出中断率统计 | [9.6.4](sec96.md#sec-9.6.4) 用 $\lambda\approx3\times10^{-6}$ 的量级表，并注明**引用报告须核对统计窗口** |
| 框架 API 字段 | 各框架自成体系 | `torch.distributed.pipelining`、`torch.distributed.checkpoint`、DeepSpeed ZeRO 配置、`peft` / `bitsandbytes` 量化配置等**字段名与语义随版本变化** | 正文所有代码片段只作**概念锚点**，凡字段处一律标「以你所用版本为准，需核实」 |

**一条通用提醒**：本讲所有带宽、算力与故障率数字都是**量级**（NVLink 约 300 GB/s、IB 400 Gb/s $\approx50$ GB/s、单卡有效算力 $10^{14}$ FLOP/s、$\lambda\approx3\times10^{-6}$/小时）。它们的用途是**让你在动手之前算出量级**，不是用来预测你的集群。**报价必须用你自己的硬件实测校准**（[9.7.4](sec97.md#sec-9.7.4)）。
