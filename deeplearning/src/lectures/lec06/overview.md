## 这一讲要解决的真实问题

前五讲已经把零件集齐了：[第 2 讲](../lec02/sec25.md)的 **Transformer** 提供序列骨干，[第 4 讲](../lec04/sec45.md)的**生成模型**给出采样框架与流匹配，[第 5 讲](../lec05/sec56.md)的**强化学习与偏好优化**提供对齐工具。本讲把它们**组装成今天最受关注的系统**：大语言模型、多模态模型、具身智能体。

但这一讲与前五讲有一个本质差别，值得在开篇就讲清楚：**前五讲的内容是收敛的，这一讲的内容是正在形成的**。Transformer 的注意力公式十年后大概仍是这个样子；而「能力涌现是不是度量假象」「视频生成模型算不算世界模拟器」「合成数据能不能突破数据墙」这些问题，**今天没有定论，且证据每月都在变**。

所以本讲的教学目标不是给你一套结论，而是给你三样东西：

1. **可用的工程判断**：哪些数字可以直接用（频率、延迟、token 预算、幂律形状），哪些必须条件化（缩放律常数、评测分数、成功率）。
2. **读取前沿主张的方法**：看到一个「突破」时，知道该问哪四个问题（哪类基准、有没有污染、方差多大、部署代价多少）。
3. **对争议的中立呈现能力**：本讲有三处**并列两方证据、不站队**的地方——能力涌现（[6.2.4](sec62.md#sec-6.2.4)）、世界模拟器之争（[6.6.8](sec66.md#sec-6.6.8)）、评测污染与刷榜（[6.7.2](sec67.md#sec-6.7.2)）。你要学的不只是两方说了什么，还有**怎样的实验能分辨它们**。

| **[6.7 评估、不确定性与可信部署](sec67.md)** | 怎么别被骗？怎样把分数变成可上线的决策？ | 四类评测各有失效方向，要看组合；污染有直接/近似/间接三条路径且**无法被证明不存在**；配对比较比平均分差可靠；模型系统性过度自信，弃答阈值是业务决策；缓存与分流是部署里回报最高的两步 | 用单榜第一名选型；把「没主动放测试集」当作无污染；用平均值估算成本而非 P95；回滚只切模型不管提示与配置 |

## 时效声明：本讲的版本时点与来源纪律

这一节是本讲与其余各讲**最大的体例差异**，请务必读完。

::: note 版本时点
本讲的素材以 **2023–2025 年**为主线，含少量必要的前置经典（标注原年份）。因此：

- **模型版本、榜单名次、定价、上下文窗口数字会迅速过期**。本讲给的是**量级与结构**（例如「一张 336² 的图约 576 个视觉 token」「10 万 token 会话的 KV cache 约 33 GB」），这些是可由算式复核的；一旦读到具体产品的规格数字，请视为**写作时点快照**并自行核对官方页面。
- **缩放律的常数与评测的分数尤其易变**。本教程的处理方式是给趋势与算式，不给「可以背下来套用」的点值（见 [6.2.1](sec62.md#sec-6.2.1) 与 [6.7.3](sec67.md#sec-6.7.3)）。
:::

::: method 来源纪律（写进正文的四条规则） {#method-6.0.1}
1. **论文引用给「标题 + 年份」**，有 arXiv 编号就附编号。**编号一律取自可核查来源，绝不编造**；凡素材中标注「无 arXiv / 编号未确认」的条目（如 MCP 规范、Sora 技术报告、o1 系统卡、Genie 后续版本、FLUX 权重、FSDP2 文档、部分 *Nature* 论文），本讲**只指向官方页面或会议/期刊**，不给编号。
2. **数据来源分三类标注**：① 课程/论文事实（可溯源）；② 工程惯例（注明「社区默认做法 / 经验共识」）；③ 本教程的推理（用「本书认为 / 建议」）。
3. **算例中的数字分两种**：凡**可复核的**（token 数、显存、频率、二项概率）都给出算式；凡**示意性的**（对照表中的成功率、成本倍数、PPL 数值）明确标注「示意」，**不作为任何论文的实测值引用**。
4. **争议话题必须并列证据**，禁止「众所周知」「研究表明」这类无主语表述。本讲的三处并列点已在「七节一览」表中标出。
:::

- **[Lab 1 · 音乐生成](../../labs/lab1.md)** 的字符级序列生成是「下一个 token 预测」的最小版本：把温度调一调，你会亲手体会 [6.1.1](sec61.md#sec-6.1.1) 里「似然与多样性」的取舍，以及 [6.3.2](sec63.md#sec-6.3.2) 中「多采样 + 投票」的原始形态。
- **[Lab 2 · 人脸检测系统](../../labs/lab2.md)** 提供视觉骨干与检测流程；[6.4](sec64.md) 的 VLM 是它的「语言侧延伸」——若你想做一个「用自然语言查询图像中的目标」的小系统，Lab 2 的检测模型可以直接当作工具接进 [6.6](sec66.md) 的 function calling 框架。
- **期末项目**：本讲可选题面很宽，几个成本可控且能产出可验证结论的方向——① **在自建小测集上复现「涌现是否依赖度量」**（固定模型族，画离散指标与连续指标两条曲线，见 [例 6.2.3](sec62.md#ex-6.2.3)）；② **亲手跑一次评测并做污染检查**（用 [lm-evaluation-harness](https://github.com/EleutherAI/lm-evaluation-harness) 在本地模型上跑一个基准，再与训练语料做 n-gram 比对）；③ **给一个多模态任务设计「错误归因探针集」**（照 [例 6.4.4](sec64.md#ex-6.4.4) 的六类探针改造到自己的任务上）；④ **搭一个最小 ReAct 智能体并测它的失败模式**（统计循环次数、无效工具调用率、以及有没有出现「未确认的不可逆操作」）。选题时先把**评价函数**写清楚，再动手（[6.7.6](sec67.md#sec-6.7.6)）。

**第一遍（约 4–5 小时，建立地图）**：按 6.1 → 6.2 → 6.3 顺序读，然后按兴趣在 6.4 / 6.5 / 6.6 中选一到两节，**最后必读 6.7**。目标是能画出「预训练 → 后训练 → 提示/推理 → 多模态/具身/智能体 → 评估」这条主线，并说出每一环里**最容易被高估**的那一点。

**必读、不许跳的框**：

- 每个 `def` 之后的 `intuition`——这一讲的手感几乎全在这里（尤其 [6.2.2](sec62.md#sec-6.2.2) 的「等比例扩张」与 [6.3.3](sec63.md#sec-6.3.3) 的「三条形态」）；
- [6.1.1](sec61.md#sec-6.1.1) 的[命题 6.1.1](sec61.md#prop-6.1.1)（交叉熵=压缩码长，本讲唯一的「必须会推」的地方之一）；

- [6.3.2](sec63.md#sec-6.3.2) 的**自洽性反例**（$p\lt0.5$ 时投票更差——这是最反直觉的一条）；

**二刷（约 5–6 小时，补齐中间步骤）**：逐行读 `proof` 与所有的**算式**——[6.2.1](sec62.md#sec-6.2.1) 的算力交换、[6.2.2](sec62.md#sec-6.2.2) 的反解 $N,D$、[6.3.2](sec63.md#sec-6.3.2) 的二项投票、[6.4.2](sec64.md#sec-6.4.2) 的视觉 token 账、[6.5.1](sec65.md#sec-6.5.1) 的频率—延迟算术、[6.7.4](sec67.md#sec-6.7.4) 的 ECE 与阈值决策。二刷结束时，你应该能在不看正文的情况下**复述这些算式的假设与结论边界**。

**动手**：三个最小实验，每个半天以内——① 用同一模型、同一批题，跑两次不同提示，亲手测出「几个百分点」的方差（[6.7.3](sec67.md#sec-6.7.3)）；② 给一道多步题采样 8 条 CoT 并做投票，观察准确率是否真的提升、失败时错误是否集中（[6.3.2](sec63.md#sec-6.3.2)）；③ 把一个待办任务写成 function-calling 工具集，检查自己有没有把不可逆操作暴露出来（[6.6.2](sec66.md#sec-6.6.2)）。

**自检路径**：每节的「即时自测」→ [本讲习题集](exercises.md)（A/B/C/D 四组）→ [闭卷回忆卡](recall-cards.md)（当天 / 隔天 / 第 3 天 / 第 7 天）→ [综合自测卷](mock-exam.md)（闭卷计时，100 分制）。

**时间预算参考**：只求建立地图、能读懂别人对前沿的主张，读 6.1、6.2、6.7 三节（约 2 小时）；要能独立设计一个可分辨争议的实验并做出部署判断，走完全部两遍并完成上面三个动手实验（约 14–18 小时）。

::: preview 第 7 讲引子：从「能力」到「后果」
本讲把模型从「文本续写」推到了**有实际副作用**的系统：它调用工具、驱动机器人、在环境里改变状态，而它的评测与部署都带着不确定（[6.7](sec67.md)）。这立刻引出下一讲要正面处理的问题——**怎样让这些系统可控、可信、符合人类价值**。

三处接缝值得预先记住：① 本讲反复出现的 **Goodhart 结构**（奖励上升质量下降、评测被优化、验证器被钻空子）在第 7 讲会以「对齐的限度」与「风险分析」的形式重新出现；② 本讲的**工具输出与提示注入**（[6.6.3](sec66.md#sec-6.6.3) 的信任边界）是第 7 讲安全议题的直接入口；③ 本讲的**弃答与校准**（[6.7.4](sec67.md#sec-6.7.4)）是「可信」在工程层面的最小可操作形态。

而在算力一侧，本讲提到的预训练、长上下文、长思维链与大规模 rollout 全部落在**[第 9 讲](../lec09/sec95.md)** 的并行与显存约束里——**本讲讲「能做什么」，第 7 讲管「该不该、稳不稳」，第 9 讲解决「怎么让它跑得动」**。
:::
