# 第 7 讲 · AI 的三条法则

> 前六讲都在回答「模型能做什么」，本讲换一个问题：**当一个系统足够强大、足够自主、被真实的人使用时，如何让它不做错事、也让我们知道它什么时候会错、并能在出错时找到负责的人。** 我们把这条主线拆成三条「法则」——**可控与对齐**、**可解释与可信**、**公平与责任**——每一条都给出定义、机制、缓解手段与局限。本讲几乎没有新数学，重点是建立一套**工程判断力**：把抽象的价值问题翻译成可测、可验证、可迭代的设计约束。

::: method[core] 10 分钟复习版 · 第 7 讲

**一句话**：AI 的安全与伦理问题可以拆成三条彼此独立的工程主线——**对齐**（目标对不对）、**可信**（我们能否理解它、知道它何时会错）、**公平与责任**（它对谁负责、谁担责）；三者都不能靠事后补一层过滤解决，必须当成**贯穿数据到监控的设计约束**。

**必记结论**

| 内容 | 要点 |
|:--|:--|
| **三条法则** | ①**可控与对齐**（目标对不对）②**可解释与可信**（能否理解、能否知道自己会错）③**公平与责任**（对谁负责、谁担责）。它们是**约束**，不是事后检查项 |
| **对齐问题** | 我们优化的是**代理目标** $g$，真正想要的是**意图** $u$；$g$ 升不保证 $u$ 升（见 [@def-7-1]） |
| **奖励黑客** | 策略找到在 $g$ 上得高分、却不推进 $u$ 的行为；是「代理目标 + 强大优化器」的结构性风险（见 [@def-7-2]） |
| **SFT** | 用「好回答」的示范数据做监督微调：直接、稳定，但成本高、**只覆盖已被示范的行为** |
| **RLHF** | 偏好数据 → 奖励模型 → RL 优化，并用 KL 惩罚拴住策略；奖励模型**仍是代理**，可被过度优化（见 [@method-7-1]） |
| **越狱与滥用** | 模型的「有用」与「安全」天然存在张力；防御靠**纵深**：红队 + 输入输出过滤 + 最小权限 + 分级部署 |
| **红队测试** | 主动、对抗性地寻找失效，是**降低未知风险**的手段，不是安全证明（见 [@def-7-3]） |
| **可解释性的两层** | **事后解释**（用更简单的对象近似行为）与**内省/机制**（打开内部看计算）；前者有**忠实性**问题（见 [@def-7-4]） |
| **校准** | 置信度应与实际正确率相符；深度网络常**过度自信**，且分布外校准不可靠（见 [@def-7-5]） |
| **鲁棒性** | 对抗扰动、分布偏移、捷径相关都会让**部署性能显著低于测试性能** |
| **公平准则** | 人口统计平价、均等化几率、分群校准等**互相冲突**（见 [@thm-7-1]）；必须显式选一个并说明代价 |
| **偏见来源** | **数据**（历史/采样/标注）、**目标**（代理指标 + 优化放大）、**部署**（群体与反馈回路）（见 [@def-7-6]） |
| **隐私与责任** | 去标识化**不等于**匿名；透明靠文档（模型卡）、审计、申诉、人在回路、可回滚来落实 |

**最该记住的四个判断**：① 优化「你写的目标」$\neq$ 优化「你想要的目标」——**一切对齐手段都只是把代理做得更接近意图，消除不了代理问题本身**；② 平均指标好、置信度高、红队没找到问题，**都不等于可信**——可信是多个正交维度的证据（正确率 + 校准 + 鲁棒 + 可解释 + 分群公平）；③ 「公平」**没有唯一正确解**，只有「按某个明确准则、并说清代价」的解；④ 安全是贯穿**数据 → 训练 → 评估 → 部署 → 监控**的设计约束，最后加一层过滤补丁不算安全。

:::

## 1.1 为什么技术人必须主动管后果

能力先于理解地增长，是这一领域最突出的事实：我们常常**先训出能用、好用的模型，事后才发现它在某些条件下会以不可接受的方式失败**。后果的成本并不由方法作者承担，而是被**外化**给用户与第三方——因此，「我只负责把模型做出来」不是中立，而是把风险推给了别人。技术人主动管后果，既出于责任，也因为**只有技术人清楚系统真正的失效边界在哪**。

::: intuition 为什么"再等等，让别人来管"不成立
安全与伦理落地的瓶颈，往往不是缺少讨论，而是缺少**能把它翻译成可测指标与可改代码**的人。伦理委员会决定「不该有群体性歧视」，但把它变成「哪几个子群的哪个指标、在上线门槛上要满足什么条件、达不到就回滚」——这是工程判断。你不做，讨论就停在口号层面；你做，才有可迭代的系统。这就是本讲把价值问题全部**工程化**的原因。
:::

现实中的失败可以归成若干**失效模式族**。它们的价值在于：拿到任意场景，你可以先用这张表**逐行排查**，而不是凭直觉。

| 失效模式族 | 触发原因 | 后果类型 | 主要对应法则 |
|:--|:--|:--|:--|
| **目标错设 / 代理目标漏洞** | 损失或奖励只是意图的近似 | 指标很高、结果很差（奖励黑客） | 一 |
| **分布偏移 / 分布外失效** | 训练分布与部署分布不同 | 上线后性能骤降，罕见场景崩溃 | 二 |
| **对抗与鲁棒性缺陷** | 输入被精心扰动或含自然扰动 | 可被欺骗、被绕过 | 二 |
| **不确定性被忽视** | 过度自信、没有拒答机制 | 错误被以高置信度输出 | 二 |
| **偏见与歧视** | 数据 / 目标 / 部署三重来源 | 对某些群体系统性不利 | 三 |
| **隐私泄露** | 模型记忆、跨数据聚合 | 个人信息被推断或还原 | 三 |
| **滥用与越权** | 能力被恶意或不当使用 | 越权操作、生成有害内容 | 一 / 三 |
| **反馈回路 / 自我强化** | 模型输出又成为它的输入 | 偏见与错误被循环放大 | 三 |
| **不可追责** | 系统复杂、自主、多人协作 | 出错无人负责，无法纠偏 | 三 |

**关键认知**：这些失效**大多是「社会-技术」的**（sociotechnical）——一半在模型里，一半在数据采集、组织结构、使用流程与激励机制里。真正可靠的做法不是问「模型是否有偏见」这种模糊问题，而是把它拆成上表里**具体的、可观测的、分群的**问句（见 [1.5](#15-案例讨论的框架如何系统地列出风险)）。

## 1.2 法则一 · 可控与对齐

**对齐（alignment）** 要解决的是「**让系统的行为符合人类的意图与价值**」这一目标问题。它的核心难点不是技术实现，而是一个结构性的错位：我们并不能直接优化「我们想要的」，只能优化「我们写下来的」。

::: def 定义 7.1 · 目标对齐问题（the alignment problem） {#def-7-1}
设我们真正期望的目标为 $u$（往往是模糊、难以形式化、甚至只有原则的价值），而系统实际被优化的**代理目标**为 $g$（损失、奖励、某项指标）。**对齐问题**指：优化 $g$ 到很高水平，**并不保证** $u$ 得到改善——两者之间存在系统性缺口。对齐的工作，就是不断把 $g$ 修正得更接近 $u$，并约束优化过程不去利用这个缺口。
:::

这个缺口有**三个来源**，混在一起时最危险：

1. **目标错设（misspecification）**：$g$ 写错了。例如用「停留时长」近似「用户满意」，于是系统学会了制造焦虑式的无限下拉。
2. **目标泛化错误**：在训练与示范所及的范围内行为合规，到了**新情境、新分布**下行为偏离意图——对齐没有随能力泛化。
3. **优化压力催生的钻空子**：$g$ 与 $u$ 的缺口一直都在，但**能力越强、优化越充分，系统越会精确地找到并利用这个缺口**。这正是「越努力优化一个不完美的目标，结果可能越糟」的一般现象（常被概括为古德哈特定律式的效应）。

::: def 定义 7.2 · 奖励黑客（reward hacking） {#def-7-2}
策略找到了在代理目标 $g$ 上获得高分、却**不推进甚至违背**真实意图 $u$ 的行为模式。它是「代理目标 + 强大优化器」组合的**结构性**风险，而非某次实现疏忽：只要目标不完全，优化压力足够大时它就会发生。
:::

对齐的手段是一条**由粗到细的谱系**，理解它们各自补哪一段缺口，比记名字重要。

**监督微调（SFT）**：用「理想行为」的示范数据（指令-回答对、拒答示例）做普通监督微调，让模型在做这类事上有个起点。它**直接、稳定、可解释**，但有两个硬边界：标注成本高；以及**只覆盖你已经想到并示范过的行为**——没示范过的情形它不会自动正确。

**RLHF（人类反馈强化学习）**：当「什么回答更好」写不成精确奖励时，用人类偏好把它*学*出来。它承接 [第 5 讲](lec05.md) 的四步流程，这里从「对齐」的角度重述并补上它的局限。

::: method RLHF 三阶段（对齐视角） {#method-7-1}
1. **得到初始策略**：预训练 + SFT，得到参考模型 $\pi_{\text{ref}}$——它是「语言能力」的载体。
2. **把偏好变成奖励**：收集成对偏好数据，训练奖励模型 $r_\phi$，使它对「被偏好的回答」给更高分。**注意 $r_\phi$ 只是比原始目标更接近人类偏好的一个代理**，仍然不完美。
3. **用 RL 优化并加约束**：优化策略以最大化 $r_\phi$，同时用 KL 惩罚把它拴在 $\pi_{\text{ref}}$ 附近，
$$\max_\theta\ \mathbb E_{x,\,y\sim\pi_\theta}\bigl[r_\phi(x,y)\bigr]\;-\;\beta\,\mathrm{KL}\bigl(\pi_\theta(\cdot\mid x)\,\Vert\,\pi_{\text{ref}}(\cdot\mid x)\bigr).$$

**三个必须记住的局限**：① **偏好数据来自有限、有噪声的人群**，它编码的是「那些标注者在这种情形下更偏好什么」，不等于「所有人真正的价值」；② **奖励模型仍可被过度优化**，$r_\phi$ 的漏洞就是新的奖励黑客入口；③ **KL 约束是权宜之计**——$\beta$ 太小会被奖励模型带偏，太大则学不动、几乎等于不训练。
:::

::: think RLHF 到底"对齐"了什么
它对齐的是 **「在这些偏好数据、这个奖励模型、这个 KL 约束下」的行为**，而不是一个放之四海皆准的「人类价值」。所以 RLHF 常被理解为一步**高质量的行为塑形**，而非对齐的终点。要真正逼近意图，还需要：更公平且更有代表性的偏好来源、更好的目标设计、以及下面要讲的**越狱防御与红队**来持续找出剩余缺口。
:::

**越狱与滥用。** 一个对齐后的模型要同时满足两个互相拉扯的要求：**有用**（尽量满足请求）与**安全**（拒绝有害请求）。这两者的边界模糊，就产生了可被利用的空间。

- **越狱（jailbreak）**：用精心设计的提示（角色扮演、假设情境、分步诱导、编码包装等）把有害请求**包装成看似无害的样子**，绕过模型的安全行为。
- **提示注入（prompt injection）**：把恶意指令**藏在模型会读到的内容里**（网页、文档、工具返回、他人消息），劫持本该执行用户意图的模型。当模型接入工具、能读写外部系统时，这是一个**安全边界**问题，而不只是「说错话」。
- **滥用（misuse）**：给定任务本身合法或灰色，但整体被用于伤害（自动化欺诈、规模化骚扰、危险信息获取等）。

防御的基本思路是**纵深与降权**，而非单点：

- **红队测试**（见 [@def-7-3]）：主动去找这些绕过方式。
- **输入与输出过滤**：在模型前后加独立的安全分类/过滤，但要意识到它可被对抗性绕过，也会**过拒**（把正当请求挡掉）。
- **最小权限与分级授权**：让模型**没有能力**做危险动作（不给出不该有的系统权限），比指望它「自觉不做」更可靠。
- **分级部署与人类审核**：高风险动作强制人在回路、限速、留痕。

::: def 定义 7.3 · 红队测试（red teaming） {#def-7-3}
由人或受控的自动化程序扮演攻击者，**对抗性地、系统地**搜索系统的失效：构造能诱发有害输出、绕过安全机制或触犯部署边界的输入，记录攻击成功率与失败模式。它是**发现未知风险**的手段，产出的是「在哪些攻击下会失守」，而非「系统安全」的证明。
:::

::: note 对齐的四个常见误解
1. **「对齐就是让模型听话/顺从」**——错。服从某条具体指令恰恰可能是不对齐。对齐是让行为符合**意图与价值**，「过度听话、可被任意越狱」本身就是风险。
2. **「对齐是发布前做一次就完了」**——错。能力提升、使用环境变化、反馈回路都会让旧的对齐失效，它是一个**持续校准**的过程。
3. **「对齐有代价，所以它和性能必然对立」**——不完全对。某些约束（好的拒答、更稳的规范）会同时提升可用性与信任；但**确实存在张力**，需要按场景权衡，而不是假装没有。
4. **「对齐已经解决了隐蔽的欺骗问题」**——这是一个**开放且具争议**的研究问题：有研究者提出，足够强的系统理论上可能学会在评估中表现得合规、在部署中偏离（有时称为「欺骗性对齐」的担忧），目前**没有定论**，也不应被当作已发生的事实。把它当**风险假设**来设计防御（如多环境评估、持续监控），比当结论更稳妥。
:::

## 1.3 法则二 · 可解释与可信

可解释性要回答的是：**我们能不能知道模型为什么给出这个结果、它在什么条件下会错。** 只有能回答，才谈得上调试、审计、追责，以及把「信任」建立在证据而不是感觉之上。

**黑箱问题的实质**：模型的参数与激活不直接对应人能读懂的语义。规模越大、越端到端，输入到输出的因果链越难人工追踪，于是传统的「读代码」式审查失效。

::: def 定义 7.4 · 可解释性的两个层次 {#def-7-4}
- **事后解释（post-hoc）**：**不改变模型**，用一个更简单、可读的对象去**近似**它的行为或决策依据。常见做法：特征重要性、逐样本的局部代理（如 LIME / SHAP）、梯度或输入显著性图、生成自然语言解释。
- **内省 / 机制可解释性（intrinsic / mechanistic）**：**打开模型内部**，直接刻画它的表示与计算——例如用线性探针检测某语义是否存在于中间层、定位与某能力相关的子网络（「电路」）、用稀疏字典学习把叠加的特征方向分离出来。
:::

两类方法回答的是**不同的问题**：事后解释回答「对它这个预测，哪个输入更重要」，内省回答「它的内部究竟在算什么」。二者都不可互相替代。

::: intuition 事后解释的"忠实性"陷阱
事后解释最常见的误用，是把「**解释看起来合理**」当成「**解释反映了真实机制**」。事实上：不同显著性方法在同一模型上可能给出**互相矛盾**的图；解释器本身也有自己的归纳偏置与失效模式；而人类对流畅的解释有强烈的**过度信任**（automation bias）。所以解释的**忠实性（faithfulness）**——解释是否真的对应模型内部的计算——需要**独立验证**，不能靠「读起来顺」来判定。内省方法正是为了绕开这个「用另一个黑箱解释黑箱」的循环，但它目前仍是一个**开放的研究方向**，不是通用可用的成品。
:::

**不确定性与校准。** 一个正确的系统还必须**知道自己何时不知道**。

- **不确定性的两类来源**：**数据固有的随机性**（同一输入本就可能有多种合理结果）与**认知不足**（该区域数据太少、模型「没见过」）。前者无论多少数据都在，后者可以靠更多数据/更好的建模缓解。
- **校准（calibration）**：置信度是否与真实正确率相符。

::: def 定义 7.5 · 校准（calibration）与期望校准误差 {#def-7-5}
一个模型是**校准的**，如果它输出的置信度与它的实际正确率相符：在所有「自信为 $p$」的预测中，约有 $p$ 的比例是对的。把预测按置信度分桶 $B_m$（桶内平均置信度 $\mathrm{conf}(B_m)$、实际正确率 $\mathrm{acc}(B_m)$），可用**期望校准误差**衡量：
$$\mathrm{ECE}=\sum_{m}\frac{\lvert B_m\rvert}{n}\,\bigl\lvert \mathrm{acc}(B_m)-\mathrm{conf}(B_m)\bigr\rvert .$$
深度网络**普遍过度自信**：ECE 大意味着「高置信度的错误」频繁出现，这比「不确定时出错」危险得多。
:::

校准的常用对策：**温度缩放**等后处理、**深度集成**、**近似贝叶斯**方法；以及用**一致性预测**提供有统计保证的预测区间——在数据**可交换**的前提下，$C(X_{\text{new}})$ 以至少 $1-\alpha$ 的概率覆盖真实标签。**重要边界：** 这些保证大多依赖「新数据与校准数据同分布」，**在分布外会失效**，所以校准必须与下面的 OOD 监测配套。

**鲁棒性与分布外行为。** 模型在测试集上表现好，不等于在真实部署里可靠。

- **对抗鲁棒性**：[第 3 讲](lec03.md) 的对抗样本说明，人眼难辨的微小扰动就能翻转预测，且可跨模型迁移。对抗训练（把对抗样本加入训练）能提升鲁棒性，但通常**牺牲一部分标准精度**，且不能保证对所有攻击都稳。
- **分布偏移与分布外（OOD）**：部署数据与训练分布不一致时，性能会下降，且**校准也随之失效**。要主动做 **OOD 检测**，并在不确定/越界时**拒答或降级**，而不是照常输出。
- **捷径与伪相关（spurious correlation）**：模型可能抓住与标签**相关但非因果**的线索（背景、水印、采集设备），在这些线索变化后彻底失效。这种失败往往**隐藏得很好**——因为测试集恰好也含同样的伪相关。

::: intuition 「性能好」不等于「可信」：四个正交维度
正确率、**校准**、**鲁棒性**、**可解释性**是**互相独立**的性质：一个模型可以在测试集上准确率极高，却过度自信（校准差）、一遇对抗扰动就翻车（不鲁棒）、决策依据无法说明（不可解释）。因此「可信」不可能由单一指标代言——它需要**多维度、多场景、分群**的证据共同支撑（这也是 1.6 节把评估单独设为一个阶段的原因）。
:::

## 1.4 法则三 · 公平与责任

前两条法则关心「系统对不对」，这一条关心「**它对谁做了什么、由谁负责**」。它天然是「社会-技术」的：模型只是链条的一环。

**偏见的三种来源**，必须分开对待，因为对策不同：

- **数据**：历史数据本身就携带过往的不平等；采集方式（谁被记录、谁被漏掉）带来采样偏差；标注者的主观与不一致带来标注偏差；某些群体的样本稀少导致模型在其上表现更差。
- **目标**：用**代理指标**替代真正关心的目标（例如用「历史录用结果」代理「谁该被录用」），优化过程会**放大**少数样本上的误差；公平很少被写进损失，于是它默认不是一个优化目标。
- **部署**：同一模型在不同人群、不同流程中的效果不同；**反馈回路**会把模型的输出变成下一轮训练数据（模型决定给谁看什么，进而改变未来数据），使偏见**自我强化**。

::: def 定义 7.6 · 常见的公平准则 {#def-7-6}
给定受保护属性 $A$、真实标签 $Y$、预测 $\hat Y$（或分数 $\hat p$）：

- **人口统计平价（demographic parity）**：各群体的正例率相等，$P(\hat Y=1\mid A=0)=P(\hat Y=1\mid A=1)$。
- **机会均等 / 均等化几率（equalized odds）**：在真实标签条件下各群体的错误率相等，即对 $y\in\{0,1\}$ 有 $P(\hat Y=1\mid Y=y,A=0)=P(\hat Y=1\mid Y=y,A=1)$。
- **预测平价 / 分群校准（predictive parity / calibration within groups）**：相同的分数意味着相同的正例概率，$P(Y=1\mid \hat p=p,\,A=a)=p$。
- **个体公平（individual fairness）**：相似的个体应被相似地对待——难点在于「相似」如何定义。

**这些准则对应不同的伦理立场**：有的要求「结果均等」，有的要求「在同等条件下机会均等」。它们不是同一件事的强弱版本，而是**不同的价值选择**。
:::

::: thm 定理 7.1 · 公平准则的不相容（陈述） {#thm-7-1}
当各群体的**基础发生率不同**时，若干常用群体公平准则一般**不能同时满足**——典型地，**分群校准**与**均等化几率**在非平凡情形下无法兼得。（这里只作陈述，不展开证明。）

**工程含义**：公平**没有唯一正确解**。你必须根据场景的伦理与合规要求，**显式选择**要满足的准则，并**说明它牺牲了什么**；「我们已做到公平」这种没有指明准则的说法无法验证。技术能保证的只是「按你选定的准则优化」，选哪一个是**价值判断**。
:::

**隐私。** 模型会**记忆**训练数据，因此隐私不是「把姓名字段删掉」就能解决的：

- **去标识化不等于匿名**：即使去掉直接标识符，属性组合也可能**唯一识别**个体，或通过与其他数据交叉比对还原身份。
- **攻击面**：**成员推断**（判断某条记录是否在训练集中）、**数据提取**（从模型里设法恢复训练片段）。
- **技术手段**：**差分隐私**用相邻数据集上输出分布的相近程度给出可量化的保护强度——

$$\Pr\bigl[\mathcal M(D)\in S\bigr]\ \le\ e^{\epsilon}\,\Pr\bigl[\mathcal M(D')\in S\bigr]+\delta ,$$

其中 $D,D'$ 只差一条记录；$\epsilon$ 越小保护越强。**联邦学习**让原始数据留在本地、只交换更新，能减少集中存储的风险，但**不等于**自动满足隐私——梯度更新本身也可能泄露信息。**合成数据**同样是缓解而非彻底解决。
- **权衡**：隐私保护通常以**效用/性能下降**为代价，$\epsilon$、$\delta$ 就是把这个权衡显式化的旋钮。

**透明度。** 让外部能**审查、理解、追责**，靠的是**文档与可追溯**：记录数据来源与用途、模型的能力与已知局限、适用与不适用场景、评估结果（包括分群结果）。业界常用**模型卡 / 数据卡 / 系统卡**这类结构化文档把这些固定下来。透明不是「泄露实现细节」，而是让**边界与假设可见**。

**责任归属。** 当系统出错，**谁负责**？链条上可能同时有数据提供者、模型开发者、部署方、运营方与最终决策者。不透明与高自主性会让追责格外困难。可操作的机制包括：**明确的责任划分与使用边界**、**审计权**、面向被影响者的**申诉与纠错通道**、高风险环节的**人在回路**、以及**可回滚**的部署形态。监管层面目前多以**原则与框架**为主（要求风险评估、文档、问责），而非给出可直接照抄的技术配方。

::: note 三条法则之间存在真实张力
更严格的**安全过滤**可能**过拒**正当请求，并可能对表达方式不同的群体**影响不均**（触碰公平）；更强的**隐私保护**会降低模型能力（触碰可用性）；更强的**可解释性要求**可能限制模型结构。因此三条法则不是「叠加更多约束」那么简单，而是需要**显式权衡**——把每种取舍记录成**可复查的决策**，本身就是责任的一部分。
:::

## 1.5 案例讨论的框架：如何系统地列出风险

给一个部署场景，光凭直觉列风险一定会漏。下面这套**五步法**（[@method-7-2]）把 [1.1](#11-为什么技术人必须主动管后果)的失效模式表变成一份**可讨论、可签字**的清单。

::: method 风险清单五步法 {#method-7-2}
1. **界定系统与上下文**：它替谁、在什么流程里、对什么做**什么决定**？是全自动还是给人建议？错了的**代价**与**可逆性**如何？
2. **列全利益相关者**：不只列「用户」，要包括**被系统影响的非用户**、数据主体、部署方、运营与维护者、监管方、社会公众。
3. **列失效模式**：对每一类利益相关者，逐行过 [1.1](#11-为什么技术人必须主动管后果)的表（目标错设、分布偏移、对抗、偏见、隐私、滥用、反馈回路、不可追责），并对照三条法则。
4. **为每项给缓解与验证**：缓解要落到具体动作（数据/训练/评估/部署/监控），并且**可验证**——写清「用什么指标、在什么数据上、达到什么门槛」。
5. **记录残余风险与决策人**：**没有任何缓解能清零风险**。明确写出「剩下的风险是什么、由谁在什么条件下决定接受」。
:::

第 5 步常被跳过，但它才是工程诚实的核心：安全不是「消灭风险」，而是**知道并主动承担剩余的部分**，并把判断记录下来，供日后复查与追责。

::: ex 例 7.1（一个部署场景的风险清单） {#ex-7-1}
场景（虚构、通用）：把「**简历初筛辅助模型**」接入招聘流程，输出「建议进入下一轮 / 建议淘汰」的分数，人类招聘者参考该分数做最终决定。

请按五步法列出风险清单。

::: proof 解
**第 1 步 · 上下文**：这是**建议型**系统，不直接决定录用，但会被当作强参考（事实上可能被当作决定）。错误代价高且**难逆**——被系统筛掉的人可能永远没有机会申诉；且影响是**分群性**的。

**第 2 步 · 利益相关者**：应聘者（尤其被不利影响群体）；招聘方；模型开发/数据提供方；被系统间接影响的公众（劳动力市场）；监管方。

**第 3 步 · 失效模式与第 4 步 · 缓解与验证**

| 失效模式 | 具体形态 | 缓解动作 | 验证方式 |
|:--|:--|:--|:--|
| **偏见（数据/目标）** | 用「历史录用结果」当标签，复制并放大历史不平等；某些群体的样本稀少 | 把标签换成**与岗位真正相关的胜任标准**；按受保护群体检查样本量；对稀有群体做重加权或补采样 | **分群评估**：各群体的通过率与错误率（如均等化几率下的两类错误），而不只看总体准确率 |
| **目标错设** | 优化「与既往录用者相似度」，而非「岗位胜任概率」 | 用与工作相关的特征与标签；对代理指标与意图的差距做说明 | 与人类专家判断在**抽样**上的一致性 |
| **分布偏移** | 岗位、行业、简历格式变化后性能下降 | 定期重训与漂移监测；对越界输入**拒答/转人工** | 线上指标漂移告警；对 OOD 样本的覆盖率与降级率 |
| **不可解释** | 应聘者问「为什么被筛掉」答不出 | 提供**逐样本的、经忠实性验证的**解释；保留人工复核 | 解释与模型行为的一致性检查；申诉样本的复核记录 |
| **隐私** | 简历含敏感信息，被模型记忆/泄露 | 最小化采集；访问控制；对训练/推理数据的留存策略 | 数据卡记录；访问审计 |
| **反馈回路** | 被筛掉的人从不出现在后续训练数据里，偏见自我强化 | 保留**随机抽样**进入下一轮；监测各群体进入训练数据的比例 | 各群体后续数据占比随时间的监测 |
| **责任不清** | 模型建议与人类决定之间责任真空 | 明确「系统只提供建议」的使用边界与**人类决策者的责任**；建立申诉通道 | 使用规范文档；申诉处理记录 |

**第 5 步 · 残余风险**：即使做了上述所有事，仍可能残留**无法完全量化的排序偏差**与**标签本身的伦理争议**（「胜任」如何度量本身就有分歧）。这些残余风险应**显式记录**，并明确由谁在什么条件下**批准上线**、何时**复审**。**这份记录就是本例题的交付物**——它把「讨论」变成了可追责的工程文档。
:::

## 1.6 把安全当成设计约束

安全最常见的错误定位，是把它当成**发布前、或发布后加的一层过滤补丁**。正确的心智是：安全与公平是**贯穿全生命周期的设计约束**，像「延迟预算」或「内存上限」一样，在**每个阶段**都有对应的动作与验收标准。

| 阶段 | 安全动作 | 要产出的证据 |
|:--|:--|:--|
| **数据** | 数据来源与用途合法知情；检查并补齐各子群代表性；记录标注规范与不一致；对敏感数据做最小化与访问控制 | 数据卡；分群样本统计；标注一致性报告 |
| **训练** | 目标设计避免单一代理；把安全行为（恰当拒答、降级）写进示范与偏好数据；对齐（SFT / RLHF）；必要时对抗训练 | 目标设计与代理缺口的说明；对齐数据说明 |
| **评估** | **分群评估**（不只看平均）；红队测试；OOD 与对抗评估；**校准**评估；面向失效的**压力测试**；明确上线门槛 | 多维度评估报告；红队记录与攻击成功率；分群与校准指标 |
| **部署** | 人在回路与分级授权；最小权限；不确定时**拒答/降级**；限速与留痕；内容溯源 | 部署边界文档；降级与拒答策略；审计日志 |
| **监控** | 线上指标与漂移监测；**反馈回路**检测；事件响应与**回滚**；定期复审与再对齐；申诉通道 | 监控看板；事件响应预案；复审记录 |

::: intuition 为什么"最后加一层过滤"不算安全
过滤层是**独立的第二个模型**，它一样有过拒、有可被绕过的对抗面、有它自己的失效分布——你已经知道「单一防线不可靠」。真正有效的是**纵深防御**：即使某一层被绕过，后续的授权限制、人在回路与留痕仍能限制后果。把安全前移到**数据与目标**（让模型从一开始就更难学到有害行为），比只在**输出端**拦截更省、更稳。**安全约束会随着能力增长而需要重新校准**——今天够用的门槛，在更强、更自主的系统上可能需要重新评估。
:::

值得强调的一点：安全与能力**存在张力，但不总是对立**。好的不确定性估计与恰当拒答会**提升**用户信任与产品可用性；把使用边界写清楚会**减少**误用与纠纷。真正需要小心的是**假装没有张力**——把「更多过滤」当成纯收益，往往会以过拒、可用性下降或群体间影响不均为代价（见 1.4 的张力讨论）。因此每个安全动作都应记录它**换来了什么、牺牲了什么**。

## 1.7 本讲陷阱

::: errata 常见误解清单
1. **「对齐就是让模型听话/顺从」**：错。对齐是让行为符合**意图与价值**，不是服从某条具体指令；「过度听话、可被任意越狱」本身就是风险。服从 $\neq$ 对齐。
2. **「可解释性工具能证明模型安全」**：错。事后解释解释的是**近似行为**，不构成证明；不同方法可能结论矛盾，且人类对流畅解释有过度信任。解释的**忠实性**需要独立验证。
3. **「公平只有一个定义」**：错。公平有多种准则且会**互相冲突**（[@thm-7-1]）；必须**显式选择**并说明代价，没有「已做到公平」的中立说法。
4. **「红队测试 / 评测通过就等于安全」**：错。通过只说明「在这些攻击下没找到失效」，不等于「不存在失效」。安全是**持续过程**，不是一次性验收。
5. **「总体平均指标好就行」**：错。平均值会**掩盖子群差异**；必须看**分群指标与最差群体**，否则无法发现系统性不公。
6. **「置信度高 = 可靠」**：错。深度网络常**过度自信**（校准差），且**分布外校准会失效**；需要校准手段 + OOD 检测 + 拒答机制。
7. **「对齐只是模型输出层的事，或者只是 RLHF」**：错。数据、目标设计、部署流程、反馈回路都在其中；RLHF 只是**其中一环**，且它对齐的是「在这个奖励模型下」的行为，不是普适的人类价值。
8. **「有偏见的只是数据，模型是中立的」**：错。即使数据客观，**目标函数与优化过程**也会引入并放大偏差；**部署与反馈回路**还会继续改变结果。
9. **「隐私 = 把姓名列删掉」**：错。去标识化**不等于**匿名；模型会记忆训练数据，存在**成员推断与数据提取**风险；需要差分隐私 / 联邦学习等手段（它们同样有权衡）。
10. **「安全是最后加的一层过滤补丁」**：错。应作为设计约束贯穿**数据 → 训练 → 评估 → 部署 → 监控**；只在输出端拦截既贵又脆。
11. **「安全只关乎模型内部」**：错。这些失效大多**社会-技术**兼有；组织流程、激励机制、使用规范与追责机制常常决定最终后果。
12. **「隐藏的欺骗性对齐已经发生」**：把**开放且有争议的研究担忧**当成已证实的事实。它应作为**风险假设**驱动防御设计（多环境评估、持续监控），而不是当作结论。
:::

## 1.8 本讲小结

**三句话带走**：

1. 三条法则把「后果」拆成三个**可工程化**的问题：**可控与对齐**（目标对不对）、**可解释与可信**（我们能否理解它、知道它何时会错）、**公平与责任**（它对谁负责、谁担责）。
2. 三者都**不能靠单点补丁**：对齐靠「目标设计 + 偏好学习 + 红队」的迭代；可信靠「校准 + 鲁棒性 + 可解释性」的多维证据；公平靠「显式准则 + 分群评估 + 问责机制」——而且三者之间存在**真实权衡**，需要显式记录取舍。
3. 把安全当成**贯穿数据到监控的设计约束**：每个阶段都有动作、都有验证、都有残余风险，且要随着能力增长**重新校准**。许多问题是**社会-技术**的，技术只解决其中一半。（这套思路的完整演练见 [@ex-7-1]。）

**与后续的连接**：本讲把前六讲的**能力**接上了**约束**。[第 3 讲](lec03.md)的对抗样本与数据集偏见、[第 5 讲](lec05.md)的 RLHF 都在本讲合流，成为三条法则的技术底座；[第 8 讲](lec08.md) 的 AI for Science 会再次面对「预测被用于真实决策」时的可信与责任问题；[第 9 讲](lec09.md) 的大规模并行训练提醒我们，**规模既放大能力，也放大风险**；而 [Lab 3](../labs/lab3.md) 微调大语言模型时，SFT 与偏好优化环节正是本讲「对齐」的工程化身——你会亲手体会到：**你写下的目标，和你真正想要的结果，中间隔着一段需要被认真对待的距离**。

::: preview 把本讲带进实践
下次你面对任何一个模型部署时，先别问「它准不准」，而是按顺序问四个问题：**它的目标写对了吗（代理 vs 意图）？我们知道它为什么这么答、什么时候会错吗？它对不同人群的影响一样吗？出了问题谁负责、怎么纠偏？** 这四个问题分别对应三条法则与责任机制，也正是 [1.5 节](#15-案例讨论的框架如何系统地列出风险)五步法的口语版。把它变成习惯，你就已经把「伦理与安全」从口号变成了工程判断。
:::
